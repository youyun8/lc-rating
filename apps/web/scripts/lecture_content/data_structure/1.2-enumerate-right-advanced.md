## 這個技術解決什麼問題

1.1 的摘要以「原始值」為鍵，只能回答「左邊有沒有等於 $x$ 的元素」。但很多題目的配對條件不是相等：

- 1010：$(a + b) \bmod 60 = 0$。
- 1497：把 $2n$ 個數配成 $n$ 對，每對和可被 $k$ 整除。
- 3185：$(h_i + h_j) \bmod 24 = 0$。
- 1995：四元組 $a + b = c + d$（$i<j<k<l$）。

若照原始值建表，$10^9$ 的值域根本裝不下，而且「互補」的對象也不是單一值。本節的進步是：**先把原始值映射成題目真正在意的「特徵」，再對特徵做互補配對。** 特徵的種類數往往只有 $O(k)$ 個，摘要瞬間變小，查詢仍是 $O(1)$。

## 狀態／資料結構定義

- **特徵函數** $\varphi: V \to K$，把原始值映射到一個小值域。常見的 $\varphi$：
  - 餘數：$\varphi(x) = x \bmod k$（1010、1497、3185、2964）。
  - 位元遮罩：$\varphi(s) = $ 各字元出現次數的奇偶（2506、1371）。
  - 正規化的形狀：$\varphi(w,h) = w/\gcd \cdot 10^9 + h/\gcd$（2001 可互換矩形）。
- **互補函數** $\psi: K \to K$（或 $K \to$ 集合），滿足：$(x, y)$ 合法 $\iff \varphi(y) = \psi(\varphi(x))$。
- **摘要**：`cnt[key]` = 左側特徵為 `key` 的元素個數。計數而非布林，因為要數配對數量。

**多元組的拆分**：$k$ 元組先固定「切點」，把它拆成「左側的 $p$ 元組」與「右側的 $q$ 元組」，兩邊各自維護一份摘要。1995 的 $a+b=c+d$ 改寫成 $a - c = d - b$ 後固定中間兩個下標，就退化成 1.3。

## 不變量或正確性證明

**核心引理（特徵的充分性）。** 設配對條件為謂詞 $P(x, y)$。若存在 $\varphi$ 與 $\psi$ 使得
$$P(x, y) \iff \varphi(y) = \psi(\varphi(x)),$$
則「左邊有幾個 $y$ 滿足 $P(x,y)$」$=$ `cnt[psi(phi(x))]`。

這一步看似顯然，但它精確說出了本技巧成立的前提：**條件必須能只透過特徵判斷，而且互補的特徵必須唯一（或是可枚舉的少數幾個）**。逐一檢查：

- $(a+b) \bmod k = 0$：$\varphi(x) = x \bmod k$，$\psi(r) = (k - r) \bmod k$。**唯一互補，成立。**
- $a + b = t$：$\varphi(x) = x$，$\psi(x) = t - x$。**成立**（這就是 1.1）。
- $|a - b| \le d$：**沒有唯一互補特徵**，互補的是一個區間 $[a-d, a+d]$。此時要改用有序集合 + `lower_bound`（$O(\log n)$）或滑動視窗，不能用雜湊表。
- 「$a$ 與 $b$ 至多差一次字元交換」（3267）：互補集合的大小是 $O(\text{字串長}^2)$，仍可枚舉，於是**枚舉所有互補特徵再查表**——這是引理的推廣形式（$\psi$ 回傳集合）。

**$\psi(r) = (k - r) \bmod k$ 的外層 `% k` 不可省。** 當 $r = 0$ 時，$k - 0 = k \notin [0, k)$，會查到一個不存在的鍵，導致「餘數為 0 的元素彼此無法配對」——而那正是最容易出現的一組配對。**這一行的 `% k` 是正確性，不是防禦性寫法。**

**計數的不重不漏。** 沿用 1.1 的不變量（查詢時摘要恰為 $\{a_0..a_{i-1}\}$）。每個合法對 $(j,i)$，$j<i$，在第 $i$ 輪被 `ans += cnt[need]` 計入恰一次。**注意這裡不需要再乘 2 或除以 2**——因為順序已由「$j$ 在左、$i$ 在右」固定。若改用「先建完整計數表再對每個元素查詢」的寫法，每對會被算兩次，就必須除以 2，而且要特別處理 $\varphi(x) = \psi(\varphi(x))$ 的自配對情形。**兩種寫法都對，但混用就錯**；本節統一採用「邊掃邊配」，因為它沒有這些例外。

**1995（統計特殊四元組 $a_i + a_j + a_k = a_l$，$i<j<k<l$）的正確性。** 移項成
$$a_i + a_j = a_l - a_k .$$
左邊只依賴 $\{i, j\}$，右邊只依賴 $\{k, l\}$——**這正是「特徵只依賴一側」這個前提的具體形式**。於是固定 $j$，維護一張表 `cnt`，其鍵是 $a_l - a_k$，範圍限制為 $j < k < l$。

實作上讓 $j$ **由大到小**掃：進入第 $j$ 輪時，先把所有 $c = j+1$ 的新配對 $(c, d)$（$d > c$）併入 `cnt`，然後對每個 $i < j$ 累加 `cnt[a[i] + a[j]]`。

*不變量*：查詢的那一刻，`cnt` 恰好等於所有滿足 $j < k < l$ 的 $(k,l)$ 對的 $a_l - a_k$ 的計數。
- 保持：從 $j+1$ 掃到 $j$ 時，新增的合法 $(k,l)$ 恰是 $k = j+1$ 的那些（$k \ge j+2$ 的在前幾輪已加入，且永遠合法，不需移除）。這就是為什麼 `cnt` **不能在每輪清空**——它是單調增長的。
- *不重不漏*：每個四元組 $(i,j,k,l)$ 在第 $j$ 輪、內層下標 $i$ 時恰被算一次。

$j$ 必須由大到小，因為「$k > j$」這個限制隨 $j$ 減小而放寬，只增不減，才能用「只加不刪」的摘要。若由小到大掃，就得刪除項目，摘要不再單調。**這與 12.1 離線查詢排序的思想是同一條：把限制排成單調的順序，讓資料結構只需支援插入。**

## C++17 模板

```cpp
// 總持續時間可被 60 整除的歌曲對（LeetCode 1010）
// 特徵 = 模 60 的餘數；互補 = (60 - r) % 60。
class Solution {
public:
    int numPairsDivisibleBy60(std::vector<int>& time) {
        constexpr int kMod = 60;
        std::array<int, kMod>
            cnt{};  // 值域已知且小 → 用陣列，不用 unordered_map
        long long ans = 0;
        for (int t : time) {
            int r = t % kMod;              // 特徵
            int need = (kMod - r) % kMod;  // 互補特徵；外層 % 不可省（r == 0）
            ans += cnt[need];              // 先查：左側有幾個互補的
            ++cnt[r];  // 再加：自己成為後續的左側
        }
        return static_cast<int>(ans);
    }
};
```

```cpp
// 統計特殊四元組 a[i] + a[j] + a[k] == a[l]，i<j<k<l（LeetCode 1995）
// 移項成 a[i] + a[j] == a[l] - a[k]：左邊只依賴 {i,j}，右邊只依賴 {k,l}。
class Solution {
public:
    int countQuadruplets(std::vector<int>& nums) {
        int n = nums.size();
        std::unordered_map<int, int> cnt;  // (a[l] - a[k]) 的計數，限 k > j
        long long ans = 0;
        for (int j = n - 3; j >= 1; --j) {
            // j 減 1，合法的 (k, l) 只增不減：新增的恰好是 k == j + 1 那一批
            for (int l = j + 2; l < n; ++l) {
                ++cnt[nums[l] - nums[j + 1]];
            }
            // 此刻 cnt 恰為所有 j < k < l 的 a[l] - a[k]（cnt 不可清空）
            for (int i = 0; i < j; ++i) {
                auto it = cnt.find(nums[i] + nums[j]);
                if (it != cnt.end()) {
                    ans += it->second;
                }
            }
        }
        return static_cast<int>(ans);
    }
};
```

`cnt` 跨輪累積、**永不清空**，是這段程式碼唯一的巧思：它把「$k > j$」這個隨 $j$ 遞減而放寬的限制，變成只需插入、不需刪除的操作。用 `find` 而非 `cnt[key]` 查詢，是為了避免 `operator[]` 在鍵不存在時插入一筆值為 0 的項目——那會讓表無謂膨脹（正確性不受影響，但在 $n$ 大時是可觀的常數）。

## 時間與空間複雜度

單層掃描版（1010、1497、3185、2506）：$O(n)$ 時間，$O(|K|)$ 空間（$|K|$ 是特徵種類數，通常是 $k$ 或 $2^{26}$ 中實際出現的部分）。

多元組拆分版（1995、2874、2964）：固定 $t$ 個下標就是 $O(n^t)$ 外層乘上 $O(1)$ 查表。四元組拆成 2+2 是 $O(n^2)$，比暴力的 $O(n^4)$ 少兩個數量級。

「巢狀最佳化」版（1031 兩段不重疊子陣列、2555 兩條線段）：左側摘要不是計數而是「到目前為止的最佳值」，仍是 $O(n)$。**這一類的正確性依據是「最佳左端點只有一個」，與 1.1 的極值型同源，而不是本節的互補配對。**

$O(k)$ 大小的陣列（1010 的 60、3185 的 24）比 `unordered_map` 快數倍；**只要 $|K|$ 已知且不大，一律用陣列**。

## 常見錯誤與邊界條件

- 互補餘數漏掉外層取模，寫成 `k - r`（$r = 0$ 時查到不存在的鍵，餘數 0 的配對全部漏掉）。
- C++ 的 `%` 對負數回傳負值，`x % k` 在 $x < 0$ 時要寫成 `((x % k) + k) % k`（1497 的輸入含負數）。
- 配對數用 `int` 累加溢位（$n = 10^5$ 時配對數可達 $5 \times 10^9$，必須 `long long`）。
- 用「先建完整表再逐一查詢」的寫法卻忘記除以 2 或忘記扣掉自配對。
- 1497 只需檢查「每種餘數的個數能否兩兩配完」（$cnt[r] = cnt[k-r]$，且 $cnt[0]$ 與 $cnt[k/2]$ 必須是偶數），而不是數配對數——**題型雖同，問法不同**。
- 多元組拆分時兩側範圍重疊，同一下標被用兩次。
- 特徵函數本身算錯（2001 的矩形比值未約分、或用浮點數比較）。
- `unordered_map` 在最壞情況退化成 $O(n)$（競賽中的雜湊攻擊，可加隨機種子）。

## 與相似技巧的比較

- **與 1.1**：本節把鍵從「值」換成「特徵」，骨架完全相同。**1.1 是 $\varphi = \mathrm{id}$ 的特例。**
- **與 2.2（前綴和 + 雜湊表）**：那是把本節套在前綴和序列上，$\varphi(s_i) = s_i \bmod k$（974、523）或 $\varphi = \mathrm{id}$（560）。**遇到「子陣列和可被 $k$ 整除」，就是 2.2 加上本節的餘數特徵。**
- **與 2.4（狀態壓縮前綴和）**：特徵是位元遮罩，互補是「XOR 後為 0 或只有一個 1」。1371 的互補集合有 $1 + 5$ 個候選，用的正是「$\psi$ 回傳集合」的推廣形式。
- **與排序 + 雙指標**：條件是「和落在某範圍」而非「和等於定值」時，雜湊表失效（沒有唯一互補），改排序後雙指標。**判準：等號用雜湊，不等號用排序。**
- **與 4.8 折半列舉**：454（四數相加 II）先算 `A+B` 的表再查 `C+D`，就是折半的思想用在「已經天然分成兩組」的輸入上。
- **與 1.3 列舉中間**：多元組拆成 $p + q$ 時，若切點在中間且左右都要摘要，就是 1.3。

## 本節重點速查

- 把鍵從**原始值**換成**特徵** $\varphi$，配對條件寫成 $\varphi(y) = \psi(\varphi(x))$。
- 前提：**條件必須只透過特徵判斷，且互補特徵唯一（或可枚舉的少數幾個）**。等號成立時用雜湊，變成不等號／區間就要改排序 + 二分。
- 互補餘數一律寫 `(k - r) % k`——外層取模是正確性，$r=0$ 時必須映射回 0。
- 負數取模要先 `((x % k) + k) % k`。
- 「邊掃邊配」不需除以 2 也沒有自配對問題；「先建全表再查」兩者都要處理。**別混用。**
- 多元組拆成 $p+q$，兩側範圍必須嚴格不交；摘要的鍵只能依賴一側，否則換一輪就整張表失效。
- 配對計數一律用 `long long`；$|K|$ 已知且小就用陣列取代 `unordered_map`。
