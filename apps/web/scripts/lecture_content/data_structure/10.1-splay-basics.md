## 這個技術解決什麼問題

線段樹（9 節）能對**固定長度**的序列做區間修改與區間查詢，但它有一個根本限制：**下標是寫死的。** 一旦要在中間插入或刪除元素，後面所有元素的下標都會平移，線段樹只能重建。

而「設計一個文字編輯器」（2296）恰恰要在游標處反覆插字、刪字；更一般的序列問題還要求「把第 $l$ 到第 $r$ 個元素整段反轉」。**這類「在任意位置插刪、並對任意一段做操作」的需求，需要一棵能維護序列的平衡樹。**

**伸展樹（Splay tree）的核心轉念只有一句：**

> **不要把樹當作「有序集合」，而是把它的中序走訪序列當作「陣列」。** 節點的比較鍵不是元素的值，而是它在序列中的**位置**——而位置由子樹大小 `sz` 隱含地決定，不需要真的存下來。

於是：
- 「取第 $k$ 個」= 按 `sz` 在樹上下降；
- 「在第 $k$ 個之後插入」= 找到位置後掛上新節點；
- 「對 $[l, r]$ 做事」= 把這段**整體提取成一棵子樹**（定理 5），然後像線段樹一樣打標記。

**伸展樹的獨特之處在於它不維護任何平衡資訊**——沒有顏色、沒有高度、沒有隨機優先級。它只做一件事：**每次訪問完一個節點，就把它旋轉到根（splay）。** 這個看似隨意的動作，能保證**攤還** $O(\log n)$（定理 3）。

**辨識訊號**：
- 資料是一個序列，要在**任意位置**插入／刪除，並查詢第 $k$ 個或某段的聚合（2296 設計文字編輯器）；
- 需要對一整段做**反轉、平移**這類「重排」操作，而且次數很多；
- 暴力是每次操作搬 $O(n)$ 個元素，$n$ 與操作數都在 $10^5$ 等級。

**先說一句誠實話**：**LeetCode 上真的非寫伸展樹不可的題目極少。** 2296 用兩個堆疊就能 $O(1)$ 每次操作（見「與相似技巧的比較」）。學它的價值在於**「把序列裝進平衡樹」這個想法**，以及**勢能法攤還分析的一個經典範例**——這兩樣東西在別處反覆出現。

## 狀態／資料結構定義

```cpp
struct Splay {
    struct Node {
        int ch[2] = {0, 0};  // 左右子
        int fa = 0;          // 父節點（伸展樹必須存父指標）
        int sz = 0;          // 子樹大小
        int val = 0;         // 元素值
        bool rev = false;    // 區間反轉的懶標記
    };
    vector<Node> t;
    int root = 0;
};
```

**四個約定，整節都靠它們：**

1. **`t[0]` 是空節點，`sz = 0`。** 與 9.5／9.6 的哨兵是同一個手法——讀到 `0` 自動回傳單位元，省掉所有空指標判斷。
2. **中序走訪序列 = 使用者看到的陣列。** 樹上完全沒有「下標」這個欄位；**第 $k$ 個元素是靠 `sz` 現算出來的。**
3. **必須存父指標 `fa`。** 這是伸展樹與 Treap 的關鍵差異：splay 要從 $x$ 一路往上轉，沒有 `fa` 走不了。**代價是每次旋轉要更新三個 `fa`，這是最高頻的 bug 來源。**
4. **序列頭尾各加一個哨兵節點。** 於是「第 $i$ 個元素」在樹中是「中序第 $i+1$ 個」。**這個偏移不是為了美觀，是定理 5 的前提**——沒有哨兵，$[1, n]$ 這種貼邊的區間就提取不出來。

**兩個基本操作：**

```cpp
void pushUp(int x) {
    t[x].sz = t[t[x].ch[0]].sz + t[t[x].ch[1]].sz + 1;
}

void pushDown(int x) {
    if (!t[x].rev) return;
    swap(t[x].ch[0], t[x].ch[1]);
    if (t[x].ch[0]) t[t[x].ch[0]].rev ^= 1;
    if (t[x].ch[1]) t[t[x].ch[1]].rev ^= 1;
    t[x].rev = false;
}
```

**`rev` 的語義沿用 9.4 的約定**：「`x` 自己已經反轉好了，但兩個子樹還沒有。」**所以 `swap` 發生在 `pushDown` 的當下，而不是打標記的當下。**

## 不變量或正確性證明

以下記 $s(x)$ 為 $x$ 的子樹大小，$r(x) = \log_2 s(x)$（稱為 $x$ 的**秩**）。

### 定理 1（旋轉保持中序序列）

**這是整棵樹的根本不變量**：無論做多少次旋轉，**中序走訪序列不變**。

*證明*。設 $x$ 是 $p$ 的左子（右子對稱），$A = x$ 的左子樹、$B = x$ 的右子樹、$C = p$ 的右子樹。旋轉前，以 $p$ 為根的子樹的中序序列是

$$A,\; x,\; B,\; p,\; C.$$

右旋後 $x$ 成為父、$p$ 成為 $x$ 的右子、$B$ 成為 $p$ 的左子，中序序列是

$$A,\; x,\; \underbrace{B,\; p,\; C}_{p\text{ 的子樹}}$$

——**逐字相同** ✔。而該子樹在整棵樹中的位置沒變（$x$ 接替了 $p$ 原來的位置），故全樹中序序列不變 ✔。$\square$

**推論 1.1**：既然中序序列不變，**任何由中序位置定義的查詢（第 $k$ 個、區間 $[l,r]$）在旋轉前後都指向同一批元素。** splay 可以在任意時刻執行而不影響語義——這是後面所有操作的許可證。

**推論 1.2（維護順序）**：旋轉時 `pushUp` 必須**先算 $p$ 再算 $x$**（$p$ 變成了 $x$ 的子節點）。順序寫反，`sz` 就永遠差一截。

### 定理 2（splay 的正確性）

*操作*：`splay(x, goal)` 反覆旋轉，把 $x$ 移到 `goal` 的子節點位置（`goal = 0` 表示移到根）。每一步依 $x$、父 $p$、祖父 $g$ 的相對位置分三種情形：

| 情形 | 條件 | 動作 |
| --- | --- | --- |
| **zig** | $p$ 就是 `goal` 的子（$g$ 是 `goal`） | 轉 $x$ 一次 |
| **zig-zig** | $x$ 與 $p$ **同側** | **先轉 $p$，再轉 $x$** |
| **zig-zag** | $x$ 與 $p$ **異側** | 轉 $x$ 兩次 |

*正確性*：每一步之後 $x$ 的深度嚴格減少（zig 減 1，另兩者減 2），故有限步後 $x$ 到達目標位置 ✔；由定理 1，中序序列全程不變 ✔。$\square$

**關鍵前提：splay 之前必須把根到 $x$ 的路徑上所有標記 `pushDown` 完畢。** 否則旋轉會把「尚未生效的標記」搬到錯誤的子樹上。**實作上有兩種寫法**：往下找 $x$ 的過程中順手 `pushDown`（推薦），或在 splay 開始前用一個堆疊自頂向下推一遍。

### 定理 3（攤還 $O(\log n)$：Access Lemma）

**這是伸展樹存在的全部理由，也是本節最值得讀的一段。**

*勢能函數*：$\Phi = \sum_{x} r(x) = \sum_x \log_2 s(x)$。（$n$ 個節點時 $0 \le \Phi \le n\log_2 n$。）

**引理（Access Lemma）**：一次 `splay(x)` 到根的**攤還成本**至多為 $3\big(r(\mathrm{root}) - r(x)\big) + 1$，其中 $r$ 取操作**前**的值。

*證明*。逐步分析。記某一步之前的秩為 $r$、之後為 $r'$。

**zig-zig**（實際成本 2 次旋轉）。旋轉後 $x$ 佔據 $g$ 原來的位置，故 $s'(x) = s(g)$，即 $r'(x) = r(g)$。勢能只有 $x, p, g$ 三點改變：

$$\Delta\Phi = r'(x)+r'(p)+r'(g) - r(x)-r(p)-r(g) = r'(p)+r'(g)-r(x)-r(p).$$

由樹的包含關係 $r'(p) \le r'(x)$ 且 $r(p) \ge r(x)$，得

$$\Delta\Phi \;\le\; r'(x) + r'(g) - 2r(x).$$

**現在是關鍵一步。** 旋轉後 $x$ 的子樹包含了「$x$ 原來的子樹」與「$g$ 旋轉後的子樹」這兩塊互不相交的部分（外加 $p$ 本身），所以

$$s(x) + s'(g) \;\le\; s'(x).$$

由 $\log$ 的**凹性**（$\log a + \log b \le 2\log\frac{a+b}{2}$）：

$$r(x) + r'(g) \;\le\; 2\log_2\frac{s(x)+s'(g)}{2} \;\le\; 2\log_2\frac{s'(x)}{2} \;=\; 2r'(x) - 2.$$

於是攤還成本

$$2 + \Delta\Phi \;\le\; 2 + r'(x)+r'(g)-2r(x) \;=\; 2 + \underbrace{\big(r(x)+r'(g)-2r'(x)\big)}_{\le\,-2} + 3\big(r'(x)-r(x)\big) \;\le\; 3\big(r'(x)-r(x)\big).$$

**zig-zag**（實際成本 2）。同樣有 $r'(x) = r(g)$，且旋轉後 $p$ 與 $g$ 的子樹互不相交、聯集不超過 $x$ 的新子樹，故 $s'(p)+s'(g) \le s'(x)$，由凹性 $r'(p)+r'(g) \le 2r'(x)-2$。因此

$$2 + \Delta\Phi = 2 + r'(p)+r'(g)-r(x)-r(p) \le 2 + 2r'(x) - 2 - 2r(x) = 2\big(r'(x)-r(x)\big) \le 3\big(r'(x)-r(x)\big).$$

（用了 $r(p) \ge r(x)$。）

**zig**（實際成本 1，整個 splay 中至多發生一次）。$r'(p) \le r(p)$ 且 $r'(x) = r(\mathrm{root})$，故

$$1 + \Delta\Phi = 1 + r'(x)+r'(p)-r(x)-r(p) \le 1 + r'(x)-r(x) \le 1 + 3\big(r'(x)-r(x)\big).$$

**把所有步驟相加**：右側的 $3(r'(x)-r(x))$ 首尾相消（望遠鏡求和），只剩第一步的 $r(x)$ 與最後一步的 $r'(x) = r(\mathrm{root})$，再加上至多一次 zig 的 $+1$：

$$\text{總攤還成本} \;\le\; 3\big(r(\mathrm{root}) - r(x)\big) + 1 \;\le\; 3\log_2 n + 1. \qquad\square$$

**由於 $\Phi \ge 0$ 且初始 $\Phi \le n\log_2 n$，$m$ 次操作的總實際成本 $\le O\big((n+m)\log n\big)$** ✔。

**這個證明依賴的前提，每一條都要點名**：
1. **勢能函數選 $\sum\log s(x)$**——換成「節點數」或「高度」都證不出來。**$\log$ 的凹性是整個證明的引擎。**
2. **zig-zig 必須先轉 $p$ 再轉 $x$**（定理 4 說明為什麼）。
3. **這是攤還界，不是最壞界。** 單次操作可以是 $\Theta(n)$（例如對一條單鏈的最深節點做第一次 splay）。**題目若要求「每次操作都必須快」，伸展樹不合適。**

### 定理 4（為什麼 zig-zig 不能拆成兩次 zig）

*反例*。把 $n$ 個節點排成一條向左的單鏈（每個節點只有左子），對最深的節點 $x$ 做 splay。

- **正確的 zig-zig 做法**：每做一次 zig-zig，**整條鏈的深度大致減半**（$x$ 上方的路徑被摺疊）。$O(\log n)$ 次之後樹的高度就降到 $O(\log n)$，勢能大幅下降，付掉了這次昂貴的操作。
- **拆成兩次 zig（自底向上逐次旋轉）**：這等價於「把 $x$ 一路提到根」，**其餘節點的相對深度幾乎不變**——原來深度 $d$ 的節點變成深度 $d-1$ 或 $d$。樹仍然是一條長鏈。於是**下一次對新的最深節點 splay 又要 $\Theta(n)$**，反覆進行，總成本 $\Theta(mn)$。

**形式上**：定理 3 的 zig-zig 分析靠 $s(x) + s'(g) \le s'(x)$ 得到 $-2$ 的常數，正是「摺疊」帶來的勢能下降；兩次 zig 得不到這個不等式 ✔。$\square$

**這是伸展樹最違反直覺的地方**：一個看起來只是「換個旋轉順序」的細節，決定了 $O(\log n)$ 與 $O(n)$ 的差別。**寫的時候務必照著三種情形分類，不要「簡化」。**

### 定理 5（區間提取：把 $[l, r]$ 變成一棵子樹）

*操作*：`split(l, r)`——
1. 把**中序第 $l-1$ 個**節點（即哨兵偏移後的「$l$ 左邊那一個」）splay 到根；
2. 把**中序第 $r+1$ 個**節點 splay 到「根的子節點」位置（`splay(y, root)`）。

**命題**：此時 `t[t[root].ch[1]].ch[0]` 這棵子樹的中序序列，**恰好是原序列的 $[l, r]$**。

*證明*。設 $u$ = 第 $l-1$ 個、$v$ = 第 $r+1$ 個。步驟 1 後 $u$ 是根，由 BST（此處指「中序 = 序列」）性質，**所有中序位置 $> l-1$ 的節點都在 $u$ 的右子樹**。步驟 2 把 $v$ splay 到 $u$ 的右子（`splay(v, u)` 保證 $v$ 是 $u$ 的直接子節點，且仍在右側，因為 $v$ 的中序位置 $> u$）。於是 $v$ 的左子樹 = 「中序位置嚴格介於 $u$ 與 $v$ 之間」的所有節點 = 位置 $l$ 到 $r$ ✔。$\square$

**兩個哨兵是必要的，而且是這個定理的前提**：查 $[1, n]$ 時 $u$ 是「第 0 個」、$v$ 是「第 $n+1$ 個」，**若沒有哨兵，這兩個節點不存在，整個提取就失效。** 加了哨兵之後，`split` 對所有 $1 \le l \le r \le n$ 一律成立，**不需要任何特判**——這正是哨兵的價值。

**推論 5.1（提取之後就是線段樹）**：拿到子樹根 $z$ 後，
- **區間反轉** = `t[z].rev ^= 1`；
- **區間聚合** = 讀 $z$ 上維護的欄位；
- **區間刪除** = `t[v].ch[0] = 0; pushUp(v); pushUp(u);`；
- **區間插入** = 建好一棵樹掛到 `t[v].ch[0]`。

**全部 $O(1)$（不計 splay 的攤還成本）。這就是「序列平衡樹」的全部威力。**

### 定理 6（反轉標記的合法性）

*命題*：對一棵子樹打 `rev` 標記，等價於把它的中序序列整段反轉；且 `pushDown` 的「交換左右子 + 標記下傳」是正確的實作。

*證明*。設子樹根為 $z$，中序序列為 $L, z, R$（$L$、$R$ 分別是左右子樹的中序序列）。反轉後應為 $\mathrm{rev}(R),\, z,\, \mathrm{rev}(L)$。

而 `pushDown` 做的事是：把左右子**交換**（於是中序變成 $R, z, L$），再對兩棵子樹各打一個 `rev`（於是變成 $\mathrm{rev}(R), z, \mathrm{rev}(L)$）✔ —— **兩者一致。** $\square$

**這是 9.4 那個「分配律」條件的具體實例**：$\mathrm{rev}$ 對序列拼接滿足 $\mathrm{rev}(A \cdot B) = \mathrm{rev}(B)\cdot\mathrm{rev}(A)$。**注意它是反序的**——所以 `pushDown` 必須交換左右子，只下傳標記是不夠的。

**標記合成**：`rev ^= 1`，兩次反轉抵消 ✔（$\mathbb{Z}_2$，與 8.6 的 $\mathbb{Z}_2$ 帶權並查集是同一個群）。

**警告**：若子樹上還維護了**不對稱**的聚合（例如「最大前綴和」`pre` 與「最大後綴和」`suf`，見 9.3 定理 3），**`pushDown` 交換左右子時必須同時交換 `pre` 與 `suf`**。忘了這件事，反轉之後聚合值就悄悄錯了。

## C++17 模板

**完整的序列版伸展樹（支援：第 $k$ 個、任意位置插刪、區間反轉）：**

```cpp
struct SplaySeq {
    struct Node {
        int ch[2] = {0, 0}, fa = 0, sz = 0, val = 0;
        bool rev = false;
    };
    vector<Node> t;
    int root = 0;

    int newNode(int v) {
        t.push_back({{0, 0}, 0, 1, v, false});
        return int(t.size()) - 1;
    }
    void pushUp(int x) { t[x].sz = t[t[x].ch[0]].sz + t[t[x].ch[1]].sz + 1; }
    void pushDown(int x) {
        if (!t[x].rev) return;
        swap(t[x].ch[0], t[x].ch[1]);
        for (int c : {t[x].ch[0], t[x].ch[1]})
            if (c) t[c].rev = !t[c].rev;
        t[x].rev = false;
    }
    int side(int x) const { return t[t[x].fa].ch[1] == x; }  // x 是父的哪一側

    void rotate(int x) {
        int p = t[x].fa, g = t[p].fa, k = side(x), c = t[x].ch[k ^ 1];
        if (g) t[g].ch[side(p)] = x;
        t[x].fa = g;
        t[x].ch[k ^ 1] = p;
        t[p].fa = x;
        t[p].ch[k] = c;
        if (c) t[c].fa = p;
        pushUp(p);
        pushUp(x);  // 先 p 後 x（推論 1.2）
    }
    // 把 x 轉到 goal 的子節點；goal = 0 表示轉到根
    void splay(int x, int goal = 0) {
        while (t[x].fa != goal) {
            int p = t[x].fa, g = t[p].fa;
            if (g != goal)
                rotate(side(x) == side(p) ? p : x);  // zig-zig 先轉 p（定理 4）
            rotate(x);
        }
        if (goal == 0) root = x;
    }
    // 中序第 k 個（1-indexed，含哨兵）
    int kth(int k) {
        int x = root;
        while (true) {
            pushDown(x);  // 下降途中順手下傳（定理 2 前提）
            int ls = t[t[x].ch[0]].sz;
            if (k <= ls)
                x = t[x].ch[0];
            else if (k == ls + 1)
                return x;
            else {
                k -= ls + 1;
                x = t[x].ch[1];
            }
        }
    }
    // 提取原序列的 [l, r]（1-indexed，不含哨兵），回傳該子樹的根
    int split(int l, int r) {
        int u = kth(l), v = kth(r + 2);  // 哨兵偏移：+0 與 +2
        splay(u);
        splay(v, u);
        return t[v].ch[0];
    }

    // 由陣列建樹（含頭尾哨兵），O(n)
    int build(const vector<int>& a, int lo, int hi) {  // 建 a[lo..hi]
        if (lo > hi) return 0;
        int mid = lo + (hi - lo) / 2, x = newNode(a[mid]);
        t[x].ch[0] = build(a, lo, mid - 1);
        t[x].ch[1] = build(a, mid + 1, hi);
        for (int c : {t[x].ch[0], t[x].ch[1]})
            if (c) t[c].fa = x;
        pushUp(x);
        return x;
    }
    explicit SplaySeq(const vector<int>& a) {
        t.reserve(a.size() + 4);
        t.emplace_back();  // t[0] 空節點，sz = 0
        vector<int> b;
        b.reserve(a.size() + 2);
        b.push_back(0);  // 前哨兵
        b.insert(b.end(), a.begin(), a.end());
        b.push_back(0);  // 後哨兵
        root = build(b, 0, int(b.size()) - 1);
    }

    void reverse(int l, int r) {
        int z = split(l, r);
        t[z].rev = !t[z].rev;
    }
    int at(int k) {
        int x = kth(k + 1);
        splay(x);
        return t[x].val;
    }
    void insertAfter(int pos, int v) {  // 在第 pos 個之後插入
        int u = kth(pos + 1), w = kth(pos + 2);
        splay(u);
        splay(w, u);
        int x = newNode(v);
        t[w].ch[0] = x;
        t[x].fa = w;
        pushUp(w);
        pushUp(u);
    }
    void erase(int l, int r) {  // 刪除 [l, r]
        split(l, r);
        int v = t[root].ch[1];
        t[v].ch[0] = 0;
        pushUp(v);
        pushUp(root);
    }
};
```

**四個「照抄就對、改了就錯」的細節**：
- `rotate` 裡 **`pushUp(p)` 在 `pushUp(x)` 之前**；
- `splay` 裡 zig-zig 判斷用 `side(x) == side(p)` 並**先轉 `p`**；
- `kth` **每一步都 `pushDown`**；
- `split` 的下標偏移是 **`kth(l)` 與 `kth(r+2)`**（因為前哨兵佔了中序第 1 位，原序列第 $i$ 個是中序第 $i+1$ 個，所以「$l$ 的前一個」是中序第 $l$、「$r$ 的後一個」是中序第 $r+2$）。

**`at()` 之後為什麼要 `splay(x)`？** 不 splay 也能得到正確答案，但**定理 3 的攤還保證就沒了**——勢能不會下降，樹會保持退化。**「訪問後必須 splay」是伸展樹的紀律，不是可選的優化。**

## 時間與空間複雜度

| 操作 | 複雜度 |
| --- | --- |
| `build`（由陣列建樹） | $O(n)$，樹高 $O(\log n)$ |
| `kth` / `at` / `insertAfter` / `erase` / `reverse` | **攤還** $O(\log n)$ |
| 單次操作的最壞情形 | $O(n)$ |
| 空間 | $O(n)$ |

**「攤還」三個字必須認真對待**（定理 3 的第三個前提）。$m$ 次操作總計 $O((n+m)\log n)$，但**任何單次操作都可能是 $\Theta(n)$**。互動式、有時限的線上系統要小心；競賽題只看總時間，所以無妨。

**常數很大**：每次操作要走一遍路徑再轉一遍回來，`pushDown`／`pushUp` 反覆呼叫，指標跳躍對快取極不友善。**實測常常比同複雜度的線段樹慢 3–5 倍。**

**各題的實際規模**：

| 題目 | 規模 | 實際建議 |
| --- | --- | --- |
| 2296 設計文字編輯器 | $\le 2\times10^4$ 次呼叫 | **兩個堆疊，$O(1)$ 攤還**——見下節 |
| 3526 | — | 先確認是否真的需要中間插刪 |

**誠實的結論：本節的兩題都不需要伸展樹。** 學它是為了「序列平衡樹」這個想法與勢能法的範例；**真要在競賽中寫平衡樹，FHQ Treap 是更好的選擇**（見下節）。

## 常見錯誤與邊界條件

- **`fa` 沒更新完整**。`rotate` 要改動三處父指標（$x \to g$、$p \to x$、$c \to p$），**加上 $g$ 的子指標**。漏任何一處，樹就斷了，而且症狀往往是無窮迴圈而非崩潰。
- **`rotate` 裡 `pushUp` 順序寫反**（推論 1.2）。必須先 $p$ 後 $x$。
- **zig-zig 拆成兩次 zig**（定理 4）。功能正確，複雜度退化到 $O(n)$ 攤還。**測資大才會暴露，最陰險的一種錯。**
- **splay 前沒 `pushDown`**（定理 2 前提）。標記被旋轉搬到錯誤的子樹上，答案錯得毫無規律。**在 `kth` 的下降迴圈裡 `pushDown` 是最省事的寫法。**
- **忘了哨兵，或哨兵偏移算錯**（定理 5）。`split(1, n)` 會直接越界。**寫個註解標明「原序列第 $i$ 個 = 中序第 $i+1$ 個」。**
- **哨兵被算進聚合**。哨兵的 `val` 要設成單位元（求和設 0、求 max 設 $-\infty$），否則區間聚合被污染。**本節模板的 `sz` 也包含哨兵，所以 `split` 依賴的是中序位置而非「有效元素個數」——兩者不要混用。**
- **`reverse` 之後忘了交換不對稱的聚合欄位**（定理 6 的警告）。`pre`／`suf`、「最左的某某」這類欄位都要在 `pushDown` 交換左右子時一起換。
- **訪問後不 splay**。攤還保證失效。
- **`t.push_back` 之後持有舊參考**。與 9.6 同一個坑：`vector` 擴容會使參考失效。**全程用下標。**
- **`erase` 之後節點沒回收**。競賽中通常不回收（空間 $O(\text{總插入數})$ 即可）；但若插刪次數極多，要維護一個空閒節點池。
- **遞迴 `build` 的深度**。$O(\log n)$，安全；但若改成「逐個 `insert` 建樹」就是 $O(n\log n)$ 且更慢。**能一次建好就一次建好。**

## 與相似技巧的比較

- **與 FHQ Treap（無旋 Treap）**：**同樣的能力，程式碼短一半，而且好懂得多。** 它用 `split`／`merge` 兩個函式取代 splay 的三種情形，不需要父指標，複雜度是**期望** $O(\log n)$（隨機優先級）而非攤還。**唯一的取捨：FHQ 是遞迴的，常數略大；而伸展樹能做「可持久化以外」的一些花招（LCT 的基礎）。實務上先寫 FHQ Treap。**
- **與 9.3／9.4 線段樹**：**線段樹的下標是固定的，伸展樹的位置是動態的。** 只要序列長度不變、不需要插刪與重排，**線段樹在每個維度都更好**：常數小、非攤還的 $O(\log n)$、易寫易除錯。**看到「插入／刪除／反轉」才考慮平衡樹。**
- **與 9.1 樹狀陣列 + 二分**：若「刪除」可以用「標記為已刪」代替（元素不真的消失，只是不計入），那麼「第 $k$ 個未刪元素」可以用樹狀陣列上二分 $O(\log n)$ 解決（9.1 的 `kth`）。**這覆蓋了相當多看似需要平衡樹的題目，而且快得多。先問：真的需要插入嗎，還是只需要刪除？**
- **與兩個堆疊（2296 的正解）**：文字編輯器的游標只會**左右移動一格**、在游標處插刪。用 `left`、`right` 兩個堆疊表示游標兩側的字元，「左移」= 從 `left` 彈出推入 `right`，插入 = 推入 `left`。**每次操作攤還 $O(1)$，程式十行。** **這是「認清問題的真正約束」勝過「搬出強大工具」的典型例子——游標局部移動這個限制，把平衡樹問題降級成了堆疊問題。**
- **與 `std::rope`（GCC 的 `__gnu_cxx::rope`）**：內部就是平衡樹，支援 $O(\log n)$ 的字串插刪與拼接。**能用就用，但 LeetCode 上不保證可用，且不支援自訂聚合。**
- **與 8 節並查集的攤還分析**：兩者都用勢能法，但 DSU 的勢能是「秩」而伸展樹的是「$\log$ 子樹大小」。**共同點是那個反覆出現的模式：昂貴的操作必然伴隨結構的不可逆改善，而改善的總量有上界。** 本章第八次見到它了。
- **與 LCT（Link-Cut Tree）**：LCT 就是「一堆伸展樹 + 虛實邊」，用來維護動態樹。**伸展樹的攤還分析（定理 3）是 LCT 複雜度證明的基石**——這是學伸展樹最實在的長期回報。

## 本節重點速查

- **核心轉念**：**中序走訪序列 = 陣列。** 鍵不是值而是位置，位置由 `sz` 隱含決定。
- **四個約定**：`t[0]` 是 `sz=0` 的哨兵；必須存 `fa`；頭尾各加一個哨兵節點（定理 5 的前提）；`rev` 的語義是「自己好了、子樹還沒」。
- **定理 1**：旋轉保持中序序列 ⇒ splay 隨時可做。**`rotate` 裡先 `pushUp(p)` 再 `pushUp(x)`。**
- **定理 3（Access Lemma）**：勢能 $\Phi=\sum\log_2 s(x)$，一次 splay 攤還 $\le 3(r(\mathrm{root})-r(x))+1 \le 3\log_2 n + 1$。**引擎是 $\log$ 的凹性**：zig-zig 由 $s(x)+s'(g)\le s'(x)$ 擠出 $-2$。**這是攤還界，單次可以是 $\Theta(n)$。**
- **定理 4**：**zig-zig 必須先轉父再轉自己。** 拆成兩次 zig 會讓單鏈永遠是單鏈，退化成 $O(n)$ 攤還——功能正確、複雜度爆炸，最陰險的錯。
- **定理 5（區間提取）**：`splay(第 l-1 個)` 到根、`splay(第 r+1 個)` 到根的子 ⇒ 後者的左子樹恰為 $[l,r]$。**哨兵讓這件事對所有 $l,r$ 無特判成立。** 提取後打標記、刪除、插入全是 $O(1)$。
- **定理 6（反轉標記）**：$\mathrm{rev}(A\cdot B)=\mathrm{rev}(B)\cdot\mathrm{rev}(A)$ ⇒ `pushDown` 必須**交換左右子**再下傳；標記在 $\mathbb{Z}_2$ 上合成。**不對稱的聚合欄位（`pre`／`suf`）也要一起交換。**
- **splay 前必須 `pushDown` 整條路徑；訪問後必須 splay**（否則攤還保證失效）。
- **實務選擇**：不需插刪 ⇒ 線段樹；只需刪除 ⇒ 樹狀陣列上二分；真要平衡樹 ⇒ **FHQ Treap 更短更好懂**；2296 這種游標局部移動 ⇒ **兩個堆疊，$O(1)$**。**學伸展樹主要是為了 LCT 與這個勢能法範例。**
