## 這個技術解決什麼問題

線段樹（9 節）很強，但它有一個硬性代價：**你維護的摘要必須可合併**——兩個子區間的摘要要能 $O(1)$ 併成父區間的摘要（9.3 要求么半群）。

可是很多摘要根本不可合併：

- 「區間內小於 $x$ 的元素有幾個？」——左右兩半各自的答案沒辦法合併成整體的答案；
- 「區間內出現次數最多的元素是哪個？」——眾數不可合併（左半的眾數 + 右半的眾數 $\ne$ 整體的眾數）；
- 「區間內有幾個不同的值？」——同樣不可合併。

**根號分解（分塊）用一句話繞開這個限制：**

> **把序列切成大小約 $\sqrt n$ 的塊。整塊有預先算好的摘要，零頭直接暴力。**

於是一次區間操作只碰 $O(\sqrt n)$ 個整塊與 $O(\sqrt n)$ 個零頭元素，總計 $O(\sqrt n)$。

**它換到了什麼？** 關鍵洞察是：

> **線段樹要求「摘要之間可合併」；分塊只要求「單塊的摘要能回答關於這一塊的問題」。** 摘要彼此不必有任何代數關係——**每塊各自排序、各自開一張頻次表都行。**

**這是分塊真正的價值，也是它值得學的唯一理由。** 光是「區間和」，線段樹在每個維度都比分塊好。

**辨識訊號**：
- 同時有修改與區間查詢，但**要維護的摘要很怪，線段樹不好寫，塊內卻可以暴力**（每塊排序、每塊一張頻次表）；
- $n$、$q$ 都在 $10^5$ 等級，$O(nq)$ 會超時而 $O((n+q)\sqrt n)$（約 $3\times10^7$）剛好能過；
- 題目帶了一個**參數**，該參數大時暴力就快、小時可以預處理（1714 特殊等間距元素和——見定理 3）；
- 需要區間操作又要查詢的怪組合（3655 區間乘法查詢後的異或 II、3400、LCP 16）。

**「$O(\sqrt n)$ 剛好能過」不是巧合**：出題者若想卡掉 $O(n\log n)$ 又不想卡死暴力，$n = 10^5$ 這個規模正是分塊的舒適區。**看到 $n, q \le 10^5$ 而題目摘要又很怪，就該想到分塊。**

## 狀態／資料結構定義

**三個座標換算函式，整節都靠它們：**

```cpp
int s;   // 塊長
int nb;  // 塊數 = (n + s - 1) / s
int bel(int i) const {
    return i / s;
}  // 元素 i 屬於哪一塊
int lo(int b) const {
    return b * s;
}  // 第 b 塊的左界（含）
int hi(int b) const {
    return min(n, (b + 1) * s);
}  // 第 b 塊的右界（不含）
```

**`hi` 必須夾住 `n`**——最後一塊通常不滿。**這是分塊最高頻的越界來源。**

**每塊維護什麼，因題而異。** 三種最常見的形態：

| 要回答的問題 | 每塊維護 | 整塊查詢 | 單點修改後的重建 |
| --- | --- | --- | --- |
| 區間和（帶區間加） | `sum[b]`、`add[b]` | $O(1)$ | $O(1)$ |
| 區間內 $< x$ 的個數 | **塊內排序副本** `srt[b]` | $O(\log s)$ 二分 | $O(s)$ 或 $O(\log s)$（插入排序） |
| 區間眾數／不同值個數 | **塊內頻次表** | $O(1)$ | $O(1)$ |

**帶區間加時的核心不變量（定理 4）：**

> **元素 $i$ 的真實值 $= \mathit{raw}[i] + \mathit{add}[\mathit{bel}(i)]$。**

**整塊修改只動 `add[b]`（$O(1)$）；零頭修改直接動 `raw[i]`（不碰 `add`）。** 這樣就永遠不需要「下傳標記」——**分塊沒有 `pushDown`，因為標記只有一層。**

## 不變量或正確性證明

以下記序列長度 $n$、塊長 $s$、塊數 $B = \lceil n/s\rceil$。

### 定理 1（塊長的最優選擇：$\sqrt n$ 只是特例）

*設定*：設單次操作的代價為

$$T(s) \;=\; a\cdot\frac{n}{s} \;+\; b\cdot s,$$

其中 $a$ 是「處理一個整塊」的代價、$b$ 是「處理一個零頭元素」的代價。

*命題*：$T$ 在 $s^\star = \sqrt{an/b}$ 取最小值 $2\sqrt{abn}$。

*證明*。由 AM–GM，$\frac{an}{s} + bs \ge 2\sqrt{\frac{an}{s}\cdot bs} = 2\sqrt{abn}$，等號成立當且僅當 $\frac{an}{s} = bs$，即 $s = \sqrt{an/b}$ ✔。$\square$

**$a = b$ 時才得到 $s = \sqrt n$。而 $a \ne b$ 的情形非常常見**：

**情形一：修改與查詢的代價不對稱。** 設有 $q_u$ 次修改（每次 $O(s)$，例如塊內重新排序）與 $q_v$ 次查詢（每次 $O(n/s)$）。總代價

$$q_u \cdot s + q_v \cdot \frac{n}{s} \quad\Longrightarrow\quad s^\star = \sqrt{\frac{q_v\, n}{q_u}}.$$

**修改多、查詢少 ⇒ 塊要小；查詢多、修改少 ⇒ 塊要大。** 盲目寫 `s = sqrt(n)` 在極端比例下會慢好幾倍。

**情形二：整塊操作帶 $\log$。** 塊內排序後二分是 $O(\log s)$，於是 $T(s) = \frac{n}{s}\log s + s$，最優塊長略大於 $\sqrt n$（約 $\sqrt{n\log n}$）。

**實務建議**：`s = max(1, (int)sqrt(n))` 起手，**若 TLE 就把 `s` 當成可調參數試 $\sqrt{n}/2$、$2\sqrt n$**。這不是玄學——定理 1 說明了 $T(s)$ 在最小值附近是平緩的（$T(2s^\star) = 1.25\,T(s^\star)$），所以粗調就夠，但差一個數量級就會有感。

### 定理 2（區間分解：與線段樹的對照）

*命題*：任意區間 $[l, r]$ 可**不重不漏**地分解成
- 至多 2 段零頭（$l$ 所在塊的一部分、$r$ 所在塊的一部分），共 $< 2s$ 個元素；
- 至多 $B$ 個完整塊。

*證明*。設 $b_l = \mathit{bel}(l)$、$b_r = \mathit{bel}(r)$。
- 若 $b_l = b_r$：整段落在同一塊內，$< s$ 個元素，**必須特判為單一段暴力** ✔（這是分塊最經典的邊界，見「常見錯誤」）。
- 否則：$[l,\,\mathit{hi}(b_l))$ 是左零頭、$[\mathit{lo}(b_r),\, r]$ 是右零頭、中間的塊 $b_l+1 \dots b_r-1$ 是完整塊。三部分兩兩不交、聯集為 $[l,r]$ ✔。$\square$

**與 9.3 定理 2 的對照，是理解分塊的關鍵：**

| | 段數 | 每段的摘要要求 |
| --- | --- | --- |
| 線段樹 | $O(\log n)$ | **必須可合併**（么半群） |
| 分塊 | $O(\sqrt n)$ | **只要能回答關於自己的子問題** |

**分塊用更多的段數，換來對摘要形態的完全自由。** 這個交換在「摘要可合併」時是純虧本，在「摘要不可合併」時是唯一出路。**每次考慮分塊，先問自己：我的摘要真的不可合併嗎？**

### 定理 3（1714：對「參數」分塊，而非對陣列分塊）

*問題*：給定陣列 $\mathit{nums}$（長度 $n$）與 $q$ 個查詢 $(x, y)$，求 $\mathit{nums}[x] + \mathit{nums}[x+y] + \mathit{nums}[x+2y] + \cdots$（下標 $< n$），對 $10^9+7$ 取模。

*天真做法*：每個查詢 $O(n/y)$。**$y = 1$ 時是 $O(n)$，$q$ 個這種查詢就是 $O(nq) = 10^{10}$。**

**根號的想法**：**分界點放在 $y$ 上，而不是放在陣列上。**

- **若 $y \ge \sqrt n$**：直接暴力，迴圈次數 $\le n/y \le \sqrt n$ ✔。
- **若 $y < \sqrt n$**：預處理 $f[y][x] = \mathit{nums}[x] + f[y][x+y]$（由 $x$ 從大到小遞推），查詢 $O(1)$。

*複雜度*。預處理只對 $y = 1 \dots \lfloor\sqrt n\rfloor - 1$ 做，每個 $y$ 花 $O(n)$，共 $O(n\sqrt n)$ 時間與空間。查詢共 $O(q\sqrt n)$。**總計 $O((n+q)\sqrt n)$** ✔。

*為什麼分界點在 $\sqrt n$*：暴力側的代價是 $n/y$（$y$ 越大越便宜），預處理側的代價是 $y_{\max}\cdot n$（$y_{\max}$ 越小越便宜）。令 $n/y_{\max} = y_{\max}$ 得 $y_{\max} = \sqrt n$ ✔——**這就是定理 1 的同一個平衡，只是套在不同的變數上。**

**這個形態值得單獨記住**：

> **「小的情形預處理，大的情形暴力，分界點取在兩側代價相等處。」**

**它不需要「塊」這個概念，只需要一個參數與一個單調的取捨。** 調和級數型的問題（枚舉倍數）、「出現次數 $> \sqrt n$ 的元素至多 $\sqrt n$ 種」（重元素／輕元素分治）都屬於這一族。

**空間要小心**：$f$ 是 $\sqrt n \times n$ 的表，$n = 5\times10^4$ 時約 $223 \times 5\times10^4 \approx 1.1\times10^7$ 個 `int` = **45 MB**。**這是 1714 的真正瓶頸，不是時間。** 可以只對 $y < \sqrt{n}/2$ 預處理來換空間（定理 1 說代價只上升常數倍）。

### 定理 4（區間加、區間求和的不變量）

**不變量 (R)**：*對每個 $i$，元素的真實值為 $\mathit{raw}[i] + \mathit{add}[\mathit{bel}(i)]$；且對每一塊 $b$，$\mathit{sum}[b] = \sum_{i \in b} \mathit{raw}[i]$。*

（注意 $\mathit{sum}[b]$ **不含** `add`——真實塊和是 $\mathit{sum}[b] + \mathit{add}[b]\cdot|b|$。這個選擇讓零頭修改不必碰 `add`。）

*維護*。區間加 $(\,[l,r],\,v\,)$：
- **整塊 $b$**：`add[b] += v`。$\mathit{raw}$ 不變 ⇒ (R) 的第二式成立 ✔；每個 $i \in b$ 的真實值都增加了 $v$ ✔。
- **零頭 $i$**：`raw[i] += v; sum[bel(i)] += v;`。第二式同步更新 ✔；真實值 $= \mathit{raw}[i]+v+\mathit{add}[\cdot]$，正確增加 $v$ ✔。**注意這裡沒有動 `add[bel(i)]`，所以同塊其他元素不受影響** ✔。

*區間和查詢*：整塊貢獻 $\mathit{sum}[b] + \mathit{add}[b]\cdot(\mathit{hi}(b)-\mathit{lo}(b))$，零頭貢獻 $\mathit{raw}[i]+\mathit{add}[\mathit{bel}(i)]$。由 (R) 與定理 2 的不重不漏，總和正確 ✔。$\square$

**「標記只有一層，所以不需要 `pushDown`」是分塊相對線段樹最舒服的地方。** 9.4 的分配律、標記合成、下傳順序在這裡全部消失——**代價只是把 $\log n$ 換成 $\sqrt n$。** 寫錯機率大幅下降。

**推論 4.1**：這個不變量對任何「整塊 $O(1)$ 可套用、零頭 $O(1)$ 可直接改」的標記都成立（區間加、區間賦值、區間乘）。**區間賦值時要小心**：`assign[b]` 生效後，塊內 `raw` 的個別值就失去意義了，讀零頭前必須先把 `assign[b]` **實際展開**到 `raw`（$O(s)$）——**這是分塊版的 `pushDown`，而且因為只有一層，它一定終止。**

### 定理 5（塊內排序：不可合併摘要的典型）

*問題*：帶單點修改，查詢「區間 $[l,r]$ 內 $< x$ 的元素個數」。

*結構*：每塊額外維護一份**排序後的副本** `srt[b]`。

*查詢*：整塊用 `lower_bound(srt[b], x)` 得 $O(\log s)$；零頭逐個比較 $O(s)$。總計 $O\big(\frac{n}{s}\log s + s\big)$。

*修改* $a[i] \gets v$：塊 $\mathit{bel}(i)$ 的排序副本要更新。$O(s)$ 重建，或用「刪一個插一個」的 $O(s)$ 搬移（`std::rotate`，常數極小）。

*正確性*：由定理 2，$[l,r]$ 被不重不漏地覆蓋；每塊內的計數與零頭的計數相加即為總數 ✔——**這裡完全沒有「合併兩個答案」這件事，只有「把互不相交的計數加起來」。** 這正是分塊能做而線段樹難做的原因：**計數本身是可加的，但「小於 $x$ 的個數」這個摘要在合併時需要知道 $x$，而 $x$ 是查詢時才給的。**

**這句話值得展開**：線段樹**也**能做這題——每個節點掛一個排序陣列（歸併樹），或用 9.6 的主席樹。**但歸併樹的空間是 $O(n\log n)$、不支援修改；主席樹也不支援修改。分塊是三者中唯一支援修改的。**

*塊長選擇*：$T(s) = \frac{n}{s}\log s + s$（查詢）與 $s$（修改）。**若修改遠多於查詢，就把 $s$ 調小**（定理 1 情形一）。

### 定理 6（定期重建：讓「插入」也能分塊）

*問題*：分塊假設下標固定，插入會讓後面所有元素移位。

*做法*：改用 `vector<vector<int>> blocks`——每塊是一個獨立的 `vector`。插入時找到目標塊，在塊內 `insert`（$O(s)$）；**當某塊的大小超過 $2s$ 時，把它裂成兩塊**；**每進行 $\Theta(s)$ 次操作就全域重建一次**（把所有塊攤平再重新均分，$O(n)$）。

*攤還分析*：全域重建每 $\Theta(s)$ 次操作發生一次，攤還成本 $O(n/s)$；單次插入 $O(s)$（塊內搬移）加上找塊的 $O(n/s)$。取 $s = \sqrt n$ 得**每次操作攤還 $O(\sqrt n)$** ✔。

**這與 10.1 的平衡樹解決同一個問題**（序列的中間插刪），但**分塊版好寫十倍、常數小、且天然支援「塊內任意暴力」**。代價是 $O(\sqrt n)$ 而非 $O(\log n)$。**$n \le 10^5$ 時這個交換通常划算。**

**「定期重建」是根號思想的第三種形態**（前兩種是「對陣列分塊」與「對參數分塊」）：**把昂貴的整理工作攤到 $\sqrt n$ 次操作上。** 它與 4.7 單調堆疊、6.6 懶刪除堆、8.5 區間並查集的攤還是同一個家族——**昂貴的動作對應一個有上界的總量。本章第九次。**

## C++17 模板

**模板一：區間加、區間求和（定理 4 的不變量）**

```cpp
struct BlockSum {
    int n, s, nb;
    vector<long long> raw, sum, add;
    explicit BlockSum(const vector<int>& a) : n(int(a.size())) {
        s = max(1, int(sqrt(double(n))));
        nb = (n + s - 1) / s;
        raw.assign(a.begin(), a.end());
        sum.assign(nb, 0);
        add.assign(nb, 0);
        for (int i = 0; i < n; i++) sum[i / s] += raw[i];
    }
    int lo(int b) const { return b * s; }
    int hi(int b) const { return min(n, (b + 1) * s); }

    void update(int l, int r, long long v) {  // [l, r] 皆含
        int bl = l / s, br = r / s;
        if (bl == br) {  // 同塊：全部當零頭（定理 2）
            for (int i = l; i <= r; i++) raw[i] += v;
            sum[bl] += v * (r - l + 1);
            return;
        }
        for (int i = l; i < hi(bl); i++) raw[i] += v;
        sum[bl] += v * (hi(bl) - l);
        for (int i = lo(br); i <= r; i++) raw[i] += v;
        sum[br] += v * (r - lo(br) + 1);
        for (int b = bl + 1; b < br; b++) add[b] += v;  // 整塊：O(1)
    }
    long long query(int l, int r) const {
        int bl = l / s, br = r / s;
        long long res = 0;
        if (bl == br) {
            for (int i = l; i <= r; i++) res += raw[i];
            return res + add[bl] * (r - l + 1);
        }
        for (int i = l; i < hi(bl); i++) res += raw[i];
        res += add[bl] * (hi(bl) - l);
        for (int i = lo(br); i <= r; i++) res += raw[i];
        res += add[br] * (r - lo(br) + 1);
        for (int b = bl + 1; b < br; b++)
            res += sum[b] + add[b] * (hi(b) - lo(b));
        return res;
    }
};
```

**`bl == br` 的特判不可省。** 不特判的話，左零頭會跑到 `hi(bl)`（超過 $r$），右零頭又從 `lo(br)` 開始（小於 $l$）——**同一批元素被算兩次，而且還多算了區間外的。**

**模板二：塊內排序，查區間內 $< x$ 的個數（定理 5）**

```cpp
struct BlockSorted {
    int n, s, nb;
    vector<int> a;
    vector<vector<int>> srt;
    explicit BlockSorted(vector<int> a_) : n(int(a_.size())), a(move(a_)) {
        s = max(1, int(sqrt(double(n))));
        nb = (n + s - 1) / s;
        srt.resize(nb);
        for (int b = 0; b < nb; b++) {
            srt[b].assign(a.begin() + b * s, a.begin() + min(n, (b + 1) * s));
            sort(srt[b].begin(), srt[b].end());
        }
    }
    void set(int i, int v) {  // 單點賦值，O(s)
        int b = i / s;
        auto& v2 = srt[b];
        v2.erase(lower_bound(v2.begin(), v2.end(), a[i]));
        v2.insert(lower_bound(v2.begin(), v2.end(), v), v);
        a[i] = v;
    }
    int countLess(int l, int r, int x) const {
        int bl = l / s, br = r / s, res = 0;
        auto brute = [&](int lo2, int hi2) {
            for (int i = lo2; i <= hi2; i++) res += (a[i] < x);
        };
        if (bl == br) {
            brute(l, r);
            return res;
        }
        brute(l, min(n, (bl + 1) * s) - 1);
        brute(br * s, r);
        for (int b = bl + 1; b < br; b++)
            res += int(lower_bound(srt[b].begin(), srt[b].end(), x) -
                       srt[b].begin());
        return res;
    }
};
```

**`set` 用 `erase` + `insert` 而非重新 `sort`**：兩者都是 $O(s)$，但前者只做記憶體搬移，常數小一個數量級。

**模板三：對參數分塊（1714，定理 3）**

```cpp
class Solution {
public:
    vector<int> solve(vector<int>& nums, vector<vector<int>>& queries) {
        const long long MOD = 1'000'000'007;
        int n = int(nums.size());
        int S = max(1, int(sqrt(double(n))));  // 分界點
        // f[y][x] = nums[x] + nums[x+y] + ...，只對 y < S 預處理
        vector<vector<int>> f(S, vector<int>(n + 1, 0));
        for (int y = 1; y < S; y++)
            for (int x = n - 1; x >= 0; x--)
                f[y][x] = int((nums[x] + (x + y < n ? f[y][x + y] : 0)) % MOD);
        vector<int> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            int x = q[0], y = q[1];
            if (y < S) {
                ans.push_back(f[y][x]);
                continue;
            }
            long long t = 0;
            for (int i = x; i < n; i += y) t += nums[i];  // 至多 n/y <= S 次
            ans.push_back(int(t % MOD));
        }
        return ans;
    }
};
```

**`f` 的第一維是 `S` 而非 `n`——這是空間能否過關的關鍵**（定理 3 的空間試算）。

## 時間與空間複雜度

令塊長 $s$、塊數 $B = \lceil n/s\rceil$。

| 操作 | 一般式 | 取 $s=\sqrt n$ |
| --- | --- | --- |
| 區間加 / 區間和 | $O(n/s + s)$ | $O(\sqrt n)$ |
| 區間內 $<x$ 的個數 | $O\big(\frac{n}{s}\log s + s\big)$ | $O(\sqrt n\log n)$ |
| 單點修改（帶塊內排序） | $O(s)$ | $O(\sqrt n)$ |
| 帶插入的序列（定理 6） | 攤還 $O(n/s + s)$ | 攤還 $O(\sqrt n)$ |
| 建表 | $O(n)$ 或 $O(n\log s)$（要排序） | — |
| 空間 | $O(n + B)$ | $O(n)$ |

**$n = q = 10^5$ 時 $O((n+q)\sqrt n) \approx 6.3\times10^7$ 次基本運算**——在 1 秒的限制內，只要常數小（連續記憶體、無指標跳躍）就能過。**分塊的常數通常比線段樹小，這部分抵消了複雜度的劣勢。**

**與線段樹的實際交叉點**：$\sqrt n$ vs $\log n$ 在 $n = 10^5$ 是 316 vs 17，**理論上差 18 倍，實測常常只差 3–5 倍**（快取友善 + 無遞迴）。**但 $n$ 上到 $10^6$ 就是 1000 vs 20，分塊必敗。**

**1714 的空間**（定理 3）：$S \times n$ 個 `int`，$n = 5\times10^4$ ⇒ 約 45 MB。**這題的瓶頸在空間，不在時間。**

## 常見錯誤與邊界條件

- **忘了 `bl == br` 的特判**（定理 2）。這是分塊的頭號錯誤：左右零頭會重疊並越界。**每個分塊函式的第一行就寫這個特判。**
- **`hi(b)` 沒有夾住 `n`**。最後一塊不滿，`(b+1)*s` 會超過 `n`。**寫成 `min(n, (b+1)*s)`。**
- **`s = 0`**。$n = 0$ 或 $n$ 很小時 `sqrt(n)` 可能是 0，除以 0 直接崩潰。**一律 `s = max(1, ...)`。**
- **塊數算成 `n / s`**。必須是 `(n + s - 1) / s`，否則最後一塊被漏掉。
- **`sum[b]` 的語義沒定清楚**（定理 4）。本節約定 $\mathit{sum}[b]$ **不含** `add`；若改成「含」，則零頭修改也要動 `add`，兩種寫法不能混。**在結構體上方寫一行註解說明語義。**
- **區間賦值忘了先展開標記**（推論 4.1）。`assign[b]` 生效後直接讀 `raw[i]` 會讀到過期的值。
- **修改後忘了維護塊內摘要**。改 `a[i]` 卻沒更新 `srt[bel(i)]` 或頻次表，之後所有整塊查詢都錯。**把「改元素」封裝成唯一入口，不要讓外部直接寫 `a[i]`。**
- **盲目用 `s = sqrt(n)`**（定理 1）。修改與查詢代價不對稱時最優塊長不是 $\sqrt n$。**TLE 時第一件事就是調 `s`。**
- **`long long` 溢位**。$n = 10^5$、值域 $10^9$、區間加 $10^5$ 次 ⇒ 塊和可達 $10^{19}$，**`long long` 也可能不夠**，必要時取模或用 `__int128`。
- **1714 的預處理表開成 `n × n`**。空間直接爆。**第一維必須是 $\sqrt n$。**
- **對參數分塊時分界點兩側漏掉一個**（定理 3）。若預處理 $y < S$、暴力 $y \ge S$，兩者必須恰好覆蓋所有 $y \ge 1$。**寫成 `if (y < S) 查表; else 暴力;`，不要用 `<=` 與 `>` 這種容易寫錯的組合。**

## 與相似技巧的比較

- **與 9.3／9.4 線段樹**：**摘要可合併就用線段樹**——$O(\log n)$ 完勝 $O(\sqrt n)$，而且空間更小。**分塊只在摘要不可合併時才有存在意義**（定理 2 的對照表）。實務上的判準：如果你能寫出 `Info operator+(Info, Info)`，就別用分塊。
- **與 11.2 莫隊**：兩者都是根號，但**莫隊要求離線**、代價是 $O((n+q)\sqrt n)$ 的**總**時間；分塊支援線上、每次操作 $O(\sqrt n)$。**莫隊處理「大量區間查詢、答案靠增量維護」；分塊處理「線上、摘要不可合併」。** 莫隊的排序本身也用到分塊（按左端點所在塊排序）——**它是分塊思想的另一種應用，不是替代品。**
- **與 9.7 ST 表**：ST 表 $O(1)$ 查詢但完全不能改；分塊 $O(\sqrt n)$ 查詢但能改，且摘要形態自由。**兩者的定位幾乎不重疊。**
- **與 9.1 樹狀陣列**：樹狀陣列做「區間加、區間和」是 $O(\log n)$ 且程式極短（9.1 的兩個 BIT）。**單論這個功能，分塊沒有任何優勢。** 本節模板一的價值在於它是後續複雜摘要的骨架。
- **與 Segment Tree Beats**：處理「區間 chmin／chmax + 區間和」這種標記不滿足分配律的問題。**它是線段樹的擴展，複雜度 $O(n\log^2 n)$；分塊做同樣的事是 $O(n\sqrt n)$ 但好寫得多。** 面試或時間緊迫時分塊是務實選擇。
- **與 10.1 伸展樹**：處理「序列中間插刪」時，**定理 6 的定期重建分塊 $O(\sqrt n)$ 攤還，比平衡樹的 $O(\log n)$ 慢但好寫十倍。** $n \le 10^5$ 時先寫分塊。
- **與「重元素／輕元素」分治**：「出現次數 $> \sqrt n$ 的元素至多 $\sqrt n$ 種」——對重元素各自暴力掃一遍（$\sqrt n$ 種 $\times$ $O(n)$），對輕元素用另一套方法。**這是定理 3 的同一個平衡，套在「出現次數」這個參數上。**
- **與調和級數枚舉**：$\sum_{d=1}^{n} n/d = O(n\log n)$ 這類枚舉倍數的技巧，本質上也是「小的多做、大的少做」。**根號分解是同一種思維，只是分界點取在 $\sqrt n$ 而非讓兩側自然平衡。**

## 本節重點速查

- **存在理由**：**線段樹要求摘要可合併，分塊不要求。** 每塊可以各自排序、各自開頻次表——**摘要形態完全自由，代價是 $O(\log n) \to O(\sqrt n)$。** 能寫出 `Info operator+` 就別用分塊。
- **三個座標函式**：`bel(i) = i/s`、`lo(b) = b*s`、**`hi(b) = min(n, (b+1)*s)`（必須夾 `n`）**。塊數 `(n+s-1)/s`，`s = max(1, sqrt(n))`。
- **定理 1（塊長）**：$T(s)=a\frac{n}{s}+bs$ 在 $s^\star=\sqrt{an/b}$ 最小。**$\sqrt n$ 只是 $a=b$ 的特例**；修改多就把 $s$ 調小，查詢多就調大。**TLE 時第一件事是調 `s`。**
- **定理 2（分解）**：$\le 2$ 段零頭 + $\le B$ 個整塊，不重不漏。**`bl == br` 必須特判——頭號錯誤。**
- **定理 3（對參數分塊）**：**「小的預處理、大的暴力，分界點取在兩側代價相等處」**。1714 以 $y=\sqrt n$ 為界，$O((n+q)\sqrt n)$；**預處理表第一維必須是 $\sqrt n$，否則空間爆。**
- **定理 4（不變量 (R)）**：真實值 $=\mathit{raw}[i]+\mathit{add}[\mathit{bel}(i)]$，$\mathit{sum}[b]$ 不含 `add`。**整塊改 `add`、零頭改 `raw`——標記只有一層，所以沒有 `pushDown`。** 這是分塊比線段樹好寫的根本原因。區間賦值例外，讀零頭前要展開標記。
- **定理 5（塊內排序）**：查「$<x$ 的個數」整塊二分 $O(\log s)$、零頭暴力。**它是三種做法（歸併樹／主席樹／分塊）中唯一支援修改的。**
- **定理 6（定期重建）**：每塊一個 `vector`，塊超過 $2s$ 就裂開，每 $\Theta(s)$ 次操作全域重建 ⇒ 插入也能攤還 $O(\sqrt n)$。**根號思想的第三種形態，與本章反覆出現的攤還模式同源。**
- **規模感**：$n=q=10^5$ ⇒ $6\times10^7$，常數小就能過；$n=10^6$ 分塊必敗，回線段樹。
