## 這個技術解決什麼問題

有一類區間查詢，摘要既**不可合併**（線段樹無效）、**也不可減**（前綴和與主席樹無效）：

- 「區間內有幾種不同的值？」
- 「區間內出現次數最多的元素出現幾次？」
- 「區間內第 $k$ 小？」（可減，但要線上就得主席樹；離線有更省的辦法）

但它們有一個共同的好性質：**如果我已經知道 $[l, r]$ 的答案，那麼 $[l, r+1]$、$[l-1, r]$、$[l+1, r]$、$[l, r-1]$ 的答案都能 $O(1)$ 算出來**——只要維護一張頻次表。

**莫隊演算法把這件事推到極致：**

> **既然答案可以「移動一格」地更新，那就把所有查詢重新排序，讓兩個指標走過的總距離最短。** 排序得當時，總移動量是 $O(n\sqrt q)$ 而非 $O(nq)$。

**它的代價是必須離線**——要先看到所有查詢才能排序。

**辨識訊號**：
- 大量區間查詢，問的是**種類數／眾數／頻次統計**這類沒有簡單區間合併公式的東西（3636 查詢超過閾值頻率最高元素、3590 第 K 小的路徑異或和）；
- **查詢可以離線**（一次給你全部查詢，中間沒有修改）；
- **相鄰區間的答案能用「加一個元素／減一個元素」$O(1)$ 更新**——**這是莫隊能用的前提，不是可選項**（定理 4）。

**三個條件缺一不可。** 少了離線就用主席樹（9.6）；少了 $O(1)$ 增量就要重新設計狀態，否則那個 $\log$ 會被乘上 $O(n\sqrt q)$ 次而爆掉（定理 6）。

## 狀態／資料結構定義

**三樣東西：**

```cpp
struct Query {
    int l, r, id;
};  // id 用來把答案放回原順序
int curL = 0, curR = -1;  // 當前窗口 [curL, curR]，初始為空
vector<int> cnt;          // 頻次表：值 v 在當前窗口出現幾次
int cur = 0;              // 當前窗口的答案
```

**`curL = 0, curR = -1` 表示空窗口。** 這個初始值不是隨便選的——它讓 `curR - curL + 1 == 0`，且第一次 `curR++` 之後就指向元素 0，**所有移動邏輯不需要特判空窗口。**

**兩個增量函式，是整個演算法唯一與題目相關的部分：**

```cpp
void add(int i) {
    if (cnt[a[i]]++ == 0) cur++;
}  // 例：不同值個數
void remove(int i) {
    if (--cnt[a[i]] == 0) cur--;
}
```

**排序鍵（定理 2 會證明為什麼是這個）：**

$$\text{按}\;\big(\mathit{bel}(l),\; r\big)\;\text{排序，其中}\;\mathit{bel}(l) = l / s.$$

**加上奇偶優化（定理 3）**：偶數塊 $r$ 遞增、奇數塊 $r$ 遞減。

**塊長 $s$ 的最優值是 $n/\sqrt q$ 而不是 $\sqrt n$**（定理 2）。$q \approx n$ 時兩者一致，但 $q \ll n$ 時差距很大。

## 不變量或正確性證明

以下記序列長度 $n$、查詢數 $q$、塊長 $s$、塊數 $B = \lceil n/s\rceil$。

### 定理 1（指標移動的正確性與順序）

**不變量 (M)**：*在處理每個查詢之前與之後，`cnt` 恰好是子陣列 $a[\mathit{curL} \dots \mathit{curR}]$ 的頻次表，且 `cur` 是該子陣列的答案。*

*維護*：四種移動各自 $O(1)$ 地維持 (M)：`curR++` 前 `add(curR+1)`、`curR--` 後 `remove(curR+1)`、`curL--` 前 `add(curL-1)`、`curL++` 後 `remove(curL)` ✔。

**但移動的順序不能任意。** 標準寫法是：

```cpp
while (curR < q.r) add(++curR);     // 先擴張
while (curL > q.l) add(--curL);     // 先擴張
while (curR > q.r) remove(curR--);  // 再收縮
while (curL < q.l) remove(curL++);  // 再收縮
```

*為什麼必須「先擴張、再收縮」*。設當前窗口是 $[5, 5]$（一個元素），目標是 $[8, 8]$。

- **先收縮**：`while (curL < 8) remove(curL++)` 會走到 $\mathit{curL} = 8$，而 $\mathit{curR}$ 還是 5——**窗口變成 $[8, 5]$，`curL > curR + 1`，中間的 6、7 被「移除」了兩次**（一次沒被加入過），`cnt` 出現負值，(M) 崩壞 ✔（這就是反例）。
- **先擴張**：`curR` 先走到 8（依序 add 6、7、8），窗口成為 $[5, 8]$；再收縮 `curL` 到 8。全程 $\mathit{curL} \le \mathit{curR}+1$，每個元素的 add／remove 恰好配對 ✔。

**形式上，先擴張保證了「窗口在任何中間時刻都是一個合法的（可能為空的）區間」**，於是 (M) 在每一步之後都成立。$\square$

**這是莫隊最常見的錯誤，而且症狀是「大部分測資對、少數錯」**——只有當相鄰兩個查詢的區間**不相交**時才會觸發。**照抄上面四行的順序。**

### 定理 2（複雜度 $O(n\sqrt q)$，以及最優塊長）

*命題*：按 $(\mathit{bel}(l),\, r)$ 排序後，兩個指標的總移動量為

$$O\!\left(\frac{n^2}{s} + qs\right),$$

取 $s = n/\sqrt q$ 得 $O(n\sqrt q)$。

*證明*。分別計算兩個指標。

**右指標 $r$**。在**同一塊內**，所有查詢按 $r$ 遞增排序，故 $r$ **單調不減**，該塊內的總移動量 $\le n$。共 $B = n/s$ 塊 ⇒ 總移動量 $\le nB = n^2/s$ ✔。（跨塊時 $r$ 可能從 $n$ 跳回小值，一次 $O(n)$，共 $B$ 次，已含在上式中。）

**左指標 $l$**。在同一塊內，所有查詢的 $l$ 都落在同一個長度 $s$ 的塊裡，故相鄰兩個查詢之間 $l$ 至多移動 $s$；共 $q$ 個查詢 ⇒ 總移動量 $\le qs$ ✔。（跨塊時 $l$ 至多移動 $2s$，共 $B$ 次，$O(Bs) = O(n)$，可忽略。）

**求最優 $s$**：由 AM–GM（與 11.1 定理 1 同一個計算），$\frac{n^2}{s} + qs$ 在 $s = n/\sqrt q$ 取最小值 $2n\sqrt q$ ✔。$\square$

**兩個實務推論**：

- **$q \approx n$ 時 $s = \sqrt n$，總複雜度 $O(n\sqrt n)$。** 這是最常見的情形，也是「莫隊 = 根號」這個印象的來源。
- **$q \ll n$ 時 $s = n/\sqrt q > \sqrt n$，塊要開大。** 例如 $n = 10^5$、$q = 10^3$ ⇒ $s \approx 3163$（而不是 316），總移動量 $2n\sqrt q \approx 6.3\times10^6$ 而非 $\sqrt{}$ 版的 $3\times10^7$。**塊長寫死 `sqrt(n)` 在這種比例下慢 5 倍。**

**這個證明依賴的前提要點名**：「$r$ 在塊內單調」完全來自排序鍵的第二維；「$l$ 在塊內移動 $\le s$」完全來自第一維的分塊。**兩維各負責一個指標——這就是排序鍵的設計理由，不是湊出來的。**

### 定理 3（奇偶排序優化）

*做法*：比較器改成

```cpp
sort(qs.begin(), qs.end(), [&](const Query& x, const Query& y) {
    int bx = x.l / s, by = y.l / s;
    if (bx != by) return bx < by;
    return (bx & 1) ? x.r > y.r : x.r < y.r;  // 奇數塊反向
});
```

*正確性*：排序只改變處理順序，而由定理 1，**任何處理順序都會得到正確答案**（(M) 與順序無關）✔。

*複雜度不變*：塊內 $r$ 仍然單調（只是方向不同），總移動量的上界 $n^2/s$ 不變 ✔。

*收益*：原本每跨一塊，$r$ 都要從 $n$ 附近「歸零」重跑一次，浪費 $O(n)$；奇偶交替後，**跨塊時 $r$ 停在哪就從哪繼續**，這 $B$ 次共 $O(n)$ 的浪費被完全省下。**實測常數約減半，一兩行的改動，值得永遠加上。** $\square$

### 定理 4（`add` / `remove` 必須 $O(1)$ 且可逆——以及做不到時怎麼辦）

*為什麼是硬前提*：由定理 2，`add`／`remove` 被呼叫 $O(n\sqrt q)$ 次。$n = q = 10^5$ 時是 $3\times10^7$ 次。**每次多一個 $\log$ 就是 $5\times10^8$，必然超時。**

**但「可逆」這個條件比想像中嚴格。** 考慮**區間眾數的出現次數**：

- `add`：`cnt[v]++; cur = max(cur, cnt[v]);` —— $O(1)$ ✔
- `remove`：`cnt[v]--;` 之後 `cur` 該變成多少？**如果 $v$ 剛好是唯一的眾數，`cur` 要減 1；否則不變。判斷這件事需要另一張「出現次數的出現次數」表，而且即使有了也只能處理「恰好減 1」的情形。** 一般而言 **max 不可撤銷** ✘。

**解法：回滾莫隊（只增不減莫隊）。**

*做法*：按 $(\mathit{bel}(l), r)$ 排序後，**對每一塊單獨處理**：
1. 令 $R_b = \mathit{hi}(b)$（塊右界）。**右指標 $r$ 從 $R_b$ 開始，在本塊內單調遞增，全程只 `add`。**
2. 對每個查詢，先把 $r$ 推到 $q.r$（只 `add`）；再**從 $R_b$ 出發把左指標臨時推到 $q.l$**（只 `add`），記錄答案；然後**把這些臨時的 `add` 全部回滾**（恢復 `cnt` 與 `cur` 的快照）。
3. 若查詢**整段落在同一塊內**（$q.r < R_b$），直接暴力 $O(s)$。

*正確性*：每個查詢被回答時，窗口恰為 $[q.l, q.r]$ ✔；回滾把狀態還原到「只含 $[R_b, r]$」，供下一個查詢使用 ✔。

*複雜度*：$r$ 每塊單調 ⇒ $O(n B) = O(n^2/s)$；每個查詢的臨時左擴 $\le s$ 且回滾同樣 $\le s$ ⇒ $O(qs)$。**與定理 2 完全相同的 $O(n\sqrt q)$** ✔。$\square$

**回滾的實作要點**：`cur` 只要存一個變數快照；`cnt` 的還原要**逐個撤銷剛才 `add` 過的位置**（不能整表清空，那是 $O(V)$）。**因為只 `add` 過 $\le s$ 個位置，撤銷也是 $O(s)$。**

**對偶的情形是「只減不增莫隊」**（`remove` 好寫、`add` 難寫），做法對稱。**先問哪一邊好寫，再決定用哪一種。**

### 定理 5（適用邊界與兩個擴展）

**莫隊要求三件事：離線、無修改、$O(1)$ 可逆增量。** 放寬前兩者各有代價：

**帶修莫隊**：查詢加上第三維「時間」$t$（前面有幾次修改），按 $(\mathit{bel}(l), \mathit{bel}(r), t)$ 排序，塊長取 $n^{2/3}$。

*複雜度*：$l$ 移動 $O(qs)$、$r$ 移動 $O(q\cdot n^2/s^2 \cdot s)$… 標準結果是 $O(n^{5/3})$（取 $s = n^{2/3}$）。**$n = 10^5$ 時 $n^{5/3} \approx 2\times10^8$——能過但很緊，通常有更好的做法。**

**樹上莫隊**：把樹展開成**歐拉序**（每個節點出現兩次），路徑 $(u,v)$ 對應歐拉序上的一段區間；出現兩次的節點視為「不在路徑上」（用一個 `vis` 標記做 XOR 式的 add／remove），LCA 要另外補上。**核心技巧是「把樹上路徑轉成序列區間」，轉完之後就是普通莫隊。** 3590 這類「路徑上的統計」屬於這一族。

**兩者都只是換排序鍵與換增量函式，主體邏輯不變。** 這說明莫隊是一個**框架**而非單一演算法。

### 定理 6（值域分塊：為什麼不能用 `set` 或樹狀陣列）

*情境*：莫隊維護頻次表之後，查詢還需要一個「全域統計」——例如「當前窗口的第 $k$ 小」「當前窗口中出現次數 $\ge$ 閾值的最大值」。

*天真做法*：用樹狀陣列維護值域計數，`add`／`remove` 是 $O(\log V)$、查詢是 $O(\log V)$。

*為什麼不行*：`add`／`remove` 被呼叫 $O(n\sqrt q)$ 次、查詢只有 $q$ 次。**代價完全不對稱——應該讓 `add`／`remove` 快，查詢慢。**

$$\underbrace{n\sqrt q \cdot \log V}_{3\times10^7 \times 20 = 6\times10^8\;\text{不可行}} \quad\text{vs}\quad \underbrace{n\sqrt q \cdot 1 + q\sqrt V}_{3\times10^7 + 10^5\times316 = 6\times10^7\;\checkmark}$$

*正確做法：**值域分塊***。把值域切成 $\sqrt V$ 塊，維護 `cnt[v]` 與 `blockCnt[b]`：
- `add`／`remove`：兩個 $O(1)$ 的增減 ✔；
- 查詢第 $k$ 小：先掃 $\sqrt V$ 個塊找到答案所在塊，再掃塊內 $\sqrt V$ 個值 ⇒ $O(\sqrt V)$ ✔。

**這是「$O(1)$ 修改 / $O(\sqrt n)$ 查詢」的資料結構，恰好與樹狀陣列的 $O(\log n)$/$O(\log n)$ 互補。**

**這條原則值得單獨記住**：

> **選資料結構時看的不是單次複雜度，而是「操作次數 × 單次代價」的總和。** 莫隊裡修改次數遠多於查詢次數，所以要挑修改快的那個。

**這也回答了 11.1 遺留的問題「$O(\sqrt n)$ 的資料結構有什麼用」——它的用處正是在這種操作次數極度不對稱的場合。**

## C++17 模板

**模板一：基礎莫隊（區間不同值個數）**

```cpp
struct Mo {
    int n, s;
    vector<int> a, cnt;
    int cur = 0;

    void add(int i) {
        if (cnt[a[i]]++ == 0) cur++;
    }
    void remove(int i) {
        if (--cnt[a[i]] == 0) cur--;
    }

    // queries: {l, r}，皆為 0-indexed 且兩端皆含
    vector<int> solve(vector<int> a_, vector<array<int, 2>> queries) {
        a = move(a_);
        n = int(a.size());
        int q = int(queries.size());
        if (q == 0) return {};
        // 離散化，讓 cnt 的大小是 O(n)
        {
            vector<int> v = a;
            sort(v.begin(), v.end());
            v.erase(unique(v.begin(), v.end()), v.end());
            for (int& x : a)
                x = int(lower_bound(v.begin(), v.end(), x) - v.begin());
            cnt.assign(v.size(), 0);
        }
        s = max(1, int(n / max(1.0, sqrt(double(q)))));  // 定理 2：n / sqrt(q)

        vector<int> ord(q);
        iota(ord.begin(), ord.end(), 0);
        sort(ord.begin(), ord.end(), [&](int x, int y) {
            int bx = queries[x][0] / s, by = queries[y][0] / s;
            if (bx != by) return bx < by;
            return (bx & 1) ? queries[x][1] > queries[y][1]  // 定理 3：奇偶優化
                            : queries[x][1] < queries[y][1];
        });

        vector<int> ans(q);
        int curL = 0, curR = -1;
        for (int id : ord) {
            int l = queries[id][0], r = queries[id][1];
            while (curR < r) add(++curR);  // 先擴張（定理 1）
            while (curL > l) add(--curL);
            while (curR > r) remove(curR--);  // 再收縮
            while (curL < l) remove(curL++);
            ans[id] = cur;
        }
        return ans;
    }
};
```

**四行指標移動的順序是硬性的**（定理 1）；**塊長是 `n / sqrt(q)` 而非 `sqrt(n)`**（定理 2）；**離散化讓 `cnt` 的大小是 $O(n)$**，否則值域 $10^9$ 開不出陣列。

**模板二：回滾莫隊骨架（`remove` 無法 $O(1)$ 時，定理 4）**

```cpp
// 依塊處理；本塊右界 R = min(n, (b+1)*s)
for (int b = 0; b * s < n; b++) {
    int R = min(n, (b + 1) * s);
    // 每塊重置：只 add 過的位置逐個清掉，不要整表 memset
    resetCounters();
    int curR = R - 1, snapshot = 0;  // 窗口 [R, R-1] 為空
    for (int id : queriesInBlock[b]) {
        int l = queries[id][0], r = queries[id][1];
        if (r < R) {
            ans[id] = bruteForce(l, r);
            continue;
        }  // 同塊，暴力
        while (curR < r) add(++curR);  // 只 add，塊內單調
        snapshot = cur;
        int tmpL = R;
        while (tmpL > l) add(--tmpL);  // 臨時左擴
        ans[id] = cur;
        while (tmpL < R) rollback(tmpL++);  // 回滾：撤銷剛才那些 add
        cur = snapshot;
    }
}
```

**`rollback` 與 `remove` 的差別**：`rollback` 只需要還原 `cnt`（`cnt[a[i]]--`），**不需要維護 `cur`**——`cur` 直接用快照覆蓋。**這正是回滾莫隊能繞開「max 不可撤銷」的原因。**

**模板三：值域分塊（$O(1)$ 修改 / $O(\sqrt V)$ 查詢，定理 6）**

```cpp
struct ValueBlocks {
    int V, s, nb;
    vector<int> cnt, blk;
    explicit ValueBlocks(int V) : V(V) {
        s = max(1, int(sqrt(double(V))));
        nb = (V + s - 1) / s;
        cnt.assign(V, 0);
        blk.assign(nb, 0);
    }
    void ins(int v) {
        cnt[v]++;
        blk[v / s]++;
    }  // O(1)
    void del(int v) {
        cnt[v]--;
        blk[v / s]--;
    }  // O(1)
    int kth(int k) const {  // 第 k 小，k 從 1 起算；O(sqrt V)
        int b = 0;
        while (b < nb && k > blk[b]) k -= blk[b], b++;
        for (int v = b * s;; v++) {
            k -= cnt[v];
            if (k <= 0) return v;
        }
    }
};
```

## 時間與空間複雜度

| | 時間 | 空間 |
| --- | --- | --- |
| 排序查詢 | $O(q\log q)$ | $O(q)$ |
| 指標移動（定理 2） | $O(n\sqrt q)$ 次 `add`／`remove` | — |
| 基礎莫隊總計（$q\approx n$） | $O(n\sqrt n)$ | $O(n)$ |
| 回滾莫隊（定理 4） | $O(n\sqrt q)$ | $O(n)$ |
| 帶修莫隊 | $O(n^{5/3})$ | $O(n)$ |
| 樹上莫隊 | $O(n\sqrt q)$ | $O(n)$ |
| 莫隊 + 值域分塊（定理 6） | $O(n\sqrt q + q\sqrt V)$ | $O(n + V)$ |
| 莫隊 + 樹狀陣列（**錯誤示範**） | $O(n\sqrt q\log V)$ | $O(n+V)$ |

**規模感**：$n = q = 10^5$ ⇒ $n\sqrt q \approx 3.2\times10^7$ 次 `add`／`remove`。**每次必須是幾條指令的等級**（一次陣列讀寫加一個比較），否則過不了。**`add` 裡出現 `map`、`set`、`vector::push_back` 都是紅燈。**

**最優塊長的實測影響**（$n = 10^5$）：

| $q$ | $s = \sqrt n = 316$ | $s = n/\sqrt q$ | 總移動量比 |
| --- | --- | --- | --- |
| $10^5$ | 316 | 316 | 1.0× |
| $10^4$ | 316 | 1000 | 約 1.6× |
| $10^3$ | 316 | 3163 | 約 5× |

**查詢少時一定要調大塊長。**

**空間**：`cnt` 的大小是離散化後的值域 $O(n)$；查詢陣列 $O(q)$。**莫隊的空間一向不是問題。**

## 常見錯誤與邊界條件

- **指標移動順序寫成「先收縮」**（定理 1）。窗口出現 `curL > curR + 1` 的非法狀態，`cnt` 變負。**只有相鄰查詢不相交時才觸發，測資小時可能矇混過關。照抄「兩個 add 在前、兩個 remove 在後」。**
- **`curL`／`curR` 初始值錯**。必須是 `curL = 0, curR = -1`（空窗口）。寫成 `curR = 0` 就漏加了元素 0。
- **忘了離散化**。值域 $10^9$ 時 `cnt` 開不出來。**離散化後 `cnt.assign(m, 0)`。**
- **塊長寫死 `sqrt(n)`**（定理 2）。$q \ll n$ 時慢數倍。**用 `n / sqrt(q)`，並注意 $q = 0$ 的除零。**
- **`add` / `remove` 不對稱**。兩者必須嚴格互逆：`add` 裡是 `cnt[v]++ == 0`（後置），`remove` 裡是 `--cnt[v] == 0`（前置）。**寫成同一種前後置就錯了，而且錯得很隱晦。**
- **在 `add` 裡做了 $O(\log)$ 的事**（定理 6）。`set::insert`、`map` 查找、BIT 更新——**全部會把總複雜度乘上 $\log$。改用值域分塊或陣列。**
- **答案沒有放回原順序**。排序後要用 `id` 寫回 `ans[id]`，不能按處理順序輸出。
- **`max` 型答案用了普通莫隊**（定理 4）。眾數、最大頻次這類不可撤銷的答案**必須用回滾莫隊**。症狀是答案偏小且無規律。
- **回滾莫隊沒有正確重置**。每塊開始時要清空 `cnt`，但**不能 `memset` 整張表**（$O(V)$ × $B$ 次會爆）——**逐個撤銷本塊 add 過的位置。**
- **回滾莫隊漏了「同塊查詢暴力處理」的分支**。$q.r < R_b$ 時右指標無法從 $R_b$ 遞增到 $q.r$，必須單獨暴力 $O(s)$。
- **奇偶優化寫錯方向判斷**。`(bx & 1)` 用的是**塊編號**的奇偶，不是 `l` 的奇偶。
- **查詢區間的閉合約定不一致**。本節一律 $[l, r]$ 兩端皆含、0-indexed。**題目若給 1-indexed 要先轉換。**

## 與相似技巧的比較

- **與 11.1 分塊**：兩者都是根號，但**分塊是「對資料分塊」、莫隊是「對查詢排序」**。分塊支援線上、每次操作 $O(\sqrt n)$；莫隊必須離線、但總複雜度更好（$O(n\sqrt q)$ 對比 $O(q\sqrt n)$，$q < n$ 時莫隊贏）。**莫隊的排序鍵用到分塊——它是分塊思想的應用，不是競爭者。** 而定理 6 更是直接把值域分塊嵌進莫隊裡。
- **與 9.6 主席樹**：**離線 ⇒ 莫隊（空間 $O(n)$）；線上 ⇒ 主席樹（空間 $O(n\log n)$）。** 對「區間第 $k$ 小」兩者都能做，主席樹是 $O(\log n)$ 單次查詢、莫隊是 $O(\sqrt n)$——**但莫隊能做主席樹做不了的「眾數」「種類數」，因為那些不可減。**
- **與 12.1 離線 + 排序掃描**：若查詢的**單調性**允許「只加不刪」（例如按門檻排序後元素只增不減），那麼一次線性掃描 + 樹狀陣列就是 $O((n+q)\log n)$，**遠優於莫隊。** **拿到離線題先問：能不能只用一個指標？能的話別上莫隊。** 莫隊是「兩個指標都要來回移動」時的最後手段。
- **與 CDQ 分治／整體二分**：處理三維偏序、帶修改的離線問題，$O(n\log^2 n)$。**複雜度比帶修莫隊的 $O(n^{5/3})$ 好，但實作更難。** 帶修莫隊的價值是「不用重新思考，只加一維排序鍵」。
- **與 9.2 樹狀陣列求逆序對**：那也是離線的區間統計，但用的是「掃描順序承擔一個維度」——**單指標、$O(n\log n)$。** 與莫隊的雙指標是完全不同的路子。**能用單指標就別用雙指標，這是效率上的一整個檔次。**
- **與滑動窗口（sliding_window 章）**：滑動窗口是「一個指標單調前進、另一個單調跟隨」的 $O(n)$ 特例。**莫隊可以看成「放棄單調性、改用排序把總移動量壓到 $O(n\sqrt q)$」的推廣。** 認出這個關係，就知道莫隊本質上是在為「無序的查詢集合」重建一種近似的單調性。

## 本節重點速查

- **三個硬前提**：**離線、無修改、$O(1)$ 可逆增量。** 缺一就換工具（線上 ⇒ 主席樹；有修改 ⇒ 帶修莫隊 $O(n^{5/3})$；不可撤銷 ⇒ 回滾莫隊）。
- **排序鍵 $(\mathit{bel}(l), r)$ + 奇偶優化**：第一維讓 $l$ 塊內只移動 $s$，第二維讓 $r$ 塊內單調。**兩維各負責一個指標。** 奇偶交替（偶塊 $r$ 遞增、奇塊遞減）省下跨塊時 $r$ 的歸零，常數約減半。
- **指標移動順序（定理 1）**：**兩個 `add` 在前、兩個 `remove` 在後。** 先收縮會產生 `curL > curR+1` 的非法窗口。初始 `curL = 0, curR = -1`。
- **複雜度 $O(n^2/s + qs)$，最優 $s = n/\sqrt q$，總 $O(n\sqrt q)$（定理 2）。** $q\approx n$ 時退化成 $\sqrt n$；**$q \ll n$ 時塊要開大，寫死 `sqrt(n)` 會慢數倍。**
- **回滾莫隊（定理 4）**：`max` 型答案不可撤銷 ⇒ 每塊內 $r$ 只增、$l$ 臨時左擴後回滾（`cur` 用快照還原，`cnt` 逐個撤銷）；同塊查詢暴力。**複雜度不變。**
- **值域分塊而非樹狀陣列（定理 6）**：`add`／`remove` 被呼叫 $O(n\sqrt q)$ 次、查詢只有 $q$ 次 ⇒ **要挑「修改 $O(1)$、查詢 $O(\sqrt V)$」的結構。** 一般原則：**看「次數 × 單次代價」的總和，不是單次複雜度。**
- **擴展只是換排序鍵**：帶修莫隊加時間維、塊長 $n^{2/3}$；樹上莫隊用歐拉序把路徑轉成區間。**主體邏輯不變——莫隊是框架。**
- **先問能不能單指標**：離線 + 門檻單調 ⇒ 排序掃描 $O((n+q)\log n)$，遠勝莫隊。**莫隊是兩個指標都必須來回時的最後手段。**
