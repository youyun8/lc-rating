## 這個技術解決什麼問題

一般我們預設「查詢來一個、答一個」。但很多題目**一次把所有查詢都給你**——這時你沒有義務按原順序回答。

**離線演算法的全部想法只有一句：**

> **先讀完所有查詢，重新排序，讓「回答查詢」與「建立資料」共用同一次掃描。**

最典型的形態是**帶門檻的查詢**：

- 「所有邊權 $<$ `limit` 時 $u$、$v$ 連通嗎？」（1697）
- 「價格 $\le$ `q` 的物品中最大的美麗值？」（2070）
- 「大小 $\ge$ `minSize` 的房間中，編號離 `preferred` 最近的？」（1847）

**天真做法是每個查詢重掃一遍資料，$O(nq)$。** 但注意：**門檻越寬，合法的元素只增不減。** 於是把查詢按門檻排序，一邊放寬門檻一邊往資料結構裡加元素——**每個元素只會被加入一次**，總計 $O((n+q)\log n)$。

**辨識訊號**：
- 每個查詢帶一個門檻，且**查詢之間互不影響、可以任意順序回答**（1697、1847、2070）；
- **門檻具單調性**：門檻越寬，合法元素只增不減 ⇒ **可以「只加不刪」**；
- 暴力是每個查詢重新篩一遍（$O(nq)$），而排序後漸進加入降到 $O((n+q)\log n)$；
- 題目一次給你整個 `queries` 陣列（**而不是一個 `query()` 介面**）。

**最後一條是最實用的辨識法。** 題目給的是陣列還是介面，直接決定了離線是否可用——**看到 `vector<vector<int>>& queries` 就該問：排序它會不會讓事情變簡單？**

## 狀態／資料結構定義

**離線的骨架永遠是這三步：**

```cpp
// 1. 給每個查詢記住原始編號
vector<int> ord(q);
iota(ord.begin(), ord.end(), 0);

// 2. 查詢與資料各自按「同一個維度」排序
sort(ord.begin(), ord.end(),
     [&](int x, int y) { return key(queries[x]) < key(queries[y]); });
sort(items.begin(), items.end(),
     [](const Item& a, const Item& b) { return a.key < b.key; });

// 3. 雙指標：一邊放寬門檻、一邊把新合法的元素加進結構
vector<int> ans(q);
int p = 0;
for (int id : ord) {
    while (p < n && items[p].key <= key(queries[id])) {
        structure.add(items[p]);
        p++;
    }
    ans[id] =
        structure.query(queries[id]);  // 一定要寫回 ans[id]，不是 push_back
}
return ans;
```

**三件事各有陷阱：**

| 步驟 | 陷阱 |
| --- | --- |
| 記 `id` | 忘了記，排序後就無法還原順序 |
| 同維度排序 | 資料與查詢的排序鍵必須是**同一個量**，且方向一致 |
| 雙指標 | `<=` 還是 `<`，取決於門檻是否嚴格（見「常見錯誤」） |

**資料結構的選擇取決於「只加不刪」還是「要加要刪」**（定理 2 vs 定理 6）：

| 情境 | 可用的結構 |
| --- | --- |
| **只加不刪**（門檻單調） | **並查集**、前綴 max、單調棧、樹狀陣列、`set` |
| **要加要刪**（DFS 上的離線） | 可撤銷並查集、計數陣列、字典樹（計數版） |

**「只加不刪」是離線給的最大紅利**——並查集根本不支援刪除，而它恰好是 1697 這類題目的最佳工具。

## 不變量或正確性證明

### 定理 1（重排查詢的合法性）

**不變量 (O)**：*若查詢之間沒有依賴——即第 $i$ 個查詢的答案不依賴第 $j$ 個查詢的答案（$j < i$），且查詢本身不修改資料——則以任意順序回答，再按 `id` 寫回，結果與按原順序回答相同。*

*證明*。每個查詢的答案是「輸入資料」的函數，而輸入資料在整個過程中不變（查詢是唯讀的）⇒ 答案與計算時機無關 ✔。$\square$

**看似顯然，但它有兩個真實的失效情形，必須點名**：

1. **強制線上（forced online）**：題目要求「第 $i$ 個查詢的參數要與第 $i-1$ 個答案做 XOR 解碼」。**這是出題者刻意封殺離線的手段**，此時只能上主席樹（9.6）、Kruskal 重構樹（定理 4）這類線上結構。
2. **查詢與修改交錯**：例如「查詢 → 修改 → 查詢」，重排就會讓查詢看到錯誤的資料版本。**此時要麼把「時間」也納入排序鍵（帶修莫隊、CDQ 分治），要麼放棄離線。**

**LeetCode 上絕大多數 `queries` 陣列型的題目都滿足 (O)。** 但看到「上一個答案」四個字就要警覺。

### 定理 2（單調門檻 ⇒ 只加不刪）

*設定*：每個查詢 $Q_i$ 帶門檻 $\theta_i$，合法元素集合為 $S(\theta) = \{\,e : \mathrm{key}(e) \le \theta\,\}$。

*命題*：$\theta \le \theta' \Rightarrow S(\theta) \subseteq S(\theta')$。因此若把查詢按 $\theta$ **遞增**排序，資料結構**只需要支援插入**，且每個元素**恰好被插入一次**。

*證明*。$S$ 的單調性由定義直接得出 ✔。處理第 $k$ 個（排序後的）查詢時，結構中的元素恰為 $S(\theta_{(k)})$；處理下一個時只需補上 $S(\theta_{(k+1)}) \setminus S(\theta_{(k)})$——**這些元素從未被插入過**（因為 key 落在 $(\theta_{(k)}, \theta_{(k+1)}]$，之前的門檻都不夠寬）✔。故雙指標 `p` 單調不減，總插入次數 $= n$ ✔。$\square$

**這個推論的價值遠超複雜度**：

> **「只加不刪」讓一批不支援刪除的結構變得可用。**

- **並查集**：合併不可逆（8 節），但離線後根本不需要拆開 ✔；
- **前綴 max / 前綴和**：只能追加 ✔；
- **單調棧**：彈出即永久丟棄（4.7），與只加不刪相容 ✔。

**這正是「昂貴的迭代對應一個不可逆的狀態變化」那個模式的另一面**——離線排序保證了狀態變化永遠朝同一個方向，於是不可逆反而成了優點。**本章第十次遇到這個主題了。**

### 定理 3（1697：瓶頸路徑 $\iff$ 子圖連通）

*問題*：給定無向帶權圖與查詢 $(u, v, \mathit{limit})$，問是否存在 $u \to v$ 的路徑，**使得路徑上每條邊的權重都嚴格小於 $\mathit{limit}$**。

**命題**：這樣的路徑存在 $\iff$ 在只保留「權重 $< \mathit{limit}$」的邊所構成的子圖 $G_{<\mathit{limit}}$ 中，$u$ 與 $v$ 連通。

*證明*。
- **($\Rightarrow$)** 該路徑的每條邊權重都 $< \mathit{limit}$，故整條路徑都在 $G_{<\mathit{limit}}$ 中，$u$、$v$ 連通 ✔。
- **($\Leftarrow$)** 若在 $G_{<\mathit{limit}}$ 中連通，取任一條連接 $u$、$v$ 的路徑；它的每條邊都屬於 $G_{<\mathit{limit}}$，即權重 $< \mathit{limit}$ ✔。$\square$

**這個等價依賴的前提必須點名**：**條件是「路徑上的**每一條**邊都滿足」，而不是「路徑的**總長**滿足」。**

- **每條邊都要滿足**（瓶頸型）⇒ 邊的合法性與路徑無關 ⇒ 可以逐條加入 ⇒ 並查集 ✔；
- **總長要滿足**（最短路型）⇒ 一條邊是否「該用」取決於整條路徑 ⇒ **這個等價完全失效**，得用 Dijkstra 之類的方法 ✘。

**這是離線題最常見的誤判：看到「limit」就以為能排序加邊。先確認限制是加在「每個元素」上，還是加在「整體」上。**

*演算法*：邊按權重遞增排序、查詢按 $\mathit{limit}$ 遞增排序，雙指標把權重 $< \mathit{limit}$ 的邊逐一 `union`，然後 `find(u) == find(v)` ✔。由定理 2，每條邊只加一次，總計 $O(m\log m + q\log q + (m+q)\alpha)$。

**嚴格 vs 非嚴格**：1697 要求「嚴格小於」，所以加邊的條件是 `edges[p][2] < limit`（不是 `<=`）。**這一個字元就是 WA 與 AC 的差別。**

### 定理 4（同一題的線上解法：Kruskal 重構樹）

*命題（瓶頸路徑定理）*：在連通無向圖中，$u$ 到 $v$ 的所有路徑裡，**「路徑上最大邊權」的最小值**，等於**最小生成樹上 $u$ 到 $v$ 唯一路徑的最大邊權**。

*證明*。記 MST 上 $u$–$v$ 路徑的最大邊為 $e$，權重 $w(e)$。

- **($\le$)** MST 上的那條路徑本身就是一條路徑，其最大邊權為 $w(e)$，故最小值 $\le w(e)$ ✔。
- **($\ge$)** 反設存在一條路徑 $P$，其所有邊權 $< w(e)$。把 $e$ 從 MST 中刪去，MST 分成兩個連通塊 $A \ni u$、$B \ni v$（$e$ 在 $u$–$v$ 路徑上，故 $u$、$v$ 被分開）。路徑 $P$ 從 $u$ 走到 $v$，必然有一條邊 $f$ 跨越 $A$ 與 $B$，且 $w(f) < w(e)$。那麼把 MST 中的 $e$ 換成 $f$ 仍是生成樹，且總權重更小——**與 MST 的最小性矛盾** ✔。$\square$

**於是 1697 也能線上回答**：建 Kruskal 重構樹（按邊權遞增合併，每次合併新建一個權重為 $w$ 的內部節點），則 $u$、$v$ 的瓶頸值 $=$ 它們在重構樹上的 LCA 的權重，查詢 $O(\log n)$。

**為什麼還是推薦離線？** 離線版只要「排序 + 並查集」，十行；重構樹版要建樹 + 倍增 LCA，五十行。**除非題目強制線上（定理 1 的失效情形），否則離線總是更划算。**

**但知道線上解法的存在很重要**：它告訴你「離線不是唯一出路」，也讓你在遇到強制線上時不至於束手無策。

### 定理 5（離線的一般框架：把一個維度變成時間）

**觀察**：定理 3 的模式可以抽象成——

> **查詢有兩個條件 $(A, B)$。把 $A$ 交給掃描順序（時間），把 $B$ 交給資料結構。**

| 題目 | 交給掃描順序的 $A$ | 交給資料結構的 $B$ |
| --- | --- | --- |
| 1697 | 邊權 $<$ limit | $u$、$v$ 是否連通（並查集） |
| 2070 | 價格 $\le$ query | 美麗值的最大值（前綴 max） |
| 1847 | 房間大小 $\ge$ minSize | 編號離 preferred 最近（`set`） |
| 9.2 逆序對 | 下標 $j < i$ | 值 $a_j > a_i$（樹狀陣列） |
| 2940 | 建築高度的單調關係 | 最小的合法下標（堆／線段樹二分） |

**這與 9.2 定理 1 的「二維偏序」是同一件事，一字不差**：*「兩個條件，一個交給掃描順序，另一個交給資料結構。」*

**框架的正確性**：處理排序後的第 $k$ 個查詢時，結構中恰好是「滿足條件 $A$」的全部元素（由定理 2 的單調性），故對結構做關於 $B$ 的查詢，得到的正是「同時滿足 $A$ 與 $B$」的答案 ✔。

**推論 5.1（維度不夠用的時候）**：**三個條件就需要 CDQ 分治或樹套樹**——一個維度給排序、一個給分治、一個給資料結構。**看到三維偏序，離線的單指標框架就不夠了。**

**推論 5.2（排序方向）**：$B$ 的形式決定了 $A$ 該遞增還是遞減排序。「$\ge$ 門檻」就遞減（1847 的房間大小），「$\le$ 門檻」就遞增（2070 的價格）。**寫之前先想清楚「放寬門檻」是往哪個方向走。**

### 定理 6（DFS 上的離線：需要撤銷的情形）

*設定*（1938 型）：查詢掛在樹的節點上，答案取決於「根到該節點的路徑上有哪些值」。

*做法*：對樹做 DFS，**進入節點時把它的值加入結構、離開時移除**；在節點處回答所有掛在它上面的查詢。

**不變量 (P)**：*在 DFS 訪問節點 $x$ 的時刻，結構中恰好是「根到 $x$ 的路徑」上所有節點的值。*

*證明（對遞迴深度歸納）*。進入根時結構為空加上根的值 ✔。設進入 $x$ 前結構為「根到 $\mathrm{fa}(x)$ 的路徑」，加入 $x$ 的值後即為「根到 $x$」✔；遞迴處理每個子節點，由歸納假設它們各自維持 (P)，且**每個子節點離開時都把自己的貢獻撤銷了**，故回到 $x$ 時結構恢復為「根到 $x$」✔；最後離開 $x$ 前移除 $x$ 的值，恢復為「根到 $\mathrm{fa}(x)$」✔。$\square$

**這裡與定理 2 的「只加不刪」形成鮮明對比**：

| | 門檻型離線（定理 2） | DFS 型離線（定理 6） |
| --- | --- | --- |
| 操作 | 只加 | 加 + **撤銷** |
| 每個元素被操作 | 1 次 | 2 次（進入、離開） |
| 可用結構 | 並查集、單調棧 | 計數陣列、可撤銷並查集（**不能路徑壓縮**） |

**「可撤銷」這個要求會排除掉一些結構。** 特別是並查集：**可撤銷版必須放棄路徑壓縮**（壓縮改動了無法還原的資訊），只保留按秩合併，複雜度變成 $O(\log n)$——**這與 9.6 推論 5.1 的可持久化並查集是同一個限制。**

**Tarjan 離線 LCA 也是這個模式**：DFS 時用並查集把已完成的子樹指向父節點，離開時回答掛在該節點的 LCA 查詢。**認出「DFS + 進出維護 + 就地回答」這個骨架，一整族題目就通了。**

## C++17 模板

**模板一：門檻型離線的通用骨架**

```cpp
// items：資料，按 key 遞增排序；queries：查詢，帶門檻 theta
vector<int> offline(vector<Item> items, vector<Query> queries) {
    int n = int(items.size()), q = int(queries.size());
    sort(items.begin(), items.end(),
         [](const Item& a, const Item& b) { return a.key < b.key; });
    vector<int> ord(q);
    iota(ord.begin(), ord.end(), 0);
    sort(ord.begin(), ord.end(),
         [&](int x, int y) { return queries[x].theta < queries[y].theta; });

    Structure st;
    vector<int> ans(q);
    int p = 0;
    for (int id : ord) {
        while (p < n && items[p].key <= queries[id].theta) st.add(items[p++]);
        ans[id] = st.query(queries[id]);  // 寫回 ans[id]，不是 push_back
    }
    return ans;
}
```

**模板二：1697 檢查邊長度限制的路徑是否存在（定理 3）**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) x = fa[x] = fa[fa[x]];
        return x;
    }

public:
    vector<bool> distanceLimitedPathsExist(int n, vector<vector<int>>& edgeList,
                                           vector<vector<int>>& queries) {
        sort(edgeList.begin(), edgeList.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[2] < b[2];
             });
        int q = int(queries.size());
        vector<int> ord(q);
        iota(ord.begin(), ord.end(), 0);
        sort(ord.begin(), ord.end(),
             [&](int x, int y) { return queries[x][2] < queries[y][2]; });

        fa.resize(n);
        iota(fa.begin(), fa.end(), 0);
        vector<bool> ans(q);
        int p = 0;
        for (int id : ord) {
            int limit = queries[id][2];
            while (p < int(edgeList.size()) &&
                   edgeList[p][2] < limit) {  // 嚴格小於
                fa[find(edgeList[p][0])] = find(edgeList[p][1]);
                p++;
            }
            ans[id] = (find(queries[id][0]) == find(queries[id][1]));
        }
        return ans;
    }
};
```

**`edgeList[p][2] < limit` 的 `<` 對應題目的「嚴格小於」。** 若題目改成「不超過」就要換成 `<=`——**這是本節最高頻的 off-by-one。**

**模板三：2070 每一個查詢的最大美麗值（前綴 max，最輕量的離線）**

```cpp
class Solution {
public:
    vector<int> maximumBeauty(vector<vector<int>>& items,
                              vector<int>& queries) {
        sort(items.begin(), items.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[0] < b[0];
             });
        for (size_t i = 1; i < items.size(); i++)  // 前綴 max
            items[i][1] = max(items[i][1], items[i - 1][1]);

        int q = int(queries.size());
        vector<int> ord(q), ans(q);
        iota(ord.begin(), ord.end(), 0);
        sort(ord.begin(), ord.end(),
             [&](int x, int y) { return queries[x] < queries[y]; });

        int p = 0, best = 0;
        for (int id : ord) {
            while (p < int(items.size()) && items[p][0] <= queries[id])
                best = items[p++][1];
            ans[id] = best;
        }
        return ans;
    }
};
```

**這題也能不排序查詢，直接對每個查詢二分前綴 max 陣列（$O(q\log n)$）。** **當「資料結構」退化成一個變數或一個陣列時，離線排序的收益就只剩常數——此時二分往往更好寫。**

**模板四：DFS 型離線的骨架（定理 6）**

```cpp
vector<vector<int>> g, qs;  // qs[x]：掛在節點 x 上的查詢編號
void dfs(int x) {
    st.add(val[x]);  // 進入：加入
    for (int id : qs[x]) ans[id] = st.query(qryParam[id]);
    for (int y : g[x]) dfs(y);
    st.remove(val[x]);  // 離開：撤銷（不變量 (P)）
}
```

**`add` 與 `remove` 必須嚴格互逆**（與 11.2 莫隊的要求一模一樣）。**字典樹用「每個節點掛一個計數」而非「刪除節點」來實現撤銷。**

## 時間與空間複雜度

| 步驟 | 時間 |
| --- | --- |
| 排序資料 | $O(n\log n)$ |
| 排序查詢 | $O(q\log q)$ |
| 雙指標插入（定理 2） | 每個元素恰一次，共 $O(n \cdot C_{\text{add}})$ |
| 回答查詢 | $O(q \cdot C_{\text{query}})$ |
| **總計** | $O\big((n+q)\log(n+q)\big)$（結構為並查集／BIT 時） |

**與暴力的對比**：$O(nq)$ vs $O((n+q)\log)$。$n = q = 10^5$ ⇒ $10^{10}$ vs $3.4\times10^6$，**四個數量級。**

**各題的結構與複雜度**：

| 題目 | 結構 | 複雜度 |
| --- | --- | --- |
| 1697 | 並查集 | $O((m+q)\log + m\,\alpha)$ |
| 2070 | 前綴 max | $O((n+q)\log)$ |
| 1847 | `set`（按編號） | $O((n+q)\log n)$ |
| 1851 | 小根堆（按區間長度） | $O((n+q)\log n)$ |
| 1938 | 01-字典樹（計數版）+ DFS | $O((n+q)\cdot 18)$ |

**空間**：離線一定要額外存下所有查詢與答案，$O(q)$。**這是離線唯一的固定代價，通常無關緊要。**

**排序是瓶頸**：實務上 $O((n+q)\log)$ 裡的 $\log$ 大多來自兩次排序，而不是資料結構。**若門檻是小整數，用計數排序可以把 $\log$ 拿掉。**

## 常見錯誤與邊界條件

- **忘了記原始 `id`**。排序後就再也還不回去。**先寫 `iota(ord.begin(), ord.end(), 0)`，再排序 `ord` 而不是排序 `queries` 本身**——這樣 `queries` 的下標仍然是原始編號。
- **答案用 `push_back` 而非 `ans[id] =`**。順序全亂，而且不會報錯。
- **嚴格與非嚴格搞混**（定理 3）。`< limit` vs `<= limit` 是 WA 與 AC 的差別。**把題目的原文抄到註解裡。**
- **資料與查詢的排序方向不一致**（推論 5.2）。「$\ge$ 門檻」要遞減排序，「$\le$ 門檻」要遞增。**寫錯的症狀是「答案總是 0 或總是最大值」。**
- **相同門檻時的處理順序**。若門檻相等，**必須先把元素全部加完再回答查詢**。用 `while (p < n && key[p] <= theta)` 這種寫法自然滿足；但若寫成「先答再加」就漏了邊界上的元素。
- **雙指標寫成每次從頭掃**。`p` 必須是外層變數，不能在迴圈內重置——**否則複雜度退回 $O(nq)$，而答案是對的**（最陰險的效能錯誤）。
- **把「總長限制」當成「每邊限制」**（定理 3 的前提）。看到 limit 就排序加邊，但題目其實問的是路徑總權重——**等價性失效，答案完全錯。**
- **強制線上卻用了離線**（定理 1）。題目說「查詢參數要與上一個答案 XOR」時，離線不可用。
- **DFS 型離線忘了撤銷**（定理 6）。`remove` 漏寫或與 `add` 不互逆，兄弟子樹之間就會互相污染。
- **可撤銷並查集用了路徑壓縮**。壓縮不可還原。**要撤銷就只能按秩合併 + 記錄操作棧。**
- **遞迴 DFS 爆棧**。樹退化成鏈且 $n = 10^5$ 時要改迭代或手動開棧。
- **離線後忘了處理「沒有任何元素合法」的查詢**。例如 2070 中所有物品都比查詢貴 ⇒ 答案是 0 而非未定義。**結構要有合理的初始值。**

## 與相似技巧的比較

- **與 9.6 主席樹**：**主席樹是「離線技巧的線上化」**——它把「按前綴建版本」這件事持久化下來，於是不需要排序查詢。**能離線就離線：空間 $O(n)$ 對比 $O(n\log n)$，程式碼短得多。**
- **與定理 4 的 Kruskal 重構樹**：同一題的線上解法。**離線 = 排序 + 並查集（10 行）；線上 = 重構樹 + 倍增 LCA（50 行）。** 只有強制線上時才值得。
- **與 11.2 莫隊**：莫隊也是離線，但它處理的是「兩個指標都要來回移動」的情形，$O(n\sqrt q)$。**本節的門檻型離線只需要一個單調前進的指標，$O((n+q)\log n)$——快一個檔次。** **拿到離線題先問：能不能只用一個指標？能的話絕不上莫隊。**
- **與 9.2 逆序對**：9.2 定理 1 的「兩個條件，一個交給掃描順序，另一個交給資料結構」就是本節定理 5 的原型。**逆序對是離線思想最早出現的地方，只是那裡的「查詢」是隱含的（每個下標都是一個查詢）。**
- **與 CDQ 分治／整體二分**：處理三維偏序或帶修改的離線問題（推論 5.1）。**本節的單指標框架處理二維；三維就要多一層分治。** 整體二分則是「對所有查詢同時二分答案」，空間 $O(n)$，是主席樹的離線替代品。
- **與掃描線（9.4 定理 5）**：掃描線就是離線——把二維問題的一維交給掃描順序。**矩形面積並、區間覆蓋計數都是這個框架，只是資料結構換成了線段樹。**
- **與 8.5 定理 4（1851 的區間並查集解法）**：1851 有兩種離線解法——「查詢按值排序 + 小根堆」與「排序後用區間並查集」。**兩者都靠排序製造單調性，差別只在資料結構。** 這說明離線是一個框架，結構可以替換。
- **與 9.3 定理 4（2940 的線段樹二分）**：2940 既可以離線（按高度排序 + 單調棧／堆），也可以線上（線段樹上二分）。**又一組「離線更短、線上更通用」的對照。**
- **與貪心的排序**：很多貪心也以排序開場，但**貪心的排序是為了證明交換論證，離線的排序是為了複用計算。** 兩者的正確性論證完全不同——**別把「排序了就對」當成證明。**

## 本節重點速查

- **三步骨架**：**記 `id` → 資料與查詢按同一維度排序 → 雙指標邊放寬門檻邊插入 → `ans[id] =` 寫回。**
- **定理 1（合法性）**：查詢唯讀且互不依賴 ⇒ 任意順序回答。**兩個失效情形：強制線上（參數與上一個答案 XOR）、查詢與修改交錯。**
- **定理 2（最大紅利）**：門檻單調 ⇒ **只加不刪**，每個元素恰插入一次。**這讓並查集、單調棧、前綴 max 這些不支援刪除的結構變得可用。**
- **定理 3（1697）**：「路徑上每條邊 $<$ limit」$\iff$「子圖 $G_{<limit}$ 中連通」。**前提是限制加在每條邊上，不是加在路徑總長上——搞混就全錯。** 嚴格小於就寫 `<`。
- **定理 4（瓶頸路徑）**：最小瓶頸路徑值 $=$ MST 上該路徑的最大邊權（用割性質反證）。**線上解法 = Kruskal 重構樹 + LCA；離線短十倍，除非強制線上。**
- **定理 5（一般框架）**：**兩個條件，一個交給掃描順序、一個交給資料結構**——與 9.2 的二維偏序一字不差。**三個條件就要 CDQ／樹套樹。** 排序方向由門檻是 $\le$ 還是 $\ge$ 決定。
- **定理 6（DFS 型）**：進入加入、離開撤銷，不變量是「結構中恰為根到當前節點的路徑」。**`add` 與 `remove` 必須嚴格互逆；可撤銷並查集不能路徑壓縮。** Tarjan LCA 同骨架。
- **最高頻錯誤**：忘了記 `id`；`push_back` 而非 `ans[id]=`；`<` 與 `<=` 搞混；雙指標在迴圈內被重置（答案對但退化成 $O(nq)$）；排序方向反了。
- **判斷順序**：題目給 `queries` 陣列 ⇒ 想離線；一個單調指標夠嗎 ⇒ 夠就用本節（$O((n+q)\log n)$）；兩個指標要來回 ⇒ 莫隊（$O(n\sqrt q)$）；強制線上 ⇒ 主席樹／重構樹。
