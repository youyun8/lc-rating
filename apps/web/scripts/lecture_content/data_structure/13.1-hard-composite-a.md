## 這個技術解決什麼問題

前面每一節都對應一個明確的工具：看到「區間最值 + 修改」就用線段樹、看到「離線門檻」就排序加元素。**但有一類題目不吃這一套**——它把好幾個概念綁在一起，你認得出每一塊零件，卻不知道怎麼拼。

**辨識訊號**：
- 題目把多個概念綁在一起（圖 + 模擬 + 狀態、棋盤 + 搜尋），**無法一眼套模板**。像尋寶（LCP 13）、追逐遊戲（LCP 21）、貓和老鼠（913、1728）這類題；
- 資料量明顯會變、又要反覆查詢，提示你需要**設計專屬的狀態與更新規則**，而不是沿用上層分類的通用模板；
- **暴力解寫得出來但會超時**——這反而是好消息，它給了你「優化哪裡」的明確起點。

**這一節不教新的資料結構，教的是拆解的方法。** 複合題的解法幾乎總是三層：

> **第一層：狀態空間**（把局面編碼成什麼？）
> **第二層：轉移規則**（狀態之間怎麼走？代價多少？）
> **第三層：搜尋策略**（怎麼把最優值算出來？DP／BFS／逆向推理）

**每一層都是你已經會的東西。難的是切在哪裡。**

**而切得對不對，有一個可驗證的判準（定理 1）——這是本節唯一真正需要證明的東西。** 一旦狀態設計正確，剩下的往往就是照抄模板。

## 狀態／資料結構定義

**設計狀態時，逐條檢查這三件事：**

| 檢查項 | 問題 | 失敗的後果 |
| --- | --- | --- |
| **完備性**（定理 1） | 兩個狀態相同的局面，後續最優值一定相同嗎？ | 答案錯，且錯得沒有規律 |
| **最小性** | 有沒有哪個分量其實推不出任何區別？ | 狀態數爆炸，TLE／MLE |
| **可編碼性** | 能不能塞進一個 `int` 或陣列下標？ | 只能用 `map`，常數暴增 |

**三個最常見的狀態骨架：**

```cpp
// 骨架 A：集合狀態壓縮（元素 <= 20 個，順序不重要但「哪些做完了」重要）
//   dp[mask][i] = 已完成 mask 這組任務、目前停在 i，的最小代價
vector<vector<long long>> dp(1 << m, vector<long long>(m, LLONG_MAX / 2));

// 骨架 B：多主體位置狀態（博弈、追逐）
//   id = (mouse * n + cat) * 2 + turn
int enc(int mouse, int cat, int turn, int n) {
    return (mouse * n + cat) * 2 + turn;
}

// 骨架 C：事件驅動模擬（時間推進由「下一個事件」決定，而非逐秒遞增）
//   四個優先佇列分別代表四種身分，時間跳到最早的事件時刻
priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>>
    workL, workR;
priority_queue<int> waitL, waitR;  // 依題目規則排序（例如效率最低者優先）
```

**骨架 A 的關鍵是「$m \le 20$」**：$2^{20} = 10^6$，乘上 $m^2$ 還在可算範圍。**看到「至多 16 個機關」「至多 20 個城市」，狀態壓縮基本上就是答案。**

**骨架 B 的關鍵是編碼要緊湊**：$n = 50$ 時 $(50\times50)\times2 = 5000$ 個狀態，可以開陣列；若還要加上「已走幾步」這一維就變成 $10^6$——**能不加就不加**（定理 4 說明為什麼可以不加）。

## 不變量或正確性證明

### 定理 1（狀態完備性判準）

**定義**：狀態映射 $\sigma$（把局面映到狀態）是**完備的**，若對任意兩個局面 $P$、$P'$，

$$\sigma(P) = \sigma(P') \;\Longrightarrow\; \mathrm{opt}(P) = \mathrm{opt}(P'),$$

其中 $\mathrm{opt}$ 是「從該局面出發能達到的最優值」。

**命題**：若 $\sigma$ 完備，則「以 $\sigma$ 的像為節點、以合法動作為邊」建圖，在圖上做 DP／BFS 得到的結果正確。

*證明*。完備性保證了 $\mathrm{opt}$ 可以寫成狀態的函數 $F(\sigma(P))$。轉移方程 $F(s) = \bigoplus_{s \to s'} \big(\mathrm{cost}(s,s') \otimes F(s')\big)$ 中，右側只依賴狀態而不依賴具體局面 ✔——這正是遞迴式良定義（well-defined）的條件。$\square$

**這就是「無後效性」的形式化，也是複合題唯一真正的難點。** 實務上怎麼檢查？

> **試著構造兩個狀態相同但後續不同的局面。構造得出來，狀態就不完備。**

**兩個典型的不完備例子**：
- **貓和老鼠只記 `(mouse, cat)` 而不記 `turn`**：同樣的位置，輪到貓走和輪到老鼠走的勝負可以完全相反 ✘。
- **尋寶只記「已觸發幾個機關」而不記「是哪些」**：同樣觸發了 3 個，剩下的距離完全不同 ✘。

**反過來，最小性的檢查是**：拿掉某一維，還能不能構造出反例？**構造不出來，那一維就是多餘的。** 例如貓和老鼠若加上「已走幾步」這一維，狀態數乘上 $2n$——**而定理 4 會證明這一維可以拿掉。**

### 定理 2（LCP 13 尋寶：把「路徑」與「順序」分離）

*問題*：$N\times M$ 的棋盤上有起點 `S`、終點 `T`、$m$ 個機關 `M`、若干石堆 `O`、障礙 `#`。**要觸發一個機關，必須先到某個石堆拿一塊石頭，再帶到該機關**（石堆的石頭無限）。求觸發所有機關後到達 `T` 的最短總步數。

**分解命題**：最優路徑必定形如

$$S \;\to\; O_{i_1} \;\to\; M_{j_1} \;\to\; O_{i_2} \;\to\; M_{j_2} \;\to\;\cdots\;\to\; O_{i_m} \;\to\; M_{j_m} \;\to\; T,$$

其中 $(j_1,\dots,j_m)$ 是機關的一個排列。因此定義

$$c(j, j') \;=\; \min_{O}\Big(d(M_j,\, O) + d(O,\, M_{j'})\Big),\qquad
c_0(j) \;=\; \min_{O}\Big(d(S,\, O) + d(O,\, M_j)\Big),$$

則答案 $= \min_{\text{排列}} \Big( c_0(j_1) + \sum_{k=2}^{m} c(j_{k-1}, j_k) + d(M_{j_m},\, T) \Big)$。

*證明*。
- **(路徑形態)** 每個機關恰需一塊石頭，而石頭只能從石堆取得且**一次只能帶一塊**（帶到機關就消耗掉）。故在觸發第 $k$ 個機關之前，必須有一次「造訪石堆」的動作，且該次造訪之後直接前往該機關（中途繞路只會更長）✔。
- **(相鄰段可獨立最小化)** 從機關 $j$ 出發、經某石堆、到達機關 $j'$ 的最短代價，只取決於 $(j, j')$——**與之前觸發了哪些機關無關**（棋盤不會改變，石堆無限）✔。這正是定理 1 的完備性：狀態只需要「已觸發的機關集合 + 當前所在機關」。
- **(不需要考慮「先拿石頭再繞路」)** 由於石堆的石頭無限且每次只帶一塊，任何「提前繞去石堆」的策略，其代價都不小於 $\min_O(d(M_j,O)+d(O,M_{j'}))$ ✔。$\square$

**於是問題化成 TSP**：

$$\mathit{dp}[\mathit{mask}][j] = \min_{j' \in \mathit{mask},\, j'\ne j} \Big(\mathit{dp}[\mathit{mask}\setminus\{j\}][j'] + c(j', j)\Big).$$

*複雜度*：$m+2$ 次 BFS 求出所有 $d$（$O((m+2)NM)$）、$O(m^2 \cdot |O|)$ 算 $c$、$O(2^m m^2)$ 做 TSP。**$m \le 16$ ⇒ $2^{16}\times16^2 \approx 1.7\times10^7$** ✔。

**這個分解值得記住的地方**：**「棋盤上的最短路」與「訪問順序的最優化」是兩個完全獨立的子問題，用 BFS 預處理把前者壓成一張 $m\times m$ 的代價表，後者就退化成標準 TSP。** 複合題的解法幾乎都長這樣——**找到那條把兩個子問題切開的縫。**

**要點名的前提**：「相鄰段可獨立最小化」依賴**石堆的石頭無限、棋盤不變**。若石堆每個只有一塊石頭，$c(j,j')$ 就會依賴「哪些石堆已用完」，狀態必須加一維石堆集合——**問題立刻變成不可解的規模。** 讀題時要確認這一點。

### 定理 3（913 貓和老鼠：為什麼必須逆向推理）

*問題*：無向圖上，老鼠從節點 1、貓從節點 2 出發，洞在節點 0。老鼠先動，兩者輪流沿邊移動（**貓不能進洞**）。老鼠進洞則老鼠贏、貓抓到老鼠則貓贏、局面無限循環則平局。求最優對弈的結果。

**為什麼正向記憶化搜尋會壞掉**：狀態圖**有環**（雙方都可以來回走），`dfs(state)` 會呼叫到自己，記憶化陣列裡是「計算中」的標記——**這不是簡單的重複子問題，而是真正的循環依賴。** 隨手把「計算中」當成平局也不對：那會把「其實有必勝走法但需要繞路」的狀態誤判。

**正確做法：逆向 BFS（retrograde analysis）。**

*設定*：狀態 $s = (\mathit{mouse}, \mathit{cat}, \mathit{turn})$。定義 $\mathrm{deg}(s)$ 為該狀態下**輪到走的一方**的合法走法數。

*演算法*：
1. 把所有**終局**（$\mathit{mouse}=0$ ⇒ 老鼠贏；$\mathit{mouse}=\mathit{cat}$ ⇒ 貓贏）加入佇列，標記結果。
2. 取出一個已確定結果的狀態 $s$，枚舉它的**前驅** $p$（上一步走到 $s$ 的狀態）：
   - 若 $s$ 的結果**對 $p$ 的行動方有利**（例如 $p$ 輪到老鼠、而 $s$ 是老鼠贏）⇒ $p$ 直接確定為「行動方贏」，入佇列；
   - 否則 `deg(p)--`；**若 `deg(p)` 降到 0**（所有走法都對行動方不利）⇒ $p$ 確定為「行動方輸」，入佇列。
3. 佇列空後，**所有未被標記的狀態就是平局**。

**正確性（三部分）**：

- **(必勝的傳播)** 若某個後繼對行動方有利，行動方選它即可獲勝 ✔——這是「存在」語意，一個後繼就夠。
- **(必敗的傳播)** 若**所有**後繼都對行動方不利，則無論怎麼走都輸 ✔——這是「全稱」語意，所以要用 `deg` 計數到 0。
- **(平局的刻畫)** 未被標記的狀態，其每個後繼要嘛未被標記、要嘛對行動方不利，且**至少有一個未被標記的後繼**（否則 `deg` 會降到 0 被標記）。因此行動方可以永遠走進未標記狀態，遊戲無限進行 ⇒ 平局 ✔。**反過來，被標記的狀態確實能在有限步內分出勝負**，因為標記是從終局出發、按 BFS 層次傳播的，每個標記都附帶一條有限長的取勝路線 ✔。$\square$

**這三段對應的是博弈論的標準結論：「必勝 = 存在一個必敗後繼」「必敗 = 所有後繼都必勝」「其餘 = 平局」。** 逆向 BFS 只是把這個定義**按拓撲序**實現出來——**環的問題被「未標記即平局」自然吸收了。**

**這是「有環的博弈 DP 必須逆向」的標準論證。** 記住它的觸發條件：**狀態圖有環 + 存在「無限循環」這種第三種結果。** 若題目規定了步數上限（1728 貓和老鼠 II 就有），環就被步數維切開了，**正向記憶化又變得可行**——這是兩題的根本差異。

### 定理 4（為什麼不需要「已走步數」這一維：抽屜原理）

*命題*：在 913 中，若雙方最優對弈下經過 $2n(n-1)$ 步仍未分勝負，則必為平局。

*證明*。狀態 $(\mathit{mouse}, \mathit{cat}, \mathit{turn})$ 的總數為 $n \times (n-1) \times 2$（貓不能在洞裡）。**若對弈超過這麼多步，由抽屜原理必有某個狀態重複出現。** 雙方採取的都是「只依賴當前狀態」的最優策略（由定理 1，最優值是狀態的函數），故從重複狀態起，之後的走法會與上一次完全相同 ⇒ **進入週期循環，永遠不會結束** ⇒ 平局 ✔。$\square$

**於是「已走步數」這一維可以完全省略**——狀態數從 $O(n^3)$ 降到 $O(n^2)$。**這是最小性檢查（見「狀態定義」表）帶來的實際收益。**

**兩點誠實的補充**：
- 已知有更緊的界（$2n$ 步），但那需要更細緻的論證；**$2n^2$ 這個界用抽屜原理三行就能證，而且對演算法設計完全夠用**（我們根本不記步數）。
- **這個論證依賴「最優策略只依賴狀態」。** 若題目允許隨機策略或有其他隱藏資訊，論證失效。

### 定理 5（2532 過橋：模擬題的不變量與時間推進）

*問題*：$k$ 個工人在橋兩側搬箱子，每人有四個時間參數，規則明確規定了「橋空閒時誰先過」（效率最低者優先）。求最後一個工人回到左岸的時刻。

**這不是貪心題，是模擬題**——策略由題目直接規定，**不需要證明任何交換論證**。正確性完全在於「忠實實現規則」與「正確推進時間」。

**不變量 (W)**：*任何時刻，四個容器（左岸等待、右岸等待、正在左岸工作、正在右岸工作）的併集恰為全部 $k$ 個工人，且互不重疊。*

**這條不變量是模擬題的除錯利器**：**每次事件處理後 `assert` 四個容器的總大小等於 $k$，絕大多數狀態轉移的 bug 會當場暴露。**

**時間推進的正確性**：

*命題*：當兩側的等待區都為空時，把當前時間直接跳到「兩個工作佇列中最早的完成時刻」，不會遺漏任何事件。

*證明*。等待區為空 ⇒ 沒有工人能立刻過橋 ⇒ 在最早完成時刻之前，系統狀態不會改變 ✔。$\square$

**這就是「事件驅動模擬」與「逐秒模擬」的分野**：時間上限可能是 $10^9$，**逐秒必然 TLE；事件驅動的迭代次數是 $O(k)$**（每個工人的過橋次數有限）。

**推論 5.1（模擬題的通用做法）**：
1. 列出所有「事件類型」；
2. 用優先佇列按時間排序；
3. **每次跳到下一個事件時刻，而不是 `time++`**；
4. 用不變量 (W) 型的斷言自我檢查。

**優先佇列的比較器必須逐字對應題目的規則**（2532 是「效率最低者優先，相同則編號大者優先」）。**模擬題的 WA 十有八九出在比較器上，把題目原文抄成註解放在比較器旁邊。**

### 定理 6（先估算狀態數，再決定要不要優化）

**複合題最常見的失誤是「過早優化」**——花兩小時設計精巧的資料結構，其實暴力就能過。

*判準*：估算 **狀態數 × 每個狀態的轉移數**。

| 量級 | 判斷 |
| --- | --- |
| $\le 10^7$ | **直接暴力／記憶化搜尋**，不要優化 |
| $10^7 \sim 10^8$ | 需要小常數（陣列而非 `map`、避免遞迴） |
| $> 10^8$ | 必須換演算法或加剪枝 |

**2056 這類「枚舉所有走法組合」的題目正是靠這個估算才敢寫暴力**——棋子數與可走方向都很小，乘起來還在 $10^7$ 以內，於是「枚舉每顆棋子的移動方向與步數 + 逐時刻檢查碰撞」直接可行。**先算一次，再決定。**

**估算時要算的是「不同狀態的個數」，不是「所有路徑的條數」。** 記憶化搜尋的複雜度是前者——**這是暴力搜尋與記憶化搜尋在複雜度上的分水嶺，也是很多人高估難度的原因。**

## C++17 模板

**模板一：狀態壓縮 TSP（LCP 13 骨架，定理 2）**

```cpp
// d[i][j]：預先用 BFS 算好的兩點最短距離；INF 表示不可達
// c[j][j2]：經由某個石堆從機關 j 走到機關 j2 的最小代價
int minimalSteps(vector<string>& maze) {
    // 1. 找出 S、T、機關 M、石堆 O，對 S 與每個 M 各做一次 BFS
    // 2. 算 c0[j] = min_O(d[S][O] + d[O][M_j])，c[j][j2] = min_O(d[M_j][O] + d[O][M_j2])
    int m = /* 機關數 */ 0;
    const long long INF = LLONG_MAX / 4;
    vector<vector<long long>> dp(1 << m, vector<long long>(m, INF));
    for (int j = 0; j < m; j++) dp[1 << j][j] = c0[j];
    for (int mask = 1; mask < (1 << m); mask++)
        for (int j = 0; j < m; j++) {
            if (!(mask >> j & 1) || dp[mask][j] == INF) continue;
            for (int j2 = 0; j2 < m; j2++) {
                if (mask >> j2 & 1) continue;
                long long nv = dp[mask][j] + c[j][j2];
                dp[mask | (1 << j2)][j2] = min(dp[mask | (1 << j2)][j2], nv);
            }
        }
    long long ans = INF;
    for (int j = 0; j < m; j++)
        if (dp[(1 << m) - 1][j] < INF && dToT[j] < INF)
            ans = min(ans, dp[(1 << m) - 1][j] + dToT[j]);
    return ans >= INF ? -1 : int(ans);
}
```

**`mask >> j & 1` 的優先級**：`>>` 高於 `&`，所以這樣寫是對的；但 `mask & 1 << j` 也對（`<<` 高於 `&`）。**混寫容易出錯，選一種風格貫徹到底。**

**推式（push）比拉式（pull）好寫**：外層 `mask` 遞增枚舉，保證 `dp[mask][j]` 在被用來更新更大的 mask 之前已經定案 ✔。

**模板二：逆向 BFS 博弈（913 骨架，定理 3）**

```cpp
class Solution {
public:
    int catMouseGame(vector<vector<int>>& graph) {
        int n = int(graph.size());
        // color[m][c][t]：0 未定（平局）、1 老鼠贏、2 貓贏；t = 0 老鼠走、1 貓走
        vector color(n, vector(n, array<int, 2>{0, 0}));
        vector deg(n, vector(n, array<int, 2>{0, 0}));
        for (int m = 0; m < n; m++)
            for (int c = 1; c < n; c++) {
                deg[m][c][0] = int(graph[m].size());
                deg[m][c][1] = int(graph[c].size());
                for (int x : graph[c])
                    if (x == 0) {
                        deg[m][c][1]--;
                        break;
                    }  // 貓不能進洞
            }
        queue<array<int, 3>> q;
        for (int c = 1; c < n; c++)
            for (int t = 0; t < 2; t++) {
                color[0][c][t] = 1;
                q.push({0, c, t});  // 老鼠進洞
                color[c][c][t] = 2;
                q.push({c, c, t});  // 貓抓到老鼠
            }
        while (!q.empty()) {
            auto [m, c, t] = q.front();
            q.pop();
            int win = color[m][c][t];
            // 枚舉前驅：上一步是誰走的？t=0 表示現在輪老鼠，故上一步是貓走的
            int pt = t ^ 1;
            vector<array<int, 2>> pre;
            if (pt == 0) {
                for (int pm : graph[m]) pre.push_back({pm, c});
            } else {
                for (int pc : graph[c])
                    if (pc != 0) pre.push_back({m, pc});
            }
            for (auto [pm, pc] : pre) {
                if (color[pm][pc][pt] != 0) continue;  // 已定案
                if ((pt == 0 && win == 1) || (pt == 1 && win == 2)) {
                    color[pm][pc][pt] = win;  // 存在有利後繼 ⇒ 必勝
                    q.push({pm, pc, pt});
                } else if (--deg[pm][pc][pt] == 0) {
                    color[pm][pc][pt] = win;  // 所有後繼都不利 ⇒ 必敗
                    q.push({pm, pc, pt});
                }
            }
        }
        return color[1][2][0];
    }
};
```

**兩個判斷分支對應定理 3 的「存在」與「全稱」語意，順序不能顛倒**——先檢查「有利後繼」，沒有才 `deg--`。

**`pt = t ^ 1`**：前驅狀態輪到的是**另一方**。**這個方向搞反是最常見的錯，寫註解標明。**

**模板三：事件驅動模擬（2532 骨架，定理 5）**

```cpp
// waitL / waitR：等待過橋（按題目規則排序，堆頂是「下一個該走的人」）
// workL / workR：正在搬箱（按完成時刻排序）
long long cur = 0;
while (/* 還有箱子或還有人在右岸 */) {
    // 1. 把所有「已完成」的工人搬到對應的等待區
    while (!workL.empty() && workL.top().first <= cur) {
        waitL.push(...);
        workL.pop();
    }
    while (!workR.empty() && workR.top().first <= cur) {
        waitR.push(...);
        workR.pop();
    }
    // 2. 依規則決定誰過橋（右岸優先）
    if (!waitR.empty()) {                         /* 過橋回左岸 */
    } else if (!waitL.empty()&& /* 還有箱子 */) { /* 過橋去右岸 */
    } else {
        // 3. 兩邊都沒人能動 ⇒ 時間跳到最早完成時刻（定理 5）
        long long nxt = LLONG_MAX;
        if (!workL.empty()) nxt = min(nxt, workL.top().first);
        if (!workR.empty()) nxt = min(nxt, workR.top().first);
        if (nxt == LLONG_MAX) break;  // 防死迴圈
        cur = nxt;
    }
}
```

**`if (nxt == LLONG_MAX) break;` 是防死迴圈的保險絲。** 模擬題若邏輯有漏洞，最常見的症狀是無窮迴圈——**主動加一道防線，能把「TLE」變成「WA」，而 WA 好除錯得多。**

## 時間與空間複雜度

| 題型 | 狀態數 | 轉移 | 總計 |
| --- | --- | --- | --- |
| LCP 13 尋寶（定理 2） | $2^m \cdot m$ | $O(m)$ | $O(2^m m^2 + (m+2)NM)$ |
| 913 貓和老鼠（定理 3） | $2n^2$ | $O(\deg)$ | $O(n^3)$（邊數 $\times$ 狀態） |
| 1728 貓和老鼠 II | $2n^2 \cdot T$（$T$ = 步數上限） | $O(\text{可走格數})$ | 有步數維 ⇒ **正向記憶化可行** |
| 2532 過橋（定理 5） | 事件數 $O(k + \text{箱數})$ | $O(\log k)$ | $O((k+B)\log k)$ |
| 2056 枚舉組合（定理 6） | 組合數 | $O(1)$ 檢查 | 先估算，$\le 10^7$ 就直接寫 |

**規模感速查（定理 6）**：

| $m$（狀態壓縮） | $2^m$ | $2^m m^2$ |
| --- | --- | --- |
| 12 | 4096 | $5.9\times10^5$ |
| 16 | 65536 | $1.7\times10^7$ |
| 20 | $10^6$ | $4.2\times10^8$（**太大，要優化轉移**） |

**$m \le 16$ 是狀態壓縮 + TSP 的舒適區；$m = 20$ 就只能做 $O(2^m m)$ 的轉移。**

## 常見錯誤與邊界條件

- **狀態不完備**（定理 1）。忘了記 `turn`、忘了記「是哪些」而只記「幾個」。**症狀是答案在小測資對、大測資錯，且找不到規律。除錯法：構造兩個同狀態但答案不同的局面。**
- **狀態不最小**。多帶了一維（例如 913 的步數），狀態數翻 $n$ 倍導致 MLE。**先問：拿掉這一維，能構造出反例嗎？**
- **有環的博弈用了正向記憶化**（定理 3）。無窮遞迴或把「計算中」誤判成平局。**判斷條件：狀態圖有環 + 有「平局」這第三種結果 ⇒ 必須逆向 BFS。**
- **逆向 BFS 的前驅方向搞反**。`pt = t ^ 1`——**前驅輪到的是另一方。**
- **`deg` 初始化沒扣掉非法走法**。913 中貓不能進洞，`deg[·][·][1]` 要減 1。**`deg` 算多了，「必敗」永遠傳播不出來。**
- **BFS 起點漏了**（LCP 13）。要對 `S` 與**每個機關**各做一次 BFS；只對 `S` 做會拿不到 $c(j,j')$。
- **不可達的處理**。棋盤有障礙時 $d$ 可能是 $\infty$，**相加會溢位**。用 `INF = LLONG_MAX / 4` 並在相加前檢查。
- **位元運算優先級**。`mask >> j & 1` 對、`mask & 1 << j` 對，`mask & 1 >> j` 錯。**選一種寫法貫徹到底。**
- **狀態壓縮的初始狀態沒設**。`dp[1 << j][j] = c0[j]`——漏了就全是 INF。
- **逐秒模擬**（定理 5）。時間上限 $10^9$ 時必然 TLE。**改事件驅動。**
- **模擬題的比較器與題目規則不符**。**把題目原文抄成註解放在比較器旁邊。**
- **模擬迴圈沒有防死迴圈的出口**。加 `if (nxt == LLONG_MAX) break;`。
- **過早優化**（定理 6）。先估算狀態數，$\le 10^7$ 就直接寫。

## 與相似技巧的比較

- **與純 DP（dynamic_programming 章）**：複合題的第三層通常就是 DP，**差別在於狀態要自己設計而不是套模板。** 定理 1 的完備性判準就是 DP「無後效性」的另一種說法——**這一節與 DP 章共用同一個核心概念。**
- **與純圖論（graph 章）**：LCP 13 的第一層是多源 BFS、第三層是 TSP。**複合題常常是「圖論預處理 + DP 主體」，切開之後兩邊都是模板。** 找那條縫，是本節唯一需要創造力的地方。
- **與 8 節並查集**：LCP 21 追逐遊戲這類「$n$ 點 $n$ 邊」的基環樹問題，第一步是找環（拓撲剝葉或並查集），之後才是距離比較。**又是「先化簡結構，再套模板」。**
- **與搜尋剪枝（IDA*、A*）**：當狀態數超過 $10^8$（定理 6），只能靠剪枝把實際訪問的狀態壓下來。**但剪枝的效果無法事先估算，是最後手段。** 先確認真的沒有多項式解法。
- **與 11 節根號演算法**：複合題若卡在「$O(nq)$ 太慢、$O(n\log n)$ 想不出來」，**根號往往是那個中間選項**。$n \le 10^5$ 時 $O(n\sqrt n)$ 可過。
- **與 12 節離線**：複合題中若查詢彼此獨立，**先問能不能離線**——這常常把一個維度直接消掉。
- **與模擬題**：模擬題（2532）與演算法題的根本差異是**「策略由題目給定，不需要證明最優性」**。**不要在模擬題上尋找貪心證明，該做的是把規則抄準、把時間推進寫對。** 反過來，也不要把貪心題當模擬寫——那會漏掉最優性的驗證。

## 本節重點速查

- **三層拆解**：**狀態空間 → 轉移規則 → 搜尋策略。** 每一層都是已知模板，難的是切在哪裡。
- **定理 1（完備性判準）**：$\sigma(P)=\sigma(P') \Rightarrow \mathrm{opt}(P)=\mathrm{opt}(P')$。**檢查法：試著構造兩個同狀態但後續不同的局面——構造得出來，狀態就不完備。** 最小性則反過來問：拿掉這一維還有反例嗎？
- **定理 2（LCP 13）**：**把「棋盤最短路」與「訪問順序」切開**——BFS 預處理成 $m\times m$ 的代價表 $c(j,j')=\min_O(d(M_j,O)+d(O,M_{j'}))$，剩下是標準 TSP，$O(2^m m^2)$。**前提：石堆無限、棋盤不變**（否則狀態要加石堆集合，直接爆）。
- **定理 3（913）**：**有環的博弈 DP 必須逆向 BFS。** 「存在有利後繼 ⇒ 必勝」（一個就夠）、「所有後繼都不利 ⇒ 必敗」（用 `deg` 計數到 0）、「其餘 ⇒ 平局」。**觸發條件：狀態圖有環 + 有第三種結果「平局」。** 有步數上限（1728）就切開了環，正向記憶化又可行。
- **定理 4（抽屜原理）**：狀態數 $2n(n-1)$ ⇒ 超過就必有重複 ⇒ 循環 ⇒ 平局。**所以「已走步數」這一維可以省掉**，狀態從 $O(n^3)$ 降到 $O(n^2)$。依賴「最優策略只依賴狀態」。
- **定理 5（模擬題）**：**策略由題目規定，不需要交換論證。** 不變量 (W)：四個容器的併集恆為全部工人（**拿來寫 `assert`**）。**事件驅動而非逐秒**：等待區皆空時直接跳到最早完成時刻。比較器逐字對應題目原文。**加防死迴圈的 `break`。**
- **定理 6（先估算）**：狀態數 × 轉移數 $\le 10^7$ ⇒ 直接暴力，別優化。**算的是「不同狀態數」而非「路徑條數」。** $2^{16}m^2 = 1.7\times10^7$ 可行、$2^{20}m^2 = 4\times10^8$ 不可行；**空間常常比時間先爆。**
