## 這個技術解決什麼問題

有一類題目**沒有演算法**——它的難不在「想出聰明做法」，而在「把一長串規則做對」。

**辨識訊號**：
- 題目描述本身就是一長串規則（合法格式、轉換對照、排版要求），重點是**照規則做對**，而非想出聰明演算法。像 8 字串轉整數（atoi）、65 有效數字、68 文字左右對齊；
- 輸入是字串或數字，要**轉成另一種表示**，且有大量邊界要處理（12/13 羅馬數字、273 整數轉英文）；
- **沒有明顯的最優化目標**（不是求最大／最小／計數），而是「忠實還原規則」。

**這類題的失分點與演算法題完全不同**：不是 TLE，而是**規則漏了一條**。所以本節的核心方法不是複雜度分析，而是：

> **把規則寫成一個「完整劃分」——輸入空間的每一種情況都恰好落入一條規則。**

**完整劃分是可以驗證的**（定理 1），這就是本節的主軸。**同時，這類題目裡也藏著兩種真正需要證明的東西**：**結構不變量**（146 LRU、460 LFU 的資料結構同步，定理 3、4）與**被規則偽裝的最優化**（420 強密碼、2468 分割訊息，定理 5、6）——**後兩題看起來是模擬題，實際上必須做貪心論證與不動點分析，這是本節最容易低估的地方。**

## 狀態／資料結構定義

**四種骨架，對應四類規則題。**

**骨架 A：DFA 狀態表（格式驗證，65、8）**

```cpp
// 把「合法字串」的規則畫成有限狀態機：state x charClass -> nextState（-1 = 拒絕）
enum CharClass { DIGIT, SIGN, DOT, EXP, OTHER };
// 每一格都必須填，包含明確的「拒絕」。留空 = 漏規則（定理 1）
static const int TRANS[9][5] = {/* ... */};
static const bool ACCEPT[9] = {/* 哪些狀態可以作為結尾 */};
```

**骨架 B：雜湊表 + 侵入式鏈結串列（LRU，146）**

```cpp
list<pair<int, int>> lst;  // 前端 = 最近使用
unordered_map<int, list<pair<int, int>>::iterator> pos;  // key -> 節點迭代器
// 提升（O(1)，且迭代器仍然有效，定理 3）：
// lst.splice(lst.begin(), lst, it);
```

**骨架 C：頻率桶 + `minFreq`（LFU，460）**

```cpp
unordered_map<int, list<pair<int, int>>>
    bucket;  // freq -> 該頻率的 key 串列（前端最新）
unordered_map<int, pair<int, list<pair<int, int>>::iterator>>
    pos;          // key -> (freq, 迭代器)
int minFreq = 0;  // 不變量見定理 4
```

**骨架 D：分組轉換（273、12/13）**

```cpp
// 273：每三位一組，組內轉換是一個對 [0,999] 全域定義的函式
static const string SCALE[] = {"", " Thousand", " Million", " Billion"};
// 12：13 個值由大到小；貪心等價於逐位查表（定理 2）
static const int VAL[13] = {1000, 900, 500, 400, 100, 90, 50,
                            40,   10,  9,   5,   4,   1};
static const char* SYM[13] = {"M",  "CM", "D",  "CD", "C",  "XC", "L",
                              "XL", "X",  "IX", "V",  "IV", "I"};
```

**選骨架的判準**：

| 規則的形狀 | 骨架 |
| --- | --- |
| 「這個字串合不合法」 | **A（DFA）**——把規則變成表格 |
| 「維護一個有淘汰策略的容器」 | **B / C**——雜湊表指向串列節點 |
| 「把 X 表示成 Y」 | **D**——找出可獨立處理的「組」 |
| 「求最少操作次數」 | **不是模擬題**，見定理 5、6 |

## 不變量或正確性證明

### 定理 1（規則實作的正確性判準：完整劃分）

**命題**：設輸入空間為 $\mathcal{I}$，程式的分支條件為 $C_1,\dots,C_k$。程式正確的**必要條件**是

$$\bigcup_{i=1}^{k} C_i = \mathcal{I} \quad\text{(不漏)}\qquad\text{且}\qquad C_i \cap C_j = \varnothing\ (i\ne j) \quad\text{(不重)}.$$

*為什麼這是可驗證的*。「不漏」失敗 ⇒ 存在輸入落不進任何分支，程式行為未定義（通常是回傳初始值）。「不重」失敗 ⇒ 行為取決於 `if` 的書寫順序，**規格與實作脫鉤**，改動順序就會改變答案。$\square$

**這聽起來像廢話，但它給了一個具體的除錯流程**：

> **把所有分支條件列成一張表，逐一問「這個輸入落在哪一格」。找不到格子 ⇒ 漏規則；找到兩格 ⇒ 重疊。**

**DFA 是這張表的極致形式**：`TRANS[state][charClass]` 的每一格都必須填值（包含明確的 $-1$ 表示拒絕）。**表格中留空的格子，就是漏掉的規則。** 這正是骨架 A 優於一連串 `if-else` 的原因——**表格的「空格」看得見，`if-else` 的「漏掉」看不見。**

**以 65 有效數字為例**，DFA 接受的語言恰為

$$\texttt{[+-]?}\;\big(\;\texttt{d+}\;\texttt{.?}\;\texttt{d*}\;\big|\;\texttt{.}\,\texttt{d+}\;\big)\;\big(\texttt{[eE]}\;\texttt{[+-]?}\;\texttt{d+}\big)\texttt{?}$$

**寫完 DFA 後的驗收方式**：把這個正規表示式與轉移表逐項對照，**確認每個接受狀態都對應到表示式的一個合法結尾**（整數部分結尾、小數部分結尾、指數部分結尾），且**「只有小數點」「只有 e」「e 後面沒有數字」都不是接受狀態** ✔。

**要點名的前提**：DFA 只驗證**格式**，不驗證**數值範圍**。8 atoi 要求截斷到 `int` 範圍——**那是另一條規則，不屬於 DFA。** 把兩者混在同一張表裡是常見的設計錯誤。

### 定理 2（12 羅馬數字：貪心等價於逐位查表）

*命題*：對 $1 \le n \le 3999$，用 13 個值由大到小的貪心，產生的字串等於標準羅馬數字表示。

*證明*。把 13 個值分成四組（依數量級）：

$$\{1000\},\quad \{900,500,400,100\},\quad \{90,50,40,10\},\quad \{9,5,4,1\}.$$

- **(組間不干擾)** 貪心處理完 $\{1000\}$ 後餘數 $< 1000$；處理完百位組後餘數 $< 100$；依此類推 ✔。因此**每一組只看到自己那一位數字**。
- **(組內正確)** 對單一組 $\{9u, 5u, 4u, u\}$ 與任意數字 $h \in [0,9]$，貪心產生的符號串就是標準寫法。這是**有限的 10 個情況**，逐一驗證：$0\to\varepsilon$、$1\to u$、$2\to uu$、$3\to uuu$、$4\to 4u$、$5\to 5u$、$6\to 5u\,u$、$7\to 5u\,uu$、$8\to 5u\,uuu$、$9\to 9u$ ✔。

兩者合起來即得結論。$\square$

**這個證明的價值在於它是「有限驗證」**——不需要巧妙的交換論證，只要確認 10 個情況。**遇到「查表 + 貪心」的轉換題，先問：能不能把它切成互不干擾的組，讓組內只剩有限個情況？**

**反方向（13 羅馬數字轉整數）的不變量**：*由左至右掃描，若 $\mathrm{val}(s_i) < \mathrm{val}(s_{i+1})$ 則減、否則加。*

*正確性依賴的前提*：**在合法的羅馬數字中，「小值在大值之前」恰好只出現在 6 個減法組合（IV, IX, XL, XC, CD, CM）中。** 這條前提由題目保證輸入合法 ✔。**若輸入可能非法，這個掃描法會靜默地算出一個數字而不報錯**——這時要改用定理 1 的完整劃分先做驗證。

### 定理 3（146 LRU：迭代器有效性是不變量的前提）

**不變量 (L)**：*對每個 key $k$ 在容器中，$\mathit{pos}[k]$ 指向 `lst` 中唯一那個 first 等於 $k$ 的節點；且 `lst` 由前到後恰為「最近使用」到「最久未使用」的順序。*

*維持 (L) 的關鍵操作*：`lst.splice(lst.begin(), lst, it)`。

*為什麼 (L) 在 splice 後仍成立*——**這裡有一條必須點名的前提**：

> **`std::list::splice` 保證被移動的元素其迭代器、指標、參考全部保持有效**，只是所屬位置改變（若跨容器則歸屬也改變）。

因此 `pos[k]` 不需要更新 ✔。**這正是選 `std::list` 而不是 `std::vector` 或 `std::deque` 的唯一理由**——後兩者的任何插入刪除都可能使迭代器失效，不變量 (L) 立刻崩潰。

**推論 3.1**：`get` 與 `put` 都是 $O(1)$，**因為 splice 是 $O(1)$ 的指標改接，不是元素搬移** ✔。

**推論 3.2（淘汰的順序不能反）**：`put` 一個新 key 且已滿時，**必須先刪 `lst.back()` 對應的 `pos` 條目，再 `lst.pop_back()`**。反過來寫會先讓迭代器懸空，然後拿它去查 `pos` ✘。**這是 LRU 最常見的 UB。**

### 定理 4（460 LFU：`minFreq` 為什麼只需要 +1）

**不變量 (F)**：*`minFreq` 恰等於當前容器中所有 key 的頻率最小值（容器非空時）。*

*證明（對操作數歸納）*。能改變頻率集合的操作只有三種：

1. **插入新 key**：其頻率為 1，是可能的最小值 ⇒ 令 `minFreq = 1` ✔。
2. **淘汰**：從 `bucket[minFreq]` 移除一個 key。若該桶變空，則接下來**一定緊接著插入新 key**（淘汰只發生在容量已滿的 `put` 中），由情況 1 重設 `minFreq = 1` ✔。
3. **存取既有 key**（`get` 或覆寫的 `put`）：把它從 `bucket[f]` 移到 `bucket[f+1]`。**這是整條不變量的核心：**
   - 若 $f > \mathit{minFreq}$：最小值不變 ✔；
   - 若 $f = \mathit{minFreq}$ 且 `bucket[f]` 移除後**非空**：仍有 key 的頻率為 $f$，最小值不變 ✔；
   - 若 $f = \mathit{minFreq}$ 且 `bucket[f]` 變空：所有 key 的頻率都 $> f$。而剛才那個 key 的新頻率是 $f+1$，**所以最小值恰為 $f+1$** ⇒ `minFreq++` ✔。

$\square$

**最後一條分支是整個 LFU 能做到 $O(1)$ 的原因**，而它依賴兩個前提：

> **前提一：頻率一次只 +1（不會跳號）。**
> **前提二：一次操作只改變一個 key 的頻率。**

**兩者缺一，`minFreq++` 就不成立，必須重掃所有桶找最小值（$O(\text{桶數})$）。** 若題目改成「存取一次頻率 +2」或「批次操作」，這個 $O(1)$ 立刻失效——**這是「不變量依賴什麼前提」的教科書例子。**

**桶內的順序**：同頻率時淘汰最久未使用者 ⇒ 每個桶自己是一個 LRU 串列（定理 3 的結構原封不動套用）✔。**LFU = LRU 再加一層頻率索引。**

### 定理 5（420 強密碼檢驗器：偽裝成模擬的貪心）

*問題*：合法密碼需滿足 (i) $6 \le \mathrm{len} \le 20$、(ii) 含大寫、小寫、數字、(iii) 無連續 3 個相同字元。求最少操作（插入／刪除／替換）次數。

**這不是模擬題。** 三種操作可以互相替代，必須做最優化論證。設 $t \in [0,3]$ 為缺少的字元種類數。

**情況 A（$\mathrm{len} < 6$）**：答案 $= \max(6 - \mathrm{len},\; t)$。

*證明*。$\ge$ 方向：長度至少要補到 6，且每種缺少的字元至少需要一次操作 ✔。$\le$ 方向：$\mathrm{len} \le 5$ ⇒ 最長連續段 $\le 5$ ⇒ 至多需要打斷一處。**每次插入都可以同時（a）增加長度、（b）補一個缺少的種類、（c）插在連續段中間打斷它**——三件事一次做完 ✔。$\square$

**情況 B（$6 \le \mathrm{len} \le 20$）**：答案 $= \max(r,\; t)$，其中 $r = \sum_{\text{連續段}} \lfloor L/3 \rfloor$。

*證明*。$r$ 是打斷所有連續段所需的最少替換數（長度 $L$ 的段每 3 個必須改一個）✔。**每次替換都可以順便補一個缺少的種類**（把被改的字元選成缺少的那類）⇒ 兩個需求可以合併，取 $\max$ ✔。$\square$

**情況 C（$\mathrm{len} > 20$）**：必須刪 $d = \mathrm{len} - 20$ 個字元。答案 $= d + \max(r',\; t)$，$r'$ 是刪除後剩餘的替換數。**這裡才是真正的貪心。**

*關鍵觀察*：對一個長度 $L \ge 3$ 的連續段，刪 $x$ 個字元後替換數變成 $\lfloor (L-x)/3 \rfloor$。因此

| $L \bmod 3$ | 少一次替換所需的刪除數 |
| --- | --- |
| $0$ | **1** |
| $1$ | **2** |
| $2$ | **3** |

*貪心*：把 $d$ 次刪除**優先用在 $L \bmod 3 = 0$ 的段（每次刪除換 1 次替換），其次 $L \bmod 3 = 1$，最後其餘。**

*交換論證*。任何一次刪除最多讓總替換數減少 1（因為 $\lfloor (L-1)/3 \rfloor \ge \lfloor L/3 \rfloor - 1$）✔。$L \bmod 3 = 0$ 的段達到了這個上界（1 次刪除換 1 次替換），是可能的最佳效率。設某個最優解沒有把第一次刪除用在某個 $L \bmod 3 = 0$ 的段上，把它換成用在該段，總替換數的減少量不減、刪除數不變 ⇒ 仍為最優 ✔。對後續刪除歸納即得。$\square$

**要點名的前提**：**刪除總數 $d$ 是固定的**（由長度上限決定），所以只需要最小化「刪除後的替換數」這一個目標——**若 $d$ 也是自由變數，這個貪心就不成立。** 另外「刪除不會製造新的連續段」在此成立，因為刪的是段內字元；**若允許刪段外字元把兩個同字元的段接起來，論證要重寫**（本題不會更優，因為那樣既沒減少替換又浪費了刪除）。

### 定理 6（2468 分割訊息：為什麼不能二分搜尋 $b$）

*問題*：把長度 $n$ 的訊息切成 $b$ 段，第 $i$ 段結尾必須附上 `<i/b>`，每段（含後綴）長度不超過 `limit`。求最小的 $b$。

*容量函式*：第 $i$ 段能裝的內容長度為

$$\mathrm{cap}_i(b) = \mathrm{limit} - 3 - |i| - |b|,\qquad |x| \coloneqq x \text{ 的十進位位數},$$

（$3$ 來自 `<`、`/`、`>`）。$b$ 可行 $\iff$ **所有** $\mathrm{cap}_i(b) \ge 1$ 且 $\sum_{i=1}^{b} \mathrm{cap}_i(b) \ge n$。

**這裡的陷阱：$b$ 同時出現在「段數」與「每段後綴長度」裡——這是一個自我指涉。**

*命題*：$C(b) \coloneqq \sum_{i=1}^{b} \mathrm{cap}_i(b)$ **不是 $b$ 的單調遞增函式**，因此**不能對 $b$ 二分搜尋可行性**。

*反例*。取 $\mathrm{limit} = 10$：

$$C(9) = \sum_{i=1}^{9}(10 - 3 - 1 - 1) = 9 \times 5 = 45,$$
$$C(10) = \sum_{i=1}^{9}(10 - 3 - 1 - 2) \;+\; (10 - 3 - 2 - 2) = 9 \times 4 + 3 = 39.$$

$C(10) = 39 < 45 = C(9)$ ✘。$\square$

**原因**：$b$ 從 9 跳到 10 時，$|b|$ 由 1 變 2，**每一段都損失一個字元**；新增的那一段補回來的容量不足以抵銷。**一般地，$b$ 跨過 $10^k$ 時 $C$ 會下降 $\approx b - \mathrm{limit}$。**

**推論 6.1（正確做法）**：**從 $b = 1$ 遞增枚舉到 $b = n$，第一個可行的就是答案。** $n \le 10^4$ ⇒ 直接枚舉完全可行；用「按位數分組」（$b \in [1,9], [10,99], \dots$）可讓每組內 $|b|$ 固定、$\sum |i|$ 用前綴和 $O(1)$ 取得，總計 $O(n)$。

**推論 6.2**：$\mathrm{cap}_i(b) \ge 1$ 這個逐段條件**不能省略**。只檢查總和 $\sum \mathrm{cap}_i(b) \ge n$，會接受「某一段裝不下任何內容」的 $b$ ✘——**這正是定理 1 的「漏規則」在數值題中的樣子。**

**這一題值得單獨記住的教訓**：**看到「參數自我指涉」（答案的位數影響答案），先驗證單調性再談二分。** 大多數人會直覺地二分，而這題的單調性剛好不成立。

## 時間與空間複雜度

| 題目 | 時間 | 空間 | 備註 |
| --- | --- | --- | --- |
| 8 atoi / 65 有效數字 | $O(n)$ | $O(1)$（DFA 表是常數） | 單次掃描，每字元一次表格查詢 |
| 12 整數轉羅馬 | $O(\log n)$ | $O(1)$ | 至多 13 個值、輸出長度 $\le 15$ |
| 13 羅馬轉整數 | $O(n)$ | $O(1)$ | 單次掃描 |
| 68 文字左右對齊 | $O(\sum \lvert w_i \rvert)$ | $O(\text{輸出})$ | 每個單字被讀 $O(1)$ 次 |
| 146 LRU | **$O(1)$ 均攤**（定理 3） | $O(\mathrm{capacity})$ | splice 是指標改接 |
| 273 整數轉英文 | $O(\log n)$ | $O(1)$ | 至多 4 組 |
| 420 強密碼（定理 5） | $O(n)$ | $O(n/3)$ 存段長 | 掃一次求段長 + 一次貪心分配 |
| 460 LFU | **$O(1)$ 均攤**（定理 4） | $O(\mathrm{capacity})$ | `minFreq` 只 +1 或重設 |
| 2468 分割訊息（定理 6） | $O(n)$ | $O(n)$ 輸出 | 按位數分組枚舉 $b$ |

**兩點值得強調**：

- **146／460 的 $O(1)$ 是真 $O(1)$，不是「$O(\log n)$ 但常數小」。** 它靠的是「雜湊表 $O(1)$ 定位 + 串列 $O(1)$ 改接」的組合。**若把 `list` 換成 `set` 或平衡樹，就退化成 $O(\log n)$**——面試中這是常被追問的一點。
- **這一類題的實際瓶頸幾乎不是複雜度，而是常數與程式碼長度。** 68 文字對齊的 $O(n)$ 毫無爭議，難的是把「最後一行左對齊」「單字間空格盡量平均、多的放左邊」「只有一個單字時右填空格」三條規則同時做對。**寫這類題時，把時間花在列規則表上，不要花在優化上。**

## 與相似技巧的比較

- **與 13.1 綜合題**：13.1 的難點是**設計狀態**（要創造），13.2 的難點是**窮盡規則**（要完備）。**兩者的檢查方式相反**：13.1 靠「構造反例」證明狀態不完備（定理 1 of 13.1），13.2 靠「列表格找空格」證明規則不完整（定理 1）。**一個是找漏洞，一個是填格子。**
- **與 6 節堆（優先佇列）**：LRU／LFU 看起來像「取最小」，很容易想用堆。**但堆的 `decrease-key` 需要 $O(\log n)$ 且標準 `priority_queue` 不支援**；LFU 靠「頻率只 +1」這個前提（定理 4 前提一）把它降成 $O(1)$ 的桶操作。**當鍵值的變化量有界且很小時，桶（counting）永遠打敗堆。**
- **與 2 節字首和**：2468 用位數分組 + 前綴和把 $\sum_{i=1}^{b}|i|$ 壓成 $O(1)$ 查詢。**規則題裡也常常需要這種小優化，但那是最後 5% 的事。**
- **與貪心（greedy 章）**：420 與 2468 是**偽裝成模擬題的最優化題**。**判準：題目問「最少操作次數」或「最小的 $b$」⇒ 需要證明，不是模擬。** 反過來，2532 過橋（13.1 定理 5）問的是「最後時刻」而策略由題目給定 ⇒ 是模擬，不需要證明。**看題目問的是「最少」還是「結果」。**
- **與正規表示式**：65 可以用 `std::regex` 一行解決，但**面試與競賽都會要求手寫 DFA**——因為 DFA 讓「規則是否完整」變成可檢查的表格（定理 1），而正規表示式把它藏起來了。**手寫 DFA 也是 $O(n)$，`std::regex` 的回溯反而可能更慢。**
- **與設計題（18 節）**：146／460 屬於設計題，差別在於**設計題通常要你自己選資料結構組合**，而本節強調的是**選定之後那條不變量為什麼成立**（定理 3、4）。**能說出「splice 保證迭代器有效」與「minFreq 只會 +1」的人，和只會背模板的人，在追問下差別立現。**

## 本節重點速查

- **定理 1（完整劃分）**：分支條件必須**不重不漏**地覆蓋輸入空間。**除錯流程：列成表格，逐一問「這個輸入落在哪一格」。** DFA 之所以優於 `if-else` 串，是因為**表格的空格看得見**。前提：DFA 只管格式，數值範圍（atoi 的溢位截斷）是另一條規則。
- **定理 2（12 羅馬數字）**：貪心 = 逐位查表。**證明靠兩步：組間不干擾（餘數逐級變小）+ 組內只有 10 個情況（有限驗證）。** 13 的反向掃描依賴「小值在前只出現在 6 個減法組合」——**這條由題目保證輸入合法。**
- **定理 3（146 LRU）**：不變量 (L) = `pos[k]` 指向 `lst` 中唯一的 $k$ 節點，`lst` 前端最新。**成立的前提是 `std::list::splice` 保證迭代器有效**——這是選 `list` 而非 `vector`／`deque` 的唯一理由。**淘汰時先刪 `pos` 條目再 `pop_back`，反了就是 UB。**
- **定理 4（460 LFU）**：不變量 (F) = `minFreq` 恆為當前最小頻率。**桶變空時只需 `minFreq++`，依賴兩個前提：頻率一次只 +1、一次只改一個 key。** 缺一就得重掃所有桶。**LFU = LRU 再加一層頻率索引。**
- **定理 5（420 強密碼）**：**這是貪心不是模擬。** $\mathrm{len}<6 \Rightarrow \max(6-\mathrm{len},t)$；$6\le\mathrm{len}\le20 \Rightarrow \max(r,t)$；$\mathrm{len}>20 \Rightarrow d + \max(r',t)$，刪除**優先給 $L\bmod3=0$ 的段（1 刪換 1 替換），再 $L\bmod3=1$（2 刪），再其餘（3 刪）**。交換論證的上界：**一次刪除最多省 1 次替換。** 前提：$d$ 是固定的。
- **定理 6（2468 分割訊息）**：容量 $C(b)=\sum_i(\mathrm{limit}-3-|i|-|b|)$ **對 $b$ 不單調**（$\mathrm{limit}=10$ 時 $C(10)=39<45=C(9)$）⇒ **不能二分，要從小到大枚舉 $b$。** 逐段條件 $\mathrm{cap}_i(b)\ge1$ 不能只用總和取代。**教訓：參數自我指涉時，先驗證單調性再談二分。**
- **判別「模擬」與「最優化」**：**題目問「最少／最小」⇒ 要證明；問「結果是什麼」且策略由題目給定 ⇒ 忠實實作即可。**
