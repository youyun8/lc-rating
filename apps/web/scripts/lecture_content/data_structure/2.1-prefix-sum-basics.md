## 這個技術解決什麼問題

「回答 $q$ 次『區間 $[l, r]$ 的和是多少』」若每次重掃是 $O(n)$，總計 $O(nq)$。$n = q = 10^5$ 時是 $10^{10}$，不可行。

前綴和把成本重新分配：**預處理一次 $O(n)$，之後每次查詢 $O(1)$**，總計 $O(n + q)$。

這個技巧的價值遠不止於「查區間和」。它真正的內容是一句話：**若一個量沿序列可累加，就把「區間的量」改寫成「兩個前綴的差」。** 只要能寫成差，區間問題就退化成兩點問題，而兩點問題可以配上雜湊表（2.2）、有序集合（2.7）、單調堆疊、二分（2.5）等各種工具。第 2 章後面七節全部建立在這一句話上。

## 狀態／資料結構定義

**定義（前綴和陣列）：**
$$s_0 = 0, \qquad s_i = \sum_{t=0}^{i-1} a_t \quad (1 \le i \le n).$$

長度是 $n+1$，**不是 $n$**。$s_i$ 的語意是「前 $i$ 個元素的和」，即 $a[0..i-1]$。

於是
$$\sum_{t=l}^{r} a_t = s_{r+1} - s_l .$$

**多開一格哨兵 $s_0 = 0$ 是本節最重要的實作決定。** 它讓「區間從 0 開始」不需要特判：$\sum_{t=0}^{r} a_t = s_{r+1} - s_0 = s_{r+1}$。若省掉哨兵而定義 $s_i = a_0 + \dots + a_i$，公式變成 $s_r - s_{l-1}$，$l = 0$ 時要寫 `l == 0 ? s[r] : s[r] - s[l-1]`——這個三元運算子就是所有前綴和 bug 的溫床。

**可累加的量不限於加法。** 只要 $(\oplus, e)$ 是一個**群**（有結合律、單位元、且每個元素有逆元），同一套公式就成立：

| 運算 | 單位元 | 逆運算 | 用途 |
| --- | --- | --- | --- |
| $+$ | 0 | $-$ | 區間和 |
| XOR | 0 | XOR 自己 | 區間異或（1738、1310） |
| $\times$（無 0） | 1 | 除法 | 區間乘積（724 變體） |
| 計數 | 0 | $-$ | 區間內某條件的個數（2559、1523） |

**逆元存在是關鍵。** $\max$ 與 $\min$ 有結合律、有單位元，但**沒有逆元**——「$\max$ 前綴」無法相減還原區間 $\max$。這正是 9.3 線段樹與 9.7 ST 表存在的理由。

## 不變量或正確性證明

**引理。** 對 $0 \le l \le r < n$，$\displaystyle\sum_{t=l}^{r} a_t = s_{r+1} - s_l$。

*證明。* 由定義 $s_{r+1} = \sum_{t=0}^{r} a_t$、$s_l = \sum_{t=0}^{l-1} a_t$。相減得 $\sum_{t=0}^{r} a_t - \sum_{t=0}^{l-1} a_t = \sum_{t=l}^{r} a_t$（第二個和是第一個和的前綴，$l \le r+1$ 保證下標範圍合法）。$\square$

**遞推的正確性（歸納）。** `s[i+1] = s[i] + a[i]`：
- 基底 $s_0 = 0$（空和）。
- 歸納：若 $s_i = \sum_{t<i} a_t$，則 $s_i + a_i = \sum_{t \le i} a_t = s_{i+1}$。$\square$

**這條論證點名了三個前提。**

1. **陣列在查詢期間不變。** 一旦某個 $a_j$ 改了，所有 $s_i$（$i > j$）都要更新，$O(n)$。**「單點修改 + 區間查詢」混合出現時，前綴和失效，必須換樹狀陣列（9.1）。** 這是選型的第一判準。
2. **運算必須有逆元。** 見上表。沒有逆元就不能相減。
3. **不能溢位。** $s_i$ 是 $i$ 個元素的和，即使每個 $a_t$ 是 `int`，$s_n$ 也可能達到 $n \cdot \max|a|$。$n = 10^5$、$|a| \le 10^9$ 時是 $10^{14}$，**必須 `long long`**。這不是防禦性寫法，是絕大多數前綴和題的實際需求。

**53（最大子陣列和）的前綴和視角。** $\max_{l \le r} (s_{r+1} - s_l) = \max_r \left( s_{r+1} - \min_{l \le r} s_l \right)$。固定右端點，最佳左端點是「歷史最小前綴」——**這正是 1.1 的「列舉右、維護左」套在前綴和序列上**。Kadane 演算法是同一件事的另一種寫法，但前綴和視角能直接推廣到「長度至少 $k$」「和不超過上限」等變體，Kadane 不行。

**1523（區間內奇數個數）的計數型前綴。** 令 $c_i$ = 前 $i$ 個整數中奇數的個數 $= \lceil i/2 \rceil$。答案是 $c_{high+1} - c_{low}$。這裡的「陣列」是隱式的（無限長的整數序列），前綴和用**閉式公式**而非陣列。**當序列有閉式前綴時，連 $O(n)$ 的預處理都省了，$O(1)$ 空間。**

## C++17 模板

```cpp
// 區域和檢索 - 陣列不可變（LeetCode 303）：前綴和的標準骨架。
class NumArray {
    std::vector<long long> s_;  // s_[i] = nums[0..i-1] 的和；長度 n+1

public:
    explicit NumArray(std::vector<int>& nums) : s_(nums.size() + 1, 0) {
        for (size_t i = 0; i < nums.size(); ++i) {
            s_[i + 1] = s_[i] + nums[i];  // 哨兵 s_[0] = 0，讓 l == 0 不必特判
        }
    }

    int sumRange(int left, int right) {
        return static_cast<int>(s_[right + 1] -
                                s_[left]);  // 閉區間 [left, right]
    }
};
```

```cpp
// 最大子陣列和（LeetCode 53）：前綴和 + 維護歷史最小前綴。
class Solution {
public:
    int maxSubArray(std::vector<int>& nums) {
        long long s = 0;          // 目前的前綴和 s_{r+1}
        long long minPrefix = 0;  // min over l <= r of s_l；初值是 s_0 = 0
        long long ans = LLONG_MIN;
        for (int x : nums) {
            s += x;                              // s 變成 s_{r+1}
            ans = std::max(ans, s - minPrefix);  // 先用「左邊的最小前綴」算答案
            minPrefix = std::min(minPrefix, s);  // 再把 s_{r+1} 併入左側摘要
        }
        return static_cast<int>(ans);
    }
};
```

第二個模板的 `minPrefix` 初值必須是 `0`（即 $s_0$），不是 `LLONG_MAX`。因為子陣列非空，右端點 $r$ 對應的合法左端點是 $l \in [0, r]$，其中 $l = 0$ 對應 $s_0 = 0$——**這一格若漏掉，全負陣列會回傳錯誤答案**。同樣地，`ans` 必須在更新 `minPrefix` **之前**算，否則會允許 $l = r+1$（空子陣列，和為 0）。

## 時間與空間複雜度

預處理 $O(n)$ 時間、$O(n)$ 空間；單次查詢 $O(1)$。$q$ 次查詢總計 $O(n + q)$。

與 $O(nq)$ 的暴力相比：$n = q = 10^5$ 時 $10^{10} \to 2\times10^5$。

**空間可以省成 $O(1)$ 的情形**：若查詢只有一次、或前綴和只被順序使用一次（53、2559 的部分寫法），用一個滾動變數即可，不必存整個陣列。**判準是「會不會回頭查任意位置的前綴」**：會，就存陣列；不會，就用變數。

**多維推廣**：二維是 $O(mn)$ 預處理、$O(1)$ 查詢（2.6）；$d$ 維是 $O(n^d)$ 預處理、$O(2^d)$ 查詢（容斥的項數）。

## 常見錯誤與邊界條件

- 前綴和陣列開成長度 $n$ 而非 $n+1$（然後被迫用 `l == 0 ? ... : ...` 特判）。
- 公式寫成 `s[r] - s[l]`（少算一項）或 `s[r+1] - s[l+1]`（多算一項）——**永遠回頭用定義驗一次 $l = r$ 的單元素情形：$s_{r+1} - s_r = a_r$ ✔**。
- 用 `int` 存前綴和導致溢位（最常見的一種）。
- 輸入含負數時仍套用「和單調遞增」的假設（滑動視窗、二分都會錯，見 2.2）。
- 53 把 `minPrefix` 初值設成 `nums[0]` 或 `LLONG_MAX`。
- 53 在更新 `minPrefix` 之後才算答案（允許了空子陣列）。
- 查詢區間用半開 $[l, r)$ 與閉區間 $[l, r]$ 混用。
- 預處理後又修改了原陣列。
- 1310（區間異或）忘記 XOR 的逆運算是它自己，寫成減法。
- 對 $\max/\min$ 套用前綴相減（**沒有逆元，根本不成立**）。

## 與相似技巧的比較

- **與差分（3.1）**：前綴和與差分互為逆運算。前綴和是「多次查詢、不修改」；差分是「多次區間修改、最後一次查詢」。**兩者都要求修改與查詢分階段**；一旦交錯，就得升級到樹狀陣列或線段樹。
- **與樹狀陣列（9.1）**：樹狀陣列 = 支援單點修改的前綴和，代價是查詢從 $O(1)$ 變 $O(\log n)$。**只有真的需要修改才付這個代價。**
- **與 ST 表（9.7）／線段樹（9.3）**：$\max/\min/\gcd$ 沒有逆元，前綴相減不成立，必須用這兩者。**「有沒有逆元」是這個選型分岔的唯一判準。**
- **與滑動視窗**：滑動視窗也算區間和，但它依賴「元素非負 ⇒ 區間和隨長度單調」，才能雙指標同向移動。**有負數時滑動視窗失效，前綴和 + 雜湊表（2.2）接手。** 反之，全正數時滑動視窗是 $O(1)$ 空間，更好。
- **與 1.1**：53 的解法就是 1.1 套在前綴和序列上。**第 2 章大部分內容都可以理解為「先做前綴和轉換，再套第 1 章的技巧」。**

## 本節重點速查

- $s_0 = 0$、$s_i = a_0 + \dots + a_{i-1}$，長度 **$n+1$**；區間和 $= s_{r+1} - s_l$。
- **哨兵 $s_0 = 0$ 是為了讓 $l = 0$ 不必特判**，省掉三元運算子這個 bug 溫床。
- 公式記不清就驗 $l = r$：$s_{r+1} - s_r = a_r$ ✔。
- 成立的三個前提：**陣列不變、運算有逆元、不溢位**。$\max/\min$ 沒有逆元，要用線段樹或 ST 表；要修改就用樹狀陣列。
- 前綴和一律開 `long long`。
- 53 = 前綴和 + 1.1：$\max_r (s_{r+1} - \min_{l \le r} s_l)$，`minPrefix` 初值是 $s_0 = 0$，且**先算答案再更新**。
- 有閉式前綴（1523）時連陣列都不用建，$O(1)$ 空間。
