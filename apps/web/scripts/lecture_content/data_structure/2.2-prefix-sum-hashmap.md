## 這個技術解決什麼問題

2.1 回答的是「給定區間，求它的和」。本節反過來：**給定和的條件，求有幾個區間（或最長／最短的區間）滿足它。** 區間本身是未知數。

- 560：和恰為 $k$ 的子陣列個數。
- 325：和為 $k$ 的最長子陣列。
- 523／974：和可被 $k$ 整除的子陣列。
- 525：0 與 1 個數相等的最長子陣列。
- 437：樹上和為 target 的路徑數。
- 1524：和為奇數的子陣列個數。

若陣列全為正數，滑動視窗就能解（$O(1)$ 空間）。**但只要有負數（或 0），加入一個元素不保證讓和變大，雙指標無法單調推進，滑動視窗徹底失效。** 本節是這種情形的通解。

核心只有一步改寫：
$$\sum_{t=l}^{r} a_t = k \iff s_{r+1} - s_l = k \iff s_l = s_{r+1} - k .$$

左邊是「區間條件」（兩個未知數），右邊是「兩個前綴值之間的關係」（配對問題）。**於是 1.1 的「列舉右、維護左」可以原封不動套上去**——只是把原陣列換成前綴和序列。

## 狀態／資料結構定義

- **前綴和** $s_i$（沿用 2.1 的定義，$s_0 = 0$）。實作上通常不存陣列，只用一個滾動變數 `s`。
- **摘要** `cnt`：把「已出現的前綴值」映射到題目需要的東西：
  - 數個數（560、974、1524）→ `unordered_map<long long,int>`：前綴值 → 出現次數。
  - 求最長（325、525、1124）→ `unordered_map<long long,int>`：前綴值 → **最早**出現的下標。
  - 求最短（不常見）→ 前綴值 → 最晚出現的下標。
  - 判存在（523 要求長度 $\ge 2$）→ 前綴值 → 最早下標，再檢查距離。
- **鍵的選擇**：條件不是「和為 $k$」而是某種同餘或狀態時，鍵要換成特徵（這就是 1.2 的 $\varphi$）：

| 題目 | 條件 | 鍵 $\varphi(s)$ | 查詢的鍵 |
| --- | --- | --- | --- |
| 560 | 和 $= k$ | $s$ | $s - k$ |
| 974／523 | 和 $\equiv 0 \pmod k$ | $((s \bmod k) + k) \bmod k$ | 同一個鍵 |
| 525 | 0/1 個數相等 | 把 0 換成 $-1$ 後的 $s$ | 同一個鍵 |
| 1524 | 和為奇數 | $s \bmod 2$ | $1 - (s \bmod 2)$ |
| 1590 | 移除最短子陣列使總和可被 $p$ 整除 | $s \bmod p$ | $(s - \text{total}) \bmod p$ |

**「和 $\equiv 0$」與「和 $= k$」的差別**：前者查的是**同一個鍵**（兩個前綴同餘 ⟹ 差可被 $k$ 整除），後者查的是**平移過的鍵**。這個差別是 974 與 560 唯一的不同。

## 不變量或正確性證明

**主不變量。** 在處理右端點 $r$（即前綴 $s_{r+1}$）並執行查詢的那一刻，`cnt` 恰好記錄了 $\{s_0, s_1, \dots, s_r\}$ 的資訊——**包含 $s_0 = 0$，不包含 $s_{r+1}$**。

*初始化*：迴圈開始前 `cnt[0] = 1`（或 `pos[0] = -1`），對應 $s_0$。
*保持*：每輪先查詢，再把當前的 $s_{r+1}$ 併入，於是下一輪的 `cnt` 是 $\{s_0..s_{r+1}\}$。

**`cnt[0] = 1` 這一行的意義。** 它代表「空前綴」$s_0 = 0$。以子陣列 $[0, r]$ 為例，它對應 $l = 0$，需要在摘要中找到 $s_0$。**若漏掉這行初始化，所有「從下標 0 開始」的子陣列全部不會被計入。** 這是本節第一大坑，而且在測資的第一個子陣列不從 0 開始時完全不會暴露。

求最長的版本對應的是 `pos[0] = -1`：長度 $= r - l + 1 = r - (\text{記錄的下標})$，$s_0$ 的「下標」是 $-1$，才能算出 $[0, r]$ 的長度為 $r + 1$。

**不重不漏。** 每個滿足條件的子陣列 $[l, r]$ 唯一對應一組 $(s_l, s_{r+1})$，其中 $l \le r$。由不變量，處理 $r$ 時 $s_l$（$l \le r$）都已在摘要中且 $s_{r+1}$ 尚未進入，故：
- *不漏*：$s_l$ 一定被找到。
- *不重*：每個子陣列只有一個右端點，只被統計一次。
- *不多算*：$s_{r+1}$ 未進入摘要，排除了 $l = r+1$（空子陣列）。**這就是「先查後加」在本節的具體後果。**

**求最長時為何存「最早」的下標。** 對固定右端點 $r$，要讓 $r - l$ 最大就要讓 $l$ 最小。同一個前綴值可能出現多次，只有**第一次**出現的下標能給出最長區間，後續的出現一律不覆蓋。寫成 `if (!pos.count(key)) pos[key] = i;`。**若寫成無條件覆蓋，答案會偏小；這個錯誤只在有重複前綴值時暴露。**

反過來，求「和恰為 $k$ 的**個數**」時必須記全部出現次數，不能只記第一次。**「求個數」與「求最長」的摘要語意不同，不能互抄。**

**負數取模的陷阱（974／523）。** 兩前綴 $s_i \equiv s_j \pmod k$ $\iff$ $k \mid (s_i - s_j)$。這個等價需要用**數學上的模**（結果落在 $[0, k)$），但 C++ 的 `%` 對負被除數回傳負值：`-1 % 3 == -1`。於是 $s_i = -1$ 與 $s_j = 2$ 明明同餘，鍵卻分別是 $-1$ 與 $2$，配不上。必須寫 `((s % k) + k) % k`。**這是本節第二大坑。**

**525 的 $0 \to -1$ 變換。** 「$[l,r]$ 中 0 與 1 的個數相等」$\iff$ 把 0 記為 $-1$、1 記為 $+1$ 後，$\sum_{t=l}^{r} b_t = 0$。*證明*：設區間內有 $z$ 個 0、$o$ 個 1，則 $\sum b = o - z$，等於 0 $\iff o = z$。$\square$ **這個變換把「兩個計數相等」轉成「和為零」，是把不可累加的條件轉成可累加的標準手法**，與 805 的均值變換同源。

**437（樹上路徑和）的移植。** 把「陣列的前綴」換成「根到當前節點的路徑和」，`cnt` 記錄根到路徑上各祖先的前綴值。關鍵差別是**回溯時必須把當前節點的前綴從 `cnt` 移除**，否則兄弟子樹會互相污染——因為不變量要求「摘要恰為當前路徑上的祖先」，而不是「所有訪問過的節點」。這與 trees 4.7 中「路徑搜尋的 `vis` 必須還原」是同一條紀律。

## C++17 模板

```cpp
// 和為 K 的子陣列（LeetCode 560）：數個數 → 摘要存出現次數。
class Solution {
public:
    int subarraySum(std::vector<int>& nums, int k) {
        std::unordered_map<long long, int> cnt;
        cnt[0] = 1;  // s_0 = 0，代表空前綴；漏掉會少算從 0 開始的區間
        long long s = 0;
        int ans = 0;
        for (int x : nums) {
            s += x;                     // s 成為 s_{r+1}
            auto it = cnt.find(s - k);  // 需要 s_l = s_{r+1} - k
            if (it != cnt.end()) {
                ans += it->second;
            }
            ++cnt[s];  // 先查後加：排除空子陣列
        }
        return ans;
    }
};
```

```cpp
// 連續的子陣列和（LeetCode 523）：和可被 k 整除、長度 >= 2 → 摘要存最早下標。
class Solution {
public:
    bool checkSubarraySum(std::vector<int>& nums, int k) {
        std::unordered_map<int, int> firstPos;
        firstPos[0] = -1;  // s_0 的「下標」是 -1
        long long s = 0;
        for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
            s += nums[i];
            int key = static_cast<int>(((s % k) + k) % k);  // 負數取模必須修正
            auto it = firstPos.find(key);
            if (it != firstPos.end()) {
                if (i - it->second >= 2) {
                    return true;
                }  // 長度 = i - l >= 2
            } else {
                firstPos[key] = i;  // 只記最早出現，後續不覆蓋
            }
        }
        return false;
    }
};
```

523 的 `else` 分支是關鍵：**找到時不更新**，因為要保留最早的下標以取得最長距離。若把 `firstPos[key] = i;` 寫在 `if/else` 之外，`[1,0]`、`k=2` 這種測資會漏判。

## 時間與空間複雜度

$O(n)$ 期望時間（雜湊表單次操作期望 $O(1)$），$O(n)$ 空間（最壞情形所有前綴值互異）。

**與滑動視窗的取捨**：全正數時滑動視窗是 $O(n)$ 時間、$O(1)$ 空間，且常數小得多。**只有出現負數或 0 時才需要付出 $O(n)$ 的空間。** 面試中被問「有負數怎麼辦」，答案就是本節。

**鍵的值域小時改用陣列**：974（模 $k$，$k \le 10^4$）用 `vector<int> cnt(k)` 比 `unordered_map` 快數倍。**只要鍵落在已知的小範圍，一律換陣列。**

437（樹上路徑）：$O(n)$ 時間（每個節點進出摘要各一次）、$O(h)$ 額外空間加上遞迴深度。**樸素的「對每個節點往下 DFS 一遍」是 $O(n^2)$**（鏈狀樹時 $n = 1000$ 就慢），這是本節在樹上帶來的收穫。

## 常見錯誤與邊界條件

- **漏寫 `cnt[0] = 1`（或 `pos[0] = -1`）**——所有從下標 0 開始的子陣列消失，是本節最常見的錯誤。
- 求最長時無條件覆蓋 `pos[key]` 而非只記最早。
- 求個數時只記「有沒有出現」而非次數。
- `s % k` 對負數未修正成 `((s % k) + k) % k`。
- 前綴和用 `int` 溢位。
- 「先加後查」導致算進空子陣列（560 會多算 $n$ 個）。
- 523 的長度 $\ge 2$ 條件漏檢。
- 523 的 $k$ 可能為 0（依題目約束判斷是否要特判）。
- 525 忘記把 0 換成 $-1$。
- 1590 需要的是「移除一段使剩下可被 $p$ 整除」，鍵是 $(s - \text{total}) \bmod p$ 而非 $s \bmod p$，且要排除「移除整個陣列」。
- 437 回溯時忘記把當前前綴從 `cnt` 移除（兄弟子樹污染）。
- 437 的路徑和用 `int` 溢位（$10^3$ 個 $10^9$）。
- 把「求個數」與「求最長」的摘要語意互抄。

## 與相似技巧的比較

- **與滑動視窗**：**判準只有一個——有沒有負數。** 全正 → 滑動視窗（$O(1)$ 空間）；有負 → 本節。「和至少為 $k$ 的最短子陣列」在有負數時（862）還需要單調佇列，見 5.4。
- **與 1.1／1.2**：本節 = 前綴和轉換 + 1.1。鍵換成特徵時就是 1.2。**不是新技巧，是組合。**
- **與 2.7（前綴和 + 有序集合）**：條件從「等於」變成「不超過／最接近／落在範圍」時，雜湊表沒有用（沒有唯一互補鍵），必須改用有序集合做 `lower_bound`，$O(n \log n)$。**等號用雜湊，不等號用有序集合。**
- **與 2.4（狀態壓縮前綴和）**：鍵從數值換成位元遮罩，配對條件從「相等」變成「XOR 後合法」。**同一個骨架，鍵的型別不同。**
- **與 9.1 樹狀陣列**：「有幾個前綴值小於 $x$」這種帶序的計數，雜湊表做不到，要用樹狀陣列（327 區間和的個數）。**計數 + 不等式 = 樹狀陣列。**
- **與 2.3（距離和）**：那裡的前綴和用在排序後的陣列上，回答的是「一段區間的和」而非「找滿足條件的區間」，屬於 2.1 的直接應用。

## 本節重點速查

- 改寫是全部：$\sum_{[l,r]} a = k \iff s_l = s_{r+1} - k$。區間問題 → 配對問題 → 套 1.1。
- **`cnt[0] = 1` / `pos[0] = -1` 是必寫的一行**，代表空前綴 $s_0 = 0$；漏掉就少算所有從 0 開始的區間。
- **先查後加**，排除空子陣列。
- 求**個數** → 存出現次數；求**最長** → 存**最早**下標且找到時不覆蓋。兩者語意不同，別互抄。
- 「和 $\equiv 0 \pmod k$」查**同一個鍵**；「和 $= k$」查**平移過的鍵**。
- C++ 的 `%` 對負數回傳負值，一律寫 `((s % k) + k) % k`。
- 「兩個計數相等」→ 把其中一類記為 $-1$，轉成「和為零」（525）。
- 搬到樹上（437）時，**回溯必須把當前前綴移出摘要**，否則兄弟子樹互相污染。
- 有負數才用本節；全正數用滑動視窗更省空間。
