## 這個技術解決什麼問題

目標函數含絕對值總和的題目：

$$f(x) = \sum_{i=0}^{n-1} |x - a_i|$$

1685（有序陣列中差絕對值之和）要對每個 $a_j$ 算 $f(a_j)$；2602（使陣列元素全部相等的最少操作次數）要對每個查詢 $q$ 算 $f(q)$；1703（得到連續 K 個 1 的最少相鄰交換次數）與 2968（執行操作使頻率分數最大）要在滑動視窗內算 $f(\text{中位數})$；2615（等值距離和）按值分組後對每組算。

樸素做法：每個查詢掃全陣列，$O(nq)$。$n = q = 10^5$ 是 $10^{10}$。

**絕對值是障礙，因為它不可累加**（$|x-a|$ 沒有前綴和的遞推）。但只要**排序**，對固定的 $x$，陣列就被切成「$\le x$」與「$> x$」兩段，每段內部絕對值可以去掉：
$$f(x) = \underbrace{\big(m \cdot x - \textstyle\sum_{i<m} a_i\big)}_{\text{左段}} + \underbrace{\big(\textstyle\sum_{i \ge m} a_i - (n-m)\cdot x\big)}_{\text{右段}},$$
其中 $m$ 是滿足 $a_i \le x$ 的元素個數。兩個 $\sum$ 都是前綴和，$O(1)$ 取得；$m$ 用二分 $O(\log n)$ 找。**每次查詢 $O(\log n)$，$q$ 次總計 $O((n+q)\log n)$。**

## 狀態／資料結構定義

- **排序後**的陣列 $a_0 \le a_1 \le \dots \le a_{n-1}$。若題目要求輸出保持原順序（1685 的輸入本來就有序；2602 只需按查詢輸出），排序前要記得保存原下標或確認不影響。
- **前綴和** $s_i = a_0 + \dots + a_{i-1}$，長度 $n+1$，型別 `long long`。
- **分界點** $m = |\{i : a_i \le x\}|$。用 `upper_bound(a.begin(), a.end(), x) - a.begin()` 取得。
- 對「$x$ 恰為某個 $a_j$」的情形（1685、2615），$m$ 就是 $j$ 或 $j+1$，連二分都省了。

**滑動視窗版（1703、2968）**：視窗 $[l, r]$ 內取中位數 $a_{mid}$（$mid = (l+r)/2$），代價是視窗內元素到 $a_{mid}$ 的距離和，同樣用前綴和拆兩段。

## 不變量或正確性證明

**引理一（拆絕對值）。** 設 $a$ 已排序，$m = |\{i : a_i \le x\}|$。則
$$\sum_{i=0}^{n-1} |x - a_i| = \left(m x - s_m\right) + \left((s_n - s_m) - (n-m)x\right).$$

*證明。* 因為 $a$ 遞增，$\{i : a_i \le x\} = \{0, 1, \dots, m-1\}$ 是一個**前綴**——這正是排序的作用，也是唯一用到排序的地方。於是
- 對 $i < m$：$a_i \le x$，故 $|x - a_i| = x - a_i$，這 $m$ 項的和是 $mx - \sum_{i<m} a_i = mx - s_m$。
- 對 $i \ge m$：$a_i > x$，故 $|x - a_i| = a_i - x$，這 $n-m$ 項的和是 $(s_n - s_m) - (n-m)x$。

相加即得。$\square$

**這條論證點名了它依賴的前提：$\{i : a_i \le x\}$ 必須是連續的一段。** 若不排序，這個集合是散落的下標，無法用前綴和表示。**排序不是「為了方便」，是這個公式成立的必要條件。**

**引理二（最佳的 $x$ 是中位數）。** $f(x) = \sum_i |x - a_i|$ 在 $x = a_{\lfloor n/2 \rfloor}$（或任一中位數）處取得最小值。

*證明。* 把 $x$ 從 $-\infty$ 往右移動。由引理一，
$$f'(x) = m - (n - m) = 2m - n$$
（在 $x$ 不等於任何 $a_i$ 處；$f$ 是分段線性的凸函數）。當 $m < n/2$ 時斜率為負（往右走 $f$ 下降），$m > n/2$ 時斜率為正。故最小值出現在斜率變號處，即 $m$ 首次達到 $\lceil n/2 \rceil$ 的位置——就是中位數。$n$ 為偶數時斜率在中間一段為 0，故兩個中位數之間**任一點**都最佳。$\square$

**這個引理的用途**：1703、2968、462（最少移動次數使陣列元素相等 II）都直接靠它把「該選哪個 $x$」這個看似要枚舉的問題變成 $O(1)$。**注意它只對「距離和」成立**；若目標是 $\sum (x-a_i)^2$，最佳點變成平均數；若是 $\max_i |x - a_i|$，變成 $(\min + \max)/2$。**三種目標，三個不同的最佳點，別記混。**

**1703（最少相鄰交換得到連續 $k$ 個 1）的化約。** 設 1 的位置是 $p_0 < p_1 < \dots < p_{c-1}$。把 $k$ 個 1 聚到一起的相鄰交換次數，等於把它們移到某段連續位置的距離和。關鍵變換是 $q_t = p_t - t$：

*為什麼要減 $t$*？目標是讓選中的 $k$ 個 1 佔據連續的格子。若最終第 $t$ 個 1 落在位置 $y + t$，則移動距離是 $\sum_t |p_t - (y+t)| = \sum_t |q_t - y|$。**減去 $t$ 把「移到連續位置」轉成「移到同一個位置」**，於是引理一、二可以直接套用，$y$ 取 $q$ 在視窗內的中位數。$\square$

這個變換與 2.2 的「0 換成 $-1$」是同一類手法：**把一個帶結構的條件，透過重新參數化變成標準形。**

**2615（等值距離和）的分組。** 對每個值 $v$，取所有 $\mathrm{nums}[i] = v$ 的下標 $I_v = \{i_0 < i_1 < \dots\}$。對 $i_t \in I_v$，答案是 $\sum_{u} |i_t - i_u|$——這就是引理一，其中「陣列」是 $I_v$、「$x$」是 $i_t$，且 $m = t$（因為 $I_v$ 本身遞增，$x$ 恰是第 $t$ 個元素）。**每組各自建前綴和，總空間仍是 $O(n)$，因為所有組的大小加起來是 $n$。**

## C++17 模板

```cpp
// 距離和的通用查詢結構：排序 + 前綴和，單次查詢 O(log n)。
class DistanceSum {
    std::vector<long long> a_;  // 排序後的元素
    std::vector<long long> s_;  // s_[i] = a_[0..i-1] 的和

public:
    explicit DistanceSum(std::vector<int> nums) {
        a_.assign(nums.begin(), nums.end());
        std::sort(a_.begin(), a_.end());  // 前提：{i : a_i <= x} 必須是前綴
        s_.assign(a_.size() + 1, 0);
        for (size_t i = 0; i < a_.size(); ++i) {
            s_[i + 1] = s_[i] + a_[i];
        }
    }

    // 回傳 sum_i |x - a_i|
    long long query(long long x) const {
        int n = a_.size();
        int m = std::upper_bound(a_.begin(), a_.end(), x) -
                a_.begin();              // a_[0..m-1] <= x
        long long left = m * x - s_[m];  // 左段：x - a_i
        long long right = (s_[n] - s_[m]) - static_cast<long long>(n - m) * x;
        return left + right;
    }

    // 使所有元素相等的最小距離和（最佳點是中位數）
    long long best() const { return a_.empty() ? 0 : query(a_[a_.size() / 2]); }
};
```

```cpp
// 得到連續 K 個 1 的最少相鄰交換次數（LeetCode 1703）
// 變換 q[t] = p[t] - t，把「移到連續位置」化成「移到同一點」，再取視窗中位數。
class Solution {
public:
    int minMoves(std::vector<int>& nums, int k) {
        std::vector<long long> q;
        for (int i = 0, t = 0; i < static_cast<int>(nums.size()); ++i) {
            if (nums[i] == 1) {
                q.push_back(i - t);
                ++t;
            }  // 關鍵變換
        }
        int c = q.size();
        std::vector<long long> s(c + 1, 0);
        for (int i = 0; i < c; ++i) {
            s[i + 1] = s[i] + q[i];
        }

        long long ans = LLONG_MAX;
        for (int l = 0; l + k <= c; ++l) {
            int r = l + k - 1;
            int mid = l + (r - l) / 2;  // 視窗中位數的下標
            long long x = q[mid];
            // 左段 [l, mid]：x - q[i]；右段 [mid+1, r]：q[i] - x
            long long leftCnt = mid - l + 1;
            long long left = leftCnt * x - (s[mid + 1] - s[l]);
            long long rightCnt = r - mid;
            long long right = (s[r + 1] - s[mid + 1]) - rightCnt * x;
            ans = std::min(ans, left + right);
        }
        return static_cast<int>(ans);
    }
};
```

## 時間與空間複雜度

**建構**：排序 $O(n \log n)$ + 前綴和 $O(n)$。

**單次查詢**：二分 $O(\log n)$，公式 $O(1)$。若 $x$ 恰是某個 $a_j$（1685、2615），$m$ 直接由下標得出，查詢降到 **$O(1)$**。

**總計**：$O((n + q)\log n)$，或 $O(n \log n)$（僅排序）當所有查詢都是陣列元素。

**滑動視窗版（1703、2968）**：外層 $O(n)$ 個視窗，每個 $O(1)$，總計 $O(n)$（若 1 的位置已排序則不需再排）。

**空間**：$O(n)$。2615 的分組版所有組的前綴和加起來仍是 $O(n)$。

與 $O(nq)$ 暴力的落差：$n = q = 10^5$ 時 $10^{10} \to 3.4 \times 10^6$。

**溢位是這一節的常態而非例外。** $m \cdot x$ 在 $m = 10^5$、$x = 10^9$ 時是 $10^{14}$；距離和本身可達 $10^{14}$。**所有中間量一律 `long long`**，包括 `(long long)(n - m) * x` 這種乘法——只寫 `(n-m) * x` 時兩個運算元都是 `int`，會先以 `int` 相乘再提升，仍然溢位。

## 常見錯誤與邊界條件

- 忘記排序（引理一的前提破裂，答案完全錯）。
- `upper_bound` 與 `lower_bound` 混用（差別在 $a_i = x$ 的元素歸到哪一段——**兩者都對，只要公式一致**：`upper_bound` 把等於 $x$ 的歸左段，`lower_bound` 歸右段，而 $|x - a_i| = 0$，所以結果相同；但若題目要的是「嚴格小於」的計數，就必須分清）。
- `int` 乘法溢位（`(n-m) * x` 沒有轉型）。
- 前綴和用 `int`。
- 中位數下標寫成 `(l + r + 1) / 2`（偶數長度時取右中位數，對距離和仍最佳，但與左中位數的公式要一致，混用會算錯段長）。
- 1703 忘記 $q_t = p_t - t$ 的變換（直接對 $p$ 取距離和，得到的是「全部移到同一格」的次數，答案偏大）。
- 1703 的視窗邊界 `l + k <= c`。
- 2615 未按值分組就整體算。
- 2615 對每個位置重新建前綴和（$O(n^2)$）。
- `best()` 在空陣列上存取 `a_[0]`。
- 2968 的目標是「頻率分數最大」，要在距離和 $\le k$ 的約束下求最長視窗，屬於雙指標 + 本節公式的組合，別漏掉外層的單調性論證。

## 與相似技巧的比較

- **與 2.1**：本節是 2.1 的直接應用，新增的只有「排序讓集合變前綴」與「拆絕對值」兩步。
- **與 binary_search 主題**：查詢時的 `upper_bound` 是二分；若題目改成「使距離和不超過 $k$ 的最大視窗」，外層還要再二分或雙指標，屬於組合題。
- **與 6.7 對頂堆**：若元素會**動態加入或刪除**（滑動視窗中位數、資料流），排序後的前綴和無法維護，要改用對頂堆（兩側各維護 sum）或樹狀陣列。**判準：陣列固定 → 本節；動態變化 → 對頂堆／樹狀陣列。**
- **與 9.1 樹狀陣列**：需要「動態插入元素並查詢距離和」時，用兩個樹狀陣列（一個記個數、一個記和）在值域上做，$O(\log V)$ 每次操作。這是本節的動態版。
- **與 greedy 的「中位數貪心」**：引理二在 greedy 主題也會出現（462、2033）。**這裡給的是完整證明（分段線性凸函數的斜率變號），不只是「取中位數就對了」。**
- **與平方距離**：目標若是 $\sum (x - a_i)^2$，最佳點是平均數，且展開後 $= n x^2 - 2x\sum a_i + \sum a_i^2$，只需前綴和與平方前綴和，連排序都不用。**這說明「要不要排序」取決於目標函數是否分段。**

## 本節重點速查

- $f(x) = \sum |x - a_i|$：**排序後**用前綴和拆成兩段，
- $$f(x) = (mx - s_m) + \big((s_n - s_m) - (n-m)x\big),\quad m = |\{a_i \le x\}| .$$
- 排序是**正確性前提**，不是效率優化——它讓 $\{i : a_i \le x\}$ 成為一個前綴。
- $f$ 是分段線性凸函數，斜率 $2m - n$，故最小值在**中位數**。平方距離的最佳點是平均數，$\max$ 距離的最佳點是 $(\min+\max)/2$，別記混。
- 「移到連續位置」用 $q_t = p_t - t$ 變成「移到同一點」（1703）。
- $x$ 恰是陣列元素時 $m$ 由下標直接得出，查詢降到 $O(1)$。
- **所有中間量 `long long`**，包括 `(long long)(n-m) * x` 的顯式轉型。
- 元素會動態進出時本節失效，改用對頂堆或樹狀陣列。
