## 這個技術解決什麼問題

有一類子陣列／子字串題，條件不是關於「和」，而是關於「每種元素出現次數的奇偶」：

- 1371：最長子字串，其中每個母音（a e i o u）都出現偶數次。
- 1915：有多少子字串可重排成迴文（至多一個字元出現奇數次）。
- 1542：最長的可重排成迴文的子字串。
- 1177：查詢子串能否在重排 + 至多 $k$ 次替換後變成迴文。
- 2791：樹上路徑版本（把「區間」換成「路徑」）。

樸素做法枚舉所有 $O(n^2)$ 個區間，每個再檢查一次計數表，$O(n^2 \Sigma)$。

本節的做法：**把「各字元的出現次數奇偶」壓成一個整數（每種字元佔一位），這個整數的前綴形式可以用 XOR 累積。** 於是「區間內某字元出現偶數次」變成「兩個前綴狀態在那一位相同」，整個條件變成前綴狀態之間的配對——回到 2.2 的骨架。

## 狀態／資料結構定義

**狀態壓縮**：字元集 $\Sigma$（母音是 5 種，小寫字母是 26 種）。定義
$$\mathrm{mask}_i = \bigoplus_{t=0}^{i-1} 2^{\mathrm{id}(a_t)},$$
即前 $i$ 個字元的「奇偶指紋」：第 $b$ 位為 1 $\iff$ 第 $b$ 種字元在 $a[0..i-1]$ 中出現奇數次。$\mathrm{mask}_0 = 0$。

遞推：`mask ^= 1 << id(c);`——**XOR 就是模 2 加法**，出現兩次自動抵消。

**摘要**：
- 求最長（1371、1542）→ `first[mask]` = 該狀態最早出現的下標（初始 `first[0] = -1`，其餘為 $-2$ 或用 map 判存在）。
- 求個數（1915）→ `cnt[mask]` = 該狀態出現次數（初始 `cnt[0] = 1`）。

**摘要容器的選擇**：$|\Sigma| = 5$ → 陣列大小 32；$|\Sigma| = 26$ → 陣列大小 $2^{26} \approx 6.7\times10^7$，開 `int` 是 268 MB，**通常超限**。1915 因此改用 `unordered_map`，或利用「只需查 27 個鍵」的特性——見下。

## 不變量或正確性證明

**引理一（區間狀態 = 前綴狀態的 XOR）。**
$$\mathrm{mask}(l, r) := \bigoplus_{t=l}^{r} 2^{\mathrm{id}(a_t)} = \mathrm{mask}_{r+1} \oplus \mathrm{mask}_{l}.$$

*證明。* $\mathrm{mask}_{r+1} \oplus \mathrm{mask}_l = \left(\bigoplus_{t \le r}\right) \oplus \left(\bigoplus_{t < l}\right)$。前 $l$ 項在兩邊都出現，XOR 後抵消（$x \oplus x = 0$），只剩 $t \in [l, r]$。$\square$

**這一步用到的是 XOR 群結構：每個元素是自己的逆元。** 對照 2.1 的表格，XOR 有逆元，所以「前綴相減」（這裡是相 XOR）成立。若題目要的是**實際次數**（不只奇偶），XOR 就不夠了——那要 $\Sigma$ 個獨立的前綴和陣列，$O(n\Sigma)$ 空間。**「只在乎奇偶」是本節的入場券。**

**引理二（各條件的鍵翻譯）。**

| 題目要求 | 等價的 mask 條件 | 對每個 $r$ 要查的鍵 |
| --- | --- | --- |
| 每種字元都出現偶數次（1371） | $\mathrm{mask}_{r+1} \oplus \mathrm{mask}_l = 0$ | 1 個：$\mathrm{mask}_{r+1}$ |
| 可重排成迴文（1915、1542） | $\mathrm{mask}_{r+1} \oplus \mathrm{mask}_l$ 的 popcount $\le 1$ | $1 + |\Sigma|$ 個：$\mathrm{mask}_{r+1}$ 與 $\mathrm{mask}_{r+1} \oplus 2^b$ |

*「可重排成迴文 $\iff$ 至多一個字元出現奇數次」的證明。* ($\Rightarrow$) 迴文中除了正中間那個字元（長度為奇數時）之外，每個字元都與對稱位置的字元配對，故出現偶數次。($\Leftarrow$) 若至多一個字元出現奇數次，把每種字元對半分放左右、奇數的那一個放正中，即構成迴文。$\square$

**這正是「popcount $\le 1$」的來源，而不是憑記憶。**

**主不變量。** 處理右端點 $r$ 並查詢的那一刻，摘要恰好記錄 $\{\mathrm{mask}_0, \dots, \mathrm{mask}_r\}$——含 $\mathrm{mask}_0 = 0$，不含 $\mathrm{mask}_{r+1}$。與 2.2 完全相同，「先查後加」與「初始化 $\mathrm{mask}_0$」兩條紀律照舊。

**1915 為何是 $1 + |\Sigma|$ 次查詢而非枚舉所有狀態。** 條件是 $\mathrm{popcount}(\mathrm{mask}_{r+1} \oplus \mathrm{mask}_l) \le 1$，即 $\mathrm{mask}_l \in \{\mathrm{mask}_{r+1}\} \cup \{\mathrm{mask}_{r+1} \oplus 2^b : b \in \Sigma\}$。**這個集合只有 $1 + |\Sigma|$ 個元素**，逐一查表即可，$O(n|\Sigma|)$。這是 1.2 中「$\psi$ 回傳集合」推廣形式的最典型例子：**互補鍵不唯一，但可枚舉。**

反過來說，若條件是「popcount $\le 2$」，候選鍵有 $1 + |\Sigma| + \binom{|\Sigma|}{2}$ 個，$|\Sigma| = 26$ 時是 352，仍可行；「popcount $\le k$」一般是 $O(|\Sigma|^k)$，$k$ 一大就崩。**這個成本結構決定了本節的適用邊界。**

**1177（查詢版）為何不能用配對。** 它問的是「子串 $[l,r]$ 至多替換 $k$ 個字元後能否重排成迴文」，區間是**給定的**，不是要找的。此時直接算 $\mathrm{mask}_{r+1} \oplus \mathrm{mask}_l$ 的 popcount $p$，需要的替換次數是 $\lfloor p/2 \rfloor$——**因為每次替換可以把兩個奇數變成兩個偶數**（把其中一個字元改成另一個），故答案是 $\lfloor p/2 \rfloor \le k$。這裡摘要退化成前綴陣列，每個查詢 $O(1)$。**同一個狀態壓縮，用在「找區間」與「查區間」上是兩種不同的骨架。**

**2791（樹上最長迴文路徑）的移植。** 把「前綴」換成「根到節點的路徑指紋」，把「區間」換成「兩節點間的路徑」：$\mathrm{mask}(u,v) = \mathrm{mask}_u \oplus \mathrm{mask}_v$（LCA 的部分被 XOR 抵消兩次，恰好消掉，**且不需要真的求出 LCA**）。搭配 trees 3.11 的 DSU on tree 或「合併子樹時查表」的做法。**XOR 在樹上自動處理 LCA，是這個技巧在樹上格外好用的原因。**

## C++17 模板

```cpp
// 每個母音包含偶數次的最長子字串（LeetCode 1371）
// 狀態只有 5 位 → 32 種，用陣列存「該狀態最早出現的下標」。
class Solution {
public:
    int findTheLongestSubstring(std::string s) {
        constexpr std::string_view kVowels = "aeiou";
        std::array<int, 32> first;
        first.fill(-2);  // -2 表示尚未出現
        first[0] = -1;   // mask_0 = 0，「下標」是 -1

        int mask = 0, ans = 0;
        for (int i = 0; i < static_cast<int>(s.size()); ++i) {
            size_t p = kVowels.find(s[i]);
            if (p != std::string_view::npos) {
                mask ^= 1 << p;
            }  // XOR = 模 2 加法

            if (first[mask] == -2) {
                first[mask] = i;  // 只記最早：要最長就要左端點最小
            } else {
                ans = std::max(
                    ans, i - first[mask]);  // 長度 = i - l，l 是記錄的下標
            }
        }
        return ans;
    }
};
```

```cpp
// 可以形成回文的最長子字串 / 統計迴文子字串（LeetCode 1915 的計數版）
// 條件：popcount(mask_r ^ mask_l) <= 1 → 每個右端點查 1 + 26 個鍵。
class Solution {
public:
    long long wonderfulSubstrings(std::string word) {
        std::vector<long long> cnt(1 << 10, 0);  // 本題字元集是 a..j，10 位
        cnt[0] = 1;                              // mask_0 = 0
        int mask = 0;
        long long ans = 0;
        for (char c : word) {
            mask ^= 1 << (c - 'a');
            ans += cnt[mask];  // 差為 0：全部偶數次
            for (int b = 0; b < 10; ++b) {
                ans += cnt[mask ^ (1 << b)];  // 差恰一位：只有一個字元奇數次
            }
            ++cnt[mask];  // 先查後加
        }
        return ans;
    }
};
```

## 時間與空間複雜度

**1371 型（條件是「差為 0」）**：每個右端點 1 次查詢，$O(n)$ 時間、$O(2^{|\Sigma|})$ 空間。$|\Sigma| = 5$ 時空間是 32，可忽略。

**1915 型（條件是「差的 popcount $\le 1$」）**：每個右端點 $1 + |\Sigma|$ 次查詢，$O(n|\Sigma|)$ 時間。$|\Sigma| = 10$ 時是 $11n$。

**空間是本節的主要限制。** $2^{|\Sigma|}$ 在 $|\Sigma| = 26$ 時是 $6.7\times10^7$ 格，`int` 陣列 268 MB，超限。三種對策：
1. 用 `unordered_map`（只存實際出現的 $\le n+1$ 個狀態），$O(n)$ 空間，常數較大。
2. 若題目的字元集實際更小（1915 只有 a–j），就按實際大小開。
3. 1542 這類「求最長」的題目，狀態數上界是 $n+1$（每個前綴一個），用 map 就夠。

**與暴力的落差**：$O(n^2\Sigma) \to O(n\Sigma)$。$n = 10^5$、$\Sigma = 26$ 時是 $2.6\times10^{11} \to 2.6\times10^6$。

## 常見錯誤與邊界條件

- 漏掉 `first[0] = -1` / `cnt[0] = 1`（所有從下標 0 開始的區間消失，與 2.2 同一個坑）。
- 「未出現」的哨兵值與合法下標混淆（用 `-2` 或 `-1` 要與 $\mathrm{mask}_0$ 的 $-1$ 區分開；本模板用 `-2` 表示未出現）。
- 求最長時覆蓋了已存在的 `first[mask]`（必須只記最早）。
- 求個數與求最長的摘要語意互抄。
- 「先加後查」（1915 會把長度為 0 的空串算進去）。
- `1 << p` 中 $p$ 超過 31（$|\Sigma| > 31$ 時要用 `long long` 或 `bitset`）。
- 1915 的答案用 `int` 溢位（$n = 10^5$ 時子串數達 $5\times10^9$）。
- 把「至多一個奇數」誤寫成「恰好一個奇數」（漏掉全偶的情形）。
- 1177 把答案寫成 $p \le k$ 而非 $\lfloor p/2 \rfloor \le k$。
- 1177 的查詢區間是閉區間，`mask[right+1] ^ mask[left]` 的下標要對齊。
- $2^{26}$ 的陣列直接開在函式內（堆疊溢位，要用 `static` 或 `vector`）。
- 2791 在樹上忘記 XOR 已自動消去 LCA 而額外處理。

## 與相似技巧的比較

- **與 2.2**：完全同一個骨架，只是鍵從「前綴和的數值」換成「前綴狀態的位元遮罩」，累積運算從 `+` 換成 `^`。**2.2 的每一條紀律（初始化、先查後加、最早 vs 計數）在這裡原樣適用。**
- **與 1.2**：查 $1 + |\Sigma|$ 個鍵，正是 1.2 中「互補特徵不唯一但可枚舉」的形式。
- **與 bitwise_operations 主題**：那裡談位元運算本身；本節把位元遮罩當成「壓縮的狀態」使用。**兩者的交集是「popcount 與 lowbit 的技巧」。**
- **與滑動視窗**：條件「每種字元恰好出現 $k$ 次」有單調性時可用滑動視窗；但「偶數次」沒有單調性（加一個字元可能讓條件成立也可能破壞），**滑動視窗在這裡不成立**。
- **與狀態壓縮 DP**：兩者都用 mask 當狀態，但那裡的 mask 是「選了哪些物品」（枚舉子集），這裡是「奇偶指紋」（前綴累積）。**mask 的語意完全不同，別把子集枚舉的直覺帶過來。**
- **與 9.1 樹狀陣列**：若條件涉及「數值大小」而非「相等／XOR」，雜湊表不夠，要用樹狀陣列。本節的條件天生是等值配對，所以雜湊表就夠。

## 本節重點速查

- 把「各字元出現次數的奇偶」壓成一個整數，用 **XOR** 累積成前綴狀態：$\mathrm{mask}(l,r) = \mathrm{mask}_{r+1} \oplus \mathrm{mask}_l$（前 $l$ 項自我抵消）。
- 入場券是「**只在乎奇偶，不在乎實際次數**」；要實際次數就得開 $\Sigma$ 條前綴和。
- **可重排成迴文 $\iff$ 至多一個字元出現奇數次 $\iff$ popcount $\le 1$**（配對法證明，不是背的）。
- 「差為 0」→ 每個右端點查 1 個鍵；「popcount $\le 1$」→ 查 $1 + |\Sigma|$ 個鍵。$O(|\Sigma|^k)$ 決定了適用邊界。
- 2.2 的三條紀律照舊：**初始化 $\mathrm{mask}_0$、先查後加、最長存最早／計數存次數**。
- 空間 $2^{|\Sigma|}$ 是主要限制；$|\Sigma| = 26$ 時改用 `unordered_map`（實際狀態數 $\le n+1$）。
- 1177 是「查給定區間」而非「找區間」，答案是 $\lfloor \mathrm{popcount}/2 \rfloor \le k$（一次替換修掉兩個奇數）。
- 搬到樹上（2791）時 **XOR 自動消去 LCA**，不必求 LCA。
