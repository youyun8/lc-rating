## 這個技術解決什麼問題

矩陣版的 2.1：**多次查詢「某個矩形區域的和」**。暴力每次 $O(mn)$，$q$ 次就是 $O(qmn)$。二維前綴和把它變成預處理 $O(mn)$、單次查詢 $O(1)$。

一維的「兩點相減」在二維變成**四點容斥**。核心公式只有一條，但正負號與下標偏移是所有錯誤的來源，所以本節的重點不是「知道公式」，而是**能從定義重新推出公式**，這樣寫錯時能自己驗。

典型應用有三層：
- **直接查詢**（304 二維區域和檢索、1738 找出第 K 大的異或座標值）。
- **枚舉矩形 + $O(1)$ 判定**（1277 全為 1 的正方形子矩陣、1292 元素和小於等於閾值的正方形最大邊長、3070）。
- **前綴和當成 DP 的加速器**（1314 矩陣區域和、1504 統計全 1 子矩形）。

## 狀態／資料結構定義

**定義。** 對 $m \times n$ 的矩陣 $a$，令
$$S[i][j] = \sum_{r < i} \sum_{c < j} a[r][c], \qquad 0 \le i \le m,\ 0 \le j \le n .$$

$S$ 的大小是 $(m+1) \times (n+1)$，第 0 列與第 0 行全為 0——**與一維同樣的哨兵理由：讓 $r_1 = 0$ 或 $c_1 = 0$ 不必特判。**

**遞推（建表）：**
$$S[i+1][j+1] = S[i][j+1] + S[i+1][j] - S[i][j] + a[i][j].$$

**查詢（左上 $(r_1,c_1)$、右下 $(r_2,c_2)$ 的閉矩形）：**
$$\mathrm{sum} = S[r_2+1][c_2+1] - S[r_1][c_2+1] - S[r_2+1][c_1] + S[r_1][c_1].$$

**兩條式子的符號恰好相反**（建表是 $+,+,-$，查詢是 $-,-,+$），這不是巧合：建表是「把兩塊拼起來扣掉重疊」，查詢是「從大塊挖掉兩塊再補回多扣的」。記住這個對偶就不會抄反。

**推廣到任意可逆運算。** 和 2.1 一樣，只要運算構成群就通用。1738 用的是 XOR：
$$S[i+1][j+1] = S[i][j+1] \oplus S[i+1][j] \oplus S[i][j] \oplus a[i][j],$$
查詢時四項也全部 XOR（XOR 自逆，正負號消失了——**這是 XOR 版比加法版好寫的唯一原因**）。

## 不變量或正確性證明

**引理（容斥）。** 記 $R(i,j) = \{(r,c) : r < i,\ c < j\}$（左上角的開矩形），則
$$\{(r,c): r_1 \le r \le r_2,\ c_1 \le c \le c_2\} = R(r_2{+}1, c_2{+}1) \setminus \big(R(r_1, c_2{+}1) \cup R(r_2{+}1, c_1)\big),$$
且 $R(r_1, c_2{+}1) \cap R(r_2{+}1, c_1) = R(r_1, c_1)$。

*證明。* 取任一 $(r,c) \in R(r_2{+}1, c_2{+}1)$，即 $r \le r_2$ 且 $c \le c_2$。它不在目標矩形內 $\iff$ $r < r_1$ 或 $c < c_1$ $\iff$ 它屬於 $R(r_1, c_2{+}1)$ 或 $R(r_2{+}1, c_1)$。而同時屬於兩者 $\iff r < r_1$ 且 $c < c_1$ $\iff (r,c) \in R(r_1,c_1)$。$\square$

由容斥原理 $|A \setminus (B \cup C)| = |A| - |B| - |C| + |B \cap C|$（推廣到加權和亦成立，因為加法可交換結合），得查詢公式。

**這條論證點名的前提：$R$ 必須是「以原點為一角的矩形」。** 也就是說，$S$ 的語意必須是**從 $(0,0)$ 累積到 $(i-1,j-1)$ 的整塊**，而不是任何別的形狀。這聽起來理所當然，但在 2.8 會遇到「三角形前綴」（只累積嚴格左上）的情形——那時 $B \cap C$ 就不再是 $R(r_1,c_1)$，容斥式子要重推。**「四點容斥」不是萬用公式，它是矩形這個特定形狀的產物。**

**推廣到 $d$ 維。** 查詢需要 $2^d$ 項，符號是 $(-1)^{\text{被截掉的維度數}}$。$d = 3$ 時是 8 項，仍可手寫；$d \ge 4$ 通常改用「逐維做一維前綴和」的寫法（見下），既不會抄錯符號也自動正確。

**逐維前綴的等價寫法（更不容易錯）：**
```
for each row i: 做一次橫向一維前綴和
for each col j: 做一次縱向一維前綴和
```
*正確性*：橫向掃完後 $T[i][j] = \sum_{c<j} a[i][c]$；縱向再掃一次得 $\sum_{r<i}\sum_{c<j} a[r][c] = S[i][j]$。這用的是**求和可交換次序**（Fubini），與容斥無關。**推薦在高維或運算複雜時用這種寫法。**

**1292（元素和 ≤ threshold 的最大正方形邊長）的單調性。** 令 $f(k) = 1$ 若存在邊長 $k$ 的正方形其和 $\le$ threshold。因矩陣元素**非負**，邊長 $k$ 的正方形包含某個邊長 $k-1$ 的正方形，故其和不小於後者。於是 $f$ 單調（$f(k)=1 \Rightarrow f(k-1)=1$），**可以二分答案**，$O(mn\log\min(m,n))$。

但更簡單的是**遞增指標**：從 $k=1$ 開始，只在「當前 $k+1$ 可行」時才 $k{+}{+}$，總計 $O(mn)$。理由是 $k$ 只增不減，攤還後每個格子只做 $O(1)$ 次判定。**這裡「元素非負」是單調性的前提；若矩陣可以有負數，$f$ 不單調，二分與遞增指標都失效，只能 $O(mn\min(m,n))$ 全枚舉。**

**1314（矩陣區域和）的邊界裁剪。** 答案 $\mathrm{ans}[i][j]$ 是以 $(i,j)$ 為中心、半徑 $k$ 的方塊和，方塊可能超出邊界。做法是把座標夾到合法範圍：
$$r_1 = \max(i-k, 0),\quad r_2 = \min(i+k, m-1),\quad c_1 = \max(j-k,0),\quad c_2=\min(j+k,n-1).$$
**夾取（clamp）是正確的，因為「超出邊界的部分貢獻為 0」等價於「只取交集」。** 但若題目改成「超出邊界視為某個非零預設值」，clamp 就錯了，得補上邊界外的貢獻——**前提要看清楚。**

## C++17 模板

```cpp
// 二維區域和檢索 - 矩陣不可變（LeetCode 304）：二維前綴和標準骨架。
class NumMatrix {
    std::vector<std::vector<long long>>
        s_;  // (m+1) x (n+1)，s_[0][*] = s_[*][0] = 0

public:
    explicit NumMatrix(std::vector<std::vector<int>>& matrix) {
        int m = matrix.size(), n = m ? matrix[0].size() : 0;
        s_.assign(m + 1, std::vector<long long>(n + 1, 0));
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                // 建表：兩塊相加，扣掉重複計入的左上角
                s_[i + 1][j + 1] =
                    s_[i][j + 1] + s_[i + 1][j] - s_[i][j] + matrix[i][j];
            }
        }
    }

    int sumRegion(int r1, int c1, int r2, int c2) {
        // 查詢：大塊挖掉上、左兩塊，再補回被扣兩次的左上角（符號與建表相反）
        long long v =
            s_[r2 + 1][c2 + 1] - s_[r1][c2 + 1] - s_[r2 + 1][c1] + s_[r1][c1];
        return static_cast<int>(v);
    }
};
```

```cpp
// 元素和小於等於閾值的正方形最大邊長（LeetCode 1292）：遞增指標 + O(1) 判定。
class Solution {
public:
    int maxSideLength(std::vector<std::vector<int>>& mat, int threshold) {
        int m = mat.size(), n = mat[0].size();
        std::vector<std::vector<long long>> s(m + 1,
                                              std::vector<long long>(n + 1, 0));
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                s[i + 1][j + 1] =
                    s[i][j + 1] + s[i + 1][j] - s[i][j] + mat[i][j];
            }
        }

        int k = 0;  // 目前已知可行的最大邊長；只增不減
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                // 嘗試把邊長推大：以 (i, j) 為右下角、邊長 k+1 的正方形
                while (i - k >= 0 && j - k >= 0) {
                    long long v = s[i + 1][j + 1] - s[i - k][j + 1] -
                                  s[i + 1][j - k] + s[i - k][j - k];
                    if (v > threshold) {
                        break;
                    }
                    ++k;  // 可行，繼續試更大的（元素非負 ⇒ 單調）
                }
            }
        }
        return k;
    }
};
```

`while` 迴圈看似 $O(\min(m,n))$，但 `k` 全程只增不減、上界 $\min(m,n)$，**攤還後整個雙層迴圈仍是 $O(mn)$**。這是本節唯一需要攤還分析的地方。

## 時間與空間複雜度

**建表** $O(mn)$ 時間、$O(mn)$ 空間；**單次查詢** $O(1)$（4 次陣列存取、3 次加減）。$q$ 次查詢總計 $O(mn + q)$，相對暴力的 $O(qmn)$。

**枚舉所有子矩形**是 $O(m^2n^2)$ 個，配 $O(1)$ 判定仍是 $O(m^2n^2)$——$m = n = 100$ 時是 $10^8$，勉強；$m = n = 300$ 就不行了。**二維前綴和不能把「枚舉所有矩形」變快，它只把每次判定變快。** 要更快得靠 1504 那種「固定上下界 + 一維前綴和 + 雜湊表」的降維，$O(m^2 n)$。

**空間優化**：若只需一次掃描，可以只保留兩列（滾動），$O(n)$ 空間。但大多數題目要隨機查詢，省不掉。

**$d$ 維**：建表 $O(n^d)$（逐維寫法是 $d$ 次 $O(n^d)$ 掃描），查詢 $O(2^d)$。

## 常見錯誤與邊界條件

- 查詢公式的符號抄成建表的符號（$+,+,-$ 與 $-,-,+$ 相反）。
- 下標忘記 $+1$（`s[r2][c2]` 少算最後一列一行）。
- `s` 開成 $m \times n$ 而非 $(m+1)\times(n+1)$，被迫特判 $r_1 = 0$。
- 空矩陣時 `matrix[0].size()` 直接崩潰（要先判 `m`）。
- 用 `int` 存二維前綴和——**$100 \times 100$ 的格子每格 $10^5$ 就是 $10^9$，已經逼近 `int` 上限，$300\times300$ 必爆**。
- 1292 的 `while` 條件寫成 `if`（就不是遞增指標，會漏解）。
- 1292 對可能有負數的矩陣套用單調性。
- 1314 的 clamp 邊界寫成 `min(i+k, m)` 而非 `m-1`。
- 1738 的 XOR 版誤用減法（XOR 沒有「減」，自己就是逆）。
- 1738 求第 $k$ 大時對整個 $mn$ 陣列排序（$O(mn\log mn)$ 可過，但 `nth_element` 是 $O(mn)$，且要注意是「第 $k$ 大」不是「第 $k$ 小」）。
- 把 clamp 用在「邊界外有預設值」的題目上。

## 與相似技巧的比較

- **與 2.1 一維前綴和**：完全同源，只是容斥從 2 項變 4 項。**同樣要求矩陣不變、運算有逆元、不溢位。** 若要支援單點修改，得換二維樹狀陣列（$O(\log m \log n)$）。
- **與 2.8 二維前綴最小值**：$\min/\max$ 沒有逆元，四點容斥不成立。2.8 用的是「只往左上遞推」的 DP，形狀與語意都不同——**別把本節的公式套過去。**
- **與 3.3 二維差分**：互為逆運算。二維差分處理「多次矩形加值、最後查詢」（2536 子矩陣元素加 1、850）；本節處理「不修改、多次查詢」。
- **與 1504（統計全 1 子矩形）的降維法**：當要枚舉的矩形數量本身就是 $O(m^2n^2)$ 時，$O(1)$ 判定救不了。降維法固定上下邊界（$O(m^2)$），把每一行壓成一個數，再對這一維用一維技巧（$O(n)$ 或 $O(n\log n)$）。**判準：查詢次數是輸入給的 ⇒ 用前綴和；查詢次數是自己枚舉出來的 ⇒ 先想降維。**
- **與 DP**：1277（全為 1 的正方形子矩陣）用 $\mathrm{dp}[i][j] = \min(\text{三鄰居}) + 1$ 是 $O(mn)$，比二維前綴和 + 枚舉邊長的 $O(mn\min(m,n))$ 更快。**「正方形」這個額外約束讓 DP 有機可乘；一般矩形就沒有。**

## 本節重點速查

- $S[i][j] = \sum_{r<i}\sum_{c<j} a[r][c]$，大小 $(m+1)\times(n+1)$，首列首行為 0。
- 建表 $S[i{+}1][j{+}1] = S[i][j{+}1] + S[i{+}1][j] - S[i][j] + a[i][j]$（$+,+,-$）。
- 查詢 $S[r_2{+}1][c_2{+}1] - S[r_1][c_2{+}1] - S[r_2{+}1][c_1] + S[r_1][c_1]$（$-,-,+$）。**兩者符號相反。**
- 公式忘了就用容斥重推：大塊 $-$ 上塊 $-$ 左塊 $+$ 左上塊。
- 高維或運算複雜時改用**逐維一維前綴和**，不會抄錯符號。
- 容斥的前提是 $R$ 為「以原點為一角的矩形」；$\min/\max$ 無逆元不適用（見 2.8）。
- 1292 的遞增指標靠「元素非負 ⇒ 邊長單調」，攤還 $O(mn)$。
- 一律 `long long`；空矩陣先判 `m`。
- 枚舉所有矩形仍是 $O(m^2n^2)$——那要靠降維（1504），不是靠前綴和。
