## 這個技術解決什麼問題

2.2 用雜湊表解「區間和**恰為** $k$」：把條件改寫成 $s_l = s_{r+1} - k$，右邊是一個**唯一確定的鍵**，查表 $O(1)$。

但很多題目的條件不是等號：

- 「區間和**不超過** $k$，求最大」（363 矩形區域不超過 K 的最大數值和）
- 「區間和為正，求**最小**」（3364 最小正和子陣列）
- 「兩數之差在 $[a,b]$ 內」（220 存在重複元素 III）

這些條件對應的不是一個鍵，而是**一段鍵的區間**。雜湊表無法回答「範圍內有沒有元素／最接近的是哪個」，因為它不保存順序。此時要換成**有序集合**（`std::set` / `std::multiset`，紅黑樹），用 `lower_bound` 在 $O(\log n)$ 內找到邊界。

**代價是每次查詢從 $O(1)$ 變 $O(\log n)$，換來的是能回答範圍型查詢。** 這是 2.2 之後最自然的一次升級。

## 狀態／資料結構定義

沿用 1.1「列舉右端點、維護左端點集合」的框架，只是左側摘要從 `unordered_map` 換成有序容器。

**形態一：左端點集合是「所有更早的前綴」（363）**
- `std::set<long long> seen`，初始放入 $s_0 = 0$。
- 外層迴圈固定右端點，`cur` 為當前前綴和 $s_{r+1}$。
- 查詢：`it = seen.lower_bound(cur - k)`，若 `it != seen.end()` 則 `cur - *it` 是「$\le k$ 且最大」的候選。
- 更新：`seen.insert(cur)`。

**形態二：左端點集合是一個滑動視窗（3364、長度受限的變體）**
- `std::multiset<long long> win`，維護所有**合法**的左端點前綴。必須用 `multiset`——**前綴和會重複，`set` 會吃掉重複值，導致視窗大小與集合大小不同步。**
- 右端點推進時：先把新變成合法的前綴 `insert`，把過期的前綴 `erase(win.find(v))`。
- 查詢：依題意用 `lower_bound` / `upper_bound` 找邊界候選。

**形態三：值域上的有序集合（220，不是前綴和但同一套推理）**
- 集合裝的是「視窗內的元素值」，查 $[\,x-t,\ x+t\,]$ 內是否有元素：`it = win.lower_bound(x - t); it != win.end() && *it <= x + t`。

## 不變量或正確性證明

**主不變量（形態一）。** 在處理右端點 $r$ 的那一刻，
$$\texttt{seen} \;=\; \{\, s_l \;:\; 0 \le l \le r \,\},$$
也就是「所有可以當左端點的前綴」，含 $s_0 = 0$（對應從頭開始的區間），且**不含** $s_{r+1}$（否則會取到空區間）。維持方式與 2.2 相同：**先查詢，再插入 `cur`。**

**核心引理（為什麼查邊界就夠）。** 固定右端點，令 $s_{r+1} = C$。要找
$$\max\{\,C - x \;:\; x \in \texttt{seen},\ C - x \le k\,\}.$$
條件 $C - x \le k \iff x \ge C - k$；而目標 $C - x$ 隨 $x$ **嚴格遞減**。故最佳的 $x$ 是可行集合中**最小的那個**，即 $\min\{x \in \texttt{seen} : x \ge C-k\}$——這正是 `lower_bound(C - k)` 回傳的元素。$\square$

**這條論證點名了它依賴的前提：目標函數對被查詢的鍵是單調的。** 因為 $C-x$ 對 $x$ 單調，「可行區間的邊界」才會是最優解，於是一次 `lower_bound` 就夠。若目標不單調（例如要最大化 $|C - x|$，或目標同時牽涉 $x$ 與 $l$ 的下標），邊界不再必然最優，就得查多個候選、甚至換線段樹。**「單調 ⇒ 查邊界」是所有 `lower_bound` 型解法的共同骨架，不只在這一節。**

**與 2.2 的分界，說得更精確一點。** 雜湊表能用的充要條件是：合法左鍵的集合是**單點** $\{\psi(C)\}$。條件變成 $x \ge C-k$ 之後，合法集合是一條**射線**，單點查詢無法覆蓋；而枚舉射線上的所有值在值域大時不可行。這正是 1.2 提過的「$|a-b| \le d$ 沒有唯一補數」在前綴和上的化身——**同一個判準，換了個舞台。**

**形態二的視窗不變量（3364：長度介於 $l$ 與 $r$ 的最小正和子陣列）。** 子陣列 $[i, j-1]$（前綴下標 $i$ 到 $j$）的長度是 $j - i$，要求 $l \le j - i \le r$，即
$$j - r \;\le\; i \;\le\; j - l .$$
處理前綴下標 $j$ 前，維持
$$\texttt{win} \;=\; \{\, s_i \;:\; \max(0,\, j-r) \le i \le j-l \,\}\quad(\text{可重集}).$$
**推進規則**：$j$ 從 $l$ 開始遞增；每步先 `insert(s[j-l])`（新變合法的下界端），若 $j - r - 1 \ge 0$ 則 `erase(win.find(s[j-r-1]))`（剛過期的）。**兩個動作的順序無所謂（它們碰的是不同元素），但都必須在查詢之前完成**——否則視窗與定義不符，這是本形態唯一的失分點。

**查詢的推導。** 要 $s_j - s_i > 0$ 且最小，即 $s_i < s_j$ 且 $s_i$ **最大**。`it = win.lower_bound(s[j])` 給出第一個 $\ge s_j$ 的位置；**前一個位置**（`--it`，需先確認 `it != win.begin()`）就是最大的 $< s_j$ 的元素。同樣是「目標對 $x$ 單調 ⇒ 取邊界」。

*為什麼不能用 `upper_bound`？* `upper_bound(s[j])` 跳過所有等於 $s_j$ 的元素，但我們要排除的正是「等於」（差為 0，不是正數）。用 `lower_bound` 再退一格，剛好把等於的那批也留在右側。**這一格之差就是「和為正」與「和非負」的區別。**

**multiset 刪除必須用迭代器。** `win.erase(v)` 會刪掉**所有**等於 $v$ 的元素；`win.erase(win.find(v))` 只刪一個。前綴和重複是常態（原陣列有 0 或正負相消時），**寫錯這一行的程式在多數測資上會對，在特定測資上錯得莫名其妙**。

**363 的降維。** 要在矩陣中找「和不超過 $k$ 的最大子矩形」。固定上下兩條列邊界 $(r_1, r_2)$ 後，把每一行壓成一個數（該行在 $[r_1,r_2]$ 內的和），問題就退化成一維的「和不超過 $k$ 的最大子陣列和」，套形態一。

*不漏*：任一子矩形都有唯一的上下邊界，故會被某組 $(r_1,r_2)$ 枚舉到。
*不重*：不同 $(r_1,r_2)$ 給出的是不同矩形集合，取 $\max$ 不受影響。
**注意這裡的行壓縮要用一維前綴和或增量累加，不能每次重算，否則多一個 $O(m)$。**

## C++17 模板

```cpp
// 矩形區域不超過 K 的最大數值和（LeetCode 363）：降維 + 前綴和 + 有序集合。
class Solution {
public:
    int maxSumSubmatrix(std::vector<std::vector<int>>& matrix, int k) {
        int m = matrix.size(), n = matrix[0].size();
        long long ans = LLONG_MIN;

        for (int top = 0; top < m; ++top) {
            std::vector<long long> colSum(n, 0);  // [top, bottom] 內每一行的和
            for (int bottom = top; bottom < m; ++bottom) {
                for (int j = 0; j < n; ++j) {
                    colSum[j] += matrix[bottom][j];
                }  // 增量，不重算

                // 一維問題：和不超過 k 的最大子陣列和
                std::set<long long> seen{0};  // s_0 = 0，代表「從頭開始」
                long long cur = 0;
                for (int j = 0; j < n; ++j) {
                    cur += colSum[j];  // cur = s_{j+1}
                    // 要 cur - x <= k 且 cur - x 最大 => x 最小且 x >= cur - k
                    auto it = seen.lower_bound(cur - k);
                    if (it != seen.end()) {
                        ans = std::max(ans, cur - *it);
                    }
                    seen.insert(cur);  // 先查後插，排除空區間
                }
            }
        }
        return static_cast<int>(ans);
    }
};
```

```cpp
// 最小正和子陣列（LeetCode 3364）：滑動視窗版的有序集合。
class Solution {
public:
    int minimumSumSubarray(std::vector<int>& nums, int l, int r) {
        int n = nums.size();
        std::vector<long long> s(n + 1, 0);
        for (int i = 0; i < n; ++i) {
            s[i + 1] = s[i] + nums[i];
        }

        long long ans = LLONG_MAX;
        std::multiset<long long> win;  // 必須 multiset：前綴和會重複
        for (int j = l; j <= n; ++j) {
            win.insert(s[j - l]);  // 新變合法的左端點
            if (j - r - 1 >= 0) {
                win.erase(win.find(s[j - r - 1]));  // 用迭代器刪，只刪一個
            }
            // 要 s[j] - x > 0 且最小 => x < s[j] 且 x 最大
            auto it = win.lower_bound(s[j]);  // 第一個 >= s[j]
            if (it != win.begin()) {
                --it;  // 退一格：最大的 < s[j]
                ans = std::min(ans, s[j] - *it);
            }
        }
        return ans == LLONG_MAX ? -1 : static_cast<int>(ans);
    }
};
```

## 時間與空間複雜度

**形態一（一維）**：每個右端點一次 `lower_bound` + 一次 `insert`，各 $O(\log n)$，總計 $O(n\log n)$ 時間、$O(n)$ 空間。

**363**：外層 $O(m^2)$ 組列邊界，內層 $O(n\log n)$，總計 $O(m^2 n\log n)$。**應該把較小的維度放外層**：先判斷 $m$ 與 $n$ 誰小，必要時把矩陣轉置，複雜度變 $O(\min^2 \cdot \max \cdot \log\max)$。$m = n = 100$ 時約 $10^4 \times 100 \times 7 \approx 7\times10^6$，可過。

**3364**：$n$ 次迭代，每次 $O(\log n)$，總計 $O(n\log n)$、空間 $O(n)$。（本題官方約束 $n \le 100$，$O(n^2)$ 暴力也能過——**這裡寫 $O(n\log n)$ 是為了讓解法能推廣到 $n = 10^5$ 的同型題。**）

**常數的現實**：`std::set` 是紅黑樹，每個節點三個指標 + 顏色，記憶體與快取表現都遠差於陣列。實測上比 `unordered_map` 慢 2–5 倍、比排序後二分慢更多。**能離線處理（先收集所有查詢再排序）時，「排序 + 二分」或「排序 + 樹狀陣列」通常比 `set` 快數倍**；`set` 的價值在於**線上**（邊插入邊查詢，且插入的內容依賴先前的查詢結果）。

## 常見錯誤與邊界條件

- `set` 忘記初始插入 $0$（漏掉「從頭開始」的區間）。
- 先插入 `cur` 再查詢（取到空區間，和為 0，在「$\le k$ 且 $k \ge 0$」時會回傳錯誤的 0）。
- `lower_bound` 與 `upper_bound` 用反——**記法：`lower_bound(v)` 是「第一個 $\ge v$」，`upper_bound(v)` 是「第一個 $> v$」**。
- 忘記檢查 `it != seen.end()` 就解參考。
- 退一格前忘記檢查 `it != win.begin()`（`--begin()` 是未定義行為，常常不會崩，只是讀到垃圾）。
- 用 `set` 而非 `multiset` 導致重複前綴被吞、視窗與集合不同步。
- `multiset::erase(value)` 一次刪光所有相同值。
- 用 `std::set::lower_bound` 的**成員函式**寫成 `std::lower_bound(s.begin(), s.end(), v)`（後者對非隨機存取迭代器退化成 $O(n)$ 線性掃描，$O(n\log n)$ 變 $O(n^2)$，**這是最隱蔽的效能陷阱**）。
- `cur - k` 溢位（`k` 可以是 $-2^{31}$，用 `long long` 算）。
- 363 忘記轉置導致 $m \gg n$ 時超時。
- 363 的 `colSum` 每輪重算而非增量。

## 與相似技巧的比較

| 條件形態 | 合法左鍵集合 | 工具 | 單次成本 |
| --- | --- | --- | --- |
| 和 $= k$ | 單點 | `unordered_map`（2.2） | $O(1)$ |
| 和 $\le k$ / 最接近 | 射線／區間 | `set` + `lower_bound`（本節） | $O(\log n)$ |
| 和 $\le k$ 且元素非負 | 射線，但端點單調 | 滑動視窗 | 攤還 $O(1)$ |
| 需要「區間內的計數」 | 區間 + 聚合 | 樹狀陣列 / 線段樹（9.x） | $O(\log n)$ |

- **與滑動視窗**：若元素全非負，前綴和單調遞增，「和 $\le k$ 的最長區間」左端點也單調，雙指標 $O(n)$ 完勝。**有負數才需要本節。** 這是選型的第一個問題。
- **與 2.2**：判準是「合法左鍵是一個點還是一段」。
- **與樹狀陣列（9.1）**：若要問的不是「最接近的元素」而是「範圍內有幾個」（例如逆序對、327 區間和的個數），`set` 不夠（它不支援 $O(\log n)$ 求排名），要用**離散化 + 樹狀陣列**。**327 與 363 長得很像，但一個問「有幾個」、一個問「最大的是哪個」，工具不同。**
- **與 2.5 排序 + 二分**：2.5 的資料是**離線**的（一次排好序，之後只查詢）；本節是**線上**的（集合隨掃描增長）。**能離線就離線，快得多。**
- **與 1.2**：$|a-b| \le d$ 型條件在 1.2 就已宣告「雜湊表無解」，本節給出正式的替代品。

## 本節重點速查

- 條件從「$=$」變成「$\le$／最接近／範圍內」⇒ 合法左鍵從**單點**變成**區間** ⇒ 雜湊表換**有序集合**，$O(1)$ 換 $O(\log n)$。
- 核心引理：目標對被查鍵**單調** ⇒ 最優解在可行區間的**邊界** ⇒ 一次 `lower_bound` 就夠。**不單調就不成立。**
- `lower_bound(v)` = 第一個 $\ge v$；要「最大的 $< v$」就 `lower_bound(v)` 後退一格，**退之前檢查 `!= begin()`**。
- 初始插入 $s_0 = 0$，且**先查後插**。
- 視窗型要用 `multiset`，刪除寫 `erase(find(v))`。
- 務必用成員函式 `s.lower_bound(v)`，不是 `std::lower_bound`（後者 $O(n)$）。
- 363 = 固定上下界降維 + 形態一；把小的維度放外層，必要時轉置。
- 元素全非負 ⇒ 改用滑動視窗；要問「範圍內有幾個」⇒ 改用樹狀陣列。
