## 這個技術解決什麼問題

2.6 的四點容斥處理「矩形區域和」。但把 $+$ 換成 $\min$ 之後，容斥立刻失效——**$\min$ 沒有逆元，前綴相減沒有意義。**

然而有一類題目只需要**角落錨定**的區域極值：「所有在我左上方（含同列同行）的格子中，最小的是多少？」這種形狀不需要容斥，一個 $O(mn)$ 的遞推就能全部算出來。代表題是 3148（矩陣中的最大得分）：求
$$\max\{\, a[r_2][c_2] - a[r_1][c_1] \;:\; r_1 \le r_2,\ c_1 \le c_2,\ (r_1,c_1)\ne(r_2,c_2) \,\}.$$

固定右下角 $(r_2,c_2)$，就是「用當前值減去左上區域的最小值」——**這正是 1.1「列舉右、維護左」推廣到二維**：外層枚舉的不再是一個右端點，而是一個右下角；左側摘要不再是一條前綴，而是一整片左上區域。

本節要說清楚的是：**為什麼 $\min$ 不能容斥卻可以遞推，以及這條分界線的真正依據是什麼。**

## 狀態／資料結構定義

**定義（左上前綴最小值）。**
$$M[i][j] \;=\; \min\{\, a[r][c] \;:\; 0 \le r \le i,\ 0 \le c \le j \,\}.$$

注意這裡是**閉區間、含自己**，與 2.6 的 $S[i][j]$（開區間、不含第 $i$ 列第 $j$ 行）語意不同。**兩節的下標約定刻意不同，因為 2.6 需要哨兵來避免特判，而本節的遞推自然帶有邊界，硬套哨兵反而要處理「空區域的 $\min$ 是 $+\infty$」。**

**遞推：**
$$M[i][j] \;=\; \min\big(a[i][j],\; M[i-1][j],\; M[i][j-1]\big),$$
越界項視為 $+\infty$。

**排除自己的版本（3148 需要）：**
$$M^{-}[i][j] \;=\; \min\big(M[i-1][j],\; M[i][j-1]\big),$$
即「左上區域但不含 $(i,j)$ 自己」。答案候選是 $a[i][j] - M^{-}[i][j]$，然後 $M[i][j] = \min(a[i][j], M^{-}[i][j])$。**先算候選、再併入自己**——與 2.1 模板中 53 的「先算答案再更新 `minPrefix`」是同一條紀律，理由也一樣：避免自己配自己。

**實作上只需要一列滾動陣列**：處理第 $i$ 列時，`row[j]` 在被更新前保存的正是 $M[i-1][j]$，更新後是 $M[i][j]$；同一列往右掃時左邊的 `row[j-1]` 已經是 $M[i][j-1]$。$O(n)$ 空間。

**四個方向的變體。** 有些題目要的是右上、左下、右下的角落極值。做法是把同一段遞推換個掃描方向跑四次（$i$ 遞增／遞減 × $j$ 遞增／遞減），存成四個陣列。**不要試圖用一個陣列硬湊——方向搞混是這類題最常見的錯誤。**

## 不變量或正確性證明

**引理 1（遞推正確）。** $M[i][j] = \min(a[i][j],\, M[i-1][j],\, M[i][j-1])$。

*證明。* 記 $R(i,j) = \{(r,c): r\le i,\ c\le j\}$。則
$$R(i,j) \;=\; \{(i,j)\} \;\cup\; R(i-1,j) \;\cup\; R(i,j-1).$$
「$\supseteq$」顯然。「$\subseteq$」：取 $(r,c) \in R(i,j)$，若 $r < i$ 則 $(r,c) \in R(i-1,j)$；若 $r = i$ 且 $c < j$ 則 $(r,c) \in R(i,j-1)$；若 $r=i, c=j$ 則是 $(i,j)$ 本身。三種情形窮盡。

由於 $\min$ 對集合的**聯集**滿足 $\min(A \cup B) = \min(\min A, \min B)$（無論 $A, B$ 是否相交），對三塊分別取 $\min$ 再取 $\min$ 即得。$\square$

**這裡的關鍵前提是冪等性（idempotence）：$\min(x,x) = x$。**

$R(i-1,j)$ 與 $R(i,j-1)$ **是相交的**（交集是 $R(i-1,j-1)$，通常非空）。對加法而言，重疊區域會被算兩次，必須用容斥扣回去，所以 2.6 才有那個 $+S[r_1][c_1]$ 的修正項。對 $\min$ 而言，重複計入同一個元素毫無影響——**冪等性讓「覆蓋」取代了「分割」**：只要三塊的聯集等於目標區域，不必互斥。

反過來說，**加法要求分割（disjoint decomposition），$\min$ 只要求覆蓋（cover）。** 這條分界線解釋了本章與第 9 章的許多對照：

| 運算 | 逆元 | 冪等 | 區間分解方式 | 對應工具 |
| --- | --- | --- | --- | --- |
| $+$、XOR | 有 | 否 | 必須互斥；可前綴相減 | 前綴和（2.1／2.6） |
| $\min$、$\max$、$\gcd$、AND、OR | 無 | 是 | 允許重疊覆蓋 | ST 表（9.7）、角落遞推（本節） |
| 矩陣乘法等 | 視情況 | 否 | 必須互斥且**有序** | 線段樹（9.3） |

ST 表用兩段長度 $2^k$ 且**互相重疊**的區間覆蓋任意查詢區間，靠的正是同一個冪等性；線段樹則因為要支援非冪等運算，只能用互斥的 $O(\log n)$ 段拼接。**知道這一條，9.7 就不用重新學一次。**

**引理 2（3148 的路徑分數等於端點差）。** 從 $(r_1,c_1)$ 只能往右或往下走到 $(r_2,c_2)$，每步得分是「新格子減舊格子」。設路徑為 $p_0 \to p_1 \to \dots \to p_t$，總分為
$$\sum_{u=1}^{t} \big(a[p_u] - a[p_{u-1}]\big) \;=\; a[p_t] - a[p_0],$$
**望遠鏡求和（telescoping）**，中間項全部相消。

*推論*：總分**與路徑無關**，只取決於起終點。於是原問題退化成「找一對 $(r_1,c_1) \preceq (r_2,c_2)$ 使 $a[r_2][c_2] - a[r_1][c_1]$ 最大」，而「$\preceq$」正是「在左上區域內」。**這一步是本題的真正難點；把它看穿之後，剩下的就只是本節的遞推。** 若把得分改成「每步的絕對值」或「每步乘上某個係數」，望遠鏡不成立，就必須真的做路徑 DP。

**引理 3（枚舉右下角不重不漏）。** 每一組合法的 $((r_1,c_1),(r_2,c_2))$ 恰有一個右下角 $(r_2,c_2)$，故在 $(r_2,c_2)$ 這一輪會被考慮到；而 $M^{-}[r_2][c_2]$ 是該輪所有合法左上角中 $a$ 最小者，故 $a[r_2][c_2] - M^{-}[r_2][c_2]$ 是該輪的最大值。對所有右下角取 $\max$ 即為全局最大。

*「不含自己」的必要性*：題目要求 $(r_1,c_1) \ne (r_2,c_2)$。若用 $M$ 而非 $M^{-}$，當 $a[i][j]$ 本身就是區域最小值時會算出 $0$，在**全部答案皆為負**的矩陣（嚴格遞減的網格）上就會錯誤地回傳 0。**這正是必須用 $M^{-}$、且必須「先算候選再併入自己」的原因。**

**本節不能做什麼。** $M$ 只能回答**角落錨定**的區域極值。任意矩形 $[r_1,r_2]\times[c_1,c_2]$ 的最小值**無法**由 $M$ 導出（沒有逆元，無從扣除）。要做任意矩形 RMQ 得用二維 ST 表（$O(mn\log m\log n)$ 預處理、$O(1)$ 查詢）或二維線段樹。**看到「任意矩形的 min」就別想套本節。**

## C++17 模板

```cpp
// 矩陣中的最大得分（LeetCode 3148）：左上前綴最小值，滾動一列。
class Solution {
public:
    int maxScore(std::vector<std::vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        const int kInf = INT_MAX;

        std::vector<int> row(
            n, kInf);  // 掃到第 i 列時，row[j] 尚未更新前 = M[i-1][j]
        int ans = INT_MIN;

        for (int i = 0; i < m; ++i) {
            int left = kInf;  // = M[i][j-1]，j = 0 時為空
            for (int j = 0; j < n; ++j) {
                int up = row[j];  // = M[i-1][j]
                int pre =
                    std::min(up, left);  // = M^-[i][j]：左上區域，不含自己

                if (pre !=
                    kInf) {  // 有合法左上角才更新答案（避免 INT_MAX 溢位）
                    ans = std::max(ans, grid[i][j] - pre);
                }
                int cur = std::min(grid[i][j],
                                   pre);  // = M[i][j]：先算候選，再併入自己

                row[j] = cur;  // 供下一列使用
                left = cur;    // 供同列右邊使用
            }
        }
        return ans;
    }
};
```

`pre != kInf` 的檢查不是防禦性冗餘：$(0,0)$ 沒有任何合法左上角，若直接算 `grid[0][0] - INT_MAX` 會**有號整數溢位（未定義行為）**，實際跑出來是個很大的正數，答案就錯了。**要嘛加這個檢查，要嘛把運算搬到 `long long`——不能兩者都不做。**

```cpp
// 四方向角落極值的通用寫法：同一段遞推換掃描方向跑四次。
// dirR/dirC 分別表示列、行的掃描是遞增(true)還是遞減(false)。
static std::vector<std::vector<int>> cornerMin(
    const std::vector<std::vector<int>>& a, bool dirR, bool dirC) {
    int m = a.size(), n = a[0].size();
    std::vector<std::vector<int>> M(m, std::vector<int>(n, INT_MAX));
    for (int t = 0; t < m; ++t) {
        int i = dirR ? t : m - 1 - t;
        int pi = dirR ? i - 1 : i + 1;  // 前一列
        for (int u = 0; u < n; ++u) {
            int j = dirC ? u : n - 1 - u;
            int pj = dirC ? j - 1 : j + 1;  // 前一行
            int best = a[i][j];
            if (pi >= 0 && pi < m) {
                best = std::min(best, M[pi][j]);
            }
            if (pj >= 0 && pj < n) {
                best = std::min(best, M[i][pj]);
            }
            M[i][j] = best;
        }
    }
    return M;
}
```

## 時間與空間複雜度

**建表** $O(mn)$ 時間（每格常數次比較）。**空間**：完整保存是 $O(mn)$；若只需邊掃邊用，滾動一列即 $O(n)$，如上面第一個模板。

**查詢**角落錨定的區域極值 $O(1)$。

**與暴力的落差**：3148 暴力枚舉兩個角落是 $O(m^2n^2)$，$m=n=1000$ 時 $10^{12}$；本節 $O(mn) = 10^6$。

**四方向版本**：四次遞推、四個陣列，$O(mn)$ 時間、$O(mn)$ 空間，常數 ×4。

**任意矩形 RMQ 的代價（對照）**：二維 ST 表 $O(mn\log m\log n)$ 時間與空間、$O(1)$ 查詢。$m=n=1000$ 時空間是 $10^6 \times 10 \times 10 = 10^8$ 個 int，**通常爆記憶體**——這也是為什麼角落錨定的特例值得單獨學：它便宜得多。

## 常見錯誤與邊界條件

- 用 2.6 的四點容斥算 $\min$（**根本不成立，$\min$ 沒有逆元**）。
- 用 $M$ 而非 $M^{-}$，導致「起終點相同」的非法解混入（全負矩陣回傳 0）。
- 先併入自己再算候選（同一個錯誤的另一種寫法）。
- `grid[i][j] - INT_MAX` 有號溢位（要嘛檢查哨兵、要嘛用 `long long`）。
- `ans` 初值設 0 而非 `INT_MIN`（同樣是全負矩陣出錯）。
- 滾動陣列時 `row[j]` 已被本列更新卻仍當成 $M[i-1][j]$ 用（**必須先把 `row[j]` 讀進 `up` 再覆寫**）。
- `left` 忘記在每列開頭重設為 $+\infty$。
- 四方向版本把掃描方向與遞推方向搞反（往右上取極值卻由左往右掃）。
- 把本節套到「任意矩形的 min」（要 ST 表）。
- 誤以為 3148 的路徑得分與路徑有關而去做 DP（望遠鏡相消，只看端點）。

## 與相似技巧的比較

- **與 2.6 二維前綴和**：形狀看似都是「左上區域」，但 2.6 能算**任意矩形**（靠容斥），本節只能算**角落錨定區域**。差別的根源是逆元。**選型時先問「這個運算有沒有逆元」。**
- **與 9.7 ST 表**：同樣靠冪等性，但 ST 表用重疊的 $2^k$ 段覆蓋**任意**區間，代價是 $O(n\log n)$ 空間。**本節是 ST 表在「區間必以角落為錨」時的退化版，便宜一個 $\log$。**
- **與 9.3 線段樹**：線段樹支援修改，本節不支援；線段樹不要求冪等，本節要求。
- **與 1.1 列舉右維護左**：本節就是它的二維版——枚舉右下角，維護左上區域的摘要。**「先查詢再併入自己」這條紀律一字不改地沿用。**
- **與 DP**：$M[i][j]$ 的遞推本身就是一個最簡單的網格 DP。反過來，很多網格 DP（1277 全 1 正方形、221 最大正方形）的轉移也是「取三鄰居的 $\min$ 再加 1」——**形狀一模一樣，只是語意從『區域極值』變成『能延伸多長』。** 認出這個共同骨架，兩邊都好寫。
- **與單調堆疊（4.7）**：若要的是「往左第一個比我小的元素」而非「左邊所有元素的最小值」，那是單調堆疊的領域，$O(n)$ 且資訊更細。**「所有元素的極值」用前綴極值；「第一個滿足條件的元素」用單調堆疊。**

## 本節重點速查

- $M[i][j] = \min(a[i][j],\, M[i-1][j],\, M[i][j-1])$，越界視為 $+\infty$；滾動一列即 $O(n)$ 空間。
- $\min$ **沒有逆元** ⇒ 不能四點容斥；$\min$ **冪等** ⇒ 允許重疊覆蓋，遞推才成立。**分割 vs. 覆蓋，就是加法與極值的分界。**
- 只能算**角落錨定**區域；任意矩形極值要 ST 表（9.7）。
- 3148：路徑得分望遠鏡相消 ⇒ 只看端點差 ⇒ 枚舉右下角 + 左上最小值。
- 必須用**不含自己**的 $M^{-}$，且**先算候選再併入自己**（否則全負矩陣回傳 0）。
- `INT_MAX` 當哨兵時記得檢查再相減，否則有號溢位。
- 滾動陣列要**先讀 `row[j]` 再覆寫**；`left` 每列開頭重設。
- 四方向變體就是同一段遞推換四種掃描方向，別硬湊成一個陣列。
