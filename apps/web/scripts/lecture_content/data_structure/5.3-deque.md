## 這個技術解決什麼問題

雙端佇列（deque, double-ended queue）在兩端都支援 $O(1)$ 的插入與刪除。它出現在三種場合：

- **兩端都要增刪**：641（設計循環雙端佇列）、需要「左右輪流取用」的模擬題。
- **把昂貴的整體操作改成端點操作**：2810（故障鍵盤）——每次遇到 `'i'` 就反轉字串是 $O(n^2)$，改成「翻轉一個布林旗標、往另一端加」是 $O(n)$。**這是本節最值得學的招式：不真的做那個操作，只改變「你從哪一端讀」。**
- **維護一個「可能有用的候選集合」，一端進、另一端出、還要從進的那端淘汰劣勢者**：2071（你可以安排的最多任務數目）、5.4 的單調佇列、0-1 BFS。

**辨識訊號**：發現自己在用 `reverse()`、`insert(begin())`、`erase(begin())` 這類 $O(n)$ 操作，而且是在迴圈裡——先問「這個操作能不能改成端點操作或一個旗標」。

## 狀態／資料結構定義

`std::deque<T>` 的關鍵性質（和 `vector`／`list` 都不同）：

| 性質 | `vector` | `deque` | `list` |
| --- | --- | --- | --- |
| 頭端插入／刪除 | $O(n)$ | $O(1)$ | $O(1)$ |
| 尾端插入／刪除 | 攤還 $O(1)$ | $O(1)$ | $O(1)$ |
| 隨機存取 `[i]` | $O(1)$ | $O(1)$ | $O(n)$ |
| 記憶體連續 | ✓ | ✗（分塊） | ✗ |
| 插入後**參考**是否失效 | 全失效 | **兩端插入不失效** | 不失效 |
| 插入後**迭代器**是否失效 | 可能全失效 | **全失效** | 不失效 |

**兩個常被忽略的點**：
1. `deque` **支援 `[i]` 隨機存取**，這讓它能同時扮演「陣列」與「雙端佇列」——5.4 的單調佇列常需要讀中間元素來除錯。
2. **`deque` 的迭代器在兩端插入後會失效，但參考（reference）不會。** 想在插入過程中保留位置，存下標不要存迭代器。

**兩種典型狀態設計：**

**(A) 內容 + 方向旗標**（2810）
```
deque<char> dq;
bool rev = false;   // true 表示「dq 目前存的是真實字串的反序」
```
真實字串 $=$ `rev ? reverse(dq) : dq`。加字元時看 `rev` 決定 `push_back` 還是 `push_front`。

**(B) 候選集合**（2071、5.4）
```
deque<int> cand;    // 尾端進、兩端都可能出
```
不變量規定「什麼元素有資格待在裡面」以及「兩端各代表什麼極值」。

## 不變量或正確性證明

### 定理 1（2810 旗標法：不做的反轉才是最快的反轉）

*不變量 (R)*：處理完輸入的每個前綴後，
$$\text{真實字串} = \begin{cases} \texttt{dq} \text{ 由頭到尾}, & \texttt{rev} = \text{false} \\ \texttt{dq} \text{ 由尾到頭}, & \texttt{rev} = \text{true} \end{cases}$$

*證明（對輸入長度歸納）*。空字串時 `dq` 空、`rev = false`，成立。

- *遇到 `'i'`*：真實字串反轉。只把 `rev` 取反：若原本 `rev = false`，真實字串是「頭到尾」，反轉後應為「尾到頭」，而新的 `rev = true` 正是這個讀法 —— (R) 保持。`rev = true` 的情形對稱。
- *遇到一般字元 $c$*：真實字串在**尾端**接上 $c$。
  - `rev = false`：讀法是頭到尾，尾端即 `dq` 的尾端 ⇒ `push_back(c)` ✔。
  - `rev = true`：讀法是尾到頭，真實字串的尾端對應 `dq` 的**頭端** ⇒ `push_front(c)` ✔。$\square$

**這個證明的價值在於它點名了前提：所有修改都發生在「真實字串的尾端」。** 如果題目允許在中間插入字元，旗標法就崩潰了——因為 `rev` 只能改變讀取方向，不能改變「哪個位置是中間」。屆時要用平衡樹或 4.6 的 gap buffer。

*複雜度*：每個字元 $O(1)$，總計 $O(n)$；直接 `reverse` 是 $O(n^2)$。**輸入全是 `'i'` 時，樸素解的 $10^5$ 個字元會做 $10^5$ 次 $O(n)$ 反轉，必定 TLE。**

### 定理 2（2071：二分答案的單調性）

`check(k)` = 「能否完成至少 $k$ 個任務」。

*宣稱 A（單調性）*：若 $k$ 可行，則 $k-1$ 可行。
*證明*：從一組完成 $k$ 個任務的可行指派中任意刪掉一組 (工人, 任務)，剩下的指派仍然合法（每個工人仍滿足自己那個任務的門檻，藥丸用量只減不增）。$\square$

*宣稱 B（選誰）*：若 $k$ 可行，則「用**最強的 $k$ 名工人**做**最簡單的 $k$ 個任務**」也可行。
*證明（交換論證）*。設有一組可行指派用到工人 $w$ 而未用到 $w' \ge w$：把 $w$ 換成 $w'$，$w'$ 能力更強，原本 $w$ 做得到的（含吃藥）$w'$ 也做得到 ⇒ 仍可行。反覆交換即得「工人集合可換成最強的 $k$ 名」。任務端對稱：把某個被選任務 $t$ 換成未被選且更簡單的 $t' \le t$，原本能做 $t$ 的工人必能做 $t'$ ⇒ 仍可行。$\square$

由宣稱 A，可行的 $k$ 構成前綴，**可以二分**；由宣稱 B，`check(k)` 只需檢查那一組固定的工人與任務。

### 定理 3（2071 的貪心：吃藥時要吃最難的那個）

`check(k)`：任務、工人皆升冪排序，取 `tasks[0..k-1]` 與 `workers[n-k..n-1]`。**由弱到強**遍歷這 $k$ 名工人 $w$：
1. 把所有滿足 `tasks[j] <= w + strength` 的任務推入 `dq` 尾端（任務升冪，故 `dq` 內也升冪）。
2. 若 `dq` 空 ⇒ 失敗（這名工人無事可做，但 $k$ 名工人必須各做一件）。
3. 若 `tasks[dq.front()] <= w` ⇒ **不吃藥，做最簡單的那個**，`pop_front()`。
4. 否則必須吃藥；若 `pills == 0` ⇒ 失敗。否則 `pills--`，**做 `dq` 中最難的那個**，`pop_back()`。

*不變量*：`dq` 恰好是「尚未指派、且當前工人吃藥後做得到」的任務集合，且升冪排列。由「工人升冪遍歷 ⇒ `w + strength` 單調不減」，加入是單向的，**每個任務最多入隊一次、出隊一次 ⇒ 攤還 $O(1)$**。

*步驟 3 的正確性*：不吃藥時做最簡單的任務。因為後續工人都更強，把難的留給他們不劣（標準交換論證）。

*步驟 4 的正確性（這步反直覺，要證）*：既然這顆藥非吃不可，就該用在 `dq` 中**最難**的任務上。
*證明*。設某個最優解中，工人 $w$ 吃藥做了 $t \in \texttt{dq}$，而 `dq` 中最難的 $h$（$t \le h$）被後面某位工人 $w' \ge w$ 承擔。交換兩人的任務：
- $w$ 改做 $h$：因 $h \in \texttt{dq}$，有 $h \le w + \textit{strength}$，吃同一顆藥即可 ✔。
- $w'$ 改做 $t$：若原本 $w'$ 不吃藥做 $h$（$h \le w'$），則 $t \le h \le w'$，仍不吃藥 ✔；若原本吃藥做 $h$（$h \le w' + \textit{strength}$），則 $t \le h \le w' + \textit{strength}$，用同一顆藥 ✔。

兩種情況下藥丸總用量都不變、可行性保持。故存在一個最優解符合「吃藥時取最難者」。$\square$

**注意證明中真正用到的前提**：**工人按能力升冪遍歷**（保證 $w' \ge w$）、**`dq` 內任務都滿足 $\le w + strength$**。少了任何一個，交換論證就不成立。

## C++17 模板

**模板一：2810 故障鍵盤（旗標 + 雙端佇列）**

```cpp
class Solution {
public:
    string finalString(string s) {
        deque<char> dq;
        bool rev = false;
        for (char c : s) {
            if (c == 'i') {
                rev = !rev;
                continue;
            }
            if (rev)
                dq.push_front(c);
            else
                dq.push_back(c);
        }
        string res(dq.begin(), dq.end());
        if (rev) reverse(res.begin(), res.end());  // 只在最後反轉一次
        return res;
    }
};
```

**模板二：2071 你可以安排的最多任務數目（二分答案 + 雙端佇列貪心）**

```cpp
class Solution {
public:
    int maxTaskAssign(vector<int>& tasks, vector<int>& workers, int pills,
                      int strength) {
        sort(tasks.begin(), tasks.end());
        sort(workers.begin(), workers.end());
        int n = workers.size(), m = tasks.size();

        auto check = [&](int k) -> bool {
            // 最簡單的 k 個任務 tasks[0..k-1]，最強的 k 名工人 workers[n-k..n-1]
            deque<int> dq;         // 存任務「值」，升冪
            int p = pills, j = 0;  // j：下一個尚未考慮的任務下標
            for (int i = n - k; i < n; ++i) {
                int w = workers[i];
                while (j < k && tasks[j] <= w + strength)
                    dq.push_back(tasks[j++]);
                if (dq.empty()) return false;
                if (dq.front() <= w) {  // 不吃藥，做最簡單的
                    dq.pop_front();
                } else {  // 必須吃藥，做最難的
                    if (p == 0) return false;
                    --p;
                    dq.pop_back();
                }
            }
            return true;
        };

        int lo = 0, hi = min(n, m), ans = 0;
        while (lo <= hi) {  // 閉區間二分
            int mid = lo + (hi - lo) / 2;
            if (check(mid)) {
                ans = mid;
                lo = mid + 1;
            } else
                hi = mid - 1;
        }
        return ans;
    }
};
```

**模板三：0-1 BFS（雙端佇列的另一個經典用途）**

```cpp
// 邊權只有 0 與 1 的最短路：權 0 走 push_front，權 1 走 push_back
vector<int> zeroOneBFS(int n, const vector<vector<pair<int, int>>>& g,
                       int src) {
    vector<int> dist(n, INT_MAX);
    deque<int> dq;
    dist[src] = 0;
    dq.push_back(src);
    while (!dq.empty()) {
        int u = dq.front();
        dq.pop_front();
        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (w == 0)
                    dq.push_front(v);
                else
                    dq.push_back(v);
            }
        }
    }
    return dist;
}
```

## 時間與空間複雜度

| 題目 | 時間 | 空間 |
| --- | --- | --- |
| 2810 故障鍵盤 | $O(n)$（樸素反轉為 $O(n^2)$） | $O(n)$ |
| 2071 你可以安排的最多任務數目 | $O((n + m)\log(n+m))$ 排序 $+\ O(k\log \min(n,m))$ 二分 $\Rightarrow O(n\log n)$ | $O(n)$ |
| 0-1 BFS | $O(V + E)$ | $O(V)$ |
| 641 循環雙端佇列 | 每個操作最壞 $O(1)$ | $O(k)$ |

**2071 為什麼是 $O(n \log n)$ 而不是 $O(n\log^2 n)$**：單次 `check(k)` 是 $O(k)$（每個任務最多入隊出隊各一次，攤還 $O(1)$），二分 $O(\log n)$ 次，故檢查部分是 $O(n\log n)$——**與排序同級，排序才是主導項**。若 `check` 內改用 `multiset`（也是常見寫法），單次變 $O(k\log k)$，總計 $O(n\log^2 n)$，在 $n = 5\times10^4$ 下仍能過，但雙端佇列版本更快也更好證。

**`deque` 的常數**：分塊配置使它比 `vector` 慢約 1.5–2 倍，且**不保證記憶體連續**（不能 `&dq[0]` 當 C 陣列用）。**在效能關鍵的迴圈裡，若兩端操作次數上界已知（例如 $\le n$），用 `vector<int> buf(2*n); int head = n, tail = n;` 手動實作會更快**——5.4 的單調佇列常這樣寫。

## 常見錯誤與邊界條件

- **`dq.front()` / `dq.back()` 對空容器是未定義行為**，不會拋例外。任何取端點的地方前面都要有 `if (!dq.empty())` 或由不變量保證非空（例如 2071 的步驟 2 先檢查再取）。
- **`pop_front()` / `pop_back()` 回傳 `void`**，不像某些語言會回傳被刪元素。要先取值再彈：`int v = dq.front(); dq.pop_front();`。
- **迭代器在兩端插入後全部失效。** `for (auto it = dq.begin(); it != dq.end(); ++it) { dq.push_back(...); }` 是 UB。要邊插邊掃，改用下標。
- **2810：不要每次遇到 `'i'` 就真的 `reverse`。** 這是本題唯一的考點，樸素解在 $|s| = 10^5$ 必 TLE。
- **2810 最後那一次 `reverse` 別忘了。** `rev` 為 true 時輸出必須反過來——這是最常見的「本地小測資都對、提交就錯」。
- **2071 二分的邊界**：`hi = min(n, m)`（工人與任務數的較小者），`lo = 0`（一個都不做恆可行）。**用閉區間 `while (lo <= hi)` 並在成功時記錄 `ans`**，避免 off-by-one。
- **2071 的 `pills` 要用區域副本**，`check` 每次呼叫都要重置。用 lambda 捕獲時寫 `int p = pills;` 而不是直接改外層的 `pills`——**這是二分答案題最容易犯的狀態污染錯誤。**
- **2071 步驟 4 寫成 `pop_front()` 是最常見的錯**：吃藥時要吃最難的（定理 3），不是最簡單的。
- **0-1 BFS 的 `push_front` 不能省略距離檢查**：同一節點可能多次入隊，必須用 `dist[u] + w < dist[v]` 過濾，否則可能無限迴圈。**它與 Dijkstra 一樣需要「發現更短才鬆弛」，不是靠 `visited` 標記。**
- **負數下標取模**：手動實作環形雙端佇列時，`(head - 1 + capacity) % capacity`，**`+ capacity` 不可省**。

## 與相似技巧的比較

- **與 5.1 佇列**：`deque` 是 `queue` 的超集，且 `std::queue` 預設就以 `deque` 為底層容器。**只需要 FIFO 就用 `queue`——它會讓讀者知道你不打算從另一端動手，是一種型別層級的文件。**
- **與 5.4 單調佇列**：單調佇列**就是**一個帶不變量的 `deque`（尾端淘汰劣勢、頭端淘汰過期）。本節提供容器，5.4 提供不變量。
- **與 4.6 相向雙棧**：兩者都能達成「兩端 $O(1)$」。**差別在中間**：gap buffer 讓「游標處」也是 $O(1)$，`deque` 不行。**需要在中間動手就用 4.6 或平衡樹，只在兩端動手用 `deque`。**
- **與 `std::list`**：`list` 任意位置 $O(1)$ 插刪，但**沒有隨機存取、快取極差、每個節點多兩個指標**。**除非需要「持有一個位置很久並在該處插刪」（例如 4.2 的 716、LRU 快取），否則不要用 `list`。**
- **與旗標法的一般化**：2810 的「不做反轉，只改讀取方向」屬於**惰性 / 延遲操作**的家族，同族還有：矩陣轉置只改索引函式、線段樹的 lazy 標記（9.3）、字串旋轉只改起點。**判準是：這個操作能否被表示成「對存取路徑的一個變換」，而非對資料本身的變換。**
- **與 6.x 優先佇列**：2071 的候選集合若需要按值取極值且加入順序無序，就得用 `multiset`／堆；**這裡之所以能用 `deque`，是因為任務升冪加入使集合天然有序**——這是把 $O(\log n)$ 降成 $O(1)$ 的關鍵前提。

## 本節重點速查

- `deque`：兩端 $O(1)$、**支援 `[i]` 隨機存取**、記憶體不連續；**兩端插入後參考不失效但迭代器會失效**。
- **2810 的招式：不真的做反轉，只翻轉「從哪一端讀」的旗標**（定理 1）。前提是**所有修改都發生在真實字串的尾端**；允許中間插入就得換 gap buffer / 平衡樹。$O(n^2) \to O(n)$。
- **旗標法是「惰性操作」家族的一員**：把對資料的變換改成對存取路徑的變換。
- **2071**：可行性對 $k$ 單調 ⇒ 二分；「最強 $k$ 工人 + 最簡單 $k$ 任務」不劣（交換論證）。
- **2071 貪心（定理 3）**：工人由弱到強；不吃藥時取 `dq.front()`（最簡單），**吃藥時取 `dq.back()`（最難）**。前提是工人升冪遍歷且 `dq` 內都 $\le w + strength$。
- `deque` 能取代 `multiset` 的前提是**元素以有序方式加入**——這是 $O(\log n) \to O(1)$ 的來源。
- **0-1 BFS**：權 0 走 `push_front`、權 1 走 `push_back`，$O(V+E)$；仍需 `dist[u]+w < dist[v]` 的鬆弛檢查，不能只靠 `visited`。
- `front()`／`back()` 對空容器是 UB；`pop_*` 回傳 `void`，先取值再彈。
- 效能關鍵處，用 `vector` + 手動 `head`／`tail` 取代 `deque` 通常快 1.5–2 倍。
