## 這個技術解決什麼問題

單調佇列回答的是：「**在一個只會往右移動的區間裡，反覆查詢最大值或最小值**」，把樸素的 $O(nk)$ 壓成 $O(n)$。

三類典型應用：

- **固定寬度視窗的極值**：239（滑動視窗最大值）、2398（預算內的最多機器人數目，視窗內 max 乘以長度）。
- **變寬度視窗但左界單調**：1438（絕對差不超過限制的最長連續子陣列）、2762（不間斷子陣列）——同時維護 max 與 min 兩條單調佇列。
- **DP 轉移的區間最優**：$\mathrm{dp}[i] = a_i + \max_{j \in [i-k,\, i-1]} \mathrm{dp}[j]$（跳躍遊戲 VI）、862（和至少為 K 的最短子陣列）、1499（滿足不等式的最大值）。**這一類是單調佇列真正的主戰場**——把一維 DP 的 $O(nk)$ 轉移降成 $O(n)$。

**核心觀察**（和 4.7 單調堆疊同源）：

> 若 $j < i$ 且 $a_j \le a_i$，則**任何包含 $j$ 的、右端不小於 $i$ 的視窗都同時包含 $i$**，此時 $a_j$ 永遠不可能是最大值（$a_i$ 至少一樣大且活得更久）。$j$ 從此無用，可以丟掉。

**這個觀察成立的前提是「視窗右端單調不減」。** 這條前提是單調佇列適用與否的分界線，見定理 1 之後的討論。

## 狀態／資料結構定義

```cpp
deque<int> dq;  // 存「下標」，不存值
```
**存下標**：因為要判斷元素是否已經滑出視窗（`dq.front() <= i - k`），只有值就辦不到。

**兩端的分工完全不同，不要搞混：**

| 端點 | 淘汰理由 | 判斷依據 | 對應的「時間 / 價值」 |
| --- | --- | --- | --- |
| **頭端** `pop_front` | **過期**——已滑出視窗 | **下標** | 時間 |
| **尾端** `pop_back` | **劣勢**——被新來的元素支配 | **值** | 價值 |

**「頭端管時間、尾端管價值」是本節唯一需要背的句子。** 4.7 的單調堆疊只有尾端（沒有過期概念），5.1 的普通佇列只有頭端（不淘汰劣勢者）——**單調佇列是兩者的合體**。

**求最大值 ⇒ 遞減佇列**（尾端彈出所有 $\le a_i$ 者），**求最小值 ⇒ 遞增佇列**。判準同 4.7。

**三步骨架**（順序不能換）：
1. **尾端去劣**：`while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();`
2. **入隊**：`dq.push_back(i);`
3. **頭端去期**：`while (dq.front() <= i - k) dq.pop_front();`，然後 `a[dq.front()]` 即答案。

**步驟 3 放在 2 之後而非之前**，可以保證 `dq` 恆非空（$i$ 剛進去），少一次 `empty()` 檢查；但**若視窗左界由條件（而非固定寬度）決定，就必須改成「先擴右、再縮左、最後讀答案」的順序**，見 1438。

**操作順序不要死背，先寫出查詢視窗的語意。** 每輪先移除已不在查詢區間內的隊首。若本輪查詢包含當前元素 `i`，就先清尾、入隊，再讀答案；若 DP 轉移只允許使用先前位置、查詢不含 `i`，就先讀答案，再把 `i` 入隊。這條規則同時避免漏掉當前元素與誤用尚未合法的狀態。

## 不變量或正確性證明

以「固定寬度 $k$、求最大值」為例（遞減佇列）。

### 定理 1（主不變量）

處理完下標 $i$（已執行完三步骨架）後，`dq` 由頭到尾的下標 $j_1 < j_2 < \dots < j_m$ 恰好是
$$\{\, j \in (i-k,\ i] \;:\; \forall\, t \in (j,\ i],\ a_t < a_j \,\},$$
且 $a_{j_1} > a_{j_2} > \dots > a_{j_m}$（假設元素互異）。特別地 **`a[dq.front()]` $= \max\{a_t : t \in (i-k, i]\}$**。

*證明*。
- *尾端結構*：與 4.7 定理 1 逐字相同——每次入隊前彈掉所有 $a_j \le a_i$，故留下的都滿足「$(j, i]$ 中無人 $\ge a_j$」，單調性隨之而來。
- *頭端範圍*：步驟 3 彈掉所有 $j \le i - k$。由下標遞增，過期者構成**前綴**，所以「反覆彈頭直到頭端合法」恰好移除全部過期者、不會誤傷。（這與 5.1 定理 1 是同一條理由。）
- *頭端即最大*：設 $M$ 是視窗 $(i-k, i]$ 的最大值位置，取其中**最右**的一個。則 $\forall t \in (M, i],\ a_t < a_M$，故 $M \in \texttt{dq}$。又 `dq` 內值嚴格遞減、$j_1$ 最小，若 $j_1 \ne M$ 則 $a_{j_1} > a_M$，與 $M$ 為最大矛盾。故 $j_1 = M$。$\square$

**這個證明用到兩個前提，缺一不可：**

1. **視窗右端單調不減**（$i$ 遞增）——尾端去劣才合法。若允許右端左移（視窗可以縮回去），被彈掉的元素會「復活」，單調佇列徹底失效。
2. **視窗左端單調不減**——頭端去期才只需彈前綴。若左端可以往回走，過期集合就不是前綴。

**兩端都必須單調右移。** 一旦題目允許任意區間查詢（例如離線給定 $q$ 個互不包含的區間），就要改用 ST 表（9.7，$O(1)$ 查詢、只支援可重複貢獻運算）或線段樹（9.3）。**這是選型時第一個要確認的事。**

### 定理 2（攤還 $O(n)$）

令位能 $\Phi = |\texttt{dq}|$。第 $i$ 步彈出 $p_i$ 個（頭尾合計）、壓入 1 個：
$$\hat{c}_i = (p_i + 1) + (1 - p_i) = 2 .$$
故總成本 $\le 2n$。**每個下標一生只入隊一次、出隊一次**，無論從哪一端出去。$\square$

**與 4.7 定理 4 完全相同的論證，只是元素現在有兩個出口。** 位能法在這裡的好處正是它不在意元素從哪端離開。

### 定理 3（862：字首和不單調時的雙向淘汰）

求最短的子陣列使其和 $\ge K$，元素**可為負**。令 $s_0 = 0,\ s_r = a_0 + \dots + a_{r-1}$，要找最小的 $r - l$ 使 $s_r - s_l \ge K$。

**因為有負數，$s$ 不單調，雙指標（滑動視窗）不適用**——這是本題的難點所在。改用單調**遞增**佇列存 $l$ 的候選下標。對每個 $r$：

**(a) 頭端淘汰（已可成交者不必再等）**：`while (!dq.empty() && s[r] - s[dq.front()] >= K) { ans = min(ans, r - dq.front()); dq.pop_front(); }`

*為什麼可以彈掉？* 設 $l = \texttt{dq.front()}$ 且 $s_r - s_l \ge K$。對任何 $r' > r$，若 $l$ 仍可成交，長度 $r' - l > r - l$，**嚴格更差**。故 $l$ 的最優貢獻已在此刻結算完畢。$\square$
**這一步用到的前提是「$r$ 只增不減」**——與定理 1 的前提 1 相同。

**(b) 尾端淘汰（被支配者）**：`while (!dq.empty() && s[dq.back()] >= s[r]) dq.pop_back();` 然後 `dq.push_back(r);`

*為什麼可以彈掉？* 設 $l' = \texttt{dq.back()} < r$ 且 $s_{l'} \ge s_r$。對任何未來的 $r'' > r$：
- 若 $l'$ 可成交（$s_{r''} - s_{l'} \ge K$），則 $s_{r''} - s_r \ge s_{r''} - s_{l'} \ge K$，$r$ **也**可成交；
- 且 $r'' - r < r'' - l'$，$r$ 給出的長度**嚴格更短**。

故 $l'$ 在任何未來都被 $r$ 支配（**兩個維度同時不劣**：既更容易成交、又更短），可以安全丟棄。$\square$

**這個「雙維度支配」論證是 862 的全部內容**，也是所有單調佇列題的通用模板：**證明「新元素在所有未來查詢中都不劣於舊元素」，舊元素才能丟。** 寫任何單調佇列題時，都應該能把這句話具體化成兩行不等式。

*結果*：`dq` 內的 $s$ 值嚴格遞增，每個下標入隊出隊各一次，$O(n)$。

### 定理 4（1438／2762：雙佇列 + 視窗合法性的單調性）

求最長子陣列使 $\max - \min \le \textit{limit}$。同時維護遞減佇列 `mx` 與遞增佇列 `mn`。

*關鍵引理*：**若 $[l, r]$ 合法，則其任一子區間 $[l', r'] \subseteq [l, r]$ 也合法。**
*證明*：子區間的 $\max$ 不增、$\min$ 不減，故 $\max - \min$ 不增。$\square$

*推論*：對固定的 $r$，合法的 $l$ 構成一個**後綴** $[L(r), r]$，且 $L(r)$ 隨 $r$ 單調不減。**因此雙指標成立**——這正是滑動視窗的可行性條件，也讓「左端單調右移」（定理 1 前提 2）自動滿足。

*實作*：右端擴張時把 $r$ 推入兩條佇列；當 `a[mx.front()] - a[mn.front()] > limit` 時 `++l`，並且**若 `mx.front() < l` 則 `mx.pop_front()`，`mn` 同理**。答案取 $\max(r - l + 1)$。

**注意這裡的頭端淘汰不是「$\le i-k$」而是「$< l$」**——視窗左界由條件決定而非固定寬度。**這是固定視窗與可變視窗在程式碼上的唯一差別，但很多人會把兩者的骨架混用而寫出錯誤的彈出條件。**

### 定理 5（1499：把二元條件拆成兩個單變數）

求 $\max (y_i + y_j + |x_i - x_j|)$，其中 $x$ 已升冪、$|x_i - x_j| \le k$。

對 $i < j$（故 $x_i \le x_j$），
$$y_i + y_j + (x_j - x_i) = \underbrace{(y_i - x_i)}_{\text{只和 } i \text{ 有關}} + \underbrace{(y_j + x_j)}_{\text{只和 } j \text{ 有關}} .$$

**這個拆分是全題的關鍵**：一旦目標函數能寫成「$f(i) + g(j)$」，固定 $j$ 後就只需要視窗 $\{i : x_j - x_i \le k\}$ 內 $f(i)$ 的最大值 ⇒ 單調佇列。

*視窗的單調性*：$x$ 升冪 ⇒ 條件 $x_i \ge x_j - k$ 的下界隨 $j$ 單調不減 ⇒ 左端單調右移 ✔ 定理 1 前提 2 成立。

**「拆成 $f(i) + g(j)$」是所有單調佇列優化 DP 的統一形式。** 看到 $\mathrm{dp}[j] = \max_i (\mathrm{dp}[i] + w(i,j))$，第一件事就是嘗試把 $w(i,j)$ 拆開；拆不開（例如 $w$ 有交叉項）就要考慮斜率優化或決策單調性，那已超出本節範圍。

## 時間與空間複雜度

| 題目 | 樸素 | 單調佇列 | 空間 |
| --- | --- | --- | --- |
| 239 滑動視窗最大值 | $O(nk)$ | $O(n)$ | $O(k)$ |
| 862 和至少為 K 的最短子陣列 | $O(n^2)$ | $O(n)$ | $O(n)$ |
| 1438 / 2762 | $O(n^2)$ | $O(n)$ | $O(n)$ |
| 1499 滿足不等式的最大值 | $O(n^2)$ | $O(n)$ | $O(n)$ |
| 2398 預算內的最多機器人數目 | $O(n^2)$ | $O(n)$ | $O(n)$ |
| DP 區間轉移 $\mathrm{dp}[i]=a_i+\max_{[i-k,i-1]}\mathrm{dp}[j]$ | $O(nk)$ | $O(n)$ | $O(k)$ |

**時間 $O(n)$**（定理 2 的位能論證），**空間 $O(k)$ 或 $O(n)$**（視窗最大長度）。

**與其他做法的量化比較**（$n = 10^5$、$k = 10^4$）：
- 樸素 $O(nk) = 10^9$ ⇒ TLE。
- `multiset` 滑動視窗 $O(n\log k) \approx 1.3\times10^6$ 次比較，但**常數大（紅黑樹節點配置、快取不友善）**，實測常慢 5–10 倍。
- 單調佇列 $O(n) = 10^5$，且全是連續記憶體上的整數比較。

**常數優化**：把 `deque<int>` 換成 `vector<int> q(n); int h = 0, t = 0;`（`t` 為尾後下標），入隊 `q[t++] = i`、彈尾 `--t`、彈頭 `++h`。**因為每個下標最多入隊一次，`n` 就是容量上界，不會溢位。** 這樣寫通常比 `std::deque` 快 2 倍以上，是競賽的標準寫法。

## 與相似技巧的比較

- **與 4.7 單調堆疊**：**單調堆疊的區間左界由「資料」決定（第一個更大者），單調佇列的左界由「下標」或「條件」決定。** 另一個說法：**堆疊只從尾端出，佇列兩端都出**；多出來的頭端出口就是「過期」的概念。**題目說「固定寬度 / 最近 k 個 / 距離不超過 k」⇒ 單調佇列；說「左邊第一個更大的」⇒ 單調堆疊。**
- **與 5.1 普通佇列**：普通佇列保留視窗內**全部**元素，單調佇列只保留**可能成為答案的候選**。**兩者的頭端淘汰邏輯完全一樣，差別只在尾端多了去劣。**
- **與 `multiset` 滑動視窗**：`multiset` 支援**任意刪除**，所以視窗左端可以任意跳、甚至可以刪中間的元素；單調佇列不行。**代價是 $O(\log k)$ 與很差的常數。** 判準：**若被刪除的永遠是「最舊的」，用單調佇列；若刪除位置任意，用 `multiset`。**（4.6 定理 3 的對頂堆與 480 的延遲刪除也屬後者。）
- **與 6.x 優先佇列 + 延遲刪除**：堆頂若已過期就彈掉，$O(n\log n)$。**寫起來比單調佇列短，但慢一個 $\log$**；當「劣勢淘汰」的判準不明確（例如比較函數複雜）時，這是穩妥的退路。
- **與 9.7 ST 表**：ST 表 $O(n\log n)$ 預處理、$O(1)$ 任意區間極值，**但需要離線知道整個陣列**，且只支援可重複貢獻的運算（min/max/gcd）。**視窗單調移動 ⇒ 單調佇列（$O(n)$、線上）；區間任意 ⇒ ST 表。**
- **與 9.3 線段樹**：支援單點修改 + 任意區間查詢。**若元素在過程中會被修改，單調佇列與 ST 表都不能用，只剩線段樹。**
- **與斜率優化 / 決策單調性**：當 $w(i,j)$ 無法拆成 $f(i)+g(j)$（有 $i\cdot j$ 之類的交叉項）時，單調佇列不夠，要升級成單調佇列 + 凸包（斜率優化）。**定理 5 的「可拆分」正是兩者的分界。**

## 本節重點速查

- **頭端管時間（下標過期）、尾端管價值（被支配）。** 這是單調佇列與單調堆疊（只有尾端）、普通佇列（只有頭端）的唯一差別。
- **存下標不存值**（要判斷過期）。求 max ⇒ 遞減佇列；求 min ⇒ 遞增佇列。
- **兩個前提缺一不可（定理 1）：視窗右端單調不減、左端單調不減。** 任一端可以往回走，就必須改用 ST 表（9.7）或線段樹（9.3）。
- **通用證明模板**：要丟掉舊元素 $l'$，必須證明新元素在**所有未來查詢**中都不劣——通常是兩個維度同時不劣（862 定理 3：既更容易成交、又更短）。寫題時應該能把它具體化成兩行不等式。
- **攤還 $O(n)$**（定理 2）：每個下標入隊一次、出隊一次，位能法不在意它從哪端離開。
- **固定寬度的頭端條件是 `dq.front() <= i - k`；可變視窗是 `dq.front() < l`。** 兩套骨架不要混用。
- **862 的教訓**：有負數 ⇒ 字首和不單調 ⇒ 樸素滑動視窗失效 ⇒ 改單調佇列。**「元素可為負」是這類題的關鍵字。**
- **1499 的教訓**：把目標拆成 $f(i) + g(j)$，就能用單調佇列優化 DP；拆不開就要斜率優化。
- 效能寫法：用 `vector<int> q(n)` + `h`／`t` 兩個下標取代 `std::deque`，通常快 2 倍以上。
- **順序規則**：先刪過期隊首； 查詢包含當前元素就先入隊再查，不包含就先查再入隊。
