## 這個技術解決什麼問題

堆（heap）／優先佇列（priority queue）解決的是：「**資料動態變動，而你要反覆取出當前的最大或最小值**」。

- **排序**只做一次，之後插入新元素就得重排 —— $O(n\log n)$ 每次。
- **掃全部找最值**是 $O(n)$ 每次。
- **堆**：插入與取極值都是 $O(\log n)$，查看極值 $O(1)$。

三種典型場景：

- **動態 Top-K**：703（資料流中的第 K 大元素）、2530（執行 K 次操作後的最大分數）。
- **貪心的「每步取最划算」**：1046（最後一塊石頭的重量）、1167（連線木棍的最低費用）、1792（最大平均透過率）、2233（K 次增加後的最大乘積）。**堆是貪心演算法的標準配件**——貪心告訴你「取最優的那個」，堆告訴你「怎麼快速取到」。
- **掃描線 + 資源池**：253（會議室 II）、1834（單執行緒 CPU）。

**辨識訊號**：出現「每次取最大／最小」「第 K 大」「合併最小的兩個」「最早結束的那個」，而且資料在過程中會增減。

**反辨識訊號**：若資料**靜態**且只問一次第 K 大，用 `nth_element`（$O(n)$ 期望）比堆快；若要**全部**排序，直接 `sort`。**堆的價值在「動態」與「只取一小撮」。**

## 狀態／資料結構定義

### `std::priority_queue` 的語意

```cpp
priority_queue<int> mx;                             // 大頂堆（預設）
priority_queue<int, vector<int>, greater<int>> mn;  // 小頂堆
priority_queue<pair<int, int>> pq;  // 先比 first，再比 second
```

**`priority_queue<T, Container, Comp>` 的 `top()` 是「在 `Comp` 這個『小於』關係下最大的元素」。** 所以傳 `greater<int>`（把「大於」當成「小於」）就得到小頂堆。**這一層反轉是所有人第一次都會寫反的地方**，記法是：**`greater` ⇒ 小頂堆**。

**自訂比較器**（注意方向與 `sort` 相反）：
```cpp
struct Task {
    int cost, id;
};
auto cmp = [](const Task& a, const Task& b) {
    if (a.cost != b.cost) return a.cost > b.cost;  // cost 小的優先 → 寫 >
    return a.id > b.id;  // 同 cost 時 id 小的優先
};
priority_queue<Task, vector<Task>, decltype(cmp)> pq(cmp);
```
**心法：`sort` 的比較器寫「誰排前面」，`priority_queue` 的比較器寫「誰排後面」。** 若不確定，用一組小資料實測，不要靠記憶。

### 底層陣列表示

堆是一棵**完全二元樹**，用陣列 `h[0..n-1]` 表示：節點 $i$ 的左右子為 $2i+1$、$2i+2$，父為 $\lfloor (i-1)/2 \rfloor$。

**堆性質（小頂堆）**：對所有非根節點 $i$，$h[\mathrm{parent}(i)] \le h[i]$。

**注意堆性質只約束父子，不約束兄弟。** 因此**堆不是排序的**：`h[1]` 不一定小於 `h[2]`，而且**第二小的元素一定是根的某個子節點，但第三小可能在任何深度 $\le 2$ 的位置**。「堆頂之外的順序」是所有堆題的常見誤解來源。

### 三個核心操作

| 操作 | 做法 | 複雜度 |
| --- | --- | --- |
| `push` | 放到陣列尾端，**上濾**（與父交換直到滿足堆性質） | $O(\log n)$ |
| `pop` | 把尾端搬到根，縮小，**下濾**（與較小的子交換） | $O(\log n)$ |
| `build` | 從 $\lfloor n/2 \rfloor - 1$ 往 0 依序**下濾** | $O(n)$，見定理 3 |

## 不變量或正確性證明

### 定理 1（上濾與下濾的區域性）

*引理*：若一棵完全二元樹**除了節點 $v$ 之外**處處滿足堆性質，且 $v$ 只違反與其父的關係，則反覆「與父交換」直到不再違反，可恢復全樹的堆性質。

*證明*。設 $v$ 的值為 $x$，父為 $p$（值 $y$），$y > x$（違反小頂堆）。交換後：
- $v$ 位置放 $y$：其子孫原本 $\ge x$⋯ 不夠，需要 $\ge y$？ 不。原本 $p$ 是 $v$ 的父，$p$ 的另一個子樹的根 $u$ 滿足 $y \le h[u]$，交換後 $y$ 移到 $v$ 的位置，$v$ 的子樹原本滿足 $x \le$ 子孫，但現在根變成 $y > x$⋯

  正確的論證是：**上濾只在「$v$ 是新插入的葉節點」或「$v$ 的子樹整體不變」時使用**。此時 $v$ 的子樹在交換後根變為 $y$，而 $y$ 原本是 $p$，$p \le v$ 的所有子孫（因為交換前 $p$ 是 $v$ 的祖先，堆性質沿路徑傳遞：$p \le$ $v$ 的子孫）。故新根 $y$ 仍 $\le$ 子孫 ✔。
- $p$ 位置放 $x$：$x < y \le$ ($p$ 的另一子樹全體) ✔；而 $x$ 與 $p$ 的父可能違反，繼續上濾。

  每次上濾使違反點的深度嚴格減 1，最多 $\lfloor \log_2 n \rfloor$ 次後到根，必然終止。$\square$

*對稱地*，**下濾**要求「$v$ 的兩棵子樹都已是合法的堆」，此時把 $v$ 與**較小的子**交換，可保證交換後該子位置滿足堆性質（新值 $\le$ 另一子、$\le$ 原本自己的子孫）。

**兩者的前提不同、不可互換**：上濾要求「除了往上這條路徑外都合法」，下濾要求「兩棵子樹都合法」。`push` 只能上濾、`pop` 只能下濾，就是因為這個前提差異。

### 定理 2（`pop` 為什麼要「把最後一個搬到根」）

直接刪掉根會留下一個洞，破壞完全二元樹的形狀。搬最後一個元素到根，**形狀恆保持為完全二元樹**（這是陣列表示能成立的必要條件），再下濾修復值的性質。

**「形狀不變量」與「值不變量」分開維護，是所有堆操作的設計原則。** 形狀由「總是在陣列尾端增刪」保證，值由上濾／下濾保證。

### 定理 3（`build_heap` 是 $O(n)$ 不是 $O(n\log n)$）

自底向上對每個非葉節點下濾。高度為 $h$ 的節點下濾成本 $O(h)$；高度為 $h$ 的節點至多 $\lceil n / 2^{h+1} \rceil$ 個。總成本
$$\sum_{h=0}^{\lfloor \log_2 n\rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) \;=\; O\!\left(n \sum_{h=0}^{\infty} \frac{h}{2^{h+1}}\right) \;=\; O(n) ,$$
因為 $\sum_{h \ge 0} h/2^{h} = 2$ 收斂。$\square$

**直覺**：**大部分節點是葉節點（成本 0），只有極少數節點在高處（成本高）。** 反過來由上而下逐個 `push` 則是 $O(n\log n)$——因為此時大部分節點都要走完整條到根的路徑。**「$n$ 個元素建堆」與「`push` $n$ 次」不是同一件事**，這是面試常考的區分。C++ 對應 `std::make_heap`（$O(n)$）與 `priority_queue` 的區間建構子（內部呼叫 `make_heap`，也是 $O(n)$）。

### 定理 4（703：大小為 K 的小頂堆的不變量）

維護一個**小頂堆**，恆保持大小 $\le K$：每次插入後若 `pq.size() > K` 就 `pop()`。

*不變量*：**堆中恰好是「目前為止所有元素中最大的 $\min(K, n)$ 個」**，故 `pq.top()` 就是第 $K$ 大。

*證明（歸納）*。設處理完前 $n$ 個元素後不變量成立。加入 $x$：
- 若 $|pq| < K$：直接加，堆中是全部 $n+1$ 個，即「最大的 $n+1$ 個」✔。
- 若 $|pq| = K$：加入後 $K+1$ 個，彈出最小者。設原堆為前 $n$ 個中最大的 $K$ 個，記為 $S$。新集合 $S \cup \{x\}$ 的最小者恰是 $\{$前 $n{+}1$ 個元素$\}$ 中第 $K+1$ 大以下的某個⋯ 更直接地：前 $n+1$ 個元素中最大的 $K$ 個，必定是 $S \cup \{x\}$ 去掉其最小者。理由：任何不在 $S \cup \{x\}$ 的元素 $y$，都不在前 $n$ 個的前 $K$ 大之列，故存在 $S$ 中至少 $K$ 個元素 $\ge y$，於是 $y$ 在前 $n+1$ 個中的排名 $> K$。$\square$

**為什麼求「第 K 大」要用小頂堆（而不是大頂堆）？** 因為要能 $O(1)$ 拿到「這 $K$ 個裡最弱的那個」以便淘汰。**記法：求第 K 大 ⇒ 小頂堆；求第 K 小 ⇒ 大頂堆。** 恆為反的。

### 定理 5（1167 連線木棍：Huffman 貪心的最優性）

每次合併兩根，費用為兩者長度和；求把 $n$ 根合成一根的最小總費用。

*宣稱*：**每次合併當前最短的兩根是最優的。**

*證明（交換論證）*。合併過程對應一棵二元樹：葉是原始木棍，內部節點是合併結果，**總費用 $= \sum_i \ell_i \cdot d_i$**，其中 $d_i$ 是葉 $i$ 的深度（因為木棍 $i$ 每參與一次合併就被計入一次費用，參與次數 = 它到根的邊數）。

設 $a \le b$ 是最短的兩根。取任一最優樹 $T$：
1. *$T$ 中存在兩片深度最大且互為兄弟的葉* $x, y$（最深的葉的父節點必有兩個子，且都是葉，否則還有更深的）。
2. *把 $a$ 與 $x$ 交換*：設 $d_a \le d_x$（$x$ 最深）。費用變化 $= (\ell_a d_x + \ell_x d_a) - (\ell_a d_a + \ell_x d_x) = (\ell_x - \ell_a)(d_a - d_x) \le 0$（因 $\ell_a \le \ell_x$、$d_a \le d_x$）。故不劣。
3. 同理把 $b$ 與 $y$ 交換，仍不劣。

於是存在一個最優樹使 $a, b$ 互為兄弟且在最深層。把它們合併成一個長度 $a+b$ 的葉，問題規模減一，對 $n$ 歸納即得。$\square$

**這個證明的兩個支柱值得單獨記住**：(i) **總費用可以改寫成 $\sum \ell_i d_i$**（把「過程」翻譯成「靜態的樹指標」）；(ii) **重排不等式式的交換**——長的配淺的、短的配深的不劣。1046（最後一塊石頭的重量）雖然是「相撞取差」而非「合併取和」，但同樣靠「每次取最大兩個」的貪心，理由是差值只由當前最大兩者決定。

### 定理 6（1792 最大平均透過率：邊際效益遞減 ⇒ 貪心正確）

有 $m$ 個班級，第 $i$ 班原本 $p_i / t_i$；有 `extra` 個一定會過的學生要分配。目標最大化平均透過率。

*邊際收益*：把一個學生分給狀態為 $(p, t)$ 的班級，收益
$$\Delta(p,t) = \frac{p+1}{t+1} - \frac{p}{t} = \frac{t-p}{t(t+1)} .$$

*引理（遞減 / 凹性）*：對同一班連續分配時，$\Delta(p+1, t+1) = \dfrac{t-p}{(t+1)(t+2)} < \dfrac{t-p}{t(t+1)} = \Delta(p, t)$（當 $t > p$）。$\square$

*定理（可分離凹函數的資源分配）*：若各班的收益函數關於「分到的人數」是**凹的**（邊際收益遞減），則「每次把下一個學生分給當前邊際收益最大的班級」得到全域最優。

*證明概要（交換論證）*。設貪心解為 $G$、某最優解為 $O$，且它們第一次分歧於第 $s$ 步：貪心給了班 $A$，最優給了班 $B$。因為 $O$ 總共比 $G$ 多給 $A$ 的人數不足⋯ 標準做法：由於 $\Delta_A$（在 $G$ 的當下狀態）$\ge \Delta_B$，把 $O$ 中某個給 $B$ 的學生改給 $A$。由凹性，$A$ 少收到的那個學生的邊際值 $\ge$ 貪心當下的 $\Delta_A$⋯ 精確地：凹性保證「$A$ 的第 $k$ 個學生的邊際收益」隨 $k$ 遞減，因此把一個學生從 $B$ 移到 $A$，$A$ 增加的量 $\ge$ 該班的最後一個邊際值 $\ge \Delta_B \ge$ $B$ 失去的量。故 $O$ 不會變差，分歧點右移一步。歸納可得 $G$ 最優。$\square$

**「邊際收益遞減」是所有『用堆做貪心分配』題的共同前提**（2233 K 次增加後的最大乘積、2530 執行 K 次操作後的最大分數、1962 移除石子使剩下的石頭最少 都是同一族）。**寫這類題時先驗證凹性，凹性不成立（邊際收益會變大）貪心就會錯。**

*實作*：堆按 $\Delta$ 排序，每次取出、分配一個、重算 $\Delta$、放回。

### 定理 7（253 會議室 II：答案 = 最大重疊數）

*宣稱*：所需會議室數 $=\max_t |\{i : t \in [s_i, e_i)\}|$。

*下界*：若某時刻 $t$ 有 $c$ 場會議同時進行，它們兩兩衝突，必須各佔一間 ⇒ 至少 $c$ 間。
*上界（構造）*：按開始時間排序，維護一個「各會議室的結束時間」的小頂堆。新會議開始時，若堆頂（最早結束）$\le$ 新會議開始時間，就重用該會議室（`pop` 後 `push` 新結束時間）；否則開一間新的。此演算法開新房間的時刻，恰是當前所有房間都被佔用的時刻，即重疊數達到新高。故用的房間數 $=$ 最大重疊數。$\square$

**「按左端點排序 + 小頂堆存右端點」是區間調度的標準骨架**（3.1.2 的差分事件掃描是同一件事的另一種寫法，$O(n)$ vs $O(n\log n)$，但堆的版本能同時回答「是哪一間」）。

## 時間與空間複雜度

| 操作 | 二元堆 | 說明 |
| --- | --- | --- |
| `top()` | $O(1)$ | |
| `push` | $O(\log n)$ 最壞，**攤還 $O(1)$**（隨機輸入） | 平均上濾距離是常數 |
| `pop` | $O(\log n)$ 最壞與攤還 | 下濾幾乎總是走到底 |
| 建堆（`make_heap`） | $O(n)$ | 定理 3 |
| 查找任意元素 | $O(n)$ | **堆不支援搜尋** |
| 刪除任意元素 | $O(n)$ 定位 $+ O(\log n)$ | 故有 6.6 懶刪除 |

**題目層級**：
- 703（第 K 大）：`add` $O(\log K)$，空間 $O(K)$。**空間是 $O(K)$ 而非 $O(n)$，這正是用堆的理由。**
- 1046 / 1167：$O(n\log n)$ 時間、$O(n)$ 空間。**1167 若木棍長度值域小，可用「兩個佇列合流」在排序後做到 $O(n)$**（一個存原始升冪、一個存合併結果，兩者都遞增）——這是 Huffman 的線性實作，值得知道。
- 253：$O(n\log n)$（排序主導）、$O(n)$。
- 1792：$O(m + \textit{extra}\cdot\log m)$。

**常數注意**：
- **`priority_queue` 沒有 `reserve`，但底層 `vector` 有。** 可以先建一個 `vector` 再用區間建構子（$O(n)$ 建堆），比逐個 `push` 快得多。
- **`pop()` 回傳 `void`**：`int x = pq.top(); pq.pop();`。
- **存大物件時用 `priority_queue<pair<int,int>>` 而非 `priority_queue<BigStruct>`**——堆的上濾下濾會做 $O(\log n)$ 次交換，物件越大越慢。

## 與相似技巧的比較

- **與 `sort`**：靜態、要全部順序 ⇒ `sort`（$O(n\log n)$，常數小）。動態、只要極值 ⇒ 堆。**「排序後只用前幾個」通常可以換成堆或 `nth_element`。**
- **與 `nth_element`**：靜態陣列求第 $K$ 小，`nth_element` 是**期望 $O(n)$**，比堆的 $O(n\log K)$ 快。**但它會重排原陣列、且最壞 $O(n^2)$（實作通常有 introselect 保護）。資料流／動態場景不能用。**
- **與 `std::set` / `multiset`**：`set` 也能 $O(\log n)$ 取極值，**而且支援任意刪除與 `lower_bound`**。代價是常數大 3–5 倍、記憶體多。**判準：只需要極值 ⇒ 堆；還需要「找某個值」或「刪中間」⇒ `multiset`（或 6.6 懶刪除堆）。**
- **與 5.4 單調佇列**：兩者都能取視窗極值。**單調佇列 $O(1)$ 攤還但要求視窗兩端單調右移；堆 $O(\log n)$ 但不限移動方式。** 視窗固定右移就用單調佇列。
- **與 6.3 二分答案**：求「第 K 小」時，堆是 $O(k\log k)$、對值域二分是 $O(n\log C)$。**$k$ 很小用堆，$k$ 接近 $n$ 用二分。**
- **與計數排序 / 桶**：若值域很小（例如 $\le 100$），用 `cnt[]` 陣列 + 從高往低掃，可以做到 $O(1)$ 取極值。**6.4 的 621 任務排程器就是這種情形，用陣列比用堆更快也更好寫。**
- **與 9.x 線段樹**：線段樹能做「區間最值 + 單點修改」，堆只能做「全域最值」。**需要區間限定就上線段樹。**

## 本節重點速查

- **`priority_queue` 預設是大頂堆；傳 `greater<T>` 得到小頂堆。** 比較器的方向與 `sort` **相反**（`sort` 寫「誰在前」，`priority_queue` 寫「誰在後」）。不確定就實測。
- **求第 K 大 ⇒ 維護大小為 K 的小頂堆**（定理 4），堆頂即答案，空間 $O(K)$。求第 K 小反之。
- **堆只保證父子關係，兄弟之間無序**——`h[1] < h[2]` 不成立，堆不是排序的。
- **`make_heap` 是 $O(n)$，`push` $n$ 次是 $O(n\log n)$**（定理 3：大多數節點在底層、成本為 0）。有一整批初始資料就用區間建構子。
- **上濾與下濾的前提不同**：上濾要求「只有往上這條路徑違反」，下濾要求「兩棵子樹都已合法」。所以 `push` 只能上濾、`pop` 只能下濾。
- **貪心 + 堆的正確性靠交換論證**：1167 靠「費用 $=\sum \ell_i d_i$ + 長的配淺的」（定理 5）；1792 靠**邊際收益遞減（凹性）**（定理 6）。**凹性不成立，貪心就會錯——這是這類題唯一要檢查的前提。**
- **253 區間調度骨架**：左端點排序 + 小頂堆存右端點；答案 = 最大重疊數（下界由衝突給出、上界由構造給出）。
