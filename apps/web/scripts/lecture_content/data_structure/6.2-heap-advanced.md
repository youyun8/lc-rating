## 這個技術解決什麼問題

基礎堆（6.1）解決「動態取極值」。進階題把堆放進更大的框架裡，共有三種：

- **K 路合流**：多條各自有序的資料來源要按全域順序消費——23（合併 K 個升序連結串列）、355（設計推特）、632（最小區間）、373／378（見 6.3）。**堆在這裡扮演「$k$ 條鏈的前緣（frontier）」。**
- **瓶頸路 / 邊界擴張**：407（接雨水 II）、778（水位上升的泳池中游泳）、1631（最小體力消耗路徑）。**堆在這裡扮演 Dijkstra 的優先佇列，只是距離函數從「路徑和」換成「路徑上的最大值」。**
- **貪心的「取最優、再帶入新候選」**：502（IPO）、1834（單執行緒 CPU）、2402（會議室 III）、857（僱用 K 名工人的最低成本）。**候選集合會隨掃描而擴大，堆負責在擴大的集合上取極值。**

這三類的共同點是：**堆本身不是演算法，而是某個框架的「取最優」子程序**。所以寫這類題的順序永遠是——**先確定框架與貪心的正確性，再決定堆裡放什麼**。

## 狀態／資料結構定義

### (A) K 路合流

```cpp
// 23：堆中恆為「每條尚未耗盡的串列的當前頭節點」
auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };  // 小頂堆
priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq(cmp);
```
**堆的大小恆 $\le k$，不是 $\le n$。** 這是 $O(n\log k)$ 而非 $O(n\log n)$ 的來源。

```cpp
// 632：堆中恆為「每條串列的當前指標所指元素」(value, listId, idx)
priority_queue<array<int, 3>, vector<array<int, 3>>, greater<>> pq;
int curMax;  // 額外維護堆中的最大值——堆只能 O(1) 看最小值
```
**`curMax` 必須自己維護**：堆看不到自己的最大值。因為每次只換掉一個元素、且新元素 $\ge$ 被換掉的，`curMax = max(curMax, newVal)` 就夠了——**這條增量更新的合法性來自「替換的一定是最小者、新值一定不小於它」**。

### (B) 瓶頸路 / 邊界擴張

```cpp
// 407：堆中是「當前水池邊界」上的格子，按高度排序
priority_queue<array<int, 3>, vector<array<int, 3>>, greater<>>
    pq;  // (height, r, c)
vector<vector<char>> vis(m, vector<char>(n, 0));
int level = 0;  // 已彈出的最大高度 = 當前水位
```
**`vis` 必須在「入堆時」標記**（和 BFS 同理），否則同一格會被推入多次。

### (C) 掃描 + 候選池

```cpp
// 502：兩個容器分工
sort(idx by capital);  // 依門檻升冪，指針 j 單向推進
priority_queue<int> profitHeap;  // 已負擔得起、尚未做的專案利潤（大頂堆）
```
**「一個排序陣列（按進入條件）+ 一個堆（按價值）」是這一族的通用形狀**：排序陣列決定「什麼時候有資格進場」，堆決定「進場後誰最優」。1834、2402、857、1353 全是同一個骨架。

## 不變量或正確性證明

### 定理 1（K 路合流：堆是「前緣」，彈出順序即全域有序）

*不變量 (F)*：任一時刻，堆中恰好包含每條**尚未耗盡**串列的當前頭元素，各一個。

*證明*：初始把每條串列的頭放入 ✔。每次彈出串列 $i$ 的頭 $x$ 後，若 $i$ 還有下一個元素就推入，否則 $i$ 耗盡 ✔。$\square$

*定理*：**彈出序列是全域非遞減的。**
*證明*。設某次彈出 $x$（來自串列 $i$），下一次彈出 $y$。要證 $x \le y$。$y$ 所屬串列 $j$ 在彈出 $x$ 時已有一個元素 $z$ 在堆中（由 (F)，若 $j$ 未耗盡）。因 $x$ 是彈出時的最小值，$x \le z$。而 $y$ 若就是 $z$ 則 $x \le y$ ✔；若 $y$ 是 $z$ 之後的元素，由串列 $j$ 自身有序，$z \le y$，故 $x \le z \le y$ ✔。$\square$

**這條證明點名的前提是「每條來源自身有序」。** 少了它，堆只是個排序器，複雜度退化成 $O(n\log n)$ 且需要一次放入全部元素（空間 $O(n)$）。**「每條來源有序」正是把空間從 $O(n)$ 壓到 $O(k)$ 的全部理由。**

*推論（355 設計推特）*：`getNewsFeed` 只要最新的 10 則。把每位追蹤者的推文串列（按時間逆序）當成一條有序來源，合流時**取滿 10 則就停**，成本 $O(f + 10\log f)$（$f$ 為追蹤數），而非 $O(\text{總推文數})$。**「只要前 $m$ 個就在第 $m$ 次彈出後停」是 K 路合流最實用的推論。**

### 定理 2（407／778／1631 是同一題：最小瓶頸路）

定義從格子 $u$ 到格線外部的一條路徑的**瓶頸值**為路徑上（含起點）所有格子高度的最大值。令
$$B(u) = \min_{\text{路徑 } P: u \to \text{外部}} \ \max_{v \in P} h_v .$$

*引理*：**格子 $u$ 上的積水量 $= \max(0,\ B'(u) - h_u)$**，其中 $B'(u)$ 是「不含 $u$ 自己」的最小瓶頸值。

*證明概要*。($\le$) 若水位高於 $B'(u)$，則沿著那條瓶頸值為 $B'(u)$ 的路徑，水會流到外面——水不可能穩定在該高度。($\ge$) 若水位是 $B'(u)$，任何一條通往外部的路徑上都存在一格高度 $\ge B'(u)$（否則該路徑的瓶頸值更小，與 $B'$ 的最小性矛盾），水被擋住。$\square$

*演算法（Dijkstra on the bottleneck metric）*：把所有邊界格推入小頂堆並標記已訪問。反覆彈出高度最小的格 $u$：
```
level = max(level, h[u]);
for 每個未訪問的鄰居 v:
    water += max(0, level - h[v]);
    vis[v] = 1;  pq.push({h[v], v});
```

*不變量 (L)*：**`level` 單調不減，且在彈出 $u$ 之後，`level` $= \max\{h_w : w \text{ 已彈出}\}$，同時等於「已彈出集合的邊界水位」。**

*正確性*：這與 Dijkstra 的證明同構，只是「路徑代價 = 邊權和」換成「路徑代價 = 節點值的 max」。關鍵性質仍然成立：
- **子路徑最優性**：最小瓶頸路的任一前綴也是到該點的最小瓶頸路（因為 $\max$ 對前綴單調）。
- **貪心可交換**：每次彈出的最小值不可能被之後更大的值改善（$\max$ 只增不減）。

因此 `level` 在彈出 $v$ 的那一刻就是 $B'(v)$，積水量正確。$\square$

**把 407 認出來是「最小瓶頸路」而不是「二維版的接雨水」，是解這一族題的關鍵。** 778（等待水位上升）問的是 $B(\text{終點})$ 本身、1631（最小體力消耗）把節點值換成邊的差值——**三題共用同一份程式碼骨架**，只差在代價定義。（1631 也可以用並查集按邊權升冪合併，見 8.x；那是同一個問題的 Kruskal 視角。）

**一維的 42 接雨水為什麼不需要堆？** 因為一維只有左右兩條路徑，$B'(i) = \min(\max_{j<i} h_j,\ \max_{j>i} h_j)$，前後綴最大值就能算完。**二維的路徑數是指數級，才需要 Dijkstra。**

### 定理 3（502 IPO：資本單調 ⇒ 純貪心正確）

有 $k$ 次機會；專案 $i$ 需要資本 $c_i$、獲利 $p_i \ge 0$；做完資本增加 $p_i$。

*引理（可行集單調）*：資本 $w$ 只增不減 ⇒ 「負擔得起的專案集合」$\{i : c_i \le w\}$ 只增不減。**這依賴前提 $p_i \ge 0$**（題目保證）。若有負獲利專案，可行集可能縮小，貪心立刻失效。

*定理*：**每一步在當前可行集中取獲利最大者，是最優的。**
*證明（交換論證）*。設最優解 $O$ 的第一步做了專案 $b$，而貪心做 $a$（$p_a \ge p_b$，且 $a$ 當下可行）。
- 若 $O$ 之後有做 $a$：把 $O$ 中 $a$ 與 $b$ 的位置互換。$a$ 提前做仍可行（第一步就負擔得起）；$b$ 延後做也仍可行（資本只增不減，之後的資本 $\ge$ 現在 $\ge c_b$）。總獲利不變。
- 若 $O$ 之後沒做 $a$：把 $b$ 換成 $a$。獲利變化 $p_a - p_b \ge 0$，不劣；且因 $p_a \ge p_b$，後續每一步的資本都不比原來少，原本可行的後續選擇仍然可行。

兩種情形下都存在一個「第一步與貪心相同」的最優解，歸納即得。$\square$

**這個證明點名了兩個前提**：**(i) 獲利非負（可行集單調）；(ii) 專案不重複做**。少了 (i)，就要改用 6.5 的反悔堆。

*實作*：專案按 $c_i$ 升冪排序，指標 $j$ 單向推進，把所有 $c_i \le w$ 的 $p_i$ 倒進大頂堆；取堆頂加到 $w$。**指標 $j$ 只進不退，所以總推入次數是 $n$，攤還 $O(\log n)$。**

### 定理 4（632 最小區間：枚舉「區間最小值」是完備的）

從 $k$ 條升冪串列中各取一個數，使這 $k$ 個數的極差最小（等價：找最小區間 $[a,b]$ 使每條串列至少有一個數落在其中）。

*引理*：最優區間 $[a, b]$ 可以取 $a$ 為某個實際存在的元素（把 $a$ 往上推到區間內的最小元素，$b$ 不變，仍覆蓋全部串列且不變長）。同理 $b$ 也可取實際元素。

*演算法*：堆中恆為「每條串列的當前指標元素」（不變量 (F)），額外維護 `curMax`。當前候選區間是 $[\texttt{pq.top()}, \texttt{curMax}]$——**它必定覆蓋所有串列各一個元素**（由 (F)）。記錄後，彈出最小者、把它所屬串列的指標右移一格並推入、更新 `curMax`。

*完備性證明*：需要證明「每個可能成為最優解的區間都會被枚舉到」。設最優區間為 $[a^*, b^*]$，$a^*$ 是串列 $i$ 的第 $t$ 個元素。考慮演算法中「串列 $i$ 的指標剛好指到第 $t$ 個元素、且 $a^*$ 是堆中最小值」的那一刻——這一刻必然存在，因為每條串列的指標都單調右移，且 $a^*$ 在成為堆中最小值之前不會被彈出。此刻堆中每條串列的元素都 $\ge a^*$（$a^*$ 是最小），而且各自是「$\ge a^*$ 的最小者」（指標從未跳過任何元素）。故 $\texttt{curMax} \le b^*$，記錄到的區間不比 $[a^*, b^*]$ 長。$\square$

**「指標從不跳過元素，所以堆中的元素恆是各串列中 $\ge$ 當前最小值的最小者」——這句話就是完備性的全部。**

### 定理 5（1834／2402／857 的共同骨架：兩階段掃描）

這一族的形狀是：**事件按時間（或某個門檻）升冪；到達時間 $t$ 時，把所有「已可用」的候選倒進堆；再從堆中取最優者處理。**

*不變量*：任一時刻，堆中恰好是「已經可用、但尚未被處理」的候選集合。

*為什麼指標不會回退*：**候選的「可用時間」與掃描的時間都單調不減**，所以推入是單向的，總推入次數 $= n$。這保證了整體 $O(n\log n)$ 而不是 $O(n^2\log n)$。

*1834 的關鍵細節*：若堆為空而任務尚未到達，**時間要直接跳到下一個任務的到達時間**（`t = max(t, tasks[j].enqueueTime)`），不能一秒一秒走——否則會 TLE 或死迴圈。

**這個骨架與 5.2 的「排序 + 惰性推進」以及 12.x 的離線掃描是同一個東西。** 認出它之後，這一族題的差異只剩下「堆的比較器怎麼寫」。

## 時間與空間複雜度

| 題目 | 時間 | 空間 | 說明 |
| --- | --- | --- | --- |
| 23 合併 K 個升序連結串列 | $O(n\log k)$ | $O(k)$ | $n$ 為總節點數。分治兩兩合併也是 $O(n\log k)$、空間 $O(\log k)$ |
| 355 設計推特 | `postTweet` $O(1)$；`getNewsFeed` $O(f + 10\log f)$ | $O(\text{推文} + \text{關係})$ | 只取前 10 則就停 |
| 407 接雨水 II | $O(mn\log(mn))$ | $O(mn)$ | 每格入堆出堆各一次 |
| 502 IPO | $O(n\log n)$ | $O(n)$ | 排序主導 |
| 632 最小區間 | $O(N\log k)$ | $O(k)$ | $N$ 為所有元素總數 |
| 778 / 1631 | $O(mn\log(mn))$ | $O(mn)$ | 亦可用並查集 $O(mn\,\alpha)$ + 排序 |

**23 的兩種解法值得對比**：
| 解法 | 時間 | 空間 | 備註 |
| --- | --- | --- | --- |
| 小頂堆 | $O(n\log k)$ | $O(k)$ | 線上、可提前停止 |
| 分治兩兩合併 | $O(n\log k)$ | $O(\log k)$ 遞迴 | 常數更小、無需堆 |
| 逐條合併 | $O(nk)$ | $O(1)$ | $k$ 大時退化 |
**同樣是 $O(n\log k)$，分治的常數更小**（只有指標比較，沒有堆的上濾下濾）。**但只有堆的版本能「取到第 $m$ 個就停」**，355 需要這個性質。

**407 的空間**：`vis` 用 `vector<vector<char>>` 而非 `vector<vector<bool>>`——後者是位元壓縮的特化，存取慢且不能取址。$m, n \le 200$ 時差別不大，但這是值得養成的習慣。

## 與相似技巧的比較

- **與 6.1 基礎堆**：差別在**堆外面包了什麼框架**。基礎題是「堆即演算法」，進階題是「堆是子程序」。**寫進階題時，先把框架的正確性證出來，再想堆裡放什麼。**
- **與 6.3 第 K 小**：6.3 的 373／378 也是 K 路合流，但**候選是「按需生成」的**（彈出一個才產生它的後繼），需要額外處理重複生成。本節的 23／632 候選來源是現成的串列，較單純。
- **與 6.5 反悔堆**：502 的貪心**不需要反悔**（定理 3：可行集單調 + 獲利非負）。**一旦「做了某個選擇會讓未來變差」，就必須升級成反悔堆。** 這是 6.2 與 6.5 的分界線。
- **與 6.6 懶刪除堆**：2402（會議室 III）需要「把用完的會議室放回可用池」，這是**推入**不是刪除，所以不需要懶刪除。**只有當「堆中某個元素因外部原因作廢」時才需要 6.6。**
- **與 Dijkstra**：407／778／1631 就是 Dijkstra，只是代價運算子從 $+$ 換成 $\max$。**Dijkstra 的正確性只要求代價運算子滿足「單調性」（$c \le c \oplus w$）與「結合性」，$\max$ 兩者皆滿足**——這也是為什麼同一份程式碼能跑兩種問題。
- **與並查集（8.x）**：1631／778 的另一解是「邊按權重升冪加入並查集，直到起終點連通」。**$O(E\,\alpha(V))$ 比 Dijkstra 快，但必須離線（要先拿到所有邊）。** 線上查詢就只能用堆。
- **與 3.1.2 差分事件掃描**：253 那類「只問重疊數」的題用差分是 $O(n)$，比堆快。**堆的優勢在於它能回答「是哪一個」而不只是「有幾個」**（2402 要知道具體是哪間會議室）。

## 本節重點速查

- 進階堆題 = **框架 + 堆**。**先證框架，再決定堆裡放什麼**；堆本身從來不是難點。
- **K 路合流（定理 1）**：不變量是「堆中恰有每條未耗盡串列的當前頭」，彈出序列全域有序；**前提是每條來源自身有序**，這也是空間 $O(k)$ 而非 $O(n)$ 的理由。**只要前 $m$ 個就在第 $m$ 次彈出後停**（355）。
- **407 / 778 / 1631 是同一題：最小瓶頸路。** 積水量 $=\max(0, B'(u) - h_u)$，`level` 單調不減即 Dijkstra 不變量；**代價運算子從 $+$ 換成 $\max$，Dijkstra 的證明照樣成立。**
- 一維的 42 不需要堆，因為只有兩條路徑；二維路徑指數多，才需要。
- **502 純貪心成立的兩個前提**：獲利非負（可行集單調）、專案不重做。**破了就要升級成 6.5 反悔堆。**
- **632**：堆看不到自己的最大值，`curMax` 要自己維護；完備性來自「指標從不跳過元素」。
- **掃描 + 候選池骨架（定理 5）**：排序陣列決定「何時有資格進場」，堆決定「進場後誰最優」；**兩個指標都單調不退**，總推入 $n$ 次。1834 記得把時間直接跳到下一個到達時間。
- 23 的分治解與堆解同為 $O(n\log k)$，**分治常數更小、空間更省，但不能提前停止。**
- `vis` 在**入堆時**標記，不是出堆時。
