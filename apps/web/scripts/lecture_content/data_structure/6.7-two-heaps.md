## 這個技術解決什麼問題

資料在動態變化（一直加入，或視窗滑動進出），卻要隨時查詢**排序後某個固定位置的值**——中位數、第 $K$ 小、分界值。

- **295 資料流的中位數**：只增不刪，查中位數。
- **480 滑動視窗中位數**：固定寬度視窗，有進有出。
- **1825 求出 MK 平均值**：去掉最小 $k$ 個與最大 $k$ 個後求平均——需要**分界 + 區段和**。
- **2102 序列順序查詢**：分界位置本身會隨查詢次數移動。
- **LCP 24 / 462 / 296**：目標函數是 $\sum |x_i - c|$，最優的 $c$ 就是中位數（定理 4）。

**核心想法**：*用兩個堆把序列切成「前半」與「後半」，讓要查的那個位置恰好卡在兩個堆的堆頂。* 前半用**大頂堆**（堆頂是前半的最大者），後半用**小頂堆**（堆頂是後半的最小者），**分界線兩側的臨界元素就都是 $O(1)$ 可得。**

**暴力是每次操作重排 $O(n\log n)$，對頂堆把單次操作壓到 $O(\log n)$。**

**辨識訊號**：要查的是「排序後第 $p$ 個」，而 $p$ 由總數決定（$n/2$）或由題目給定，且資料動態變動。**若 $p$ 每次查詢都不同、任意指定，對頂堆就不適用**（見「與相似技巧的比較」）。

## 狀態／資料結構定義

```cpp
priority_queue<int> lo;                             // 前半，大頂堆
priority_queue<int, vector<int>, greater<int>> hi;  // 後半，小頂堆
```

**兩條不變量**（4.6 定理 3 已證，此處直接沿用）：
- **(P1)** $\max(\texttt{lo}) \le \min(\texttt{hi})$——`lo` 的每個元素都不大於 `hi` 的每個元素。
- **(P2)** $|\texttt{lo}| = |\texttt{hi}|$ 或 $|\texttt{lo}| = |\texttt{hi}| + 1$。

在 (P1)(P2) 之下：
- $n$ 奇數 ⇒ 中位數 $=$ `lo.top()`；
- $n$ 偶數 ⇒ 中位數 $= (\texttt{lo.top()} + \texttt{hi.top()}) / 2.0$。

**「第 $K$ 小」的版本**：把 (P2) 換成 $|\texttt{lo}| = K$（固定），則 `lo.top()` 恆為第 $K$ 小。**中位數只是 $K = \lceil n/2\rceil$ 的特例。**

**帶區段和的版本（1825）**：除了兩個堆，額外維護 `sumLo`、`sumHi`，每次搬動元素時同步加減。**這是「$O(1)$ 取得前 $K$ 大之和」的標準做法**，比每次遍歷堆快得多。1825 需要三段（最小 $k$ / 中間 / 最大 $k$），就是三個容器加三個和。

**帶懶刪除的版本（480）**——這是本節唯一真正困難的部分：
```cpp
priority_queue<int> lo;
priority_queue<int, vector<int>, greater<int>> hi;
unordered_map<int, int> delayed;  // 待刪的值 -> 次數
int balance = 0;                  // 有效大小之差：|lo|_eff - |hi|_eff
```
**`lo.size()` 包含垃圾，絕對不能拿來做平衡判斷**——必須用 `balance` 這個獨立計數器。**這是 480 的全部難點，也是最常見的錯誤來源。**

## 不變量或正確性證明

### 定理 1（分界不變量與中位數的正確性）

在 (P1)(P2) 之下，把 `lo` 的元素由大到小、`hi` 的元素由小到大排列，整體就是原集合的排序。設 $n = |\texttt{lo}| + |\texttt{hi}|$。

- 由 (P1)，`lo` 中的元素在排序中全部排在 `hi` 之前，故 **`lo.top()` 是排序後的第 $|\texttt{lo}|$ 個**（1-indexed），**`hi.top()` 是第 $|\texttt{lo}|+1$ 個**。
- 由 (P2)，$|\texttt{lo}| = \lceil n/2\rceil$。$n$ 奇數時 $\lceil n/2\rceil = (n+1)/2$ 正是中位數位置 ✔；$n$ 偶數時第 $n/2$ 與第 $n/2+1$ 個分別是兩個堆頂 ✔。$\square$

**注意這裡真正被使用的只有 (P1)**——(P2) 只是把「第 $|\texttt{lo}|$ 個」調到我們想要的位置。**所以要查第 $K$ 小，只要把 (P2) 改成 $|\texttt{lo}| = K$，其餘完全不動。** 認清這一點，2102（分界位置隨查詢移動）就只是「每次查詢後把 (P2) 的目標值加一」。

### 定理 2（插入的三行寫法為什麼保持 (P1)(P2)）

```cpp
lo.push(x);  // (1)
hi.push(lo.top());
lo.pop();  // (2)
if (hi.size() > lo.size()) {
    lo.push(hi.top());
    hi.pop();
}  // (3)
```

*證明*（4.6 定理 3 的複述，因為它是本節的地基）。
- (1) 之後 `lo` 可能違反 (P1)（$x$ 可能大於 `hi` 的某些元素）。
- (2) 把 `lo` 的**最大者**移到 `hi`。移走之後，`lo` 剩下的元素都 $\le$ 那個最大者 $\le$ ⋯ 需要它 $\le \min(\texttt{hi})$：新的 $\min(\texttt{hi})$ 就是剛移進去的那個或原本的 $\min$，兩者都 $\ge$ `lo` 的所有剩餘元素 ✔。**(P1) 恢復。**
- (2) 之後大小關係可能變成 $|\texttt{hi}| = |\texttt{lo}| + 1$，(3) 把一個搬回來，恢復 (P2)。搬的是 `hi` 的最小者，搬到 `lo` 後它是 `lo` 的最大者，仍 $\le$ 剩下的 `hi` ✔ **(P1) 保持。**$\square$

**這個寫法沒有 `if/else` 分支，是它值得記住的原因**——「先無條件過一手，再修平衡」比「先比較 $x$ 與堆頂再決定放哪邊」少一類邊界錯誤（例如 `lo` 為空時 `lo.top()` 是 UB）。

### 定理 3（480 滑動視窗中位數：懶刪除下的平衡）

**問題所在**：懶刪除之後，`lo.size()` 是「有效元素 + 垃圾」的總數。**用它做平衡判斷會把垃圾算進去，導致分界線跑掉，中位數錯誤。**

**解法**：另外維護 `balance` $= |\texttt{lo}|_{\text{eff}} - |\texttt{hi}|_{\text{eff}}$，所有操作都只更新 `balance`，永遠不看 `size()`。

```cpp
auto prune = [&](auto& h) {  // 清掉堆頂的垃圾
    while (!h.empty()) {
        auto it = delayed.find(h.top());
        if (it == delayed.end()) break;
        if (--it->second == 0) delayed.erase(it);
        h.pop();
    }
};
auto rebalance = [&]() {
    if (balance > 1) {
        hi.push(lo.top());
        lo.pop();
        balance -= 2;
        prune(lo);
    } else if (balance < 0) {
        lo.push(hi.top());
        hi.pop();
        balance += 2;
        prune(hi);
    }
};
auto insert = [&](int x) {
    if (lo.empty() || x <= lo.top()) {
        lo.push(x);
        ++balance;
    } else {
        hi.push(x);
        --balance;
    }
    rebalance();
};
auto erase = [&](int x) {
    ++delayed[x];
    if (x <= lo.top()) {
        --balance;
        if (x == lo.top()) prune(lo);
    } else {
        ++balance;
        if (x == hi.top()) prune(hi);
    }
    rebalance();
};
```

*不變量*：
- **(E1)** `balance` 恆等於有效元素的個數差，且操作結束後 $\in \{0, 1\}$；
- **(E2)** 兩個堆的**堆頂都是有效元素**（`prune` 保證）；
- **(E3)** (P1) 對有效元素成立。

*為什麼 `erase` 只在 `x == top` 時才 `prune`*：若 $x$ 不是堆頂，它躺在堆中間，**根本不影響堆頂的讀取**，等它自己浮上來再清即可。**這正是懶刪除的核心（6.6）：垃圾只有在堆頂才礙事。**

*為什麼 `erase` 用 `x <= lo.top()` 判斷歸屬是對的*：由 (E2)，`lo.top()` 是有效的、且是 `lo` 中有效元素的最大者。由 (E3)，$x \le \texttt{lo.top()}$ ⟺ $x$ 屬於 `lo`（若 $x$ 屬於 `hi` 則 $x \ge \min(\texttt{hi}) \ge \texttt{lo.top()}$，相等時歸哪邊都可以，因為值相同）。**相等時的歸屬歧義無害——刪掉的是同一個值，多重集合的結果相同。** $\square$

*為什麼 `rebalance` 之後要再 `prune`*：搬動會讓新的堆頂暴露出來，而它可能是垃圾。**漏掉這個 `prune`，下一次的 `x <= lo.top()` 判斷就會用到一個已刪除的值。**

**480 值得完整手寫一遍的理由**：它把「懶刪除」（6.6）與「對頂堆」（本節）疊在一起，兩層不變量互相牽制。**寫之前先把 (E1)(E2)(E3) 抄在紙上，寫完逐條檢查每個分支是否維持——這是唯一可靠的方法。**

*更短的替代解*：`multiset` + 一個指向中位數的迭代器。插入／刪除後把迭代器 `++`／`--` 修正。$O(\log k)$、程式碼一半長度、沒有垃圾。**面試或比賽時建議用這個；對頂堆版本適合用來練不變量。**（刪除時若刪到迭代器本身，要先移動迭代器再 `erase`。）

### 定理 4（中位數最小化 $\sum|x_i - c|$）

**定理**：$f(c) = \sum_{i=1}^{n} |x_i - c|$ 在 $c$ 取任一中位數時達到最小。

*證明*。$f$ 是有限個絕對值函數之和，故**凸**且**分段線性**。在區間 $(x_{(j)}, x_{(j+1)})$ 上，
$$f'(c) = \#\{i : x_i < c\} - \#\{i : x_i > c\} = j - (n - j) = 2j - n .$$
$f'$ 隨 $j$ 遞增，符號在 $j = n/2$ 處由負轉正。
- $n$ 奇數：$f'$ 在 $c < x_{((n+1)/2)}$ 時為負、之後為正 ⇒ 唯一最小點 $c = x_{((n+1)/2)}$。
- $n$ 偶數：$f' = 0$ 於 $[x_{(n/2)}, x_{(n/2+1)}]$ ⇒ 整段皆為最小點。$\square$

*推論（$O(1)$ 求最小值）*：用對頂堆同時維護 `sumLo`、`sumHi`，令 $m = \texttt{lo.top()}$、$a = |\texttt{lo}|$、$b = |\texttt{hi}|$，則
$$f(m) = \big(a\cdot m - \texttt{sumLo}\big) + \big(\texttt{sumHi} - b\cdot m\big) .$$
**「維護分界 + 維護兩側和」讓每次查詢從 $O(n)$ 降到 $O(1)$**，這是 462、296、LCP 24、以及各種「把陣列變成等差／全相等的最小代價」題的共同骨架。

**變形提醒**：若要變成「相鄰元素相差 1 的遞增序列」，先做 $x_i \leftarrow x_i - i$ 的變換再取中位數（把等差問題化歸為全相等問題）。**變換之後定理 4 直接適用**——這是這一族題唯一的技巧。

### 定理 5（1825 MK 平均值：三段結構）

要求「去掉最小 $k$ 個與最大 $k$ 個後的平均」，視窗大小 $m$。維護三個容器：
- `small`：最小的 $k$ 個（大頂堆）
- `mid`：中間的 $m - 2k$ 個（雙端有序結構，或兩個堆）
- `large`：最大的 $k$ 個（小頂堆）

以及 `sumMid`。

*不變量*：$\max(\texttt{small}) \le \min(\texttt{mid})$ 且 $\max(\texttt{mid}) \le \min(\texttt{large})$，且 $|\texttt{small}| = |\texttt{large}| = k$（在元素數 $\ge m$ 時）。

*插入／刪除的處理*：新元素先按值放進正確的容器，然後**逐級搬動**恢復大小約束（`small` 太大就把最大者推給 `mid`，依此類推）。**每次操作最多搬動 $O(1)$ 個元素**（因為每個容器的大小最多偏差 1），故仍是 $O(\log m)$。

**實作建議**：這題用 `multiset` + 三個迭代器（或 `multiset` + 前綴和）遠比三個堆好寫。**當「段數 $\ge 3$」時，對頂堆的寫法會爆炸，改用有序容器。** 這是對頂堆的實際適用邊界。

| 題目 | 操作 | 時間 | 空間 |
| --- | --- | --- | --- |
| 295 資料流的中位數 | `addNum` / `findMedian` | $O(\log n)$ / $O(1)$ | $O(n)$ |
| 480 滑動視窗中位數 | 每個視窗 | $O(\log k)$ 攤還 | $O(k)$ 有效 + 垃圾 |
| 1825 MK 平均值 | `addElement` / `calculateMKAverage` | $O(\log m)$ / $O(1)$ | $O(m)$ |
| 2102 序列順序查詢 | `add` / `get` | $O(\log n)$ | $O(n)$ |
| 462 / LCP 24 | 全部 | $O(n\log n)$（排序即可，不需堆） | $O(n)$ |

**462 這類離線題不需要對頂堆**——直接排序取中位數 $O(n\log n)$。**對頂堆的價值只在「線上、邊加邊查」。** 看到題目給的是一個固定陣列而非資料流，先想排序。

**480 的空間**：垃圾最壞 $O(n)$（$n$ 為總元素數而非視窗大小 $k$）。**若 $n$ 很大而 $k$ 很小，建議改用 `multiset`（空間恆為 $O(k)$）。**

**溢位**：
- `(lo.top() + hi.top()) / 2.0` 中，兩個 `int` 相加可能溢位。**寫成 `((long long)lo.top() + hi.top()) / 2.0`。** 480 的測資明確包含 `INT_MAX` 來抓這個錯。
- 定理 4 的 $f(m)$ 與 1825 的 `sumMid` 都要 `long long`。

## 與相似技巧的比較

- **與 4.6 定理 3**：4.6 從「相向雙容器」的角度介紹了對頂堆的基本形。**本節多了三件事：一般化到第 $K$ 小、懶刪除（480）、以及維護區段和（1825、定理 4 推論）。**
- **與 1670 設計前中後佇列（5.2）**：形狀極像但語意不同——**1670 的「中間」是位置的中間（按下標分割，用 `deque`），本節的「中間」是值的中位（按值分割，用堆）。** 看清楚是位置還是值，是這兩題唯一的分歧點。
- **與 `multiset` + 中位數迭代器**：功能相同，程式碼更短、無垃圾、常數略大。**實務首選；對頂堆的優勢是常數與「不依賴迭代器穩定性」。**
- **與有序統計樹（pb_ds `tree_order_statistics_node_update`）**：支援 `find_by_order(k)`（第 $k$ 小）與 `order_of_key(x)`（排名），**$K$ 可以每次查詢都不同**。**這是對頂堆的硬邊界：對頂堆只能維護一條（或固定幾條）分界線，任意排名查詢必須換工具。**
- **與值域樹狀陣列 / 線段樹（9.x）**：在值域上建樹，用「樹上二分」找第 $K$ 小，$O(\log C)$。**當值域可離散化且查詢排名任意時，這是最通用的解。** 缺點是要先知道所有可能的值（或動態開點）。
- **與 5.4 單調佇列**：單調佇列只能取視窗的**極值**，不能取中位數。**「極值」用單調佇列（$O(1)$ 攤還），「任意排名」用對頂堆或樹（$O(\log k)$）。**
- **與 6.3 第 K 小**：6.3 是「一次性求出第 $K$ 小」，本節是「持續維護第 $K$ 小」。**一次性 ⇒ `nth_element` 或二分；持續維護 ⇒ 對頂堆。**

## 本節重點速查

- **核心：兩個堆把序列切成兩半，要查的位置卡在分界線上——`lo` 大頂堆、`hi` 小頂堆。**
- **真正起作用的只有 (P1) $\max(\texttt{lo}) \le \min(\texttt{hi})$**；(P2) 只是把分界線調到想要的位置。**改成 $|\texttt{lo}| = K$ 就是第 $K$ 小**（2102 只是讓 $K$ 隨查詢遞增）。
- **無分支的插入三行**：`lo.push(x); hi.push(lo.top()); lo.pop(); if (hi.size() > lo.size()) {搬回來}`。比「先比較再決定放哪邊」少一類邊界錯誤。
- **480 的全部難點：`heap.size()` 包含垃圾，不能用來平衡——必須另設 `balance` 計數器。** 三條不變量 (E1)(E2)(E3) 要抄下來逐分支檢查。`rebalance` 之後**必須再 `prune`**。
- **`erase` 只在 `x == top` 時才 `prune`**——垃圾只有在堆頂才礙事。
- **480 實務首選是 `multiset` + 中位數迭代器**，程式碼一半長度、無垃圾。
- **中位數最小化 $\sum|x_i - c|$**（定理 4，凸 + 分段線性，斜率 $2j-n$ 變號處）。配合 `sumLo`／`sumHi` 可 $O(1)$ 求出最小值。**「相鄰差 1 的遞增序列」先做 $x_i \leftarrow x_i - i$ 再套用。**
- **段數 $\ge 3$（1825）就別用堆了**，改 `multiset` + 前綴和。
- **硬邊界**：對頂堆只能維護固定的分界線。**任意排名查詢 ⇒ 有序統計樹或值域樹狀陣列。**
- `(lo.top() + hi.top()) / 2.0` 記得先轉 `long long`。
