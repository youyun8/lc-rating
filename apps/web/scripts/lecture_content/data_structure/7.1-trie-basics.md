## 這個技術解決什麼問題

一本字典有 $n$ 個字串、總長 $L$。要回答「$s$ 在不在字典裡」「字典裡有幾個字以 $s$ 開頭」「字典裡哪個字是 $s$ 的前綴」這類問題。

- **雜湊表能回答第一個問題**（$O(|s|)$），**但完全無法回答後兩個**——雜湊把字串打散了，前綴關係在雜湊值上不留任何痕跡。
- **排序 + 二分能回答前綴計數**（前綴相同的字在字典序中連續），**但只能離線**，且每次比較是 $O(|s|)$。
- **逐一比對是 $O(L)$**，字典一大就不能接受。

**核心想法**：*把字典裡所有字串的所有前綴，共用地存成一棵樹——每個節點代表一個前綴，每條邊代表一個字元。* 於是「以 $s$ 開頭」就是「$s$ 對應節點的整棵子樹」，前綴關係從「要比對字元」變成「是不是祖先」。

**這才是 trie 的本質：把前綴關係轉成樹上的祖先關係。** 記住這句話，7.1～7.4 的所有題目都只是它的不同用法：
- 648 單字替換 = 找最淺的祖先；
- 720 最長單字 = 在「合法節點」構成的子樹裡找最深；
- 820 單字壓縮編碼（反向插入）= 數葉子；
- 7.4 的 0-1 trie = 把整數當成固定長度的二進位字串。

**代價是空間**：節點數最壞是 $L+1$，每個節點若用陣列存 26 個孩子，就是 $26L$ 個 `int`。**trie 是典型的「用空間換時間」，資料量上限沒算清楚就會 MLE。**

## 狀態／資料結構定義

**寫法 A：指標／結構體（好讀，適合設計題如 208、677）**

```cpp
struct Node {
    Node* ch[26]{};  // 值初始化為 nullptr
    bool isEnd = false;  // 從根到此節點的字串，本身是一個字典單字
    int cnt = 0;  // 有多少個插入的字串「經過」此節點（＝以此前綴開頭的字數）
    int val = 0;  // 677 這類鍵值題用
};
```

**寫法 B：靜態陣列池（快，適合大資料量與 0-1 trie）**

```cpp
constexpr int MAXN = 100005 * 32;  // 上界＝所有字串總長 + 1，務必自己算
int ch[MAXN][26], cnt[MAXN];
bool isEnd[MAXN];
int tot = 0;  // 已配置的節點數，節點 0 是根
```

**三個欄位的語意必須分清楚——這是 trie 題最常見的混淆來源：**

| 欄位 | 語意 | 回答什麼 |
| --- | --- | --- |
| 節點存在 | 這個前綴出現過 | `startsWith(s)` |
| `isEnd` | 這個前綴**本身**是一個單字 | `search(s)` |
| `cnt` | 有幾個單字以這個前綴開頭 | `countPrefix(s)`、可刪除的引用計數 |

**根節點代表空字串**，深度 $d$ 的節點代表長度 $d$ 的前綴。

**字元集不是 26 就要改**：小寫字母 26、大小寫加數字 62、任意 ASCII 128。**字元集大而稀疏時用 `unordered_map<char, Node*> ch;`**——時間多一個雜湊常數，空間從 $O(\Sigma \cdot |\text{節點}|)$ 降到 $O(|\text{邊}|)$。

## 不變量或正確性證明

### 定理 1（結構不變量：節點 ↔ 前綴的雙射）

設插入的字串集合為 $S$，令
$$P(S) = \{\, p : p \text{ 是某個 } s \in S \text{ 的前綴（含空串與 } s \text{ 本身）} \,\}.$$

**不變量 (T)**：任何時刻，trie 的節點集合與 $P(S)$ 之間存在雙射，且節點 $u$ 對應的字串恰為「從根到 $u$ 的邊標籤依序連接」。

*證明*（對插入次數歸納）。
- **基底**：$S = \emptyset$，trie 只有根，$P(\emptyset) = \{\varepsilon\}$，根對應空串 ✔。
- **歸納步**：假設插入 $s_1,\dots,s_{k-1}$ 後 (T) 成立，現插入 $s_k$。插入程序沿 $s_k$ 的字元逐個下走，孩子不存在就新建。走到第 $i$ 步時所在節點對應 $s_k[0..i)$。
  - **新增的節點**恰好是 $s_k$ 那些「先前不存在的前綴」，也就是 $P(S \cup \{s_k\}) \setminus P(S)$ ✔；
  - **不新增任何其他節點**，也不刪除節點 ✔；
  - 對應關係由「沿邊下走」定義，與 (T) 的敘述一致 ✔。$\square$

**(T) 是整節的地基。** 它把「字串的前綴關係」翻譯成「樹上的祖先關係」：

> **推論 1.1**：$p$ 是 $q$ 的前綴 $\iff$ 節點 $u_p$ 是節點 $u_q$ 的祖先（或相等）。

*證明*：由 (T)，$u_q$ 對應的字串由根到 $u_q$ 的路徑決定；$u_p$ 是祖先 $\iff$ 該路徑的某個前段走到 $u_p$ $\iff$ $p$ 是 $q$ 的前段。$\square$

**推論 1.1 就是所有 trie 題的共同轉譯規則。** 下面每個定理都只是在推論 1.1 上加一句話。

### 定理 2（查詢的正確性，以及 `search` 與 `startsWith` 的唯一差別）

*前提*：插入 $s$ 時，**只在終點節點**把 `isEnd` 設為 `true`，且從不設回 `false`（無刪除的情形）。

- `startsWith(s)`：沿 $s$ 下走，中途缺孩子回 `false`，走完回 `true`。
  由 (T)，「走得完」$\iff$ $s \in P(S)$ $\iff$ $s$ 是某個插入字串的前綴 ✔。
- `search(s)`：同上，再加一句 `return isEnd[u]`。
  由前提，`isEnd[u]` 為真 $\iff$ 曾有某次插入以 $u$ 為終點 $\iff$ $s \in S$ ✔。

**這兩個函式的差別只有最後一行。** 也就是說：**「$s$ 是否在字典裡」與「$s$ 是否為字典裡某字的前綴」是兩件事，而 trie 天生能區分它們——這正是雜湊表做不到的地方。**

*支援刪除時*：不要真的刪節點，改成維護 `cnt`（經過此節點的字串數），刪除時沿路 `--cnt`。**節點的 `cnt == 0` 表示這個前綴已無人使用**，此時可以（但不必）回收。**用 `cnt` 而不是實際刪除，是因為刪節點必須確認它沒有其他後代——那需要額外資訊，而 `cnt` 恰好就是那個資訊。**

### 定理 3（648 單字替換：為什麼「走到第一個 `isEnd` 就停」是對的）

*問題*：字典裡有一堆字根，把句子中每個單字換成「能作為它前綴的**最短**字根」。

*引理*：一個字串 $w$ 的所有前綴，依長度排序構成一條**鏈**——任兩個前綴之間必有一個是另一個的前綴。

*證明*：長度為 $i$ 與 $j$（$i \le j$）的前綴分別是 $w[0..i)$ 與 $w[0..j)$，前者顯然是後者的前綴。$\square$

*定理*：沿 $w$ 從根下走，**第一個遇到的 `isEnd` 節點**就是最短的合法字根。

*證明*：由推論 1.1，「$r$ 是 $w$ 的前綴且 $r$ 在字典裡」$\iff$「$u_r$ 在從根到 $u_w$ 的路徑上且 `isEnd[u_r]`」。下走的順序恰是路徑上節點由淺到深的順序，也就是候選字根**由短到長**的順序。故第一個命中者長度最小 ✔。$\square$

**這個證明的關鍵前提是「候選集合構成一條鏈」**——所以「最短」是良定義的、且不需要任何比較，走到就是答案。**若題目改成「找字典裡與 $w$ 有最長公共前綴的字」，候選就不再是鏈（分佈在不同子樹），第一個命中就不再是答案。** 遇到 trie 題先問：**我要找的東西是不是落在一條根到葉的路徑上？** 是 ⇒ 邊走邊判；不是 ⇒ 要搜子樹（7.2）。

### 定理 4（720 詞典中最長的單字：前綴封閉性）

*問題*：找出字典中最長的字 $w$，使得 $w$ 的**每一個**前綴（長度 $1 \dots |w|$）都在字典裡；同長取字典序最小。

*定理*：合法字的集合 $V$ 在 trie 上構成一棵**包含根的連通子樹**；因此只要做 DFS，**遇到 `isEnd` 為假的孩子就直接剪枝**，就不會漏掉任何合法字。

*證明*。
- **$V$ 前綴封閉**：若 $w \in V$，則 $w$ 的任一前綴 $p$ 的所有前綴也都是 $w$ 的前綴，故都在字典裡，故 $p \in V$ ✔。
- 由推論 1.1，前綴封閉 $\iff$ $\{u_w : w \in V\} \cup \{\text{root}\}$ 對「取父節點」封閉 $\iff$ 它是包含根的連通子樹 ✔。
- **剪枝的正確性**：若某節點 $u$ 的 `isEnd` 為假，則 $u$ 對應的字串不在字典裡，於是 $u$ 的任何後代 $v$ 都有一個不在字典裡的前綴，故 $v \notin V$。**剪掉 $u$ 的整棵子樹不會丟失任何 $V$ 中的元素** ✔。$\square$

*字典序最小*：DFS 時**按 `a` 到 `z` 的順序遍歷孩子**，同深度先到達者字典序較小；用「嚴格大於才更新答案」即可保住最小者。

**「答案集合對某個操作封閉 ⇒ 它在結構上是連通的 ⇒ 可以安全剪枝」是一個通用套路**，不只出現在 trie。看到「每個前綴都要滿足 X」，先想封閉性。

### 定理 5（820 單字壓縮編碼：為什麼反向插入後答案是葉子深度之和）

*問題*：把一組字串編碼成 `s#` 的串接，允許一個字串**共用另一個字串的後綴位置**。求最短編碼長度。

*觀察鏈*：
$$A \text{ 可併入 } B \iff A \text{ 是 } B \text{ 的後綴} \iff \mathrm{rev}(A) \text{ 是 } \mathrm{rev}(B) \text{ 的前綴} \overset{\text{推論 1.1}}{\iff} u_{\mathrm{rev}(A)} \text{ 是 } u_{\mathrm{rev}(B)} \text{ 的祖先}.$$

於是：把所有字串**反轉後插入 trie**，答案 $= \sum_{\text{葉節點 } v} (\mathrm{depth}(v) + 1)$。

*證明（兩個方向）*。
- **上界（構造）**：對每個葉節點 $v$，把它對應的字串（反轉回來）加上 `#` 寫進編碼。任何非葉的 `isEnd` 節點 $u$，其字串是某個葉字串的後綴，可以直接指向該葉字串的尾段。故此編碼合法，長度為 $\sum_v (\mathrm{depth}(v)+1)$ ✔。
- **下界**：設兩個葉 $v_1 \ne v_2$，它們互不為祖先（葉的定義 + 不同節點），故對應字串互不為對方後綴，**它們在編碼中的 `#` 必不相同**（若共用同一個 `#`，兩者都是從該 `#` 往前讀，短者必為長者的後綴，矛盾）。每個葉獨佔一個 `#` 及其前面 $\mathrm{depth}(v)$ 個字元；不同葉佔用的區段互不重疊（同上論證）。故任何合法編碼長度 $\ge \sum_v (\mathrm{depth}(v)+1)$ ✔。$\square$

**必須先去重**（用 `set` 或 trie 自身的 `isEnd`）：兩個相同的字串對應同一個節點，只能算一次。**忘記去重是這題的標準錯誤。**

### 定理 6（規模上界）

**節點數 $\le L + 1$**，其中 $L$ 是所有插入字串的總長。

*證明*：由 (T)，節點數 $= |P(S)|$。每個字串 $s$ 貢獻至多 $|s|$ 個非空前綴，加上共用的空串 ⇒ $|P(S)| \le 1 + \sum_{s}|s| = L+1$ ✔。$\square$

**這個上界是開靜態陣列的唯一依據。** 例如 208 的約束是「總呼叫 $3\times10^4$ 次、每字長 $\le 2000$」⇒ $L \le 6\times10^7$，$26L$ 個 `int` 是 6 GB——**這種情況必須用 `unordered_map` 存孩子，或改用指標動態配置。開陣列前一定要乘出來看。**

## 時間與空間複雜度

設 $L$ 為總長、$|s|$ 為單次操作字串長、$\Sigma$ 為字元集大小。

| 操作 | 陣列孩子 | `unordered_map` 孩子 |
| --- | --- | --- |
| `insert(s)` | $O(\lvert s\rvert)$ | $O(\lvert s\rvert)$ 期望 |
| `search(s)` / `startsWith(s)` | $O(\lvert s\rvert)$ | $O(\lvert s\rvert)$ 期望 |
| 建整本字典 | $O(L)$ | $O(L)$ 期望 |
| 空間 | $O(\Sigma L)$ | $O(L)$ |

**注意 `search` 的複雜度與字典大小 $n$ 完全無關**——這是 trie 相對於「逐一比對 $O(L)$」的全部價值。

各題：
- **208**：所有操作 $O(|s|)$，空間 $O(\Sigma L)$。
- **648**：建樹 $O(L_{\text{dict}})$，處理句子 $O(L_{\text{sentence}})$。
- **720**：建樹 $O(L)$，DFS $O(\Sigma \cdot |\text{節點}|)$。**這題也可以排序後用 `unordered_set` 遞推，$O(L\log n)$ 且好寫**——trie 不是唯一解。
- **820**：$O(L)$。
- **677**：`insert` 與 `sum` 都 $O(|s|)$。**注意 `insert` 可能覆寫既有鍵，要傳「差值」沿路更新 `val` 的前綴和，或者查詢時走子樹加總。**

**常數提醒**：`Node* ch[26]{}` 每個節點 208 bytes（64 位元），節點多時 cache miss 主導耗時。**極端追求速度時改用靜態陣列池 + `int` 索引**，記憶體連續、快 2～3 倍。

## 與相似技巧的比較

- **與雜湊表 `unordered_set<string>`**：精確查詢兩者都是 $O(|s|)$，且雜湊常數更小、空間更省。**只要題目不涉及前綴，就用雜湊表，別建 trie。** trie 的不可替代性在於前綴查詢、前綴計數、以及「邊走邊判斷」。
- **與排序 + 二分**：把字典排序後，以 $s$ 為前綴的字在陣列中構成一段連續區間，用兩次 `lower_bound` 就能計數，$O(|s|\log n)$、空間 $O(L)$。**離線且只需前綴計數時，這個做法比 trie 省得多。** trie 勝在支援動態插入與 $O(|s|)$（無 $\log$）。
- **與 7.2 的 trie 搜尋**：本節的查詢都沿**單一路徑**下走（定理 3 的「鏈」）。**7.2 處理的是查詢本身有分支的情形**（211 的 `.` 萬用字元、212 在網格上搜尋），必須 DFS 整棵子樹並剪枝。**判準：候選是否落在一條根到葉的路徑上。**
- **與 AC 自動機**：trie + 失配指標，能在 $O(|text| + \sum|pattern|)$ 內找出文字中所有模式的所有出現位置。**212 那類「多模式匹配」用 AC 自動機是正解形態，trie + DFS 剪枝只是在題目規模小時夠用。**
- **與後綴陣列 / 後綴自動機**：那些處理的是「**一個**字串的所有子串」，trie 處理的是「**多個**字串的前綴」。820 之所以能用 trie，是因為它把後綴問題透過反轉化歸成前綴問題——**這個化歸只在「整個字串的後綴」時有效，對「任意子串」無效。**
- **與 7.4 的 0-1 trie**：完全同一個資料結構，只是 $\Sigma = 2$、每個「字串」是固定 32 位元。**因為長度固定，0-1 trie 的每次查詢都恰好走 32 步、必定走得完，不需要 `isEnd`**——這是它與一般 trie 在寫法上的主要差異。
- **與 9.x 的值域樹狀陣列／線段樹**：0-1 trie 本質上是一棵值域上的動態開點線段樹。**兩者可以互換，選擇取決於你要做的是「逐位貪心」（trie 直觀）還是「區間求和」（線段樹直觀）。**

## 本節重點速查

- **一句話：trie 把「字串的前綴關係」轉成「樹上的祖先關係」（推論 1.1）。** 所有 trie 題都是這句話加一個條件。
- **三個欄位別混**：**節點存在** = 前綴出現過（`startsWith`）；**`isEnd`** = 這個前綴本身是單字（`search`）；**`cnt`** = 以此為前綴的單字數（計數、可刪除）。`search` 與 `startsWith` 只差最後一行。
- **根 = 空字串**，深度 $d$ 的節點 = 長度 $d$ 的前綴。
- **648**：候選字根構成一條鏈 ⇒ 由淺到深走，**第一個 `isEnd` 就是最短答案**，不需比較。
- **720**：合法字集合前綴封閉 ⇒ 在 trie 上是連通子樹 ⇒ **遇到 `isEnd == false` 的孩子直接剪枝**；按 `a`–`z` 順序 DFS 自然取到字典序最小。
- **820**：`A` 是 `B` 的後綴 $\iff$ `rev(A)` 是 `rev(B)` 的前綴 ⇒ **反向插入，答案 = $\sum_{\text{葉}}(\mathrm{depth}+1)$**。**記得先去重。**
- **節點數 $\le L+1$（定理 6）。開靜態陣列前先把 $26L$ 乘出來**——208 的最壞情況是 6 GB，必須改用 `map` 孩子或指標。
- **支援刪除用 `cnt` 沿路遞減，不要真的刪節點。**
- **判斷該不該用 trie**：只做精確查詢 ⇒ 雜湊表；離線前綴計數 ⇒ 排序 + 二分；**動態 + 前綴 ⇒ trie**。
- **判斷該用 7.1 還是 7.2**：候選落在一條根到葉的路徑上 ⇒ 邊走邊判（本節）；查詢本身有分支 ⇒ DFS 子樹 + 剪枝（7.2）。
