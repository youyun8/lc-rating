## 這個技術解決什麼問題

7.1 的查詢都沿**一條路徑**下走：給定 $s$，路徑唯一，走不動就失敗。本節處理的是**路徑不唯一**的情形——查詢本身帶分支，或者要在別的結構（網格、另一組字串）上同時匹配整本字典。

四類典型需求：

1. **查詢帶萬用字元**（211 新增與搜尋單字：`.` 可配任意字元）。每個 `.` 都讓路徑分裂成 $\Sigma$ 條，必須 DFS。
2. **在一個大結構裡同時找很多個單字**（212 單字搜尋 II、425 單字方塊）。逐一搜尋會把「共同前綴」的工作重算 $n$ 次；**把字典建成 trie，一次搜尋就同時推進所有單字，並在共同前綴失敗時一次剪掉一整批。**
3. **同時牽涉前綴與後綴**（336 迴文對、745 前綴和後綴搜尋）。正插一棵、反插一棵，或把兩者編碼進同一個鍵。
4. **設計題需要按前綴分組聚合**（642 設計搜尋自動補全、677 鍵值對映的加強版、1858 包含所有前綴的最長單字）。

**共同的價值主張**：*把 $n$ 次獨立搜尋合併成一次樹上搜尋，共同前綴只算一次，失敗時整棵子樹一起剪掉。* 剪枝不是優化，**在 212 這類題裡它是能不能過的分界線。**

## 狀態／資料結構定義

在 7.1 的節點上追加欄位，欄位的選擇決定你能回答什麼問題：

```cpp
struct Node {
    Node* ch[26]{};
    int wordId = -1;  // 212：此節點是哪個單字的終點（-1 表示不是）
    int cnt = 0;  // 子樹中還剩幾個未被找到的單字（用於 212 的剪枝）
    int best = -1;  // 745：子樹中權重最大的索引
    vector<int> palIdx;  // 336：子樹方向上「剩餘部分是迴文」的單字索引
};
```

**用 `wordId` 而不是 `bool isEnd`**：212 找到單字後要輸出它，且要**防止重複輸出**——把 `wordId` 設回 `-1` 就同時完成了「記錄」與「去重」兩件事。

**各題的具體結構**：

- **211**：純 7.1 的 trie，複雜度全在搜尋函式。
- **212**：字典建 trie；網格 DFS 時攜帶一個 `Node*`，**網格的路徑與 trie 的路徑同步前進**。
- **336**：把每個字**反轉後**插入 trie，節點上額外記 `palIdx`（見定理 3 的兩種情形）。
- **425**：字典建 trie，`cnt` 或節點上掛「以此為前綴的單字索引清單」，供 $O(1)$ 取出候選。
- **745**：不用兩棵樹——把每個字編碼成所有的 `後綴 + '{' + 完整字`（`'{'` 是 `'z'+1`）插入一棵 trie，查詢 `suffix + '{' + prefix`。**這是「兩個維度合成一個鍵」的經典技巧。**

## 不變量或正確性證明

### 定理 1（211 萬用字元搜尋：前緣集合不變量）

*搜尋函式*：
```cpp
bool dfs(Node* u, const string& w, int i) {
    if (i == (int)w.size()) return u->isEnd;
    if (w[i] != '.') {
        Node* v = u->ch[w[i] - 'a'];
        return v && dfs(v, w, i + 1);
    }
    for (int c = 0; c < 26; ++c)
        if (u->ch[c] && dfs(u->ch[c], w, i + 1)) return true;
    return false;
}
```

**不變量 (F)**：`dfs(u, w, i)` 被呼叫時，$u$ 對應的字串 $p$ 滿足 $|p| = i$ 且 $p$ 匹配模式前綴 $w[0..i)$；反之，**每一個匹配 $w[0..i)$ 且存在於 trie 中的長度-$i$ 字串，都恰好對應一次呼叫。**

*證明*（對 $i$ 歸納）。
- $i=0$：唯一匹配空模式的字串是空串，對應根，恰好呼叫一次 ✔。
- 歸納步：設 (F) 對 $i$ 成立。字串 $q$（$|q|=i+1$）匹配 $w[0..i{+}1)$ $\iff$ $q[0..i)$ 匹配 $w[0..i)$ **且** $q[i]$ 匹配 $w[i]$。
  - $w[i] \ne \texttt{'.'}$：後者 $\iff q[i] = w[i]$，程式只遞迴這一個孩子 ✔。
  - $w[i] = \texttt{'.'}$：後者恆真，程式遞迴所有存在的孩子 ✔。
  由歸納假設，$q[0..i)$ 恰好對應一次呼叫，故 $q$ 也恰好對應一次 ✔。$\square$

由 (F) 與 7.1 定理 2，`i == |w|` 時 `u->isEnd` 為真 $\iff$ 找到一個匹配的字典單字。**「恰好一次」的部分保證了沒有重複展開**——這是複雜度分析的前提。

*複雜度*：設模式中有 $d$ 個 `.`。最壞情形下，被訪問的節點數不超過 $\min\big(\Sigma^{d}\cdot|w|,\ |\text{節點總數}|\big)$。**兩個上界都要看**：$d$ 小時第一項緊，$d$ 大時第二項緊（訪問不可能超過整棵樹）。

*重要的剪枝*：**先按長度分桶**——`vector<Trie> tries(26)`，`addWord(w)` 放進 `tries[w.size()]`。**因為 trie 上長度 $i$ 的節點只可能匹配長度 $i$ 的模式，長度不同的單字完全不必參與搜尋。** 這一行在 211 的實測中通常是 5～10 倍的加速。

### 定理 2（212 單字搜尋 II：邊搜邊剪的正確性與攤還）

*搜尋骨架*：網格 DFS 攜帶 trie 節點，兩者同步移動。

**不變量 (S)**：DFS 進入 `dfs(r, c, u)` 時，$u$ 對應的字串**恰為**當前網格路徑上的字元序列。

*證明*：進入前檢查 `u->ch[grid[r][c]]` 存在才遞迴，且遞迴傳入該孩子。由歸納，路徑字串與 trie 路徑逐字元對應 ✔。$\square$

由 (S) 與 7.1 推論 1.1：**「網格路徑拼出的字在字典裡」$\iff$「同步到達的節點 `wordId >= 0`」**。所以檢查一個字典單字與檢查所有字典單字的成本相同——**這就是把字典建成 trie 的全部收益。**

**兩個剪枝，以及它們為什麼安全：**

- **剪枝 A（找到後移除）**：命中時記錄答案並令 `u->wordId = -1`。
  *安全性*：同一個單字被找到第二次不會產生新答案（答案是集合）。**這同時解決了「同一個字在網格中有多條路徑」造成的重複輸出。**
- **剪枝 B（回溯時摘掉空子樹）**：DFS 從節點 $u$ 返回後，若 $u$ 沒有孩子且 `u->wordId == -1`，就把父節點指向 $u$ 的指標設為 `nullptr`。
  *安全性*：這樣的 $u$ 的子樹裡已無任何未找到的單字，**任何經過 $u$ 的網格路徑都不可能產生新答案**，摘掉不影響結果 ✔。
  *效益（攤還）*：每個 trie 節點最多被摘一次，總摘除成本 $O(|\text{節點}|)$。**而每摘掉一個節點，就永久消除了一整支未來的搜尋分支。** 沒有剪枝 B 時，網格上會反覆走進「只剩已找到單字」的死路；**在 LeetCode 的最壞測資上，剪枝 B 是 TLE 與 AC 的分界。**

*另一種等價寫法*：用 `cnt`（子樹剩餘單字數）。命中時沿路 `--cnt`，DFS 時 `if (u->cnt == 0) return;`。**邏輯與剪枝 B 相同，但不改動樹結構，比較不容易寫錯。**

*必須注意的前提*：**同一格不能重複使用**——用 `visited` 或原地改字元為 `'#'`，**回溯時務必還原**。這與 trie 無關，但是這題最常見的錯誤。

### 定理 3（336 迴文對：完整的分類，以及為什麼需要兩種情形）

*問題*：給定互不相同的字串 $w_0,\dots,w_{n-1}$，找出所有有序對 $(i,j)$，$i \ne j$，使得 $w_i + w_j$ 是迴文。

設 $A = w_i$、$B = w_j$、$m = |A|$、$k = |B|$。

**引理**：$A+B$ 是迴文，當且僅當下列之一成立：

- **(情形 I) $m \ge k$**：$A[0..k) = \mathrm{rev}(B)$，且 $A[k..m)$ 本身是迴文。
- **(情形 II) $m < k$**：$B[k-m..k) = \mathrm{rev}(A)$，且 $B[0..k-m)$ 本身是迴文。

*證明（情形 I）*。令 $T = A+B$，$|T| = m+k$。$T$ 是迴文 $\iff$ $T[t] = T[m+k-1-t]$ 對所有 $t$。
- 取 $t \in [0,k)$：$T[t] = A[t]$（因 $t < k \le m$），$T[m+k-1-t] = B[k-1-t]$（因 $m+k-1-t \ge m$）。故條件為 $A[t] = B[k-1-t]$，即 $A[0..k) = \mathrm{rev}(B)$ ✔。
- 取 $t \in [k, m)$（此區間對稱於自身：$m+k-1-t$ 也落在 $[k,m)$）：$T[t] = A[t]$、$T[m+k-1-t] = A[m+k-1-t]$。令 $t' = t-k$，條件成為 $A[k+t'] = A[m-1-t']$，即 $A[k..m)$ 是迴文 ✔。
- 兩段合起來覆蓋了所有 $t \in [0, m)$，而 $t \ge m$ 的條件與 $t < k$ 的對稱等價，不提供新約束。$\square$

情形 II 由對稱性（考慮 $\mathrm{rev}(T) = \mathrm{rev}(B)+\mathrm{rev}(A)$）同理可得。

**為什麼必須分兩種情形，不能只做一種？** 因為 trie 的下走是有方向的：**把所有字反轉後插入 trie，沿 $A$ 往下走，只能檢測到「$A$ 有一個前綴等於某個 $\mathrm{rev}(B)$」，也就是 $k \le m$。** 當 $k > m$ 時，$A$ 走完了樹卻還停在半路，這時要問的是「**停在這個節點下方、剩餘部分是迴文的字有哪些**」——這正是 `palIdx` 存在的理由。

*實作*：插入 $\mathrm{rev}(w_j)$ 時，在路徑上每個節點 $u$（對應 $\mathrm{rev}(w_j)$ 的長度-$d$ 前綴）記錄：**若 $\mathrm{rev}(w_j)[d..]$ 是迴文，則把 $j$ 加入 `u->palIdx`**（等價於 $w_j$ 的前 $k-d$ 個字元是迴文，即情形 II 的條件）。查詢 $A$ 時：
- 每走到一個 `isEnd` 節點（深度 $d \le m$），檢查 $A[d..m)$ 是否迴文 ⇒ 情形 I 的解；
- 走完 $A$（深度 $m$）後，該節點的 `palIdx` 全部是 ⇒ 情形 II 的解。

**三個必踩的坑**：
1. **空字串**。若 $w_j = \varepsilon$，則 $\varepsilon + A$ 是迴文 $\iff$ $A$ 是迴文——這由情形 I（$k=0$）自動涵蓋，前提是你**允許 $d=0$ 時就檢查 `isEnd`**（根節點也要檢查）。
2. **$i = j$ 要排除**。情形 I 在 $d = m$ 且 $A$ 自身是迴文時會配到自己。
3. **重複計數**。$m = k$ 時情形 I 與 II 會描述同一對；把情形 II 的條件寫成嚴格 $m < k$（即只在走完 $A$ 後才收 `palIdx`，且不含深度恰為 $m$ 的 `isEnd`）即可避免。

*複雜度*：$O\!\left(\sum_j |w_j| + \sum_i |w_i|^2\right)$。**平方項來自「對 $A$ 的每個切點判斷後綴是否迴文」**——可用 Manacher 或雜湊預處理降到 $O(\sum|w_i|)$，但在 LeetCode 的約束下不必要。

### 定理 4（425 單字方塊：行列對偶約束）

*問題*：用字典中的字排成 $L\times L$ 方陣，使得**第 $i$ 行讀出的字 $=$ 第 $i$ 列讀出的字**（對所有 $i$）。

*等價條件*：$\mathrm{sq}[i][j] = \mathrm{sq}[j][i]$ 對所有 $i,j$——**方陣關於主對角線對稱。**

**定理**：若已確定前 $k$ 行（$k \ge 1$），則第 $k$ 行的**前 $k$ 個字元被完全決定**，且必須等於
$$\mathrm{sq}[0][k],\ \mathrm{sq}[1][k],\ \dots,\ \mathrm{sq}[k-1][k]$$
（即前 $k$ 行的第 $k$ 個字元依序拼成的字串）。

*證明*：對稱條件給出 $\mathrm{sq}[k][t] = \mathrm{sq}[t][k]$，右側對 $t < k$ 都在已確定的前 $k$ 行內 ✔。反之，若第 $k$ 行滿足這個前綴條件，則它與前 $k$ 行之間的所有對稱約束都已滿足；與後續行的約束會在填那些行時檢查。**故此條件既必要又充分地刻畫了「可以繼續」**，回溯搜尋不會漏解也不會產生非法解。$\square$

**這就是為什麼要 trie**：每一步都需要「以某個特定前綴開頭的所有單字」，這正是 trie 的 $O(\text{前綴長} + \text{答案數})$ 查詢（在節點上掛索引清單）。**用暴力篩選字典是 $O(n)$ 每步，指數級搜尋乘上這個因子就過不了。**

**通用心得**：**回溯 + trie 的組合，關鍵永遠是「找出一個既必要又充分的『可繼續』條件」。** 條件太弱（只檢查必要性的一部分）會搜出非法解，太強會漏解。425 的條件恰好是對稱約束在「已填部分」上的完整投影。

### 定理 5（745 前綴和後綴搜尋：把兩個維度編碼成一個鍵）

*問題*：預處理一組字串，支援查詢「同時以 $p$ 為前綴、以 $s$ 為後綴的字中，索引最大者」。

*做法*：對每個字 $w$（索引 $i$），把**所有** `w的後綴 + '{' + w` 插入 trie，路徑上每個節點的 `best` 更新為 $\max(\texttt{best}, i)$。查詢時走 `s + '{' + p`，回傳終點的 `best`。

*正確性*：分隔符 `'{'`（ASCII 恰為 `'z'+1`）**不出現在任何單字中**，所以鍵 `X{Y` 唯一分解為 $(X, Y)$。於是
$$\texttt{s+'\{'+p} \text{ 是 } \texttt{suf+'\{'+w} \text{ 的前綴} \iff \big(s = \mathrm{suf} \text{ 的前綴且 } \mathrm{suf} \text{ 走完}\big) \dots$$
更精確地：因為 `'{'` 是唯一的分隔符，前綴關係成立當且僅當 $s = \mathrm{suf}$（分隔符位置必須對齊）**且** $p$ 是 $w$ 的前綴。而「$s$ 出現在某個 `suf` 的位置」$\iff$ $s$ 是 $w$ 的後綴（因為我們插入了 $w$ 的所有後綴）✔。$\square$

**前提是分隔符不在字元集內。** 若字串可能包含任意字元，這個技巧就失效，得改用兩棵 trie 求索引集合交集（或 bitset）。

*複雜度*：建樹 $O(\sum |w|^2)$（每個字插入 $|w|+1$ 個鍵），查詢 $O(|p|+|s|)$。**在 $|w| \le 10$ 時完全可行；字串一長就要換方法。**

## 時間與空間複雜度

| 題目 | 時間 | 空間 | 備註 |
| --- | --- | --- | --- |
| 211 新增與搜尋單字 | 插入 $O(\lvert w\rvert)$；查詢最壞 $O(\Sigma^{d}\lvert w\rvert)$，$d$ 為 `.` 數 | $O(\Sigma L)$ | **按長度分桶可大幅剪枝** |
| 212 單字搜尋 II | $O(M N \cdot 3^{\ell})$，$\ell$ 為最長單字長 | $O(L)$ | 指數底是 3（不走回頭路）；剪枝 B 讓實測遠低於此 |
| 336 迴文對 | $O\!\left(\sum\lvert w\rvert + \sum \lvert w\rvert^{2}\right)$ | $O(\Sigma L)$ | 平方項來自迴文判斷，可用雜湊消去 |
| 425 單字方塊 | 指數級，實測受剪枝主導 | $O(L)$ | trie 把每步的候選枚舉降到輸出規模 |
| 745 前綴和後綴搜尋 | 建 $O(\sum\lvert w\rvert^{2})$，查 $O(\lvert p\rvert+\lvert s\rvert)$ | $O(\Sigma \sum\lvert w\rvert^{2})$ | 只適用短字串 |

**212 的 $3^{\ell}$ 從哪來**：網格 DFS 每格有 4 個鄰居，但其中一個是來路，故分支因子為 3。**這是上界，不是實際耗時**——實際耗時由「trie 中真正存在的路徑數」決定，而剪枝 B 讓這個數字隨搜尋進行單調下降。

**空間的實際風險**：745 的 $O(\Sigma \sum|w|^2)$ 在 $|w| \le 10$、$n \le 10^4$ 時是 $26 \times 10^6$ 個指標 ≈ 800 MB。**必須改用 `unordered_map` 存孩子。** 這種「複雜度式子看起來還好、乘出來爆炸」的情況在進階 trie 題裡很常見，**養成把數字代進去乘一遍的習慣。**

## 與相似技巧的比較

- **與 7.1**：判準是**查詢路徑是否唯一**。唯一 ⇒ 邊走邊判（7.1 定理 3 的「鏈」論證）；有分支 ⇒ DFS 子樹 + 剪枝（本節）。
- **與 AC 自動機**：212 那類「一段文字中找所有模式」的**正統**解法是 AC 自動機（trie + 失配指標 + BFS 建自動機），$O(|text| + \sum|pattern| + \text{命中數})$。**本節的 DFS + 剪枝只是在「文字是網格、必須回溯」時的替代品**——網格上沒有線性掃描的概念，失配指標派不上用場。**遇到一維文字的多模式匹配，用 AC 自動機。**
- **與字串雜湊**：336 的「判斷子串是否迴文」用雜湊是 $O(1)$；425 的「以某前綴開頭的字」用 `unordered_map<string, vector<int>>` 也能做，且好寫得多。**雜湊在「等值判斷」上勝過 trie，trie 在「共享前綴的批量推進與剪枝」上不可替代。** 425 若用雜湊表，就失去了「一次推進所有候選」的能力，但因為每步都要完整前綴，雜湊表其實夠用——**425 是 trie 與雜湊表都能做的題，選 trie 是為了節點上掛索引清單的便利。**
- **與 Manacher / 迴文自動機**：336 的瓶頸是「判斷 $O(|w|)$ 個切點的後綴是否迴文」。Manacher 預處理一次 $O(|w|)$ 可全部 $O(1)$ 回答。**trie 負責配對，Manacher 負責迴文判斷，兩者是正交的。**
- **與 bitset 交集**：745 若字串長不能容忍 $\sum|w|^2$，改成兩棵 trie（正插與反插），節點上掛 `bitset<n>`，查詢時取交集後找最高位。$O(n/64)$ 每次查詢。**這是「兩維度合成單鍵」失效時的標準退路。**
- **與 9.x 線段樹合併**：336 的 `palIdx`、745 的 `best`，本質上都是「在 trie 節點上聚合子樹資訊」。**當聚合的東西是可合併的集合（而非單一最大值）時，就會演變成線段樹合併或啟發式合併。**

## 本節重點速查

- **本節與 7.1 的分界：查詢路徑是否唯一。** 有分支就要 DFS 子樹，剪枝從優化變成必需。
- **211**：前緣集合不變量（定理 1）保證 DFS 不重不漏。**按單字長度分桶是最有效的一行剪枝。** 複雜度取 $\min(\Sigma^d|w|,\ |\text{節點數}|)$ 兩個上界。
- **212**：網格路徑與 trie 路徑**同步前進**（不變量 (S)）。兩個剪枝——**A：命中後把 `wordId` 設回 `-1`**（兼作去重）；**B：回溯時摘掉無孩子且無單字的節點**（每節點最多摘一次，攤還 $O(|\text{節點}|)$，是 TLE/AC 的分界）。等價寫法是維護子樹剩餘單字數 `cnt`。別忘了回溯還原網格標記。
- **336**：$A+B$ 迴文的完整分類——**$|A|\ge|B|$ ⇒ $A$ 的前 $|B|$ 位 $=\mathrm{rev}(B)$ 且 $A$ 的剩餘部分是迴文；$|A|<|B|$ ⇒ 對稱形式。** 必須兩種都處理，因為 trie 下走有方向。三個坑：空字串、$i=j$、$|A|=|B|$ 時的重複計數。
- **425**：對稱約束 ⇒ **第 $k$ 行的前 $k$ 個字元被前 $k$ 行的第 $k$ 列完全決定**（既必要又充分）。回溯 + trie 的關鍵永遠是找出這種「可繼續」條件。
- **745**：`後綴 + '{' + 完整字` 把兩個維度編碼成一個鍵。**前提是分隔符不在字元集內。** 空間會爆，用 `map` 孩子或改 bitset 交集。
- **一維文字的多模式匹配用 AC 自動機，不要用本節的 DFS 剪枝**——後者是為了網格回溯才存在的。
- **複雜度式子要把數字代進去乘一遍**，進階 trie 題的空間爆炸通常不在式子的形狀上，在常數 $\Sigma$ 上。
