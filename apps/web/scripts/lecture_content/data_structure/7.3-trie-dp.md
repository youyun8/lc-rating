## 這個技術解決什麼問題

有一類 DP，狀態是「字串的前綴」，轉移是「切下一段合法單字」：

$$f(i) \leftarrow \bigoplus_{\substack{j < i \\ s[j..i) \in \mathrm{dict}}} g\big(f(j)\big)$$

（$\oplus$ 依題目是「或」（139 可行性）、「加」（計數）、「取最小」（面試題 17.13）、「收集」（140 列舉）。）

**DP 本身完全沒有難度，難的是枚舉轉移。** 樸素做法對每個 $(j, i)$ 都去字典裡查 $s[j..i)$：

- 用 `unordered_set<string>`：$O(n^2)$ 個子串，每個要構造 + 雜湊，$O(n^2 \cdot \bar{\ell})$；
- 逐一比對字典：$O(n \cdot |\mathrm{dict}| \cdot \bar{\ell})$。

**trie 的作用只有一個：把「從位置 $j$ 出發，有哪些 $i$ 使 $s[j..i)$ 是字典單字」這件事，從『每個 $i$ 各查一次』變成『沿字串走一趟，順路報告所有命中』。** 走的長度自然被字典中最長單字的長度 $\ell_{\max}$ 截斷，而且一旦走進不存在的孩子就立刻停止——**這個「提前終止」在實測中比複雜度式子顯示的還有效。**

**先講清楚 trie 在這裡的定位：它不改變 DP 的狀態、不改變轉移的語意、不改變答案。它只是一個枚舉器。** 想不清楚 DP 就先別碰 trie；DP 想清楚了，trie 只是替換掉迴圈裡的那一句判斷。

典型題：139 單字拆分（可行性）、140 單字拆分 II（列舉全部方案）、472 連接詞（每個字各做一次 139）、面試題 17.13 恢復空格（最小化未識別字元數）、2977 字串轉換的最小成本 II（轉移帶成本，且要先做 Floyd 閉包）。

## 狀態／資料結構定義

**DP 狀態**（以 $s$ 的長度 $n$ 為界，全部是一維前綴狀態）：

| 題目 | 狀態 | 初值 | 轉移 | 答案 |
| --- | --- | --- | --- | --- |
| 139 | `f[i]`：`s[0..i)` 可否完全拆分 | `f[0] = true` | 或 | `f[n]` |
| 140 | `g[j]`：`s[j..n)` 的所有拆分方案 | `g[n] = {""}` | 收集 | `g[0]` |
| 472 | 對每個字各跑一次 139 | 同上 | 或 | 逐字判定 |
| 17.13 | `f[i]`：`s[0..i)` 最少未識別字元數 | `f[0] = 0` | 取 min | `f[n]` |
| 2977 | `f[i]`：改造 `s[0..i)` 的最小成本 | `f[0] = 0` | 取 min | `f[n]` |

**trie 結構**（7.1 的寫法 A 即可，但要注意方向）：

```cpp
struct Node {
    Node* ch[26]{};
    bool isEnd = false;  // 139/140/472
    int id = -1;         // 17.13 需要單字長度；2977 需要單字編號
};
```

**方向的選擇是本節唯一的結構性決策**（見定理 2）：

- **正向 trie（單字照原樣插入）**：搭配**刷表法**——外層 $j$ 從小到大，若 `f[j]` 有效，就從 $j$ 沿 trie 往右走，命中就更新 `f[i]`。
- **反向 trie（單字反轉後插入）**：搭配**填表法**——外層 $i$ 從小到大，從 $i-1$ 往左走，命中就用 `f[j]` 更新 `f[i]`。

**17.13 用反向 trie 更順**，因為它的轉移還有一項 `f[i] = f[i-1] + 1`（把第 $i-1$ 個字元丟棄），填表法能把兩項寫在一起。**139/140 用正向 trie 更順。**

**140 的 `g` 存的是「後綴的所有拆分」而不是「前綴的」**——因為要拼句子時前面的詞先出現，用後綴狀態遞迴時字串拼接方向自然。**記憶化用 `unordered_map<int, vector<string>>` 或 `vector<vector<string>>` 皆可。**

## 不變量或正確性證明

### 定理 1（trie 走訪恰好枚舉出所有轉移）

**命題**：從位置 $j$ 出發，令 $u_0 = \text{root}$，$u_{t+1} = u_t\text{.ch}[s[j+t]]$（缺孩子則停止）。則

$$\{\, i > j : s[j..i) \in \mathrm{dict} \,\} \;=\; \{\, j+t : u_t \text{ 存在且 } u_t.\texttt{isEnd} \,\}$$

且走訪按 $t$ 遞增，**即按 $i$ 遞增的順序報告命中**。

*證明*。由 7.1 的不變量 (T)，$u_t$ 存在 $\iff$ $s[j..j{+}t)$ 是某個字典單字的前綴；由 7.1 定理 2，$u_t.\texttt{isEnd}$ $\iff$ $s[j..j{+}t) \in \mathrm{dict}$。兩者合起來即得等式。順序由迴圈變數 $t$ 遞增給出。$\square$

**兩個推論，都是效率的來源：**

> **推論 1.1（提前終止是安全的）**：$u_t$ 不存在時可立即 `break`。因為 $s[j..j{+}t)$ 已不是任何字典單字的前綴，由前綴的傳遞性，$s[j..j{+}t')$（$t' > t$）也不是任何字典單字的前綴，更不可能是字典單字。

> **推論 1.2（走訪長度 $\le \ell_{\max}$）**：trie 的深度不超過最長單字長度，故 $t \le \ell_{\max}$。

**推論 1.1 才是重點。** 複雜度式子只保證 $O(n\ell_{\max})$，但實際上大多數位置走幾步就撞牆——**字典越「不像」目標字串，trie 越快，而暴力法對此毫無感覺。**

### 定理 2（方向決定寫法：正向 trie 必須刷表，填表必須反向 trie）

**命題**：trie 的走訪只能沿字串**遞增**方向進行（因為邊是「下一個字元」）。因此：

- 用**正向 trie**（單字照原樣插入），從 $j$ 出發只能發現「以 $j$ 為**左**端點」的合法段，所以必須寫成**刷表法**：`for j: if (f[j]) for i in trie_walk(j): update f[i]`。
- 要寫**填表法**（`for i: f[i] = combine over j`），就得從 $i$ 往**左**枚舉左端點，也就是要能「從右端點出發匹配」——這需要把單字**反轉後**插入，並沿 $s$ 反向讀取字元。

*證明*：trie 的節點對應「從根沿邊讀出的字串」，走一步就消耗字串的下一個字元。要匹配 $s[j..i)$，起點必須是 $j$（正向）或 $i-1$ 往左（若 trie 中存的是反轉單字，則沿 $s[i-1], s[i-2], \dots$ 走恰好匹配 $\mathrm{rev}(s[j..i))$，而 $\mathrm{rev}(s[j..i)) \in \mathrm{rev}(\mathrm{dict}) \iff s[j..i) \in \mathrm{dict}$）✔。$\square$

**這條看似瑣碎，但它是本節最常見的實作錯誤源頭**：拿正向 trie 卻想寫填表法，於是寫成「對每個 $i$，對每個 $j$，從 $j$ 走到 $i$」——複雜度退回 $O(n^2)$，trie 白建了。**寫之前先決定刷表還是填表，再決定 trie 的方向。**

*另一個等價視角*：刷表法的 `f[j]` 在被使用時必須已經最終確定。因為轉移只從 $j$ 到 $i > j$（**單向、無環**），按 $j$ 遞增處理即可——**這就是無後效性在這裡的具體形式。**

### 定理 3（139 的正確性：最優子結構與無後效性）

**命題**：`f[i] = true` $\iff$ $s[0..i)$ 可以拆成若干個字典單字。

*證明*（對 $i$ 強歸納）。
- **$i=0$**：空串拆成零個單字，`f[0] = true` ✔。
- **($\Leftarrow$)** 設 $s[0..i)$ 有一個合法拆分，其**最後一段**為 $s[j..i)$，則 $s[j..i) \in \mathrm{dict}$ 且 $s[0..j)$ 有合法拆分。由歸納假設 `f[j] = true`；由定理 1，走訪從 $j$ 出發時會報告 $i$；故 `f[i]` 被設為 `true` ✔。
- **($\Rightarrow$)** 設 `f[i]` 被設為 `true`，則存在 $j$ 使 `f[j] = true` 且 $s[j..i) \in \mathrm{dict}$。由歸納假設 $s[0..j)$ 有合法拆分，接上 $s[j..i)$ 即得 $s[0..i)$ 的合法拆分 ✔。$\square$

**這個證明依賴兩件事，兩件事都值得點名**：

1. **「最後一段」的存在性與唯一枚舉**：任何非空拆分都有唯一的最後一段，且它的左端點 $j$ 在 $[0, i)$ 中——**枚舉 $j$ 就窮盡了所有拆分**。這是所有「線性劃分 DP」的共同骨架。
2. **無後效性**：$s[0..j)$ 能否拆分，**與 $s[j..i)$ 怎麼切、與 $i$ 之後是什麼，完全無關**。所以 `f[j]` 可以先算好、算一次、重複使用。**若題目加上「相鄰兩段不能是同一個單字」之類的約束，這條就破了，狀態必須擴充**——這是判斷「能不能直接套本節模板」的檢查點。

### 定理 4（140 的複雜度本質上是輸出敏感的，記憶化不能改變這一點）

**命題**：140 的答案數量最壞是 $\Theta(2^{n/2})$，因此任何列舉全部方案的演算法在最壞情況下都是指數級。**記憶化能消除「重複探索」，但不能消除「輸出本身很大」。**

*下界構造*：$s = \texttt{"aaaa...a"}$（$n$ 個 `a`），$\mathrm{dict} = \{\texttt{"a"}, \texttt{"aa"}\}$。拆分數 $=$ 用 1 和 2 組成 $n$ 的方法數 $= F_{n+1}$（費氏數），即 $\Theta(\varphi^{n})$ ✔。

*記憶化後的成本*：設 `g[j]` 為 $s[j..n)$ 的方案列表。則
$$\text{總成本} = O\!\big(n\,\ell_{\max}\big) \;+\; \sum_{j} \big|\,\texttt{g}[j]\,\big| \cdot O(\text{單句長度})$$
第一項是 trie 走訪，第二項是**輸出的總體積**。**記憶化把第一項從指數壓成多項式，第二項不可能壓縮**（你必須把答案寫出來）。$\square$

**未記憶化的版本更糟**：$s = \texttt{"aaa...ab"}$、$\mathrm{dict} = \{\texttt{"a"},\texttt{"aa"}\}$，**答案是空的**，但樸素 DFS 會探索 $\Theta(\varphi^n)$ 條路徑才發現每條都在末尾失敗。**這是 140 的經典 TLE 測資。** 記憶化（`g[j]` 記為空列表）立刻把它變成 $O(n\ell_{\max})$。

**實務建議**：先跑一次 139 的 `f` 陣列，DFS 時檢查 `f[j]`——**這對「有解」的情形沒幫助（成本仍是輸出量），對「部分位置無解」的情形則能砍掉大量分支。** 這是一個「不改變最壞複雜度、但顯著改善實際表現」的剪枝，值得寫。

### 定理 5（472 連接詞：按長度遞增處理的正確性）

*定義*：連接詞 = 完全由字典中**至少兩個**較短單字串接而成的字。

**命題**：把字典按長度**非遞減**排序後依序處理；處理單字 $w$ 時，trie 中只插入了所有長度**嚴格小於** $|w|$ 的單字。此時對 $w$ 跑 139，結果正確。

*證明*。
- **每個組成部分嚴格更短**：$w$ 由 $k \ge 2$ 個非空單字串接而成，每個部分的長度 $\le |w| - 1 < |w|$（因為其他部分至少佔 1 個字元）✔。**這裡用到「字典中無空字串」——這正是為什麼必須特判空字串。**
- 故所有可能的組成部分都在「長度 $< |w|$」的集合中，而該集合已完整插入 trie ✔。
- 反之，trie 中的每個字都是字典單字，故找到的拆分都合法 ✔。$\square$

**兩個實作細節，都由證明直接讀出**：

1. **必須先把所有長度 $< |w|$ 的字插完，才處理 $w$**。同長度的字之間互不影響（長度 $L$ 的字無法由若干長度 $L$ 的字串接而成，因為那至少要 $2L > L$），所以「同長度批次插入」與「逐一插入」都可以，**但絕不能把 $w$ 自己先插進去再判它**——那樣每個字都會被判成「由自己一段組成」。
2. **必須要求 $k \ge 2$**。實作上就是：跑 139 時，`f[0] = true`，但**不允許整段 $w$ 直接命中**——由第 1 點，$w$ 尚未插入 trie，所以這自動成立。**這是「先排序後插入」這個設計最漂亮的地方：$k\ge2$ 的約束被結構本身保證了，不需要額外判斷。**

### 定理 6（面試題 17.13：加入「丟棄字元」轉移後仍保持最優子結構）

$$f(i) = \min\Big(\underbrace{f(i-1) + 1}_{\text{丟棄 } s[i-1]},\ \min_{\substack{j<i,\ s[j..i)\in\mathrm{dict}}} f(j)\Big),\qquad f(0)=0.$$

*正確性*：任何一種「標記方式」（把 $s$ 的某些不相交子串標記為字典單字，其餘字元算未識別）都可以按**最後一個字元**分類：它要嘛屬於某個被標記的單字（則該單字為 $s[j..i)$，剩下的是 $s[0..j)$ 的子問題），要嘛未被識別（剩下的是 $s[0..i-1)$ 的子問題）。**兩類互斥且窮盡**，故遞推式正確 ✔。

*無後效性*：$f(j)$ 的值不依賴 $j$ 之後如何標記——**因為「未識別字元數」是可加的，且標記區間不相交。** 若題目改成「未識別字元必須連續」或「相鄰單字不能重複」，可加性就破了。$\square$

**這題用反向 trie**：外層 $i$ 遞增，內層從 $s[i-1]$ 往左走，命中深度 $d$ 時得到 $j = i-d$。**兩項轉移都在同一個 $i$ 的迴圈裡，程式最短。**

## C++17 模板

**模板一：139 單字拆分（正向 trie + 刷表法）**

```cpp
class Solution {
    struct Node {
        Node* ch[26]{};
        bool isEnd = false;
    };

public:
    bool wordBreak(string s, vector<string>& wordDict) {
        Node* root = new Node();
        for (const string& w : wordDict) {
            Node* u = root;
            for (char c : w) {
                int k = c - 'a';
                if (!u->ch[k]) u->ch[k] = new Node();
                u = u->ch[k];
            }
            u->isEnd = true;
        }
        int n = s.size();
        vector<char> f(n + 1, false);
        f[0] = true;
        for (int j = 0; j < n; ++j) {
            if (!f[j]) continue;  // 刷表法：只從可達狀態出發
            Node* u = root;
            for (int i = j; i < n; ++i) {
                int k = s[i] - 'a';
                if (!u->ch[k]) break;  // 推論 1.1：提前終止
                u = u->ch[k];
                if (u->isEnd) f[i + 1] = true;  // s[j..i] 是單字
            }
        }
        return f[n];
    }
};
```

**模板二：472 連接詞（按長度排序 + 增量插入）**

```cpp
class Solution {
    struct Node {
        Node* ch[26]{};
        bool isEnd = false;
    };
    Node* root = new Node();

    void insert(const string& w) {
        Node* u = root;
        for (char c : w) {
            int k = c - 'a';
            if (!u->ch[k]) u->ch[k] = new Node();
            u = u->ch[k];
        }
        u->isEnd = true;
    }
    bool splittable(const string& s) {  // 就是模板一的 wordBreak
        int n = s.size();
        vector<char> f(n + 1, false);
        f[0] = true;
        for (int j = 0; j < n; ++j) {
            if (!f[j]) continue;
            Node* u = root;
            for (int i = j; i < n; ++i) {
                int k = s[i] - 'a';
                if (!u->ch[k]) break;
                u = u->ch[k];
                if (u->isEnd) f[i + 1] = true;
            }
        }
        return f[n];
    }

public:
    vector<string> findAllConcatenatedWordsInADict(vector<string>& words) {
        sort(words.begin(), words.end(), [](const string& a, const string& b) {
            return a.size() < b.size();
        });
        vector<string> ans;
        for (const string& w : words) {
            if (w.empty()) continue;  // 空字串必須跳過（定理 5）
            if (splittable(w)) ans.push_back(w);  // 此時 trie 只含更短的字
            insert(w);                            // 判完才插入自己
        }
        return ans;
    }
};
```

**模板三：面試題 17.13 恢復空格（反向 trie + 填表法）**

```cpp
class Solution {
    struct Node {
        Node* ch[26]{};
        bool isEnd = false;
    };

public:
    int respace(vector<string>& dictionary, string sentence) {
        Node* root = new Node();
        for (const string& w : dictionary) {
            Node* u = root;
            for (int t = w.size() - 1; t >= 0; --t) {  // 反轉插入
                int k = w[t] - 'a';
                if (!u->ch[k]) u->ch[k] = new Node();
                u = u->ch[k];
            }
            u->isEnd = true;
        }
        int n = sentence.size();
        vector<int> f(n + 1, 0);
        for (int i = 1; i <= n; ++i) {
            f[i] = f[i - 1] + 1;  // 丟棄 s[i-1]
            Node* u = root;
            for (int j = i - 1; j >= 0; --j) {  // 從右端點往左走
                int k = sentence[j] - 'a';
                if (!u->ch[k]) break;
                u = u->ch[k];
                if (u->isEnd) f[i] = min(f[i], f[j]);  // s[j..i) 是單字
            }
        }
        return f[n];
    }
};
```

**模板四：140 單字拆分 II（記憶化 + 可行性前置剪枝）**

```cpp
class Solution {
    unordered_map<int, vector<string>> memo;
    vector<char> feasible;  // 先跑一次 139
public:
    vector<string> wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> dict(wordDict.begin(), wordDict.end());
        int n = s.size(), maxLen = 0;
        for (const string& w : wordDict) maxLen = max(maxLen, (int)w.size());
        feasible.assign(n + 1, false);
        feasible[n] = true;
        for (int j = n - 1; j >= 0; --j)
            for (int L = 1; L <= maxLen && j + L <= n; ++L)
                if (feasible[j + L] && dict.count(s.substr(j, L))) {
                    feasible[j] = true;
                    break;
                }
        return dfs(s, 0, dict, maxLen);
    }

private:
    vector<string> dfs(const string& s, int j,
                       const unordered_set<string>& dict, int maxLen) {
        if (j == (int)s.size()) return {""};
        auto it = memo.find(j);
        if (it != memo.end()) return it->second;
        vector<string> res;
        for (int L = 1; L <= maxLen && j + L <= (int)s.size(); ++L) {
            if (!feasible[j + L]) continue;  // 剪枝：右邊拆不完就別遞迴
            string w = s.substr(j, L);
            if (!dict.count(w)) continue;
            for (const string& rest : dfs(s, j + L, dict, maxLen))
                res.push_back(rest.empty() ? w : w + " " + rest);
        }
        return memo[j] = res;
    }
};
```

（140 的字典很小時用 `unordered_set` 比 trie 更短；**若字典大到雜湊成為瓶頸，把內層換成模板一的 trie 走訪即可，DP 結構不變**——這正是定理 1 所說的「trie 只是枚舉器」。）

## 時間與空間複雜度

設 $n = |s|$、$m = |\mathrm{dict}|$、$\ell_{\max}$ 為最長單字長、$L = \sum_{w}|w|$。

| 題目 | 樸素 | trie 版 | 空間 |
| --- | --- | --- | --- |
| 139 | $O(n^{2}\ell_{\max})$（`substr` + 雜湊） | $O(n\,\ell_{\max} + L)$ | $O(n + \Sigma L)$ |
| 472 | $O(m\,\bar{\ell}^{2}\,\ell_{\max})$ | $O\!\left(\sum_w |w|\,\ell_{\max} + L\right)$ | $O(\Sigma L)$ |
| 17.13 | $O(n^{2}\ell_{\max})$ | $O(n\,\ell_{\max} + L)$ | $O(n + \Sigma L)$ |
| 140 | 指數（無記憶化） | $O(n\,\ell_{\max} + \lvert\text{輸出}\rvert)$ | $O(\lvert\text{輸出}\rvert)$ |
| 2977 | — | $O\!\left(m^{3} + n\cdot\text{命中數}\right)$ | $O(\Sigma L + m^{2})$ |

**$O(n\ell_{\max})$ 這個式子要理解，不要背**：外層 $n$ 個起點，每個起點沿 trie 最多走 $\ell_{\max}$ 步（推論 1.2），每步 $O(1)$。**跟字典大小 $m$ 無關**——這是 trie 相對於「逐一比對」的全部收益。

**與 `unordered_set` + `substr` 的真實差距**：後者是 $O(n\ell_{\max})$ 次 `substr`（每次配置一個 `string`，$O(\ell)$ 拷貝 + 可能的堆配置）加上雜湊計算。**式子上都是 $O(n\ell_{\max}^{?})$ 級別，但常數差 5～20 倍**，且 trie 有提前終止。$n = 300$、$\ell_{\max} = 20$ 的 139 兩者都能過；$n \ge 10^4$ 就必須用 trie。

**2977 的 $m^3$** 來自 Floyd：轉換成本要先在「原字串 ↔ 目標字串」的有向圖上求傳遞閉包的最短路，**因為一次替換的結果可以再被替換**。這一步與 trie 無關，但是這題的正確性關鍵——**沒做閉包會漏掉多步替換的更便宜路徑。** 枚舉命中則用 AC 自動機（7.2）比純 trie 更省。

## 常見錯誤與邊界條件

- **拿正向 trie 卻寫填表法**（定理 2）。症狀是「對每個 $i$，對每個 $j$，重新從 $j$ 走一遍」，複雜度退回 $O(n^2\ell_{\max})$，trie 完全白建。**先決定刷表／填表，再決定 trie 方向。**
- **刷表法忘記 `if (!f[j]) continue;`**。不僅慢，在 140 那種「收集方案」的變體裡會直接產生錯誤答案（從不可達的狀態刷出方案）。
- **`u->isEnd` 檢查的位置**。必須在**移動到孩子之後**檢查，而不是移動之前——否則會把根（空字串）誤判為單字，造成 `f[j] → f[j]` 的自環。
- **472 忘記跳過空字串**。輸入含 `""` 時，`splittable("")` 回傳 `f[0] = true`，空字串被誤判為連接詞。**定理 5 的證明明確用到「無空字串」這個前提。**
- **472 先插入自己再判定**。每個字都會被判成連接詞。**順序必須是「判定 → 插入」。**
- **472 用字典序排序而非長度排序**。`sort(words.begin(), words.end())` 是字典序，`"aa"` 會排在 `"b"` 前面但 `"b"` 更短——**長度順序才是定理 5 需要的。**
- **140 沒有記憶化**。`"aaa...ab"` 直接 TLE（定理 4）。
- **140 的空字串拼接**。`g[n] = {""}` 是哨兵，回傳時要寫 `rest.empty() ? w : w + " " + rest`，否則句尾會多一個空格。
- **17.13 忘記 `f[i] = f[i-1] + 1` 這一項**。只寫字典命中的轉移，會讓「沒有任何單字結尾於 $i$」的位置停在初值 $+\infty$。
- **字元集假設**。模板都假設小寫字母。**題目若含大寫或數字，`ch[26]` 會越界**——這是 UB，可能表現為隨機錯誤答案而非崩潰。
- **`new` 出來的節點沒回收**。LeetCode 上不影響判題，但**在多測資的本地測試或「設計題反覆建樹」時會累積成 MLE**。用 `vector<Node>` 池或 `deque<Node>` 配置更安全（注意 `vector` 擴容會使指標失效，池要 `reserve` 或改存索引）。
- **狀態擴充的信號**。題目若加上「相鄰兩段不能相同」「總段數不超過 $k$」「每個單字最多用一次」，定理 3 的無後效性就破了——**必須把違反可加性的那個量加進狀態**，本節的一維模板不再適用。

## 與相似技巧的比較

- **與 `unordered_set` + `substr`**：語意完全等價（定理 1 說明兩者枚舉的是同一個集合）。**字典小、$n$ 小 ⇒ 用 set，程式短；$n$ 大或字典總長大 ⇒ 用 trie。** 決定因素是常數與提前終止，不是漸近複雜度。
- **與字串雜湊（滾動雜湊）**：可以 $O(1)$ 取任意子串的雜湊值，把 139 做到 $O(n\ell_{\max})$ 且常數極小。**缺點是有碰撞風險，且不支援「提前終止」**——雜湊必須算完整個子串才知道不在字典裡，trie 走兩步就能放棄。
- **與 AC 自動機**：AC 自動機能在 $O(n + \text{命中數})$ 內找出「$s$ 中所有字典單字的所有出現位置」，**比本節的 $O(n\ell_{\max})$ 更優**。代價是建自動機（BFS 求 fail 指標）與程式長度。**$\ell_{\max}$ 很大（例如 $10^3$）而 $n$ 也大時，AC 自動機是唯一選擇；2977 就是這種規模。** $\ell_{\max}$ 小（$\le 20$）時 trie 完全夠用。
- **與 7.1／7.2**：7.1 是查詢單一字串，7.2 是查詢帶分支。**本節的走訪其實就是 7.1 的形態（路徑唯一），只是重複執行 $n$ 次、且中途每個 `isEnd` 都要用**——差別在「沿路收集所有命中」而非「走到底才回答」。
- **與區間 DP**：本節是**線性劃分 DP**（狀態是前綴，轉移枚舉最後一段），$O(n)$ 狀態、$O(\ell_{\max})$ 轉移。**若合法段的定義依賴段內的其他資訊（例如「這一段本身要是迴文」），就變成 132 分割迴文串 II 那類題**——結構相同，只是把 trie 換成迴文預處理表。**「把『某段是否合法』的判斷抽出來單獨加速」是這一整族題的統一思路。**
- **與 KMP / Z 函數**：那些解決的是「單一模式在文字中的出現」，本節是「多個模式」。**單模式用 KMP，多模式用 trie 或 AC 自動機。**

## 本節重點速查

- **trie 在 DP 裡只是枚舉器**：它不改變狀態、不改變轉移語意、不改變答案。**DP 想不清楚就別碰 trie。**
- **核心命題（定理 1）**：從 $j$ 沿 trie 走，恰好按 $i$ 遞增報告所有使 $s[j..i)\in\mathrm{dict}$ 的 $i$。兩個推論：**撞牆立刻 `break` 是安全的**（前綴傳遞性）、**走訪長度 $\le \ell_{\max}$**。
- **方向決定寫法（定理 2）**：**正向 trie ⇒ 刷表法**（`for j: if(f[j]) walk`）；**填表法 ⇒ 反向 trie**（單字反轉插入，從 $i-1$ 往左走）。搞混就退回 $O(n^2)$。
- **139 的兩個前提**：最後一段的枚舉窮盡所有拆分；**未識別／已識別的量可加 ⇒ 無後效性**。題目加上「相鄰段不同」之類的約束就要擴充狀態。
- **140 是輸出敏感的**：答案數可達 $\Theta(\varphi^n)$，記憶化只能消除重複探索，不能壓縮輸出。**`"aaa...ab"` 是經典 TLE 測資**；先跑 139 的可行性表做剪枝。
- **472 的三個順序性要求**：**按長度非遞減排序**（不是字典序）、**判定完才插入自己**、**跳過空字串**。$k\ge2$ 的約束由「尚未插入自己」自動保證，不需額外判斷。
- **17.13 別漏掉 `f[i] = f[i-1] + 1`** 這一項。
- **複雜度是 $O(n\ell_{\max} + L)$，與字典大小 $m$ 無關**——這是全部收益所在。
- **$\ell_{\max}$ 大到不能接受時換 AC 自動機**（$O(n + \text{命中數})$）；字典小、$n$ 小時 `unordered_set` 就夠。
- **`ch[26]` 假設小寫字母**，題目字元集不同時會越界成 UB。
