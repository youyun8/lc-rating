## 這個技術解決什麼問題

有一組元素，不斷地宣告「這兩個是同一類」，中間穿插「這兩個現在是不是同一類？」「現在有幾類？」的查詢。

暴力有兩條路，兩條都不行：

- **每次查詢跑一次 BFS/DFS**：單次 $O(n+m)$，查詢多就爆炸。
- **每類存一個集合，合併時把小的搬進大的**：查詢 $O(1)$，但合併要搬元素，樸素實作最壞 $O(n)$ 一次。

**核心想法**：*不要維護「集合裡有誰」，只維護「每個元素的頂頭上司是誰」。* 每一類選一個代表元，每個元素存一個 `parent` 指向同類的另一個元素，順著 `parent` 一路往上必定走到代表元。於是：

- 「$x$ 與 $y$ 同類？」= 「兩者的代表元相同？」
- 「把 $x$ 與 $y$ 併起來」= 「把其中一個代表元的 `parent` 指向另一個」——**只動一個指標。**

代價是「找代表元」要沿鏈往上爬。**並查集的全部技術含量，就在兩個讓這條鏈不變長的技巧**：**路徑壓縮**（爬完之後把沿路節點直接掛到根上）與**按秩／按大小合併**（永遠讓矮的掛到高的下面）。兩者合用後單次操作是攤還 $O(\alpha(n))$，$\alpha$ 是反 Ackermann 函數，在任何現實規模下 $\le 4$——**實務上就當常數。**

**適用的硬前提：關係只增不減。** 並查集能高效合併，但**不能拆分**——`parent` 指標一旦指出去，就沒有資訊可以還原「這個子樹原本屬於誰」。看到題目要刪邊、刪點，本節的工具直接失效，要走 8.2 的離線倒序，或改用不壓縮路徑的可撤銷並查集。

**辨識訊號**：出現「連通塊個數」「是否屬於同一組」「合併帳號／朋友圈」「等價、同義、同類」這些字眼，而且**沒有刪除操作**。

## 狀態／資料結構定義

```cpp
struct DSU {
    vector<int> fa, sz;
    int comp;  // 目前的連通塊個數

    explicit DSU(int n) : fa(n), sz(n, 1), comp(n) {
        iota(fa.begin(), fa.end(), 0);  // 初始每個元素自成一類
    }
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];  // 路徑減半（迭代版壓縮）
            x = fa[x];
        }
        return x;
    }
    bool unite(int x, int y) {  // 回傳「這次合併是否真的發生」
        x = find(x);
        y = find(y);
        if (x == y) return false;
        if (sz[x] < sz[y]) swap(x, y);
        fa[y] = x;
        sz[x] += sz[y];
        --comp;
        return true;
    }
    bool same(int x, int y) { return find(x) == find(y); }
};
```

**三個欄位的語意**：

| 欄位 | 語意 | 有效性 |
| --- | --- | --- |
| `fa[x]` | $x$ 的父節點；`fa[x] == x` 表示 $x$ 是代表元 | 對所有 $x$ |
| `sz[x]` | 以 $x$ 為根的整棵樹的節點數 | **只有 $x$ 是根時才有意義** |
| `comp` | 連通塊個數 | 全域 |

**`sz` 只在根上有效，是最常被誤用的地方。** 想查「$x$ 所在的組有多大」，必須寫 `sz[find(x)]`，不能寫 `sz[x]`。同理，任何掛在「集合」上的資訊（組內和、組內最大值、組內某個標記）都只在根上維護，讀取前先 `find`。

**`unite` 回傳 `bool` 的價值**：`false` 表示兩者本來就同類。**684 的答案、Kruskal 的「這條邊是否入選」、「這條邊是否構成環」全部靠這個回傳值**，不要寫成 `void`。

**元素不是整數時**：先用 `unordered_map<string,int>` 把字串／座標／pair 映射成 $0..n-1$ 的整數（721 帳號合併、990 等式方程都要這一步）。**二維網格用 $r \times C + c$ 攤平，不要用 `map<pair<int,int>,int>`——慢 10 倍以上。**

**`iota` 初始化不能忘。** 忘了初始化 `fa`（全為 0）會讓所有元素一開始就在同一類，症狀是「答案永遠是 1」。

## 不變量或正確性證明

### 定理 1（森林不變量：`fa` 恆為森林，且每棵樹恰為一個等價類）

設已處理的合併請求為 $E = \{(x_1,y_1),\dots,(x_k,y_k)\}$，令 $\sim_E$ 為由 $E$ 生成的最小等價關係（自反、對稱、遞移閉包）。

**不變量 (U)**：
1. 有向圖 $\{x \to \texttt{fa}[x] : \texttt{fa}[x] \ne x\}$ **無環**，故構成一片森林，每棵樹有唯一的根（`fa[r] == r`）；
2. 每棵樹的節點集合，**恰好**是 $\sim_E$ 的一個等價類。

*證明*（對操作次數歸納）。

- **基底**：初始 `fa[x] == x` 對所有 $x$，森林由 $n$ 棵單點樹組成；$\sim_\emptyset$ 的等價類就是 $n$ 個單元素集 ✔。

- **`find` 不改變 (U)**：路徑壓縮把 $x$ 的 `fa` 改成 $x$ 的某個**祖先**（`fa[fa[x]]` 或根）。
  - *無環*：新的父節點仍是原樹中 $x$ 的祖先，$x$ 到根的路徑仍存在且變短，不可能產生指向後代的邊 ✔。
  - *節點集合不變*：壓縮只在**同一棵樹內部**改指標，沒有節點換樹 ✔。
  - *根不變*：$x$ 到根的路徑仍終止於同一個根 ✔。

- **`unite(x,y)` 維持 (U)**：設 $r_x = \texttt{find}(x)$、$r_y = \texttt{find}(y)$。
  - $r_x = r_y$：什麼都不做。而此時 $x \sim_E y$ 已成立，加入 $(x,y)$ 不改變 $\sim_E$ ✔。
  - $r_x \ne r_y$：令 `fa[r_y] = r_x`。因為 $r_y$ 原本是根（無出邊），新增這條邊不可能形成環（兩棵樹原本不相交）✔。合併後的節點集 = 兩棵樹節點集的聯集 = 兩個等價類的聯集，這正是加入 $(x,y)$ 後 $\sim_{E \cup \{(x,y)\}}$ 的等價類 ✔。$\square$

**(U) 的第 2 條就是並查集的全部正確性**：`same(x,y)` 回傳 `find(x) == find(y)`，由 (U) 這等價於「$x$ 與 $y$ 在同一棵樹」，等價於 $x \sim_E y$。

**注意證明中「路徑壓縮把父指標改成祖先」這個前提被用了兩次**（無環、根不變）。**任何「把父指標指向非祖先節點」的優化都是錯的**——這聽起來理所當然，但在寫帶權並查集（8.6）時很容易在壓縮時算錯權值，效果等同於把節點掛到了錯誤的地方。

### 定理 2（按大小合併 ⇒ 樹高 $\le \lfloor \log_2 n\rfloor$）

**引理**：只用按大小合併（不壓縮路徑）時，高度為 $h$ 的樹至少有 $2^h$ 個節點。

*證明*（對合併次數歸納）。單點樹 $h=0$、$1 = 2^0$ 個節點 ✔。設把樹 $T_2$（高 $h_2$、$s_2$ 個節點）掛到 $T_1$（高 $h_1$、$s_1$ 個節點）下，且 $s_1 \ge s_2$。新樹高 $h = \max(h_1,\ h_2+1)$，節點數 $s = s_1+s_2$。
- 若 $h = h_1$：$s \ge s_1 \ge 2^{h_1} = 2^h$ ✔。
- 若 $h = h_2+1$：$s = s_1+s_2 \ge 2s_2 \ge 2\cdot 2^{h_2} = 2^{h}$ ✔（用到 $s_1 \ge s_2$，這正是「按大小」）。$\square$

**推論**：$2^h \le n \Rightarrow h \le \log_2 n$。故單次 `find` 最壞 $O(\log n)$。

**同樣的論證換個角度，得到更好用的形式：**

> **定理 2'（節點深度只會增加 $\log_2 n$ 次）**：固定一個節點 $v$。$v$ 的深度只在「$v$ 所在的樹被掛到另一棵樹下」時增加 1，而此時 $v$ 所在連通塊的大小**至少翻倍**（因為被掛的是較小的那棵）。連通塊大小從 1 出發、上限為 $n$，故最多翻倍 $\log_2 n$ 次 ✔。

**定理 2' 是「按大小合併」最漂亮的說法**，而且它是一個**勢能／攤還式**的論證：不去追蹤樹的形狀，只追蹤一個單調遞增且有上界的量（連通塊大小），用它的變化次數來限制代價。**這個套路在 4.7（單調堆疊）與 6.6（懶刪除堆）都出現過，值得抽象記住：找一個單調變化、有界的量，用它的變化總量來限制操作總量。**

**按秩合併（rank = 樹高的上界）的引理與證明形式相同**，只是把「大小」換成「秩」：秩為 $r$ 的樹至少有 $2^r$ 個節點。**兩者效果等價，按大小的好處是 `sz` 順便能回答「這組多大」，所以本節模板用大小。**

### 定理 3（路徑壓縮為什麼有效：父節點的秩嚴格遞增）

**引理**：在只用路徑壓縮（配合按秩合併）的並查集中，沿任何一條 `fa` 鏈往上走，**節點的秩嚴格遞增**。

*證明*：合併時只把根掛到秩不小於它的根下，且相等時被掛者的秩不變、掛上者的秩 $+1$——兩種情形都保證「父的秩 $>$ 子的秩」。路徑壓縮把節點掛到更高的祖先，由遞移性其秩更大 ✔。$\square$

**這個引理是複雜度分析的核心**：它說明一條長度為 $\ell$ 的路徑上有 $\ell$ 個嚴格遞增的秩。而路徑壓縮把整條路徑上的節點**全部**接到根上，**每個被壓縮的節點，其父節點的秩至少跳到根的秩**——也就是說，一次 $O(\ell)$ 的代價換來了 $\ell-1$ 個節點的「父秩大幅提升」，而每個節點的父秩最多提升 $\log_2 n$ 次。

**完整的攤還分析（Tarjan 1975）證明：路徑壓縮 + 按秩合併下，$m$ 次操作的總代價是 $O(m\,\alpha(n))$**，其中 $\alpha$ 是反 Ackermann 函數。**這個證明需要把秩分成 Ackermann 尺度的區塊並分別計費，本節不展開**——但上面的引理已經足以說明「為什麼壓縮有效」，而且它是後續帶權並查集正確性的直接依據（8.6）。

**你需要記住的三個數字**：

| 策略 | 單次最壞 | $m$ 次總計 |
| --- | --- | --- |
| 都不用 | $O(n)$ | $O(mn)$ |
| 只按大小／按秩 | $O(\log n)$ | $O(m\log n)$ |
| 只路徑壓縮 | $O(n)$ | $O(m\log_{1+m/n} n)$ 攤還 |
| 兩者都用 | $O(\log n)$ | $O(m\,\alpha(n))$ |

**「只路徑壓縮」的單次最壞仍是 $O(n)$**（第一次 `find` 一條長鏈），但攤還很好，**在競賽中通常單獨使用就夠了**。**只有「必須保證單次最壞」或「必須可撤銷（不能壓縮）」時，按秩合併才不可省。**

### 定理 4（990 等式方程：為什麼必須先處理所有 `==`）

*問題*：給一組形如 `a==b` 或 `a!=b` 的方程，問是否可滿足。

**演算法**：先把所有 `==` 全部 `unite`，再逐一檢查每個 `a!=b` 是否 `same(a,b)`；有一個成立就矛盾。

*正確性（兩個方向）*。
- **($\Rightarrow$ 有解則不報矛盾)**：設存在賦值滿足全部方程。相等關係在該賦值下是等價關係，且包含所有 `==` 對，故包含它們生成的等價閉包 $\sim_E$。若某個 `a!=b` 滿足 $a \sim_E b$，則該賦值下 $a$ 與 $b$ 相等，與 `a!=b` 矛盾 ✔。故演算法不會誤報。
- **($\Leftarrow$ 不報矛盾則有解)**：構造賦值——**給每個等價類一個不同的值**。所有 `==` 自動滿足（同類同值）；所有 `a!=b` 因為 $a \not\sim_E b$ 而分屬不同類、取值不同，也滿足 ✔。$\square$

**「先併後查」的順序不可交換**，理由由證明直接讀出：($\Leftarrow$) 方向用的是**最終**的等價類，而不是中間狀態。若邊讀邊處理，一個早出現的 `a!=b` 可能在後面的 `==` 把它們併起來之前就通過了檢查。**這是這題唯一的坑。**

**這個「等價閉包 + 每類給不同值」的構造是一個通用模板**：任何「只有相等約束與不等約束」的可滿足性問題都可以這樣解。**注意它不適用於「$a < b$」這種偏序約束**——偏序不是等價關係，那要用拓撲排序找環。

### 定理 5（684 冗餘連線：第一條「已連通」的邊就是答案）

*問題*：$n$ 個節點、$n$ 條邊的無向連通圖（恰含一個環），刪一條邊使其變成樹。若有多解，回傳**輸入中最後出現**的那一條。

**演算法**：按輸入順序 `unite`，**第一次回傳 `false` 的那條邊就是答案。**

*證明*。
- **可刪的邊恰為環上的邊**：刪掉環上任一邊仍連通（環上兩點還有另一條路）；刪掉非環邊會斷開（它是橋）✔。
- **設 $e_t$ 是第一條使 `unite` 回傳 `false` 的邊**，即處理它時兩端已連通。那麼 $e_t$ 與「前 $t-1$ 條邊構成的連通路徑」形成一個環 ⇒ **$e_t$ 在環上** ✔。
- **$e_t$ 是輸入中最後出現的環邊**：反設環上還有一條邊 $e_{t'}$，$t' > t$。環上的邊共同構成唯一的環（圖恰含一個環），而處理到 $e_t$ 時，環上除 $e_t$ 以外的邊**必須全部已被處理**（否則 $e_t$ 的兩端不會連通——連通的證據只能來自環上的另一條路徑）。故 $t' < t$，矛盾 ✔。$\square$

**這個證明依賴「圖恰含一個環」**（$n$ 點 $n$ 邊且連通）。**685 冗餘連線 II 是有向版，圖可能有「入度為 2 的節點」與「環」兩種問題疊加，不能直接套**——那是 8.2 的內容。

### 定理 6（為什麼並查集不能刪邊）

**命題**：在路徑壓縮的並查集中，無法在 $O(\text{polylog})$ 時間內支援「刪除一條先前加入的邊」。

*直觀論證*：`fa` 只記錄了「$x$ 屬於某棵樹」，**完全沒有記錄「$x$ 是因為哪條邊被併進來的」**。刪掉邊 $(u,v)$ 後，要判斷樹是否分裂、以及誰跟誰一起走，需要重建整個連通關係——而路徑壓縮已經把原始的合併歷史抹掉了（節點被直接掛到根上，中間結構永久丟失）。

**三條出路，選哪條取決於題目的形態**：
1. **離線倒序**：把所有操作讀進來，倒著處理，刪邊變成加邊（8.2 的 803 打磚塊、1970 你能穿過矩陣的最後一天）。**這是最常用的，前提是操作可以離線。**
2. **可撤銷並查集**：**放棄路徑壓縮**，只按秩合併（保證 $O(\log n)$），用一個堆疊記錄每次合併改動了哪些欄位，撤銷時回滾。**只能撤銷「最近一次」，配合線段樹分治可處理任意時段的邊。**
3. **動態連通性（LCT / 歐拉序樹）**：真正的線上刪邊結構，$O(\log^2 n)$。**遠超一般面試與多數競賽的範圍。**

**「只併不拆」不是並查集的缺點，是它的定義域。** 看到刪除，第一反應應該是「能不能離線倒過來」，而不是「怎麼改並查集」。

## 時間與空間複雜度

設 $n$ 為元素數、$m$ 為操作數（合併 + 查詢）。

| 操作 | 時間 |
| --- | --- |
| 初始化 | $O(n)$ |
| `find` / `unite` / `same` | 攤還 $O(\alpha(n))$，最壞 $O(\log n)$ |
| 全部 $m$ 次操作 | $O(n + m\,\alpha(n))$ |

**空間 $O(n)$**（`fa` 與 `sz` 各一個 `int` 陣列）。

**$\alpha(n)$ 有多小**：$\alpha(n) \le 4$ 對所有 $n < 2^{2^{2^{16}}}$——這個數遠大於宇宙中的原子數。**寫題解時說「近乎常數」是準確的，說「$O(1)$」則不精確。**

各題：
- **684 冗餘連線**：$O(n\,\alpha(n))$。
- **721 帳號合併**：設 email 總數 $L$。建映射 $O(L)$（雜湊），合併 $O(L\,\alpha)$，最後每組排序 $O(L\log L)$。**瓶頸在排序，不在並查集。**
- **737 句子相似性 II**：$O\big((|pairs| + |words|)\,\alpha\big)$，加上字串映射的雜湊成本。
- **990 等式方程**：$O(|equations| \cdot \alpha)$，元素只有 26 個。
- **1101 彼此熟識的最早時間**：$O(m\log m)$——**瓶頸是按時間排序**，並查集部分只有 $O(m\,\alpha)$。

**實務常數提醒**：
- **`find` 的迭代版（路徑減半）比遞迴版快，而且不會爆堆疊。** $n = 10^5$ 的長鏈遞迴 `find` 在某些判題環境會 stack overflow。
- **完整壓縮（兩趟：先找根，再把沿路全部指向根）與路徑減半（一趟：`fa[x] = fa[fa[x]]`）的漸近複雜度相同**（都是 $O(\alpha)$ 攤還，配合按秩合併）。路徑減半只掃一趟、程式短，**通常更快。**
- **多測資時用 `iota` 重設 `fa`，不要 `memset`**（`memset` 只能填 0）。

## 與相似技巧的比較

- **與 BFS/DFS 求連通塊**：**一次性地問「有幾個連通塊」，DFS 更簡單**（$O(n+m)$，不需要任何資料結構）。**並查集的價值在「邊加邊問」**——圖是動態長出來的，或者查詢穿插在合併之間。**判準：連通關係是靜態還是動態。**
- **與二分圖染色 / BFS 判奇環**：判斷「能否二分」時，DFS 染色與「擴展域並查集」（把每個點拆成 $x$ 與 $x+n$ 兩份，代表「同組」與「異組」）都可以。**DFS 染色更直觀，擴展域並查集在「約束是離線給的、且要邊加邊判」時更順手**（886 可能的二分法、990 的變形）。
- **與 Kruskal 最小生成樹**：Kruskal 就是「排序後依序 `unite`，回傳 `true` 的邊入選」。**`unite` 的 `bool` 回傳值在這裡就是「這條邊是否入選」。** 1101 彼此熟識的最早時間本質上是「Kruskal 跑到連通為止」。
- **與拓撲排序**：並查集處理**等價關係**（自反、對稱、遞移），拓撲排序處理**偏序**（反對稱）。**「$a$ 與 $b$ 同類」⇒ 並查集；「$a$ 必須在 $b$ 之前」⇒ 拓撲排序。** 定理 4 的證明用到了對稱性，所以那個構造對偏序無效。
- **與 8.6 帶權並查集**：本節的 `same` 只回答「是否同類」，帶權版還能回答「差多少／比值多少」。**結構相同，只是每條 `fa` 邊上掛一個權值，壓縮時要同步累積。**
- **與 8.4／8.5 的「指向下一個可用位置」**：那是並查集的一種**非連通性**用法——`fa[i] = i+1` 表示「位置 $i$ 已用，下一個候選是 $i+1$」。**它借用的只有「路徑壓縮讓重複跳躍變快」這個機制，與等價類無關。** 認清這一點，8.4 就不再神秘。
- **與可撤銷並查集 / 線段樹分治**：需要刪邊時的標準組合。**代價是放棄路徑壓縮**（撤銷需要保留歷史），複雜度退化到 $O(\log n)$ 每次操作。
- **與 `unordered_map` 直接存集合**：「小集合併入大集合」（啟發式合併）也能得到 $O(n\log n)$，而且**能枚舉集合內容**——並查集做不到這件事（要枚舉組內元素必須額外掃一遍全部元素按 `find` 分桶）。**721 帳號合併最後那一步就是在做這件事。**

## 本節重點速查

- **核心**：不記「集合有誰」，只記「父親是誰」。同類 $\iff$ 代表元相同。
- **兩條不變量（定理 1）**：`fa` 無環（森林）＋ **每棵樹恰為一個等價類**。路徑壓縮之所以安全，是因為它只把節點掛到**自己的祖先**上——節點不換樹、根不變。
- **`sz[x]` 只在 $x$ 是根時有意義。** 查組大小要寫 `sz[find(x)]`。任何掛在集合上的資訊都只在根上維護。
- **`unite` 一定要回傳 `bool`**（本來是否同類）。684 的答案、Kruskal 的選邊、環的偵測全靠它。
- **按大小合併 ⇒ 樹高 $\le\log_2 n$（定理 2）**，更好用的說法是**定理 2'：一個節點的深度最多增加 $\log_2 n$ 次，因為每次增加時它的連通塊至少翻倍。**「找一個單調有界的量來限制操作總數」是通用的攤還套路。
- **路徑壓縮有效的原因**：沿 `fa` 鏈往上秩嚴格遞增（定理 3），壓縮一次讓整條路徑的父秩跳到根。兩者合用是攤還 $O(\alpha(n))$，$\alpha \le 4$。
- **競賽中單用路徑壓縮通常就夠**；「必須保證單次最壞」或「必須可撤銷」時才需要按秩合併。
- **`find` 用迭代版（路徑減半），不要遞迴**——長鏈會爆堆疊。
- **990 必須「先併全部 `==`，再查全部 `!=`」**，順序不可交換（定理 4）。等價閉包 + 每類給不同值，是這類可滿足性問題的通用構造；**對「$a<b$」型的偏序約束無效。**
- **684：第一條讓 `unite` 回傳 `false` 的邊就是答案**（定理 5），前提是「$n$ 點 $n$ 邊且恰含一個環」。**685 有向版不能直接套。**
- **並查集不能刪邊（定理 6）。** 看到刪除先想「能不能離線倒過來」（8.2），其次才是可撤銷並查集（放棄壓縮）。
- **忘記 `iota` 初始化 ⇒ 所有元素一開始就同類 ⇒ 答案永遠是 1。**
