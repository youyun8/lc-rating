## 這個技術解決什麼問題

8.1 說過並查集的定義域是「只併不拆」。本節處理的，全是**題目看起來要拆、但可以想辦法變成併**的情形，以及**連通性不是題目直接問的東西、需要先建模**的情形。

四類：

1. **刪邊／刪點後查連通性，而且操作能一次全部讀入（離線）** ⇒ **倒著跑**，刪變成併。803 打磚塊、1970 你能穿過矩陣的最後一天、2503 矩陣查詢可獲得的最大分數。
2. **答案對某個閾值單調** ⇒ **按閾值排序後逐步加邊**，第一次連通時就是答案。778 水位上升的泳池、1102 得分最高的路徑、1631 最小體力消耗路徑。**這與 6.2 定理 2 的「最小瓶頸路」是同一件事，只是換了工具。**
3. **題意其實在說「這些東西該歸成同一類」，只是包裝過**。765 情侶牽手、947 移除最多的同行或同列石頭、959 由斜槓劃分區域、839 相似字串組。**難點在建模，不在並查集。**
4. **需要在合併的同時維護額外資訊或選擇特定代表元**。685 冗餘連線 II、1061 按字典序排列最小的等效字串、2092 找出知曉秘密的所有專家。

**共同的心法**：*並查集本身沒有變難，變難的是「把題目翻譯成合併操作」這一步。* 本節的每個定理，證的都是「這個翻譯是對的」。

## 狀態／資料結構定義

沿用 8.1 的 `DSU`，本節在它之上加三種常見的擴充。

**（一）虛擬節點（超級源點）**——把「與某個外部條件相連」也表達成連通性。

```cpp
DSU dsu(n* m + 1);      // 節點 0 是虛擬的「天花板」
const int SKY = n * m;  // 或直接用 0，本節統一用最後一個編號
// 第 0 列的每塊磚都 unite(cell, SKY)
```
**803 的「穩定」= 與天花板連通**，1970 的「能穿過」= 上邊界與下邊界連通（**兩個虛擬節點**）。**「某個性質是否成立」若能寫成「與某個固定點連通」，就可以用虛擬節點吸收掉。**

**（二）擴展域（種類並查集）**——把每個元素拆成多份，表達「敵對／異類」。

```cpp
DSU dsu(2 * n);  // x 表示「x 在 A 組」，x + n 表示「x 在 B 組」
// 「x 與 y 不同組」：unite(x, y + n); unite(y, x + n);
// 「x 與 y 同組」：  unite(x, y);     unite(x + n, y + n);
// 矛盾檢查：same(x, x + n)
```
**適用於「關係只有兩種，且第二種是第一種的『反』」**（886 可能的二分法、1202 的變形）。**三種以上的循環關係（食物鏈）就開三倍域。**

**（三）在根上掛聚合資訊**——組大小、組內最小編號、組內某個計數。

```cpp
struct DSU {
    vector<int> fa, sz, mn;  // mn[root] = 該組的最小元素編號（1061 用）
    // ...
    bool unite(int x, int y) {
        x = find(x);
        y = find(y);
        if (x == y) return false;
        if (sz[x] < sz[y]) swap(x, y);
        fa[y] = x;
        sz[x] += sz[y];
        mn[x] = min(mn[x], mn[y]);  // 聚合：與合併方向無關才安全
        return true;
    }
};
```
**聚合量必須滿足「可交換、可結合」**（min、max、sum、xor 都可以）。**若聚合量依賴合併方向（例如「先加入者優先」），就不能這樣寫**——那需要在根上存完整資訊或改用啟發式合併。

## 不變量或正確性證明

### 定理 1（離線倒序：刪除 $\Rightarrow$ 加入的等價性）

設初始圖為 $G_0$，第 $t$ 次操作刪除邊集 $D_t$（$t = 1..T$），令 $G_t = G_{t-1} \setminus D_t$。**查詢 $q_t$ 只依賴 $G_t$ 的連通結構。**

**命題**：倒序處理——從 $G_T$ 開始，依次把 $D_T, D_{T-1}, \dots, D_1$ 加回去——所經歷的圖序列恰為 $G_T, G_{T-1}, \dots, G_0$。

*證明*：$G_{t-1} = G_t \cup D_t$（$D_t \subseteq G_{t-1}$，刪掉再加回就是原圖）。對 $t$ 從 $T$ 遞減歸納即得 ✔。$\square$

**兩個必要前提，缺一不可：**

1. **離線**：所有刪除操作必須事先知道，才能先建出 $G_T$。**線上（每次操作依賴前一次的答案）就不能用。**
2. **查詢只依賴當時的圖**，不依賴「到達該狀態的歷史」。**803 需要特別檢查這一點**（見定理 2）。

**還有一個實作上的前提**：**要先把所有被刪的東西刪掉，得到 $G_T$，再開始倒序。** 忘記這一步（直接在完整圖上倒序）是這一族題最常見的錯誤。

### 定理 2（803 打磚塊：為什麼答案是「加回後穩定數的增量減一」）

*問題*：網格中 1 表示磚塊。與**頂列**相連（透過上下左右的磚塊）的磚塊是**穩定**的。依序敲掉 $\text{hits}[i]$ 位置的磚塊，問每次敲擊後有多少磚塊**掉落**（不含被敲掉的那塊）。

**演算法**：
1. 把 `hits` 中所有位置**先全部設為 0**（不管原本是不是磚塊），得到最終網格 $G_T$；
2. 對 $G_T$ 建並查集，虛擬節點 `SKY` 連接頂列所有磚塊，記 $S_T = |\{\text{與 SKY 連通的磚塊}\}|$；
3. 倒序 $i = T-1 \dots 0$：若 $\text{hits}[i]$ 在**原始**網格中不是磚塊，答案為 0（該次敲擊什麼也沒發生）；否則把它加回、與四鄰及（若在頂列）SKY 合併，得到新的穩定數 $S'$，**答案 $= \max(0,\ S' - S - 1)$**，然後令 $S \leftarrow S'$。

*正確性*。固定一次敲擊，設敲前的網格為 $H$（含被敲的磚 $b$），敲後為 $H' = H \setminus \{b\}$。令 $\mathrm{St}(X)$ 為網格 $X$ 中穩定磚塊的集合。

- **引理（單調性）**：$\mathrm{St}(H') \subseteq \mathrm{St}(H)$。
  *證明*：$H'$ 中任一條「從磚塊到頂列」的路徑，在 $H$ 中也存在（$H' \subseteq H$）✔。
- **掉落的磚塊恰為 $\mathrm{St}(H) \setminus \mathrm{St}(H') \setminus \{b\}$**。
  *證明*：一塊磚會掉落 $\iff$ 它敲前穩定、敲後不穩定，且它不是 $b$ 自己。**注意「敲前不穩定的磚」不會掉**——它早就掉過了（或者說，題目的模型中它從一開始就不在），這是題目語意，也是為什麼要用「穩定數」而非「磚塊數」來計算 ✔。
- 故掉落數 $= |\mathrm{St}(H)| - |\mathrm{St}(H')| - [\,b \in \mathrm{St}(H)\,]$。

倒序時，$S' = |\mathrm{St}(H)|$、$S = |\mathrm{St}(H')|$。**若 $b$ 加回後穩定**（$b \in \mathrm{St}(H)$），掉落數 $= S' - S - 1$；**若 $b$ 加回後仍不穩定**，則 $\mathrm{St}(H) = \mathrm{St}(H')$，$S' = S$，掉落數 $= 0$——而公式給出 $S'-S-1 = -1$，**這正是要用 $\max(0,\cdot)$ 的原因** ✔。$\square$

**三個容易錯的細節，每一個都在證明裡有對應：**

- **`hits` 可能重複，或指向空格**。步驟 1「不管原本是不是磚塊都設 0」加上步驟 3「查原始網格判斷是否為磚塊」，共同處理了這兩種情況。**重複的 `hits`：第二次敲同一格時原始網格是磚塊、但它在倒序中已經被加回過**——所以要用一個「當前網格」陣列而非原始網格來判斷「這格現在是不是空的」，或者更簡單：把重複的位置在步驟 3 中視為「原始網格為 0」處理。
- **$\max(0,\cdot)$ 不能省。**
- **`SKY` 的連接要在加回磚塊時同步做**：若加回的磚在第 0 列，除了與四鄰合併，還要 `unite(cell, SKY)`。

### 定理 3（765 情侶牽手：答案 $=$ 情侶對數 $-$ 連通塊數）

*建模*：座位 $2i$ 與 $2i+1$ 是一張沙發。把**情侶對**編號為 $0..n-1$（人 $p$ 屬於情侶對 $\lfloor p/2 \rfloor$）。對每張沙發，把坐在上面的兩個人所屬的情侶對 `unite`。

**命題**：最少交換次數 $= n - (\text{連通塊數})$，其中 $n$ 是情侶對數（沙發數）。

*證明*。設連通塊為 $C_1,\dots,C_k$，$|C_j| = c_j$，$\sum c_j = n$。

- **每個連通塊內部自洽**：$C_j$ 中的 $c_j$ 對情侶恰好佔據 $c_j$ 張沙發（每張沙發貢獻一條邊，$c_j$ 個節點的連通塊至少 $c_j - 1$ 條邊；而總邊數 = 總沙發數 = $n$ = 總節點數，故**每個連通塊恰好是一個「基環樹」，即恰含一個環**，邊數 = 節點數 $c_j$）✔。
- **上界（構造 $c_j - 1$ 次交換）**：若 $c_j = 1$，該沙發已坐著一對情侶，0 次 ✔。若 $c_j \ge 2$，任取一張「坐著兩個不同情侶對」的沙發，把其中一人與其伴侶交換過來——**該情侶對就從連通塊中分離成一個孤立點**，剩下 $c_j - 1$ 個節點仍連通（環被打開成鏈，仍連通）。遞迴得 $c_j - 1$ 次 ✔。
- **下界**：目標狀態是「每個連通塊都是孤立點」，即 $n$ 個連通塊。**一次交換最多讓連通塊數增加 1**——交換只改動兩張沙發（兩條邊）的端點，而**改動一條邊最多讓連通塊數 $+1$**；仔細看，一次交換是把兩條邊 $(a,b),(c,d)$ 換成 $(a,c),(b,d)$（或 $(a,d),(b,c)$），這在圖上是「2-opt」操作，最多把一個連通塊拆成兩個 ✔。故從 $k$ 個連通塊到 $n$ 個至少需要 $n-k$ 次 ✔。$\square$

**這個「答案 = 元素數 − 連通塊數」的形式在交換類問題中反覆出現**（例如「最少交換次數使陣列有序」用置換環分解）。**共同結構：目標是把所有元素變成不動點，一次操作最多打散一個環。** 認出這個形狀，證明就是套模板。

### 定理 4（778 水位上升：單調性 ⇒ 排序後逐步加點）

*問題*：$n\times n$ 網格，格 $(i,j)$ 的高度 $h_{ij}$。水位 $t$ 時可以在所有 $h \le t$ 的格子間自由移動（四連通）。求從 $(0,0)$ 游到 $(n-1,n-1)$ 的最小 $t$。

**引理（單調性）**：令 $P(t) = $「在 $\{h \le t\}$ 的格子中，$(0,0)$ 與 $(n-1,n-1)$ 連通」。則 $t \le t' \Rightarrow P(t) \Rightarrow P(t')$。

*證明*：$\{h \le t\} \subseteq \{h \le t'\}$，前者中的路徑在後者中仍存在 ✔。$\square$

**由單調性，答案 $= \min\{t : P(t)\}$，可用兩種方式求：**

- **二分 $t$ + 每次 BFS**：$O(n^2 \log(\max h))$。
- **排序所有格子後遞增加入並查集**：$O(n^2\log n \cdot \alpha)$，**第一次 `same(起點, 終點)` 為真時的高度就是答案**。

*後者的正確性*：加入格子 $c$（高度 $h_c$）時，並查集中恰為 $\{h \le h_c\}$ 的連通結構（前提是**按高度非遞減排序**，且相同高度的要**全部加完再檢查**——否則會回報一個偏小的答案）。由引理，第一次連通的高度就是最小的 $t$ ✔。$\square$

**這就是 6.2 定理 2 的「最小瓶頸路」，換成並查集的說法。** 三種解法的關係：

| 解法 | 複雜度 | 適用 |
| --- | --- | --- |
| 二分 + BFS | $O(n^2\log V)$ | 高度值域小、只問一次 |
| Dijkstra（$\oplus = \max$） | $O(n^2\log n)$ | 要輸出路徑、或起點固定終點多變 |
| 排序 + 並查集 | $O(n^2\log n)$ | **要回答多組「$t$ 為何值時 $u,v$ 連通」** |

**第三種的獨特價值是可以離線批量回答**：把所有查詢按閾值排序，一趟掃完（2503 矩陣查詢可獲得的最大分數就是這個形態）。**更進一步就是 Kruskal 重構樹**，能線上回答「$u,v$ 之間的瓶頸值」。

### 定理 5（685 冗餘連線 II：有向版的完整分類）

*問題*：一棵有根樹（每個非根節點入度 1，根入度 0）加上一條多餘的有向邊，共 $n$ 點 $n$ 邊。刪一條邊使其恢復為有根樹；多解時回傳輸入中最後出現的。

**分類**：多加一條有向邊 $(u,v)$，只可能造成兩種「病症」：

- **病症 A：某個節點 $v$ 的入度變成 2**（$v$ 原本就有父親）。
- **病症 B：出現有向環**（$v$ 原本是根，於是根有了父親，形成環）。

**且兩者不會同時以「兩個獨立問題」的形式出現**——只加了一條邊，最多製造一個問題點。但**病症 A 與 B 可以同時發生**：$v$ 有兩個父親，且其中一條邊參與了一個環。

**演算法**：
1. 掃一遍找入度為 2 的節點 $v$。若沒有 ⇒ **純病症 B**，退化成 684 的有向版：按順序 `unite`，**第一條使兩端已連通的邊**就是答案（證明同 8.1 定理 5）。
2. 若有 ⇒ 記下指向 $v$ 的兩條邊 $e_1$（較早）與 $e_2$（較晚）。**先試著刪 $e_2$**：把除 $e_2$ 外的所有邊 `unite`，若過程中沒有出現「已連通」⇒ 刪 $e_2$ 可行，答案是 $e_2$；否則答案是 $e_1$。

*正確性*。
- 情形 1（無入度 2）：每個節點入度 $\le 1$ 且共 $n$ 條邊 ⇒ 每個節點入度恰為 1 ⇒ **圖中必有環**（從任一點反向沿父指標走必定循環）。刪掉環上的邊即可，而「最後出現的環邊」就是第一條使 `unite` 回傳 `false` 的邊 ✔。
- 情形 2（有入度 2 的 $v$）：多餘的邊**必定是 $e_1$ 或 $e_2$**（其他邊都是原樹的邊，刪掉會斷開）✔。
  - 刪 $e_2$ 後若剩餘 $n-1$ 條邊構成樹（無環、連通）⇒ $e_2$ 是多餘邊，且它比 $e_1$ 晚出現 ⇒ 依「回傳最後出現者」的規則，答案是 $e_2$ ✔。
  - 刪 $e_2$ 後仍有環 ⇒ 環由 $e_1$ 與原樹邊構成 ⇒ 多餘的邊只能是 $e_1$（刪 $e_2$ 解決不了環）✔。$\square$

**這題的教訓不是並查集，是「窮盡所有病症並證明它們互斥或可分別處理」。** 直接套 684 會在有入度 2 的測資上錯，而且錯得很隱蔽。**遇到有向圖的連通性，先問「入度／出度的約束是什麼」，再問「並查集能不能表達它」——並查集本身只懂無向連通，有向的部分必須靠額外的入度統計。**

### 定理 6（959 由斜槓劃分區域：四分格建模的正確性）

*問題*：$n\times n$ 網格，每格是 `/`、`\` 或空格。問這些斜槓把正方形分成幾塊。

**建模**：把每格切成 4 個三角形（上 0、右 1、下 2、左 3）。

- 格內：`/` 連 (0,3) 與 (1,2)；`\` 連 (0,1) 與 (2,3)；空格連全部 4 個。
- 格間：當前格的 1（右）連右鄰格的 3（左）；當前格的 2（下）連下鄰格的 0（上）。

**答案 = 連通塊數。**

*正確性的關鍵*：**「4 個三角形」這個切分足夠細——任何一條斜槓都恰好沿著三角形的邊界，不會穿過任何三角形的內部。** 於是：

- 每個三角形內部是連通的、且完全屬於某一塊區域 ✔；
- 兩個相鄰三角形屬於同一塊區域 $\iff$ 它們之間**沒有斜槓隔開** $\iff$ 演算法中它們被 `unite` ✔；
- 區域是三角形的連通閉包 ⇒ 區域數 = 連通塊數 ✔。$\square$

**「切得夠細，使得所有障礙都落在格子邊界上」是這一族網格題的通用手法。** 若題目的斜線更複雜（例如允許水平／垂直的牆），就切成 $3\times3$ 或更細的子格。**判準：每一種障礙都必須能被表達成「某兩個子格之間不連通」，而不能穿過子格內部。**

### 定理 7（1061 指定代表元：為什麼要放棄按大小合併）

*問題*：給一組等價的字元對，把字串中每個字元換成其等價類中**字典序最小**的字元。

**做法一（改變合併方向）**：`unite` 時**永遠讓字典序小的當根**：
```cpp
if (x > y) swap(x, y);
fa[y] = x;  // 小的當根
```
**代價**：放棄了按大小合併，樹高可能退化。**但配合路徑壓縮，攤還仍是 $O(\log n)$**（8.1 表格的「只路徑壓縮」那一行），而且這題只有 26 個元素，完全不是問題。

**做法二（保留按大小合併，額外維護 `mn`）**：根上多存一個 `mn[root]`，合併時取 `min`。**這是通用解**——聚合量滿足交換律與結合律，與合併方向無關（見「狀態／資料結構定義」第三點）。

**該選哪個**：
- 元素少、或代表元的選擇規則就是全部所需資訊 ⇒ **做法一**，程式短。
- 元素多、或需要保證 $O(\alpha)$、或需要同時維護多個聚合量 ⇒ **做法二**。

**通用原則：不要為了「讓代表元有意義」而犧牲平衡策略，除非規模很小。** 代表元只是實作細節，題目要的資訊應該掛在根上，而不是編碼進「誰是根」這件事。

## C++17 模板

**模板一：803 打磚塊（離線倒序 + 虛擬天花板）**

```cpp
class Solution {
    vector<int> fa, sz;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }
    void unite(int x, int y) {
        x = find(x);
        y = find(y);
        if (x == y) return;
        if (sz[x] < sz[y]) swap(x, y);
        fa[y] = x;
        sz[x] += sz[y];
    }

public:
    vector<int> hitBricks(vector<vector<int>>& grid,
                          vector<vector<int>>& hits) {
        int n = grid.size(), m = grid[0].size();
        int SKY = n * m;
        fa.resize(n * m + 1);
        iota(fa.begin(), fa.end(), 0);
        sz.assign(n * m + 1, 1);

        auto cur = grid;  // 步驟 1：先全部敲掉
        for (auto& h : hits) cur[h[0]][h[1]] = 0;

        const int dx[4] = {-1, 1, 0, 0}, dy[4] = {0, 0, -1, 1};
        auto id = [&](int r, int c) { return r * m + c; };

        for (int r = 0; r < n; ++r) {  // 步驟 2：建 G_T
            for (int c = 0; c < m; ++c) {
                if (!cur[r][c]) continue;
                if (r == 0) unite(id(r, c), SKY);
                if (r > 0 && cur[r - 1][c]) unite(id(r, c), id(r - 1, c));
                if (c > 0 && cur[r][c - 1]) unite(id(r, c), id(r, c - 1));
            }
        }
        auto stable = [&]() { return sz[find(SKY)] - 1; };  // 扣掉 SKY 自己

        int T = hits.size();
        vector<int> ans(T, 0);
        int prev = stable();
        for (int i = T - 1; i >= 0; --i) {  // 步驟 3：倒序加回
            int r = hits[i][0], c = hits[i][1];
            if (grid[r][c] == 0) continue;  // 原本就不是磚塊 → 0
            if (cur[r][c] == 1) continue;   // 重複的 hits，已加回 → 0
            cur[r][c] = 1;
            if (r == 0) unite(id(r, c), SKY);
            for (int d = 0; d < 4; ++d) {
                int nr = r + dx[d], nc = c + dy[d];
                if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
                if (cur[nr][nc]) unite(id(r, c), id(nr, nc));
            }
            int now = stable();
            ans[i] = max(0, now - prev - 1);  // 定理 2
            prev = now;
        }
        return ans;
    }
};
```

**模板二：765 情侶牽手（連通塊計數）**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    int minSwapsCouples(vector<int>& row) {
        int n = row.size() / 2;  // 情侶對數 = 沙發數
        fa.resize(n);
        iota(fa.begin(), fa.end(), 0);
        int comp = n;
        for (int i = 0; i < n; ++i) {
            int a = find(row[2 * i] / 2), b = find(row[2 * i + 1] / 2);
            if (a != b) {
                fa[a] = b;
                --comp;
            }
        }
        return n - comp;  // 定理 3
    }
};
```

**模板三：778 水位上升的泳池（排序 + 遞增加點）**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    int swimInWater(vector<vector<int>>& grid) {
        int n = grid.size();
        vector<int> pos(n * n);  // 高度 h 的格子在哪
        for (int r = 0; r < n; ++r)
            for (int c = 0; c < n; ++c) pos[grid[r][c]] = r * n + c;

        fa.resize(n * n);
        iota(fa.begin(), fa.end(), 0);
        vector<char> on(n * n, false);
        const int dx[4] = {-1, 1, 0, 0}, dy[4] = {0, 0, -1, 1};

        for (int t = 0; t < n * n; ++t) {  // 高度即為 0..n*n-1 的排列
            int r = pos[t] / n, c = pos[t] % n;
            on[pos[t]] = true;
            for (int d = 0; d < 4; ++d) {
                int nr = r + dx[d], nc = c + dy[d];
                if (nr < 0 || nr >= n || nc < 0 || nc >= n) continue;
                if (!on[nr * n + nc]) continue;
                int a = find(pos[t]), b = find(nr * n + nc);
                if (a != b) fa[a] = b;
            }
            if (find(0) == find(n * n - 1)) return t;  // 第一次連通
        }
        return -1;
    }
};
```

（778 的高度恰為 $0..n^2-1$ 的排列，所以連排序都省了。**高度有重複時，必須把同一高度的格子全部加完才檢查連通性**——見定理 4 的括號註記。）

## 時間與空間複雜度

設 $n$ 為元素／格子數、$m$ 為邊數／操作數、$q$ 為查詢數。

| 題目 | 時間 | 空間 | 瓶頸 |
| --- | --- | --- | --- |
| 803 打磚塊 | $O\big((nm + \lvert hits\rvert)\,\alpha\big) $ | $O(nm)$ | 建 $G_T$ |
| 765 情侶牽手 | $O(n\,\alpha)$ | $O(n)$ | — |
| 778 水位上升 | $O(n^{2}\alpha)$（高度是排列，免排序） | $O(n^{2})$ | — |
| 一般「排序 + 加邊」 | $O(m\log m + m\,\alpha)$ | $O(n)$ | **排序** |
| 685 冗餘連線 II | $O(n\,\alpha)$ | $O(n)$ | — |
| 959 斜槓劃分區域 | $O(n^{2}\alpha)$ | $O(n^{2})$ | 節點數是 $4n^2$ |
| 947 移除石頭 | $O(n\,\alpha)$（用行／列當虛擬節點） | $O(n)$ | — |
| 839 相似字串組 | $O(n^{2}\ell + n^{2}\alpha)$ | $O(n)$ | **兩兩比較 $O(n^2\ell)$** |

**兩個「瓶頸不在並查集」的例子值得記住**：
- **「排序 + 加邊」類題目的瓶頸永遠是排序**（$O(m\log m)$），並查集只佔 $O(m\alpha)$。**想優化就從「能不能免排序」下手**（778 的高度是排列、計數排序、值域小）。
- **839 的瓶頸是兩兩比較。** $n \le 300$、$\ell \le 300$ ⇒ $2.7\times10^7$，剛好能過。**若 $n$ 再大一級，就必須換成「枚舉每個字串的所有可能交換」來建邊**——判斷該枚舉哪一邊，比較 $n^2\ell$ 與 $n\ell^2$。

**離線倒序的額外成本是 $O(1)$**——它只是改變處理順序，不增加任何漸近開銷。**這是它如此划算的原因：一個純粹的「換個方向看」就把不可做變成可做。**

## 常見錯誤與邊界條件

- **倒序前忘記先建 $G_T$**。直接在完整圖上倒序，第一步的狀態就錯了。**「先刪光，再倒著加回來」是兩個步驟，不是一個。**
- **803 忘記 $\max(0,\cdot)$**。加回的磚塊本身不穩定時公式給出 $-1$。
- **803 沒處理重複的 `hits` 或空格上的 `hits`**。兩者都要回傳 0，判斷依據不同：空格看**原始網格**，重複看**當前網格**。
- **803 的 `stable()` 忘記扣掉 SKY 自己**。`sz[find(SKY)]` 包含虛擬節點，要 $-1$。
- **虛擬節點的編號與真實節點衝突**。$n\times m$ 的網格用 `n*m` 當虛擬節點，陣列要開 `n*m+1`。**開成 `n*m` 是越界，症狀通常是隨機錯誤而非崩潰。**
- **778 高度有重複時邊加邊查**。必須把同高度的全部加完再檢查，否則答案偏小。**題目保證是排列時可以不管，但變形題要小心。**
- **擴展域忘記「雙向」表達不同組**。`unite(x, y+n)` 只說了一半，還要 `unite(y, x+n)`。**只寫一半在多數測資上碰巧會對，在鏈式約束上會錯。**
- **擴展域的陣列開 `2*n` 但索引寫成 `x + n` 時 `x` 已經是 `find` 過的根**。**必須用原始編號做偏移**，`find(x) + n` 是錯的。
- **685 只處理了環、沒處理入度 2**（或反之）。兩種病症都要檢查。
- **959 的三角形編號順序不一致**。上右下左（0123）與上下左右（0123）混用會讓格間連接錯位。**寫在註解裡，並在格間連接處對照一次。**
- **在根上維護聚合量，但讀取時忘記 `find`**。`mn[x]` 是垃圾，`mn[find(x)]` 才對（8.1 的老問題，在本節因為聚合量變多而更容易犯）。
- **合併時聚合量的更新寫在 `swap` 之前**。`swap(x,y)` 之後 `x` 才是新根，聚合必須在 `swap` 之後、且寫進 `x`。
- **1061 改變合併方向後仍假設 $O(\alpha)$**。放棄按大小合併後是 $O(\log n)$；規模大時要改用「聚合量」寫法。

## 與相似技巧的比較

- **與 8.1**：8.1 是「工具本身」，本節是「怎麼把題目翻譯成這個工具」。**本節的每個定理都在證明一個翻譯的正確性**，而不是在改進並查集。
- **與可撤銷並查集 + 線段樹分治**：處理「每條邊只在某個時間區間內存在」的一般情形。**離線倒序（定理 1）是它的特例**——所有邊的存在區間都是「從某時刻到最後」這種後綴形式。**看到「邊有存活區間，而且不是後綴」就要上線段樹分治。** 代價是放棄路徑壓縮，$O(m\log^2 n)$。
- **與 Kruskal 重構樹**：定理 4 的「排序 + 加邊」若要**線上**回答「$u$ 與 $v$ 的瓶頸值」，就把每次合併建成一個新節點（權值 = 當前閾值），最後得到一棵二元樹，查詢變成 LCA。**$O(m\log m)$ 預處理、$O(\log n)$ 查詢。** 這是本節第 2 類題的終極形態。
- **與 Dijkstra（$\oplus=\max$）**：6.2 定理 2 證明了最小瓶頸路可以用 Dijkstra 求。**Dijkstra 適合單源多終點且要輸出路徑；並查集適合離線批量回答任意點對。** 兩者複雜度相近，選擇看查詢形態。
- **與 BFS/DFS + 二分答案**：778 用二分 + BFS 是 $O(n^2\log V)$，寫起來更短。**值域小的時候二分更划算；要回答多個查詢時並查集更划算。**
- **與拓撲排序**：685 的有向部分（入度統計）本質上是拓撲的思路。**並查集只懂無向連通，有向圖的環／入度必須另外處理**——這是 684 與 685 難度差距的全部來源。
- **與 8.3～8.6**：後面四節都是本節「建模」思路的專門化——**8.3 用質因數當橋樑節點、8.4／8.5 用 `fa` 表達「下一個可用位置」（與連通性無關）、8.6 在邊上掛權值。** 8.4／8.5 尤其值得注意：**它們借的只是「路徑壓縮讓重複跳躍變快」這個機制**，不要用等價類的直覺去理解。

## 本節重點速查

- **本節難在建模，不在並查集。** 每個定理證的都是「這個翻譯對不對」。
- **離線倒序（定理 1）**：刪 ⇒ 併。兩個前提——**離線**、**查詢只依賴當時的圖**。實作上**必須先刪光建出 $G_T$，再倒著加回**。額外成本為零，是最划算的技巧。
- **803**：穩定 = 與虛擬天花板連通；**答案 $=\max(0,\ S'-S-1)$**。$-1$ 扣掉磚塊自己，$\max$ 處理「加回後仍不穩定」。空格與重複 `hits` 分別看原始網格與當前網格。`stable()` 記得扣掉 SKY。
- **765**：把情侶對當節點、沙發當邊，**答案 $= n - \text{連通塊數}$**。「答案 = 元素數 − 連通塊數」是交換類問題的通用形狀（一次操作最多打散一個環）。
- **閾值單調 ⇒ 排序後遞增加邊，第一次連通即答案（定理 4）。** 這與 6.2 的最小瓶頸路是同一件事。**同閾值的元素要全部加完再檢查。** 瓶頸是排序而非並查集。
- **685 的兩種病症**：入度 2、有向環，**可以同時發生**。有入度 2 時先試刪較晚那條。**並查集只懂無向連通，有向的入度約束必須額外統計。**
- **959 的四分格**：切得夠細，使所有障礙都落在子格邊界上，不穿過子格內部。
- **虛擬節點**把「與某個外部條件相連」表達成連通性；**擴展域**（$x$ 與 $x+n$）表達「敵對」，記得雙向寫。
- **在根上掛聚合量時，聚合必須可交換可結合，且更新要寫在 `swap` 之後、讀取要先 `find`。**
- **指定代表元（1061）**：改變合併方向最短但放棄平衡（$O(\log n)$）；維護 `mn` 是通用解。**規模大就用後者。**
- **邊的存活區間不是後綴 ⇒ 線段樹分治 + 可撤銷並查集；要線上查瓶頸值 ⇒ Kruskal 重構樹。**
