## 這個技術解決什麼問題

一條長度 $n$ 的資源帶（天數、座位、格子），反覆執行同一種操作：

> **「從位置 $i$ 開始往右找第一個還沒被佔用的位置，佔用它。」**

暴力是每次從 $i$ 一格一格往右掃，單次 $O(n)$，$q$ 次請求就是 $O(nq)$。$n, q$ 都到 $10^5$ 就過不了。

**核心想法**：*讓 `fa[i]` 記錄「從 $i$ 出發，下一個值得嘗試的位置」。* 位置 $i$ 一旦被佔用，就令 `fa[i] = i + 1`——意思是「別再問我了，去問我右邊那個」。查詢就是沿 `fa` 一路跳到底，而**路徑壓縮讓下一次查詢直接跳過整段連續的已佔用區**。

**這是並查集的一種「非等價類」用法，必須先講清楚，否則會用 8.1 的直覺去理解而卡住：**

| | 8.1／8.2／8.3 | 本節 |
| --- | --- | --- |
| `fa` 的語意 | 同一等價類的代表元 | **下一個可用位置** |
| 合併方向 | 由平衡策略決定（按大小） | **由語意固定：永遠指向右邊** |
| `find(x)` 的意義 | $x$ 屬於哪一類 | **$\ge x$ 的第一個空位** |
| 能否問「$x$ 與 $y$ 同類嗎」 | 能 | **不能，也沒有意義** |

**本節借用的只有「路徑壓縮讓重複跳躍變快」這個機制。** 認清這一點，剩下的都很簡單。

**辨識訊號（三個要同時成立）**：
1. 資源是**一維排列**的（天、位置、編號）；
2. **一旦佔用就永久失效**（單調消耗，不會釋放）；
3. 反覆查詢「某位置右邊（或左邊）第一個可用的」。

**典型題**：1353 最多可以參加的會議數目、1488 避免洪水氾濫、2382 刪除操作後的最大子段和（配合 8.2 的倒序）、2334 元素值大於變化閾值的子陣列、3666 允許的最大變換次數。

## 狀態／資料結構定義

**寫法 A：指向右鄰（最常用）**

```cpp
struct NextFree {
    vector<int> fa;  // fa[i] = 從 i 出發下一個值得試的位置
    explicit NextFree(int n) : fa(n + 1) {  // 注意是 n + 1，多一個哨兵
        iota(fa.begin(), fa.end(), 0);
    }
    int find(int x) {  // 回傳 >= x 的第一個空位；n 表示沒有
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }
    void occupy(int x) { fa[x] = x + 1; }  // x 被用掉，指向右鄰
};
```

**哨兵 `fa[n] = n` 是必要的**：當 $\ge x$ 的位置全被佔滿時，`find` 回傳 $n$，呼叫端據此判斷「沒有可用位置」。**陣列開成 `n` 而不是 `n+1` 會越界，而且是那種「大部分測資都對、極端測資才崩」的越界。**

**注意 `occupy(x)` 必須傳入 `find` 的結果，不能傳任意位置。** 寫 `occupy(find(i))` 而不是 `occupy(i)`——否則會把一個本來就非空的位置的指標覆蓋掉（見「常見錯誤」）。

**寫法 B：在根上記錄區間右端（可以恢復按大小合併）**

寫法 A 的合併方向被語意固定（永遠指向右），**因此不能按大小合併**，攤還界比正統並查集差（見「時間與空間複雜度」）。想要 $O(\alpha)$ 保證，可以改成：

```cpp
struct NextFree2 {
    vector<int> fa, sz, nxt;  // nxt[root] = 該連通塊的右端 + 1
    // find/unite 用正統的按大小合併
    int nextFree(int x) { return nxt[find(x)]; }  // 語意不變，實作換成聚合量
};
```
**佔用 $x$ 時把 $x$ 與 $x+1$ `unite`，並在新根上維護 `nxt = max(兩邊的 nxt)`。** 這就回到 8.2 「在根上掛聚合量」的正統做法。**規模不大時寫法 A 就夠；要保證最壞複雜度就用寫法 B。**

**雙向（同時要「左邊第一個空位」）**：**開兩個獨立的陣列**，`L` 指向左鄰、`R` 指向右鄰，佔用時**兩個都要更新**。不要試圖用一個陣列表達雙向——那不是並查集能做的事。

**「合併相鄰區段」的變體（1562／2382）**：這時 `fa` 回到正統語意（連通塊 = 一段連續的活躍區間），只是**合併對象固定為左右鄰居**。此時可以正常用按大小合併，並在根上掛「區段和」「區段長度」等聚合量。**這個變體與寫法 A 不是同一件事，別混。**

## 不變量或正確性證明

### 定理 1（主不變量：`find(x)` 恰為 $\ge x$ 的第一個空位）

令 $U \subseteq \{0,\dots,n-1\}$ 為已佔用位置的集合，$\mathrm{free}(x) = \min\{\,j \ge x : j \notin U\,\}$（約定 $n \notin U$，故最小值必存在且 $\le n$）。

**不變量 (N)**：任何時刻，對所有 $x \in [0, n]$，
$$\texttt{fa}[x] = \begin{cases} x, & x \notin U,\\ \text{某個} > x \text{的值}, & x \in U,\end{cases}$$
且**沿 `fa` 從 $x$ 出發必定終止**。

**命題**：在 (N) 之下，`find(x)` $= \mathrm{free}(x)$。

*證明*（對 $n - x$ 歸納，即從右往左）。
- $x = n$：`fa[n] = n`（哨兵，$n \notin U$），`find(n) = n = free(n)` ✔。
- $x < n$ 且 $x \notin U$：由 (N)，`fa[x] = x`，`find(x) = x`；而 $\mathrm{free}(x) = x$ ✔。
- $x < n$ 且 $x \in U$：由 (N)，`fa[x] = y > x`。歸納假設給出 `find(y) = free(y)`。又因為 $x \in U$，$\mathrm{free}(x) = \mathrm{free}(x+1)$。**還需要 $\mathrm{free}(y) = \mathrm{free}(x+1)$**——這由下面的維護論證保證：`fa[x]` 只會被設成 $x+1$，或（路徑壓縮時）設成某個 `find` 的結果，而後者依歸納假設是一個**空位**，且是 $\ge x+1$ 的第一個空位。兩種情形都滿足 $\mathrm{free}(y) = \mathrm{free}(x+1)$ ✔。$\square$

**(N) 的維護**：
- **`occupy(x)`（$x$ 原本是空位）**：令 `fa[x] = x + 1`。$x$ 加入 $U$，(N) 的第二行對 $x$ 成立；其他位置的 `fa` 不變，而它們的 $\mathrm{free}$ 值可能改變——**但由上面的歸納論證，`find` 仍會走到正確的答案**（因為指標鏈只是「往右跳」，終點由沿途每一格的即時狀態決定）✔。
- **路徑壓縮 `fa[x] = fa[fa[x]]`**：新值仍 $> x$，且它在鏈上，故 `find` 的終點不變 ✔。

**這個證明裡最值得注意的一句是「終點由沿途每一格的即時狀態決定」。** 也就是說：**`fa[x]` 不需要（也不可能）永遠等於 $\mathrm{free}(x)$，它只需要是一個「不會跳過任何空位」的中繼站。** 這正是為什麼 `occupy` 只寫一格就夠，不必更新所有指向 $x$ 的位置。

**推論（絕不會跳過空位）**：`fa[x] > x` 只發生在 $x \in U$ 時，故鏈上經過的每一格都是已佔用的。**「跳過的一定是已佔用的」是這個結構的安全性核心。**

### 定理 2（1488 避免洪水：取「最早的可用抽水日」是安全的）

*問題*：第 $i$ 天若 `rains[i] > 0` 則該湖蓄滿水；若 `rains[i] == 0` 則可以選一個湖抽乾。同一個湖在未抽乾前再次下雨就氾濫。求一組可行的抽水安排。

**演算法**：掃描每一天。遇到湖 $L$ 下雨且 $L$ 上次下雨是第 $t$ 天 ⇒ 必須在 $(t, i)$ 之間找一個晴天抽 $L$。**用本節的結構取 $\ge t+1$ 的第一個未使用晴天**；找不到（或 $\ge i$）則無解。

**命題**：取最早的可用晴天是安全的——若存在任何可行解，這樣做也能得到可行解。

*證明（交換論證）*。設存在可行解 $O$，且 $O$ 與貪心在前 $k-1$ 次「必須抽水」的決策上一致，在第 $k$ 次分歧：貪心選晴天 $d$，$O$ 選晴天 $d'$，且由貪心的「取最早」有 $d < d'$（$d$ 在當時可用，而 $O$ 前面的決策與貪心相同，故 $d$ 在 $O$ 中也未被前 $k-1$ 次使用）。

$O$ 中的 $d$ 有兩種情形：
- **$d$ 未被 $O$ 使用**：把 $O$ 的第 $k$ 次決策從 $d'$ 改成 $d$。合法性：$d$ 落在 $(t, i)$ 內（貪心找到它時已檢查），故抽 $L$ 有效 ✔。
- **$d$ 被 $O$ 用於抽另一個湖 $L'$**：則 $L'$ 的約束區間 $(t', i')$ 包含 $d$。**交換兩者**：$L$ 改在 $d$ 抽、$L'$ 改在 $d'$ 抽。$L$ 合法同上；$L'$ 合法需要 $d' \in (t', i')$——由 $d' > d > t'$ 得下界；上界需要 $d' < i'$。**這裡用到「第 $k$ 次分歧的約束右端 $i$ 是所有尚未處理的必須抽水事件中最早的」**：因為我們按天掃描，$i' \ge i > d'$ ✔。

兩種情形都得到一個與貪心一致更久的可行解，矛盾於 $k$ 的最大性 ✔。$\square$

**這個證明點名的前提是「按天掃描，所以後面的截止日不會更早」。** 若題目允許亂序給出約束，交換論證的第二種情形就會失效。**看到「取最早可用資源」的貪心，永遠要問一句：後面的需求會不會有更緊的截止日？**

### 定理 3（1353 最多可以參加的會議數目：按結束日排序 + 取最早空位是最優的）

*演算法*：把會議按 `end` 遞增排序；對每個會議 $j$，取 $d = \texttt{find}(s_j)$，若 $d \le e_j$ 則參加並 `occupy(d)`，否則放棄。

**命題**：此貪心參加的會議數是最大值。

*證明（交換論證）*。把問題看成二分圖匹配：會議 $j$ 可以匹配天 $d \in [s_j, e_j]$，求最大匹配。設 $M^{*}$ 是一個最大匹配，且在所有最大匹配中，**與貪心在處理順序的前綴上一致最久**。設第一個分歧點是會議 $j$。

- **情形 1：貪心匹配 $j \mapsto d$，$M^{*}$ 不匹配 $j$。**
  由「前綴一致」，前面的會議在兩者中佔用同一組天，故 $d$ 在 $M^{*}$ 中未被前面的會議佔用。
  - 若 $d$ 在 $M^{*}$ 中完全空閒 ⇒ $M^{*} \cup \{(j,d)\}$ 更大，與最大性矛盾。
  - 若 $d$ 被某個**後面的**會議 $j'$ 佔用 ⇒ 把 $M^{*}$ 改成「$j \mapsto d$、$j'$ 不參加」。大小不變，仍是最大匹配，但前綴一致更久 ⇒ 矛盾 ✔。
- **情形 2：貪心不匹配 $j$，$M^{*}$ 匹配 $j \mapsto d$。**
  貪心放棄 $j$ 表示 $[s_j, e_j]$ 中**每一天都已被前面的會議佔用**；由前綴一致，$M^{*}$ 中這些天也被同樣的會議佔用。那 $M^{*}$ 無法再把 $d \in [s_j,e_j]$ 分給 $j$ ⇒ **此情形不可能發生** ✔。
- **情形 3：兩者都匹配 $j$，但天不同：貪心 $j \mapsto d$、$M^{*} : j \mapsto d'$。** 由貪心取最早可用天，$d < d'$。
  - 若 $d$ 在 $M^{*}$ 中空閒 ⇒ 直接改成 $j\mapsto d$ ✔。
  - 若 $d$ 被後面的會議 $j'$ 佔用 ⇒ **交換**：$j \mapsto d$、$j' \mapsto d'$。合法性檢查：$s_{j'} \le d < d'$ 給出下界；**$d' \le e_j \le e_{j'}$ 給出上界——這裡用到「按 `end` 遞增排序」，所以後處理的會議截止日不會更早** ✔。
  兩種情形都讓前綴一致更久 ⇒ 矛盾 ✔。$\square$

**三個情形窮盡了所有可能，且每一個都導出矛盾，故貪心即最優。** 注意情形 3 的合法性驗證是整個證明中唯一用到排序條件的地方——**排序不是為了方便，是正確性的前提。** 若改成按 `start` 排序，情形 3 就會失效，而且真的會出錯（例如 `[[1,2],[1,1]]` 按 start 排序可能先把第 1 天分給 `[1,2]`，導致 `[1,1]` 無日可用）。

### 定理 4（2334：按值遞減加入，插入時檢查即可）

*問題*：找一個子陣列，使得**其中每個元素都大於 $\texttt{threshold}/k$**（$k$ 為子陣列長度）。回傳任一個滿足的 $k$，不存在回傳 $-1$。

*等價條件*：子陣列的**最小值** $v$ 與長度 $k$ 滿足 $v \cdot k > \texttt{threshold}$。

**演算法**：把所有位置按值**遞減**排序，依序「啟用」。啟用位置 $p$ 時，與左右已啟用的鄰居合併，得到所在區段長度 $k$；若 $\text{nums}[p] \cdot k > \texttt{threshold}$ 則回傳 $k$。

**命題**：存在合法子陣列 $\iff$ 演算法在某次插入時回傳。

*證明*。
- **($\Leftarrow$ 回傳的必合法)**：插入 $p$ 時，同一區段中的所有元素都**已被啟用**，即值都 $\ge \text{nums}[p]$。故該區段的最小值 $\ge \text{nums}[p]$，而 $\text{nums}[p]\cdot k > \texttt{threshold}$ ⇒ 每個元素都 $> \texttt{threshold}/k$ ✔。
- **($\Rightarrow$ 合法的必被抓到)**：設合法子陣列為 $[l, r]$，長度 $k_0$，最小值 $v_0$ 出現在位置 $p_0$，即 $v_0 k_0 > \texttt{threshold}$。當演算法啟用 $p_0$ 時，$[l,r]$ 中其餘位置的值都 $\ge v_0$，故**都已啟用**（遞減順序）。因此 $p_0$ 所在區段包含整個 $[l,r]$，長度 $k \ge k_0$，於是 $\text{nums}[p_0]\cdot k = v_0 k \ge v_0 k_0 > \texttt{threshold}$，演算法回傳 ✔。$\square$

**「按值排序後逐一啟用，使得任何時刻已啟用集合恰為 $\{\text{值} \ge v\}$」是一個極常用的套路**（8.2 定理 4 的 778 是它的無向圖版本）。**本節的貢獻只是把「合併相鄰」這件事做成 $O(\alpha)$。**

### 定理 5（2382：倒序加回 + 正值保證答案單調）

*問題*：依 `removeQueries` 的順序刪除元素，每次刪除後回報「最大的連續非刪除子段和」。

**演算法**：倒序（8.2 定理 1）——從全刪光開始，逐一加回，加回時與左右已存在的段合併，在根上維護段和，維護一個全域 `best`，答案倒著填。

**命題**：`best` 在加回過程中**單調不減**，所以「維護一個全域最大值」是對的。

*證明*：設加回位置 $p$（值 $x$），其左段和為 $A$、右段和為 $B$（不存在則為 0）。新段和為 $A + x + B$。**題目保證 $\text{nums}[i] \ge 1$**，故 $A + x + B > \max(A, B)$——**被消滅的兩個段（$A$ 與 $B$）都被一個更大的段取代**，其他段不受影響。故所有段和的最大值不減 ✔。$\square$

**這個「單向失效」的論證與 6.6（懶刪除堆）、5.1（1429 第一個唯一數字）是同一個形狀：只要能證明「被移除的候選一定被更好的候選取代」，就可以只維護一個全域最大值，不需要真的維護整個集合。**

**前提是「所有元素非負」，必須點名。** 若 `nums` 可以有負數，$A + x + B$ 可能小於 $\max(A,B)$，此時全域最大值可能下降，就必須用 `multiset` 維護所有段和（或線段樹）。

## C++17 模板

**模板一：1353 最多可以參加的會議數目**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    int maxEvents(vector<vector<int>>& events) {
        int maxDay = 0;
        for (auto& e : events) maxDay = max(maxDay, e[1]);
        fa.resize(maxDay + 2);  // 天數 1..maxDay，哨兵 maxDay+1
        iota(fa.begin(), fa.end(), 0);

        sort(events.begin(), events.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] < b[1];
             });

        int ans = 0;
        for (auto& e : events) {
            int d = find(e[0]);  // >= start 的第一個空閒日
            if (d <= e[1]) {
                ++ans;
                fa[d] = d + 1;  // 佔用 d
            }
        }
        return ans;
    }
};
```

**模板二：1488 避免洪水氾濫（`set` 版與並查集版對照）**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    vector<int> avoidFlood(vector<int>& rains) {
        int n = rains.size();
        fa.resize(n + 1);
        iota(fa.begin(), fa.end(), 0);  // fa[i] = >= i 的第一個晴天
        // 先把所有雨天標成「不可用」
        for (int i = 0; i < n; ++i)
            if (rains[i] > 0) fa[i] = i + 1;

        unordered_map<int, int> last;  // 湖 -> 上次下雨的日子
        vector<int> ans(n, 1);
        for (int i = 0; i < n; ++i) {
            if (rains[i] == 0) continue;
            ans[i] = -1;
            int lake = rains[i];
            auto it = last.find(lake);
            if (it != last.end()) {
                int d = find(it->second + 1);  // 最早的可用晴天（定理 2）
                if (d >= i) return {};         // 無解
                ans[d] = lake;
                fa[d] = d + 1;  // 該晴天用掉了
            }
            last[lake] = i;
        }
        return ans;
    }
};
```

（`set<int> sunny` + `lower_bound` 是等價的解法，**程式更短、複雜度 $O(n\log n)$ 有保證、而且支援「把晴天放回去」**。本節的並查集版本勝在常數與「不需要刪除」的場景。）

```cpp
        long long best = 0;
        for (int q = n - 1; q >= 1; --q) {  // 倒序，ans[n-1] = 0
            int p = removeQueries[q];
            alive[p] = true;
            sum[p] = nums[p];
            if (p > 0 && alive[p - 1]) {  // 與左段合併
                int r = find(p - 1);
                sum[p] += sum[r];
                fa[r] = p;
            }
            if (p + 1 < n && alive[p + 1]) {  // 與右段合併
                int r = find(p + 1);
                sum[p] += sum[r];
                fa[r] = p;
            }
            best = max(best, sum[p]);  // 定理 5：單調不減
            ans[q - 1] = best;
        }
        return ans;
    }
};
```

（**合併時一律把根設成 $p$**，這樣 `sum[p]` 就是新段的和；犧牲了按大小合併，換來程式簡潔。$n \le 10^5$ 完全夠用。）

## 時間與空間複雜度

| 操作 | 時間 |
| --- | --- |
| `find` | 攤還近乎常數（見下方討論） |
| `occupy` | $O(1)$ |
| 初始化 | $O(n)$ |

**這裡必須誠實：本節的寫法 A 放棄了按大小／按秩合併**（合併方向被語意固定為「指向右」），所以不能直接引用 8.1 的 $O(\alpha(n))$ 保證。

- **只用路徑壓縮的一般上界**是 $O\!\big(m\log_{1+m/n} n\big)$；$m = \Theta(n)$ 時即 $O(n\log n)$。
- **但本節的合併模式非常特殊（永遠是「$i$ 與 $i+1$ 合併」，即區間並查集）**，這個特例有更緊的分析（Gabow–Tarjan 的靜態樹並查集可做到 $O(n)$）。**完整證明超出本節範圍**，這裡只點明：**寫法 A 的實測表現接近線性，但它的最壞界不是 $O(\alpha)$；需要嚴格保證時用寫法 B。**

各題：

| 題目 | 時間 | 空間 | 瓶頸 |
| --- | --- | --- | --- |
| 1353 | $O(m\log m + D)$ | $O(D)$，$D$ = 最大天數 | **排序** |
| 1488 | $O(n)$ 近乎 | $O(n)$ | — |
| 2382 | $O(n)$ 近乎 | $O(n)$ | — |
| 2334 | $O(n\log n)$ | $O(n)$ | **按值排序** |

**又一次：瓶頸幾乎都在排序，不在並查集。** 這與 8.2、8.3 的結論一致——**並查集是這些題裡最便宜的部分。**

**與 `std::set` 解法的比較（這是本節最實際的決策）：**

| | 並查集（本節） | `set<int>` + `lower_bound` |
| --- | --- | --- |
| 單次查詢 | 攤還近乎 $O(1)$ | $O(\log n)$ 保證 |
| 常數 | 小（陣列，cache 友善） | 大（紅黑樹，指標跳躍） |
| **支援「放回去」** | **不支援** | **支援（`insert`）** |
| 程式長度 | 中 | 短 |

**實測上並查集快 2～5 倍，但 `set` 版更短更不容易錯，而且能處理「資源會被釋放」的變形。** 面試中先寫 `set` 版說清楚思路，再提「可以用並查集把 $\log$ 去掉」是很好的回答。

## 常見錯誤與邊界條件

- **陣列開成 `n` 而不是 `n + 1`（缺哨兵）**。所有位置佔滿時 `find` 走到 `fa[n]` 越界。**這是本節最經典的越界，而且往往只在極端測資才觸發。**
- **`occupy(i)` 傳入未經 `find` 的位置**。正確寫法是 `int d = find(i); ...; fa[d] = d + 1;`。若直接寫 `fa[i] = i + 1`，當 $i$ 本來就已被佔用時，會**覆蓋掉一條已壓縮的捷徑**——結果不是錯誤答案（不變量 (N) 仍成立，因為 $i+1$ 仍不跳過空位），而是**效能退化**。但若 $i$ 是空位而你並未真的使用它，那就是**真的錯了**（憑空吃掉一個空位）。
- **忘記檢查 `find` 的回傳是否為哨兵**。1353 要檢查 `d <= end`，1488 要檢查 `d < i`。**漏檢會用到一個不存在的位置。**
- **把本節的結構拿去問「$x$ 與 $y$ 連通嗎」**。`find(x) == find(y)` 在這裡的意思是「它們右邊的第一個空位相同」，**與連通性無關**。
- **雙向需求只開一個陣列**。要同時找左邊與右邊的空位，必須開兩個獨立陣列並在佔用時**都更新**。
- **1488 忘記把雨天標成不可用**。雨天不能抽水，初始化時就要 `fa[i] = i + 1`。
- **1488 的 `ans` 初值**。晴天若沒被指派抽水，答案可以是任意合法湖編號（題目要求 $\ge 1$），**初值填 1 而不是 0 或 -1**。
- **2382 的和要用 `long long`**。$n \le 10^5$、$\text{nums}[i] \le 10^9$ ⇒ 總和可達 $10^{14}$。
- **2382 的答案錯位**。刪除第 $q$ 次之後的答案，對應「加回到剩 $q$ 個被刪」的狀態。**寫的時候用具體小例子（$n=2$）驗證一次索引。**
- **2334 相同值的處理**。按值遞減排序時，相同值的位置可以任意順序啟用——**由定理 4 的證明，只要「所有 $\ge v$ 的都已啟用」，順序無關**，但要確認排序是穩定或不影響結果。
- **遞迴版 `find` 爆堆疊**。初始鏈長可達 $n$，$n = 10^5$ 的遞迴在某些環境會 stack overflow。**用迭代版。**

## 與相似技巧的比較

- **與 8.1／8.2／8.3**：**語意完全不同**。那三節的 `fa` 是等價類代表元，本節的 `fa` 是「下一個候選」。**唯一共用的是路徑壓縮這個機制。** 用等價類的直覺理解本節會處處卡住。
- **與 `std::set` + `lower_bound`**：功能上 `set` 更強（支援放回、複雜度有保證），並查集更快更省。**判準：資源會不會被釋放。** 會 ⇒ 只能用 `set`；不會 ⇒ 兩者皆可，看你要短還是要快。
- **與線段樹上二分**：維護一個 0/1 陣列，查詢「$\ge x$ 的第一個 1」。$O(\log n)$ 保證，**而且支援區間修改與釋放**，還能回答區間計數。**功能最強、程式最長。** 當題目同時需要「找空位」與「數某段有幾個空位」時，線段樹是唯一選擇（9.3）。
- **與 8.5 區間並查集**：8.5 處理的是「一次填滿一整段」，本節是「一次佔用一個點」。**兩者的不變量幾乎相同**——8.5 只是把 `occupy(d)` 換成「把整段的指標都指向段尾之後」，並靠路徑壓縮讓重疊部分只被掃一次。**看完本節再看 8.5，會發現它是同一個結構的區間版。**
- **與「合併相鄰區段」的變體（1562／2382）**：如「狀態／資料結構定義」所述，**那個變體的 `fa` 回到正統的等價類語意**（連通塊 = 一段連續的活躍區間），可以正常按大小合併、在根上掛聚合量。**它更像 8.2 而不像本節的寫法 A**，只是常常被歸在一起講。
- **與貪心／匹配理論**：本節的題目（1353、1488）的**難點在證明貪心正確，不在資料結構**。定理 2 與定理 3 都是交換論證，而且都在同一個地方用到「按截止日排序」這個前提。**先把貪心證對，再挑資料結構。**

## 本節重點速查

- **語意先講清楚**：本節的 `fa[i]` 是「**從 $i$ 出發下一個值得試的位置**」，不是等價類代表元。**不能拿來問連通性。** 借的只有路徑壓縮。
- **三個適用條件**：一維資源、**用了就永久失效**、反覆查「右邊第一個可用的」。
- **主不變量（定理 1）**：`find(x)` $=\ge x$ 的第一個空位。安全性核心是「**跳過的一定是已佔用的**」。`fa[x]` 不必等於答案，只要是「不跳過空位的中繼站」。
- **哨兵 `fa[n] = n` 不能省**，陣列開 `n + 1`。回傳 $n$ 表示沒有可用位置，**呼叫端一定要檢查**。
- **`occupy` 要傳 `find` 的結果**，不是原始位置。
- **寫法 A 放棄了按大小合併**（方向被語意固定），最壞界不是 $O(\alpha)$；要保證就用**寫法 B**（正統並查集 + 根上記 `nxt`）。
- **1488／1353 的難點是證貪心，不是資料結構。** 兩個交換論證都用到「按截止日／結束日排序，後面的截止日不會更早」——**排序是正確性前提，不是方便。**
- **2334**：按值**遞減**啟用 ⇒ 已啟用集合恆為 $\{\ge v\}$ ⇒ 插入時檢查 $v\cdot k > \texttt{threshold}$ 即可，不重不漏。
- **2382**：倒序加回 + **所有元素非負**（前提！）⇒ 段和最大值單調不減 ⇒ 只需維護一個全域 `best`。有負數就要 `multiset`。
- **雙向需求開兩個陣列**，佔用時兩個都更新。
- **`set` + `lower_bound` 是等價替代**：慢 2～5 倍但更短、複雜度有保證、**而且支援資源釋放**。同時要「找空位」又要「區間計數」⇒ 線段樹。
- **瓶頸幾乎都在排序**，不在並查集。
