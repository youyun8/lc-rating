## 這個技術解決什麼問題

8.4 處理的是「一次佔用**一個點**」。本節把它推廣到：

> **「把整段 $[l, r]$ 都標記掉，但每個位置一生只需要被真正處理一次。」**

暴力是每次操作跑一遍 $[l, r]$，$q$ 次操作最壞 $O(nq)$。可是**如果每個位置只需要被處理一次，那所有操作加起來的「真正工作量」上限就是 $n$**——問題只剩下「如何跳過已處理的位置」。

**這正是 8.4 的結構要做的事**：`fa[i]` 指向「從 $i$ 出發下一個未處理的位置」，於是

```cpp
for (int i = find(l); i <= r; i = find(i + 1)) {
    // 處理位置 i（一生只會進來這一次）
    fa[i] = i + 1;  // 標記為已處理
}
```

**這個五行迴圈就是本節的全部。** 它的攤還總成本是 $O((n + q)\,\alpha(n))$，不論每段有多長、操作有多少次。

**適用的關鍵前提（本節唯一需要小心的地方）**：

> **一個位置只需要被處理一次。**

有兩種常見的方式讓這個前提成立：
1. **先到先得**：問「這次操作**新**染了多少格」（2158）——已染的格子本來就不該再算。
2. **後蓋前 ⇒ 倒序變成先到先得**：問「所有區間賦值做完後每格是什麼顏色」（LCP 52）——**倒著處理操作，第一個蓋到某格的就是最終答案**，蓋過就不必再看。這與 8.2 定理 1 的倒序思想是同一招，只是那裡把「刪除」倒成「加入」，這裡把「覆蓋」倒成「首次寫入」。

**若前提不成立就不能用。** 例如「區間加 1，最後查每格的值」——每格會被處理很多次，總量不是 $O(n)$，必須用差分（第 3 章）或線段樹（9.3）。

**典型題**：2158 每天新增的漆補區域、LCP 52 二叉搜尋樹染色、1851 包含每個查詢的最小區間、3244 新增道路查詢後的最短距離 II。

## 狀態／資料結構定義

```cpp
struct IntervalDSU {
    vector<int> fa;  // fa[i] = 從 i 出發下一個未處理的位置
    explicit IntervalDSU(int n) : fa(n + 1) {  // n + 1：哨兵不可省
        iota(fa.begin(), fa.end(), 0);
    }
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }
    // 處理 [l, r] 中所有尚未處理的位置，回傳處理了幾個
    template <class F>
    int sweep(int l, int r, F&& f) {
        int cnt = 0;
        for (int i = find(l); i <= r; i = find(i + 1)) {
            f(i);
            fa[i] = i + 1;
            ++cnt;
        }
        return cnt;
    }
};
```

**與 8.4 的差別只有一行**：8.4 呼叫一次 `find` 就結束，本節用 `for` 迴圈掃到 $r$ 為止。**不變量、哨兵、路徑壓縮全部相同。**

**三個實作細節：**

- **`i = find(i + 1)` 而不是 `i = i + 1`。** 寫成 `++i` 就退化成暴力，複雜度回到 $O(nq)$——而且因為結果仍然正確，你只會看到 TLE 而不是 WA，很難察覺。
- **`fa[i] = i + 1` 必須在迴圈體內。** 漏掉會無窮迴圈（`find(i+1)` 之後 `find` 又回到 $i$）。
- **哨兵**：`fa` 開 `n + 1` 個元素，`fa[n] = n`。當 $[l, r]$ 之後全滿時 `find` 回傳 $n$，迴圈條件 `i <= r` 自然終止（前提 $r < n$）。

**值域不是小整數時**：例如 LCP 52 的節點值可到 $10^9$。兩條路——**離散化**後用本結構，或**直接用 `set<int>`**：

```cpp
// set 版：語意完全相同，程式更短，支援任意值域與「放回去」
auto it = s.lower_bound(l);
while (it != s.end() && *it <= r) {
    f(*it);
    it = s.erase(it);
}
```
**`set` 版單次 $O(\log n)$ 有保證、程式短、值域任意；陣列版常數小 2～5 倍。** 值域大又不想離散化就用 `set`，這是本節最常見的實務選擇。

## 不變量或正確性證明

### 定理 1（`sweep` 恰好走訪 $[l,r]$ 中所有未處理位置，各一次）

沿用 8.4 定理 1 的不變量 (N)：`find(x)` $= \min\{\,j \ge x : j \text{ 未處理}\,\}$（無則回傳哨兵 $n$）。

*證明*。迴圈變數依序取值 $i_0 = \texttt{find}(l)$，$i_{k+1} = \texttt{find}(i_k + 1)$。
- **不漏**：由 (N)，$i_0$ 是 $\ge l$ 的第一個未處理位置；每輪把 $i_k$ 標為已處理後，$i_{k+1}$ 是 $\ge i_k+1$ 的第一個未處理位置。故 $(i_k)$ 恰為 $[l, \infty)$ 中未處理位置的遞增列舉，在 $> r$ 時停止 ✔。
- **不重**：每輪立刻執行 `fa[i] = i + 1`，且**標記不可逆**（沒有任何操作會把已處理位置改回未處理），故 $i$ 不會再次出現 ✔。$\square$

### 定理 2（攤還總成本 $O((n + q)\,\alpha(n))$）

*證明*。把所有 `find` 呼叫分成兩類：
- **成功迭代的 `find`**：每次都伴隨一個位置從「未處理」變成「已處理」。由**單向性**（定理 1 的不重論證），這種事件全域最多發生 $n$ 次。
- **終止的 `find`**：每次 `sweep` 恰好多做一次回傳值 $> r$ 的 `find`。$q$ 次操作就是 $q$ 次。

總 `find` 次數 $\le n + q$，每次攤還 $O(\alpha(n))$（實務上為小常數，最壞界的討論見 8.4「時間與空間複雜度」）✔。$\square$

**這個論證的形狀值得記下來：「每次昂貴的迭代都對應一個不可逆的狀態變化，而狀態變化總量有上界」。** 它與 8.1 定理 2′（節點深度增加 ⇒ 連通塊至少倍增）、4.7（單調堆疊每元素進出各一次）、6.6（懶刪除每元素刪一次）是同一個攤還模式。**這是資料結構章節反覆出現的主旋律。**

**定理 2 點名的前提是「標記不可逆」。** 若題目允許「取消染色」，這個界立刻崩潰——被取消的位置可以被反覆處理，總量無上界。此時必須改用線段樹。

### 定理 3（倒序把「後蓋前」變成「先到先得」）

*設定*：$q$ 個區間賦值操作依序執行，第 $t$ 個把 $[l_t, r_t]$ 全部設為 $c_t$。問最終每個位置的值。

**命題**：位置 $p$ 的最終值 $= c_{t^{*}(p)}$，其中 $t^{*}(p) = \max\{\,t : p \in [l_t, r_t]\,\}$。**倒序（$t$ 從 $q$ 到 $1$）掃描時，第一次覆蓋到 $p$ 的操作恰為 $t^{*}(p)$。**

*證明*。正序語意即「最後一次寫入獲勝」，故最終值為 $c_{t^{*}(p)}$（若無操作覆蓋 $p$ 則為初值）。倒序掃描時操作編號遞減，第一個滿足 $p \in [l_t, r_t]$ 的 $t$ 就是這類 $t$ 中的最大者，即 $t^{*}(p)$ ✔。$\square$

**推論**：倒序之下每個位置只需被處理一次，定理 2 的前提成立，總複雜度 $O((n+q)\alpha)$。

**這個轉換的價值在於它把一個「必須支援區間覆蓋」的問題，變成一個「只需要支援一次性標記」的問題。** LCP 52 就是這樣：正序做要區間賦值（線段樹 + 懶標記），倒序做只要一個 `set` 加二十行。

**適用邊界**：倒序法要求**離線**（所有操作事先已知），且**查詢只在最後**。若中途穿插查詢，倒序就失去意義——回到線段樹。

### 定理 4（1851：按長度遞增分配，每個查詢被最短的覆蓋區間接住）

*問題*：給定區間集合與若干查詢 $x$，對每個 $x$ 求「包含 $x$ 的最短區間長度」（無則 $-1$）。

**演算法**：把查詢**排序**成 $x_0 \le x_1 \le \cdots \le x_{m-1}$（記住原始下標）。把區間按**長度遞增**排序。依序處理每個區間 $[l, r]$：用二分找出查詢陣列中值落在 $[l, r]$ 的下標範圍 $[a, b]$，對這段中**尚未被回答**的查詢，填入本區間的長度並標記為已回答。

**命題**：每個查詢得到的是包含它的最短區間長度。

*證明*。
- **每個查詢至多被回答一次**（標記不可逆），且回答它的是**處理順序中第一個**包含它的區間。
- 區間按長度遞增處理 ⇒ 第一個包含 $x$ 的區間就是**包含 $x$ 的最短區間** ✔（長度相同時取誰都對，因為答案只要長度）。
- 若無區間包含 $x$，則 $x$ 始終未被標記，輸出 $-1$ ✔。$\square$

**這個證明依賴兩個前提，都必須點名：**
1. **查詢已排序** ⇒ 「值落在 $[l,r]$ 的查詢」在陣列上是**連續一段**，才能用本節的區間掃描。若不排序，這些查詢散落各處，區間並查集就無從下手。
2. **區間按長度遞增** ⇒ 「先到」等於「最短」。

**這是把非區間問題「掰成」區間問題的典型手法：排序製造連續性。** 8.2 定理 4（778）用排序製造單調性，這裡用排序製造**連續性**——兩者都是「先排序，讓一個看似無序的集合獲得結構」。

### 定理 5（3244：不交叉前提下，答案 = 存活節點數 $-\,1$）

*問題*：節點 $0..n-1$，初始有道路 $i \to i+1$。每個查詢加入一條單向道路 $u \to v$（$u < v$），並回報 $0 \to n-1$ 的最短路長度。**題目保證任意兩個查詢不交叉**：不存在 $u_1 < u_2 < v_1 < v_2$。

**演算法**：加入 $u \to v$ 時，用 `sweep(u+1, v-1, ...)` 把中間所有尚存活的節點標記為**被吸收**，答案 $=n-1-(\text{累計被吸收數})$。

令 $A$ 為已吸收節點集，$S = \{0,\dots,n-1\}\setminus A$，把 $S$ 遞增排成 $p_0 < p_1 < \cdots < p_m$。注意 $0, n-1$ 永不被吸收（吸收只發生在 $(u,v)$ 內部，而 $0 \le u < v \le n-1$），故 $p_0 = 0$、$p_m = n-1$。

**不變量 (B)**：任何時刻，對每個 $k < m$ 都存在一條道路 $p_k \to p_{k+1}$。

*證明（對操作次數歸納）*。初始 $S$ 為全體，$p_{k+1} = p_k + 1$，鏈上道路即是 ✔。
設加入道路 $(u, v)$：
- **若 $u \in A$**：$u$ 被某條先前道路 $(u', v')$ 吸收，即 $u' < u < v'$。不交叉條件排除 $u' < u < v' < v$，故 $v \le v'$。於是 $(u,v)$ 的內部 $\subseteq (u',v')$ 的內部，**早已全被吸收**，本次操作不改變 $S$，(B) 自動保持 ✔。
- **若 $v \in A$**：同理存在 $(u',v')$ 使 $u' < v < v'$；不交叉排除 $u < u' < v < v'$，故 $u' \le u$；而 $u \in S$ 表示 $u$ 不在 $(u',v')$ 內部，故 $u' \ge u$，得 $u' = u$。於是道路 $(u, v')$ 已存在且 $(u,v)$ 內部已全被吸收，$S$ 不變 ✔。
- **$u, v \in S$**：操作把 $(u,v)$ 內所有存活節點吸收。**新的 $S$ 中，$u$ 的後繼恰為 $v$，而道路 $(u,v)$ 剛剛加入** ✔；其餘相鄰對不受影響 ✔。$\square$

**命題**：最短路長度 $= m = |S| - 1$。

*證明*。
- **上界**：由 (B)，$0 = p_0 \to p_1 \to \cdots \to p_m = n-1$ 是一條長度 $m$ 的合法路徑 ✔。
- **下界**：定義 $r(x) = |\{p \in S : p \le x\}|$。**宣稱任何一條道路 $x \to y$ 都滿足 $r(y) - r(x) \le 1$。**
  - 鏈上道路 $i \to i+1$：$r$ 至多增加 1 ✔。
  - 加入的道路 $(u,v)$：加入時 $(u,v)$ 的內部已全被吸收，而**吸收不可逆**，故此後恆有 $S \cap (u,v) = \varnothing$，即 $r(v) - r(u) \le 1$ ✔。

  於是任何 $0 \to n-1$ 的路徑長度 $\ge r(n-1) - r(0) = (m+1) - 1 = m$ ✔。$\square$

**上下界都證了，等號成立。** 注意下界論證裡「吸收不可逆」又出現了一次——**它同時撐起了複雜度（定理 2）與正確性（本定理的下界）**，是這個結構的樞紐性質。

**不交叉前提用在哪裡？** 只用在 (B) 的歸納中。**它是必要的**：若允許交叉，先加 $(0,5)$ 吸收 $1..4$，再加 $(3,8)$ 吸收 $5..7$，此時 $S = \{0, 8, 9, \dots\}$，但**根本不存在 $0 \to 8$ 的道路**，(B) 崩潰，答案也就錯了。（這正是 3243「最短距離 I」與 3244「II」的差別：I 沒有不交叉保證，只能每次重跑 BFS。）

## C++17 模板

**模板一：2158 每天新增的漆補區域**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    vector<int> amountPainted(vector<vector<int>>& paint) {
        int maxEnd = 0;
        for (auto& p : paint) maxEnd = max(maxEnd, p[1]);
        fa.resize(maxEnd + 2);  // 位置 0..maxEnd-1，留哨兵
        iota(fa.begin(), fa.end(), 0);

        vector<int> ans;
        ans.reserve(paint.size());
        for (auto& p : paint) {
            int l = p[0], r = p[1] - 1;  // [start, end) -> 閉區間 [l, r]
            int cnt = 0;
            for (int i = find(l); i <= r; i = find(i + 1)) {
                fa[i] = i + 1;  // 標記已漆
                ++cnt;
            }
            ans.push_back(cnt);
        }
        return ans;
    }
};
```

**模板二：3244 新增道路查詢後的最短距離 II**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    vector<int> shortestDistanceAfterQueries(int n,
                                             vector<vector<int>>& queries) {
        fa.resize(n + 1);
        iota(fa.begin(), fa.end(), 0);  // fa[i] = 下一個存活節點

        int cur = n - 1;  // 目前最短路長度 = 存活節點數 - 1
        vector<int> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            int u = q[0], v = q[1];
            for (int i = find(u + 1); i < v; i = find(i + 1)) {
                fa[i] = i + 1;  // 節點 i 被吸收
                --cur;
            }
            ans.push_back(cur);
        }
        return ans;
    }
};
```

**模板三：1851 包含每個查詢的最小區間**

```cpp
class Solution {
    vector<int> fa;
    int find(int x) {
        while (fa[x] != x) {
            fa[x] = fa[fa[x]];
            x = fa[x];
        }
        return x;
    }

public:
    vector<int> minInterval(vector<vector<int>>& intervals,
                            vector<int>& queries) {
        int m = queries.size();
        vector<int> idx(m);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(),
             [&](int a, int b) { return queries[a] < queries[b]; });
        vector<int> qs(m);  // 排序後的查詢值
        for (int i = 0; i < m; ++i) qs[i] = queries[idx[i]];

        sort(intervals.begin(), intervals.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] - a[0] < b[1] - b[0];  // 按長度遞增
             });

        fa.resize(m + 1);
        iota(fa.begin(), fa.end(), 0);
        vector<int> ans(m, -1);
        for (auto& it : intervals) {
            int l = it[0], r = it[1];
            int a = lower_bound(qs.begin(), qs.end(), l) - qs.begin();
            int b = int(upper_bound(qs.begin(), qs.end(), r) - qs.begin()) - 1;
            for (int i = find(a); i <= b; i = find(i + 1)) {
                ans[idx[i]] = r - l + 1;  // 定理 4：先到即最短
                fa[i] = i + 1;
            }
        }
        return ans;
    }
};
```

（1851 的**主流解法是排序 + 最小堆**，複雜度相同、程式更短。這裡放並查集版是為了展示「排序製造連續性」這個轉換——**遇到「每個查詢只需要被第一個符合條件的東西回答」時，這個模式可以直接套用。**）

## 時間與空間複雜度

| | 時間 | 空間 |
| --- | --- | --- |
| 核心結構 | $O((n + q)\,\alpha(n))$ 攤還（定理 2） | $O(n)$ |
| 2158 | $O(M + q)$ 近乎，$M$ = 最大端點 | $O(M)$ |
| 3244 | $O(n + q)$ 近乎 | $O(n)$ |
| LCP 52 | $O(n\log n)$（`set` 版） | $O(n)$ |
| 1851 | $O(n\log n + m\log m)$ | $O(n + m)$ |

**再一次：瓶頸在排序或 `set`，不在並查集本身。** 2158 與 3244 完全沒有 $\log$，是真正的近線性。

**與寫法 A 相同的誠實聲明**（詳見 8.4）：合併方向被語意固定為「指向右」，**不能按大小合併**，所以嚴格的最壞界不是 $O(\alpha)$；但這個特殊形態（總是與右鄰合併）實測接近線性。**需要嚴格保證時改用 8.4 的寫法 B**（正統並查集 + 根上記 `nxt`）。

**空間陷阱**：2158 的端點可到 $5\times10^4$，開陣列沒問題；但若題目端點到 $10^9$，就**必須離散化或改用 `set`**——盲目 `resize(maxEnd + 2)` 會直接 MLE。

## 常見錯誤與邊界條件

- **迴圈遞增寫成 `++i`**。`for (int i = find(l); i <= r; ++i)` 結果正確但退化成 $O(nq)$。**這是本節最隱蔽的錯誤：不是 WA 而是 TLE。** 必須是 `i = find(i + 1)`。
- **忘記在迴圈內寫 `fa[i] = i + 1`**。`find(i+1)` 之後 `find` 仍回到 $i$，**無窮迴圈**。
- **哨兵沒開**。`fa` 要 `n + 1` 個元素。$[l,r]$ 之後全滿時 `find` 讀 `fa[n]`。
- **半開／閉區間搞混**。2158 的 `paint[i] = [start, end)` 對應**位置 `start..end-1`**，寫成 `r = p[1]` 會多漆一格。**下筆前先確認題目的區間是開是閉。**
- **在「區間累加」的題目上套用本節結構**。前提是「每格只處理一次」；累加類每格會被處理多次，總量無上界。**用差分或線段樹。**
- **忘記倒序**。「區間賦值，最後查每格顏色」正序做需要懶標記；**倒序才能用本節結構**（定理 3）。中途有查詢就不能倒序。
- **1851 忘記還原原始順序**。查詢排序後要記住原下標，填答案時寫 `ans[idx[i]]`。
- **1851 的二分邊界**。`b` 用 `upper_bound(r) - 1`；若 $a > b$（沒有查詢落在區間內）迴圈自然不執行，不必特判——但 `find(a)` 要求 $a \le m$，由 `lower_bound` 的性質這永遠成立。
- **3244 的掃描範圍是 `[u+1, v-1]`**。掃 `[u, v]` 會把端點也吸收掉，答案全錯。
- **3244 誤用在 3243 上**。3243 沒有不交叉保證，(B) 不成立（見定理 5 的反例），必須每次重跑 BFS。**兩題只差一個約束，解法完全不同。**
- **值域大時直接開陣列**。$10^9$ 的值域要離散化或用 `set`。
- **遞迴版 `find` 爆堆疊**。初始鏈長可達 $n$。用迭代版。

## 與相似技巧的比較

- **與 8.4**：**同一個不變量，同一個哨兵，同一個路徑壓縮。** 差別只在 8.4 呼叫一次 `find`，本節用迴圈掃到 $r$。**先讀 8.4 再讀本節，會發現本節幾乎沒有新東西——新的只有「攤還總量 $\le n$」這個論證（定理 2）。**
- **與 `set<int>` + `lower_bound`／`erase`**：語意完全等價，**值域任意（不必離散化）、複雜度 $O(\log n)$ 有保證、而且支援把元素放回去**。代價是常數大 2～5 倍。**判準：值域小且不需要放回 ⇒ 陣列版；否則 `set`。** LCP 52 的節點值到 $10^9$，`set` 是自然選擇。
- **與珂朵莉樹（ODT，`map` 維護值相同的極長區間）**：ODT 支援**真正的重複區間賦值**與區間查詢，功能比本節強得多。**它的複雜度依賴「隨機資料下區間數量期望為 $O(\log n)$」，在有意構造的資料上會退化**——競賽中要小心，LeetCode 上通常安全。**若題目要求「多次區間賦值 + 中途查詢」，ODT 或線段樹是正解，本節不適用。**
- **與線段樹（區間賦值 + 懶標記，9.3）**：功能最強——支援中途查詢、支援取消、支援區間聚合，$O(\log n)$ 有保證。**代價是程式長 5 倍。** 當「每格只處理一次」的前提被打破時（有撤銷、有累加、有中途查詢），線段樹是唯一出路。
- **與差分（第 3 章）**：「區間加、最後查」用差分 $O(n + q)$，比什麼都快。**差分不能做區間賦值，本節不能做區間累加——兩者互補，別搞混。**
- **與掃描線**：掃描線把區間事件排序後一次掃過，也能算「總覆蓋長度」（如 2158 的變形）。**差別在掃描線需要離線且輸出是聚合量；本節可以線上回答「這次新增了多少」。** 2158 恰好要求每次操作的增量，本節更直接。
- **與 8.1／8.2／8.3**：那三節的 `fa` 是**等價類代表元**；本節與 8.4 的 `fa` 是**下一個未處理位置**。**不要混用直覺。** 唯一的共同點是路徑壓縮這個機制。

## 本節重點速查

- **核心是五行迴圈**：`for (int i = find(l); i <= r; i = find(i + 1)) { 處理 i; fa[i] = i + 1; }`。**遞增一定要 `find(i + 1)`，`++i` 會 TLE 但不會 WA。**
- **唯一的適用前提**：**每個位置一生只需要被處理一次**。兩種來源——「先到先得」（2158）或「**倒序讓後蓋前變成先到先得**」（LCP 52，定理 3）。
- **攤還 $O((n+q)\alpha)$（定理 2）**：成功迭代 $\le n$ 次（不可逆），終止 `find` $\le q$ 次。**「昂貴迭代對應不可逆狀態變化」是資料結構章反覆出現的攤還模式**（4.7、6.6、8.1 定理 2′ 同形）。
- **「標記不可逆」同時撐起複雜度與正確性**——3244 的下界論證也用它。有撤銷就整套崩潰，改用線段樹。
- **哨兵 `fa[n] = n` 不可省**；閉區間 vs 半開區間要對清楚（2158 是 $[\text{start}, \text{end})$）。
- **1851**：**排序製造連續性**——查詢排序後「落在 $[l,r]$ 的查詢」才是連續一段；區間按長度遞增 ⇒ 先到即最短。答案要用 `ans[idx[i]]` 還原原順序。
- **3244**：答案 $=$ 存活節點數 $-1$，掃描範圍是 **$[u+1, v-1]$**。**不交叉前提是必要的**，`(0,5)` 後接 `(3,8)` 就是反例——這也是 3243 不能這樣做的原因。
- **值域大就用 `set` + `lower_bound`／`erase`**：語意等價、值域任意、$O(\log n)$ 保證、支援放回；只是常數大。
- **不能做區間累加**（用差分）、**不能做中途查詢的多次區間賦值**（用 ODT 或線段樹）。
