## 這個技術解決什麼問題

普通並查集只能回答「$x$ 與 $y$ 同一類嗎」。但很多題目給的不是「同類」，而是**帶量的相對關係**：

- $a / b = 2.0$、$b / c = 3.0$，問 $a / c$（399 除法求值）；
- $a - b = 5$、$b - c = -2$，問 $a - c$；
- $a$ 與 $b$ 奇偶性相同、$b$ 與 $c$ 相異，問 $a$ 與 $c$。

這些關係都有兩個共通性質：

1. **可傳遞、可合成**：知道 $x \to y$ 與 $y \to z$ 就能算出 $x \to z$；
2. **可逆**：知道 $x \to y$ 就能算出 $y \to x$。

**這正是「群」的定義。** 帶權並查集把每條 `fa` 邊掛上一個群元素 $w[x] = \mathrm{rel}(x, \texttt{fa}[x])$，於是：

> **$x$ 與 $y$ 的關係 $=$（$x$ 到根的合成）$\ominus$（$y$ 到根的合成）。**

只要兩者同根，關係就能在近乎 $O(1)$ 內算出——**而且根本不需要知道任何一個變數的絕對值。**

**它同時解決三件事**：
- **查詢**：回答任兩個同組元素之間從未被直接給出的關係；
- **合併**：把兩組用一條新關係接起來；
- **矛盾偵測**：新關係若連接兩個**已同組**的元素，就必須與既有推導一致，否則整個方程組無解（2307）。

**辨識訊號**：題目給的是**成對的相對量**（比值、差值、同餘、奇偶），要你推導未給出的配對，或判斷是否自相矛盾。

**它做不到的事（必須先講清楚）**：**帶權並查集永遠回答不了絕對值。** 每個連通塊的根可以被賦予任意值，整塊隨之伸縮而所有相對關係不變。若題目要求具體數值（例如「$a$ 等於多少」），要嘛題目另給了錨點，要嘛這個工具就不對。

## 狀態／資料結構定義

**權值群 $(G, \oplus, e, \ominus)$**：$\oplus$ 為合成、$e$ 為單位元、$\ominus$ 為逆元。常見選擇：

| 關係 | $G$ | $\oplus$ | $e$ | 逆元 |
| --- | --- | --- | --- | --- |
| 比值 $a/b$ | $(\mathbb{R}^{+}, \times)$ | 乘 | $1$ | 倒數 |
| 差值 $a-b$ | $(\mathbb{Z}, +)$ | 加 | $0$ | 取負 |
| 奇偶／同／異 | $(\mathbb{Z}_2, \oplus)$ | XOR | $0$ | 自身 |
| 模 $k$ 偏移 | $(\mathbb{Z}_k, +)$ | 模加 | $0$ | $k - a \bmod k$ |

**交換律不是必要的**（合成順序在實作中是固定的），但實務上遇到的權值群幾乎都是交換群。

**資料結構**（以加法群為例）：

```cpp
struct WeightedDSU {
    vector<int> fa, sz;
    vector<long long> w;  // w[x] = rel(x, fa[x])，即 val[x] - val[fa[x]]
    explicit WeightedDSU(int n) : fa(n), sz(n, 1), w(n, 0) {
        iota(fa.begin(), fa.end(), 0);
    }
    int find(int x) {  // 遞迴版最不容易寫錯
        if (fa[x] == x) return x;
        int r = find(fa[x]);
        w[x] += w[fa[x]];  // 先累積（此時 w[fa[x]] 已是「到根」）
        fa[x] = r;         // 再改指標
        return r;
    }
};
```

**`find` 裡那兩行的順序是本節最容易寫錯的地方。** `w[x] += w[fa[x]]` 必須在遞迴**之後**、改 `fa[x]` **之前**：遞迴保證了 `w[fa[x]]` 已經是「`fa[x]` 到根」的合成，加完 `w[x]` 才變成「$x$ 到根」；一旦先寫 `fa[x] = r`，`w[fa[x]]` 就變成 `w[r] = 0`，權值靜靜地歸零而程式照跑。**這個 bug 不會崩、不會警告，只會給出錯誤答案。**

**合併**（記錄 $\mathrm{rel}(x, y) = v$，即 $\mathrm{val}(x) - \mathrm{val}(y) = v$）：

```cpp
// 回傳 false 表示矛盾
bool unite(int x, int y, long long v) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return w[x] - w[y] == v;  // 一致性檢查
    if (sz[rx] > sz[ry]) {                  // 按大小合併：需要逆元
        fa[ry] = rx;
        w[ry] = w[x] - w[y] - v;  // 方向反轉 ⇒ 取負
        sz[rx] += sz[ry];
    } else {
        fa[rx] = ry;
        w[rx] = v + w[y] - w[x];
        sz[ry] += sz[rx];
    }
    return true;
}
// 查詢 rel(x, y)：同根才有意義
bool query(int x, int y, long long& res) {
    if (find(x) != find(y)) return false;
    res = w[x] - w[y];
    return true;
}
```

**按大小合併與帶權完全相容**——只要群有逆元，把邊反向時取負（乘法群取倒數）即可。**不要因為「權值有方向」就放棄平衡策略**，那會白白讓樹退化。

## 不變量或正確性證明

以下用加法記號（$\oplus = +$、$\ominus = -$），乘法版把加改乘、減改除即可。設每個元素有一個**虛擬值** $\mathrm{val}(\cdot)$（實際上並不儲存）。

### 定理 1（主不變量與 `find` 的正確性）

**不變量 (W)**：任何時刻，對每個非根節點 $x$，
$$w[x] = \mathrm{val}(x) - \mathrm{val}(\texttt{fa}[x]);$$
對每個根 $r$，$w[r] = 0$。

**命題**：在 (W) 之下，`find(x)` 執行完畢後 $w[x] = \mathrm{val}(x) - \mathrm{val}(\text{root}(x))$，且 (W) 仍然成立。

*證明（對 $x$ 到根的距離 $d$ 歸納）*。
- $d = 0$：$x$ 是根，`find` 直接回傳，$w[x] = 0 = \mathrm{val}(x) - \mathrm{val}(x)$ ✔。
- $d \ge 1$：令 $p = \texttt{fa}[x]$，其距離為 $d-1$。歸納假設：遞迴呼叫後 $w[p] = \mathrm{val}(p) - \mathrm{val}(r)$，且 $\texttt{fa}[p] = r$。此時
  $$w[x] + w[p] = \big(\mathrm{val}(x) - \mathrm{val}(p)\big) + \big(\mathrm{val}(p) - \mathrm{val}(r)\big) = \mathrm{val}(x) - \mathrm{val}(r),$$
  正是把 `fa[x]` 改成 $r$ 後 (W) 所要求的值 ✔。$\square$

**這裡有兩個前提，都必須點名：**

1. **中間項 $\mathrm{val}(p)$ 相消** —— 這是「相對關係可合成」的數學內容，也是群結合律的體現。**若權值不構成群（例如你想維護「兩點間的最大值」），這一步就不成立，帶權並查集就用不了。**
2. **壓縮的目標必須是原本的祖先** —— 8.1 定理 1 已經指出這一點，本節把它變得更嚴苛：**普通並查集壓縮到祖先只影響效率，帶權並查集若壓縮到非祖先，(W) 直接失效**，因為 $w[x]$ 累積的是**沿原路徑**的和。這就是 8.1 中那句「8.6 的帶權並查集可能因為權值算錯而破壞這一點」的具體所指。

**推論 1.1（查詢公式）**：若 $x, y$ 同根 $r$，則
$$\mathrm{val}(x) - \mathrm{val}(y) = \big(\mathrm{val}(x) - \mathrm{val}(r)\big) - \big(\mathrm{val}(y) - \mathrm{val}(r)\big) = w[x] - w[y].$$
**根的值 $\mathrm{val}(r)$ 被消掉了** ——這既是「不需要絕對值」的原因，也是「無法得知絕對值」的原因。**同一枚硬幣的兩面。**

### 定理 2（`unite` 的權值公式是唯一正確的選擇）

*設定*：要記錄 $\mathrm{val}(x) - \mathrm{val}(y) = v$，且 $rx = \texttt{find}(x) \ne ry = \texttt{find}(y)$。

**命題**：令 $\texttt{fa}[rx] = ry$，則 (W) 要求 $w[rx] = v + w[y] - w[x]$，且此值唯一。

*證明*。(W) 對新邊要求 $w[rx] = \mathrm{val}(rx) - \mathrm{val}(ry)$。由定理 1，$\mathrm{val}(x) = w[x] + \mathrm{val}(rx)$、$\mathrm{val}(y) = w[y] + \mathrm{val}(ry)$。代入約束：
$$v = \mathrm{val}(x) - \mathrm{val}(y) = \big(w[x] + \mathrm{val}(rx)\big) - \big(w[y] + \mathrm{val}(ry)\big),$$
移項得 $\mathrm{val}(rx) - \mathrm{val}(ry) = v + w[y] - w[x]$ ✔。**表達式由 (W) 唯一決定，沒有選擇餘地。**

反向掛（$\texttt{fa}[ry] = rx$）時取逆元：$w[ry] = w[x] - w[y] - v$ ✔。$\square$

**推導這條公式的正確做法是「寫下 (W) 的要求，代入定理 1，移項」，不要憑感覺拼。** 帶權並查集的公式錯誤有一半來自方向拼錯，而方向拼錯在小測資上常常剛好對（例如所有權值都是 $1$ 或所有關係都對稱時）。**用一個非對稱的三元素例子手算驗證：$a-b=3$、$b-c=5$，查 $a-c$ 應得 $8$。**

### 定理 3（399 除法求值：可答 $\iff$ 同組）

*問題*：給定若干 $\mathrm{val}(a_i)/\mathrm{val}(b_i) = v_i$，回答若干 $\mathrm{val}(x)/\mathrm{val}(y)$，無法確定則回 $-1$。

**命題**：$\mathrm{val}(x)/\mathrm{val}(y)$ 被方程組唯一確定 $\iff$ $x, y$ 出現過且在同一連通塊；此時答案 $= w[x]/w[y]$。

*證明*。
- **($\Leftarrow$)** 同根時由推論 1.1（乘法版）得 $\mathrm{val}(x)/\mathrm{val}(y) = w[x]/w[y]$，而該式只依賴給定的方程 ✔。
- **($\Rightarrow$)** 設 $x, y$ 不同塊（或某一者從未出現）。取任一組滿足所有方程的賦值 $\mathrm{val}$，把 $x$ 所在塊的所有值同乘一個常數 $t > 0$、其餘不動。**所有方程仍然成立**（每個方程的兩端在同一塊內，比值不變），但 $\mathrm{val}(x)/\mathrm{val}(y)$ 變成原值的 $t$ 倍。$t$ 任意 ⇒ 該比值未被確定 ✔。$\square$

**($\Rightarrow$) 這一半才是重點**：它證明了「不同塊 ⇒ 真的無解」，而不只是「我們的演算法算不出來」。**論證方式是「造出兩組都滿足約束但答案不同的解」——這是所有『資訊不足』證明的標準形狀。**

### 定理 4（2307 矛盾偵測：檢查每條非樹邊就夠了）

*問題*：給定 $m$ 個方程 $\mathrm{val}(a_i)/\mathrm{val}(b_i) = v_i$，判斷是否存在矛盾。

**演算法**：依序 `unite`；若某次 $rx = ry$ 且 $|w[x]/w[y] - v| > \varepsilon$ 則回報矛盾。

**命題**：方程組可滿足 $\iff$ 演算法從未回報矛盾。

*證明*。把每個方程看成一條無向邊。演算法對每條邊做一次判斷：$rx \ne ry$ 的邊構成一棵**生成森林**（稱樹邊），其餘是**非樹邊**。

- **($\Rightarrow$ 可滿足則不回報)**：設有滿足解 $\mathrm{val}$。由定理 1，任何時刻 $w[\cdot]$ 都忠實反映 $\mathrm{val}$ 的相對關係，故非樹邊的檢查 $w[x]/w[y]$ 恰等於 $\mathrm{val}(x)/\mathrm{val}(y) = v$ ✔。
- **($\Leftarrow$ 不回報則可滿足)**：**構造解**。對每棵樹的根任意指定 $\mathrm{val}(r) = 1$，其餘節點取 $\mathrm{val}(x) = w[x]$。則所有**樹邊**的方程依 (W) 自動成立；所有**非樹邊**的方程因為通過了檢查而成立 ✔。$\square$

**這個證明的價值在於它回答了「為什麼只檢查非樹邊就夠、不必檢查所有環」**：因為構造出的賦值讓**每一條給定的邊**都成立，而方程組的可滿足性就只關乎這些邊。（用圖論語言說：基本環構成環空間的一組基，檢查每條非樹邊等於檢查所有環——但上面的構造性證明更直接，也不需要環空間的語言。）

**浮點細節**：$m \le 10^5$、$v \le 20$，連乘可能溢位或下溢到 $10^{\pm 100}$ 以外。**用相對誤差比較**：`fabs(w[x] / w[y] - v) > 1e-5 * max(1.0, fabs(v))`；更穩健的做法是**改存 $\log$，把乘法群換成加法群**（$\log(a/b) = \log a - \log b$），連乘變連加，誤差不再相乘放大。

### 定理 5（$\mathbb{Z}_2$ 權值 $\equiv$ 8.2 的擴展域並查集）

*設定*：關係只有「同類」與「異類」（奇偶、敵友、二分圖判定）。

**命題**：以 $G = \mathbb{Z}_2$（$\oplus$ 為 XOR）的帶權並查集，與 8.2 的擴展域並查集（為每個 $x$ 額外開一個節點 $x + n$ 表示「$x$ 的反面」）**判定能力完全相同**。

*證明（雙向模擬）*。
- **帶權 $\to$ 擴展域**：若帶權判定 $x, y$ 同根且 $w[x] \oplus w[y] = 0$，則路徑上「異類」邊為偶數條；在擴展域中沿同一路徑做 `unite(a, b)`／`unite(a, b+n)` 的對應合併，可得 $x$ 與 $y$ 同組 ✔。
- **擴展域 $\to$ 帶權**：擴展域中 $x$ 與 $y$ 同組表示存在一條交錯路徑，其「翻面」次數為偶數，對應帶權下 $w[x] \oplus w[y] = 0$ ✔。$\square$

**兩者的取捨：**

| | 帶權（$\mathbb{Z}_2$） | 擴展域 |
| --- | --- | --- |
| 空間 | $2n$ 個 `int`（`fa` + `w`） | $2n$ 個 `int`（`fa`） |
| 程式複雜度 | 要正確維護 `w`，易錯 | **只有普通 `unite`，幾乎不會錯** |
| 推廣到 $k \ge 3$ 類 | **改成 $\mathbb{Z}_k$ 即可** | 要開 $kn$ 個節點，且「互斥」語意在 $k \ge 3$ 時不再等價 |

**結論很實際：只有兩類就用擴展域（更不容易錯）；三類以上或需要具體數值差就用帶權。** 這是 8.2 與本節的分界線。

## C++17 模板

**模板一：399 除法求值（乘法群，字串映射）**

```cpp
class Solution {
    vector<int> fa;
    vector<double> w;  // w[x] = val[x] / val[fa[x]]
    int find(int x) {
        if (fa[x] == x) return x;
        int r = find(fa[x]);
        w[x] *= w[fa[x]];  // 先累積
        fa[x] = r;         // 再改指標
        return r;
    }

public:
    vector<double> calcEquation(vector<vector<string>>& equations,
                                vector<double>& values,
                                vector<vector<string>>& queries) {
        unordered_map<string, int> id;
        auto getId = [&](const string& s) {
            auto it = id.find(s);
            if (it != id.end()) return it->second;
            int k = id.size();
            id[s] = k;
            fa.push_back(k);
            w.push_back(1.0);
            return k;
        };
        for (int i = 0; i < (int)equations.size(); ++i) {
            int a = getId(equations[i][0]), b = getId(equations[i][1]);
            int ra = find(a), rb = find(b);
            if (ra == rb) continue;  // 本題保證無矛盾
            fa[ra] = rb;
            w[ra] = values[i] * w[b] / w[a];  // 定理 2 的乘法版
        }
        vector<double> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            auto ia = id.find(q[0]), ib = id.find(q[1]);
            if (ia == id.end() || ib == id.end() ||
                find(ia->second) != find(ib->second)) {
                ans.push_back(-1.0);
            } else {
                ans.push_back(w[ia->second] / w[ib->second]);
            }
        }
        return ans;
    }
};
```

（本題沒有按大小合併——變數數量 $\le 40$，樹深可忽略。**規模大時務必加回按大小合併**，並記得反向掛時把權值取倒數。）

**模板二：2307 檢查方程式中的矛盾（改存 $\log$，把乘法變加法）**

```cpp
class Solution {
    vector<int> fa, sz;
    vector<double> w;  // w[x] = log(val[x]) - log(val[fa[x]])
    int find(int x) {
        if (fa[x] == x) return x;
        int r = find(fa[x]);
        w[x] += w[fa[x]];
        fa[x] = r;
        return r;
    }

public:
    bool checkContradictions(vector<vector<string>>& equations,
                             vector<double>& values) {
        unordered_map<string, int> id;
        auto getId = [&](const string& s) {
            auto it = id.find(s);
            if (it != id.end()) return it->second;
            int k = id.size();
            id[s] = k;
            fa.push_back(k);
            sz.push_back(1);
            w.push_back(0.0);
            return k;
        };
        const double EPS = 1e-5;
        for (int i = 0; i < (int)equations.size(); ++i) {
            int a = getId(equations[i][0]), b = getId(equations[i][1]);
            double v = log(values[i]);
            int ra = find(a), rb = find(b);
            if (ra == rb) {
                if (fabs(w[a] - w[b] - v) > EPS) return true;  // 矛盾
                continue;
            }
            if (sz[ra] > sz[rb]) {  // 按大小合併，反向掛要取負
                fa[rb] = ra;
                w[rb] = w[a] - w[b] - v;
                sz[ra] += sz[rb];
            } else {
                fa[ra] = rb;
                w[ra] = v + w[b] - w[a];
                sz[rb] += sz[ra];
            }
        }
        return false;
    }
};
```

**模板三：$\mathbb{Z}_k$ 版通用骨架（奇偶、模 $k$ 偏移）**

```cpp
template <int K>
struct ModDSU {
    vector<int> fa, sz, w;  // w[x] = (val[x] - val[fa[x]]) mod K
    explicit ModDSU(int n) : fa(n), sz(n, 1), w(n, 0) {
        iota(fa.begin(), fa.end(), 0);
    }
    int find(int x) {
        if (fa[x] == x) return x;
        int r = find(fa[x]);
        w[x] = (w[x] + w[fa[x]]) % K;
        fa[x] = r;
        return r;
    }
    // 記錄 (val[x] - val[y]) mod K == v；回傳 false 表示矛盾
    bool unite(int x, int y, int v) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return ((w[x] - w[y]) % K + K) % K == v % K;
        if (sz[rx] > sz[ry]) {
            fa[ry] = rx;
            w[ry] = ((w[x] - w[y] - v) % K + K) % K;
            sz[rx] += sz[ry];
        } else {
            fa[rx] = ry;
            w[rx] = ((v + w[y] - w[x]) % K + K) % K;
            sz[ry] += sz[rx];
        }
        return true;
    }
};
```

（`K = 2` 就是奇偶／二分圖判定；**但如前所述，只有兩類時 8.2 的擴展域寫法更不容易錯。**）

## 時間與空間複雜度

| 操作 | 時間 |
| --- | --- |
| `find` | $O(\alpha(n))$ 攤還 $\times$ 群運算成本 |
| `unite` | $O(\alpha(n))$ 攤還 |
| `query` | $O(\alpha(n))$ 攤還 |

**與 8.1 完全相同的漸近界**——按大小合併與路徑壓縮都保留了，只是每次跳躍多做一次群運算（一次加法或乘法，$O(1)$）。

**空間**：$O(n)$，比普通並查集多一個權值陣列。權值型別要按群選：整數差用 `long long`（防溢位），比值用 `double`，模 $k$ 用 `int`。

**遞迴深度**：本節推薦遞迴版 `find`（迭代版要兩趟，見下），深度上界即樹高。**有按大小合併時樹高 $\le \log_2 n$**（8.1 定理 2），$n = 10^5$ 時只有 17 層，遞迴完全安全。**沒有按大小合併時樹高可達 $O(n)$，就有爆堆疊風險——這是「帶權並查集一定要按大小合併」的另一個理由。**

**迭代版**（需要時）：第一趟走到根並記錄路徑，第二趟從根往回累加權值並改指標。

```cpp
int find(int x) {
    int r = x;
    while (fa[r] != r) r = fa[r];
    long long acc = 0;  // 從 r 往回走時累積的權值
    while (fa[x] != r) {
        int nxt = fa[x];
        long long nw = w[x] + acc;  // 注意：這裡的累積方向要小心
        // 兩趟寫法容易寫反，建議直接用遞迴版
        acc = nw;
        x = nxt;
    }
    return r;
}
```
**兩趟版的累積方向極易寫反，而且錯了不會崩。除非確定會爆堆疊，否則用遞迴版。**

## 常見錯誤與邊界條件

- **路徑壓縮時忘記更新權值**。這是本節的頭號 bug。改了 `fa[x]` 卻不改 `w[x]`，(W) 立刻失效，答案錯得毫無規律。
- **`find` 裡兩行順序寫反**。必須是「遞迴 → `w[x] ⊕= w[fa[x]]` → `fa[x] = r`」。先改指標會讓 `w[fa[x]]` 變成根的 $0$，**權值靜靜歸零**。
- **`unite` 的權值公式方向拼錯**。**唯一可靠的辦法是照定理 2 推導**：寫下 (W) 的要求、代入 $\mathrm{val}(x) = w[x] + \mathrm{val}(rx)$、移項。用非對稱例子驗證：$a-b=3$、$b-c=5$ ⇒ $a-c=8$。
- **按大小合併時忘記把權值取逆**。反向掛（`fa[ry] = rx`）的權值是正向的逆元，不是同一個值。
- **查詢時忘記先 `find`**。`w[x]` 只有在 `find(x)` 之後才保證是「到根」的值。**`query` 一定要先呼叫兩次 `find`，再讀 `w`。**
- **不同塊的查詢沒特判**。399 要回 $-1.0$；直接算 `w[x] / w[y]` 會得到一個看似合理的垃圾數字。
- **變數未出現過**。399 的查詢可能含從未在方程中出現的變數，也要回 $-1.0$。**注意 `"x" / "x"` 若 `x` 未出現，答案仍是 $-1.0$ 而不是 $1.0$。**
- **自環方程**。$a / a = v$ 且 $v \ne 1$ 是矛盾；$v = 1$ 是廢話。一般的一致性檢查（$rx = ry$ 分支）會自動處理，**不需要特判，但要確認你的程式真的走進那個分支**。
- **浮點誤差**。長鏈連乘會放大誤差。**用相對誤差比較，或改存 $\log$ 把乘法變加法**（模板二）。整數差值群請用 `long long`。
- **整數溢位**。差值群若 $|v| \le 10^9$ 且鏈長 $10^5$，累積差可達 $10^{14}$，**必須 `long long`**。
- **模 $k$ 群忘記處理負數取模**。C++ 的 `%` 對負數回傳負值，要寫 `((a % K) + K) % K`。
- **想用它維護非群的量**。「路徑上的最大值」「路徑上的元素集合」都不是群（沒有逆元），**帶權並查集做不了**。這類需求要用 LCT 或樹上倍增。
- **想問絕對值**。連通塊的根可以自由伸縮（定理 3 的 ($\Rightarrow$) 方向），**絕對值本質上不存在**，除非題目另給錨點。

## 與相似技巧的比較

- **與 8.1 普通並查集**：普通版是本節的 $G = \{e\}$（平凡群）特例——所有權值都是單位元，(W) 退化成廢話。**反過來說，本節的所有複雜度分析可以直接沿用 8.1，不必重做。**
- **與 8.2 擴展域並查集**：由定理 5，擴展域 $\equiv$ $\mathbb{Z}_2$ 帶權。**兩類用擴展域（不易錯），多類或需要數值差用帶權。**
- **與「建圖 + DFS 賦值」**：399 也可以建無向圖，對每個連通塊做一次 DFS，把根設為 $1$ 並沿邊算出所有點的值，之後查詢 $O(1)$。**複雜度 $O(n + m + q)$，比帶權並查集還好，程式也不見得長。** 差別在於：DFS 版是**離線**的（要先收齊所有方程），帶權並查集支援**方程與查詢交錯到來的線上場景**，以及**邊加邊檢查矛盾**（2307）。**題目若是純離線，DFS 往往是更好的選擇——不要為了用工具而用工具。**
- **與 Floyd 傳遞閉包**：399 的變數只有 $\le 40$ 個，$O(V^3)$ 的 Floyd（把 $\times$ 當作路徑合成）完全可行，而且十行寫完。**小規模時它是最省腦力的解。**
- **與差分約束系統（SPFA／Bellman-Ford）**：差分約束處理的是**不等式** $\mathrm{val}(x) - \mathrm{val}(y) \le c$，帶權並查集只能處理**等式**。**看到不等式就換工具**，那是圖論章的內容。
- **與線段樹／樹狀陣列**：完全不同的問題域。本節維護的是「元素之間的關係」，不是「區間上的聚合量」。
- **與 8.4／8.5**：那兩節的 `fa` 根本不表示等價類。**本節的 `fa` 是正統等價類，而且額外掛了權值——它是 8.1 的正向擴展，8.4／8.5 是側向借用。**

## 本節重點速查

- **適用形狀**：關係**可傳遞、可逆**（比值、差值、同餘、奇偶）⇒ 權值構成**群** ⇒ 每條 `fa` 邊掛一個群元素。
- **主不變量 (W)**：$w[x] = \mathrm{rel}(x, \texttt{fa}[x])$；`find` 之後 $w[x] = \mathrm{rel}(x, \text{root})$。
- **查詢公式**：同根時 $\mathrm{rel}(x, y) = w[x] \ominus w[y]$。**根的值被消掉**——這既是「不需要絕對值」也是「得不到絕對值」的原因。
- **`find` 的兩行順序**：遞迴 → `w[x] ⊕= w[fa[x]]` → `fa[x] = r`。**寫反會讓權值靜靜歸零**，這是頭號 bug。
- **`unite` 公式照定理 2 推**：寫下 (W) 的要求、代入 $\mathrm{val}(x) = w[x] \oplus \mathrm{val}(rx)$、移項。**不要憑感覺拼方向**，用 $a-b=3,\ b-c=5 \Rightarrow a-c=8$ 驗證。
- **按大小合併完全相容**，反向掛時取逆元。**不加平衡策略會讓遞迴 `find` 有爆堆疊風險。**
- **矛盾偵測（2307）**：`unite` 遇到同根就檢查。**只檢查非樹邊就夠**——構造性證明：樹邊由 (W) 自動成立，非樹邊逐一驗過（定理 4）。
- **399 的 $-1$ 情形**：不同塊、或變數未出現過。**($\Rightarrow$) 方向要靠「整塊同乘 $t$」的構造證明資訊真的不足**，不是演算法弱。
- **浮點就改存 $\log$**，把乘法群換成加法群，誤差不再相乘放大；整數差用 `long long`。
- **只有兩類就用 8.2 的擴展域**（定理 5 證明兩者等價，但擴展域不易錯）；**三類以上或要數值差才用帶權**。
- **純離線的 399 用「建圖 + DFS 賦值」更好**（$O(n+m+q)$，且不必維護權值）。帶權並查集的真正價值在**線上**與**邊加邊檢查矛盾**。
- **做不到的事**：絕對值、不等式（用差分約束）、非群的量如路徑最大值（用倍增或 LCT）。
