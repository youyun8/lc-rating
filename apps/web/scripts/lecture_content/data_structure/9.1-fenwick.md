## 這個技術解決什麼問題

「單點修改」與「前綴查詢」這兩件事，各自都有 $O(1)$ 的做法，但**互相衝突**：

| 表示法 | 單點修改 | 前綴和查詢 |
| --- | --- | --- |
| 原陣列 | $O(1)$ | $O(n)$ |
| 前綴和陣列（第 2 章） | $O(n)$ | $O(1)$ |
| **樹狀陣列** | $O(\log n)$ | $O(\log n)$ |

前綴和之所以改得慢，是因為**一個位置的變動會影響它後面的每一個前綴和**——資訊被儲存了 $n$ 次。樹狀陣列的想法是：**只儲存 $O(\log n)$ 個「精心挑選的區段和」，讓任何前綴都能由其中 $O(\log n)$ 段拼出，而任何位置也只落在 $O(\log n)$ 段裡面。**

挑選的規則出奇簡單：**`tree[i]` 負責的區段長度就是 `lowbit(i) = i & -i`（$i$ 的最低位 1 所代表的權重）。** 整個資料結構就這一條規則，其餘都是它的推論。

**它真正的價值不只是「可修改的前綴和」，更是「值域桶」**：把值離散化成下標，`add(v, 1)` 表示「見過一個 $v$」，`query(v-1)` 就是「已見過的數中有幾個小於 $v$」。**一邊掃陣列一邊查詢與插入，就把「對每個元素數前面有多少個比它小」這類 $O(n^2)$ 的計數壓成 $O(n\log n)$**——9.2 整節都在講這件事，而 2519、1409、2179 等題都是它的變體。

**辨識訊號**：
- 單點改 + 前綴／區間**求和**（可差分的聚合）反覆交錯 ⇒ 307；
- 「有多少個數比我小／大」的計數 ⇒ 離散化 + 值域桶；
- 二維單點改、矩形查 ⇒ 308（兩層樹狀陣列）。

## 狀態／資料結構定義

**核心定義（一維，1-indexed）**：
$$\texttt{tree}[i] = \sum_{j = i - \mathrm{lowbit}(i) + 1}^{i} a[j], \qquad \mathrm{lowbit}(i) = i \mathbin{\&} (-i).$$
即 `tree[i]` 存的是**左開右閉區間 $(\,i - \mathrm{lowbit}(i),\ i\,]$ 的和**。

**下標必須從 1 開始。** $\mathrm{lowbit}(0) = 0$，`0` 會讓查詢迴圈永遠停在原地或讓更新迴圈死循環。**這不是風格問題，是正確性問題。**

```cpp
struct Fenwick {
    int n;
    vector<long long> t;
    explicit Fenwick(int n) : n(n), t(n + 1, 0) {}

    void add(int i, long long v) {  // a[i] += v
        for (; i <= n; i += i & -i) t[i] += v;
    }
    long long sum(int i) const {  // a[1] + ... + a[i]
        long long s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    }
    long long range(int l, int r) const {  // a[l] + ... + a[r]
        return sum(r) - sum(l - 1);
    }
};
```

**兩個迴圈的方向恰好相反，這不是巧合**：查詢是「把 $[1, i]$ 拆成幾段」（往下走），更新是「找出所有覆蓋位置 $i$ 的段」（往上走）。定理 2 與定理 3 分別證明兩者。

**$O(n)$ 建樹**（比 $n$ 次 `add` 的 $O(n\log n)$ 快，且程式一樣短）：

```cpp
void build(const vector<long long>& a) {  // a 為 1-indexed
    for (int i = 1; i <= n; ++i) {
        t[i] += a[i];
        int j = i + (i & -i);
        if (j <= n) t[j] += t[i];
    }
}
```

**三種常見變體（都是同一個結構換個解讀）：**

| 需求 | 做法 |
| --- | --- |
| 單點改、前綴查 | 直接用（上面的定義） |
| **區間改、單點查** | 樹狀陣列存**差分陣列** $d$；`add(l, v); add(r+1, -v)`，單點值 $= \texttt{sum}(i)$ |
| **區間改、區間查** | 開**兩個**樹狀陣列，維護 $\sum d[i]$ 與 $\sum i\cdot d[i]$ |
| 二維單點改、矩形查 | `tree[i][j]` 覆蓋 $(i-\mathrm{lowbit}(i), i] \times (j-\mathrm{lowbit}(j), j]$，兩層迴圈 |

**樹狀陣列上二分（求第 $k$ 小，$O(\log n)$ 而非 $O(\log^2 n)$）**——值域桶場景極常用：

```cpp
int kth(long long k) const {  // 最小的 i 使 sum(i) >= k
    int pos = 0;
    for (int pw = 1 << __lg(max(n, 1)); pw > 0; pw >>= 1) {
        if (pos + pw <= n && t[pos + pw] < k) {
            pos += pw;
            k -= t[pos];
        }
    }
    return pos + 1;
}
```
**它之所以能work，是因為 `tree` 的下標結構恰好就是一棵完全二元樹的層次編號**：從高位往低位試著「往右跳」，每次跳躍讀的正好是一個完整段。

## 不變量或正確性證明

以下把 $i$ 的二進位展開寫成 $i = 2^{b_1} + 2^{b_2} + \cdots + 2^{b_k}$，其中 $b_1 > b_2 > \cdots > b_k \ge 0$。於是 $\mathrm{lowbit}(i) = 2^{b_k}$。

### 定理 1（結構不變量）

**不變量 (F)**：任何時刻，對每個 $i \in [1, n]$，
$$\texttt{tree}[i] = \sum_{j \in (\,i - \mathrm{lowbit}(i),\ i\,]} a[j].$$

`add` 與 `build` 的任務就是維護 (F)，`sum` 的正確性完全建立在 (F) 之上。**下面三個定理分別處理「拆得對」「改得全」「維護得住」。**

### 定理 2（`sum` 的下標序列恰好切出 $[1, i]$ 的一個分割）

*命題*：令 $i_0 = i$、$i_{m+1} = i_m - \mathrm{lowbit}(i_m)$，直到 $i_k = 0$。則區間族
$$\big(i_1, i_0\big],\ \big(i_2, i_1\big],\ \dots,\ \big(i_k, i_{k-1}\big] = \big(0, i_{k-1}\big]$$
**兩兩不交，且聯集恰為 $(0, i]$**；而 `tree[i_m]` 覆蓋的正是 $(i_{m+1}, i_m]$。項數 $k = \mathrm{popcount}(i)$。

*證明*。
- 「減去 lowbit」就是**清掉最低位的 1**，故 $i_m = 2^{b_1} + \cdots + 2^{b_{k-m}}$，序列在 $k$ 步後歸零 ⇒ 項數 $= k = \mathrm{popcount}(i)$ ✔。
- 由定義，`tree[`$i_m$`]` 覆蓋 $(\,i_m - \mathrm{lowbit}(i_m),\ i_m\,] = (i_{m+1}, i_m]$ ✔。
- 這些區間**首尾相接**（前一段的左端點就是下一段的右端點），故不交且**望遠鏡式地**併成 $(i_k, i_0] = (0, i]$ ✔。$\square$

**「首尾相接」這個觀察就是整個查詢迴圈的全部內容。** 不需要記憶任何位運算技巧——只要記得「減 lowbit 等於清掉最低位的 1」，分割性質自動成立。

**推論 2.1**：$k = \mathrm{popcount}(i) \le \lfloor\log_2 i\rfloor + 1$，故 `sum` 是 $O(\log n)$。

### 定理 3（`add` 的下標序列恰好是所有覆蓋 $x$ 的段）

*命題*：位置 $x$ 被 `tree[j]` 覆蓋（即 $j - \mathrm{lowbit}(j) < x \le j$）**當且僅當** $j$ 出現在序列 $j_0 = x$、$j_{m+1} = j_m + \mathrm{lowbit}(j_m)$ 中（且 $j \le n$）。

*證明*。分三步。

**(a) $x$ 本身覆蓋 $x$**：$x - \mathrm{lowbit}(x) < x \le x$ ✔。

**(b) 若 $j$ 覆蓋 $x$，則 $(j, j + \mathrm{lowbit}(j))$ 之間沒有任何下標覆蓋 $x$。**
設 $\mathrm{lowbit}(j) = 2^b$，取 $j' = j + t$ 且 $0 < t < 2^b$。則 $\mathrm{lowbit}(j') = \mathrm{lowbit}(t) \le t$，於是
$$j' - \mathrm{lowbit}(j') = j + \big(t - \mathrm{lowbit}(t)\big) \ge j \ge x,$$
不滿足「$<x$」，故 $j'$ 不覆蓋 $x$ ✔。（最後一步用到 $j \ge x$，這由「$j$ 覆蓋 $x$」給出。）

**(c) $j'' = j + \mathrm{lowbit}(j)$ 覆蓋 $x$。**
寫 $j = m\cdot 2^b$（$m$ 為奇數，$2^b = \mathrm{lowbit}(j)$），則 $j'' = (m+1)\cdot 2^b$ 且 $m+1$ 為偶數，故 $\mathrm{lowbit}(j'') \ge 2^{b+1}$。於是
$$j'' - \mathrm{lowbit}(j'') \le j'' - 2^{b+1} = j + 2^b - 2^{b+1} = j - 2^b = j - \mathrm{lowbit}(j) < x,$$
又 $j'' > j \ge x$，兩個條件都滿足 ✔。

由 (a)(b)(c)，從 $x$ 出發反覆「加 lowbit」，**不重不漏地列舉出所有覆蓋 $x$ 的下標**，直到超出 $n$ ✔。$\square$

**這個定理是樹狀陣列最容易被跳過、卻最值得看的一段。** 大多數教材只說「加 lowbit 就對了」；(b) 才是「不漏」的保證，(c) 才是「不重」與「連續」的保證。**沒有 (b)，你無法排除「中間某個下標也覆蓋了 $x$ 但被跳過」的可能。**

**推論 3.1（`add` 是 $O(\log n)$）**：由 (c) 的推導，$\mathrm{lowbit}(j'') \ge 2\,\mathrm{lowbit}(j)$——**每一步 lowbit 至少加倍**，故不超過 $\lfloor\log_2 n\rfloor + 1$ 步 ✔。

**推論 3.2（(F) 被 `add` 正確維護）**：`a[x] += v` 後，需要且僅需要把 $v$ 加到所有覆蓋 $x$ 的 `tree[j]` 上——正是定理 3 列舉的那些 ✔。

### 定理 4（$O(n)$ 建樹的正確性）

*命題*：`build` 執行完畢後 (F) 成立。

*證明（對 $i$ 歸納）*。定義 `tree[i]` 的**直接子節點**為所有 $j < i$ 滿足 $j + \mathrm{lowbit}(j) = i$。由定理 2 的分割性質，$(i - \mathrm{lowbit}(i), i]$ 恰好被 $\{a[i]\} \cup \bigcup_{j \text{ 為 } i \text{ 的子節點}} (j - \mathrm{lowbit}(j), j]$ 不交地覆蓋。

迴圈按 $i$ 遞增執行，處理到 $i$ 時：所有子節點 $j < i$ 都已被處理完畢（歸納假設 ⇒ `t[j]` 已滿足 (F)），且在處理 $j$ 時已把 `t[j]` 累加進 `t[i]`。再加上本輪的 `a[i]`，`t[i]` 即滿足 (F) ✔。$\square$

**注意迴圈裡是 `t[j] += t[i]` 而不是 `t[j] += a[i]`——因為 `t[i]` 此刻已經是完整的段和。** 寫成 `a[i]` 是常見的抄錯。

### 定理 5（樹狀陣列只能處理「可差分」的聚合）

*命題*：`range(l, r) = sum(r) - sum(l - 1)` 成立的前提是聚合運算構成**群**（有逆元）。

*證明*。$\mathrm{sum}(r) = \mathrm{sum}(l-1) \oplus \big(a[l] \oplus \cdots \oplus a[r]\big)$ 要能解出中間項，必須能對 $\mathrm{sum}(l-1)$ 取逆 ✔。$\square$

**這條界線決定了整章的分工**：

| 聚合 | 有逆元？ | 樹狀陣列 |
| --- | --- | --- |
| 加法、XOR | 是 | ✅ 可以 |
| 乘法（非零） | 是 | ✅ 可以 |
| **max / min / gcd** | **否** | ❌ **要用線段樹（9.3）** |

**（技術補充：只做「單點改成更大的值 + 查前綴 max」時，樹狀陣列仍可用——因為那不需要差分，只需要 `tree[i] = max(...)` 且修改是單調的。但一旦有「改小」或要查任意區間 max，就必須換線段樹。這個特例在 LIS 類 DP 中很常見，別忘了它。）**

## 時間與空間複雜度

| 操作 | 時間 | 說明 |
| --- | --- | --- |
| `add` | $O(\log n)$ | 推論 3.1：lowbit 每步至少加倍 |
| `sum` | $O(\log n)$ | 推論 2.1：迭代次數 $=\mathrm{popcount}(i)$ |
| `range` | $O(\log n)$ | 兩次 `sum` |
| `kth`（樹上二分） | $O(\log n)$ | **不是 $O(\log^2 n)$** |
| 建樹 | $O(n)$ | 定理 4 |
| 空間 | $O(n)$ | **只有一個陣列**，無指標、無節點物件 |
| 二維 `add`／`query` | $O(\log n\log m)$ | 空間 $O(nm)$ |

**常數是樹狀陣列真正的賣點。** 與線段樹比較（同為 $O(\log n)$）：

| | 樹狀陣列 | 線段樹 |
| --- | --- | --- |
| 程式行數 | ~10 | ~60 |
| 空間 | $n$ | $4n$（遞迴版） |
| 實測速度 | **基準** | 約慢 2～4 倍 |
| 每次操作的實際迭代 | $\mathrm{popcount}(i)$，**平均只有 $\log n / 2$** | 完整 $\log n$ 層遞迴 |
| 快取行為 | 好（單一陣列、下標局部性高） | 差（遞迴 + 跳躍） |

**平均迭代次數是 $\log_2 n$ 的一半**（隨機下標的 popcount 期望值），這是樹狀陣列常數小的主要來源之一。

**各題的實際複雜度**：

| 題目 | 時間 | 瓶頸 |
| --- | --- | --- |
| 307 區域和檢索 | $O(n + q\log n)$ | — |
| 308 二維區域和檢索 | $O(nm + q\log n\log m)$ | 二維 |
| 2519 統計 K-Big 索引 | $O(n\log n)$ | **兩個樹狀陣列各掃一遍** |
| 1409 查詢帶鍵的排列 | $O((n+m)\log(n+m))$ | 需預留前置空間 |

**空間陷阱**：二維樹狀陣列是 $O(nm)$，$1000\times1000$ 的 `long long` 就是 8 MB——**還可以，但 $5000\times5000$ 就爆了**。值域桶則務必**先離散化**：值到 $10^9$ 直接開陣列必然 MLE。

## 與相似技巧的比較

- **與前綴和（第 2 章）**：**陣列不變就用前綴和**，$O(1)$ 查詢，沒有理由用樹狀陣列。**只要出現一次修改，前綴和就崩了。** 判準只有一句：資料會不會變。
- **與線段樹（9.3）**：分界線就是**定理 5**——聚合有沒有逆元。求和／XOR 用樹狀陣列（短、快、省），max／min／gcd 或「節點要維護複合資訊」（2213 那種前綴段／後綴段／最長段）只能用線段樹。**樹狀陣列能做的事線段樹都能做，反之不然；但能用樹狀陣列時就別寫線段樹。**
- **與 Lazy 線段樹（9.4）**：樹狀陣列的「區間改」是靠差分硬湊出來的，**只支援區間加**（可差分的修改）；區間**賦值**（把一段全設為 $v$）樹狀陣列做不到，必須 lazy 線段樹。
- **與平衡樹／`pb_ds` order-statistics tree**：後者直接支援 `order_of_key`／`find_by_order`，**不需要離散化**，且支援刪除任意元素。代價是常數大 3～5 倍。**值域已知且可離散化 ⇒ 樹狀陣列；值域動態或需要真正的有序集合操作 ⇒ 平衡樹。**
- **與「離線 + 排序」**：很多需要樹狀陣列的線上問題，離線後按值排序就能用更簡單的手段解決（例如雙指標）。**先問一句「這題能不能離線」，常常省掉整個資料結構。**
- **與歸併排序求逆序對（9.2）**：兩者複雜度相同。歸併版不需要離散化、常數更小；樹狀陣列版更容易改成各種變形（$a_i > 2a_j$、前綴和區間計數）。**9.2 會詳細比。**
- **與分塊（第 11 章）**：分塊 $O(\sqrt n)$ 比 $O(\log n)$ 慢，但**能處理沒有結合律友善性質的怪異操作**。樹狀陣列做不到的、線段樹也做不到的，才輪到分塊。
- **與差分（第 3 章）**：差分是「離線的、只能查一次最終狀態」的區間改；樹狀陣列 + 差分是「線上的、隨時可查」的區間改。**差分 $O(n)$ 更快，能用就用。**

## 本節重點速查

- **一句話定義**：`tree[i]` 存 $(\,i - \mathrm{lowbit}(i),\ i\,]$ 的和，$\mathrm{lowbit}(i) = i \,\&\, {-i}$。**整個結構只有這一條規則。**
- **兩個迴圈方向相反**：查詢 `i -= i & -i`（清掉最低位 1，把 $[1,i]$ 切成 $\mathrm{popcount}(i)$ 段，望遠鏡式相接——定理 2）；更新 `i += i & -i`（列舉所有覆蓋位置 $i$ 的段，不重不漏——定理 3）。
- **定理 3 的 (b)(c) 才是重點**：(b) 保證中間沒有被跳過的覆蓋者，(c) 保證下一個確實覆蓋且 **lowbit 至少加倍** ⇒ $O(\log n)$。
- **下標必須 1-indexed**。$\mathrm{lowbit}(0) = 0$ ⇒ 死迴圈或空轉。
- **$O(n)$ 建樹**：`t[i] += a[i]; t[i + lowbit(i)] += t[i];`。注意加的是 **`t[i]` 不是 `a[i]`**。
- **定理 5 是整章的分工線**：聚合**有逆元**（加法、XOR）⇒ 樹狀陣列；**沒有**（max/min/gcd）⇒ 線段樹。例外：只做「單點變大 + 查前綴 max」仍可用樹狀陣列（LIS 類 DP 常用）。
- **最重要的用法不是前綴和，是值域桶**：離散化後 `add(v, 1)` + `query(v-1)` = 「比 $v$ 小的有幾個」，把 $O(n^2)$ 計數壓成 $O(n\log n)$（9.2 全節）。
- **三種變體**：區間改單點查（存差分）、區間改區間查（兩個樹狀陣列，維護 $\sum d$ 與 $\sum i\,d$）、二維（兩層 lowbit）。
- **樹上二分 `kth` 是 $O(\log n)$**，不要寫成外層二分 + 內層 `sum` 的 $O(\log^2 n)$。
- **常數小是真正的賣點**：程式 10 行、空間 $n$、平均迭代只有 $\log n / 2$，比線段樹快 2～4 倍。
- **兩個空間陷阱**：值域桶一定要離散化；二維是 $O(nm)$。
- **陣列不會變就用前綴和**——不要為了用資料結構而用資料結構。
