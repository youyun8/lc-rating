## 這個技術解決什麼問題

一大類看似不同的題目，其實都是同一個問題：

> **數出滿足「下標有序 + 數值有序」兩個條件的配對數量。**

$$\#\{\,(i, j) : i < j \ \text{且}\ f(a_i, a_j)\,\}$$

暴力是雙層迴圈 $O(n^2)$；$n = 10^5$ 就是 $10^{10}$ 次比較。

**核心想法只有一句：兩個條件，一個交給掃描順序，另一個交給資料結構。**

- **下標條件 $i < j$** ⟶ 由左往右掃描，掃到 $j$ 時「已插入資料結構的」恰好就是所有 $i < j$；
- **數值條件** ⟶ 把值當成下標建**值域桶**（樹狀陣列），一次前綴查詢就得到答案。

這個框架叫**二維偏序**。逆序對（$i<j$ 且 $a_i > a_j$）是它最小的實例，而 315、493、327、2426 都只是換了「數值條件」的寫法：

| 題目 | 數值條件 | 化簡後 |
| --- | --- | --- |
| 經典逆序對 | $a_i > a_j$ | 直接查 |
| 315 右側小於當前元素 | $a_j < a_i$（從右往左掃） | 直接查 |
| 493 翻轉對 | $a_i > 2a_j$ | 值域要同時含 $a$ 與 $2a$ |
| 327 區間和的個數 | $\ell \le S_j - S_i \le r$ | $S_j - r \le S_i \le S_j - \ell$ |
| 2426 滿足不等式的數對 | $a_i - a_j \le b_i - b_j + d$ | 令 $c = a - b$，查 $c_i \le c_j + d$ |

**看到「對每個元素，問前面（或後面）有多少個滿足某不等式」，先做的事永遠是移項——把 $i$ 的量搬到一邊、$j$ 的量搬到另一邊。** 移項成功之後，剩下的就是套模板。

**另一個獨立的價值**：逆序對數 $=$ 用**相鄰交換**把序列排好序的最少次數（定理 4）。這讓 1850、2193 這類「最少相鄰交換」的題目瞬間變成計數題。

## 狀態／資料結構定義

**主線做法：離散化 + 樹狀陣列值域桶**

```cpp
// 通用骨架：計算嚴格逆序對數 #{ i < j : a[i] > a[j] }
long long countInversions(vector<int> a) {
    int n = a.size();
    vector<int> v(a);  // 離散化
    sort(v.begin(), v.end());
    v.erase(unique(v.begin(), v.end()), v.end());  // 去重不可省，見定理 3
    auto rk = [&](int x) {                         // 1-indexed 排名
        return int(lower_bound(v.begin(), v.end(), x) - v.begin()) + 1;
    };

    int m = v.size();
    vector<int> t(m + 1, 0);
    auto add = [&](int i) {
        for (; i <= m; i += i & -i) ++t[i];
    };
    auto sum = [&](int i) {
        int s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    };

    long long ans = 0;
    for (int j = 0; j < n; ++j) {
        int r = rk(a[j]);
        ans +=
            (j -
             sum(r));  // 已插入的總數 - (值 <= a[j] 的個數) = 值 > a[j] 的個數
        add(r);
    }
    return ans;
}
```

**`ans += j - sum(r)` 這一行值得停下來看**：`j` 是目前已插入的元素個數，`sum(r)` 是其中值 $\le a_j$ 的個數，相減就是值 $> a_j$ 的個數。**用「總數減補集」比直接查後綴更不容易寫錯**，因為樹狀陣列天生只會算前綴。

**備援做法：歸併排序**

```cpp
long long merge_count(vector<int>& a, vector<int>& buf, int l, int r) {
    if (r - l <= 1) return 0;
    int mid = (l + r) / 2;
    long long res = merge_count(a, buf, l, mid) + merge_count(a, buf, mid, r);
    int p = l, q = mid, k = l;
    while (p < mid && q < r) {
        if (a[p] <= a[q]) {  // <= 保證「嚴格」逆序對；用 < 會多算相等對
            buf[k++] = a[p++];
        } else {
            res += mid - p;  // a[p..mid) 全都 > a[q]，且下標都更小
            buf[k++] = a[q++];
        }
    }
    while (p < mid) buf[k++] = a[p++];
    while (q < r) buf[k++] = a[q++];
    copy(buf.begin() + l, buf.begin() + r, a.begin() + l);
    return res;
}
```

**兩者的選擇**：

| | 樹狀陣列 | 歸併排序 |
| --- | --- | --- |
| 需要離散化 | **是** | 否 |
| 常數 | 小 | 更小（無額外 $\log$ 的 `lower_bound`） |
| 改成 $a_i > 2a_j$（493） | 值域擴一倍即可 | 要**額外一趟**雙指標 |
| 改成區間計數（327） | **直接改查詢範圍** | 要兩趟雙指標，繁瑣 |
| 支援線上（邊插邊查） | **是** | 否（必須離線） |
| 附帶產出 | 無 | **順便排好序** |

**結論**：只求逆序對數 ⇒ 歸併更短更快；**條件一變複雜（帶倍數、帶區間、帶偏移）就用樹狀陣列**，因為只要改一行查詢範圍。

## 不變量或正確性證明

### 定理 1（掃描 + 值域桶：每個配對恰被計數一次）

**迴圈不變量 (I)**：在處理下標 $j$（即執行 `ans += ...` 那一刻）之前，樹狀陣列中恰好包含集合 $\{\,a_i : i < j\,\}$（重複值計重）。

*證明*。$j = 0$ 時桶為空 ✔。每輪結尾執行 `add(rk(a[j]))` 恰好把 $a_j$ 加入，故進入下一輪時桶為 $\{a_i : i < j+1\}$ ✔。$\square$

**命題**：`ans` 最終等於 $\#\{(i,j) : i<j,\ a_i > a_j\}$。

*證明*。固定一對 $(i, j)$ 且 $i < j$。它只可能在處理下標 $j$ 的那一輪被計入（其他輪的查詢與 $j$ 無關）。由 (I)，該輪桶中含 $a_i$，且查詢統計的是「桶中值 $> a_j$ 的個數」，故 $(i,j)$ 被計入 $\iff a_i > a_j$ ✔。**恰好一次，不重不漏。**$\square$

**這個證明看起來平凡，但它點出了整個框架賴以成立的前提：「下標條件必須能由掃描順序完全承擔」。** 一旦條件變成 $|i - j| \le k$（有距離限制）或 $i < j$ 換成三維偏序 $i<j$ 且 $a_i<a_j$ 且 $b_i<b_j$，這個框架就不夠了——前者要加滑動視窗式的刪除，後者要 CDQ 分治。**先確認「掃描順序能不能吃掉一整個維度」，是套用模板前該問的第一句話。**

### 定理 2（歸併排序法：每個逆序對恰在一層被計數一次）

*命題*：`merge_count` 回傳嚴格逆序對數。

*證明*。分兩步。

**(a) 分層不重不漏。** 對任一逆序對 $(i, j)$（$i<j$，$a_i > a_j$），遞迴樹上存在**唯一**一個節點 $[l, r)$ 使得 $i, j$ 都在其中、但分屬左右兩半（即 $l \le i < \text{mid} \le j < r$）——就是 $i$ 與 $j$ 的「最近公共區間」。在該節點以外的節點裡，兩者要嘛不同時出現，要嘛在同一半（此時計數交給更深的遞迴）✔。

**(b) 單層計數正確。** 考慮某次 `merge`，此時左半 $a[l..\text{mid})$ 與右半 $a[\text{mid}..r)$ **各自已排序**（歸納假設）。當演算法因 `a[p] > a[q]` 而取走右半的 $a_q$ 時：
- 左半剩餘的 $a[p], a[p+1], \dots, a[\text{mid}-1]$ **全部 $> a_q$**（左半已排序，$a[p]$ 是其中最小者）；
- 它們的**原始下標全部 $<$ $a_q$ 的原始下標**（左半整體位於右半之前）。

故這 $\text{mid} - p$ 個配對全是逆序對，且每個都只在此刻被數一次 ✔。反之，被跳過的（`a[p] <= a[q]` 分支）確實不構成逆序對 ✔。$\square$

**(b) 有兩個前提，都必須點名**：
1. **左右兩半各自已排序**——這由遞迴保證。若順序被破壞（例如你在 merge 中途又去讀原陣列），計數立刻失效。
2. **「左半整體在右半之前」**——這由陣列的物理佈局保證。**這也是為什麼歸併版天生離線**：它靠位置關係表達下標順序，一旦允許插入新元素就崩了。

**相等元素的處理**：`a[p] <= a[q]` 取左邊 ⇒ 相等對**不**計入（嚴格逆序對）。改成 `a[p] < a[q]` 會把相等對也算進去。**題目問「嚴格大於」還是「大於等於」，就差這一個字元。**

### 定理 3（離散化保序，且必須去重）

*命題*：設 $\phi$ 為把值映到排名的映射。若 $\phi$ **嚴格保序**（$x < y \iff \phi(x) < \phi(y)$），則對 $\phi(a)$ 計數與對 $a$ 計數結果相同。

*證明*。逆序對的定義只用到值之間的「$>$」比較，而嚴格保序映射保持所有比較結果 ✔。$\square$

**推論（為什麼 `unique` 不能省）**：若用「排序後的位置」而非「去重後的排名」當作 $\phi$，相同的值會得到**不同**的下標，$\phi$ 就不再滿足 $x = y \Rightarrow \phi(x) = \phi(y)$。此時 `sum(r)` 會漏掉部分相等元素，**相等對被誤判成逆序對**。

具體反例：$a = [2, 2]$。正確答案 0。若把兩個 `2` 分別映成排名 1 和 2，掃到 $j=1$ 時查「值 $>$ 排名 2」得 0，看似沒事；但 $a = [2, 2, 1]$ 這種帶重複又帶比較的資料就會出錯。**養成 `sort` + `unique` + `lower_bound` 三件套的習慣，不要自己發明離散化。**

### 定理 4（相鄰交換次數的下界與上界都等於逆序對數）

*命題*：把序列 $a$ 用**相鄰元素交換**變成非遞減序列，最少需要 $\mathrm{inv}(a)$ 次，其中 $\mathrm{inv}$ 為逆序對數。

*證明*。
- **下界**：一次相鄰交換只改變**一對**元素的相對順序（其餘所有配對的相對順序不變），故 $\mathrm{inv}$ 每次至多變化 $1$。目標狀態 $\mathrm{inv} = 0$，故至少需要 $\mathrm{inv}(a)$ 次 ✔。
- **上界**：若 $\mathrm{inv}(a) > 0$，則**必存在相鄰的逆序對**（否則 $a_1 \le a_2 \le \cdots \le a_n$，$\mathrm{inv} = 0$，矛盾）。交換它使 $\mathrm{inv}$ 恰好減 1。反覆執行（即氣泡排序）$\mathrm{inv}(a)$ 步後到達有序 ✔。$\square$

**上下界都達到，等號成立。** 這個定理把一整類「最少相鄰交換」的題目（1850、2193）化成計數題。

**注意「必存在相鄰逆序對」這一步**——它是上界論證的關鍵，而且是反證法。**很多人只證了下界就以為證完了；下界只說明「不可能更少」，不保證「真的做得到」。**

**有重複元素時的推廣（1850、2193 都會遇到）**：目標序列若含相同字元，要把 $a$ 變成指定的目標串 $t$，**最少相鄰交換數 $=$「把 $a$ 的每個位置對應到 $t$ 中同字元位置」所有匹配方案裡逆序對最少的那個**；而**最優匹配一定是「同字元按出現順序一一對應」**（否則交換兩個同字元的對應可使逆序對不增），於是可以貪心地做。

### 定理 5（493 翻轉對的兩個陷阱）

*問題*：數 $\#\{(i,j) : i<j,\ a_i > 2a_j\}$。

**陷阱一（樹狀陣列版）：值域必須同時包含 $\{a_i\}$ 與 $\{2a_j\}$。**
查詢時要問「桶中有幾個值 $> 2a_j$」，而 $2a_j$ **不一定出現在原陣列中**。若只離散化 $\{a_i\}$，`lower_bound(2*a[j])` 會落在錯誤的排名上。**正確做法是把 $\{a_i\} \cup \{2a_i\}$ 合併後一起離散化**（也可以只離散化 $\{a_i\}$，但查詢時用 `upper_bound(2*a[j])` 取得「第一個 $> 2a_j$ 的排名」——兩種寫法都對，混著寫就錯）。

**陷阱二（歸併版）：計數必須在 merge 之前用獨立的雙指標完成。**
merge 的比較條件是 $a_p \le a_q$，與 $a_p > 2a_q$ **不是同一個條件**，不能共用同一組指標。正確結構是：

```cpp
// 先數，再併
for (int p = l, q = mid; q < r; ++q) {
    while (p < mid && (long long)a[p] <= 2LL * a[q]) ++p;
    res += mid - p;  // a[p..mid) 都 > 2*a[q]
}
// 然後才做標準 merge
```
**這一趟是 $O(r - l)$ 的**：$q$ 遞增時 $2a_q$ 遞增（右半已排序），故 $p$ **單調不減**，兩個指標各只走一遍 ✔。**單調性來自「右半已排序」，這是雙指標合法的唯一前提。**

**陷阱三（兩種版本共有）：溢位。** $a_i$ 可到 $2^{31}-1$，$2a_j$ 就超出 `int`。**`2LL * a[q]`，不是 `2 * a[q]`。**

### 定理 6（327 區間和的個數：移項與 $S_0$）

*問題*：數 $\#\{(i,j) : i \le j,\ \ell \le a_i + \cdots + a_j \le r\}$。

**化簡**：令 $S_0 = 0$、$S_k = a_1 + \cdots + a_k$。則子陣列 $[i, j]$ 的和 $= S_j - S_{i-1}$，於是
$$\ell \le S_j - S_{i-1} \le r \iff S_j - r \le S_{i-1} \le S_j - \ell,$$
問題變成：**對每個 $j$，數前綴和序列中下標 $< j$ 的項有幾個落在 $[S_j - r,\ S_j - \ell]$ 內。** 這正是定理 1 的框架，只是查詢從「前綴」變成「區間」（兩次前綴相減）。

**兩個必踩的坑：**
1. **$S_0 = 0$ 必須被插入桶中**。子陣列 $[1, j]$ 對應 $i - 1 = 0$；漏掉 $S_0$ 就會少算所有從頭開始的子陣列。**掃描迴圈要在處理 $S_1$ 之前先 `add(rk(0))`。**
2. **離散化的值域要含 $\{S_k\} \cup \{S_k - \ell\} \cup \{S_k - r\}$**（共 $3(n+1)$ 個），否則查詢邊界對不上。
3. **`long long`**：$n \le 10^5$、$|a_i| \le 2^{31}-1$ ⇒ $|S_k|$ 可達 $2\times10^{14}$。

**「先移項、再確認值域、最後補哨兵」是這一類題目的固定順序。** 三步任一步漏掉，答案都只會差一點點——**而「差一點點」是最難 debug 的錯誤**。

## 時間與空間複雜度

| 做法 | 時間 | 空間 | 備註 |
| --- | --- | --- | --- |
| 離散化 + 樹狀陣列 | $O(n\log n)$ | $O(n)$ | 排序 $O(n\log n)$ + $n$ 次 $O(\log n)$ 操作 |
| 歸併排序 | $O(n\log n)$ | $O(n)$ | 常數更小，**順便得到排序結果** |
| 值域線段樹（不離散化） | $O(n\log V)$ | $O(n\log V)$ | 動態開點，$V$ 為值域 |
| `pb_ds` 平衡樹 | $O(n\log n)$ | $O(n)$ | 常數大 3～5 倍，**但不用離散化** |
| 暴力 | $O(n^2)$ | $O(1)$ | $n \le 5000$ 時仍是最省腦力的選擇 |

**各題**：

| 題目 | 時間 | 值域大小 | 注意 |
| --- | --- | --- | --- |
| 315 右側小於當前元素 | $O(n\log n)$ | $n$ | 從右往左掃 |
| 493 翻轉對 | $O(n\log n)$ | $2n$ | `2LL *`，值域含 $2a$ |
| 327 區間和的個數 | $O(n\log n)$ | $3(n+1)$ | $S_0$、`long long` |
| 2426 滿足不等式的數對 | $O(n\log n)$ | $n$（或 $2n$） | 先令 $c = a - b$ |
| 1850 最小相鄰交換 | $O(k\cdot n + n^2)$ | — | $k$ 次 `next_permutation`，$n \le 1000$ 故 $O(n^2)$ 貪心即可 |

**常數比較（$n = 10^5$ 實測量級）**：歸併 $\approx$ 樹狀陣列 $<$ 值域線段樹 $<$ `pb_ds`。**但「離散化的那次 `sort`」通常才是主要成本**——樹狀陣列本身只佔總時間的三分之一左右。

**空間陷阱**：不離散化直接開值域桶。$|a_i| \le 10^9$ ⇒ 需要 $2\times10^9$ 個桶，必然 MLE。**看到值域大就離散化，或改用動態開點線段樹（9.5）。**

## 與相似技巧的比較

- **樹狀陣列 vs 歸併排序**：如「狀態」一節的表格。**單純數逆序對用歸併（短、快、不用離散化）；條件一複雜就用樹狀陣列（改一行查詢範圍即可）。** 493 是分水嶺：歸併版要多寫一趟雙指標，樹狀陣列版只要把 `rk(a[j])` 換成 `rk(2*a[j])`。
- **與 `pb_ds` order-statistics tree**：`tree<int, null_type, less<int>, rb_tree_tag, tree_order_statistics_node_update>` 直接提供 `order_of_key`，**完全不用離散化，而且支援刪除**。程式最短，常數最大。**面試或需要動態刪除時是好選擇。**
- **與值域線段樹／動態開點（9.5）**：功能等同樹狀陣列值域桶，但**不必離散化**（線上處理值域到 $10^9$）。代價是常數與空間。**離線可離散化 ⇒ 樹狀陣列；線上且值域大 ⇒ 動態開點。**
- **與 CDQ 分治**：本節處理**二維**偏序（下標 + 一個數值）。若條件是**三維**（$i<j$ 且 $a_i<a_j$ 且 $b_i<b_j$），一維交給分治、一維交給排序、一維交給樹狀陣列，就是 CDQ。**LeetCode 上罕見，但「掃描吃掉一維」的思路完全相同。**
- **與 9.1 樹狀陣列**：9.1 講的是資料結構本身，本節講的是**它最重要的應用模式**。**「離散化 + 值域桶 + 邊掃邊查」這三件事的組合，比樹狀陣列的實作重要得多。**
- **與「離線 + 排序」**：某些逆序對變形按值排序後可用雙指標解決，完全不需要資料結構。**先問「能不能離線」。**
- **與 6.1／6.3 的堆**：「前 $k$ 大」用堆，「有幾個比我大」用樹狀陣列。**堆回答的是極值，桶回答的是計數——需求不同，別互換。**
- **與 4.7 單調堆疊**：單調堆疊回答「左／右第一個比我大的」（**最近**的一個），樹狀陣列回答「有幾個比我大」（**計數**）。**兩者常在同一題的不同部分出現，看清楚問的是「哪一個」還是「有幾個」。**

## 本節重點速查

- **框架一句話**：兩個條件，**下標條件交給掃描順序，數值條件交給值域桶**（二維偏序）。
- **看到「對每個元素數前面有多少個滿足不等式」，第一件事永遠是移項**——把 $i$ 的量搬一邊、$j$ 的量搬另一邊。2426 的 $c = a - b$、327 的 $S_j - r \le S_{i-1} \le S_j - \ell$ 都是這一步。
- **不重不漏的理由（定理 1）**：配對 $(i,j)$ 只可能在處理 $j$ 的那一輪被計入，而那一輪桶中恰為 $\{a_i : i<j\}$。**框架的前提是「掃描順序能吃掉一整個維度」**；有距離限制或三維偏序就不夠。
- **`ans += j - sum(r)`**：用「總數減補集」算後綴，比直接查後綴不易錯。
- **離散化三件套 `sort` + `unique` + `lower_bound`**。**`unique` 不能省**（定理 3）：不去重會讓相同值拿到不同排名，相等對被誤判成逆序對。
- **歸併版的兩個前提（定理 2）**：左右各自已排序、左半整體在右半之前。**相等元素用 `<=` 取左邊 ⇒ 嚴格逆序對**，改成 `<` 就變成非嚴格。
- **逆序對數 $=$ 最少相鄰交換次數（定理 4）**：下界靠「一次交換只改變一對的相對順序」，上界靠「$\mathrm{inv}>0$ 必存在相鄰逆序對」。**只證下界不算證完。** 有重複元素時「同字元按出現順序一一對應」是最優匹配。
- **493 的三個陷阱**：值域要含 $2a$（或改用 `upper_bound`）、歸併版要**額外一趟**雙指標（單調性來自右半已排序）、**`2LL *` 防溢位**。
- **327 的三個陷阱**：**$S_0 = 0$ 必須先插入**、值域要含 $\{S\}\cup\{S-\ell\}\cup\{S-r\}$、`long long`。
- **選擇**：純逆序對 ⇒ 歸併；條件複雜 ⇒ 樹狀陣列；要線上或值域巨大 ⇒ 動態開點線段樹；懶得離散化又能忍常數 ⇒ `pb_ds`。
- **值域大不離散化就是 MLE**——這是本節最常見的當機原因。
