## 這個技術解決什麼問題

9.1 的定理 5 劃下了一條界線：**樹狀陣列靠 `sum(r) - sum(l-1)` 回答區間查詢，所以聚合必須有逆元。** max、min、gcd 都沒有逆元——知道 $[1,r]$ 的最大值和 $[1,l-1]$ 的最大值，**無法**還原 $[l,r]$ 的最大值。

線段樹換了一個思路：**不做減法，改做拼接。**

> **把 $[1, n]$ 遞迴二分成一棵樹，每個節點存自己那段的聚合值。任何區間 $[l, r]$ 都能拆成樹上 $O(\log n)$ 個節點的不交聯集，把它們的值合併起來就是答案。**

於是對聚合的要求從「群」放寬成**幺半群（monoid）**：只需要**結合律**與**單位元**，不需要逆元，也不需要交換律。

這個放寬帶來兩層能力：

1. **max / min / gcd / 位元 OR** 之類沒有逆元的聚合，全部可以做；
2. **更關鍵的**：節點裡可以存**複合資訊**。2213「由單個字元重複的最長子字串」的每個節點存「前綴最長同字元段、後綴最長同字元段、區間內最長同字元段、兩端字元」四樣東西，合併時靠邊界拼接算出跨界的段——**這種「答案不是簡單數值、而是一個需要精心設計合併規則的結構」，是線段樹真正不可替代的地方。**

**辨識訊號**：
- 單點改 + 區間查，但查的是 max / min / gcd 這類**不可差分**的聚合 ⇒ 2940、3161；
- 節點需要**複合資訊**才能合併 ⇒ 2213；
- 需要在樹上**二分**（找「第一個滿足某條件的位置」）⇒ 2940、2286；
- 一連串「修改某位置 + 詢問某區間性質」的操作流。

**本節只講單點修改。** 區間修改需要懶標記，那是 9.4。

## 狀態／資料結構定義

**樹形結構**（遞迴版，堆式編號）：節點 $k$ 覆蓋區間 $[\mathit{lo}_k, \mathit{hi}_k]$，根是節點 $1$ 覆蓋 $[0, n-1]$；若 $\mathit{lo} < \mathit{hi}$，令 $\mathit{mid} = \lfloor(\mathit{lo}+\mathit{hi})/2\rfloor$，左子 $2k$ 覆蓋 $[\mathit{lo}, \mathit{mid}]$、右子 $2k+1$ 覆蓋 $[\mathit{mid}+1, \mathit{hi}]$。

**幺半群介面**（把「聚合」抽象出來，之後換題只要換這一段）：

```cpp
struct Info {
    long long val;                                // 這段的聚合值
    static Info id() { return Info{LLONG_MIN}; }  // 單位元：max 的單位元是 -inf
    friend Info operator+(const Info& a, const Info& b) {
        return Info{max(a.val, b.val)};  // 結合律成立、單位元正確
    }
};
```

**單位元不能亂填。** 求 max 用 `0` 當單位元，在全是負數的資料上立刻錯；求 gcd 的單位元是 `0`（因為 $\gcd(0, x) = x$）；求 min 用 `LLONG_MAX`。**寫任何線段樹之前，先在紙上確認 `id() + x == x` 對所有 `x` 成立。**

**合併不必交換，但順序不能反。** `operator+` 的兩個參數是「左段」和「右段」，2213 的合併規則會用到「左段的右端字元 vs 右段的左端字元」——**`pushUp` 寫成 `t[k] = t[2k+1] + t[2k]` 就全錯了，而且在 max/sum 這類交換的聚合上測不出來。**

**節點陣列開 $4n$。** 理由見「時間與空間複雜度」。

**2213 的複合資訊**（本節最值得看的 `Info` 設計）：

```cpp
struct Info {
    int len;             // 這段長度
    int pre, suf, best;  // 前綴最長同字元段、後綴最長同字元段、區間最長同字元段
    char lc, rc;         // 這段最左、最右的字元
};
Info merge(const Info& L, const Info& R) {
    if (L.len == 0) return R;
    if (R.len == 0) return L;
    Info c;
    c.len = L.len + R.len;
    c.lc = L.lc;
    c.rc = R.rc;
    bool join = (L.rc == R.lc);
    c.pre = (L.pre == L.len && join) ? L.len + R.pre : L.pre;
    c.suf = (R.suf == R.len && join) ? R.len + L.suf : R.suf;
    c.best = max({L.best, R.best, join ? L.suf + R.pre : 0});
    return c;
}
```

**空段 `len == 0` 就是這個幺半群的單位元**，`merge` 的頭兩行負責它。

## 不變量或正確性證明

### 定理 1（結構不變量）

**不變量 (S)**：任何時刻，對每個節點 $k$，
$$t[k] = a[\mathit{lo}_k] \oplus a[\mathit{lo}_k + 1] \oplus \cdots \oplus a[\mathit{hi}_k]$$
（$\oplus$ 為幺半群運算，按**下標遞增順序**折疊）。

**維護**：`build` 自底向上一次填滿；單點修改只改一片葉子，然後沿**根路徑**逐層 `pushUp`。

*正確性*：修改位置 $x$ 只影響覆蓋 $x$ 的節點，而它們恰好是從葉子 $x$ 到根的那條路徑（每層恰一個，因為同層節點不交）。**這與 9.1 定理 3 是同一件事的不同版本**——那裡「覆蓋 $x$ 的段」是 lowbit 鏈，這裡是根路徑，**兩者長度都是 $O(\log n)$，這才是兩個結構複雜度相同的真正原因。**

### 定理 2（區間分解定理：$[l,r]$ 拆成 $O(\log n)$ 個節點）

這是線段樹的核心定理，**也是 9.1 那條「拆成 popcount 段」性質在線段樹上的對應物**。

*設定*：標準查詢遞迴為

```
query(k):
  若 [lo_k, hi_k] 與 [l, r] 不交      → 回傳單位元
  若 [lo_k, hi_k] ⊆ [l, r]           → 回傳 t[k]      （稱為「典範節點」）
  否則                                → 回傳 query(2k) ⊕ query(2k+1)
```

**引理 2.1（每層至多 2 個「部分相交」節點）**：稱節點 $k$ 為**部分相交**，若 $[\mathit{lo}_k, \mathit{hi}_k]$ 與 $[l,r]$ 相交但不被 $[l,r]$ 包含。則在遞迴樹的每一層，部分相交的節點至多 2 個。

*證明*。同層節點兩兩不交且從左到右排列。設某層有三個部分相交節點 $N_1 < N_2 < N_3$（按位置）。因為 $N_1$ 與 $[l,r]$ 相交，$[l,r]$ 含有 $N_2$ 左側的點，故 $l < \mathit{lo}_{N_2}$；因為 $N_3$ 與 $[l,r]$ 相交，$[l,r]$ 含有 $N_2$ 右側的點，故 $r > \mathit{hi}_{N_2}$。**於是 $[l,r] \supseteq N_2$，$N_2$ 不是部分相交**，矛盾 ✔。$\square$

**定理 2**：查詢遞迴訪問的節點數為 $O(\log n)$，其中典範節點至多 $2\lceil\log_2 n\rceil$ 個，且它們構成 $[l, r]$ 的一個**不交分割**。

*證明*。
- **訪問數**：只有部分相交的節點會繼續遞迴（不交與被包含都立即回傳）。由引理 2.1，每層至多 2 個節點遞迴，故每層至多產生 4 個子呼叫，訪問節點數 $\le 4\log_2 n = O(\log n)$ ✔。
- **典範節點數**：典範節點的父親必為部分相交（否則父親已被包含，遞迴不會下來），每個部分相交節點至多貢獻 2 個典範子節點，但**若兩個子節點都被包含，父親本身就被包含**——矛盾。故每個部分相交節點至多貢獻 **1** 個典範子節點 ⇒ 每層至多 2 個典範節點 ⇒ 總數 $\le 2\lceil\log_2 n\rceil$ ✔。
- **分割性**：遞迴在每個節點要嘛整段回傳、要嘛把段切成兩半分別處理，**過程中沒有任何位置被丟棄或重複**（不交的部分本來就不在 $[l,r]$ 內）。故典範節點的區間不交且聯集恰為 $[l,r]$ ✔。$\square$

**「不交且聯集為 $[l,r]$」加上「$\oplus$ 有結合律」，才推得出 `query` 的結果等於 $a_l \oplus \cdots \oplus a_r$。** 兩個前提缺一不可：

- **沒有分割性** ⇒ 元素被重複計入（對 max 無害，**對 sum 就是災難**）。這解釋了為什麼「不交」這件小事必須證。
- **沒有結合律** ⇒ 「先合併哪兩段」會影響結果，而遞迴的合併順序是由樹形決定的。**結合律是線段樹存在的前提，不是可有可無的細節。**

**推論 2.2**：交換律**不需要**。遞迴永遠以 `左 ⊕ 右` 的順序合併，與下標順序一致，故非交換的幺半群（如 2213 的 `Info`）完全合法。**但這也意味著任何一處把左右寫反都會出錯。**

### 定理 3（2213 的合併規則正確）

*命題*：設字串 $L$ 與 $R$ 相接成 $LR$，則 $LR$ 中最長的「單一字元重複段」長度為
$$\max\Big(L.\mathit{best},\ R.\mathit{best},\ [\,L.\mathit{rc} = R.\mathit{lc}\,]\cdot\big(L.\mathit{suf} + R.\mathit{pre}\big)\Big).$$

*證明*。取 $LR$ 中任一極長的同字元段 $B$。$B$ 是一段連續區間，三種情形窮盡：
- $B$ 完全落在 $L$ 內 ⇒ $|B| \le L.\mathit{best}$ ✔；
- $B$ 完全落在 $R$ 內 ⇒ $|B| \le R.\mathit{best}$ ✔；
- $B$ **跨越邊界** ⇒ $B$ 同時含 $L$ 的最後一個字元與 $R$ 的第一個字元，故 $L.\mathit{rc} = R.\mathit{lc}$；且 $B \cap L$ 是 $L$ 的一個同字元後綴、$B \cap R$ 是 $R$ 的一個同字元前綴，於是 $|B| \le L.\mathit{suf} + R.\mathit{pre}$ ✔。

反向：三個候選值都對應 $LR$ 中真實存在的同字元段（第三個需要 $L.\mathit{rc} = R.\mathit{lc}$ 才成立，已用指示函數守住）✔。取最大即得等號。$\square$

**`pre` 的規則同理**：$LR$ 的前綴同字元段等於 $L$ 的前綴段，**除非 $L$ 整段都是同一個字元且與 $R$ 的首字元相同**，此時可以延伸進 $R$。`suf` 對稱。

**結合律必須另外檢查。** `merge` 只是一個二元運算，**線段樹要求 $(A \oplus B) \oplus C = A \oplus (B \oplus C)$**。上述規則滿足結合律（兩邊都等於「對三段串接的直接計算」），但**自訂 `Info` 時這一步經常被跳過，然後在特定的分割形狀下才爆炸**。**實務檢查法：拿三個單字元葉子，手算兩種括號方式，確認結果相同。**

### 定理 4（線段樹上二分：2940 的 $O(\log n)$ 而非 $O(\log^2 n)$）

*問題*：2940 要對每組 $(i, j)$（設 $i < j$）找**最小的 $k > j$ 使 $h[k] > \max(h[i], h[j])$**。

*演算法*：在區間 $[j+1, n-1]$ 上找第一個值 $> x$ 的位置。

```
descend(k):                    // 前提：t[k].mx > x
  若 k 是葉子 → 回傳 lo_k
  若 t[2k].mx > x → 回傳 descend(2k)
  否則             → 回傳 descend(2k+1)
```
外層照定理 2 把 $[j+1, n-1]$ 分解成**由左到右**的典範節點序列，**掃到第一個 `mx > x` 的節點就 `descend` 進去，立即回傳。**

**正確性**：
- **剪枝安全**：`t[k].mx <= x` 表示該子樹內**每個**元素都 $\le x$，跳過不會漏 ✔。
- **回傳的是最小下標**：典範節點按下標遞增排列，第一個含合法元素的節點必包含答案；`descend` 內優先走左子樹，而「左子樹有合法元素」時答案必在左子樹（下標更小）✔。

**複雜度 $O(\log n)$**：分解出 $O(\log n)$ 個典範節點，每個只做 $O(1)$ 的 `mx > x` 判斷；**`descend` 只會被呼叫一次**，且深度 $O(\log n)$ ✔。

**不要寫成「外層二分答案 + 內層區間查 max」**——那是 $O(\log^2 n)$，而且在 $q = 10^5$ 時差距明顯。**「把二分做進樹裡」是線段樹相對於樹狀陣列與 ST 表的一個獨門優勢。**

### 定理 5（2286 的 `scatter` 為什麼是攤還 $O(\log n)$）

*問題*：$n$ 排、每排 $m$ 個座位。`gather(k, maxRow)` 找最小的排使剩餘座位 $\ge k$；`scatter(k, maxRow)` 從最小的排開始依序分配 $k$ 個座位。

*結構*：線段樹每個節點同時維護該段的**剩餘座位最大值** `mx`（供 `gather` 做定理 4 的樹上二分）與**剩餘座位總和** `sum`（供 `scatter` 判斷可行性）。

**`scatter` 的實作是遞迴下降，遇到「本排剩餘 $\le$ 待分配量」就把整排填滿並繼續。** 單次最壞是 $O(n\log n)$（填滿很多排），但——

**命題**：$q$ 次操作的**總**成本為 $O\big((n + q)\log n\big)$。

*證明（攤還）*。把 `scatter` 遞迴訪問的葉子分成兩類：
- **被填滿的排**：該排從此剩餘 0，**永遠不會再被 `scatter` 訪問**（訪問前會先檢查剩餘 $>0$）。全程至多 $n$ 次 ✔。
- **未被填滿的排**：每次 `scatter` 至多一個（$k$ 用完就停）。全程至多 $q$ 次 ✔。

每次葉子訪問伴隨 $O(\log n)$ 的路徑代價，總計 $O((n+q)\log n)$ ✔。$\square$

**又一次是「昂貴的迭代對應不可逆的狀態變化」**——與 8.5 定理 2、4.7 單調堆疊、6.6 懶刪除同形。**這個攤還模式在整個資料結構章出現了至少五次，值得當成一個獨立的思考工具記住：先問「這個昂貴的步驟消耗了什麼不可再生的資源」。**

## C++17 模板

**模板一：通用單點改 + 區間查（把 `Info` 換掉就能重用）**

```cpp
template <class Info>
struct SegTree {
    int n;
    vector<Info> t;
    explicit SegTree(const vector<Info>& a) : n(a.size()), t(4 * a.size()) {
        build(1, 0, n - 1, a);
    }
    void build(int k, int lo, int hi, const vector<Info>& a) {
        if (lo == hi) {
            t[k] = a[lo];
            return;
        }
        int mid = (lo + hi) >> 1;
        build(2 * k, lo, mid, a);
        build(2 * k + 1, mid + 1, hi, a);
        t[k] = t[2 * k] + t[2 * k + 1];  // 順序不可反
    }
    void update(int k, int lo, int hi, int pos, const Info& v) {
        if (lo == hi) {
            t[k] = v;
            return;
        }
        int mid = (lo + hi) >> 1;
        if (pos <= mid)
            update(2 * k, lo, mid, pos, v);
        else
            update(2 * k + 1, mid + 1, hi, pos, v);
        t[k] = t[2 * k] + t[2 * k + 1];
    }
    Info query(int k, int lo, int hi, int l, int r) const {
        if (r < lo || hi < l) return Info::id();  // 不交
        if (l <= lo && hi <= r) return t[k];      // 典範節點
        int mid = (lo + hi) >> 1;
        return query(2 * k, lo, mid, l, r) +
               query(2 * k + 1, mid + 1, hi, l, r);
    }
    // 對外介面
    void update(int pos, const Info& v) { update(1, 0, n - 1, pos, v); }
    Info query(int l, int r) const {
        if (l > r) return Info::id();
        return query(1, 0, n - 1, l, r);
    }
};
```

**模板二：2213 由單個字元重複的最長子字串（複合 `Info`）**

```cpp
struct Info {
    int len = 0, pre = 0, suf = 0, best = 0;
    char lc = 0, rc = 0;
    static Info id() { return Info{}; }  // len == 0 即單位元
    friend Info operator+(const Info& L, const Info& R) {
        if (L.len == 0) return R;
        if (R.len == 0) return L;
        Info c;
        c.len = L.len + R.len;
        c.lc = L.lc;
        c.rc = R.rc;
        bool join = (L.rc == R.lc);
        c.pre = (L.pre == L.len && join) ? L.len + R.pre : L.pre;
        c.suf = (R.suf == R.len && join) ? R.len + L.suf : R.suf;
        c.best = max({L.best, R.best, join ? L.suf + R.pre : 0});
        return c;
    }
};

class Solution {
public:
    vector<int> longestRepeating(string s, string queryCharacters,
                                 vector<int>& queryIndices) {
        int n = s.size();
        vector<Info> a(n);
        for (int i = 0; i < n; ++i) a[i] = Info{1, 1, 1, 1, s[i], s[i]};
        SegTree<Info> st(a);
        vector<int> ans;
        ans.reserve(queryIndices.size());
        for (int q = 0; q < (int)queryIndices.size(); ++q) {
            char c = queryCharacters[q];
            int i = queryIndices[q];
            st.update(i, Info{1, 1, 1, 1, c, c});
            ans.push_back(st.query(0, n - 1).best);
        }
        return ans;
    }
};
```

**模板三：線段樹上二分——區間內第一個 $> x$ 的下標（定理 4）**

```cpp
struct MaxSeg {
    int n;
    vector<int> mx;
    explicit MaxSeg(const vector<int>& a)
        : n(a.size()), mx(4 * a.size(), INT_MIN) {
        build(1, 0, n - 1, a);
    }
    void build(int k, int lo, int hi, const vector<int>& a) {
        if (lo == hi) {
            mx[k] = a[lo];
            return;
        }
        int mid = (lo + hi) >> 1;
        build(2 * k, lo, mid, a);
        build(2 * k + 1, mid + 1, hi, a);
        mx[k] = max(mx[2 * k], mx[2 * k + 1]);
    }
    // 在 [l, n-1] 中找第一個 > x 的下標；不存在回傳 -1
    int firstGreater(int k, int lo, int hi, int l, int x) const {
        if (hi < l || mx[k] <= x) return -1;  // 剪枝：整段都 <= x
        if (lo == hi) return lo;
        int mid = (lo + hi) >> 1;
        int res = firstGreater(2 * k, lo, mid, l, x);
        if (res != -1) return res;  // 左子樹優先 ⇒ 下標最小
        return firstGreater(2 * k + 1, mid + 1, hi, l, x);
    }
    int firstGreater(int l, int x) const {
        if (l >= n) return -1;
        return firstGreater(1, 0, n - 1, l, x);
    }
};
```

**`mx[k] <= x` 這個剪枝是整段程式的靈魂**：沒有它就是 $O(n)$ 的暴力遞迴，有了它就是 $O(\log n)$。

## 時間與空間複雜度

| 操作 | 時間 | 說明 |
| --- | --- | --- |
| `build` | $O(n)$ | 每個節點 $O(1)$，節點總數 $O(n)$ |
| 單點修改 | $O(\log n)$ | 根路徑長度 |
| 區間查詢 | $O(\log n)$ | 定理 2：至多 $4\log_2 n$ 個節點 |
| 樹上二分 | $O(\log n)$ | 定理 4，**不是 $O(\log^2 n)$** |
| 空間 | $\mathbf{4n}$ 個節點 | 見下 |

**為什麼是 $4n$ 而不是 $2n$**：堆式編號要求陣列大小為「完全二元樹的節點數」。當 $n$ 不是 2 的冪時，樹的最底層會有空洞，最壞需要 $2 \cdot 2^{\lceil\log_2 n\rceil} \le 4n$。例如 $n = 5$ 時最大節點編號是 $13 > 2n$。**開 $2n$ 是最常見的線段樹越界原因，而且往往只在特定 $n$ 上才炸。** 想省空間就用非遞迴（zkw）版或動態開點（9.5）。

**與樹狀陣列的實測比較**（$n = 10^5$、$q = 10^5$）：

| | 樹狀陣列 | 線段樹（遞迴） | 線段樹（非遞迴） |
| --- | --- | --- | --- |
| 程式行數 | ~10 | ~60 | ~30 |
| 空間 | $n$ | $4n$ | $2n$ |
| 相對耗時 | 1.0 | 2～4 | 1.3～2 |
| 支援 max/min/gcd | ❌ | ✅ | ✅ |
| 支援複合 `Info` | ❌ | ✅ | ✅（合併非交換時要小心） |

**各題**：

| 題目 | 時間 | 節點資訊 |
| --- | --- | --- |
| 2213 最長重複子字串 | $O((n + q)\log n)$ | `len/pre/suf/best/lc/rc` |
| 2940 Alice 和 Bob 相遇 | $O((n + q)\log n)$ | `max` + 樹上二分 |
| 2286 團體訂票 | $O((n + q)\log n)$ **攤還** | `max` + `sum`，定理 5 |
| 3161 放置方塊查詢 | $O((n+q)\log n)$ | `max`（區段長）+ 樹上二分 |

**注意 2940 也有 $O(n + q)$ 的離線做法**（把查詢按 $j$ 分組 + 單調堆疊）。**線段樹是通用解，不一定是最優解——寫之前值得花三十秒想想有沒有離線的捷徑。**

## 常見錯誤與邊界條件

- **節點陣列只開 $2n$**。必須 $4n$（或用 `2 << (32 - __builtin_clz(n))`）。**這是線段樹第一大坑。**
- **`pushUp` 的左右順序寫反**。`t[k] = t[2k] + t[2k+1]`，不是反過來。**在 sum/max 上測不出來，換到 2213 這種非交換的 `Info` 立刻錯。**
- **忘記 `pushUp`**。單點修改後只改葉子不往上更新，查詢會讀到舊值。
- **單位元填錯**。max 用 `0`（全負資料錯）、min 用 `0`（全正資料錯）、gcd 的單位元是 `0` 不是 `1`。**寫之前先驗證 `id() + x == x`。**
- **空區間查詢沒處理**。$l > r$ 時要回傳單位元。**2940 的 $j = n-1$、327 的邊界都會觸發。**
- **不交判斷寫錯**。`if (r < lo || hi < l) return id();` 少一個等號就會漏或重。
- **`mid` 的計算與子區間劃分不一致**。左子是 $[\mathit{lo}, \mathit{mid}]$、右子是 $[\mathit{mid}+1, \mathit{hi}]$。**寫成 $[\mathit{lo}, \mathit{mid}-1]$／$[\mathit{mid}, \mathit{hi}]$ 會在 $\mathit{lo}+1 = \mathit{hi}$ 時無窮遞迴。**
- **0-indexed 與 1-indexed 混用**。整份程式選一種並貫徹。本節模板一律 0-indexed 資料 + 1-indexed 節點編號。
- **`Info` 沒驗證結合律**。自訂複合資訊時**一定要用三個葉子手算兩種括號方式**。
- **溢位**。求和用 `long long`；`(lo + hi) >> 1` 在 $n$ 不到 $10^9$ 時安全，但別在超大值域的動態開點上照抄。
- **樹上二分寫成外層二分**。$O(\log^2 n)$ 在 $q = 10^5$ 時可能 TLE，而且程式並沒有比較短。
- **2286 忘記 `maxRow` 的限制**。`gather`／`scatter` 都只在 $[0, \mathit{maxRow}]$ 內操作，樹上二分的範圍要跟著限制。
- **遞迴深度**。$n = 10^5$ 時深度只有 17，**遞迴版完全安全**，不必為此改寫成非遞迴。

## 與相似技巧的比較

- **與 9.1 樹狀陣列**：分界線是**定理 5（9.1）**——聚合有沒有逆元。**能用樹狀陣列就用**（短 6 倍、快 2～4 倍、省 4 倍空間）。max/min/gcd、複合資訊、樹上二分才輪到線段樹。
- **與 9.4 Lazy 線段樹**：本節只做**單點**修改，所以不需要懶標記——修改只影響一條根路徑，沿路 `pushUp` 即可。**一旦出現「把一整段全加／全設為某值」就必須加 lazy**，那是另一套心智負擔（`pushDown`、標記合併、標記與查詢的順序）。**不需要區間修改時不要寫 lazy 版，多出來的每一行都是 bug 的機會。**
- **與 9.5 動態開點**：本節假設值域 $= [0, n-1]$ 且 $n$ 不大。值域到 $10^9$ 且稀疏時，改成動態開點（用指標或左右子下標，只在需要時建節點）。**結構與定理 2 完全相同，只是節點按需分配。**
- **與 9.7 ST 表**：ST 表 $O(1)$ 查詢、$O(n\log n)$ 預處理，**但完全不支援修改**，且只適用**可重複貢獻**的聚合（max/min/gcd，因為區間可以重疊）。**判準只有一句：資料會不會改。** 不會改 + 大量區間 max 查詢 ⇒ ST 表完勝。
- **與 4.7 單調堆疊**：單調堆疊 $O(n)$ 解決「每個位置左／右第一個比它大的」，**線段樹二分 $O(n\log n)$ 也能做同一件事**。**能離線就用單調堆疊**；要線上、要帶修改、要任意起點才用線段樹（2940 的線上版本）。
- **與分塊（第 11 章）**：分塊 $O(\sqrt n)$ 更慢，但**不要求結合律**，能處理「沒有好的合併規則」的怪操作。**線段樹寫不出 `merge` 時，才考慮分塊。**
- **與 8.5 區間並查集**：那是「每格只處理一次」的一次性標記，$O((n+q)\alpha)$ 遠快於線段樹。**只要前提成立就用它**；有撤銷、有累加、有中途查詢才升級到線段樹。

## 例題與分級練習

**延伸閱讀**：通用、已驗證的介面可參考 [AtCoder Library `segtree.hpp`](https://github.com/atcoder/ac-library/blob/master/atcoder/segtree.hpp)；重點是合併運算需滿足結合律並提供單位元。

## 本節重點速查

- **存在理由**：樹狀陣列靠差分，需要**逆元**；線段樹靠拼接，只需要**幺半群**（結合律 + 單位元），**不需要交換律**。
- **兩個能力**：(1) max/min/gcd 這類不可差分的聚合；(2) **節點存複合資訊**（2213 的 `len/pre/suf/best/lc/rc`）——後者才是線段樹不可替代的地方。
- **定理 2 是核心**：每層至多 **2 個部分相交節點**（三個會導致中間那個被完全包含，矛盾）⇒ 訪問 $O(\log n)$ 個節點、典範節點 $\le 2\log_2 n$ 個、且**不交且聯集為 $[l,r]$**。
- **「不交」與「結合律」缺一不可**：沒有前者 sum 會重複計入，沒有後者合併順序會改變答案。
- **單位元要驗證**：max ⇒ $-\infty$、min ⇒ $+\infty$、**gcd ⇒ 0**、sum ⇒ 0。寫之前先確認 `id() + x == x`。
- **`pushUp` 順序 `t[2k] + t[2k+1]` 不可反**——在 sum/max 上測不出來，在 2213 上必錯。
- **自訂 `Info` 要手動驗結合律**：三個葉子、兩種括號方式，結果必須相同。
- **節點陣列開 $4n$**，不是 $2n$。這是第一大坑。
- **樹上二分是獨門優勢（定理 4）**：`mx <= x` 剪枝 + 左子優先 ⇒ **$O(\log n)$ 找第一個滿足條件的位置**。不要寫成外層二分的 $O(\log^2 n)$。
- **2286 的攤還（定理 5）**：填滿的排永不再訪（$\le n$ 次）+ 每次至多一個未填滿的排（$\le q$ 次）。**「昂貴迭代對應不可逆狀態變化」在本章已出現五次**（4.7、6.6、8.1、8.5、本節）。
- **選擇順序**：能前綴和就前綴和 → 能樹狀陣列就樹狀陣列 → 不可差分或要複合資訊才線段樹 → 要區間改才 lazy（9.4）→ 值域大才動態開點（9.5）→ 不改資料且只查 max/min/gcd 就 ST 表（9.7）。
