## 這個技術解決什麼問題

9.3 的線段樹只能**單點**修改：改一個位置，沿根路徑往上 `pushUp`，$O(\log n)$。

但如果要「把 $[l, r]$ 全部加 $v$」呢？照 9.3 的做法要改 $r - l + 1$ 片葉子，單次 $O(n\log n)$——比暴力還糟。

**懶標記的想法只有一句：**

> **改到「整段都被包含」的節點就停下來，直接更新這個節點的聚合值，並在節點上記一筆「我欠子孫一個修改」的帳。只有真的要往下走時，才把帳結清。**

由 9.3 定理 2，$[l, r]$ 只會拆出 $O(\log n)$ 個典範節點，**在每個典範節點打一個標記就走人**，於是區間修改也是 $O(\log n)$。

**但這個「欠帳」的機制對聚合提出了三個新要求**（9.3 的幺半群不夠了）：

1. **能整段套用**：給定標記 $f$、段長 $\mathit{len}$、原聚合值 $x$，必須能在 $O(1)$ 算出 $\mathrm{apply}(x, f, \mathit{len})$。區間加求和 ⇒ $x + v\cdot \mathit{len}$ ✔；**區間加求 max ⇒ $x + v$ ✔；區間加求「不同值的個數」⇒ 算不出來 ❌。**
2. **標記能合成**：一個節點可能連續欠好幾筆帳，必須能把它們壓成一筆。
3. **套用與合併可交換**（分配律）：$\mathrm{apply}(a \oplus b, f) = \mathrm{apply}(a, f) \oplus \mathrm{apply}(b, f)$。**這條保證了「在父節點打標記」與「在兩個子節點各打一次標記」等價**——沒有它，懶標記整套機制不成立。

**滿足這三條的，數學上叫「幺半群上的作用（monoid action）」。** 本節的所有細節都是這三條的實作。

**辨識訊號**：
- 「把一整段全部加 $v$ / 全部設為 $v$」+ 區間聚合查詢 ⇒ 2502、LCP 52；
- **掃描線**：每條邊讓一段的「覆蓋次數 $\pm1$」，再查「目前被覆蓋的總長度」⇒ 850；
- **DP 轉移的批次更新**：$dp$ 的候選值在加入新元素時整段同時變化 ⇒ 2547；
- 全域的加、乘、查詢 ⇒ 1622（**這題是標記代數的極簡形式，見「C++17 模板」的說明**）。

## 狀態／資料結構定義

每個節點多存一個**懶標記** `lz[k]`，語意是：

> **`t[k]` 已經反映了 `lz[k]`；但 $k$ 的兩個子節點（及其子樹）還沒有。**

這句話就是全部的約定，**寫錯任何一行 lazy 程式碼，本質上都是違反了它**。

**三個必須成對定義的原語：**

```cpp
// 1) 把標記 f 套到「一個長度為 len、聚合值為 x 的段」上
void applyTag(int k, int len, Tag f);
// 2) 把標記 g 疊到節點已有的標記上（先 lz[k]，後 g）
Tag composeTag(Tag old, Tag g);
// 3) 把 lz[k] 下推給兩個子節點，然後清空
void pushDown(int k, int lLen, int rLen);
```

**「區間加、區間求和」的具體版本：**

```cpp
struct LazySeg {
    int n;
    vector<long long> t, lz;  // lz[k]：整段每個元素還欠加多少
    explicit LazySeg(const vector<long long>& a)
        : n(a.size()), t(4 * a.size(), 0), lz(4 * a.size(), 0) {
        build(1, 0, n - 1, a);
    }
    void build(int k, int lo, int hi, const vector<long long>& a) {
        if (lo == hi) {
            t[k] = a[lo];
            return;
        }
        int mid = (lo + hi) >> 1;
        build(2 * k, lo, mid, a);
        build(2 * k + 1, mid + 1, hi, a);
        t[k] = t[2 * k] + t[2 * k + 1];
    }
    void applyTag(int k, int len, long long v) {
        t[k] += v * len;  // 整段套用：需要段長
        lz[k] += v;       // 標記合成：加法標記直接相加
    }
    void pushDown(int k, int lo, int mid, int hi) {
        if (lz[k] == 0) return;
        applyTag(2 * k, mid - lo + 1, lz[k]);
        applyTag(2 * k + 1, hi - mid, lz[k]);
        lz[k] = 0;  // 清帳，不可漏
    }
    void update(int k, int lo, int hi, int l, int r, long long v) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {
            applyTag(k, hi - lo + 1, v);
            return;
        }
        int mid = (lo + hi) >> 1;
        pushDown(k, lo, mid, hi);
        update(2 * k, lo, mid, l, r, v);
        update(2 * k + 1, mid + 1, hi, l, r, v);
        t[k] = t[2 * k] + t[2 * k + 1];
    }
    long long query(int k, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return 0;
        if (l <= lo && hi <= r) return t[k];
        int mid = (lo + hi) >> 1;
        pushDown(k, lo, mid, hi);  // 查詢也要 pushDown！
        return query(2 * k, lo, mid, l, r) +
               query(2 * k + 1, mid + 1, hi, l, r);
    }
};
```

**`query` 也要 `pushDown`**——這是初學者第一個踩的坑。查詢會走進節點內部，內部節點的子樹還欠著帳，不結清就讀到舊值。（副作用是 `query` **不能宣告成 `const`**。）

**常見標記代數一覽：**

| 修改 | 標記 $f$ | 合成（先 $f_1$ 後 $f_2$） | 套用（段長 $\mathit{len}$） |
| --- | --- | --- | --- |
| 區間加，查和 | $v$ | $v_1 + v_2$ | $x + v\cdot \mathit{len}$ |
| 區間加，查 max | $v$ | $v_1 + v_2$ | $x + v$ |
| **區間賦值**，查和 | $c$ | **$c_2$（後者吃掉前者）** | $c \cdot \mathit{len}$ |
| **加 + 乘**（仿射） | $(m, b):\ x\mapsto mx+b$ | $(m_1m_2,\ b_1m_2 + b_2)$ | $m\cdot x + b\cdot \mathit{len}$ |
| 賦值 + 加（混用） | `(hasAssign, c, v)` | **賦值會清掉待加的量** | 分兩種情形 |

**「賦值 + 加」混用是最容易寫錯的組合。** 約定成 $x \mapsto (\text{有賦值} ? c : x) + v$，則疊上新標記時：新的是賦值 ⇒ 整個舊標記作廢，換成 `(true, c_new, 0)`；新的是加 ⇒ `v += v_new`（`hasAssign` 與 `c` 不動）。**先在紙上寫清楚語意，再寫程式。**

## 不變量或正確性證明

### 定理 1（懶標記的主不變量）

令 $a[\cdot]$ 為陣列的**真實**當前值。對節點 $k$，令 $A_k$ 為從根到 $k$ 的**嚴格祖先**的標記依序合成後的作用。

**不變量 (L)**：任何時刻，
$$A_k\big(t[k]\big) = \bigoplus_{i \in [\mathit{lo}_k,\, \mathit{hi}_k]} a[i],$$
且 `lz[k]` 已經反映在 `t[k]` 中、尚未反映在子樹中。

換一種說法：**`t[k]` 是「假裝所有祖先的欠帳都不存在」時，這一段的正確聚合值。** 根節點沒有祖先，故 $t[1]$ 永遠是全域的真實聚合值。

**維護的四個地方：**

- **`applyTag(k, len, f)`（節點 $k$ 被整段修改）**：$t[k] \leftarrow \mathrm{apply}(t[k], f, \mathit{len})$、$\mathit{lz}[k] \leftarrow \mathrm{compose}(\mathit{lz}[k], f)$。$k$ 的真實聚合值確實被 $f$ 作用了一次，$t[k]$ 跟著變 ✔；子孫的 (L) 不變，因為它們的祖先鏈剛好多了一個 $f$，而 $A$ 也跟著多了一個 $f$ ✔。**這一步的合法性正是「要求 1（能整段套用）」。**
- **`pushDown(k)`**：把 $\mathit{lz}[k]$ 套到兩個子節點再清空。子節點的 $t$ 被 $f$ 作用一次，而它們的 $A$ 少了一個 $f$，**兩者恰好抵消** ✔。$k$ 自己的 $t[k]$ 不變、$A_k$ 不變 ✔。
- **`pushUp(k)`**：$t[k] \leftarrow t[2k] \oplus t[2k+1]$。此處要求 $A_{2k} = A_{2k+1} = A_k \circ \mathit{lz}[k]$，而 `pushUp` 只在 `pushDown` 之後（$\mathit{lz}[k] = \text{id}$）呼叫，故 $A_{2k} = A_k$，兩子的 $t$ 直接合併就是 $k$ 的 $t$ ✔。**這解釋了為什麼「先 `pushDown` 再遞迴、回來再 `pushUp`」的順序不能動。**
- **`query` 走進內部節點**：必須先 `pushDown`，否則讀到的子節點 $t$ 少算了 $\mathit{lz}[k]$ ✔。

$\square$

**(L) 點名的關鍵前提是「$A_k$ 對子樹的每個位置一視同仁」**——祖先的標記作用在整段上，不會只作用在半段。**這正是「分配律（要求 3）」在證明中的角色**：$A_k(t[2k] \oplus t[2k+1]) = A_k(t[2k]) \oplus A_k(t[2k+1])$。若沒有分配律，「在父節點打一個標記」與「在兩個子節點各打一次」就不等價，(L) 的第二條 bullet 立刻失效。

### 定理 2（區間修改是 $O(\log n)$）

*證明*。修改遞迴與 9.3 的查詢遞迴**形狀完全相同**（不交則返回、被包含則處理、否則分兩半）。由 9.3 定理 2，訪問節點數 $O(\log n)$。每個節點額外做 $O(1)$ 的 `pushDown` / `applyTag` / `pushUp` ✔。$\square$

**注意這是最壞情況界，不是攤還界。** `pushDown` 不會累積債務：每次訪問一個節點就結清它的帳，而訪問總數已被定理 2 限制住。

### 定理 3（仿射標記的合成公式）

*設定*：標記 $(m, b)$ 表示 $x \mapsto mx + b$（**先乘後加**）。

*命題*：先套 $(m_1, b_1)$ 再套 $(m_2, b_2)$，等於套 $(m_1 m_2,\ b_1 m_2 + b_2)$。

*證明*：$m_2\big(m_1 x + b_1\big) + b_2 = (m_1m_2)x + (b_1m_2 + b_2)$ ✔。$\square$

*套用到「長度 $\mathit{len}$ 的段和」*：$\sum (m x_i + b) = m\sum x_i + b\cdot \mathit{len}$ ✔——**分配律成立，所以仿射變換可以當懶標記。**

**「先乘後加」是一個約定，不是定理。** 若你定義成 $x \mapsto m(x + b)$，合成公式就變成 $(m_1m_2,\ b_1 + b_2/m_1)$——**需要除法，在模運算下要求逆元存在**。**選 $x \mapsto mx + b$，永遠。**

**推論（`pushDown` 的順序）**：把父標記 $(m, b)$ 下傳給已有標記 $(m', b')$ 的子節點，正確結果是 $(m'm,\ b'm + b)$——**先乘再加，順序寫反是本節最常見的 WA。**

### 定理 4（區間賦值的標記吸收律）

*命題*：賦值標記 $C_c : x \mapsto c$ 滿足 $g \circ C_c = C_{g(c)}$ 且 $C_c \circ g = C_c$（後套的賦值吃掉一切）。

*證明*：$C_c(g(x)) = c$，故 $C_c \circ g = C_c$ ✔；$g(C_c(x)) = g(c)$，為常數映射 ✔。$\square$

**實作意涵**：疊上賦值標記時，**必須把節點上待處理的加法標記整個丟棄**（而不是保留）。忘記丟棄就會出現「先賦值成 5，再被之前欠的 +3 補上變成 8」的幽靈 bug。**在紙上寫清楚「我的標記代表哪個函數」，然後套定理 4 推導合成規則——不要憑感覺拼。**

### 定理 5（850 掃描線：為什麼**不需要**也**不能**下傳標記）

這是本節最值得單獨拿出來講的一題。

*設定*：矩形面積並。把 $y$ 座標離散化成 $m$ 個值，線段樹的葉子代表**相鄰兩個 $y$ 之間的縫隙**（不是點）。掃描 $x$ 時，矩形的左邊讓 $[y_1, y_2)$ 的「覆蓋次數 $+1$」、右邊 $-1$。每次要查**根**的「被覆蓋總長度」。

*結構*：節點存 `cnt[k]`（**恰好完整覆蓋 $\mathrm{seg}(k)$ 的區間有幾個**，即打在 $k$ 上的次數淨值）與 `len[k]`（$\mathrm{seg}(k)$ 中被覆蓋的長度）。

```cpp
void pushUp(int k, int lo, int hi) {
    if (cnt[k] > 0)
        len[k] = ys[hi + 1] - ys[lo];  // 整段被蓋滿
    else if (lo == hi)
        len[k] = 0;  // 葉子且無覆蓋
    else
        len[k] = len[2 * k] + len[2 * k + 1];
}
```

**不變量 (C)**：$\mathit{cnt}[k]$ 等於「典範分解**恰好包含節點 $k$**」的活躍區間數量；
$$\mathit{len}[k] = \big|\{\,y \in \mathrm{seg}(k) : y \text{ 被某個典範分解落在 } k \text{ 子樹內的活躍區間覆蓋}\,\}\big|.$$

*證明（對節點高度歸納）*。
- $\mathit{cnt}[k] > 0$ ⇒ 有區間完整覆蓋 $\mathrm{seg}(k)$ ⇒ 整段都被覆蓋 ⇒ $\mathit{len}[k] = |\mathrm{seg}(k)|$ ✔（**注意此時不能寫成 $\mathit{len}[2k] + \mathit{len}[2k+1]$，因為子樹並不知道父親被蓋滿了**）。
- $\mathit{cnt}[k] = 0$ ⇒ 沒有區間的典範分解正好是 $k$ ⇒ 落在 $k$ 子樹內的典範節點都在兩個子樹裡，由歸納假設兩邊各自正確且**不交**，相加即得 ✔。
- 葉子且 $\mathit{cnt} = 0$ ⇒ $0$ ✔。$\square$

**根的正確性**：任一活躍區間的典範分解**不重不漏**地落在某些節點上（9.3 定理 2），故 $\mathit{len}[1]$ 恰為被至少一個活躍區間覆蓋的總長度 ✔。

**為什麼不能 `pushDown`**：修改是**成對的 $+1/-1$**，$\mathit{cnt}$ 可以減回 $0$。**若把 $+1$ 下傳給子節點，後來的 $-1$ 打在哪裡就變成一筆糊塗帳**（$-1$ 的典範分解可能與 $+1$ 的不同——實際上在本題中相同，但一旦下傳過，節點上的資訊就對不起來了）。**上面的 `pushUp` 之所以能只靠 `cnt[k] > 0` 的三分支就恢復正確值，正是因為標記從不離開它被打上的那個節點。**

**這是一個重要的一般教訓：懶標記不是唯一的區間修改手法。當標記「可撤銷」且「只查詢根」時，『標記永駐 + 特殊 pushUp』往往更簡單、更安全。** 掃描線類問題（矩形面積並、矩形周長並、天際線）幾乎都用這一招。

### 定理 6（2547：DP 轉移的區間批次更新）

*問題*：把陣列分成若干段，每段代價 $= k + (\text{段長} - \text{段內恰好出現一次的元素個數})$，求最小總代價。

令 $\mathrm{tr}(l, r) = \sum_{v:\ \mathrm{cnt}_v \ge 2} \mathrm{cnt}_v$（段內出現 $\ge 2$ 次的元素的總個數），則 $dp[i] = \min_{0 \le j < i}\big(dp[j] + k + \mathrm{tr}(j+1, i)\big)$。

**命題**：每把一個新元素 $a_i$ 併進來，函數 $g(j) = dp[j] + \mathrm{tr}(j+1, i)$ 只在 $O(1)$ 段區間上變化，且變化量是常數。

*證明*。令 $p_1$ 為 $a_i$ 在 $[0, i-1]$ 的最後一次出現位置，$p_2$ 為倒數第二次（不存在則設為 $-\infty$ 對應的空區間）。對每個 $j$，考慮 $a_i$ 在 $[j+1, i-1]$ 中的出現次數 $c_j$：
- $j \le p_2 - 1$ ⇒ $c_j \ge 2$ ⇒ 加入第 $c_j+1$ 個 ⇒ $\mathrm{tr}$ **$+1$**；
- $p_2 \le j \le p_1 - 1$ ⇒ $c_j = 1$ ⇒ 該值從「不計入」變成「計入 2 個」 ⇒ $\mathrm{tr}$ **$+2$**；
- $j \ge p_1$ ⇒ $c_j = 0$ ⇒ 該值仍只出現一次 ⇒ $\mathrm{tr}$ **$+0$** ✔。

三段互不重疊且覆蓋 $[0, i-1]$ ✔。$\square$

**於是每一步只要兩次「區間加」，再查一次「全域最小」，$O(n\log n)$ 完成。** $dp[i] = k + \min_{j} g(j)$，把 $dp[i]$ 寫回線段樹的位置 $i$。

**這個模式（「DP 的候選值隨著狀態推進而整段平移，用 lazy 線段樹維護 min」）在 DP 章會反覆出現。** 本節提供的是機制，**辨識的關鍵是「新元素只讓 $O(1)$ 段候選值發生常數變化」——先驗證這件事，再決定要不要上線段樹。**

## C++17 模板

**模板一：850 矩形面積 II（掃描線 + 標記永駐）**

```cpp
class Solution {
    vector<int> ys;         // 離散化後的 y 座標
    vector<int> cnt;        // 完整覆蓋本節點的活躍區間數
    vector<long long> cov;  // 本節點內被覆蓋的長度
    // 葉子 k 代表縫隙 [ys[lo], ys[lo+1])
    void pushUp(int k, int lo, int hi) {
        if (cnt[k] > 0)
            cov[k] = ys[hi + 1] - ys[lo];
        else if (lo == hi)
            cov[k] = 0;
        else
            cov[k] = cov[2 * k] + cov[2 * k + 1];
    }
    void update(int k, int lo, int hi, int l, int r, int d) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {
            cnt[k] += d;
            pushUp(k, lo, hi);
            return;
        }
        int mid = (lo + hi) >> 1;
        update(2 * k, lo, mid, l, r, d);
        update(2 * k + 1, mid + 1, hi, l, r, d);
        pushUp(k, lo, hi);  // 沒有 pushDown，只有 pushUp
    }

public:
    int rectangleArea(vector<vector<int>>& rectangles) {
        const long long MOD = 1'000'000'007LL;
        for (auto& r : rectangles) {
            ys.push_back(r[1]);
            ys.push_back(r[3]);
        }
        sort(ys.begin(), ys.end());
        ys.erase(unique(ys.begin(), ys.end()), ys.end());
        int m = ys.size() - 1;  // 縫隙數
        if (m <= 0) return 0;
        cnt.assign(4 * m, 0);
        cov.assign(4 * m, 0);

        // 事件：(x, y1, y2, +1/-1)
        vector<array<int, 4>> ev;
        ev.reserve(rectangles.size() * 2);
        for (auto& r : rectangles) {
            ev.push_back({r[0], r[1], r[3], 1});
            ev.push_back({r[2], r[1], r[3], -1});
        }
        sort(ev.begin(), ev.end(),
             [](const array<int, 4>& a, const array<int, 4>& b) {
                 return a[0] < b[0];
             });

        long long area = 0;
        int prevX = ev[0][0];
        for (auto& e : ev) {
            area = (area + cov[1] % MOD * ((e[0] - prevX) % MOD)) % MOD;
            prevX = e[0];
            int l = lower_bound(ys.begin(), ys.end(), e[1]) - ys.begin();
            int r =
                int(lower_bound(ys.begin(), ys.end(), e[2]) - ys.begin()) - 1;
            update(1, 0, m - 1, l, r, e[3]);
        }
        return int(area % MOD);
    }
};
```

**注意 `r` 要減 1**：$y$ 區間 $[y_1, y_2)$ 對應的是縫隙下標 $[\,l,\ r-1\,]$。**這個 off-by-one 是掃描線的頭號錯誤。**

**模板二：區間賦值 + 區間求和（LCP 52 的正序解法）**

```cpp
struct AssignSeg {
    int n;
    vector<long long> sum;
    vector<int> tag;  // -1 表示無標記，否則表示「整段賦值為 tag」
    explicit AssignSeg(int n) : n(n), sum(4 * n, 0), tag(4 * n, -1) {}
    void applyTag(int k, int len, int c) {
        sum[k] = 1LL * c * len;  // 定理 4：整段套用
        tag[k] = c;              // 後者吃掉前者
    }
    void pushDown(int k, int lo, int mid, int hi) {
        if (tag[k] == -1) return;
        applyTag(2 * k, mid - lo + 1, tag[k]);
        applyTag(2 * k + 1, hi - mid, tag[k]);
        tag[k] = -1;
    }
    void assign(int k, int lo, int hi, int l, int r, int c) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {
            applyTag(k, hi - lo + 1, c);
            return;
        }
        int mid = (lo + hi) >> 1;
        pushDown(k, lo, mid, hi);
        assign(2 * k, lo, mid, l, r, c);
        assign(2 * k + 1, mid + 1, hi, l, r, c);
        sum[k] = sum[2 * k] + sum[2 * k + 1];
    }
    long long total() const { return sum[1]; }
};
```

（**對照 8.5 定理 3**：LCP 52 也可以**倒序 + `set`** 二十行解決，複雜度更好。**線段樹是通用解，倒序是這題的巧解——兩個都該會，並知道各自的適用邊界：中途要查詢就只能用線段樹。**）

**模板三：1622 奇妙序列——只有標記，沒有樹**

1622 的三種操作（`addAll`、`multAll`）**都作用在整個序列上**。既然永遠是「整段」，樹就退化成一個節點：**只要維護一個全域仿射變換 $(m, b)$，把 `append(v)` 存成「原像」即可。**

```cpp
class Fancy {
    static constexpr long long MOD = 1'000'000'007LL;
    vector<long long> raw;   // 存的是「還原到初始變換下」的值
    long long m = 1, b = 0;  // 全域仿射：x -> m*x + b
    static long long qpow(long long a, long long e) {
        long long r = 1;
        for (a %= MOD; e; e >>= 1, a = a * a % MOD)
            if (e & 1) r = r * a % MOD;
        return r;
    }

public:
    void append(int val) {
        long long inv = qpow(m, MOD - 2);  // m 在模質數下的逆元
        raw.push_back((val - b % MOD + MOD) % MOD * inv % MOD);
    }
    void addAll(int inc) { b = (b + inc) % MOD; }
    void multAll(int mul) {
        m = m * mul % MOD;
        b = b * mul % MOD;
    }  // 定理 3
    int getIndex(int idx) {
        if (idx >= (int)raw.size()) return -1;
        return int((m * raw[idx] + b) % MOD);
    }
};
```

**`multAll` 的兩行就是定理 3 的合成公式**（把 $(m, b)$ 再套上 $(\mathit{mul}, 0)$，得 $(m\cdot \mathit{mul},\ b\cdot \mathit{mul})$）。**這題的價值在於它把懶標記的代數剝到只剩骨頭：標記合成、標記套用、逆元還原——沒有樹的干擾。搞懂它，`pushDown` 就不再神秘。**

## 時間與空間複雜度

| 操作 | 時間 | 說明 |
| --- | --- | --- |
| `build` | $O(n)$ | |
| 區間修改 | $O(\log n)$ **最壞** | 定理 2，不是攤還 |
| 區間查詢 | $O(\log n)$ | 含 `pushDown` |
| 空間 | $\mathbf{8n}$ | `t` 與 `lz` 各 $4n$ |

**常數比 9.3 的無 lazy 版明顯大**：每個內部節點多了一次 `pushDown`（讀寫兩個子節點）。實測約慢 1.5～2 倍。**不需要區間修改就不要寫 lazy 版**——多出來的每一行都是 bug 的機會。

**各題**：

| 題目 | 時間 | 備註 |
| --- | --- | --- |
| 850 矩形面積 II | $O(n\log n)$ | 排序 $2n$ 個事件 + $2n$ 次 $O(\log n)$ 修改 |
| LCP 52 二叉搜尋樹染色 | $O((n+q)\log n)$ | **倒序 + `set` 是 $O(n\log n)$，更好** |
| 2547 拆分陣列的最小代價 | $O(n\log n)$ | 每步兩次區間加 + 一次全域 min |
| 2502 設計記憶體分配器 | $O(q\log n)$ | $n, q \le 1000$，**暴力 $O(nq)$ 也能過** |
| 1622 奇妙序列 | $O(\log \mathit{MOD})$ / 次 | **不需要樹**，瓶頸是求逆元的快速冪 |

**掃描線的空間**：離散化後縫隙數 $m \le 2n$，線段樹 $4m = 8n$ 個節點。$n = 200$（850 的規模）完全不是問題，但推廣到 $n = 10^5$ 的天際線類問題時要留意。

**1622 的優化**：`append` 每次呼叫快速冪是 $O(\log \mathit{MOD}) \approx 30$ 次乘法。**可以改成「預先累積 $m$ 的前綴積並最後一次性求逆」或「維護 $m^{-1}$ 隨 `multAll` 同步更新」**，把 `append` 降到 $O(1)$。

## 常見錯誤與邊界條件

- **`query` 忘記 `pushDown`**。查詢走進內部節點就必須先結清欠帳。**第一大坑。** 副作用：`query` 不能是 `const`。
- **`pushDown` 後忘記清空標記**。帳結了兩次，值翻倍。
- **`applyTag` 忘記乘段長**。區間加求「和」時是 $x + v\cdot \mathit{len}$；求 max 時才是 $x + v$。**兩者的公式不同，抄錯模板必錯。**
- **標記合成順序寫反**。仿射標記下傳給子節點是 $(m'm,\ b'm + b)$——**先乘後加**（定理 3 推論）。
- **賦值標記沒有吃掉待加標記**（定理 4）。混用 assign 與 add 時，賦值必須清空待加量。
- **賦值標記用 `0` 表示「無標記」**。若題目允許賦值成 `0`，這就撞號了。**用 `-1` 或另開一個 `bool`。**
- **掃描線的區間端點沒減 1**。$[y_1, y_2)$ 對應縫隙下標 $[l, r-1]$。
- **掃描線寫了 `pushDown`**（定理 5）。**標記必須永駐**；下傳會讓成對的 $-1$ 無處可扣。
- **掃描線的 `pushUp` 三分支寫成兩分支**。`cnt[k] > 0` 時**不能**用 `cov[2k] + cov[2k+1]`。
- **葉子代表點而不是縫隙**。掃描線的線段樹必須以「相鄰座標之間的縫隙」為葉子，否則長度算不出來。
- **標記型別溢位**。區間加的標記累積後可能超出 `int`；求和更要 `long long`。
- **模運算的負數**。減法後要 `(x % MOD + MOD) % MOD`。
- **`build` 忘記初始化 `lz`**。`vector` 預設歸零可以救加法標記，但賦值標記的「無標記」是 `-1`，必須顯式 `assign`。
- **在 `pushDown` 之前呼叫 `pushUp`**。順序永遠是「`pushDown` → 遞迴 → `pushUp`」。
- **空區間**。$l > r$（例如掃描線裡 $y_1 = y_2$ 的退化矩形）要直接返回，否則 `update(1, 0, m-1, l, r)` 的邊界判斷可能出錯。

## 與相似技巧的比較

- **與 9.3 無 lazy 線段樹**：只有**單點**修改就不需要 lazy——修改只影響一條根路徑，沿路 `pushUp` 即可。**判準只有一句：修改是點還是段。** 是點就別寫 lazy（少一半程式、少一半 bug、快 1.5 倍）。
- **與 3. 差分**：「區間加、最後一次性查全部」用差分 $O(n + q)$，比什麼都快。**差分不支援中途查詢、不支援區間賦值。** 能用就用。
- **與 9.1 樹狀陣列 + 差分**：「區間加、單點查」一個樹狀陣列；「區間加、區間和」兩個樹狀陣列。**比 lazy 線段樹短得多、快 2～3 倍。** 但**只能做區間加**（可差分的修改），**做不了區間賦值**。**這是選擇的分界線。**
- **與 8.5 區間並查集**：「每格只需被處理一次」時 $O((n+q)\alpha)$，遠快於 lazy。**先檢查 8.5 的前提是否成立**（一次性標記、無撤銷、無累加）；成立就別上線段樹。LCP 52 就是這樣。
- **與珂朵莉樹（ODT）**：`map` 維護「值相同的極長區間」，區間賦值 $O(\log n)$ 攤還（隨機資料下），**程式短得多，而且能直接遍歷區間**。缺點是複雜度依賴資料隨機性，**被針對性構造的資料可以卡到 $O(n)$**。LeetCode 上通常安全，競賽中要小心。
- **與 Segment Tree Beats**：處理「區間取 min／max 並查詢和」這類**標記不滿足分配律**的操作。**它是本節三個要求被打破後的補救方案**，複雜度 $O(n\log^2 n)$，實作複雜度高一個檔次。LeetCode 上極少需要。
- **與分塊（第 11 章）**：$O(\sqrt n)$，更慢但**不要求分配律、不要求標記可合成**。**當你發現「標記無法 $O(1)$ 套用到整段」時，分塊往往是唯一出路。**
- **與掃描線 + 「標記永駐」（定理 5）**：**當修改成對可撤銷且只查根時，這個寫法比一般 lazy 更簡單也更安全。** 矩形面積並／周長並／天際線都用它。**不要看到區間修改就反射性地寫 `pushDown`。**

## 本節重點速查

- **一句話約定**：**`t[k]` 已含 `lz[k]`，子樹尚未含**。所有 lazy 的 bug 都是違反這句話。
- **三個代數要求**：(1) 能用「段長 + 標記」$O(1)$ 整段套用；(2) 標記能合成；(3) **分配律** $\mathrm{apply}(a \oplus b, f) = \mathrm{apply}(a,f)\oplus \mathrm{apply}(b,f)$。**第三條是「父節點打一個標記 $\equiv$ 兩個子節點各打一次」的保證，缺了它整套機制不成立。**
- **順序永遠是「`pushDown` → 遞迴 → `pushUp`」**，而且 **`query` 也要 `pushDown`**（所以不能 `const`）。
- **`applyTag` 求和要乘段長，求 max 不乘**。抄錯模板必錯。
- **仿射標記約定 $x \mapsto mx + b$**，合成 $(m_1m_2,\ b_1m_2+b_2)$（定理 3）。**先乘後加**，寫反是頭號 WA。定義成 $m(x+b)$ 會需要除法。
- **賦值標記吃掉一切**（定理 4）：$C_c \circ g = C_c$。混用 assign+add 時賦值必須清空待加量。**「無標記」不要用 `0` 表示。**
- **掃描線用「標記永駐 + 三分支 `pushUp`」，不要 `pushDown`（定理 5）**：`cnt[k] > 0` ⇒ 整段長；葉子且 `cnt == 0` ⇒ 0；否則兩子相加。**葉子代表縫隙不是點；$[y_1,y_2)$ 對應縫隙下標 $[l, r-1]$。**
- **2547 的模式**：新元素只讓 $O(1)$ 段候選值發生常數變化（$+1$／$+2$／$+0$，由 $a_i$ 的最後兩次出現位置切分）⇒ 區間加 + 全域 min。**上線段樹之前先驗證這個「$O(1)$ 段」的性質。**
- **1622 沒有樹**：全域仿射 + 存原像 + 模逆元。**它是懶標記代數的極簡形式，搞懂它 `pushDown` 就不神秘。**
- **空間 $8n$**（`t` 與 `lz` 各 $4n$），常數比無 lazy 版慢 1.5～2 倍。
- **選擇順序**：差分（離線、只查一次）→ 樹狀陣列 + 差分（只有區間**加**）→ 8.5 區間並查集（每格只處理一次）→ ODT（區間賦值、資料不刁鑽）→ **lazy 線段樹（通用）** → Segment Tree Beats / 分塊（分配律被打破）。
