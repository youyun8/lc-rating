## 這個技術解決什麼問題

9.3、9.4 的線段樹都假設「值域就是陣列下標 $[0, n-1]$」。但日程表系列（729／731／732）的時間座標到 $10^9$，掉落方塊（699）的位置也一樣——**開一個 $4\times10^9$ 的陣列是不可能的。**

關鍵觀察是：**值域很大，但真正被碰到的點很稀疏。** $q$ 次操作最多只涉及 $2q$ 個端點，而線段樹只需要「真的被走過」的那些節點。

於是有三條路：

| 做法 | 前提 | 代價 |
| --- | --- | --- |
| **離散化 + 靜態線段樹** | **離線**（所有操作事先已知） | 最省，$O(q)$ 節點 |
| **動態開點線段樹** | 無 | $O(q\log V)$ 節點，**支援線上** |
| `map` / `set` 維護不交區間 | 操作是「整段賦值」 | 程式最短，複雜度依情形 |

**動態開點的想法只有一句：**

> **保持完整值域 $[0, V)$ 的邏輯樹形，但節點按需分配——沒有被建立的節點，代表一整段「什麼都沒發生」。**

於是 `lc`／`rc` 從「$2k$／$2k+1$」變成兩個存下來的下標，`0` 表示「還不存在」。

**為什麼必須是「線上」才值得用它**：日程表系列每次 `book` 都要**立刻**回答能不能訂，你**沒辦法**先收齊所有預訂再離散化。**離線可離散化時，靜態線段樹又快又省，不要為了用工具而用工具。**

**辨識訊號**：
- 座標／時間值域到 $10^9$，但操作次數只有 $10^4 \sim 10^5$；
- **邊加邊問**，無法預先收集所有端點（729／731／732）；
- 大值域上的區間取 max 與查詢（699）；
- 值域巨大的計數桶（2276 統計區間中的整數數目、2770）。

## 狀態／資料結構定義

**節點池寫法**（比指標版好——沒有 `new`／`delete`，快取友善，容易 `reserve`）：

```cpp
struct DynSeg {
    struct Node {
        int lc = 0, rc = 0;
        int mx = 0;
        int add = 0;
    };
    vector<Node> t;
    int V;  // 值域為 [0, V)
    explicit DynSeg(int V) : V(V) {
        t.reserve(1 << 20);  // 先 reserve，避免反覆搬移
        t.emplace_back();    // t[0] 是「不存在」的哨兵，永遠不用
        t.emplace_back();    // t[1] 是根
    }
    int newNode() {
        t.emplace_back();
        return int(t.size()) - 1;
    }
};
```

**核心不變量（見定理 1）：`lc == 0` 表示「左子樹整段都還是初始狀態」。** 所有讀取子節點的地方都必須容忍 `0`，並把它當成單位元。

**`mid` 必須寫成 `lo + (hi - lo) / 2`。** 值域到 $10^9$ 時 `lo + hi` 會溢位 `int`——**這是動態開點獨有的坑，靜態版因為 $n$ 小從來不會遇到。**

**兩種標記策略：**

| | 需要建點嗎 | 適用 |
| --- | --- | --- |
| **一般 lazy**（`pushDown`） | **要**：下傳前必須先把子節點建出來 | 所有情形，含區間賦值 |
| **標記永久化**（標記永駐，查詢時沿路累加） | **不要** | 標記**可交換**且與查詢順序無關（區間加 ✔、區間賦值 ✘） |

**標記永久化省下大量節點，是動態開點的標準搭配**，但它有嚴格的適用條件（定理 3）。**區間賦值不能永久化**，因為「後蓋前」的順序資訊會遺失。

## 不變量或正確性證明

以下記值域為 $[0, V)$，$L = \lceil\log_2 V\rceil$。

### 定理 1（空節點不變量）

**不變量 (D)**：若某節點的 `lc == 0`（或 `rc == 0`），則對應的整個子區間**從未被任何修改觸及**，其聚合值為單位元。

*維護*：節點只在「修改遞迴真的要走進去」時才被建立；查詢遇到 `0` 直接回傳單位元，不建立節點 ✔。

**推論 1.1（查詢不應建點）**：`query` 若不小心呼叫了 `newNode`，節點數會從 $O(q_{\text{改}}\log V)$ 膨脹到 $O(q_{\text{總}}\log V)$。**在只讀多寫少的場景下這是數倍的記憶體差距。** 寫 `query` 時檢查一遍：有沒有任何一條路徑會建點。

### 定理 2（節點數上界 $O(q\log V)$）

*命題*：$q$ 次區間修改後，節點總數不超過 $4q\lceil\log_2 V\rceil + O(1)$。

*證明*。單次修改的遞迴形狀與 9.3 完全相同，由 9.3 定理 2，**訪問的節點數 $\le 4L$**。新建的節點必定在訪問集合之內（沒被訪問就不會被建立），故單次至多新建 $4L$ 個 ✔。$\square$

**這個界很鬆但夠用。實際上更精確的界是 $2L$ 左右**（每層至多 2 個部分相交節點，每個至多新建 2 個子節點，但其中至多 1 個會繼續遞迴）。

**記憶體是真正的風險，必須算清楚**：$V = 10^9$ ⇒ $L = 30$；$q = 10^5$ ⇒ 節點數可達 $6\times10^6$。若每個節點是 `{int lc, rc; long long sum, add;}` = 24 位元組，就是 **144 MB——直接 MLE**。

**三個省記憶體的手段**（按效果排序）：
1. **能離線就離散化**，節點數降到 $O(q)$；
2. **標記永久化**（省掉為了 `pushDown` 而建的節點）；
3. **縮小節點型別**（`int` 而非 `long long`，能省一半）。

### 定理 3（標記永久化的正確性與適用條件）

*設定*：「區間加、區間求和」。不 `pushDown`，而是在每個典範節點上把 `add[k] += v` 記著，**永不下傳**；同時仍然更新沿途所有祖先的 `sum`。

*查詢* $[l, r]$ 的實作：遞迴下降，每經過一個節點 $k$ 就累加 $\mathit{add}[k] \times \big|[l,r] \cap \mathrm{seg}(k)\big|$，走到典範節點時再加上 $\mathit{sum}[k]$。

**不變量 (P)**：$\mathit{sum}[k]$ 等於 $\mathrm{seg}(k)$ 的真實總和**扣掉所有嚴格祖先的 `add` 貢獻**；$\mathit{add}[k]$ 記錄「整段 $\mathrm{seg}(k)$ 被加了多少」。

*正確性*。任一次區間加操作 $(\,[l', r'], v\,)$ 對查詢答案的貢獻是 $v \times |[l,r]\cap[l',r']|$。該操作把 $v$ 記在若干典範節點上，而這些節點的區間不交、聯集為 $[l', r']$（9.3 定理 2）。查詢時：
- 若典範節點 $k'$ **在查詢的下降路徑上**（是查詢典範節點的祖先或本身），$v$ 由「沿途累加 $\mathit{add}[k'] \times |\text{交集}|$」計入 ✔；
- 若 $k'$ **在查詢的某個典範節點之下**，$v$ 已被計入 $\mathit{sum}$（修改時更新了所有祖先的 `sum`）✔；
- 若 $k'$ 與查詢區間**不交**，交集為空，貢獻 $0$ ✔。

三種情形窮盡且不重疊 ⇒ 恰好計入一次 ✔。$\square$

**適用條件（必須點名）**：
1. **標記可交換**：查詢時是「把沿路所有 `add` 加起來」，**順序無關**。區間加滿足；**區間賦值不滿足**——「先賦值 5 再賦值 3」與「先 3 再 5」結果不同，而永久化丟失了順序資訊。
2. **能用「交集長度」$O(1)$ 算貢獻**：區間加求和 ✔（乘交集長度）、區間加求 max ✔（直接加）。

**要做區間賦值就老實用 `pushDown`，並在下傳前把子節點建出來。**

### 定理 4（日程表系列：$k$ 重預訂 $\iff$ 覆蓋計數的 max $\ge k$）

*命題*：一組半開區間 $\{[s_i, e_i)\}$ 存在 $k$ 個兩兩有共同內點的區間，**當且僅當**覆蓋計數函數 $c(x) = \#\{i : x \in [s_i, e_i)\}$ 的最大值 $\ge k$。

*證明*。
- **($\Leftarrow$)** 若某點 $x_0$ 滿足 $c(x_0) \ge k$，則覆蓋 $x_0$ 的那 $k$ 個區間都含 $x_0$，兩兩相交 ✔。
- **($\Rightarrow$)** 設 $I_1, \dots, I_k$ 兩兩相交。**區間具有 Helly 性質**（一維：兩兩相交的區間族必有公共點）：取 $s^* = \max_j s_j$、$e^* = \min_j e_j$，兩兩相交蘊含 $s^* < e^*$，故 $s^*$ 被全部 $k$ 個區間覆蓋，$c(s^*) \ge k$ ✔。$\square$

**於是三題化成同一個資料結構操作**：

| 題目 | 操作 |
| --- | --- |
| 729 我的日程安排表 I | 訂前查 $\max_{[s,e)} c$，$\ge 1$ 就拒絕 |
| 731 我的日程安排表 II | 訂前查 $\max_{[s,e)} c$，$\ge 2$ 就拒絕 |
| 732 我的日程安排表 III | 訂後回傳**全域** $\max c$（即根節點的 `mx`） |

**都是「區間加 1 + 區間查 max」，一份程式碼三題通吃。** 而「區間加 + 區間 max」的標記恰好滿足定理 3 的兩個條件，**可以標記永久化，不必 `pushDown`。**

**($\Rightarrow$) 用到的 Helly 性質不是廢話**：如果區間換成二維矩形，「兩兩相交」**不**蘊含「有公共點」（三個互相重疊的矩形可以沒有共同區域），這個化簡就失效了。**點名前提，才知道推廣的邊界在哪裡。**

### 定理 5（715 Range 模組：`map` 維護不交區間的攤還分析）

715 也可以用線段樹（區間賦值 0/1 + 查「整段是否全 1」），但**用 `map` 維護「不交且互不相鄰的極長 1 段」程式短得多**。值得證的是它的複雜度。

*結構*：`map<int,int> m`，鍵為區間左端、值為右端，保證區間**兩兩不交且互不相鄰**（相鄰的會被合併）。

*`addRange(l, r)`*：找出所有與 $[l, r)$ 相交或相鄰的區間，**全部刪除**，插入它們與 $[l,r)$ 的聯集（必為單一區間）。

**命題**：$q$ 次操作的總時間為 $O(q\log q)$。

*證明（攤還）*。令勢能 $\Phi = $ 目前 `map` 中的區間數。
- 一次 `addRange` 刪除 $d$ 個區間、插入 1 個 ⇒ $\Delta\Phi = 1 - d$，實際成本 $O((d+1)\log q)$。攤還成本 $O((d+1)\log q) + (1-d)\cdot c\log q = O(\log q)$（取 $c$ 足夠大）✔。
- 一次 `removeRange` 至多**新增 2 個**區間（左右各切出一截）⇒ $\Delta\Phi \le 2$，攤還 $O(\log q)$ ✔。
- $\Phi \ge 0$ 且初始為 $0$ ⇒ 總攤還成本即為總實際成本的上界 ✔。$\square$

**「刪除的數量由勢能付帳」是勢能法最典型的用法**，與 4.7 單調堆疊、6.6 懶刪除堆同構。**本章第七次出現這個模式了。**

### 定理 6（699 掉落方塊：為什麼是「賦值」而不是「取 max」）

*問題*：方塊依序落在 $[l, l + \mathit{sz})$ 上，落到「該區間現有最大高度」之上，回傳每次落下後的**全域**最大高度。

**命題**：設落下前 $h^* = \max_{x\in[l,\,l+\mathit{sz})} h(x)$，則落下後該區間的高度**處處等於** $h^* + \mathit{sz}$，即這是一次**區間賦值**而非「區間取 max」。

*證明*。方塊是剛體且底面是平的，落到 $h^*$ 就停住（再低會穿透最高的那一點），其上表面高度處處為 $h^* + \mathit{sz}$。而對區間內任一點 $x$，原高度 $h(x) \le h^* < h^* + \mathit{sz}$，故新高度 $= h^* + \mathit{sz}$ **嚴格大於**原值，賦值不會覆蓋掉更高的東西 ✔。$\square$

**「賦值合法」依賴 $\mathit{sz} > 0$**（方塊有厚度）。若允許厚度 0，就必須改成 `chmax`，而 `chmax` 的標記不滿足定理 3 的條件，也不滿足 9.4 的分配律——**得用 Segment Tree Beats。一個小前提，決定了兩個檔次的實作難度。**

**邊界**：題目規定「只在邊緣接觸不算重疊」，所以區間要用**半開** $[l, l+\mathit{sz})$；若用閉區間 $[l, l+\mathit{sz}]$，相鄰的兩個方塊會被誤判成重疊。**699 的規模只有 $n \le 1000$，$O(n^2)$ 暴力完全能過——但它是理解「大值域區間賦值」的好練習。**

## C++17 模板

**模板一：動態開點 + 標記永久化（區間加 1、區間查 max）——729／731／732 通用**

```cpp
class MyCalendarThree {
    struct Node {
        int lc = 0, rc = 0, mx = 0, add = 0;
    };
    vector<Node> t;
    static constexpr int V = 1'000'000'001;  // 值域 [0, V)
    int newNode() {
        t.emplace_back();
        return int(t.size()) - 1;
    }

    // 區間 [l, r) 加 v；標記永久化，不 pushDown
    void update(int k, int lo, int hi, int l, int r, int v) {
        if (r <= lo || hi <= l) return;
        if (l <= lo && hi <= r) {
            t[k].add += v;
            t[k].mx += v;
            return;
        }
        int mid = lo + (hi - lo) / 2;  // 不可寫 (lo + hi) / 2
        if (l < mid) {
            if (!t[k].lc) t[k].lc = newNode();
            update(t[k].lc, lo, mid, l, r, v);
        }
        if (mid < r) {
            if (!t[k].rc) t[k].rc = newNode();
            update(t[k].rc, mid, hi, l, r, v);
        }
        int L = t[k].lc ? t[t[k].lc].mx : 0;
        int R = t[k].rc ? t[t[k].rc].mx : 0;
        t[k].mx = t[k].add + max(L, R);  // 自己的永久標記要加回來
    }
    int query(int k, int lo, int hi, int l, int r) const {
        if (k == 0 || r <= lo || hi <= l) return 0;  // 空節點回傳單位元
        if (l <= lo && hi <= r) return t[k].mx;
        int mid = lo + (hi - lo) / 2;
        int res =
            max(query(t[k].lc, lo, mid, l, r), query(t[k].rc, mid, hi, l, r));
        return res + t[k].add;  // 沿路累加永久標記
    }

public:
    MyCalendarThree() {
        t.reserve(1 << 18);
        t.emplace_back();
        t.emplace_back();
    }
    int book(int startTime, int endTime) {
        update(1, 0, V, startTime, endTime, 1);
        return t[1].mx;  // 732：全域最大覆蓋數
    }
};
```

**`t[k].mx = t[k].add + max(L, R)` 與 `return res + t[k].add` 這兩處，就是永久化的全部。** 前者維護 (P)，後者在查詢時把祖先的帳補回來。

**729／731 只要改 `book`：**

```cpp
bool book(int s, int e) {  // 729：k = 1；731：改成 >= 2
    if (query(1, 0, V, s, e) >= 1) return false;
    update(1, 0, V, s, e, 1);
    return true;
}
```

**模板二：一般 lazy 版（支援區間賦值，`pushDown` 前必須建點）**

```cpp
void pushDown(int k, int lo, int mid, int hi) {
    if (t[k].tag == NONE) return;
    if (!t[k].lc) t[k].lc = newNode();  // 沒有子節點就先建
    if (!t[k].rc) t[k].rc = newNode();
    applyTag(t[k].lc, mid - lo, t[k].tag);
    applyTag(t[k].rc, hi - mid, t[k].tag);
    t[k].tag = NONE;
}
```

**「下傳前先建點」是動態開點 lazy 版與靜態版唯一的差別，但漏掉就是空指標般的邏輯錯誤（標記寫進 `t[0]` 這個哨兵，被後續操作讀到）。**

**模板三：715 Range 模組（`map` 維護不交區間，最短解）**

```cpp
class RangeModule {
    map<int, int> m;  // left -> right，半開 [left, right)
public:
    void addRange(int left, int right) {
        auto it = m.upper_bound(left);  // 第一個 left' > left
        if (it != m.begin() && prev(it)->second >= left)
            --it;  // 可能與前一段相鄰／相交
        while (it != m.end() && it->first <= right) {
            left = min(left, it->first);
            right = max(right, it->second);
            it = m.erase(it);
        }
        m[left] = right;
    }
    bool queryRange(int left, int right) {
        auto it = m.upper_bound(left);
        if (it == m.begin()) return false;
        --it;
        return it->second >= right;  // 單一段就能蓋住才算 true
    }
    void removeRange(int left, int right) {
        auto it = m.upper_bound(left);
        if (it != m.begin() && prev(it)->second > left) --it;
        while (it != m.end() && it->first < right) {
            int l = it->first, r = it->second;
            it = m.erase(it);
            if (l < left) m[l] = left;  // 左邊切一截回去
            if (r > right) {
                m[right] = r;
                break;
            }  // 右邊切一截，之後必無交集
        }
    }
};
```

**`queryRange` 只檢查「單一段能否蓋住」是對的**——因為不變量保證區間互不相鄰，兩段之間必有空隙。**這個不變量是 `addRange` 用 `it->first <= right`（而不是 `<`）合併相鄰段換來的。**

## 時間與空間複雜度

令 $V$ 為值域大小、$L = \lceil\log_2 V\rceil$、$q$ 為操作數。

| | 時間 | 節點數 |
| --- | --- | --- |
| 動態開點（永久化） | $O(q\log V)$ | $O(q\log V)$，實測約 $2L$／次 |
| 動態開點（一般 lazy） | $O(q\log V)$ | $O(q\log V)$，**常數更大**（`pushDown` 會建點） |
| 離散化 + 靜態線段樹 | $O(q\log q)$ | $O(q)$ |
| `map` 維護不交區間 | $O(q\log q)$ **攤還**（定理 5） | $O(q)$ |

**$V = 10^9$ 時 $L = 30$，$\log q$（$q = 10^5$）只有 17——離散化不只省記憶體，還快將近一倍。** 能離線就離線。

**記憶體試算（必做）**：

| 節點欄位 | 每節點 | $q = 10^5$、$L = 30$、係數 2 | 結論 |
| --- | --- | --- | --- |
| `int lc, rc, mx, add` | 16 B | $6\times10^6 \times 16$ = **96 MB** | **危險** |
| `int lc, rc, mx` | 12 B | 72 MB | 危險 |
| 離散化後 $4q$ 個節點 | 16 B | 6.4 MB | 安全 |

**LeetCode 的記憶體上限通常是 256 MB，但 `vector` 擴容時會同時持有新舊兩份**——`reserve` 到位可以避開這個峰值。**動態開點的第一大死因是 MLE，不是 TLE。**

**各題**：

| 題目 | 值域 | 操作數 | 建議 |
| --- | --- | --- | --- |
| 729／731 日程表 I／II | $10^9$ | $\le 1000$ | **`set` 維護不交區間或暴力都行**，動態開點是殺雞用牛刀 |
| 732 日程表 III | $10^9$ | $\le 400$ | 同上，但動態開點最直觀 |
| 715 Range 模組 | $10^9$ | $\le 10^4$ | **`map` 版最短** |
| 699 掉落方塊 | $10^8$ | $\le 1000$ | $O(n^2)$ 暴力即可 |
| 2276 統計區間中的整數數目 | $10^9$ | $\le 10^5$ | **`map` 維護不交區間**（動態開點也行） |

**誠實的結論：本節列出的 LeetCode 題目規模都不大，`map` / `set` 維護不交區間往往是更短更快的解。** 動態開點的真正價值在於**它是通用的**——當操作不只是「整段賦值」（例如區間加、區間求和、區間 max 混用）時，`map` 就無能為力了。

## 常見錯誤與邊界條件

- **`mid = (lo + hi) / 2` 溢位**。值域到 $10^9$ 時 `lo + hi` 超出 `int`。**必須寫 `lo + (hi - lo) / 2`。這是動態開點獨有的坑。**
- **查詢時建點**（推論 1.1）。`query` 遇到 `0` 應直接回傳單位元，**絕不呼叫 `newNode`**。
- **忘記 `reserve`**。`vector` 反覆擴容既慢又會製造記憶體峰值。**先估好節點數再 `reserve`。**
- **`pushDown` 前沒建子節點**。標記被寫進哨兵 `t[0]`，之後所有讀到 `t[0]` 的地方都被污染。
- **對區間賦值使用標記永久化**（定理 3）。賦值不可交換，永久化會丟失順序。**只有可交換的標記（加法）能永久化。**
- **永久化版忘記在查詢時累加沿路 `add`**，或忘記在 `pushUp` 時加回自己的 `add`。**兩處缺一都錯。**
- **半開／閉區間混用**。日程表是 $[s, e)$、掉落方塊是 $[l, l+\mathit{sz})$。**「邊緣接觸不算重疊」就必須用半開區間。**
- **根區間寫成 $[0, V]$ 而不是 $[0, V)$**。與 `update` 的邊界判斷 `r <= lo || hi <= l` 要一致。
- **值域下界不是 0**。若座標可為負，要平移或把根區間設成 $[-V, V)$（此時 `mid` 的溢位風險更大）。
- **`long long` vs `int`**。求和類要 `long long`，但那會讓記憶體翻倍——**先確認真的會溢位再改。**
- **715 的 `queryRange` 檢查了多段拼接**。不變量保證區間互不相鄰，**必須是單一段蓋住**才回 `true`；寫成「累加多段長度」是錯的。
- **715 的 `addRange` 用 `<` 而不是 `<=` 判斷合併**。相鄰（`it->first == right`）的段也要合併，否則不變量破壞，`queryRange` 就會誤判。
- **699 用閉區間**。相鄰方塊會被誤判成重疊。

## 與相似技巧的比較

- **與離散化 + 靜態線段樹（9.3／9.4）**：**只要能離線，離散化永遠更好**——節點 $O(q)$ 而非 $O(q\log V)$，$\log q$ 而非 $\log V$，程式也更短。**動態開點的唯一理由是「線上」。** 拿到題目先問：所有操作是不是事先都知道？
- **與 `map` / `set` 維護不交區間（ODT 風格）**：當操作是「整段賦值／整段標記」時，`map` 版程式短一半、常數小、記憶體 $O(q)$，而且攤還複雜度有證明（定理 5）。**715、2276、729 都建議先寫 `map` 版。** 但它做不了「區間加 + 區間求和」這類需要聚合的操作。
- **與 9.6 可持久化線段樹**：可持久化也是「按需建節點」，但目的不同——**動態開點是為了省空間，可持久化是為了保留歷史版本。** 兩者常常同時使用（主席樹 = 動態開點 + 版本共享）。
- **與 9.1 樹狀陣列**：樹狀陣列**必須有連續的小下標**，值域大就只能離散化。**沒有「動態開點樹狀陣列」這種東西**（有 `map` 版但常數極差）。
- **與平衡樹（`pb_ds` / 手寫 Treap）**：平衡樹的節點數是 $O(q)$（只存真正存在的元素），比動態開點省。**但它不支援「區間加、區間 max」這類需要區間分解的操作**，除非寫成 Treap 按位置分裂——那已經是另一個檔次的實作。
- **與掃描線（9.4 定理 5）**：離線的區間覆蓋問題（矩形面積並）用掃描線 + 靜態線段樹，比動態開點好。**再一次：能離線就離線。**
- **與暴力**：729／699 的 $n \le 1000$，$O(n^2)$ 只有 $10^6$ 次操作。**面試中先寫暴力並說明可以升級成動態開點，往往比直接寫 200 行更好。**

## 本節重點速查

- **存在理由**：值域 $10^9$ 但操作只有 $10^5$，且**必須線上**。**能離線就離散化——那更快更省。**
- **核心不變量 (D)**：`lc == 0` 表示「整段從未被觸及」，讀到就回傳單位元。**`query` 絕不建點**，否則節點數從 $O(q_{\text{改}}\log V)$ 膨脹到 $O(q_{\text{總}}\log V)$。
- **`mid = lo + (hi - lo) / 2`**。`(lo + hi) / 2` 在 $10^9$ 值域下溢位——**動態開點獨有的坑**。
- **節點數 $O(q\log V)$（定理 2）**，$V=10^9$、$q=10^5$ ⇒ 可達 $6\times10^6$ 個 ⇒ **96 MB，第一大死因是 MLE 不是 TLE**。務必 `reserve` 並算一次記憶體。
- **標記永久化（定理 3）**：不 `pushDown`，修改時在典範節點記 `add`、查詢時沿路累加。**條件：標記可交換（區間加 ✔、區間賦值 ✘）且能用交集長度 $O(1)$ 算貢獻。** 省下大量節點。
- **一般 lazy 版的唯一差別是「`pushDown` 前先建子節點」**，漏掉就把標記寫進哨兵。
- **日程表三題同一份程式（定理 4）**：$k$ 重預訂 $\iff$ 覆蓋計數 max $\ge k$，靠一維區間的 **Helly 性質**（推廣到矩形就失效）。729 查 $\ge1$、731 查 $\ge2$、732 回傳根的 `mx`。
- **699 是「區間賦值」不是「區間取 max」（定理 6）**：方塊有厚度 ⇒ 新高度嚴格大於區間內任何舊值。**厚度可為 0 就得用 Segment Tree Beats。** 用半開區間，否則相鄰方塊誤判重疊。
- **715 用 `map` 維護不交且不相鄰的區間**，攤還 $O(q\log q)$（勢能法，定理 5——本章第七次出現這個攤還模式）。**`queryRange` 必須單一段蓋住**；`addRange` 要用 `<=` 把相鄰段也合併。
- **選擇順序**：暴力（$n\le1000$）→ 離散化 + 靜態線段樹（離線）→ `map` 維護不交區間（只有整段賦值）→ **動態開點 + 永久化（線上、可交換標記）** → 動態開點 + lazy（線上、要區間賦值）。
