## 這個技術解決什麼問題

到目前為止的線段樹都只有**一個「現在」**：修改之後，舊的狀態就沒了。但有些問題要問**歷史**：

- 「陣列在第 $t$ 次操作之後長什麼樣？」
- 「子陣列 $[l, r]$ 的第 $k$ 小是多少？」

第二個問題乍看與歷史無關，但它其實是同一件事。**關鍵的轉換是**：

> 令版本 $i$ 表示「只放入前 $i$ 個元素的值域計數線段樹」。那麼**版本 $r$ 減版本 $l-1$**，就是「只含 $a_l \dots a_r$」的值域計數線段樹。

在這棵「差」上做值域二分，就能 $O(\log n)$ 求出區間第 $k$ 小。這就是**主席樹**（可持久化權值線段樹）最經典的用法。

**但天真的做法是不可行的**：存 $n$ 個完整版本要 $O(n^2)$ 空間。**可持久化的全部想法只有一句：**

> **相鄰兩個版本只差一次單點修改，而單點修改只改動根到葉的一條路徑（$O(\log n)$ 個節點）。把這條路徑複製一份，其餘節點兩個版本共用。**

於是每個版本只多花 $O(\log n)$ 空間，總共 $O(n\log n)$。

**辨識訊號**：
- 需要查詢「歷史版本」或保留每一步的狀態；
- **任意**子陣列 $[l, r]$ 的第 $k$ 小／值域計數（**任意**是重點——若只問全域第 $k$ 小，排序就夠了）；
- 多次查詢彼此獨立、針對不同時間切片的資料（3762）。

**先問一個問題：能離線嗎？** 若所有查詢事先已知，**整體二分**或「按值排序後用樹狀陣列掃描」通常更短、常數更小、空間 $O(n)$。**主席樹的不可替代之處在於線上查詢，以及真的要保留歷史版本。**

## 狀態／資料結構定義

```cpp
struct PersistentSeg {
    struct Node {
        int lc = 0, rc = 0, cnt = 0;
    };
    vector<Node> t;
    vector<int> root;  // root[i] = 第 i 個版本的根
    int m;             // 離散化後的值域大小 [0, m)

    explicit PersistentSeg(int m, int n) : m(m) {
        t.reserve(size_t(n) * (__lg(max(m, 1)) + 2) + 2);  // 節點池要一次開夠
        t.emplace_back();   // t[0]：空節點，代表「整段計數為 0」
        root.push_back(0);  // 版本 0 = 空樹
    }
};
```

三件事值得注意：

1. **`t[0]` 同時扮演「空節點」與「空樹」。** 這與 9.5 的空節點不變量是同一個約定：讀到 `0` 就當成單位元（計數 0）。**版本 0 的根直接就是 `0`，不需要建一棵全零的樹。**
2. **`root` 是版本表。** 版本之間**不是**父子關係，只是共享子樹的一堆 DAG 根。
3. **節點池必須一次 `reserve` 足夠**。$n$ 次插入、每次 $\lceil\log_2 m\rceil + 1$ 個新節點，寫成 `n * (log2(m) + 2)` 留餘裕。**這是可持久化最常見的 RE／MLE 來源。**

**最重要的約定（定理 1 會證明它為什麼必要）：**

> **節點一旦建立，內容永不改變（immutable）。** 任何「就地修改」都會同時污染所有共用該節點的舊版本。

**這條約定直接封殺了 `pushDown`。** 詳見定理 5。

## 不變量或正確性證明

以下記離散化後值域為 $[0, m)$，$L = \lceil\log_2 m\rceil$。

### 定理 1（可持久化不變量：版本互不干擾）

**不變量 (V)**：對每個版本 $i$，從 `root[i]` 出發的整棵樹，**語義上等同於**「把前 $i$ 個元素依序插入一棵獨立的值域計數線段樹」的結果。

*證明（對 $i$ 歸納）*。

**基底** $i = 0$：`root[0] = 0`，所有計數為 0 ✔。

**歸納步**：設 (V) 對版本 $i-1$ 成立。插入 $a_i$ 時，我們沿著「$a_i$ 所在葉子」的根到葉路徑 $P$ 走，**為 $P$ 上每個節點建立一份新副本**，副本的兩個子指標中，**路徑方向的那個指向新建的副本，另一個原封不動指向舊版本的節點**。

- 對 $P$ 上的節點：新副本的 `cnt` = 舊值 + 1 ✔（$a_i$ 落在它的值域區間內）。
- 對不在 $P$ 上、但被新版本可達的節點 $u$：$u$ 是某個 $P$ 上節點的「非路徑方向」子樹的根。$u$ 從未被寫入，其子樹在新舊版本中**是同一份記憶體**，而 $a_i$ 不落在 $\mathrm{seg}(u)$ 內，所以「舊版本的正確值」也正是「新版本應有的值」✔。
- 舊版本 `root[i-1]` 可達的節點**一個都沒被寫**（我們只寫了剛 `emplace_back` 出來的新節點）⇒ 版本 $i-1$ 的 (V) 仍然成立 ✔。$\square$

**這個證明依賴兩個前提，必須點名**：

1. **修改只影響一條根到葉的路徑。** 這對**單點修改**成立。區間修改會觸及 $O(\log m)$ 個典範節點及其祖先——仍是 $O(\log m)$ 個節點，複製它們也行；**但 `pushDown` 不行**（定理 5）。
2. **新版本只寫新節點。** 只要有一行寫進了舊節點，所有共享它的版本一起壞掉，而且**症狀是「某個舊版本的查詢答案莫名其妙變了」，極難除錯。**

**推論 1.1**：任兩個版本可以自由地同時查詢、互相比較，因為它們是各自完整的樹。**定理 3 就建立在這一點上。**

### 定理 2（空間與時間：$O(n\log m)$）

*命題*：$n$ 次單點插入後，節點總數 $\le n(L+1) + 1$。

*證明*。根到葉的路徑長為 $L+1$（含根與葉），每次插入恰好複製這條路徑上的每個節點各一次 ✔。$\square$

**試算**：$n = 10^5$、$m = 10^5$ ⇒ $L = 17$ ⇒ 節點數 $\approx 1.8\times10^6$。每節點 `{int lc, rc, cnt}` = 12 B ⇒ **約 22 MB，安全。**

**與 9.5 對照**：9.5 是「一個版本、大值域、按需建點」，這裡是「多個版本、小值域（先離散化）、按需複製」。**兩者都是 $O(q\log V)$ 個節點，但目的完全不同**——9.5 為了省空間，本節為了保留歷史。（**兩者可以疊加**：若值域大又要持久化，就不離散化、直接在 $[0, 10^9)$ 上可持久化，節點數變成 $O(n\log V)$。）

### 定理 3（主席樹的可減性）

*命題*：設 $\mathrm{cnt}_i(u)$ 為版本 $i$ 中節點 $u$ 所在值域區間的元素個數。則對任意值域區間 $S$，

$$\#\{\,j \in [l, r] : a_j \in S\,\} \;=\; \mathrm{cnt}_r(S) - \mathrm{cnt}_{l-1}(S).$$

*證明*。版本 $i$ 恰好裝入 $a_1, \dots, a_i$，故 $\mathrm{cnt}_i(S) = \#\{j \le i : a_j \in S\}$。兩式相減，$j \le l-1$ 的項全數抵消，剩下 $l \le j \le r$ ✔。$\square$

**這裡點名的前提，是整章反覆出現的同一件事：計數在加法下構成一個群，有反元素，所以「相減」有意義。** 9.1 定理 5 說樹狀陣列的區間查詢需要群、9.3 說線段樹只需要么半群；**主席樹的「版本相減」也需要群。**

**推論 3.1（主席樹的能力邊界）**：**主席樹能做「區間第 $k$ 小」「區間內值在 $[x,y]$ 的個數」「區間不同值個數（配合另一種建版本方式）」，但不能做「區間 max」**——最大值沒有反元素，$\max_r - \max_{l-1}$ 毫無意義。**要區間 max 就用 9.7 的 ST 表或 9.3 的線段樹。**

**注意這裡「相減」的具體形式**：我們**不**真的建一棵差樹，而是**兩個指標同步下降**——每一步都同時走版本 $r$ 與版本 $l-1$ 的對應節點，用兩者的 `cnt` 相減。**這也是為什麼推論 1.1 重要：兩棵樹的形狀完全相同（都是完整值域的邏輯樹形），才能這樣配對下降。**

### 定理 4（值域二分求第 $k$ 小的正確性）

*演算法*：從 $(u, v) = (\mathrm{root}[l-1], \mathrm{root}[r])$、值域區間 $[0, m)$ 出發。令 $c = \mathrm{cnt}(v.\mathit{lc}) - \mathrm{cnt}(u.\mathit{lc})$（左半值域在 $[l,r]$ 中的元素個數）。若 $k \le c$ 就往左走，否則往右走並令 $k \gets k - c$。走到葉子時回傳該葉子的值。

**迴圈不變量 (K)**：*當前值域區間 $[\mathit{lo}, \mathit{hi})$ 內恰有 $\ge k$ 個 $[l,r]$ 中的元素，且**原問題的答案**就是「$[l,r]$ 中落在 $[\mathit{lo}, \mathit{hi})$ 內的元素的第 $k$ 小」。*

*證明*。

**初始**：$[\mathit{lo}, \mathit{hi}) = [0, m)$ 包含全部元素，$k$ 未改動 ✔。

**維持**。設 (K) 在 $[\mathit{lo}, \mathit{hi})$ 成立，中點 $\mathit{mid}$，左半含 $c$ 個元素。

- 若 $k \le c$：左半的所有元素都**嚴格小於**右半的所有元素（值域切分），所以「$[\mathit{lo},\mathit{hi})$ 內的第 $k$ 小」= 「$[\mathit{lo},\mathit{mid})$ 內的第 $k$ 小」，且左半確實有 $\ge k$ 個元素 ✔。
- 若 $k > c$：$[\mathit{lo},\mathit{hi})$ 內最小的 $c$ 個元素全在左半，故第 $k$ 小 = 右半的第 $k - c$ 小；由 (K) 有 $\ge k$ 個元素，扣掉左半的 $c$ 個，右半有 $\ge k - c$ 個 ✔。

**終止**：值域區間長度每次減半，$L$ 步後成為單點 $[\mathit{lo}, \mathit{lo}+1)$。此時 (K) 說「該值出現 $\ge k$ 次且答案是其中第 $k$ 小」——同一個值的第 $k$ 小就是它自己 ✔。$\square$

**兩個容易忽略的點**：
- **「左半嚴格小於右半」是值域線段樹的性質，不是下標線段樹的性質。** 這個證明放在下標線段樹上完全不成立。**先確認你建的是權值線段樹。**
- **$k$ 必須滿足 $1 \le k \le r-l+1$。** 初始不變量要求「$\ge k$ 個元素」，$k$ 越界時整個論證失效（實作上會走到葉子回傳一個錯誤的值，而不是報錯）。**呼叫前檢查。**

### 定理 5（為什麼可持久化不能 `pushDown`，以及標記永久化為什麼可以）

*命題*：在可持久化線段樹上執行 9.4 式的 `pushDown` 會破壞不變量 (V)。

*證明（給出破壞的實例）*。`pushDown(k)` 做兩件事：把 `t[k].tag` 套用到兩個子節點、再把 `t[k].tag` 清空。**這兩個寫入都落在既有節點上。** 若 $k$ 的某個子節點 $u$ 同時被舊版本 $i'$ 可達（共享），那麼 $u$ 的值被改了，而版本 $i'$ 的根到 $u$ 的路徑上並沒有相應的標記被移除——版本 $i'$ 的查詢會把這個標記算兩次 ✔（破壞了 (V)）。$\square$

**正確的做法是標記永久化（9.5 定理 3）**：標記寫在典範節點上、**永不下傳**，查詢時沿路累加。**因為修改時這些節點本來就要複製，寫入落在新副本上，舊版本毫髮無傷。**

**於是可持久化與標記永久化是天生一對**——這也解釋了為什麼競賽程式碼裡「可持久化 + lazy」幾乎總是寫成永久化的形式。**代價是繼承 9.5 定理 3 的限制：標記必須可交換，區間賦值做不到。**

**推論 5.1**：一切「就地修改」都要重新檢查。例如想在主席樹上「刪掉一個元素」，不能改 `cnt`，只能**建一個新版本**。

### 定理 6（版本鏈不必是線性的）

*觀察*：`root` 只是一個指標陣列，**版本 $i$ 的父版本可以是任意舊版本**，不必是 $i-1$。

於是可持久化天然支援：
- **可回溯**：`root[i] = root[j]`（$j < i-1$）就是「回到版本 $j$」，$O(1)$；
- **版本樹**：從同一個版本分岔出多條修改線（可持久化並查集、可持久化平衡樹皆賴此）。

**但定理 3 的「相減」只在版本鏈是線性前綴時才有意義。** 若版本形成一棵樹，$\mathrm{cnt}_r - \mathrm{cnt}_{l-1}$ 對應的不再是連續子陣列，而是「樹上路徑」——那是「樹上主席樹」的做法：對每個節點建立「根到它」的版本，查詢路徑 $(u,v)$ 時用 $\mathrm{cnt}_u + \mathrm{cnt}_v - \mathrm{cnt}_{\mathrm{lca}} - \mathrm{cnt}_{\mathrm{fa}(\mathrm{lca})}$。**四個版本一起下降，原理完全相同——都只依賴「計數可加減」這一個前提。**

## C++17 模板

**模板一：主席樹求區間第 $k$ 小（最常用的形態）**

```cpp
struct KthSeg {
    struct Node {
        int lc = 0, rc = 0, cnt = 0;
    };
    vector<Node> t;
    vector<int> root, vals;  // vals：離散化後的值
    int m = 0;

    // 插入 pos（值域下標），基於版本 prev，回傳新節點下標
    int insert(int prev, int lo, int hi, int pos) {
        int cur = int(t.size());
        t.push_back(t[prev]);  // 複製整個節點（含兩個子指標）
        t[cur].cnt++;
        if (hi - lo == 1) return cur;
        int mid = lo + (hi - lo) / 2;
        if (pos < mid)
            t[cur].lc = insert(t[prev].lc, lo, mid, pos);
        else
            t[cur].rc = insert(t[prev].rc, mid, hi, pos);
        return cur;
    }

    explicit KthSeg(const vector<int>& a) {
        vals = a;
        sort(vals.begin(), vals.end());
        vals.erase(unique(vals.begin(), vals.end()), vals.end());
        m = max<int>(vals.size(), 1);
        t.reserve(a.size() * (__lg(m) + 2) + 2);
        t.emplace_back();   // t[0]：空節點
        root.assign(1, 0);  // 版本 0：空樹
        for (int x : a) {
            int p =
                int(lower_bound(vals.begin(), vals.end(), x) - vals.begin());
            root.push_back(insert(root.back(), 0, m, p));
        }
    }

    // a[l..r]（0-indexed，皆含）的第 k 小，k 從 1 起算
    int kth(int l, int r, int k) const {
        int u = root[l], v = root[r + 1];  // 版本 l-1 與版本 r（前綴長度）
        int lo = 0, hi = m;
        while (hi - lo > 1) {
            int c = t[t[v].lc].cnt - t[t[u].lc].cnt;
            int mid = lo + (hi - lo) / 2;
            if (k <= c) {
                u = t[u].lc;
                v = t[v].lc;
                hi = mid;
            } else {
                k -= c;
                u = t[u].rc;
                v = t[v].rc;
                lo = mid;
            }
        }
        return vals[lo];
    }
};
```

**`t.push_back(t[prev])` 這一行是整份程式碼的心臟**：先整份複製（所以「非路徑方向」的子指標自動被共用），再只改動需要改的部分。**注意不能寫成 `t.push_back(t[prev]); ...` 之後又用 `t[prev]` 的參考——`push_back` 可能觸發擴容使參考失效。上面的寫法用的是下標，安全。**

**`t[0].cnt == 0` 讓 `t[t[v].lc].cnt` 在 `lc == 0` 時自動回傳 0**，省去所有空指標判斷。**這是 `t[0]` 哨兵最漂亮的地方。**

**模板二：查詢區間內值落在 $[x, y]$ 的個數**

```cpp
// 版本差 (u, v) 中，值域下標落在 [ql, qr) 的個數
int count(int u, int v, int lo, int hi, int ql, int qr) const {
    if (qr <= lo || hi <= ql) return 0;
    if (ql <= lo && hi <= qr) return t[v].cnt - t[u].cnt;
    int mid = lo + (hi - lo) / 2;
    return count(t[u].lc, t[v].lc, lo, mid, ql, qr) +
           count(t[u].rc, t[v].rc, mid, hi, ql, qr);
}
```

**與 9.3 的區間查詢一模一樣，只是每個節點都拖著兩個版本同步走。** 由 9.3 定理 2，訪問 $O(\log m)$ 個節點對。

## 時間與空間複雜度

令 $n$ 為元素數、$m$ 為離散化後值域、$q$ 為查詢數、$L = \lceil\log_2 m\rceil$。

| 操作 | 時間 | 空間 |
| --- | --- | --- |
| 建樹（$n$ 次插入） | $O(n\log m)$ | $O(n\log m)$ 節點 |
| 區間第 $k$ 小 | $O(\log m)$ | $O(1)$（迴圈版，非遞迴） |
| 區間值域計數 | $O(\log m)$ | $O(\log m)$ 遞迴堆疊 |
| 離散化 | $O(n\log n)$ | $O(n)$ |

**總計 $O((n+q)\log n)$ 時間、$O(n\log n)$ 空間。**

**空間試算**：$n = m = 10^5$、$L = 17$ ⇒ $10^5 \times 19 \approx 1.9\times10^6$ 節點 $\times$ 12 B $\approx$ **23 MB**。$n = 10^6$ 就變成 230 MB——**規模上去就要考慮離線做法。**

**與替代方案的複雜度對照（區間第 $k$ 小）**：

| 做法 | 時間 | 空間 | 線上？ |
| --- | --- | --- | --- |
| 主席樹 | $O((n+q)\log n)$ | $O(n\log n)$ | **✔** |
| 整體二分 | $O((n+q)\log n\log V)$ | $O(n)$ | ✘ |
| 莫隊 + 值域分塊 | $O(n\sqrt q + q\sqrt n)$ | $O(n)$ | ✘ |
| 排序 + 樹狀陣列（離線掃描） | $O((n+q)\log n)$ | $O(n)$ | ✘ |
| 暴力排序每個查詢 | $O(qn\log n)$ | $O(n)$ | ✔ |

**主席樹是唯一同時做到「線上」與 $O(\log n)$ 單次查詢的。空間是它付出的代價。**

## 常見錯誤與邊界條件

- **節點池開太小**。$n(L+2)+2$ 是安全值。**開太小是 RE，開太大是 MLE——先算一次。** 用 `reserve` 而非固定大小陣列，可以避免猜錯上界。
- **`push_back` 後仍持有舊參考**。`t.push_back(t[prev])` 若寫成 `Node& p = t[prev]; t.push_back(p);` 會在擴容時讀到失效參考。**全程用下標，不要用參考。**
- **版本編號差一**。`root[i]` 通常定義為「放入前 $i$ 個元素」，查 $[l, r]$（0-indexed）要用 `root[l]` 與 `root[r+1]`。**這個 off-by-one 是本節最高頻的錯誤，寫註解標明 `root` 的語義。**
- **忘記離散化，或離散化後忘記 `unique`**。重複值不去重會讓值域變大（不致錯，但浪費），而**答案要用 `vals[lo]` 還原回原值**——直接回傳值域下標是錯的。
- **`pushDown`**（定理 5）。可持久化上絕不能下傳標記，只能永久化。
- **就地修改既有節點**（推論 5.1）。任何 `t[x].cnt++`（$x$ 不是剛建的節點）都會污染舊版本。**症狀是「舊版本的答案變了」，而不是崩潰——極難除錯。建議把修改集中在 `insert` 一個函式裡。**
- **`k` 越界**（定理 4）。$k > r-l+1$ 時演算法不會報錯，只會回傳垃圾。
- **值域寫成閉區間**。本節模板一律用半開 $[lo, hi)$，遞迴終止條件是 `hi - lo == 1`。**混用閉區間會讓葉子判斷錯位。**
- **`mid = (lo + hi) / 2`**。離散化後 $m \le n$ 很小，這裡不會溢位；**但若跳過離散化直接在 $[0, 10^9)$ 上可持久化，就回到 9.5 的坑，必須寫 `lo + (hi - lo) / 2`。** 模板統一用安全寫法。
- **想拿它做區間 max**（推論 3.1）。沒有反元素，版本相減沒有意義。

## 與相似技巧的比較

- **與 9.5 動態開點**：兩者都「按需建節點」，但 9.5 是**一棵樹**在大值域上省空間，本節是**多棵樹**共享子樹以保留歷史。**技術上可以疊加**（不離散化的可持久化 = 動態開點 + 持久化），而且**兩者都被迫使用標記永久化**——9.5 是為了省節點，本節是為了不破壞舊版本。
- **與 9.3／9.4 一般線段樹**：唯一結構差異是「改節點」變成「複製節點」。**9.3 定理 2 的區間分解、定理 1 的覆蓋路徑，在這裡逐字成立**——所以查詢的複雜度分析可以整段搬過來。
- **與離線做法（整體二分、莫隊、排序+樹狀陣列）**：**能離線就先考慮它們**，空間 $O(n)$ 且常數小。整體二分尤其值得學——它用 $O(n)$ 空間換一個 $\log$，思路是「對所有查詢同時二分答案」。**主席樹換來的是線上與更好的單次查詢複雜度。**
- **與可持久化 Trie**：同一個想法套在 01-Trie 上，用來做「區間內與 $x$ 異或最大」。**結構更簡單（固定 30 層、無需離散化），值得作為理解可持久化的第一個例子。**
- **與 wavelet tree**：也能做區間第 $k$ 小，空間 $O(n\log \sigma)$ 位元（比主席樹省很多），但實作較繁、修改困難。**競賽中主席樹的性價比更高。**
- **與 9.7 ST 表**：ST 表是「不修改、$O(1)$ 查詢、只支援可重複貢獻的聚合」；主席樹是「不修改原陣列、$O(\log n)$ 查詢、支援可減的計數」。**兩者的能力邊界剛好互補：ST 表能做 max 不能做第 $k$ 小，主席樹反之。**
- **與 8 節並查集**：可持久化並查集用同樣的手法（可持久化陣列 = 可持久化線段樹的葉子），但**必須放棄路徑壓縮**（壓縮是就地修改，違反推論 5.1），只保留按秩合併，複雜度退化到 $O(\log n)$。**又一次「不變量決定了哪些優化可用」。**

## 本節重點速查

- **核心想法**：相鄰版本只差一條根到葉的路徑 ⇒ **複製路徑、共享其餘**，每個版本只多花 $O(\log m)$ 空間。
- **不變量 (V)（定理 1）**：每個 `root[i]` 都是一棵語義完整的樹。**依賴兩個前提：修改只碰一條路徑；只寫新節點、絕不寫舊節點。**
- **空間 $O(n\log m)$（定理 2）**。節點池 `reserve(n * (log2(m) + 2) + 2)`，**開太小 RE、開太大 MLE**。
- **主席樹 = 前綴版本 + 版本相減（定理 3）**：$\mathrm{cnt}_r - \mathrm{cnt}_{l-1}$。**前提是計數構成群（有反元素）——和 9.1 定理 5 是同一個條件。** 所以能做第 $k$ 小、值域計數，**不能做區間 max**（推論 3.1）。
- **實作上不建差樹，而是兩個指標同步下降。**
- **值域二分（定理 4）**：$c$ = 左半計數差，$k\le c$ 往左、否則 $k \gets k-c$ 往右。**不變量：答案是當前值域區間內的第 $k$ 小。** 正確性依賴「值域線段樹的左半嚴格小於右半」——下標線段樹上不成立。
- **絕不 `pushDown`（定理 5）**：下傳會寫進共享節點，污染舊版本。**用標記永久化（9.5 定理 3），代價是標記必須可交換。**
- **版本鏈可以是樹（定理 6）**：$O(1)$ 回溯、可持久化並查集、樹上主席樹（四版本同步下降）。**但「相減」只在線性前綴或樹上路徑差分時有意義。**
- **最高頻錯誤**：`root` 的 off-by-one（查 $[l,r]$ 要用 `root[l]` 與 `root[r+1]`）；`push_back` 後持有失效參考；忘了用 `vals[lo]` 還原原值。
- **先問能不能離線**：整體二分／排序+樹狀陣列空間 $O(n)$、常數更小。**主席樹的不可替代之處是線上。**
