## 這個技術解決什麼問題

線段樹的區間查詢是 $O(\log n)$。當查詢次數遠多於元素數——例如 $n = 10^5$ 但要在某個雙層迴圈裡問 $10^7$ 次區間 max——那個 $\log$ 就是瓶頸。

**但如果陣列從頭到尾不會被修改**，我們可以用預處理換掉這個 $\log$：

> **ST 表：$O(n\log n)$ 預處理，$O(1)$ 回答區間 min／max／gcd。**

代價是**完全不支援修改**（改一個元素要重建整張表），而且**只適用於「可重複貢獻」的運算**（定理 2 會說清楚這是什麼意思，以及為什麼求和用不了）。

**辨識訊號**：
- **陣列固定不變**，但要回答極多次區間 min／max／gcd 查詢。**「不需修改」是關鍵前提——一旦要改就改用線段樹。**
- 演算法的內層反覆需要「某段的最值」，且該段隨著指標滑動（3691 最大子陣列總值 II、3501 操作後最大活躍區段數 II）；
- 查詢次數 $q \gg n$，$O(q\log n)$ 被卡；
- 需要在區間最值上再做二分／遞迴分治（例如笛卡爾樹式的分治，每層要 $O(1)$ 取區間最大值的位置）。

**反過來說，看到「修改」兩個字就不要用 ST 表。** 這不是效率問題，是**做不到**——ST 表沒有任何增量更新的辦法。

## 狀態／資料結構定義

**狀態定義（整節只有這一個式子）：**

$$\mathit{st}[k][i] \;=\; \mathrm{op}\big(a_i,\, a_{i+1},\, \dots,\, a_{i + 2^k - 1}\big),$$

也就是**從 $i$ 開始、長度恰為 $2^k$ 的區間**的聚合值。合法範圍是 $0 \le i$ 且 $i + 2^k \le n$。

```cpp
template <class T, class Op>
struct SparseTable {
    vector<vector<T>> st;
    Op op;
    explicit SparseTable(const vector<T>& a, Op op = Op()) : op(op) {
        int n = int(a.size()), K = (n > 1 ? __lg(n) : 0) + 1;
        st.assign(K, vector<T>(n));
        st[0] = a;
        for (int k = 1; k < K; k++)
            for (int i = 0; i + (1 << k) <= n; i++)
                st[k][i] = op(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
    }
    T query(int l, int r) const {  // [l, r] 皆含，需 l <= r
        int k = __lg(r - l + 1);
        return op(st[k][l], st[k][r - (1 << k) + 1]);
    }
};
```

**兩層迴圈的順序不能換**：$\mathit{st}[k]$ 依賴 $\mathit{st}[k-1]$，必須先把整層 $k-1$ 算完。

**`query` 只有兩行，而且沒有迴圈——這就是 $O(1)$。** 它取兩段長度都是 $2^k$ 的區間：一段貼左端、一段貼右端。**這兩段一定會重疊**（除非 $r-l+1$ 恰好是 2 的冪），而**「重疊沒關係」正是 ST 表最強的假設，也是它最大的限制。**

**運算 $\mathrm{op}$ 必須滿足三條性質（缺一不可）：**

| 性質 | 意思 | `max` | `gcd` | `+` |
| --- | --- | --- | --- | --- |
| 結合律 | $(x\,\mathrm{op}\,y)\,\mathrm{op}\,z = x\,\mathrm{op}\,(y\,\mathrm{op}\,z)$ | ✔ | ✔ | ✔ |
| 交換律 | $x\,\mathrm{op}\,y = y\,\mathrm{op}\,x$ | ✔ | ✔ | ✔ |
| **冪等（可重複貢獻）** | $x\,\mathrm{op}\,x = x$ | ✔ | ✔ | **✘** |

**滿足三者的運算構成一個半格（semilattice）**：`min`、`max`、`gcd`、`lcm`、按位 `&`、按位 `|`。**求和、乘積、XOR 都不冪等，ST 表對它們無效**（$x \oplus x = 0 \ne x$）。

## 不變量或正確性證明

### 定理 1（預處理的正確性）

**不變量 (T)**：迴圈結束後，對所有合法的 $(k, i)$，$\mathit{st}[k][i] = \mathrm{op}(a_i, \dots, a_{i+2^k-1})$。

*證明（對 $k$ 歸納）*。

**基底** $k = 0$：$\mathit{st}[0][i] = a_i$，區間長度 $2^0 = 1$ ✔。

**歸納步**：設 (T) 對 $k-1$ 成立。長度 $2^k$ 的區間 $[i,\, i+2^k-1]$ 可**恰好**切成兩段長度 $2^{k-1}$ 的區間 $[i,\, i+2^{k-1}-1]$ 與 $[i+2^{k-1},\, i+2^k-1]$，**不重不漏**。由歸納假設兩段的值分別是 $\mathit{st}[k-1][i]$ 與 $\mathit{st}[k-1][i+2^{k-1}]$，由**結合律**可以先算兩段再合併 ✔。$\square$

**注意這裡只用了結合律**——預處理階段兩段不重疊，還不需要冪等。**冪等是查詢階段才用到的。**

### 定理 2（$O(1)$ 查詢的正確性）

*命題*：設 $\mathit{len} = r - l + 1 \ge 1$，$k = \lfloor\log_2 \mathit{len}\rfloor$。則

$$\mathrm{op}\big(\mathit{st}[k][l],\; \mathit{st}[k][\,r - 2^k + 1\,]\big) \;=\; \mathrm{op}(a_l, \dots, a_r).$$

*證明*。令 $S_1 = [\,l,\; l+2^k-1\,]$、$S_2 = [\,r-2^k+1,\; r\,]$。

**(a) 兩段都落在 $[l, r]$ 內。** 由 $k = \lfloor\log_2 \mathit{len}\rfloor$ 得 $2^k \le \mathit{len}$，故 $S_1$ 的右端 $l + 2^k - 1 \le l + \mathit{len} - 1 = r$ ✔；同理 $S_2$ 的左端 $r - 2^k + 1 \ge r - \mathit{len} + 1 = l$ ✔。**這保證不會把區間外的元素算進來。**

**(b) 兩段的聯集覆蓋 $[l, r]$。** 由 $k = \lfloor\log_2 \mathit{len}\rfloor$ 得 $\mathit{len} < 2^{k+1} = 2\cdot 2^k$，即 $2^k > \mathit{len}/2$。於是 $S_1$ 的右端 $\ge l + \mathit{len}/2 - 1$，而 $S_2$ 的左端 $\le r - \mathit{len}/2 + 1$；具體地，$S_2$ 的左端 $-\, S_1$ 的右端 $= (r - 2^k + 1) - (l + 2^k - 1) = \mathit{len} + 1 - 2^{k+1} \le 0$，所以 $S_2$ 的左端 $\le S_1$ 的右端 $+\,1$——**兩段首尾相接或重疊，中間沒有空隙** ✔。**這保證不會漏掉元素。**

**(c) 重疊部分被算兩次也無妨。** 由 (a)(b)，$S_1 \cup S_2 = [l, r]$，但作為**多重集** $S_1 \uplus S_2$ 中，$S_1 \cap S_2$ 的元素出現兩次。由**交換律與結合律**，我們可以把結果重排成 $\mathrm{op}$ 依序作用於 $S_1\cap S_2$ 的元素各兩次、其餘各一次；再由**冪等律** $x\,\mathrm{op}\,x = x$，反覆消去重複項，得到與「每個元素恰一次」相同的結果 ✔。$\square$

**三條性質各自負責證明的一個部分**——(a)(b) 是純算術，(c) 才動用代數。**這就是為什麼求和用不了：對 `+`，重疊部分被加了兩次，答案直接錯。**

**推論 2.1（唯一需要檢查的事）**：拿到一個新的 $\mathrm{op}$，只需驗證「$x\,\mathrm{op}\,x = x$」。結合律與交換律通常一眼可見，冪等律才是真正的分水嶺。$\gcd(x,x)=x$ ✔、$\mathrm{lcm}(x,x)=x$ ✔、$x\,\&\,x = x$ ✔、$x \oplus x = 0$ ✘。

**推論 2.2（區間長度為 2 的冪時兩段重合）**：此時 $2^k = \mathit{len}$，$S_1 = S_2$，計算的是 $\mathrm{op}(v, v) = v$。**這是冪等律的極端情形，也順帶說明程式碼不必特判。**

### 定理 3（$k$ 的計算必須是**下**取整）

*命題*：定理 2 的 (a) 依賴 $2^k \le \mathit{len}$，(b) 依賴 $2^{k+1} > \mathit{len}$。**兩者合起來唯一確定 $k = \lfloor\log_2 \mathit{len}\rfloor$。**

- 若取大了（$2^k > \mathit{len}$）：(a) 失效，$S_1$ 會伸出 $r$ 之外，**答案包含不該有的元素**，而且 $\mathit{st}[k][l]$ 甚至可能越界。
- 若取小了（$2^{k+1} \le \mathit{len}$）：(b) 失效，中間出現空隙，**漏算元素**。

**實作上有兩種算法**：
- `__lg(x)`（GCC 內建，$O(1)$，`x` 必須 $> 0$）；
- 預處理 `lg[1] = 0; lg[i] = lg[i/2] + 1;`（可攜、無分支、快取友善）。

**`__lg(0)` 是未定義行為**（底層是 `31 - __builtin_clz(0)`，而 `__builtin_clz(0)` 未定義）。**所以 `query` 必須保證 $l \le r$。空區間要由呼叫端處理，不要指望 `query` 回傳單位元。**

### 定理 4（非冪等運算怎麼辦：Disjoint Sparse Table）

冪等律不是天生必要的——**它只是「允許重疊」這個偷懶做法的代價。** 若改成「保證兩段不重疊」，就只需要結合律。

*Disjoint Sparse Table 的構造*：對第 $k$ 層，把陣列按 $2^{k+1}$ 分塊；在每塊內以塊中點為界，**向左做後綴聚合、向右做前綴聚合**，都存進 $\mathit{dst}[k]$。

*查詢 $[l, r]$*：取 $k$ 使得 $l$ 與 $r$ 在第 $k$ 層**首次被同一塊的中點分開**——即 $k = \lfloor\log_2(l \oplus r)\rfloor$。此時 $\mathit{dst}[k][l]$ 是「$l$ 到中點」的後綴、$\mathit{dst}[k][r]$ 是「中點到 $r$」的前綴，**兩段不重不漏**，合併即得答案。

*正確性的關鍵*：$l \oplus r$ 的最高位 $k$，恰好是 $l$ 與 $r$ 在二進位上首次分歧的位置，也就是「以 $2^{k+1}$ 分塊時，$l$ 與 $r$ 同塊但被中點分開」的那一層 ✔。

**所以：$O(n\log n)$ 預處理、$O(1)$ 查詢、只需結合律——連求和、矩陣乘法都能做。** 代價是實作較繁、常數較大、且 $l = r$ 要特判（$l\oplus r = 0$）。

**但要誠實**：**區間和用前綴和就好（$O(n)$ 空間、$O(1)$ 查詢），DST 是為了「不可減的結合運算」而生**——例如區間矩陣乘積、區間最大子段和的 `Info` 合併（9.3 定理 3 的那種）。**LeetCode 上罕見，知道有這個東西即可。**

### 定理 5（gcd 的 ST 表：複雜度與一個常用性質）

**複雜度不一樣**：`gcd` 本身是 $O(\log V)$，所以預處理是 $O(n\log n\log V)$、查詢是 $O(\log V)$ 而非 $O(1)$。**寫「$O(1)$ 查詢」的時候心裡要清楚這是對 `min`／`max` 說的。**

**一個常被用到的性質**：*固定左端點 $l$，序列 $g_r = \gcd(a_l, \dots, a_r)$ 隨 $r$ 增大而單調不增（在整除意義下），且**至多只有 $O(\log V)$ 個不同值**。*

*證明*。$g_{r+1} \mid g_r$。若 $g_{r+1} \ne g_r$，則 $g_{r+1} \le g_r / 2$（真因數至多是一半）。從 $g_l = a_l \le V$ 開始，最多減半 $\log_2 V$ 次就到 1 ✔。$\square$

**這個性質讓「枚舉所有不同的區間 gcd」變成 $O(n\log V)$ 而非 $O(n^2)$**，配上 ST 表的二分（對固定 $l$ 二分出每段 gcd 相同的極大區間）就能高效處理「有多少子陣列的 gcd 等於 $x$」這類問題。**同樣的論證對 `按位 &`、`按位 |` 也成立**（每次變化至少改變一個位元，故至多 $O(\log V)$ 種值）——**這是「ST 表 + 值段合併」這一族解法的共同基礎。**

### 定理 6（ST 表上的二分：$O(\log n)$ 找最遠邊界）

*問題*：固定 $l$，求最大的 $r$ 使得 $\max(a_l, \dots, a_r) \le x$。

由於 $\max$ 隨 $r$ 單調不減，可以直接二分 + `query`，$O(\log n)$ 且每步 $O(1)$。**但也可以用「倍增」做成一次掃描**：從 $k = \lfloor\log_2 n\rfloor$ 往下，若 $\mathit{st}[k][\mathit{pos}] \le x$ 就 $\mathit{pos} \mathrel{+}= 2^k$。**正確性與 LCA 倍增完全同構**——不變量是「$\mathit{pos}$ 始終是合法的右端界之後一格」，每步嘗試盡量大的跳躍。

**與 9.3 定理 4 的線段樹上二分對照**：線段樹二分是 $O(\log n)$ 且**支援修改**；ST 表二分也是 $O(\log n)$ 但**不支援修改**。**單看這個操作，ST 表沒有優勢——它的優勢只在單次 $O(1)$ 的區間查詢。**

## C++17 模板

**模板一：泛型 ST 表（最常用的形態）**

```cpp
template <class T, class Op>
struct SparseTable {
    vector<vector<T>> st;
    Op op;
    SparseTable() = default;
    SparseTable(const vector<T>& a, Op op = Op()) : op(op) {
        int n = int(a.size());
        if (n == 0) return;
        int K = __lg(n) + 1;
        st.assign(K, vector<T>(n));
        st[0] = a;
        for (int k = 1; k < K; k++)
            for (int i = 0; i + (1 << k) <= n; i++)
                st[k][i] = op(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
    }
    // [l, r] 兩端皆含；呼叫端必須保證 0 <= l <= r < n
    T query(int l, int r) const {
        int k = __lg(r - l + 1);
        return op(st[k][l], st[k][r - (1 << k) + 1]);
    }
};

// 用法
SparseTable<int, function<int(int, int)>> mx(a, [](int x, int y) {
    return max(x, y);
});
SparseTable<int, function<int(int, int)>> g(a, [](int x, int y) {
    return gcd(x, y);
});
```

**用 `function` 方便但有間接呼叫開銷；效能敏感時改用無狀態的 functor：**

```cpp
struct MaxOp {
    int operator()(int x, int y) const { return x > y ? x : y; }
};
SparseTable<int, MaxOp> mx(a);  // 可完全內聯
```

**模板二：一維扁平化（省記憶體、更快）**

```cpp
struct MaxST {
    int n, K;
    vector<int> st, lg;  // st 攤平成 K * n
    explicit MaxST(const vector<int>& a) : n(int(a.size())) {
        lg.assign(n + 1, 0);
        for (int i = 2; i <= n; i++) lg[i] = lg[i >> 1] + 1;
        K = lg[max(n, 1)] + 1;
        st.assign(size_t(K) * n, INT_MIN);
        copy(a.begin(), a.end(), st.begin());
        for (int k = 1; k < K; k++)
            for (int i = 0; i + (1 << k) <= n; i++)
                st[size_t(k) * n + i] =
                    max(st[size_t(k - 1) * n + i],
                        st[size_t(k - 1) * n + i + (1 << (k - 1))]);
    }
    int query(int l, int r) const {
        int k = lg[r - l + 1];
        return max(st[size_t(k) * n + l], st[size_t(k) * n + r - (1 << k) + 1]);
    }
};
```

**自建 `lg` 表而不用 `__lg`，順帶避開了 `__lg(0)` 的未定義行為（`lg[0] = 0`），也不依賴 GCC 擴充。**

**模板三：同時要最值與其位置**

```cpp
// 存下標而非值，比較時查原陣列——這樣就能回傳「最大值在哪」
int better(int i, int j) const {
    return a[i] >= a[j] ? i : j;
}
```

**「回傳位置」比「回傳值」更通用**（有了位置就有值，反之不然），而且是笛卡爾樹式分治的必要條件。**唯一要小心的是相等時的取捨要一致**，否則同一個查詢可能回傳不同下標。

## 時間與空間複雜度

| | 預處理 | 單次查詢 | 空間 |
| --- | --- | --- | --- |
| ST 表（min／max／&／\|） | $O(n\log n)$ | $O(1)$ | $O(n\log n)$ |
| ST 表（gcd／lcm） | $O(n\log n\log V)$ | $O(\log V)$ | $O(n\log n)$ |
| Disjoint ST 表（任意結合運算） | $O(n\log n)$ | $O(1)$ | $O(n\log n)$ |
| 線段樹 | $O(n)$ | $O(\log n)$ | $O(n)$ |
| 前綴和（僅可減運算） | $O(n)$ | $O(1)$ | $O(n)$ |

**$q$ 次查詢的總時間**：ST 表 $O(n\log n + q)$、線段樹 $O(n + q\log n)$。**交叉點大約在 $q \approx n$**：$q \ll n$ 時線段樹（甚至暴力）更好，$q \gg n$ 時 ST 表明顯勝出。

**空間是 ST 表唯一真正的弱點，必須試算**：

| $n$ | $K = \log_2 n + 1$ | `int` 表大小 | 結論 |
| --- | --- | --- | --- |
| $10^4$ | 15 | 0.6 MB | 安全 |
| $10^5$ | 18 | 7.2 MB | 安全 |
| $10^6$ | 21 | **84 MB** | 危險 |
| $10^7$ | 25 | 1000 MB | 不可行 |

**$n \ge 10^6$ 就要改用「分塊 + 塊內 ST 表」的 $O(n)$–$O(1)$ 方案，或直接退回線段樹。** LeetCode 的 $n$ 通常 $\le 10^5$，ST 表夠用。

**另外**：`vector<vector<T>>` 的每一層是獨立配置，查詢時兩次間接定址。**模板二的扁平化版本在熱迴圈裡通常快 20%–40%。**

## 常見錯誤與邊界條件

- **拿去做區間和／XOR**。不冪等，重疊部分被算兩次（定理 2(c)）。**這是最根本的誤用，而且測資小時可能剛好蒙對——因為兩段不重疊時答案是對的。務必用長度非 2 的冪的區間測試。**
- **`__lg(0)`**。$l > r$ 時 `r - l + 1 <= 0`，`__lg` 未定義。**呼叫端保證 $l \le r$，或改用自建 `lg` 表。**
- **`k` 用了上取整**（定理 3）。`__lg` 本身就是下取整，但若手寫成 `ceil(log2(len))` 就錯了；**`log2` 的浮點誤差也會在 $\mathit{len}$ 恰為 2 的冪時出錯**（可能得到 $k$ 或 $k-1$）。**不要用浮點 `log2`。**
- **$K$ 開太小**。$K$ 必須 $\ge \lfloor\log_2 n\rfloor + 1$。**寫成 `__lg(n)` 少一層，最長的那個查詢就越界。**
- **內層迴圈的邊界寫成 `i < n`**。必須是 `i + (1 << k) <= n`，否則讀到未初始化的元素。
- **兩層迴圈順序顛倒**。必須 $k$ 在外、$i$ 在內。
- **建表後修改了原陣列**。ST 表不會跟著變，**而且不會報錯**——只會安靜地回答舊資料。**若模板三存的是下標且參考原陣列，這一點尤其危險。**
- **`min`／`max` 的初始值**。扁平化版把未使用的格子填 `INT_MIN`（對 `max`）；若拿去做 `min` 要改成 `INT_MAX`。**單位元選錯，越界讀取就會安靜地污染答案。**
- **`gcd` 沒處理 0**。$\gcd(0, x) = x$ 是對的（0 是 `gcd` 的單位元），但若題目語義上 0 代表「空」，就要另外約定。
- **記憶體**。$n \ge 10^6$ 時 $O(n\log n)$ 會炸（見上表）。
- **回傳位置時相等的取捨不一致**（模板三），導致同一查詢的兩段給出不同下標。

## 與相似技巧的比較

- **與 9.3／9.4 線段樹**：**能不能修改，是唯一的分水嶺。** 線段樹 $O(n)$ 空間、$O(\log n)$ 查詢、支援修改；ST 表 $O(n\log n)$ 空間、$O(1)$ 查詢、**完全不支援修改**。而且線段樹只需要么半群（9.3），ST 表還要求冪等——**ST 表能做的事嚴格少於線段樹，換來的只有那個常數級的查詢。** $q \gg n$ 時這個交換才划算。
- **與 9.1 樹狀陣列**：樹狀陣列要群（9.1 定理 5），ST 表要半格，**兩者的代數要求不相容**：`sum` 有反元素但不冪等（BIT ✔ / ST ✘），`max` 冪等但沒反元素（BIT ✘ / ST ✔）。**「這個運算有沒有反元素／是不是冪等」決定了你該用哪個工具——這是第 9 節從頭到尾的主線。**
- **與前綴和（2 節）**：前綴和是 $O(n)$–$O(1)$ 的最佳解，**但只對可減運算成立**。ST 表可以視為「不可減運算的前綴和替代品」，代價是 $\log n$ 倍空間。
- **與單調隊列（5 節）**：若查詢的是**固定長度**的滑動窗口最值，單調隊列 $O(n)$ 時間 $O(n)$ 空間，全面優於 ST 表。**只有窗口長度會變時才需要 ST 表。**
- **與離線 + 排序掃描**：若所有查詢事先已知，把查詢按右端點排序 + 單調棧，往往 $O(n\log n)$ 就能解，空間 $O(n)$。**又是那句話：能離線就先想離線。**
- **與 Disjoint Sparse Table（定理 4）**：放棄「重疊」換掉冪等要求，能處理任意結合運算。**LeetCode 罕見，但它清楚地說明了「冪等」在 ST 表裡到底扮演什麼角色——它只是為了讓兩段可以重疊。**
- **與 LCA 的倍增表（trees 章）**：$\mathit{st}[k][i]$ 與 $\mathit{up}[k][v]$ 是同一個「倍增」骨架——**狀態定義都是「從 $x$ 出發跳 $2^k$ 步」，遞推都是「兩個 $2^{k-1}$ 拼成一個 $2^k$」。** 差別在 LCA 的跳躍必須不重疊（所以是 $O(\log n)$ 查詢），而 ST 表允許重疊（所以是 $O(1)$）。**認出這是同一個骨架，兩個東西就只需要記一次。**
- **與 9.6 主席樹**：能力互補——ST 表做 max 不能做第 $k$ 小，主席樹做第 $k$ 小不能做 max（推論 3.1）。**兩者都不支援修改。**
- **與 $O(n)$–$O(1)$ RMQ**：把陣列切成大小 $\log n$ 的塊，塊間用 ST 表（$O(n/\log n \cdot \log n) = O(n)$ 空間），塊內用笛卡爾樹的位元遮罩。**理論最優但常數大、實作複雜，競賽中幾乎不需要。** 知道 $O(n\log n)$ 不是下界就好。

## 例題與分級練習

**延伸閱讀**：[OI Wiki：Sparse Table](https://oi-wiki.org/ds/sparse-table/)。ST 表適合靜態、冪等的 RMQ；若運算不冪等，重疊兩塊會重複計入。

## 本節重點速查

- **存在理由**：**陣列不變 + 查詢極多**。$O(n\log n)$ 預處理換 $O(1)$ 查詢。**看到「修改」就換線段樹——ST 表沒有增量更新的辦法。**
- **狀態**：$\mathit{st}[k][i] = \mathrm{op}(a_i \dots a_{i+2^k-1})$。遞推 $\mathit{st}[k][i] = \mathrm{op}(\mathit{st}[k-1][i],\, \mathit{st}[k-1][i+2^{k-1}])$，**$k$ 在外層、$i$ 在內層，邊界是 `i + (1<<k) <= n`。**
- **查詢兩行**：$k = \lfloor\log_2(r-l+1)\rfloor$，$\mathrm{op}(\mathit{st}[k][l],\, \mathit{st}[k][r-2^k+1])$。**兩段重疊，靠冪等律消掉重複。**
- **三條性質（定理 2）**：結合、交換、**冪等**。(a) $2^k\le \mathit{len}$ ⇒ 不超界；(b) $\mathit{len} < 2^{k+1}$ ⇒ 不漏；(c) 冪等 ⇒ 重疊無害。**唯一要檢查的是 $x\,\mathrm{op}\,x = x$**（推論 2.1）：`min`／`max`／`gcd`／`lcm`／`&`／`|` ✔，`+`／`*`／`^` ✘。
- **$k$ 必須下取整（定理 3）**，用 `__lg` 或自建 `lg` 表，**絕不用浮點 `log2`**；`__lg(0)` 未定義，呼叫端保證 $l\le r$。
- **`gcd` 版查詢是 $O(\log V)$ 不是 $O(1)$（定理 5）**；附帶性質：固定左端點，區間 gcd 至多 $O(\log V)$ 種值（`&`、`|` 同理）——這是「值段合併」解法的基礎。
- **空間 $O(n\log n)$ 是唯一硬傷**：$n=10^5$ ⇒ 7 MB 安全，$n=10^6$ ⇒ 84 MB 危險。**扁平成一維陣列可快 20%–40%。**
- **Disjoint ST（定理 4）**：改成不重疊分段，只需結合律，可做求和／矩陣乘；$k = \lfloor\log_2(l\oplus r)\rfloor$。
- **與倍增 LCA 是同一個骨架**：狀態都是「跳 $2^k$」，差別只在允不允許重疊。
- **選擇順序**：可減 ⇒ 前綴和；固定窗口 ⇒ 單調隊列；要修改 ⇒ 線段樹；能離線 ⇒ 排序掃描；**其餘（不變、多查、冪等）才輪到 ST 表。**
