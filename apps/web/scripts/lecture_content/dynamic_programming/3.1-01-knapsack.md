## 這個技術解決什麼問題

0-1 背包是**「子集選取」問題的標準形式**：

> $n$ 個物品，第 $i$ 個有重量 $w_i$ 與價值 $v_i$，**每個最多用一次**。在總重不超過 $C$ 的前提下求最大總價值。

它之所以是整章最重要的模型，是因為**大量看起來不像背包的題目，都能歸約到它**：分割等和子集是「湊出總和的一半」、目標和是「選哪些數當正號」、最後一塊石頭的重量 II 是「兩堆盡量接近」。**認出歸約，題目就結束了。**

**而本節技術上最關鍵的一條，是「一維陣列為什麼必須倒序」**（定理 2）。它不是口訣，是 2.1 定理 2 的直接推論——**在這裡想通，3.2 完全背包的正序就不必再背。**

**辨識訊號**：
- 一堆物品，每個只能用一次，在某種「容量／預算」限制下求最佳、可行或計數；
- 問題能轉成「選一個子集，使其總和 $=$ 某目標 / $\le$ 某上限」；
- 每個元素的決策**順序無關，只在乎取捨**——這種「順序無關」就是背包味。

## 狀態／資料結構定義

```cpp
// 二維（好懂、好除錯、能回溯方案）
// f[i][c] = 只考慮前 i 個物品、總重不超過 c 的最大價值
vector f(n + 1, vector<int>(C + 1, 0));
for (int i = 1; i <= n; i++)
    for (int c = 0; c <= C; c++) {
        f[i][c] = f[i - 1][c];  // 不選第 i 個
        if (c >= w[i - 1])
            f[i][c] = max(f[i][c], f[i - 1][c - w[i - 1]] + v[i - 1]);
    }

// 一維（實戰用）：容量必須倒序 —— 定理 2
vector<int> g(C + 1, 0);
for (int i = 0; i < n; i++)
    for (int c = C; c >= w[i]; c--)  // 倒序！
        g[c] = max(g[c], g[c - w[i]] + v[i]);
```

**三種題型的初值（定理 3）**：

| 題型 | 初值 | 答案 |
| --- | --- | --- |
| **最大價值、容量「至多」$C$** | `g[*] = 0` | `g[C]` |
| **最大價值、容量「恰好」$C$** | `g[0] = 0`，其餘 `-INF` | `g[C]`（$=-\infty$ 表無解） |
| **可行性 / 計數** | `g[0] = true / 1`，其餘 `false / 0` | `g[C]` |

**「至多」與「恰好」的初值不同，是本節最常見的 WA 來源。** 判準見定理 3。

**可行性型用 `bitset` 可以快 64 倍（定理 5）**：

```cpp
bitset<20001> f;
f[0] = 1;
for (int x : nums) f |= f << x;  // 不需要倒序 —— 定理 5
```

## 不變量或正確性證明

### 定理 1（選或不選：二維遞推的正確性）

*命題*：$f(i, c) = \max\big(f(i-1, c),\; f(i-1,\, c - w_i) + v_i\big)$（第二項僅當 $c \ge w_i$），邊界 $f(0, c) = 0$。

*證明*。設 $O$ 是「前 $i$ 個物品、總重 $\le c$」的一個最優子集。按**第 $i$ 個物品在不在 $O$ 裡**劃分——不漏、不重 ✔。

- **(不在)** $O$ 是「前 $i-1$ 個、總重 $\le c$」的合法子集 ⇒ $\mathrm{val}(O) \le f(i-1,c)$。
- **(在)** $O \setminus \{i\}$ 是「前 $i-1$ 個、總重 $\le c - w_i$」的合法子集 ⇒ $\mathrm{val}(O) \le f(i-1, c-w_i) + v_i$。

反向：右邊兩項各自對應一個合法子集（第二項合法，因為 $f(i-1,c-w_i)$ 的子集不含物品 $i$，加進來仍是子集且總重 $\le c$ ✔）。夾擠得等號。$\square$

**「順序無關」在哪裡用到了**：定理 1 的劃分依據是「物品 $i$ 選不選」，**完全沒有涉及選取的先後**。**這就是背包與 1.1 定理 2「排列數」的分野**——背包按「物品」外層迴圈，數的是**集合**；若按「容量」外層，數的就是**序列**（見 3.2 定理 4）。

**點名前提**：定理 1 不需要 $v_i \ge 0$（`max` 會自動不選），**但需要 $w_i \ge 0$**。**負重量會讓 $c - w_i > c$，依賴指向「更大的容量」⇒ 依賴圖成環 ⇒ DP 失效** ✘。

### 定理 2（一維陣列為什麼必須倒序）

*命題*：把物品維度滾掉、就地更新 `g[c] = max(g[c], g[c - w] + v)` 時，**容量必須由大到小掃描**。

*證明*。由定理 1，計算「加入物品 $i$ 之後」的 $g[c]$ 時，右側的 $g[c-w_i]$ **必須是「尚未考慮物品 $i$」的值**（即 $f(i-1, c-w_i)$）。

由 2.1 定理 2 的判準——**要讀「上一輪」的值，就逆著寫入方向掃**——而 $c - w_i < c$（因 $w_i > 0$），故 $g[c-w_i]$ 位於 $g[c]$ 的**左側**。**倒序掃描時，左側尚未被本輪寫過 ⇒ 讀到的正是上一輪的值** ✔。$\square$

**正序會發生什麼（具體反例）**。設只有一個物品 $w = 2, v = 3$，$C = 4$，正序執行：

| $c$ | 讀 `g[c-2]` | 寫入 `g[c]` | 說明 |
| --- | --- | --- | --- |
| 2 | `g[0] = 0` | $\max(0, 0+3) = 3$ | 用了 1 次 ✔ |
| 3 | `g[1] = 0` | $3$ | |
| 4 | **`g[2] = 3`（本輪剛寫的！）** | $\max(0, 3+3) = \mathbf{6}$ | **同一個物品用了 2 次** ✘ |

**正確答案是 3（只有一個物品），正序算出 6。** $\square$

**這個反例值得手算一次。** 它同時解釋了 3.2 完全背包**故意**用正序的原因——**在那裡，「同一個物品被重複使用」正是我們想要的行為。**

> **一句話總結整個背包章的迴圈方向：
> 每個物品只能用一次 ⇒ 讀上一輪 ⇒ 倒序；
> 每個物品可以用無限次 ⇒ 讀本輪 ⇒ 正序。**

**推論 2.1**：內層迴圈的下界寫成 `c >= w[i]` 即可，**不必額外判斷 `c - w[i] >= 0`** ✔。

**推論 2.2（二維寫法不受影響）**：二維時 `f[i][*]` 與 `f[i-1][*]` 是不同的陣列，**容量正序倒序都對** ✔。**「倒序」是壓縮空間的代價，不是模型本身的要求。**

### 定理 3（「至多」與「恰好」：初值代表什麼）

*命題*：一維陣列的初值 $g[c]$ 應等於「**不選任何物品時，容量 $c$ 的答案**」。

- **「至多 $c$」型**：不選任何物品總是合法（總重 $0 \le c$）⇒ 每個 $g[c] = 0$ ✔。
- **「恰好 $c$」型**：不選任何物品只能達成 $c = 0$；其餘容量**無解** ⇒ $g[0] = 0$、其餘 $g[c] = -\infty$ ✔。
- **計數型**：不選任何物品恰好湊出 0，有 1 種方式 ⇒ $g[0] = 1$、其餘 $0$ ✔。（**計數天然是「恰好」語意**，沒有第二種初值。）

*為什麼「恰好」型不能用 0 初始化*。若 $g[5] = 0$（表示「容量恰好 5 可達、價值 0」），但實際上沒有任何子集和為 5 ⇒ **後續會把這個不存在的狀態當成可用的起點，算出根本湊不出來的答案** ✘。$\square$

**`-INF` 的取值**：用 `INT_MIN` 會在 `g[c-w] + v` 時溢位 ✘。**慣例是 `-0x3f3f3f3f`（約 $-10^9$），加上任何合理的 $v$ 都不會溢位** ✔。判斷無解時用 `g[C] < 0` 而不是 `g[C] == -INF`（因為它可能被加過幾次 $v$）。

**「至多」轉「恰好」的小技巧**：若答案是「至多 $C$」但你寫成了「恰好」，可以最後取 $\max_{c \le C} g[c]$ ✔。**反之則不行**——「至多」的表無法還原「恰好」的資訊。**不確定時寫「恰好」，資訊比較多。**

### 定理 4（494 目標和：歸約與它的可行性條件）

*問題*：給非負整數陣列 `nums`（總和 $S$），每個數前面加 `+` 或 `-`，使結果為 $T$。求方案數。

*歸約*。設取 `+` 的下標集合為 $P$、其和為 $p$，則取 `-` 的和為 $S - p$，於是

$$p - (S - p) = T \;\Longleftrightarrow\; p = \frac{S + T}{2}.$$

**符號分配 $\leftrightarrow$ 子集 $P$ 是雙射**（給定 $P$ 就決定了所有符號，反之亦然）✔ ⇒ **原題 $\equiv$ 「和恰為 $\frac{S+T}{2}$ 的子集個數」，即計數型 0-1 背包。**

**三個可行性條件，缺一就是 WA**：
1. **$S + T$ 必須是偶數**（否則 $p$ 不是整數 ⇒ 答案 0）✔；
2. **$S + T \ge 0$**（$p$ 不能為負 ⇒ 答案 0）✔；
3. **$p \le S$**，即 $T \le S$（等價於條件 2 對 $-T$ 的版本）✔。

**$T$ 可能是負數，記得取絕對值或同時檢查兩端。** **這三條在很多題解裡被寫成一行 `if ((S+T) % 2 || S+T < 0) return 0;`，值得看懂它涵蓋了什麼。**

**為什麼需要 `nums[i] >= 0`**：若有負數，$p$ 的範圍不再是 $[0, S]$，**容量軸得往負方向延伸**（要做下標偏移）⇒ 歸約本身仍對，但實作要改 ✔。**LeetCode 494 保證非負。**

**同型歸約速查**：

| 題目 | 歸約成 |
| --- | --- |
| 416 分割等和子集 | 「和恰為 $S/2$ 的子集是否存在」（$S$ 為奇數直接 false） |
| 1049 最後一塊石頭的重量 II | 「和 $\le S/2$ 的最大子集和 $p$」，答案 $S - 2p$ |
| 494 目標和 | 「和恰為 $(S+T)/2$ 的子集個數」 |
| 474 一和零 | **二維費用**背包（0 的個數、1 的個數各一維） |
| 879 盈利計劃 | **二維費用**（人數上限 + 利潤下限），利潤那維要**夾在下限**（`min(p + profit, minProfit)`） |

**879 的「利潤下限」處理值得單獨記**：容量是「至少」而非「至多」時，**把超過下限的部分全部歸到下限那一格**（`min(...)`），這樣狀態數才有界 ✔。

### 定理 5（可行性型的 `bitset` 加速，以及它為什麼不需要倒序）

*設定*：可行性型背包中 $g$ 是布林陣列。用 `bitset` 表示：**第 $c$ 位為 1 $\iff$ 容量 $c$ 可達。**

*命題*：加入重量為 $w$ 的物品後，新的可達集合為 $g \cup (g \ll w)$。

*證明*。新可達的容量 $c$ 要嘛原本就可達（不選這個物品），要嘛 $c - w$ 原本可達（選它）✔。而 `g << w` 的第 $c$ 位恰為 $g$ 的第 $c-w$ 位 ✔。$\square$

**為什麼不需要倒序**：`f |= f << x` 是**先用舊的 `f` 完整算出 `f << x`，再一次性合併**——它根本不是「就地逐位更新」，**沒有「讀到本輪新值」的機會** ✔。**這正好對照定理 2：倒序是為了在就地逐格更新時避免讀到新值；一次性的向量運算天生免疫。**

**複雜度**：$O(nC/64)$。$n = 200$、$C = 2\times10^4$ ⇒ 約 $6\times10^4$ 次字操作 ✔ **比樸素的 $4\times10^6$ 快兩個數量級。**

**限制**：`bitset` 的大小**必須是編譯期常數** ⇒ 要開足夠大（例如 `bitset<20001>`），不能用變數。**只適用於可行性（布林）型，最大價值型與計數型都不能用。**

### 定理 6（兩個實用的剪枝，以及它們的正確性）

**(a) 容量上界剪枝**：設 $W = \sum w_i$，則實際只需計算 $c \le \min(C, W)$。
*證明*。總重不可能超過 $W$ ⇒ $g[c] = g[\min(c, W)]$ 對 $c > W$ 成立 ✔。$\square$
**在 $C$ 很大而物品總重很小時，這一條能省下大量時間。**

**(b) 後綴剪枝**：處理第 $i$ 個物品時，內層容量只需掃到

$$c \;\ge\; \max\Big(w_i,\;\; C - \sum_{t > i} w_t\Big).$$

*證明*。**只有那些「還有機會被後面的物品填滿到 $C$」的容量才可能對最終答案 $g[C]$ 有貢獻。** 若 $c < C - \sum_{t>i} w_t$，即使後面所有物品全選也達不到 $C$ ⇒ 這個 $c$ 對 $g[C]$ 無用 ✔。$\square$

**注意 (b) 只在「答案只取 $g[C]$」時成立**——**若題目要輸出所有容量的答案（或答案是 $\max_{c\le C} g[c]$），這個剪枝會破壞其他格子的正確性** ✘。**這是一條必須點名前提的優化。**

**(c) 物品維度可以滾掉的前提**：$f(i,\cdot)$ 只依賴 $f(i-1,\cdot)$ ✔。**但一旦題目要求輸出「選了哪些物品」，就必須保留二維表**（見 16 節），或另存 $O(nC)$ 的決策位圖。**$n = C = 10^3$ 時 $O(nC)$ 個 `bool` 是 1 MB，通常可以接受。**

## 時間與空間複雜度

| 型別 | 時間 | 空間 | 備註 |
| --- | --- | --- | --- |
| 標準 0-1 背包 | $O(nC)$ | $O(C)$ | **偽多項式**：與 $C$ 的數值成正比，不是與輸入長度 |
| 二維費用（474、879） | $O(nC_1C_2)$ | $O(C_1C_2)$ | 兩維都要倒序 |
| 可行性 + `bitset`（定理 5） | $O(nC/64)$ | $O(C/64)$ | 快 64 倍 |
| 要輸出方案 | $O(nC)$ | $O(nC)$ | 不能滾動 |

**「偽多項式」這四個字很重要**：0-1 背包是 **NP-hard**，$O(nC)$ 之所以看起來像多項式，是因為 $C$ 用數值而非位元數計量。**$C = 10^9$ 時 $O(nC)$ 完全不可行**——**遇到大容量，要嘛換成「按價值當容量軸」（$O(n\sum v)$），要嘛用 meet-in-the-middle（$O(2^{n/2})$，$n \le 40$ 時可行，見 trees 章）。**

**規模速查**：

| $n$ | $C$ | $nC$ | 判斷 |
| --- | --- | --- | --- |
| $100$ | $10^4$ | $10^6$ | ✔ 輕鬆 |
| $10^3$ | $10^4$ | $10^7$ | ✔ 可以 |
| $10^3$ | $10^6$ | $10^9$ | ✘ 需要 `bitset` 或換模型 |

**空間**：$C = 10^6$ 的 `int` 陣列是 4 MB ✔；二維費用時 $C_1 C_2$ 很快就爆——**474 的 $(m, n) \le (600, 600)$ ⇒ $1.4$ MB ✔，但若兩維都到 $10^4$ 就是 400 MB ✘。**

## 與相似技巧的比較

- **與 3.2 完全背包**：**唯一的差別是內層迴圈方向**（倒序 vs 正序），而那個差別完全由定理 2 解釋。**兩節應該一起讀。**
- **與 3.3 多重背包**：0-1 是「上限 1」、完全是「上限 $\infty$」、多重是「上限 $k_i$」。**多重背包的二進位拆分，就是把它拆成若干個 0-1 物品** ⇒ 直接套本節。
- **與 1.1 定理 2（排列 vs 組合）**：**外層物品內層容量 ⇒ 組合（集合）；外層容量內層物品 ⇒ 排列（序列）。** 背包永遠是前者。**377 之所以不是背包，正因為它要的是後者。**
- **與 9.4 子集狀壓 DP**：$n \le 20$ 且**容量無法用小整數表示**時（例如「每個子集有一個複雜的可行性判斷」），要改用 $2^n$ 的狀壓。**判準：$nC$ 與 $2^n$ 誰小。** $n=20, C=10^4$ ⇒ $2\times10^5$ vs $10^6$ ⇒ 狀壓反而更快。
- **與貪心（分數背包）**：**允許把物品切開時，按 $v_i/w_i$ 由大到小貪心是最優的**（交換論證）；**不能切開時貪心錯**——`w = [3,4,5], v = [3,5,6], C = 8` 貪心按性價比選 $v=6$ 與 $v=3$ 得 9，最優是 $5+6=11$ ✘。**這是「連續鬆弛可解、整數版 NP-hard」的經典對照。**
- **與二分答案**：「最小化最大值」型的容量問題（5.3、410）有時可以二分 + 貪心檢查，比背包更快。**判準：可行性對容量單調嗎？** 單調就能二分。

## 本節重點速查

- **模型**：$n$ 個物品各用**至多一次**，容量限制下求最優／可行／計數。**「順序無關、只在乎取捨」就是背包味。**
- **定理 1（選或不選）**：$f(i,c) = \max(f(i-1,c),\, f(i-1,c-w_i)+v_i)$。前提 $w_i \ge 0$（負重量讓依賴成環）。
- **定理 2（倒序）**：一維就地更新要讀「**上一輪**」的 $g[c-w]$，而它在左側 ⇒ **倒序掃描**。正序的反例：單一物品 $w=2,v=3,C=4$ 會算出 6（用了兩次）。**一句話：只能用一次 ⇒ 倒序；可以無限用 ⇒ 正序。** 二維寫法不受影響。
- **定理 3（初值）**：初值 = 「不選任何物品時的答案」。**至多 ⇒ 全 0；恰好 ⇒ `g[0]=0` 其餘 `-INF`；計數 ⇒ `g[0]=1` 其餘 0。** `-INF` 用 `-0x3f3f3f3f` 防溢位，判無解用 `< 0`。
- **定理 4（494 歸約）**：$p = (S+T)/2$，**三個可行性條件**：$S+T$ 為偶數、$S+T\ge0$、$T \le S$。**416 / 1049 / 474 / 879 的歸約表值得背下來**；879 的「至少」型要把超額夾到下限。
- **定理 5（`bitset`）**：`f |= f << x`，$O(nC/64)$。**不需要倒序，因為它是一次性向量運算而非就地逐格更新。** 只適用布林型，大小須為編譯期常數。
- **定理 6（剪枝）**：容量上界取 $\min(C, \sum w)$；後綴剪枝 $c \ge \max(w_i,\, C - \sum_{t>i}w_t)$，**但只在「答案只取 $g[C]$」時成立。** 要輸出方案就不能滾動。
- **偽多項式**：$O(nC)$ 與 $C$ 的**數值**成正比。$C = 10^9$ 時不可行 ⇒ 換「價值當容量軸」或 meet-in-the-middle。**不能切開的背包沒有正確的貪心解**（反例 `w=[3,4,5], v=[3,5,6], C=8`）。
