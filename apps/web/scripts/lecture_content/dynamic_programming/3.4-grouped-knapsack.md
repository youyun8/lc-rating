## 這個技術解決什麼問題

分組背包處理的是這種約束：

> **物品被分成若干組，每組最多（或恰好）只能選一個。**

**它與前三節的差別不在轉移式，而在「誰是一次決策」。** 0-1 背包的每個物品各自是一次「選或不選」的決策；分組背包把**一整組**綁成**一次多選一**的決策：

| 節 | 一次決策的形狀 | 選項數 |
| --- | --- | --- |
| 3.1 0-1 | 選 / 不選 | 2 |
| 3.2 完全 | 用 $0,1,2,\dots$ 個 | $\infty$（可壓成 2 條） |
| 3.3 多重 | 用 $0..k_i$ 個 | $k_i + 1$（有等差結構） |
| **3.4 分組** | **從 $G_i$ 裡挑一個，或都不挑** | $|G_i| + 1$（**任意，無結構**） |

**分組背包是這個家族裡最一般的形式**——3.1 是「每組兩個選項」、3.3 是「每組選項的重量與價值成等差」的特例。**代價是它沒有任何可利用的結構，所以只能老實枚舉組內選項；好處是它適用面極廣。**

**辨識訊號**：
- 物品天然成批，**每批只貢獻一次選擇**——1155 的「每顆骰子擲出一個點數」、1981 的「每列選一個數」、2218 的「從這一堆拿 $j$ 個」；
- 或者：**同一組的選項彼此互斥**（選了 A 就不能選 B）。

**最容易被錯過的訊號是第三種**：**原問題看起來不是背包，但「把某個維度切成組」之後就是**（定理 4 的 2218 就是這樣）。

## 狀態／資料結構定義

$$g(c) = \text{只考慮已處理過的組、容量恰好／至多為 } c \text{ 時的最優值}$$

**三層迴圈的順序是本節唯一真正要記的東西**（定理 2）：

```text
for 每一組 i:                       ← 最外層
    for c = C down to 0:            ← 中層，倒序
        for 組內每個選項 (w, v):     ← 最內層
            g[c] = max(g[c], g[c - w] + v)
```

**組內選項一定要在容量迴圈的「裡面」。** 這樣 `g[c - w]` 讀到的永遠是「本組尚未做過任何選擇」的值 ⇒ 每組至多被用一次 ✔。

**「至多選一個」與「恰好選一個」的差別只在初始化**（沿用 3.1 定理 3）：

| 語意 | 初始化 | 判斷無解 |
| --- | --- | --- |
| 每組**至多**選一個 | `g[c] = 0` | 不會無解 |
| 每組**恰好**選一個 | `g[0] = 0`，其餘 `-0x3f3f3f3f` | `g[C] < 0` |

**「恰好選一個」時不可以寫 `g[c] = max(g[c], ...)`**——那個 `g[c]` 是「本組不選」的值，必須被排除。**正確寫法是用一個新陣列 `h`**：

```cpp
vector<long long> h(C + 1, NEG);  // 每組重新開一張表
for (int c = 0; c <= C; c++)
    for (auto [w, v] : group[i])
        if (c >= w && g[c - w] > NEG) h[c] = max(h[c], g[c - w] + v);
g = move(h);  // 這時就不需要倒序了
```

**注意這個寫法用的是正序**——因為 `h` 與 `g` 是兩張表，不存在就地覆寫問題（2.1 定理 2）✔。

## 不變量或正確性證明

### 定理 1（分組背包轉移的正確性）

*命題*：設 $g_i(c)$ 為「只用前 $i$ 組、容量 $\le c$」的最優值，則

$$g_i(c) = \max\Big(\; \underbrace{g_{i-1}(c)}_{\text{本組不選}},\;\; \max_{(w,v)\in G_i,\; w \le c} \big( g_{i-1}(c - w) + v \big) \Big).$$

*證明*。按「第 $i$ 組選了哪一個」劃分方案集合：**不漏**（要嘛不選、要嘛選了某個唯一的 $(w,v)$）、**不重**（兩個分支互斥，且組內各選項互異）✔。每個分支內用剪貼論證得等號 ✔。$\square$

**這裡的「不重」依賴一個前提：同一組內不會選兩個。** 這正是分組背包的定義，也正是定理 2 要保護的東西。

**與 3.3 定理 4 的對照值得注意**：多重背包的二進位拆分只給「覆蓋」不給「劃分」，所以計數型會出錯；**分組背包的劃分是嚴格的（每組的選擇唯一）⇒ 計數型可以直接套同一個轉移式，把 `max` 換成 `+` 就好** ✔（1155 就是計數型）。**這是分組背包比多重背包「乾淨」的地方。**

### 定理 2（**三層迴圈的順序**：選項必須在最內層）

*命題*：把組內選項迴圈放在容量迴圈**外面**（即 `for 選項 { for c }`），會允許同一組被選多次，答案錯誤。

*證明（反例）*。一組兩個選項 $(w,v) = (1, 1)$ 與 $(2, 3)$，容量 $C = 4$，正確答案是 $3$（只能選一個）。

若寫成

```cpp
for (auto [w, v] : group[i])  // ✘ 選項在外
    for (int c = C; c >= w; c--) g[c] = max(g[c], g[c - w] + v);
```

處理選項 $(1,1)$ 後 $g = [0,1,1,1,1]$；再處理 $(2,3)$ 時 $g[4] = \max(1,\; g[2] + 3) = \max(1, 1+3) = 4$ ✘——**這個 4 = 「選了 $(1,1)$ 又選了 $(2,3)$」，同一組用了兩次。**

正確寫法把選項放最內層：

```cpp
for (int c = C; c >= 0; c--)  // ✔ 容量在外、倒序
    for (auto [w, v] : group[i])
        if (c >= w) g[c] = max(g[c], g[c - w] + v);
```

此時 $g[4] = \max(0,\; g[3] + 1,\; g[2] + 3)$，而 $g[3], g[2]$ 都還是**本組處理前**的值 $0$ ⇒ $g[4] = 3$ ✔。$\square$

**這條定理是 3.1 定理 2「倒序」的延伸，理由完全相同**：

> **倒序保證 `g[c - w]` 尚未在本輪被寫過 ⇒ 讀到的是「上一組結束時」的值。**
> **選項放最內層則保證「本輪」的粒度是「一整組」而不是「一個選項」。**

**兩個條件缺一不可。** 少了倒序 ⇒ 同一個選項被用多次（退化成完全背包）；少了「選項在內層」⇒ 同一組的不同選項被同時選中 ✘。

**驗證方法**：故意造一組「兩個選項加起來剛好塞得下」的資料跑一遍。**這是分組背包唯一需要專門測試的東西。**

### 定理 3（1155 擲骰子：計數型分組背包 + 滑動窗口和）

*設定*：$n$ 顆骰子，每顆有 $k$ 面（點數 $1..k$），求點數和恰為 $\mathit{target}$ 的方案數。

*歸約*：**每顆骰子是一組，組內 $k$ 個選項「重量 $d$、方案數 $1$」，且每組恰好選一個** ⇒ 轉移

$$f_i(t) = \sum_{d=1}^{k} f_{i-1}(t - d).$$

*正確性*：由定理 1（計數版）——按「第 $i$ 顆擲出幾點」劃分，**不重不漏**且**骰子可區分**（第 $i$ 顆就是第 $i$ 顆）✔。

**「骰子可區分」這個前提必須點名**：若題目改問「多重集合有幾種」（例如兩顆骰子擲出 $\{1,3\}$ 與 $\{3,1\}$ 算同一種），上面的劃分就重複計數了 ✘，得改成「按點數分組、每種點數用幾顆」的多重背包（3.3）。**同一個場景，問法一變模型就換——這是背包題最常見的誤讀。**

*優化*：轉移是**一段連續區間的和** $\sum_{t' = t-k}^{t-1} f_{i-1}(t')$ ⇒ 用前綴和或滑動窗口和 $O(1)$ 完成 ⇒ 總複雜度從 $O(nk\cdot\mathit{target})$ 降到 $O(n\cdot\mathit{target})$ ✔。

**這與 3.3 定理 5 是同一招**，但這裡簡單得多：**分組背包的兩層之間有獨立的新舊陣列，不需要 `old` 快照，也不必分同餘類**（因為區間是 $[t-k, t-1]$ 這種**連續**區間，不是 $\{t-w, t-2w, \dots\}$ 這種**等差**區間）✔。

**邊界**：$\mathit{target} < n$ 或 $\mathit{target} > nk$ 時答案為 0，**可以先判掉**；不判也不會錯，但陣列開太小會越界。

### 定理 4（2218 從棧頂取硬幣：**為什麼它是分組背包**）

*設定*：$m$ 個硬幣堆，**每堆只能從頂部連續取**，總共取 $k$ 枚，最大化面值和。

*命題*：這等價於分組背包——第 $i$ 組的選項是 $\{(j,\; P_i(j)) : 0 \le j \le |\mathit{pile}_i|\}$，其中 $P_i(j)$ 是第 $i$ 堆前 $j$ 枚的前綴和。

*證明*。歸約要驗證兩件事（沿用 1.2 定理 3 的兩步格式）：

- **(a) 每個合法方案對應一個組合選擇。** 一個方案在第 $i$ 堆取了若干枚；**由「只能從頂部取」的規則，這些硬幣必然是該堆的一個前綴** ⇒ 完全由「取了幾枚 $j$」決定 ⇒ 對應到選項 $(j, P_i(j))$ ✔。
- **(b) 每個組合選擇對應一個合法方案，且價值相同。** 選了 $(j_1,\dots,j_m)$ 且 $\sum j_i = k$，就依序從每堆取前 $j_i$ 枚，合法 ✔，總價值 $\sum P_i(j_i)$ ✔。

雙射且保值 ⇒ 兩問題的最優值相等 ✔。$\square$

**這條證明真正做的事，是說明「$j$ 一旦決定，取哪些硬幣就沒有自由度了」。** 這正是把一個看起來像「選硬幣」的問題，壓縮成「每堆選一個數字 $j$」的理由。

**判準（可以帶到別的題）**：

> **當某個子結構的「規模」一旦固定，其「內容」也隨之唯一確定（或其最優內容可 $O(1)$ 查得），這個子結構就可以塌縮成分組背包的一組選項。**

**若題目改成「可以從堆的任意位置取」，前提就崩了**——取 $j$ 枚的最大值變成「取該堆最大的 $j$ 枚」，雖然仍可預處理（排序後前綴和），但**證明的 (a) 步要重寫**；**若再加上「取走後下面的會露出來」之類的耦合，就完全不是分組背包了** ✘。

*複雜度*：$O(k \sum_i |\mathit{pile}_i|) = O(kn)$，其中 $n$ 是硬幣總數 ✔。

**注意「恰好取 $k$ 枚」**：若所有堆的總數 $> k$，用「至多」語意也對（多取只會更好嗎？——**不一定，面值可能是 0 或負，題目保證非負時才成立**）。**保險做法是直接用「恰好」語意 + `-INF` 初始化**（見「狀態／資料結構定義」）。

### 定理 5（1981 最小化 $|{\sum} - \mathit{target}|$：**為什麼要記錄整個可達集合**）

*設定*：$m \times n$ 矩陣，每列選一個數，最小化 $|\text{和} - \mathit{target}|$。

*命題*：不能只維護「最大和」或「最接近 target 的和」，**必須維護所有可達和的集合**。

*證明*。目標函數 $\phi(s) = |s - \mathit{target}|$ **不是 $s$ 的單調函數** ⇒ 前 $i$ 列的「最優 $s$」不保證能延伸成整體最優。

具體反例：$\mathit{target} = 10$，第一列可選 $\{9, 5\}$，第二列可選 $\{5\}$。只看前一列，$s=9$（誤差 1）優於 $s=5$（誤差 5）；但加上第二列後 $9+5=14$（誤差 4）反而劣於 $5+5=10$（誤差 0）✘。

⇒ **無後效性不成立於「以誤差為狀態值」的定義**（1.1 定理 4）。**修法是把狀態換成布林可達性**：

$$\mathit{reach}_i(s) = \text{[前 } i \text{ 列能否湊出和 } s\text{]},$$

最後掃一遍所有 $s$ 取 $\min_s |s - \mathit{target}|$ ✔。$\square$

**這是一個很值得記住的模式**：

> **當目標函數對「狀態值」非單調（絕對值、平方差、取模後比較）時，不要在 DP 過程中做最優化——改成記錄可達集合，最後再一次評估。**

**代價是狀態數從 $O(1)$ 變成 $O(S)$，所以必須先確認 $S$ 有界。** 這裡 $s \le 70 \times 70 = 4900$ ⇒ 完全可行 ✔。

**兩個實作細節**：
- **同一列的重複數字要去重**（`sort` + `unique`），否則白跑；
- 用 `bitset<4901>` 可以把整列的轉移寫成 `nxt |= cur << v`，常數快 64 倍 ✔——**這與 3.1 定理 5 的 `bitset` 是同一招，而且同樣不需要倒序**（`nxt` 與 `cur` 是兩個物件）。

### 定理 6（複雜度只與「總選項數」有關，與組數無關）

*命題*：三層迴圈的總運算量是 $O\!\big(C \cdot \sum_i |G_i|\big)$。

*證明*。外兩層對每一組跑 $O(C)$ 次，內層跑 $|G_i|$ 次 ⇒ 第 $i$ 組貢獻 $O(C|G_i|)$，求和即得 ✔。$\square$

**推論 6.1**：**分組方式若有自由度，應該讓「總選項數」最小，而不是讓「組數」最小。** 把一組拆成兩組（若語意允許）不會增加複雜度；但把兩組合併成一組會讓選項數變成乘積 ⇒ **合併是昂貴的、拆分是免費的** ✔。

**這個推論在建模時很實用**：遇到「每個單位有多個屬性要一起選」時，**先問能不能把屬性拆成獨立的組**——能拆就拆，選項數從乘積降成和 ✔。

## C++17 模板

```cpp
// ---- 1. 分組背包（每組至多選一個，最大化）----
// group[i] = vector<pair<int,int>>{ {weight, value}, ... }
long long groupedKnapsack(const vector<vector<pair<int, int>>>& group, int C) {
    vector<long long> g(C + 1, 0);
    for (const auto& G : group)
        for (int c = C; c >= 0; c--)  // 倒序（定理 2）
            for (auto [w, v] : G)     // 選項在最內層（定理 2）
                if (c >= w) g[c] = max(g[c], g[c - w] + v);
    return g[C];
}

// ---- 2. 分組背包（每組恰好選一個）：雙陣列寫法 ----
const long long NEG = -0x3f3f3f3f3f3f3f3fLL;
long long groupedExactlyOne(const vector<vector<pair<int, int>>>& group,
                            int C) {
    vector<long long> g(C + 1, NEG);
    g[0] = 0;
    for (const auto& G : group) {
        vector<long long> h(C + 1, NEG);  // 每組換一張新表
        for (int c = 0; c <= C; c++)      // 兩張表 ⇒ 正序也安全
            for (auto [w, v] : G)
                if (c >= w && g[c - w] != NEG) h[c] = max(h[c], g[c - w] + v);
        g = move(h);
    }
    return g[C] < 0 ? -1 : g[C];  // 負值代表無解
}

// ---- 3. LC 1155 擲骰子：計數型 + 滑動窗口和（定理 3）----
int numRollsToTarget(int n, int k, int target) {
    const int MOD = 1'000'000'007;
    if (target < n || target > 1LL * n * k) return 0;
    vector<int> f(target + 1, 0);
    f[0] = 1;
    for (int i = 1; i <= n; i++) {
        vector<int> pre(target + 2, 0);  // pre[t+1] = f[0..t] 之和
        for (int t = 0; t <= target; t++) pre[t + 1] = (pre[t] + f[t]) % MOD;
        vector<int> nxt(target + 1, 0);
        for (int t = i; t <= target; t++) {
            int lo = max(0, t - k), hi = t - 1;  // 區間 [t-k, t-1]
            if (lo > hi) continue;
            nxt[t] = (pre[hi + 1] - pre[lo] + MOD) % MOD;  // 減法補 MOD
        }
        f = move(nxt);
    }
    return f[target];
}

// ---- 4. LC 2218 從棧頂取硬幣：組 = 一堆，選項 = 取幾枚（定理 4）----
int maxValueOfCoins(vector<vector<int>>& piles, int k) {
    vector<int> g(k + 1, 0);
    int taken = 0;  // 已處理堆的硬幣總數，用來剪枝
    for (const auto& p : piles) {
        int m = (int)p.size();
        vector<int> pre(m + 1, 0);
        for (int j = 0; j < m; j++) pre[j + 1] = pre[j] + p[j];
        taken = min(k, taken + m);
        for (int c = taken; c >= 0; c--)  // 倒序，且只掃到 taken
            for (int j = 1; j <= min(m, c);
                 j++)  // j = 0 就是「不選」，已在 g[c] 裡
                g[c] = max(g[c], g[c - j] + pre[j]);
    }
    return g[k];
}

// ---- 5. LC 1981 每列選一個、最小化 |sum - target|（定理 5）----
int minimizeTheDifference(vector<vector<int>>& mat, int target) {
    const int LIM = 4901;  // 70 * 70 的上界
    bitset<4901> cur;
    cur[0] = 1;
    for (auto row : mat) {
        sort(row.begin(), row.end());
        row.erase(unique(row.begin(), row.end()), row.end());  // 去重（定理 5）
        bitset<4901> nxt;
        for (int v : row) nxt |= cur << v;  // 兩個物件 ⇒ 不需倒序
        cur = nxt;
    }
    int best = INT_MAX;
    for (int s = 0; s < LIM; s++)
        if (cur[s]) best = min(best, abs(s - target));
    return best;
}
```

## 時間與空間複雜度

**設 $C$ 為容量上限、$T = \sum_i |G_i|$ 為所有組的選項總數。**

| 版本 | 時間 | 空間 |
| --- | --- | --- |
| 通用分組背包 | $O(CT)$ | $O(C)$ |
| 恰好選一個（雙陣列） | $O(CT)$ | $O(C)$（兩張表） |
| 1155 樸素 / 前綴和 | $O(nk\cdot\mathit{target})$ / $O(n\cdot\mathit{target})$ | $O(\mathit{target})$ |
| 2218 | $O(kn)$（$n$ = 硬幣總數） | $O(k)$ |
| 1981 `bool` / `bitset` | $O(mnS)$ / $O(mnS/64)$ | $O(S)$ |

**注意複雜度寫的是 $T$ 不是「組數 × 最大組大小」**（定理 6）：**組的大小很不均勻時，前者可能小上一個數量級。**

**2218 的剪枝值得一提**：`for (int c = taken; c >= 0; c--)` 只掃到「目前為止能取到的最大枚數」，而不是每次都掃到 $k$。**最壞情況不變，但在堆很多、每堆很小時能省下大量無效狀態** ✔。

**溢位**：價值和用 `long long`；計數型每步取模，**前綴和相減記得 `+ MOD`**。

**空間**：一維 $O(C)$。**「恰好選一個」的雙陣列寫法需要兩份 ⇒ $2C$，仍是 $O(C)$** ✔。若 $C$ 極大而選項稀疏，可改用 `unordered_map` 存可達狀態。

## 常見錯誤與邊界條件

- **✘ 把組內選項迴圈放到容量迴圈外面。** 這是本節第一大錯，會讓同一組選中多個（定理 2 有完整反例）。**正確順序：組 → 容量（倒序）→ 選項。**
- **✘ 忘記倒序。** 少了倒序，同一個選項會被重複使用 ⇒ 退化成完全背包。**唯一的例外是雙陣列寫法**（新舊表分離時正序才安全，2.1 定理 2）。
- **✘ 「恰好選一個」卻用 `g[c] = max(g[c], ...)` 就地更新。** 那個 `g[c]` 代表「本組不選」，在「恰好」語意下是非法狀態 ✘。**用雙陣列 + `-INF` 初始化。**
- **✘ `-INF` 相加溢位。** `NEG + v` 若 `NEG` 取 `LLONG_MIN` 會 UB。**用 `-0x3f3f3f3f3f3f3f3f`，並在相加前檢查 `!= NEG`。**
- **✘ 空組沒處理。** 「恰好選一個」遇到 $|G_i| = 0$ 時整題無解，**新表會全是 `-INF`**——這是正確行為，但要確認最後的無解判斷（`g[C] < 0`）真的抓得到，別讓 `-INF` 被誤當成有效答案。
- **✘ 計數型忘記「元素是否可區分」。** 1155 的骰子**可區分**，所以每顆一組是對的；若題目數的是多重集合，模型要換成 3.3 的多重背包（定理 3 的前提說明）。
- **✘ 目標函數非單調卻在 DP 中途取最優。** 1981 的 $|s-\mathit{target}|$ 就是（定理 5 有反例）。**改成記錄可達集合，最後一次評估。**
- **✘ 1981 忘記同列去重。** 不會答錯，但會讓 `bitset` 的移位次數翻好幾倍。
- **✘ 2218 誤以為可以貪心取「當前最大的硬幣」。** 反例：兩堆 `[[1,100],[2]]`，$k=2$。貪心先拿 2（堆頂最大）再拿 1，得 3；正解是拿第一堆前兩枚得 101 ✘。**「只能從頂部取」讓局部最大值毫無意義。**
- **邊界**：$C = 0$（答案是 0 或 `-INF`）、所有組都空、$\mathit{target}$ 超出可達範圍（1155 先判掉）、單一組（退化成「挑最大值」）。

## 與相似技巧的比較

- **與 3.1 / 3.2 / 3.3**：分組背包是這一家族的**最一般形式**——0-1 是「每組兩個選項」、多重是「每組選項成等差」的特例。**因此當你想不出某題屬於哪種背包時，先套分組背包**：它一定對，只是可能不夠快 ✔。反過來，**看到分組背包的組內選項有規律（等差、單調），就該回頭找 3.2 / 3.3 的優化。**
- **與 3.3 的關鍵差異（計數型）**：多重背包的二進位拆分只給覆蓋、不給劃分 ⇒ 計數會錯（3.3 定理 4）；**分組背包的劃分天生嚴格 ⇒ `max` 換成 `+` 就是計數版，不需要任何額外處理** ✔。
- **與 3.5 樹形背包**：樹形背包是「組的結構由樹決定」的分組背包——**每個節點的子樹分配就是一組選項**，只是選項本身要遞迴算出來。**先把 3.4 的三層迴圈寫熟，3.5 的合併迴圈才不會寫錯。**
- **與 4.1 LCS / 5. 劃分型**：劃分型 DP（第 5 章）也可以看成分組背包——「第 $j$ 段選多長」就是一組選項。**兩者的複雜度分析（定理 6）通用**：總運算量 = 狀態數 × 平均選項數。
- **與 11.1 字首和優化**：定理 3 的滑動窗口和是最單純的形式。**判準：組內選項的重量構成連續整數區間 ⇒ 前綴和；構成等差數列 ⇒ 同餘類前綴和（3.3 定理 5）；毫無規律 ⇒ 只能老實枚舉。**
- **與貪心**：分組背包沒有貪心解（2218 的反例見上）。**「每組挑性價比最高的」在有容量耦合時一律失敗**——這與 3.1 對分數背包的說明是同一件事。

## 本節重點速查

- **模型**：物品分組，**每組至多／恰好選一個**。是 0-1、多重背包的共同推廣，**想不出用哪種背包時的安全選擇。**
- **定理 2（第一要務）**：**三層迴圈順序 = 組 → 容量（倒序）→ 組內選項。** 選項放外層 ⇒ 同組選中多個 ✘（反例：$(1,1)$ 與 $(2,3)$、$C=4$，錯得 4、正解 3）。**倒序保證讀到上一組的值；選項在內層保證「一輪」的粒度是一整組。**
- **兩種語意**：「至多」⇒ 全 0 初始化、就地倒序；**「恰好」⇒ `g[0]=0` 其餘 `-INF`、雙陣列、正序**（兩張表就不怕覆寫）。
- **定理 1 + 與 3.3 對照**：分組背包的劃分**天生嚴格** ⇒ **計數型把 `max` 換成 `+` 即可**，不像多重背包的二進位拆分會重複計數 ✔。
- **定理 3（1155）**：每顆骰子一組、恰選一個；轉移是**連續區間和** ⇒ 前綴和降到 $O(n\cdot\mathit{target})$。**前提：骰子可區分**——問多重集合就要改用 3.3。
- **定理 4（2218）**：**「規模固定 ⇒ 內容唯一」就能塌縮成一組選項。** 只能從頂部取 ⇒ 取 $j$ 枚必是前綴 ⇒ 選項 $(j, \mathit{pre}[j])$。**這個判準可以帶到很多不像背包的題目。**
- **定理 5（1981）**：**目標函數對狀態值非單調（絕對值、平方差）⇒ 不要在 DP 中途取最優**，改記錄可達集合、最後一次評估。反例：$\mathit{target}=10$、第一列 $\{9,5\}$、第二列 $\{5\}$。`bitset` + 同列去重。
- **定理 6**：複雜度 $O(C\sum_i|G_i|)$，**只看總選項數，與組數無關** ⇒ **拆組免費、併組昂貴**（選項數從和變成積）。
