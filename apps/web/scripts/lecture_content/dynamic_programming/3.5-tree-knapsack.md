## 這個技術解決什麼問題

樹形背包處理「**選擇之間有樹狀依賴**」的資源分配：

> **要選子節點，必須先選它的父節點；總花費不超過預算 $C$。**

**它是 3.4 分組背包在樹上的遞迴版本**——**每棵子樹就是一組，組內的選項是「分配多少預算給這棵子樹」，而每個選項的價值本身又是一個子問題。**

**這一節之所以標「選做」，不是因為它不重要，而是因為它把前四節的東西全部疊在一起**：

| 來自 | 用在哪 |
| --- | --- |
| 3.4 定理 2（三層迴圈順序） | 合併子樹時的迴圈順序，一字不差 |
| 2.1 定理 2（就地更新方向） | 合併時為什麼要倒序／要開 `tmp` |
| trees 章的後序歸納 | 子樹先算完，父節點才能合併 |
| **本節定理 2** | **「$O(n^2)$ 而不是 $O(nC^2)$」的複雜度證明** |

**定理 2 是本節唯一全新的東西，也是最有價值的一段**：它解釋了為什麼一段看起來是三重迴圈的程式碼實際上只跑 $O(n^2)$ 次。**不知道這件事的人，會誤判複雜度而不敢寫這個做法。**

**辨識訊號**：
- **先修關係構成一棵樹或森林**（每個項目至多一個前置項目）；
- 樹 + 一條容量／預算／人數的軸；
- 需要**後序 DFS 把各子樹的分配方案合併**起來。

**反面訊號**：若依賴關係是一般的 DAG（一個項目有多個前置），**這不是樹形背包，而且一般情況是 NP-hard 的**（定理 4 的說明）。

## 狀態／資料結構定義

**兩種狀態定義，對應兩種語意，不可混用**：

| 語意 | 狀態定義 | 合併時的初值 |
| --- | --- | --- |
| **無依賴**（子樹裡選誰都行） | $f(u, j)$ = 以 $u$ 為根的子樹、花費 $\le j$ 的最優值 | $f(u, \cdot) = 0$ |
| **有依賴**（選子必選父） | $f(u, j)$ = **在「$u$ 必被選」的前提下**，子樹花費 $\le j$ 的最優值 | $f(u, j) = v_u$ 對 $j \ge w_u$，否則 $-\infty$ |

**「有依賴」那一列的粗體是關鍵**（定理 4）：**把「必選 $u$」寫進狀態定義，依賴約束就在合併時自動被滿足，不需要任何額外檢查。**

**合併的形狀（這就是 3.4 的三層迴圈）**：

```text
dfs(u):
    f[u] ← 初值（見上表）
    sz[u] ← w_u  或  1
    for 每個子節點 v:                     ← 外層：一棵子樹 = 一組
        dfs(v)
        for j = min(C, sz[u] + sz[v]) down to 0:   ← 中層：倒序
            for k = 0 .. min(j, sz[v]):            ← 內層：分給 v 的量
                f[u][j] = max(f[u][j], f[u][j-k] + f[v][k])
        sz[u] += sz[v]
```

**中層與內層的上界寫成 `sz` 而不是 `C`，是定理 2 成立的前提**——**寫成 `C` 程式依然正確，但複雜度會從 $O(n^2)$ 退化成 $O(nC^2)$** ✘。

**若題目還有「父節點的選擇會影響子節點代價」這類耦合**（3562 的半價），就多開一維 $f(u, j, b)$，$b$ 表示父節點的狀態（定理 5）。

## 不變量或正確性證明

### 定理 1（子樹合併的正確性 = 分組背包）

*命題*：設 $u$ 有子節點 $v_1, \dots, v_m$，各子樹互不相交，則

$$f(u, j) = \max_{\substack{k_1 + \cdots + k_m \le j - w_u \\ k_t \ge 0}} \Big( v_u + \sum_{t=1}^{m} f(v_t, k_t) \Big),$$

且這個 $m$ 維的最大化可以用 $m$ 輪分組背包逐一合併完成。

*證明*。分兩步。

- **(a) 分解正確。** 任一個「以 $u$ 為根的合法選法」把被選節點分成 $\{u\}$ 與 $m$ 個子樹的部分。**因為樹的不同子樹頂點集互不相交**（這是樹的定義給的），這 $m$ 部分之間**沒有共享的節點、沒有共享的預算以外的耦合** ⇒ 各部分的最優解可以獨立取得 ⇒ 剪貼論證成立 ✔。
- **(b) 逐一合併正確。** 對 $m$ 做歸納。合併第 $t$ 棵子樹時，狀態 $f(u, \cdot)$ 的語意是「已併入前 $t-1$ 棵」；轉移「把 $k$ 分給 $v_t$」正是 3.4 定理 1 的分組背包轉移，**組 = 子樹 $v_t$，選項 = $\{(k,\, f(v_t,k)) : 0 \le k \le \mathit{sz}(v_t)\}$** ⇒ 由 3.4 定理 1 得正確 ✔。$\square$

**這條證明真正依賴的前提只有一個：不同子樹之間除了共用預算以外互不影響。** 值得把它反過來記：

> **若題目出現「子樹 A 選了某物，子樹 B 的代價就變了」這種跨子樹耦合，樹形背包立刻失效**——因為 (a) 的獨立性沒了 ✘。

**這種題通常要靠「把耦合量壓進狀態」來救**（定理 5 就是最輕微的一種：耦合只來自父節點，且只有 1 bit）。

### 定理 2（**$O(n^2)$ 複雜度**：每對節點只在它們的 LCA 處被計算一次）

*命題*：若合併時的迴圈上界寫成 $j \le \min(C,\ \mathit{sz}(u) + \mathit{sz}(v))$、$k \le \min(j,\ \mathit{sz}(v))$，則整棵樹的合併總運算量為 $O(n^2)$（$n$ 為節點數），**與 $C$ 無關**。

*證明*。忽略 $\min(C, \cdot)$（它只會讓次數更少），合併子樹 $v$ 到 $u$ 時，內外兩層的迴圈次數是

$$\big(\text{已併入的大小}\big) \times \big(\mathit{sz}(v)\big).$$

**把這個乘積解讀成「配對數」**：它恰好等於「$u$ 已併入的節點」與「$v$ 子樹的節點」之間的**節點對數目**。

現在考慮任意一對節點 $(x, y)$，$x \ne y$。它在什麼時候被計入？只有在「$x$ 已併入 $u$、$y$ 屬於正被合併的子樹」時——**而這個 $u$ 恰好就是 $\mathrm{LCA}(x, y)$，且只發生一次**（$y$ 所在的那棵子樹只會被合併一次）✔。

所以總運算量 $= \#\{(x,y) : x < y\} = \binom{n}{2} = O(n^2)$ ✔。$\square$

**這條定理的兩個推論值得單獨記住**：

- **推論 2.1**：**迴圈上界必須用子樹大小，不能用 $C$。** 寫成 `for (j = C; j >= 0; j--) for (k = 0; k <= j; k++)` 程式仍然正確，但複雜度變成 $O(nC^2)$——**這是同一份程式碼快與慢差好幾個數量級的唯一原因** ✔。
- **推論 2.2**：**$C$ 很大時複雜度是 $O(n^2)$；$C$ 很小時是 $O(nC)$。** 精確的上界是 $O(n\min(n, C))$，因為 $\min$ 同時卡住兩邊。

**這個「配對計數」的論證方式本身比結論更有用**——它是分析所有「樹上合併型 DP」的標準工具，之後 12 章樹形 DP 還會再用到。**看到「合併時迴圈次數 = 兩邊大小相乘」，就直接套 LCA 配對論證。**

### 定理 3（合併時為什麼要倒序／開臨時陣列）

*命題*：合併子樹 $v$ 時，若 $j$ 正序遞增地就地更新 `f[u][j] = max(f[u][j], f[u][j-k] + f[v][k])`，會得到「同一棵子樹 $v$ 被分配多次」的錯誤答案。

*證明*。這是 3.4 定理 2 的直接翻譯：**組 = 子樹 $v$，若 `f[u][j-k]` 已在本輪被寫過，它裡面就已經含有一次對 $v$ 的分配** ⇒ 再加上 `f[v][k]` 等於把 $v$ 用了兩次 ✘。**倒序保證 `f[u][j-k]`（$k \ge 1$ 時下標更小）尚未在本輪被寫過** ✔。$\square$

**$k = 0$ 這一項是安全的**（`f[u][j] = max(f[u][j], f[u][j] + f[v][0])`），但**前提是 $f(v, 0)$ 必須代表「不選 $v$ 子樹的任何東西」且值為 0**。在「有依賴」的定義下 $f(v, 0)$ 可能是 $-\infty$（因為 $v$ 必選卻沒預算）——**這時 $k=0$ 分支要另外處理成「整棵 $v$ 都不選」**，見「常見錯誤」。

**另一種等價寫法是開臨時陣列**：

```cpp
auto tmp = f[u];  // 快照：本輪之前的值
for (int j = 0; j <= lim; j++)
    for (int k = 0; k <= min(j, szv); k++)
        f[u][j] = max(f[u][j], tmp[j - k] + f[v][k]);
```

**兩張表分離之後正序就安全了**（2.1 定理 2）。**代價是每次合併多一次 $O(C)$ 的複製——通常可以忽略，而且它比倒序更不容易寫錯，初學建議用這個。**

### 定理 4（有依賴的背包：把「必選 $u$」寫進狀態）

*設定*：每個項目 $i$ 有至多一個前置項目 $p_i$；選 $i$ 必須先選 $p_i$。依賴關係構成森林。

*命題*：定義 $f(u, j)$ = 「**$u$ 必被選**，$u$ 的子樹總花費 $\le j$」的最優值，則定理 1 的合併式在**不加任何額外檢查**的情況下只會產生合法方案。

*證明*。對子樹大小做歸納。

- **基底**：葉節點 $u$，$f(u,j) = v_u$（$j \ge w_u$）／$-\infty$（否則）。「$u$ 被選」成立，無其他約束 ✔。
- **歸納步**：合併時對子樹 $v$ 分配 $k$。若 $k \ge w_v$ 且 $f(v,k) > -\infty$，由歸納假設該方案中 $v$ 被選，且其內部所有依賴已滿足；**而 $v$ 的唯一外部依賴就是 $u$，$u$ 由 $f(u,\cdot)$ 的定義保證被選** ✔。若 $k$ 小到 $f(v,k) = -\infty$，該分支不會成為最大值（前提：$-\infty$ 用的是不會被加法救回來的哨兵）✔。$\square$

**這條定理說明了為什麼狀態定義要寫成「必選 $u$」而不是「$\le j$ 的最優」**：

> **依賴約束的傳遞閉包在樹上就是「到根的整條路徑」。把「$u$ 被選」放進狀態，等於把這條路徑的約束在遞迴中逐層兌現，於是合併時只剩下預算這一個維度需要協調。**

**前提必須點名：依賴關係是森林（每點至多一個前驅）。** 若某個項目有兩個前置（DAG 依賴），「必選 $u$」就不足以刻畫約束——**兩個前驅可能來自不同分支，合併時會重複計算它們的共同祖先** ✘。**一般 DAG 上的依賴背包是 NP-hard 的**（可從最大密度子圖／閉包問題的相關結果得到，此處只引用不證明）。

**實作上的常見技巧**：加一個虛擬根 $0$（$w_0 = v_0 = 0$）連向所有無前驅的項目，把森林變成樹，答案就是 $f(0, C)$ ✔。

### 定理 5（3562 型：父節點的選擇影響子節點代價）

*設定*：樹狀的上下級關係，**若某人的直屬上級「買了」，此人可以打折買**；預算 $C$，最大化利潤。

*命題*：狀態擴充為 $f(u, j, b)$，其中 $b \in \{0,1\}$ 表示「$u$ 的父節點是否買了」，則無後效性成立。

*證明（無後效性檢查，1.1 定理 4 的格式）*。要驗證：**兩條到達「$u$、剩餘預算 $j$、父狀態 $b$」的不同前綴，對 $u$ 子樹的後續可行集與收益完全相同。**

$u$ 子樹內的每個決策，其代價只取決於「該節點自己的價格」與「其父節點是否買了」；後者對 $u$ 而言就是 $b$，對 $u$ 的後代而言則由子樹內部的決策決定 ⇒ **子樹外的一切資訊，除了 $(j, b)$ 之外都不會被用到** ✔ ⇒ 無後效性成立 $\square$

**於是合併變成：$f(u, \cdot, b)$ 先取 $u$ 的兩個分支（$u$ 買 / 不買，價格由 $b$ 決定），再各自以 $u$ 的買賣狀態作為子節點的 $b'$ 去合併子樹。** 兩個分支是**獨立的兩次分組背包**，最後取 max。

**這裡有一個容易漏掉的細節**：$u$ 買與不買會導致**兩套不同的子樹合併結果**，所以**不能先合併子樹再決定 $u$** ✘——**必須先固定 $u$ 的決策，再合併子樹** ✔。這是狀態多一維時迴圈結構的實質改變，不只是多開一個陣列。

**半價的取整**：折扣價可能不是整數。**穩妥做法是把所有價格乘 2**，全程用整數運算，最後再還原——**這樣就完全不必依賴題目對取整方向的規定，也避免浮點誤差** ✔。**若題目明確規定了取整方向，直接照規定寫也可以，但要在測資上驗證奇數價格的情形。**

### 定理 6（DFS 序寫法：$O(C)$ 空間的依賴背包）

*命題*：有依賴的背包可以不做「子樹合併」，改成沿 **DFS 序**掃一遍，用 $O(nC)$ 時間、$O(C)$ 空間完成。

*證明*。把節點按 DFS 先序編號 $1..n$，記 $\mathit{sz}(i)$ 為 $i$ 子樹大小，則**子樹 $i$ 的節點編號恰為連續區間 $[i,\, i + \mathit{sz}(i) - 1]$**（這是 DFS 先序的基本性質）。定義

$$g(i, j) = \text{「只考慮編號} \ge i \text{的節點、預算 } j \text{」的最優值},$$

轉移只有兩個分支：

- **選 $i$**：付出 $w_i$、得到 $v_i$，接著處理 $i+1$ ⇒ $g(i+1,\ j - w_i) + v_i$；
- **不選 $i$**：由依賴關係，**$i$ 的整棵子樹都不能選** ⇒ 直接跳到 $i + \mathit{sz}(i)$ ⇒ $g(i + \mathit{sz}(i),\ j)$。

兩分支不重不漏（$i$ 選或不選）✔，且「不選就跳過整棵子樹」正確地表達了依賴約束（**依賴的傳遞閉包 = 子樹**）✔。$\square$

**這個寫法的優點**：
- **時間 $O(nC)$、空間 $O(C)$**（$i$ 那一維可以滾動，倒著算即可）；
- **沒有子樹合併，也就沒有定理 3 的倒序陷阱** ✔；
- 程式碼短很多。

**缺點**：$C$ 大而 $n$ 小時，$O(nC)$ 可能劣於定理 2 的 $O(n^2)$；**而且它只適用於「每個節點的花費是固定值」的依賴背包**——**一旦節點自己也有多種選擇（分組），或有定理 5 那種父子耦合，就回不到這個形式** ✘。

**兩種寫法的選擇**：**先看 $\min(n, C)$ 與 $C$ 誰小。** $n \ll C$ ⇒ 用合併寫法；$C$ 小 ⇒ 用 DFS 序寫法。

## C++17 模板

```cpp
// ---- 1. 樹形背包（有依賴：選子必選父），合併寫法，O(n * min(n, C)) ----
// w[u], v[u]: 節點花費與價值；g[u]: 子節點列表；根為 0（可用虛擬根）
int C_;
vector<int> w_, v_, sz_;
vector<vector<int>> g_;
vector<vector<long long>> f_;
const long long NEG = -0x3f3f3f3f3f3f3f3fLL;

void dfs(int u) {
    // 「u 必選」：花費不足 w_[u] 的預算一律非法
    f_[u].assign(C_ + 1, NEG);
    for (int j = w_[u]; j <= C_; j++) f_[u][j] = v_[u];
    sz_[u] = w_[u];  // 用花費當「大小」上界
    for (int c : g_[u]) {
        dfs(c);
        int lim = min(C_, sz_[u] + sz_[c]);
        auto tmp = f_[u];  // 快照，正序也安全（定理 3）
        for (int j = w_[u]; j <= lim; j++) {
            int kmax = min(j - w_[u], sz_[c]);  // 上界用 sz，不用 C（定理 2）
            for (int k = w_[c]; k <= kmax; k++) {
                if (tmp[j - k] == NEG || f_[c][k] == NEG) continue;
                f_[u][j] = max(f_[u][j], tmp[j - k] + f_[c][k]);
            }
        }
        sz_[u] = min(C_, sz_[u] + sz_[c]);
    }
}

// ---- 2. 依賴背包的 DFS 序寫法，O(nC) 時間、O(C) 空間（定理 6）----
// ord[0..n-1] 為先序，w/v/sz 均以先序下標存取
long long dependentKnapsackDfsOrder(const vector<int>& w, const vector<int>& v,
                                    const vector<int>& sz, int C) {
    int n = (int)w.size();
    // g[i][j]：只考慮先序編號 >= i 的節點、預算 j 的最優值；i 從後往前算
    vector<long long> cur(C + 1, 0), nxt;
    vector<vector<long long>> G(n + 1, vector<long long>(C + 1, 0));
    for (int i = n - 1; i >= 0; i--)
        for (int j = 0; j <= C; j++) {
            long long best = G[i + sz[i]][j];  // 不選 i：跳過整棵子樹
            if (j >= w[i])                     // 選 i：繼續看 i+1
                best = max(best, G[i + 1][j - w[i]] + v[i]);
            G[i][j] = best;
        }
    return G[0][C];
}

// ---- 3. 父節點狀態影響子節點代價（定理 5 的骨架）----
// f[u][j][b]：b = 父節點是否「買了」；先固定 u 的決策，再合併子樹
void dfs2(int u, vector<array<vector<long long>, 2>>& f,
          const vector<vector<int>>& g, const vector<int>& full,
          const vector<int>& half, const vector<int>& gain, int C) {
    for (int b = 0; b < 2; b++) f[u][b].assign(C + 1, NEG);

    // 先遞迴，取得子節點在「u 買 / u 不買」兩種前提下的表
    for (int c : g[u]) dfs2(c, f, g, full, half, gain, C);

    for (int uBuy = 0; uBuy < 2; uBuy++) {
        for (int b = 0; b < 2; b++) {
            int cost =
                uBuy ? (b ? half[u] : full[u]) : 0;  // b=1 表示父節點買了
            if (cost > C) continue;
            vector<long long> h(C + 1, NEG);
            for (int j = cost; j <= C; j++) h[j] = uBuy ? gain[u] : 0;
            for (int c : g[u]) {  // 分組背包合併
                auto tmp = h;
                for (int j = cost; j <= C; j++)
                    for (int k = 0; k + cost <= j; k++) {
                        if (tmp[j - k] == NEG || f[c][uBuy][k] == NEG) continue;
                        h[j] = max(h[j], tmp[j - k] + f[c][uBuy][k]);
                    }
            }
            for (int j = 0; j <= C; j++) f[u][b][j] = max(f[u][b][j], h[j]);
        }
    }
}
```

**模板 3 是骨架而非完整解**——`full` / `half` / `gain` 的具體定義與取整規則要依題目填入（定理 5 建議把價格乘 2 以避免取整爭議）。

## 時間與空間複雜度

| 寫法 | 時間 | 空間 | 適用 |
| --- | --- | --- | --- |
| 合併寫法，上界用 `sz`（定理 2） | $O\big(n \min(n, C)\big) $ | $O(nC)$ | $n$ 小、$C$ 大 |
| 合併寫法，上界誤用 `C`（✘） | $O(nC^2)$ | $O(nC)$ | **同一份程式，只差迴圈上界** |
| DFS 序寫法（定理 6） | $O(nC)$ | $O(C)$（滾動後） | $C$ 小、無節點內分組 |
| 加一維父狀態（定理 5） | 上面各項 $\times\,2$ | 上面各項 $\times\,2$ | 父子耦合為常數位元時 |

**空間可以再壓**：合併寫法中，**子節點的 $f(v, \cdot)$ 在合併完之後就沒用了** ⇒ 遞迴回傳前釋放（`vector<long long>().swap(f_[v])`），峰值空間降到 $O(\text{最長根鏈} \times C)$ ✔。

**遞迴深度**：鏈狀樹的深度是 $O(n)$。**$n$ 上萬時 DFS 有爆棧風險** ⇒ 改成顯式堆疊，或直接用定理 6 的 DFS 序寫法（它本身就是迭代的）✔。

**溢位**：價值和用 `long long`；`NEG` 用 `-0x3f3f3f3f3f3f3f3f` 而非 `LLONG_MIN`，**並且在相加前檢查 `!= NEG`**（模板都有這一行）。

## 常見錯誤與邊界條件

- **✘ 迴圈上界用 $C$ 而不是子樹大小。** 程式正確但複雜度從 $O(n\min(n,C))$ 掉到 $O(nC^2)$（定理 2 推論 2.1）。**這是樹形背包最常見的 TLE 原因，而且很難從輸出看出來。**
- **✘ 合併時正序就地更新。** 同一棵子樹被分配多次（定理 3）。**用倒序，或開 `tmp` 快照——後者更不容易錯。**
- **✘ 先合併子樹再決定父節點的狀態。** 在定理 5 那類父子耦合題中，父節點的兩種決策會導出兩套不同的子樹結果 ⇒ **必須先固定父決策再合併** ✔。
- **✘ 「有依賴」的定義下把 $k = 0$ 當成合法分支而沒處理。** $f(v, 0)$ 在「$v$ 必選」的定義下通常是 $-\infty$；**「整棵 $v$ 都不選」這個選項要靠 `f[u][j]` 保持原值來表達**（模板 1 的內層從 `k = w_[c]` 起跳，正是為此）。**寫成 `k` 從 0 開始並讀 `f_[c][0]` 會把 $-\infty$ 帶進來。**
- **✘ 忘記虛擬根。** 森林（多棵樹）不能直接取某一棵的答案。**加一個 $w = v = 0$ 的虛擬根連向所有根** ✔。
- **✘ 定理 6 的 `sz` 算錯。** 它必須是**先序意義下的子樹大小**（節點個數），**不是花費和**——這一點與模板 1 的 `sz_`（那裡刻意用花費當上界）不同，兩者容易混淆。
- **✘ 半價用浮點數。** 精度與取整都會出事。**乘 2 轉整數。**
- **✘ 遞迴爆棧。** 鏈狀樹 + 大 $n$。
- **邊界**：$C = 0$（只有花費為 0 的節點可選）、單節點樹、所有花費都超過預算（答案應為 0 或「什麼都不選」，**確認 `-INF` 沒有洩漏成答案**）、$n = 1$ 的森林、價值全為負（此時「至多」語意的答案是 0，別回傳負值）。

## 與相似技巧的比較

- **與 3.4 分組背包**：樹形背包**就是**遞迴的分組背包——**每棵子樹一組，選項是「分給它多少預算」，而選項的價值由遞迴算出**（定理 1）。**兩者的迴圈順序陷阱完全相同**（3.4 定理 2 = 本節定理 3）。**先把 3.4 寫熟。**
- **與 3.1 0-1 背包**：樹退化成「根 + 一排葉子」時，樹形背包就是 0-1 背包。**這是檢查程式的好方法**：拿一棵星形樹跑一遍，答案應該與 0-1 背包一致 ✔。
- **與 12 章樹形 DP**：本節是「樹形 DP + 一條容量軸」。**12 章的多數題目狀態是 $O(1)$ 維的（如「選／不選」），合併是 $O(1)$；本節的狀態多一條 $O(C)$ 的軸，合併變成 $O(\mathit{sz}_u \times \mathit{sz}_v)$**——定理 2 的配對論證就是為了分析後者。**看到「樹上合併時迴圈次數 = 兩邊大小相乘」，直接套 LCA 配對論證。**
- **與 trees 章的後序歸納**：正確性的骨架完全來自那裡——**子樹先算完，父節點才合併；歸納假設是「所有真子樹的 $f$ 都正確」。**
- **與最大權閉合子圖（網路流）**：依賴背包若**沒有容量限制**、只要最大化權值和，就是最大權閉合子圖，可用最小割在多項式時間解決；**加上容量限制之後（本節），一般 DAG 版本變成 NP-hard，只有樹／森林依賴才有本節的多項式算法** ✔。**這解釋了為什麼「依賴必須是森林」不是實作方便，而是可解性的分界線。**
- **與 DFS 序 + 線性 DP**：定理 6 說明樹上的依賴結構可以用「先序區間」表達，從而把樹形問題壓平成線性問題。**這個「子樹 = 先序連續區間」的轉換在整個樹論裡反覆出現**（樹上差分、DSU on tree、樹鏈剖分都靠它）。

## 本節重點速查

- **模型**：選子必選父 + 預算上限。**= 遞迴版的分組背包**（每棵子樹一組，選項是分配的預算量）。
- **定理 2（本節核心）**：合併時迴圈上界寫 $\min(C, \mathit{sz})$ ⇒ **總複雜度 $O(n\min(n,C))$，不是 $O(nC^2)$**。證明：迴圈次數 = 兩側節點的配對數，而**每對節點恰在其 LCA 處被數一次** ⇒ $\binom{n}{2}$。**上界誤寫成 $C$ 是最常見的 TLE 原因。**
- **定理 3**：合併要**倒序**，或開 `tmp` 快照後正序（推薦後者）。理由與 3.4 定理 2 一字不差。
- **定理 4**：狀態定義成「**$u$ 必被選**」⇒ 依賴約束在合併時自動滿足，無需額外檢查。**前提：依賴是森林；一般 DAG 依賴 + 容量限制是 NP-hard。** 用虛擬根把森林接成樹。
- **定理 5（3562 型）**：父節點的決策影響子節點代價 ⇒ 多一維 $b$。**必須先固定父決策、再合併子樹**（兩種決策導出兩套子樹結果）。**半價一律把價格乘 2 轉整數。**
- **定理 6（DFS 序寫法）**：先序下**子樹 = 連續區間** ⇒ 「選 $i$ 走 $i+1$／不選 $i$ 跳到 $i+\mathit{sz}(i)$」⇒ $O(nC)$ 時間、$O(C)$ 空間、沒有合併陷阱。**限制：節點本身不能再有分組選擇或父子耦合。**
- **選哪個寫法**：$n \ll C$ ⇒ 合併寫法（$O(n^2)$）；$C$ 小 ⇒ DFS 序寫法（$O(nC)$）。
- **自我檢查**：拿星形樹跑一遍，答案必須等於 0-1 背包。
