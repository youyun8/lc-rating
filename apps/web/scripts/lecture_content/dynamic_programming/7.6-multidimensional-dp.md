## 這個技術解決什麼問題

**「我想用一維 DP，但發現少了一個資訊。」**

本節處理的就是這個時刻：**當 $f(i)$ 不足以決定後續，就補上第二個（甚至第三個）維度，直到狀態完備為止。**

**判準來自 7.1 定理 1（替換性質）**：

> 若兩個「走到位置 $i$ 的方案」在後續的**合法性**或**代價**上表現不同，$f(i)$ 就不完備。
> **它們差在哪個量，那個量就是要補的維度。**

**維度的三個常見來源**：

| 來源 | 意思 | 代表題 |
| --- | --- | --- |
| **上一步的選擇** | 相鄰兩步之間有約束 | 256 / 265 粉刷房子、568 最大休假天數 |
| **某個累計量** | 後續合法性取決於「怎麼走到這裡的」 | 403 青蛙過河（上一步的跳躍距離） |
| **另一個物件的進度** | 兩個序列 / 兩個指標同時推進 | 514 自由之路（鑰匙已拼到第幾個字） |

**⚠ 本節最容易誤解的一句話**：**「多維」不是目的，「最小完備」才是。**

盲目加維度會讓狀態數爆炸；而**該加卻不加**會得到錯誤答案。**本節六條定理，一半在教「怎麼加」，一半在教「怎麼證明不用加」。**

## 狀態／資料結構定義

**通用形式**：

$$f(i,\ \theta) = \text{在主軸位置 } i\text{、附加資訊為 }\theta\text{ 時的最優值（或可行性）}.$$

**主軸 $i$** 幾乎總是「已處理到第幾個元素 / 第幾天 / 第幾週」，**保證無後效性**（只往前推進）。
**附加維度 $\theta$** 則因題而異：

| 題 | 主軸 | 附加維度 $\theta$ | $|\Theta|$ | 狀態數 |
| --- | --- | --- | --- | --- |
| 256 粉刷房子 | 房子編號 $i$ | 第 $i$ 間的顏色 | 3 | $O(n)$ |
| 265 粉刷房子 II | 房子編號 $i$ | 第 $i$ 間的顏色 | $k$ | $O(nk)$ |
| 568 最大休假天數 | 週數 $w$ | 當週所在城市 | $n$ | $O(nk)$ |
| 403 青蛙過河 | 石頭下標 $i$ | **上一步的跳躍距離** | $O(n)$ | $O(n^2)$ |
| 514 自由之路 | 鑰匙進度 $i$ | 轉盤指標位置 | $O(n)$ | $O(nm)$ |

**兩種 $\theta$ 的實作差別（沿用 7.4 定理 6 的表）**：

- **$|\Theta|$ 為常數或小整數（256、265、568、514）** ⇒ **二維 `vector`** ✔；
- **$|\Theta|$ 稀疏（403 的跳躍距離）** ⇒ **每個 $i$ 一個 `unordered_set` / `bitset`** ✔，因為大部分 $(i,k)$ 根本不可達。

**⚠ 維度順序決定滾動可行性**：**把「只依賴上一層」的那個維度放在最外層**，才能用 $O(|\Theta|)$ 的滾動陣列（2.1 定理 2）。

## 不變量或正確性證明

### 定理 1（**什麼時候必須加維度：替換性質的失敗點就是新維度**）

*命題*：設 $P_1,P_2$ 是兩個都在位置 $i$ 結束的方案。若存在後續 $Q$ 使得

- $P_1Q$ 合法但 $P_2Q$ 不合法（**合法性差異**），或
- $\mathrm{cost}(P_1Q)-\mathrm{cost}(P_1) \ne \mathrm{cost}(P_2Q)-\mathrm{cost}(P_2)$（**邊際代價差異**），

則 $f(i)$（單一維度）**不可能正確**。

*證明*。反證。若 $f(i)$ 正確，代表「只保留位置 $i$ 的最優值」就足以推出最終答案。但上面兩種情形下，一個在 $i$ 處較差的方案可能在加上 $Q$ 後反超（或唯一合法）⇒ 最優子結構失效 ⇒ 保留單一最優值必然丟失最優解 ✔。$\square$

**用法（本節的操作流程）**：

1. 寫下 $f(i)$，**試著構造兩個「$i$ 相同但後續表現不同」的方案**；
2. 構造成功 ⇒ **它們差在哪個量，就把那個量設為 $\theta$**；
3. 重複第 1 步，直到構造不出來 ⇒ **狀態完備**（7.4 定理 1 的充要條件）。

**逐題套用**：

| 題 | 構造出的差異 | 得到的 $\theta$ |
| --- | --- | --- |
| 256 | 兩個方案第 $i$ 間顏色不同 ⇒ 第 $i+1$ 間可選的顏色不同 | 第 $i$ 間的顏色 |
| 403 | 兩個方案到同一顆石頭，但上一步跳 3 與跳 5 ⇒ 下一步能跳到的石頭不同 | 上一步的跳躍距離 |
| 514 | 兩個方案拼完同樣多字，但指標停在不同位置 ⇒ 下一段旋轉代價不同 | 指標位置 |
| 568 | 兩個方案到同一週，但人在不同城市 ⇒ 下週能去的地方不同 | 當前城市 |

**反過來，證明「不用加」也是用它**（下面定理 4 對 403 的剪枝、定理 5 對 514 的位置集合縮減，都是這種論證）。

### 定理 2（**265：排除自己的最小值 = 最小值 + 次小值，$O(nk^2)\to O(nk)$**）

*設定*：$f(i,c) = \mathit{cost}[i][c] + \min_{c'\ne c} f(i-1,c')$。

*命題*：設 $f(i-1,\cdot)$ 的最小值在 $c_1$ 取得、次小值在 $c_2$ 取得（$c_1\ne c_2$，允許數值相等），則

$$\min_{c'\ne c} f(i-1,c') = \begin{cases} f(i-1,c_2), & c = c_1,\\[2pt] f(i-1,c_1), & c \ne c_1. \end{cases}$$

*證明*。
若 $c\ne c_1$：$c_1$ 本身就在可選集合裡，且它是全域最小 ⇒ 最小值即 $f(i-1,c_1)$ ✔。
若 $c=c_1$：可選集合是 $\{c'\ne c_1\}$。**「在去掉全域最小值後的集合中取最小」的定義就是次小值** ⇒ $f(i-1,c_2)$ ✔。$\square$

*依賴的前提*：**$k\ge2$**。$k=1$ 時 $\{c'\ne c\}$ 是空集，相鄰兩間房必同色 ⇒ 只有 $n\le1$ 才有解 ⇒ **必須特判** ✘。

> **這個「取最小值時排除某一個元素」的技巧極通用**：
> 只要轉移形如 $\min_{j\ne i}(\cdots)$ 且被 $\min$ 的東西**與 $i$ 無關**，就能用 (最小, 次小) 兩個數字取代 $O(k)$ 掃描 ✔。
> **前提是「與 $i$ 無關」**——若寫成 $\min_{j\ne i}\big(f(j)+w(i,j)\big)$ 且 $w$ 真的依賴 $(i,j)$，這招失效 ✘。

**維護次小值的正確寫法**（一次掃描，**注意不能寫成「先求最小、再掃一次求次小」以外的偷懶版**）：

```cpp
int m1 = INT_MAX, m2 = INT_MAX, i1 = -1;  // m1 <= m2
for (int c = 0; c < k; c++) {
    if (f[c] < m1) {
        m2 = m1;
        m1 = f[c];
        i1 = c;
    } else if (f[c] < m2) {
        m2 = f[c];
    }
}
```

**⚠ `else if` 這裡是對的**（與 6.3 定理 4 的 801 相反）——因為 `f[c] < m1` 與 `f[c] < m2` 在 `m1 <= m2` 之下**確實互斥地表達了「更新哪一格」**，而 801 的兩個條件是**獨立事件**。**判準：兩個分支是「同一件事的分級」用 `else if`，是「兩件獨立的事」用兩個 `if`。**

### 定理 3（**568：分層圖 DP——把「時間 × 位置」攤成 DAG**）

*設定*：$n$ 個城市、$k$ 週，`flights[i][j]=1` 表示 $i\to j$ 有航班，**且 `flights[i][i]` 一律視為可行（留在原地）**；`days[c][w]` 是在城市 $c$ 過第 $w$ 週能休的天數。第 0 週從城市 0 出發。

$$f(w,\,c) = \mathit{days}[c][w] + \max_{c'\,:\ \mathit{flights}[c'][c]=1\ \lor\ c'=c} f(w-1,\,c'),\qquad f(-1,\,c)=\begin{cases}0,& c=0\\ -\infty,& c\ne0\end{cases}$$

答案 $=\max_c f(k-1,c)$。

*命題*：這個遞推正確，且**沒有後效性**。

*證明*。把狀態畫成 $k\times n$ 的格點，第 $w$ 層的 $c$ 只連到第 $w+1$ 層 ⇒ **圖是分層的、必為 DAG**（邊只從小 $w$ 指向大 $w$）✔ ⇒ 拓撲序就是 $w$ 遞增 ⇒ 按 $w$ 遞增填表即滿足無後效性（1.1 定理 4）✔。

**最優子結構**：一條「第 0..k-1 週的行程」的總休假 $=\sum_w \mathit{days}[c_w][w]$，**可加**且**每項只取決於當週所在城市** ⇒ 前 $w$ 週的部分與後續獨立 ⇒ $f(w,c)$ 只需保留最大值 ✔（替換性質成立，定理 1）。$\square$

*依賴的前提*：**「一週只換一次城市，且換城市發生在週初」**——題目如此定義；若允許週中轉機，$\mathit{days}$ 的歸屬就不再是「當週所在城市」單值 ⇒ 模型崩潰 ✘。

**$-\infty$ 的必要性**：第 0 週只能在城市 0 或 0 的鄰居 ⇒ **其他城市在第 $-1$ 週不可達**。若把不可達寫成 0 而非 $-\infty$，會允許「憑空出現在任意城市」✘（2.1 定理 3：**單位元必須是該運算的真正單位元，不可達要用吸收元**）。實作上用 `INT_MIN / 2` 避免加法溢位 ✔。

> **這是 13 章圖 DP 的預告**：**「時間 × 位置」的分層展開，是把有環圖上的問題轉成 DAG 的標準手法**（同樣的想法在 6.3 定理 5 的矩陣快速冪、以及「恰走 $k$ 步的最短路」裡出現過）。

### 定理 4（**403：狀態數其實是 $O(n^2)$ 而非 $O(n\cdot 10^{31})$**）

*設定*：石頭位置嚴格遞增 $s_0=0<s_1<\dots<s_{n-1}$（$s_i$ 可達 $2^{31}-1$）。上一步跳了 $k$，下一步只能跳 $k-1,k,k+1$（且必須 $>0$）。

*天真的擔憂*：$k$ 的值域高達 $2^{31}$ ⇒ 狀態 $(i,k)$ 看似無法列舉。

*命題*：**可達狀態 $(i,k)$ 的總數 $\le n^2$**，更精確地，對每顆石頭 $i$，可達的 $k$ 值不超過 $i$ 個。

*證明*。設青蛙用 $t$ 步到達石頭 $i$。每一步的跳躍距離最多比前一步多 1，且第一步固定跳 1 ⇒ **第 $t$ 步的距離 $k \le t$** ✔。另一方面每一步至少跨過一顆石頭（位置嚴格遞增）⇒ **$t\le i$** ✔。故 $k\le t\le i$ ⇒ 石頭 $i$ 上的可達 $k$ 落在 $\{1,\dots,i\}$ ⇒ 至多 $i$ 個 ✔。總計 $\sum_i i = O(n^2)$ ✔。$\square$

> **這條定理的價值不在於複雜度，而在於它把「值域看起來爆炸」的恐慌消掉。**
> **一般教訓：附加維度的「理論值域」與「可達值域」可以差很多個數量級——先估可達值域再決定資料結構。**

*實作推論*：**用 `unordered_map<int position, unordered_set<int> jumps>` 或 `vector<unordered_set<int>>`**（按下標）比開 $n\times n$ 的 `bool` 更貼合稀疏性；$n\le2000$ 時 $n\times n$ 的 `vector<vector<char>>` 也只有 4 MB，**兩種都可以，但別開 `vector<vector<bool>>` 以外的大型 `int` 陣列** ✔。

*另一個必要的前提*：**必須用「位置 $\to$ 下標」的雜湊表**，因為轉移算出的是**位置** $s_i+k'$，要反查它是不是石頭 ✔。

### 定理 5（**514：只需枚舉「等於當前鑰匙字元」的轉盤位置**）

*設定*：轉盤 `ring` 長 $n$，鑰匙 `key` 長 $m$。$f(i,j)$ = 已拼完 `key` 的前 $i$ 個字元、指標停在 `ring[j]`（必有 `ring[j] == key[i-1]`）時的最小步數（含按鈕）。

$$f(i,j) = \min_{j'\,:\ \mathit{ring}[j']=\mathit{key}[i-2]} \Big( f(i-1,j') + \mathrm{dist}(j',j) \Big) + 1,\qquad \mathrm{dist}(a,b) = \min\big(|a-b|,\ n-|a-b|\big).$$

*命題*：**只考慮 $\mathit{ring}[j]=\mathit{key}[i-1]$ 的 $j$ 就夠了，不會漏掉最優解。**

*證明*。任何合法方案在「按下第 $i$ 個字元」的那一刻，指標**必定**指在一個內容等於 $\mathit{key}[i-1]$ 的位置 ✔。中途經過的其他位置不影響代價——**因為旋轉代價只看起終點的環上距離，與路徑無關** ✔（環上兩點間走最短弧即可，且不繞多圈永遠不劣）。故把狀態限制在這些位置上，仍涵蓋所有方案 ✔。$\square$

*依賴的前提*：**旋轉代價與中途無關**。若題目改成「經過某些位置有額外代價」，這個縮減立刻失效 ✘。

**環上距離的正確寫法**：$\mathrm{dist}(a,b)=\min(d,\ n-d)$ 其中 $d=|a-b|$。
**⚠ 常見錯誤**：寫成 `min(abs(a-b), n - abs(a-b))` 但忘記 `abs`，或寫成 `(a-b+n)%n` **只取了單一方向** ✘。

*複雜度*：$\sum_i \mathit{cnt}[\mathit{key}[i]]\cdot \mathit{cnt}[\mathit{key}[i-1]] \le O(mn^2/\ldots)$，最壞 $O(mn^2)$（全同字元），但 $n,m\le100$ ⇒ 綽綽有餘 ✔。

### 定理 6（**維度該加到幾維：與狀壓 DP 的分界**）

*命題*：附加維度 $\theta$ 若必須記錄「**哪些元素已被使用**」這種**集合**資訊，且集合不能被常數個標量摘要，則問題屬於 9 章狀壓 DP，狀態數必然含 $2^n$ 因子。

*判準表*：

| 需要記住的東西 | 屬於 | 狀態數 |
| --- | --- | --- |
| 上一步的選擇（常數種） | **6 章狀態機** | $O(n\cdot|S|)$ |
| 上一步的選擇（值域隨輸入變） | **7.4 合法子序列** | $O(n|\Theta|)$ |
| 一到三個**獨立的標量**（位置、進度、次數） | **本節多維 DP** | 各維度相乘 |
| **用過哪些元素的集合** | **9 章狀壓** | $O(2^n\cdot\ldots)$ |
| 一個**區間的兩個端點** | **8 章區間 DP** | $O(n^2)$ |

*為什麼集合不能摘要成標量*：以 TSP 為例，兩條走過同樣多城市、同樣停在城市 $v$ 的路徑，**只要走過的城市集合不同，後續可走的城市就不同** ⇒ 定理 1 的合法性差異 ⇒ 「已走過的個數」不完備 ✔。**但若題目沒有「不能重複」的限制**（例如 568 可以反覆造訪同一城市），集合資訊就完全不需要 ⇒ 停在本節 ✔。

> **這條判準是第 7 章與第 9 章之間的分水嶺：問「有沒有『不能重複使用』的限制」。**

**加維度前的三個檢查**（避免無謂爆炸）：

1. **能不能由其他維度推出來？** 若 $\theta$ 是 $i$ 的函數（如 7.4 定理 2 的 1218），維度可省 ✔。
2. **可達值域有多大？** 定理 4 的教訓：理論值域 $\ne$ 可達值域。
3. **能不能換主軸？** 7.1 定理 4 的 871 示範了「狀態與答案互換」把大值域換成小值域。

## C++17 模板

```cpp
// ---- 1. LC 256 粉刷房子（k = 3，樸素二維）----
int minCost3(const vector<vector<int>>& cost) {
    int n = (int)cost.size();
    array<int, 3> f = {cost[0][0], cost[0][1], cost[0][2]};
    for (int i = 1; i < n; i++) {
        array<int, 3> g{};
        for (int c = 0; c < 3; c++) {
            int best = INT_MAX;
            for (int p = 0; p < 3; p++)
                if (p != c) best = min(best, f[p]);
            g[c] = best + cost[i][c];
        }
        f = g;  // 整層替換，不就地更新
    }
    return *min_element(f.begin(), f.end());
}

// ---- 2. LC 265 粉刷房子 II：最小值 + 次小值，O(nk) ----
int minCostII(const vector<vector<int>>& cost) {
    int n = (int)cost.size();
    if (n == 0) return 0;
    int k = (int)cost[0].size();
    if (k == 1) return (n == 1) ? cost[0][0] : -1;  // k==1 且 n>1 無解，須特判
    vector<int> f = cost[0];
    for (int i = 1; i < n; i++) {
        int m1 = INT_MAX, m2 = INT_MAX, i1 = -1;  // m1 <= m2
        for (int c = 0; c < k; c++) {
            if (f[c] < m1) {
                m2 = m1;
                m1 = f[c];
                i1 = c;
            } else if (f[c] < m2) {
                m2 = f[c];
            }
        }
        vector<int> g(k);
        for (int c = 0; c < k; c++)
            g[c] = cost[i][c] + (c == i1 ? m2 : m1);  // 定理 2
        f.swap(g);
    }
    return *min_element(f.begin(), f.end());
}

// ---- 3. LC 568 最大休假天數：分層圖 DP ----
int maxVacationDays(const vector<vector<int>>& flights,
                    const vector<vector<int>>& days) {
    int n = (int)flights.size();
    if (n == 0) return 0;
    int k = (int)days[0].size();
    const int NEG = INT_MIN / 2;  // 不可達，不是 0
    vector<int> f(n, NEG);
    f[0] = 0;  // 第 0 週開始前人在城市 0
    for (int w = 0; w < k; w++) {
        vector<int> g(n, NEG);
        for (int c = 0; c < n; c++)
            for (int p = 0; p < n; p++)
                if (f[p] != NEG && (p == c || flights[p][c]))
                    g[c] = max(g[c], f[p] + days[c][w]);
        f.swap(g);
    }
    return *max_element(f.begin(), f.end());
}

// ---- 4. LC 403 青蛙過河：稀疏的第二維 ----
bool canCross(const vector<int>& stones) {
    int n = (int)stones.size();
    if (n >= 2 && stones[1] != 1) return false;  // 第一步只能跳 1
    unordered_map<int, int> idx;                 // 位置 -> 下標
    idx.reserve(n * 2);
    for (int i = 0; i < n; i++) idx[stones[i]] = i;
    vector<unordered_set<int>> jump(n);  // jump[i] = 可用哪些距離抵達 i
    jump[0].insert(0);
    for (int i = 0; i < n; i++)
        for (int k : jump[i])
            for (int nk : {k - 1, k, k + 1}) {
                if (nk <= 0) continue;
                auto it = idx.find(stones[i] + nk);
                if (it == idx.end() || it->second <= i) continue;
                if (it->second == n - 1) return true;
                jump[it->second].insert(nk);
            }
    return n == 1;
}

// ---- 5. LC 514 自由之路：只枚舉字元相符的位置 ----
int findRotateSteps(const string& ring, const string& key) {
    int n = (int)ring.size(), m = (int)key.size();
    vector<vector<int>> pos(26);
    for (int i = 0; i < n; i++) pos[ring[i] - 'a'].push_back(i);
    auto dist = [&](int a, int b) {
        int d = abs(a - b);
        return min(d, n - d);  // 環上取短弧
    };
    const int INF = INT_MAX / 2;
    vector<int> cur(n, INF);
    cur[0] = 0;  // 起始指標在 0
    vector<int> prevPos{0};
    for (int i = 0; i < m; i++) {
        const auto& nxt = pos[key[i] - 'a'];
        if (nxt.empty()) return -1;  // 鑰匙字元不在轉盤上
        vector<int> nf(n, INF);
        for (int j : nxt)
            for (int p : prevPos)
                if (cur[p] < INF) nf[j] = min(nf[j], cur[p] + dist(p, j) + 1);
        cur.swap(nf);
        prevPos = nxt;
    }
    int ans = INF;
    for (int j : prevPos) ans = min(ans, cur[j]);
    return ans;
}
```

## 時間與空間複雜度

| 題 | 時間 | 空間（滾動後） |
| --- | --- | --- |
| 256 | $O(9n)=O(n)$ | $O(1)$ |
| 265 樸素 / 優化 | $O(nk^2)$ / **$O(nk)$** | $O(k)$ |
| 568 | $O(kn^2)$ | $O(n)$ |
| 403 | $O(n^2)$（定理 4） | $O(n^2)$ 最壞 |
| 514 | $O\!\big(\sum_i \mathit{cnt}[\mathit{key}[i]]\cdot\mathit{cnt}[\mathit{key}[i-1]]\big)\subseteq O(mn^2)$ | $O(n)$ |

**通則**：**狀態數 = 各維度值域的乘積；時間 = 狀態數 × 單次轉移代價。** 兩者要分開估——**定理 2 就是「狀態數不變、把單次轉移從 $O(k)$ 壓到 $O(1)$」的典型。**

**滾動的條件**：主軸 $i$ 只依賴 $i-1$ ⇒ 保留兩層即可 ⇒ 空間降為 $O(|\Theta|)$ ✔。
**⚠ 本節一律用「整層替換」（`g` 算完再 `swap`）而不是就地更新**——因為轉移是 $\max_{c'} f(i-1,c')$ **跨越所有 $c'$**，就地更新會讀到本層的髒值 ✘（2.1 定理 2 的同一條規則，只是這裡連「順序調整」都救不了，必須雙陣列）。

**403 的空間**：最壞 $O(n^2)$ 個 `unordered_set` 元素。$n\le2000$ ⇒ 約 $4\times10^6$ 個 `int`，**`unordered_set` 的常數開銷不小**；若卡常，改用 `vector<vector<char>>` 的 $n\times n$ 布林表（4 MB）✔。

## 常見錯誤與邊界條件

- **✘ 該加維度卻不加。** 用定理 1 的流程檢查：**能不能構造出「$i$ 相同但後續不同」的兩個方案？**
- **✘ 加了不必要的維度。** 先問定理 6 的三個檢查（能否推導、可達值域、能否換主軸）。
- **✘ 就地更新導致讀到本層髒值。** 本節的轉移都跨越整個 $\Theta$ ⇒ **必須雙陣列 / 整層替換** ✔。
- **✘ 265 忘記 $k=1$ 的特判。** 次小值不存在 ⇒ `m2 == INT_MAX` ⇒ 加法溢位 ✘。
- **✘ 265 的次小值維護寫錯。** 常見錯法是「先掃出最小值，再掃一次跳過 `i1`」——**這在有重複最小值時仍然正確**，但若寫成「跳過所有等於 `m1` 的值」就錯了 ✘（兩間房都花費相同時仍可用不同顏色）。
- **✘ 568 把不可達寫成 0。** 必須 `INT_MIN/2` ✘，否則會憑空出現在任意城市。
- **✘ 568 忘記 `p == c`（留在原地）。** 題目的 `flights[i][i]` 定義為 0，但留在原地永遠合法 ✔。
- **✘ 403 沒特判第一步。** `stones[1] != 1` 直接無解 ✔。
- **✘ 403 用位置當陣列下標。** 位置可達 $2^{31}-1$ ⇒ **必須用雜湊表反查下標** ✘。
- **✘ 403 允許 `nk <= 0`。** 跳躍距離必須為正 ✘。
- **✘ 514 的環上距離只算單方向。** 必須 $\min(d,\ n-d)$ ✘。
- **✘ 514 忘記每按一次鑰匙要 +1 步。** 答案至少是 $m$ ✔（可用來自檢）。
- **邊界**：$n=1$（403 直接成功；256 直接回傳最小花費）、`key` 有轉盤上不存在的字元、`days` 全 0、$k=0$ 週。

## 與相似技巧的比較

- **與 6 章狀態機 DP**：**只差在 $|\Theta|$ 是不是常數。** 256（3 色）其實就是狀態機；265（$k$ 色）因為 $k$ 隨輸入變，才歸到本節。**兩者的證明工具完全相同（定理 1 = 6.2 定理 1）。**
- **與 7.4 合法子序列 DP**：那裡的 $\theta$ 是「**由歷史元素算出的特徵**」（公差、前兩項）；本節的 $\theta$ 更常是「**當前所在的物理位置 / 選擇**」。**7.4 定理 1 與本節定理 1 是同一條定理的兩種說法。**
- **與 9 章狀壓 DP**：**分水嶺是「有沒有不能重複使用的限制」**（定理 6）。568 可以反覆造訪 ⇒ 停在本節；TSP 不行 ⇒ 進 9 章。
- **與 2.2 網格圖 DP**：網格圖的兩個維度是「輸入本來就是二維」；本節的第二維是**我們自己補上的**。**別把兩者混為一談——前者維度是給定的，後者維度是設計出來的。**
- **與 13 章圖 DP**：568 的「時間 × 位置」分層展開是圖 DP 的入門形態。**凡是「在圖上走恰好 $k$ 步」的題目都用這個攤平法**（6.3 定理 5 的矩陣快速冪就是它的加速版）。
- **與 11 章優化 DP**：定理 2 的「最小 + 次小」是**單次轉移優化**的最簡單形態。**11 章的字首和、單調佇列、線段樹優化都在做同一件事：不改狀態數，只壓縮 $\max/\min$ 的求值成本。**

## 本節重點速查

- **核心流程（定理 1）**：寫下 $f(i)$ → **構造兩個「$i$ 相同但後續不同」的方案** → 差在哪個量，那個量就是新維度 → 重複到構造不出來為止。**「最小完備」不是「越多維越好」。**
- **維度的三個來源**：上一步的選擇（256/265/568）、某個累計量（403 的跳躍距離）、另一個物件的進度（514 的鑰匙）。
- **定理 2（265）**：$\min_{c'\ne c}$ = **(最小, 次小)** 兩個數字，$O(nk^2)\to O(nk)$。**前提：被 $\min$ 的量與 $c$ 無關，且 $k\ge2$。** `else if` 在這裡是對的（同一件事的分級），與 6.3 定理 4 的 801 相反（兩件獨立的事）。
- **定理 3（568）**：**時間 × 位置的分層展開必為 DAG** ⇒ 無後效性；**不可達要用 `INT_MIN/2` 而非 0**；13 章圖 DP 的入門形態。
- **定理 4（403）**：第 $t$ 步距離 $\le t$ 且 $t\le i$ ⇒ **可達狀態只有 $O(n^2)$**。教訓：**理論值域 $\ne$ 可達值域**。位置要用雜湊表反查下標。
- **定理 5（514）**：**只枚舉字元相符的位置**，因為旋轉代價只看起終點；環上距離 $=\min(d,\ n-d)$。
- **定理 6（分水嶺）**：要記「**用過哪些元素的集合**」⇒ 9 章狀壓；只要記常數個標量 ⇒ 本節。**問一句「有沒有不能重複使用的限制」就分得出來。**
- **實作**：本節轉移都跨越整個 $\Theta$ ⇒ **一律整層替換（雙陣列），不可就地更新。**
