## 這個技術解決什麼問題

在連通的帶權無向圖上，挑出 `n - 1` 條邊把所有點連起來，使邊權總和最小。典型情境是「用最低成本鋪設網路連通所有城市」。

## 辨識題型的訊號

要求連通所有節點且成本最小；輸入是無向帶權邊或點座標（後者需自行建完全圖）；問最小總成本、或問「使得任意兩點可達的最小瓶頸值」。求最大生成樹只需把排序反向。

## 核心想法與直覺

兩種主流做法都建立在同一個貪心事實上。Kruskal 由小到大掃邊，只要這條邊連接兩個不同的連通塊就採用，用並查集判斷；Prim 則從一個點出發，每次把「連向樹外最便宜的邊」拉進來，用堆維護候選。稀疏圖用 Kruskal，稠密圖用 Prim。

## 狀態／資料結構定義

Kruskal：邊集依權重排序；並查集維護目前的連通塊，`cc` 為連通塊個數。Prim：`in_tree[x]` 標記是否已在樹中，堆中存放 `(邊權, 端點)`。

## 不變量或正確性證明

兩者都由割性質（cut property）保證：對任意把節點分成兩半的割，跨越該割的最小權邊必屬於某棵最小生成樹。

證明：設最小生成樹 `T` 不含跨割最小邊 `e`。把 `e` 加入 `T` 會形成唯一的環，該環必定再次跨越此割，故環上還有另一條跨割邊 `f`，其權重不小於 `e`。用 `e` 換掉 `f` 仍是生成樹，且總權重不增，因此存在包含 `e` 的最小生成樹。

Kruskal 的不變量：已選邊集始終是某棵最小生成樹的子集。每次採用的邊都是連接兩個當前連通塊的最小邊，對「該連通塊 vs 其餘」這個割而言正是跨割最小邊，故由割性質可安全採用。Prim 的不變量相同，只是割固定為「樹內 vs 樹外」。

## 逐步演算法

Kruskal：所有邊依權重升序排序；依序嘗試合併兩端點，合併成功即計入答案；選滿 `n - 1` 條邊即可提前結束；若最終連通塊多於一個則圖不連通。

## C++17 模板

```cpp
struct UnionFind {
    vector<int> fa;
    int cc;
    explicit UnionFind(int n) : fa(n), cc(n) { iota(fa.begin(), fa.end(), 0); }

    int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

    bool merge(int a, int b) {
        const int x = find(a), y = find(b);
        if (x == y) {
            return false;
        }
        fa[x] = y;
        --cc;
        return true;
    }
};

// 回傳最小生成樹的邊權和；圖不連通時回傳 -1。
long long mstKruskal(int n, vector<vector<int>>& edges) {
    sort(edges.begin(), edges.end(),
         [](const auto& a, const auto& b) { return a[2] < b[2]; });

    UnionFind uf(n);
    long long total = 0;
    for (const auto& e : edges) {
        if (uf.merge(e[0], e[1])) {
            total += e[2];
            if (uf.cc == 1) {
                break;
            }  // 已連通，提前結束
        }
    }
    return uf.cc == 1 ? total : -1;
}
```

稠密圖（例如由座標建出的完全圖）改用 $O(n^2)$ 的 Prim，避免產生 $O(n^2)$ 條邊再排序。

## 時間與空間複雜度

Kruskal 為 $O(m \log m)$，瓶頸在排序；並查集部分近似線性。堆優化的 Prim 為 $O(m \log n)$，樸素 Prim 為 $O(n^2)$，在稠密圖上反而更快。

## 常見錯誤與邊界條件

- 忘記處理圖不連通的情況。
- 邊權總和溢位（需 `long long`）。
- 求最大生成樹時只把比較反向卻忘了同步改其他判斷。
- 自環會被並查集自動忽略是正確的，重邊也無妨。
- `n == 1` 時答案為 0 且不需要任何邊。

## 與相似技巧的比較

最小瓶頸路（讓路徑上最大邊最小）的答案就在最小生成樹上，因此許多「最小化最大值」的連通題可直接套 Kruskal；若只問連通性而不問成本，單純的並查集就夠；若要動態加邊維護 MST，則需要更進階的資料結構。

## 本節重點速查

- 割性質保證貪心正確
- 稀疏用 Kruskal、稠密用 Prim
- 選滿 `n - 1` 條邊
- 不連通要回傳無解。
