## 這個技術解決什麼問題

有些題目本質是最小費用最大流，但輸入按時間或位置依序到來，完整建圖太重。模擬費用流用堆直接維護「可配對的舊端點」與「撤銷舊配對的憑證」：新元素到來時做一次最便宜的配對，必要時把先前決定改接到現在。它常以「反悔貪心」或「後悔堆」的名字出現。

## 辨識題型的訊號

依序處理一串價格、端點或事件；一個較早元素可以和較晚元素配對；後來更好的端點可能取代先前配對；撤銷代價能由單一鍵值比較並放進堆。若限制同時有重量、件數等多個維度，通常不能只靠一個後悔堆。

## 核心想法與直覺

費用流的反向邊代表「撤銷先前決定」。在序列結構上不必顯式建圖：堆中放所有目前可用的左端點；讀到新值 `p` 時，若最便宜端點 `q` 滿足 `q < p`，就取得收益 `p - q`，並把 `q` 從堆中移除。

關鍵是賣出後把 `p` **放回兩次的效果**：一次取代被配掉的 `q`，代表這筆交易日後可以沿反向邊撤銷並改接；另一次把今天當成新的買入候選。實作上是「有獲利時先 pop、push 一次 `p`，迴圈尾端再固定 push 一次 `p`」。這個順序正是模擬殘量網路，不是普通的「看到上漲就賣」口訣。

## 狀態／資料結構定義

小根堆 `buys` 存可作為買入端點的價格；`profit` 存目前累計收益。對價格 `p`，堆頂是當前最便宜的可配對端點。若成交，重新放回的 `p` 是反向邊憑證；迴圈尾端再放一次 `p` 是新的正向候選。

## 不變量或正確性證明

不變量：處理完前 `i` 個價格後，`profit` 是此前綴在「同日最多持有一股、可做任意次完整交易、無手續費與冷卻期」下的最大收益；堆中每個鍵都代表一個仍可使用的買入端點或一條可撤銷既有配對的反向邊。

歸納考慮新價格 `p`。若堆頂 `q >= p`，任何舊端點與 `p` 配對都不會增加收益，跳過成交最優，只需把 `p` 留作未來候選。若 `q < p`，最優解若讓 `p` 與某個更貴端點 `q'` 配對，把 `q'` 換成最小的 `q` 只會讓收益增加，因此取堆頂安全。成交後放回 `p` 作反悔憑證，使未來較高價格可以把「`q -> p` 加 `p -> r`」改寫或串接，而不會鎖死今天的局部決定；再放一個 `p` 則保留今天作新買點的選項。故不變量延伸到下一個前綴。

這個證明依賴端點按序到來、收益可加、且反悔只需一個價格鍵。加入交易費、冷卻期、持股上限或交易次數上限後，憑證與狀態都要重新設計；不能原封不動套用。

## 逐步演算法

由左到右掃價格；若堆非空且堆頂小於目前價格，就以目前價格配對堆頂、累加差值、彈出舊端點，並把目前價格放回作反悔憑證；接著無條件再把目前價格放入，保留為新的買入端點。

## C++17 模板

```cpp
// 序列替換／模擬費用流：無手續費、無冷卻期、可做任意次股票交易。
long long maxProfitRegretHeap(const vector<long long>& prices) {
    priority_queue<long long, vector<long long>, greater<long long>> buys;
    long long profit = 0;

    for (long long p : prices) {
        if (!buys.empty() && buys.top() < p) {
            profit += p - buys.top();
            buys.pop();
            buys.push(p);  // 反向邊憑證：既有配對日後可在價格 p 處改接
        }
        buys.push(p);  // 正向候選：今天也可以是一個新的買入點
    }
    return profit;
}
```

## 程式碼拆解

- 堆頂永遠是最便宜的可配對舊端點；只有 `buys.top() < p` 時成交，避免加入負收益。
- 成交分支中的 `push(p)` 是反悔憑證，迴圈尾端的 `push(p)` 是全新的買入候選，兩次用途不同，不能合併掉。
- `profit` 與價格使用 `long long`；若題目有手續費、冷卻期或交易次數限制，這個模板不再直接適用。

## 時間與空間複雜度

每個價格入堆至多兩次、出堆至多一次，時間 $O(n\log n)$，空間 $O(n)$。通用最小費用流的成本取決於增廣次數與最短路實作，通常明顯更高；不應用一個固定的 $O(fnm)$ 公式概括所有版本。

## 常見錯誤與邊界條件

- 把兩次 `push(p)` 誤刪成一次。
- 先 push 當前價格再比較，造成與自己配對。
- 用大根堆而不是取最便宜端點的小根堆。
- 差值非正仍成交。
- 答案累加溢位。
- 加入交易費、冷卻期或交易次數上限後仍硬套原模板。

## 常見變形

**不交叉 DP 是另一條結構化捷徑，不是上述後悔堆。** [2463 最小移動總距離](https://leetcode.cn/problems/minimum-total-distance-traveled) 把機器人與工廠依位置排序。若 `a <= b` 是兩個機器人、`x <= y` 是兩個工廠槽位，交叉配對的代價
`|a-y| + |b-x|` 不小於不交叉的 `|a-x| + |b-y|`；因此存在保持順序的最優解。可定義 `dp[i][j]` 為前 `i` 個機器人使用前 `j` 個工廠的最小成本，對第 `j` 個工廠枚舉接收數量。直接轉移為 $O(RF C_{\max})$，可再以單調佇列等技巧優化；它和序列反悔堆的狀態、證明與適用前提都不同。

## 與相似技巧的比較

一般貪心不保留反悔機會；真正的費用流最通用但模板與常數較重；後悔堆利用單一可交換鍵把殘量邊壓進堆；不交叉 DP 則利用排序後的結構壓掉圖。後兩者都不是萬用最小費用流，必須各自證明交換性或不交叉性。

## 代表例題

股票序列是理解「彈出舊端點、把新端點放回作反向邊」的最小模型；[2463 最小移動總距離](https://leetcode.cn/problems/minimum-total-distance-traveled) 則用來對照另一種不交叉 DP 模擬方式。

## 本節重點速查

- 小根堆保存可配對舊端點與反向邊憑證。
- 成交時先彈出最便宜端點，再把目前值放回作反悔憑證。
- 迴圈尾端還要再放一次目前值，保留新的正向候選。
- 後悔堆需要單一可交換鍵；多維限制或交易附加規則不能直接套用。
- 不交叉 DP 是不同結構變形，需另證排序後配對不交叉。
