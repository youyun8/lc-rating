## 這個技術解決什麼問題

在一維陣列上，每個位置能一步跳到某個區間或某些特定位置，問最少跳幾次抵達終點。這是「圖論建模 + BFS」最常考的一種特例：節點是下標，邊由跳躍規則決定。

## 辨識題型的訊號

線性排列的位置、每格標了可跳距離或可跳目標、問最少次數。若改問「能不能到達」則退化成貪心可達性；若每次跳躍成本不同則是 Dijkstra。

## 核心想法與直覺

樸素做法把每個可跳目標都連一條邊，邊數可能達到 $O(n^2)$。關鍵優化是察覺 BFS 的每一層恰好是一段連續區間：第 `t` 層能覆蓋的下標形成區間 `[left, right]`，下一層的右界就是這段區間內 `i + nums[i]` 的最大值。於是不必真的建圖，用兩個指標掃過去即可，這正是「跳躍遊戲 II」的貪心解法與 BFS 分層的等價之處。

## 狀態／資料結構定義

`left`、`right` 是目前這一層（跳 `steps` 次可達）覆蓋的下標區間；`farthest` 是掃描本層時看到的下一層最遠可達位置。

## 不變量或正確性證明

不變量：進入第 `steps` 輪時，區間 `[left, right]` 恰好是「最少跳 `steps` 次可以到達」的所有下標集合。

證明可達集合確實連續：若下標 `j` 可在 `steps` 步內到達，則任何 `left <= k < j` 也可在 `steps` 步內到達，因為跳到 `j` 的最後一跳來自某個 `i`，而 `i` 能跳到 `[i, i + nums[i]]` 的每一個位置，其中包含 `k`。由此可知每層都是區間，取本層所有 `i + nums[i]` 的最大值即為下一層右界，BFS 的逐層性質保證這就是最短步數。

## 逐步演算法

初始化區間為 `[0, 0]`、步數為 0；每輪掃描區間內所有下標求出 `farthest`；把區間更新為 `[right + 1, farthest]` 並把步數加一；當右界涵蓋終點即回傳步數。

## C++17 模板

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        const int n = nums.size();
        int steps = 0, right = 0, farthest = 0;

        // 只掃到 n - 2：踏到最後一格就不需要再跳。
        for (int i = 0; i < n - 1; ++i) {
            farthest = max(farthest, i + nums[i]);
            if (i == right) {  // 本層掃完，換層
                right = farthest;
                ++steps;
            }
        }
        return steps;
    }
};
```

當跳躍目標不是連續區間（例如相同數字可互相傳送）時，回到一般 BFS，並在用過某組傳送後清空該組以免重複展開：

```cpp
unordered_map<int, vector<int>> same;  // 值 -> 下標
// ... BFS 展開 x 時
for (int y : same[arr[x]]) { /* 入隊 */
}
same[arr[x]].clear();  // 關鍵：整組只展開一次，總複雜度才是 O(n)
```

## 時間與空間複雜度

區間掃描版本每個下標只被讀一次，時間 $O(n)$、空間 $O(1)$。一般 BFS 版本為 $O(n + m)$，其中傳送組清空技巧把總邊數壓回 $O(n)$。

## 常見錯誤與邊界條件

- 迴圈掃到 `n - 1` 而多算一次跳躍。
- `n == 1` 時應回傳 0。
- `nums[i]` 可能為 0 造成原地停滯，需確認題目保證可達或另外處理。
- 傳送類題目忘記清空已用過的分組，導致複雜度退化成 $O(n^2)$。

## 與相似技巧的比較

「跳躍遊戲 I」只問可達性，維護一個最遠可達位置的貪心即可，不需要分層；本節分層貪心等價於 BFS；若每次跳躍有不同成本，區間連續性不再成立，必須改用 Dijkstra 或線段樹優化建圖。

## 本節重點速查

- 每層可達下標是連續區間
- `i == right` 就換層
- 掃到 `n - 2` 為止
- 傳送分組用完即清空。
