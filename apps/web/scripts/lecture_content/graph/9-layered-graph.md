## 這個技術解決什麼問題

最短路題目多了一個附加資源：「最多可以免費走 `k` 條邊」「最多加油 `k` 次」「可以把 `k` 條邊的權重改成 0」。分層圖把這個剩餘額度編進節點狀態，讓題目重新變成一個標準最短路。

## 辨識題型的訊號

題目在最短路的基礎上出現一個很小的整數上限 `k`（通常不超過幾百），並允許有限次數的特殊操作；或是「最多換乘 `k` 次」「至多刪除 `k` 條邊的代價」。

## 核心想法與直覺

把節點從 `x` 擴充成 `(x, j)`，其中 `j` 是已使用的特殊操作次數。整張圖等於把原圖複製 `k + 1` 層：層內走一般邊（權不變、層數不變），層間走特殊邊（權變 0 或折扣、層數加一）。在這張擴充圖上跑一次 Dijkstra 就得到答案。

## 狀態／資料結構定義

`dis[x][j]` 是「抵達節點 `x`、已使用 `j` 次特殊操作」的最短距離。節點總數為 `n * (k + 1)`，可用 `x * (k + 1) + j` 壓成一維編號。

## 不變量或正確性證明

擴充圖仍然是一張邊權非負的有向圖，因此 Dijkstra 的定案不變量原封不動成立：`(x, j)` 出堆時 `dis[x][j]` 即為最短。

建模的正確性在於狀態的完備性與無後效性：任何一條原問題的合法走法，都唯一對應擴充圖上的一條路徑（每用一次特殊操作就上升一層），反之亦然；而未來的決策只取決於「目前在哪個點、還剩多少額度」，與如何走到這裡無關。因為層數只增不減，擴充圖不會產生額外的環。答案是 `min(dis[target][j])` 取遍所有 `j`——沒用完額度同樣合法。

## 逐步演算法

決定狀態第二維的含義與上限；把起點 `(start, 0)` 入堆；展開 `(x, j)` 時，對每條邊分別嘗試「照常付費留在第 `j` 層」與「消耗一次額度進到第 `j + 1` 層」；照常跑 Dijkstra；最後在目標節點的所有層中取最小值。

## C++17 模板

以「最多可讓 `k` 條邊免費」為例：

```cpp
long long shortestPathWithFreeEdges(int n,
                                    const vector<vector<pair<int, int>>>& g,
                                    int start, int target, int k) {
    const long long kInf = LLONG_MAX;
    vector<vector<long long>> dis(n, vector<long long>(k + 1, kInf));
    dis[start][0] = 0;

    using Node = tuple<long long, int, int>;  // (距離, 節點, 已用次數)
    priority_queue<Node, vector<Node>, greater<Node>> heap;
    heap.emplace(0LL, start, 0);

    while (!heap.empty()) {
        const auto [d, x, j] = heap.top();
        heap.pop();
        if (d > dis[x][j]) {
            continue;
        }
        for (const auto& [y, w] : g[x]) {
            if (d + w < dis[y][j]) {  // 照常付費，留在本層
                dis[y][j] = d + w;
                heap.emplace(dis[y][j], y, j);
            }
            if (j < k && d < dis[y][j + 1]) {  // 用掉一次免費，上一層
                dis[y][j + 1] = d;
                heap.emplace(dis[y][j + 1], y, j + 1);
            }
        }
    }
    return *min_element(dis[target].begin(), dis[target].end());
}
```

## 時間與空間複雜度

擴充圖有 $O(nk)$ 個節點、$O(mk)$ 條邊，時間 $O(mk \log (mk))$，空間 $O(nk)$。因此本法只在 `k` 很小時可行。

## 常見錯誤與邊界條件

- 只在 `dis[target][k]` 取答案，漏掉沒用滿額度的情形。
- 狀態第二維的定義在「已使用次數」與「剩餘次數」之間混用。
- 忘記 `j < k` 的邊界檢查造成越界。
- `k` 大於實際可用邊數時應自動退化為正常最短路。
- 記憶體估算忽略了 `n * (k + 1)` 的乘積。

## 與相似技巧的比較

這是「狀態擴充」這一通用思路在最短路上的具體化，與位元遮罩 DP（把已訪問集合編進狀態）同源。若附加資源的取值連續或範圍很大，分層圖不可行，需改用其他建模（例如二分答案再驗證）。若特殊操作沒有次數限制而只是另一種邊，直接加邊即可，不必分層。

## 本節重點速查

- 狀態加一維「已用幾次」
- 層內照常付費、層間消耗額度
- 答案取遍所有層
- `k` 必須夠小。
