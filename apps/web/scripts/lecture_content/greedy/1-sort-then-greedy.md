## 這個技術解決什麼問題

從一堆元素中挑選或決定處理順序，使某個總量最優。關鍵不是「每步挑當下最好」這種模糊直覺，而是先排序，讓「當下最好」有明確且可證明的定義。

## 狀態／資料結構定義

排序後用一個指標由小到大（或由大到小）掃過陣列，維護累積量（已用預算、已選個數、當前總和）。多數題目不需額外結構。

## 不變量或正確性證明

不變量：掃描到第 `i` 個元素時，前 `i - 1` 個元素上的決策已構成「只考慮這些元素時」的最優解，且可延伸為全域最優解的一部分。

正確性用交換論證：設存在一個最優解 `OPT` 與貪心解在第一個位置產生分歧，貪心選了最小的 `a`，而 `OPT` 選了 `b`（`b >= a`）。把 `OPT` 中的 `b` 換成 `a`——因為 `a` 更小，它消耗的預算不會更多，故替換後仍然可行；而所選個數不變或更優。於是存在一個至少同樣好的最優解與貪心在此位置一致。逐位重複此論證，即可把某個最優解完全轉換成貪心解，故貪心最優。

這個論證成立的前提是「小的元素永遠不比大的差」——也就是**替換不會破壞可行性**。若題目中大元素反而有額外好處（例如同時計入另一個受限資源），前提失效，貪心不再正確，須改用 DP。

## 逐步演算法

依題意排序；由一端開始掃描；對每個元素判斷是否可取（預算是否足夠）；可取就更新累積量與答案；掃完回傳。

## C++17 模板

```cpp
// 在總預算內盡量多買：由小到大取。
int maxCount(vector<int>& costs, int budget) {
    sort(costs.begin(), costs.end());
    int taken = 0;
    for (int c : costs) {
        if (budget < c) {
            break;
        }  // 之後只會更貴，可提前結束
        budget -= c;
        ++taken;
    }
    return taken;
}
```

## 時間與空間複雜度

排序 $O(n \log n)$ 主導，掃描 $O(n)$，總計 $O(n \log n)$，空間 $O(1)$（不計排序）。

## 常見錯誤與邊界條件

- 排序方向弄反。
- 累加溢位需 `long long`。
- 提前 `break` 的條件不成立時（例如元素可為負）會漏解。
- 題目要求的是「最大總和」而非「最多個數」時排序方向相反。
- 空陣列回傳 0。

## 與相似技巧的比較

若每個元素有兩個維度（重量與價值）而需權衡，排序貪心通常失效，要用背包 DP；若選擇之間互相影響（選了 A 就不能選 B），需區間排程或圖論建模；若前面的選擇可能需要撤銷，見「反悔貪心」。

## 本節重點速查

- 先排序讓「最好」有定義
- 用交換論證檢查替換是否保持可行
- 替換不破壞可行性是前提
- 兩個維度就別用貪心。
