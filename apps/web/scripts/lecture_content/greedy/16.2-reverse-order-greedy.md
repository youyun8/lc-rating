## 這個技術解決什麼問題

構造「滿足某條件且字典序最小（或數值最小）」的答案。從左往右硬湊容易卡死，改從最低位往左掃，找到第一個可以「往上調一點」的位置動手，再把它右邊全部重設為最小，就能得到剛好大於原值的最小解。

## 狀態／資料結構定義

一個由右往左的掃描指標，加上「右側已出現過哪些值」的統計（陣列或後綴極值）。找到可調位置後，右側整段重建。

## 不變量或正確性證明

不變量：掃描到位置 `i` 時，後綴 `[i+1, n)` 已無法在不改動 `[0, i]` 的前提下變得更優。

以「下一個排列」為例，目標是找出字典序剛好比當前大的排列。從右往左找到第一個滿足 `a[i] < a[i+1]` 的位置 `i`，稱為樞紐。

為何 `i` 右邊動不了：後綴 `[i+1, n)` 依定義是非遞增的，它已是該組數字所能排出的**最大**排列，任何重排只會更小。因此要變大就必須動到 `i`。

為何 `a[i]` 要換成右側「大於它的最小者」：換上更大的值才能使整體變大，而換上其中最小者能使增幅最小，符合「剛好大於」的要求。因為後綴非遞增，從右往左第一個大於 `a[i]` 的元素就是該最小者。

為何交換後要把後綴反轉：交換後後綴仍保持非遞增（用一個更小的值替換掉原位置，不破壞單調性），而我們要的是該組數字的**最小**排列，故反轉成非遞減即可。三步合起來恰好給出字典序的直接後繼。

## 逐步演算法

從右往左找到第一個 `a[i] < a[i+1]` 的樞紐；若不存在則整個序列已是最大排列，直接反轉成最小；否則從右往左找第一個大於 `a[i]` 的元素與之交換；最後反轉 `[i+1, n)`。

## C++17 模板

```cpp
void nextPermutation(vector<int>& a) {
    const int n = a.size();
    int i = n - 2;
    while (i >= 0 && a[i] >= a[i + 1]) {
        --i;
    }  // 找樞紐

    if (i >= 0) {
        int j = n - 1;
        while (a[j] <= a[i]) {
            --j;
        }  // 右側大於 a[i] 的最小者
        swap(a[i], a[j]);
    }
    reverse(a.begin() + i + 1, a.end());  // 後綴重設為最小
}
```

## 時間與空間複雜度

三次線性掃描，時間 $O(n)$、空間 $O(1)$。

## 常見錯誤與邊界條件

- 找樞紐時用 `>` 而非 `>=`，遇到重複值會出錯。
- 忘記樞紐不存在（已是最大排列）時要整個反轉。
- 交換後用排序而非反轉（結果正確但多花 $O(n \log n)$）。
- 反轉範圍寫成 `[i, n)`。
- 單元素序列應原樣返回。

## 與相似技巧的比較

從左往右的貪心適合「每位取最小可行值」且限制簡單的構造題；倒序貪心專治「剛好大於／小於某值」這類需要精準跨越門檻的題目。若限制複雜到無法局部判定，改用數位 DP。

## 本節重點速查

- 從右找第一個上升處當樞紐
- 換成右側大於它的最小者
- 後綴反轉成最小
- 樞紐不存在就整個反轉。
