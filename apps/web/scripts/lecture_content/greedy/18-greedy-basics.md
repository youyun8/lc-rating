## 這個技術解決什麼問題

建立貪心這個思想本身的判準。貪心快又短，但只有在能證明「局部最優不會害到全域最優」時才正確——本節說明什麼時候可以用，以及怎麼檢驗。

## 狀態／資料結構定義

貪心通常只需極少的狀態：一個累積量、一個當前最優候選、或一個排序後的指標。狀態少正是它與 DP 的直觀差異。

## 不變量或正確性證明

貪心正確需要兩個性質同時成立：

**貪心選擇性質**：存在一個最優解，包含「當下的貪心選擇」。這是交換論證要證的東西——把某個最優解中與貪心不同的部分換成貪心的選擇，證明不會變差。

**最優子結構**：做完貪心選擇後，剩下的子問題的最優解與原問題的最優解可以拼接成整體最優。

兩者缺一不可。經典反例是 0-1 背包：按「單位價值」排序的貪心滿足不了貪心選擇性質——容量 10、物品為 `(重6,值10)`、`(重5,值9)`、`(重5,值9)` 時，貪心先拿單位價值最高的第一個，得 10；但最優是後兩個，得 18。因為拿走第一個之後，剩餘容量無法再被有效利用，替換論證失敗。反之，分數背包允許切割，替換總能保持可行，貪心就正確。

實務上的檢驗流程：先寫一個小規模的暴力或 DP，隨機生成資料與貪心對拍。對拍不通過就直接放棄貪心；通過了再回頭補證明。「看起來很合理」從來不是理由。

## 逐步演算法

辨識出候選的貪心規則；嘗試用交換論證證明貪心選擇性質；確認子問題結構不變；寫暴力對拍驗證；通過後再實作。

## C++17 模板

```cpp
// 貪心的骨架幾乎總是這個形狀：排序（或不排序）後單次掃描累積。
sort(items.begin(), items.end(), rule);  // rule 由交換論證推出
long long answer = 0;
for (const auto& item : items) {
    if (feasible(item)) {  // 當下可取就取
        take(item);
        answer += gain(item);
    }
}
```

## 常見錯誤與邊界條件

- 未經證明就假設貪心成立（最常見的失分點）。
- 把「多數測資通過」當成正確。
- 排序規則不可傳遞。
- 資源有多個維度時仍用單一指標排序。
- 邊界情況（空輸入、全相等、極值）未測。

## 與相似技巧的比較

貪心是 $O(n \log n)$ 且狀態極少；DP 一定正確但狀態數可能爆炸；兩者的分水嶺就是貪心選擇性質是否成立。若不確定，先寫 DP 求正確性，再觀察其決策是否呈現單調規律——若是，往往能簡化成貪心。

## 本節重點速查

- 要同時具備貪心選擇性質與最優子結構
- 用交換論證檢驗
- 一定要對拍
- 有兩個維度時多半不能貪心。

## 時間與空間複雜度

貪心的典型成本是排序主導的 $O(n \log n)$；不需排序時為 $O(n)$。空間多為 $O(1)$。這正是它相對 DP 的優勢——代價是必須先證明正確性。
