## 這個技術解決什麼問題

把一堆數字全部移動到同一個值，每移動一單位付一單位代價，求最小總代價。答案是移到**中位數**，而不是平均數。

## 狀態／資料結構定義

排序後取中位數作為目標值，再累加每個元素到它的絕對差。若題目要求的是「變成公差為 1 的遞增序列」等變形，先做座標變換（例如 `a[i] -= i`）再取中位數。

## 不變量或正確性證明

目標是最小化 $f(x) = \sum_i |a_i - x|$。

證明中位數最優：考慮把 `x` 向右移動一小段 $\delta$。對於所有滿足 $a_i < x$ 的元素（設有 `L` 個），距離各增加 $\delta$；對於 $a_i > x$ 的元素（設有 `R` 個），距離各減少 $\delta$。總變化為 $(L - R)\delta$。

因此當 `L < R` 時右移可降低代價，`L > R` 時左移可降低代價，最優點必在 `L = R` 之處——也就是左右兩側元素個數相等的位置，即中位數。偶數個元素時，中位數區間內任一點都給出相同的最小值（該區間上 `L = R`，導數為零）。

換個角度看更直觀：把最小與最大配成一對，無論 `x` 取在這對之間何處，這兩者的距離和恆為它們的差；逐層向內配對後，只剩最中間的元素（或區間），把 `x` 放在那裡即可讓最後一項為零。

平均數最小化的是**平方**距離和 $\sum (a_i - x)^2$，與本題不同，這是最容易混淆的地方。

## 逐步演算法

排序；取中位數（偶數個時取任一中間值）；累加所有元素到它的絕對差；若題目有變形先做座標變換。

## C++17 模板

```cpp
// 讓所有元素相等的最小總移動代價。
long long minMoves(vector<int>& nums) {
    sort(nums.begin(), nums.end());
    const long long median = nums[nums.size() / 2];
    long long cost = 0;
    for (int x : nums) {
        cost += llabs(x - median);
    }
    return cost;
}
```

變形：要使序列成為嚴格遞增且相鄰差為 1，先令 `a[i] -= i`，把問題化為「全部變成同一個值」，再套用本法。

## 常見錯誤與邊界條件

- 用平均數而非中位數。
- 總代價溢位需 `long long`。
- 偶數個元素時誤以為必須取兩者平均（取任一皆可，但取平均在整數下可能不是最優的整數點）。
- 變形題忘記先做座標變換。
- 未排序就取中間元素。

## 與相似技巧的比較

最小化絕對差之和用中位數；最小化平方差之和用平均數；最小化最大差則用中點（極差的一半）。三者對應不同的目標函式，套錯就全錯。若移動代價帶權重，改用加權中位數。

## 本節重點速查

- 絕對距離和用中位數
- 平方距離和才用平均數
- 偶數個取任一中間值
- 遞增變形先 `a[i] -= i`。

## 時間與空間複雜度

排序 $O(n \log n)$ 主導，累加 $O(n)$，空間 $O(1)$。若改用快速選擇找中位數可降到期望 $O(n)$。
