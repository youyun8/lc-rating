## 這個技術解決什麼問題

從最小的情形出發，一步步把「目前能做到的範圍」往外擴。每加入一個新元素就檢查它能否讓範圍變大，能就吃下。代表題是「加油站」「能湊出的最小不可達金額」「按要求補齊陣列」。

## 狀態／資料結構定義

一個表示「已覆蓋範圍」的量：可湊出的金額上界 `reach`、已連續覆蓋到的位置、目前能達到的最大值。排序後線性掃描並持續擴張。

## 不變量或正確性證明

不變量：處理完前 `i` 個元素後，`[1, reach]` 中的每個值都可以被前 `i` 個元素湊出，且 `reach + 1` 是最小的湊不出的值。

擴張條件的證明（以「用給定硬幣湊出連續金額」為例，硬幣已升序排序）：設當前可湊出 `[1, reach]`。考慮下一枚硬幣 `c`。

若 $c \le reach + 1$，則加入它後可湊範圍擴張為 $[1, reach + c]$——因為對任何 $v \in [c, reach + c]$，都有 $v - c \in [0, reach]$ 可湊出，再加上這枚硬幣即可；而 $[1, c-1]$ 原本就在 $[1, reach]$ 內（由 $c - 1 \le reach$）。故新的 `reach` 為 `reach + c`，區間依然連續。

若 $c > reach + 1$，則 `reach + 1` 這個值湊不出來——所有不大於 `reach + 1` 的硬幣都已用過且只能湊到 `reach`，而 `c` 及其後的硬幣都嚴格大於 `reach + 1`，加進來只會跳過它。因此 `reach + 1` 就是答案（或需要補一枚硬幣）。

排序是前提：若不排序，就無法保證「所有小於等於 `reach + 1` 的硬幣都已被考慮」，上述論證會失效。

## 逐步演算法

排序；`reach` 初始為 0；逐一檢查元素，若其值不超過 `reach + 1` 就併入並擴張 `reach`；否則回報斷點（或補入 `reach + 1` 這個值後重試）。

## C++17 模板

```cpp
// 用 nums 中的元素（可各取一次）能湊出的最小正整數。
long long minUnreachable(vector<int>& nums) {
    sort(nums.begin(), nums.end());
    long long reach = 0;  // [1, reach] 都湊得出
    for (int x : nums) {
        if (x > reach + 1) {
            break;
        }  // 出現斷層
        reach += x;
    }
    return reach + 1;
}
```

「最少補幾個數才能覆蓋 `[1, n]`」的變形：當出現斷層時補入 `reach + 1`，令 `reach += reach + 1`，計數加一，直到覆蓋 `n`。

## 時間與空間複雜度

排序 $O(n \log n)$ 主導，掃描 $O(n)$，空間 $O(1)$。補數變形因為 `reach` 每次至少翻倍，補的次數為 $O(\log n)$。

## 常見錯誤與邊界條件

- 未排序。
- 擴張條件寫成 `x > reach`（漏掉恰好等於 `reach + 1` 的情形）。
- `reach` 溢位需 `long long`。
- 補數變形中忘記補完後不要前進原陣列指標。
- 空陣列時答案為 1。

## 與相似技巧的比較

歸納法貪心的特徵是「維護一個連續覆蓋區間並持續擴張」，與區間覆蓋的分層貪心結構相似；若元素可重複取用無限次，則變成完全背包或裴蜀定理的問題，不能直接套用。

## 本節重點速查

- 先排序
- `x <= reach + 1` 才能擴張
- 斷點就是 `reach + 1`
- 補數時 `reach` 會翻倍故只需對數次。
