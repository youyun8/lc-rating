## 這個技術解決什麼問題

收錄「看穿一條數學規律後，貪心就變得很短」的題目。它們沒有統一模板，共同點是先用數學觀察把問題化簡，再貪心地逼近答案。

## 狀態／資料結構定義

依題而定，多半只需幾個計數器或一次排序。真正的工作在於找出那條規律，實作往往只有數行。

## 不變量或正確性證明

本節不引入單一定理，而是列出幾條最常被用到的觀察，每條都附成立條件：

**奇偶不變量**：若某個量在每次操作後奇偶性不變，則奇偶性不同的目標狀態不可達。這是構造題判定無解的首選工具。

**總和守恆**：若操作只在元素間搬移數值而不改變總和，則目標狀態的總和必須與初始相同；由此常可直接算出答案或判定無解。例如「使所有元素相等」的可行條件是總和能被 `n` 整除。

**貪心界的夾擊**：先證明答案不可能優於某個下界（通常由某個守恆量或計數論證給出），再構造一個達到該界的方案。兩邊相符即得最優，這是構造類貪心最可靠的證明格式。

**位元獨立性**：若各個位元互不影響，可逐位獨立決策再合併。成立條件是操作不會在位元間產生進位。

使用時務必先驗證前提。例如總和守恆只在操作確實不改變總和時成立；一旦題目允許「增加或減少任意值」，這條就失效。

## 逐步演算法

先手算小規模樣例找規律；嘗試用上述某條觀察給出下界；構造一個達到下界的方案；用暴力對拍驗證；再實作。

## C++17 模板

```cpp
// 典型形態：先用守恆量判定可行性，再用一次掃描算出答案。
long long minOperations(vector<int>& nums) {
    const long long total = accumulate(nums.begin(), nums.end(), 0LL);
    const int n = nums.size();
    if (total % n != 0) {
        return -1;
    }  // 總和守恆：不整除即無解

    const long long target = total / n;
    long long moves = 0;
    for (int x : nums) {
        if (x > target) {
            moves += x - target;
        }  // 只數「搬出」的量，避免重複計
    }
    return moves;
}
```

## 常見錯誤與邊界條件

- 把觀察到的規律當成已證結論。
- 守恆量用錯（總和與奇偶是不同的量）。
- 把搬入與搬出都計入而使答案加倍。
- 溢位需 `long long`。
- 未驗證可行性就直接輸出答案。

## 與相似技巧的比較

有明確規律時本法最短；找不到規律時退回 DP 或搜尋。建議固定流程：小資料暴力打表 → 觀察 → 猜規律 → 對拍 → 證明。跳過對拍是這類題最常見的翻車原因。

## 本節重點速查

- 先找守恆量或不變量
- 用下界加構造證最優
- 規律一定要對拍
- 搬移類題目只數單向的量。

## 時間與空間複雜度

多數為一次掃描的 $O(n)$，空間 $O(1)$；若需先排序則為 $O(n \log n)$。
