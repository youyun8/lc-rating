## 這個技術解決什麼問題

問題太大看不出頭緒時，先縮到最特殊、最簡單的情形手算一遍，從中找出規律，再推廣到一般。這不是特定演算法，而是一套推導流程。

## 狀態／資料結構定義

沒有固定結構。實務上會準備一張小規模的打表結果（`n = 1, 2, 3, 4` 的答案），以及一份暴力解用來對拍。

## 不變量或正確性證明

這套方法本身不提供正確性，它只產生**猜想**。因此流程必須包含驗證環節，否則等於沒有證明：

1. **打表**：對 `n = 1, 2, 3, …` 用暴力求出答案，觀察數列。
2. **猜規律**：找出封閉式或遞推關係。
3. **驗證**：用更大的 `n` 對拍，確認猜想在超出打表範圍時仍成立。
4. **證明**：對規律做歸納——證明基礎情形成立，並證明「若 `n` 成立則 `n+1` 成立」。

第 4 步才是把猜想升級為結論的關鍵。歸納的標準形式是：假設前 `k` 個情形的答案符合猜想，說明第 `k+1` 個情形如何由前面組合而來，且組合方式恰好產生猜想中的下一項。

常見的陷阱是規律在小範圍成立但在某個閾值後失效——例如前幾項恰好符合某個多項式，實則答案另有分段。只打表到 `n = 4` 就下結論，是這類題最常見的翻車方式；至少要驗到規律穩定數項之後。

## 逐步演算法

寫暴力；對小 `n` 打表；觀察數列（查差分、比值、是否為已知數列）；提出猜想；用較大的 `n` 對拍；補上歸納證明；實作。

## C++17 模板

```cpp
// 打表骨架：先用暴力產生前若干項，再觀察規律。
int bruteForce(int n);  // 指數級也無所謂，只跑小 n

void printTable(int maxN) {
    for (int n = 1; n <= maxN; ++n) {
        cout << n << " -> " << bruteForce(n) << '\n';
    }
}
```

觀察時的常用檢查：一階差分是否為常數（線性）、二階差分是否為常數（二次）、相鄰比值是否固定（指數）、是否符合費波那契或卡塔蘭數。

## 常見錯誤與邊界條件

- 打表範圍太小就下結論。
- 暴力本身寫錯導致規律建立在錯誤資料上。
- 規律在邊界（`n = 0` 或 `n = 1`）失效卻未特判。
- 只驗證不證明就交出去。
- 忽略答案可能依輸入的其他性質分段。

## 與相似技巧的比較

從特殊到一般用來**發現**規律；交換論證與歸納法用來**證明**規律；對拍用來**驗證**規律。三者是互補的環節，缺任何一環都不牢靠。若規律遲遲找不到，通常代表問題本身需要 DP 而非封閉式。

## 本節重點速查

- 先暴力打表再猜規律
- 打表範圍要夠大
- 猜想必須經對拍與歸納
- 邊界情形要單獨驗。

## 時間與空間複雜度

打表階段用暴力，成本不限（只跑小 $n$）；找到規律後正式解通常是 $O(1)$ 或 $O(n)$。
