## 這個技術解決什麼問題

正面硬解看起來要模擬一大堆操作，但只要看穿背後的關鍵性質，答案往往是一條公式或一兩行掃描。重點不在演算法複雜，而在觀察角度。

## 狀態／資料結構定義

通常只需一兩個變數。若還需要複雜的資料結構，多半代表關鍵性質尚未被找到。

## 不變量或正確性證明

這類題的解法幾乎都建立在一個**操作不變量**上——某個量在每次操作後保持不變或單調變化，於是最終狀態被它完全決定，過程可以整段跳過。

尋找不變量的固定問法：

- 每次操作後，**總和**有什麼變化？固定？減少固定量？
- **奇偶性**是否不變？某個模數下的餘數是否不變？
- 是否存在一個**單調量**（只增不減），使過程必然終止？
- 若把元素重新編號或換個座標系，問題會不會變簡單？

舉例：一堆石頭每次任取兩顆對撞、剩下差值放回，問最後剩下什麼。直接模擬是指數級；但注意每次操作後「總和的奇偶性」不變（`a + b` 與 `|a - b|` 同奇偶），故最終單一石頭的奇偶性等於初始總和的奇偶性——這把問題降為 $O(n)$，而剩下的最小值問題則化為「把石頭分成兩堆使差最小」的背包。

證明的標準格式是：先用不變量給出答案的**下界**（或可行性限制），再構造一個達到該界的操作序列作為**上界**，兩者相符即得答案。只有下界沒有構造，等於只證明了一半。

## 逐步演算法

列出一次操作前後有哪些量改變、哪些不變；挑出不變量並推導它對最終狀態的限制；構造一個達到該限制的方案；對拍驗證。

## C++17 模板

```cpp
// 典型形態：找到不變量後，答案往往只是一次掃描。
int lastStoneWeight(vector<int>& stones) {
    const int total = accumulate(stones.begin(), stones.end(), 0);
    // 奇偶性守恆 + 分成兩堆使差最小 -> 背包
    vector<bool> reachable(total / 2 + 1, false);
    reachable[0] = true;
    for (int s : stones) {
        for (int j = total / 2; j >= s; --j) {
            reachable[j] = reachable[j] || reachable[j - s];
        }
    }
    for (int j = total / 2; j >= 0; --j) {
        if (reachable[j]) {
            return total - 2 * j;
        }
    }
    return total;
}
```

## 常見錯誤與邊界條件

- 找到不變量就直接交答案，忘了還要構造達成方案。
- 把「必要條件」誤當「充分條件」。
- 不變量其實會被某種操作破壞卻未察覺。
- 沒有對拍就相信自己的觀察。
- 邊界情形（只有一個元素、全部相等）未驗。

## 與相似技巧的比較

腦筋急轉彎與「其他數學貪心」高度重疊，差別只在前者更強調「換角度看」而非「套公式」；若怎麼看都找不到不變量，退回 DP 或搜尋加剪枝，不要硬凹。

## 本節重點速查

- 先問一次操作改變了什麼、保住了什麼
- 不變量給下界、構造給上界
- 兩者相符才算證完
- 務必對拍。

## 時間與空間複雜度

找到不變量後多半是 $O(n)$ 一次掃描、$O(1)$ 空間；若仍需搭配背包等 DP，則為該 DP 的成本。
