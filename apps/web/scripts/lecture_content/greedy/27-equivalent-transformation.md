## 這個技術解決什麼問題

把難算的問題換成一個「答案完全相同、但好算很多」的等價問題。換個說法之後，原本卡住的題目往往就變成熟悉的套路。

## 狀態／資料結構定義

依轉換後的問題而定。轉換本身通常是一次線性預處理：做差分、取前綴和、座標平移、補集轉換。

## 不變量或正確性證明

等價轉換的正確性要求是**雙射或保序對應**：原問題的每個可行解都對應轉換後問題的一個可行解，反之亦然，且對應的目標值相等（或差一個常數）。只有兩個方向都成立，最優解才會互相對應。

幾個高頻轉換與各自的依據：

- **差分**：把「區間加值」變成「兩點修改」。依據是差分與前綴和互為逆運算，故解一一對應。注意還原時要掃回前綴和。
- **補集**：把「最多保留幾個」換成「最少刪除幾個」。依據是兩者之和恆為總數，故最大化其一等於最小化另一。
- **座標平移**：把「使序列嚴格遞增」換成「使序列全部相等」，方法是令 `a[i] -= i`。依據是這個變換是雙射，且嚴格遞增等價於變換後非遞減；若要求相鄰差恰為 1 則等價於變換後全等。
- **取反**：把最大化換成最小化，只需把所有值取負。

轉換前務必檢查邊界是否也對應——例如座標平移後元素可能變成負數，若題目限制為正整數，轉換就不是雙射，結論會出錯。這是最常見的失誤來源。

## 逐步演算法

寫下原問題的目標與限制；尋找一個能保持解集對應的變換；驗證雙向對應與目標值關係；在轉換後的問題上求解；把解映射回原問題。

## C++17 模板

```cpp
// 差分：把「對 [l, r] 全部加 v」變成兩點修改，最後一次前綴和還原。
vector<long long> applyRangeUpdates(int n,
                                    const vector<array<int, 3>>& updates) {
    vector<long long> diff(n + 1, 0);
    for (const auto& [l, r, v] : updates) {
        diff[l] += v;
        diff[r + 1] -= v;  // 右端點外一格扣回
    }
    for (int i = 1; i < n; ++i) {
        diff[i] += diff[i - 1];
    }  // 還原
    diff.resize(n);
    return diff;
}
```

## 常見錯誤與邊界條件

- 轉換不是雙射（漏掉某些解或多出不合法解）。
- 差分右端點寫成 `r` 而非 `r + 1`。
- 座標平移後違反題目對值域的限制。
- 補集轉換時總數算錯。
- 還原時忘記做前綴和。

## 與相似技巧的比較

等價轉換與「腦筋急轉彎」的差別在於前者有明確的變換公式可驗證，後者靠觀察不變量；若找不到保持等價的變換，就只能直接面對原問題。轉換成功時往往能把 $O(n^2)$ 直接降到 $O(n)$，是性價比極高的一步。

## 本節重點速查

- 轉換必須雙向對應且目標值一致
- 差分要扣 `r + 1`
- 平移後檢查值域限制
- 補集轉換注意總數。

## 時間與空間複雜度

轉換本身通常是 $O(n)$ 的線性預處理，之後成本取決於轉換後的問題。差分寫法為 $O(n + m)$，其中 $m$ 為更新次數。
