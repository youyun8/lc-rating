## 這個技術解決什麼問題

題目不斷刪除或破壞元素，每刪一次就要查詢當下的結果。刪除很難維護——並查集不支援拆分、連通性無法回退。把時間倒過來，刪除就變成加入，一切迎刃而解。

## 狀態／資料結構定義

先把所有操作讀完，記下最終狀態；再由最後一個操作往前處理，每步「加回」一個元素並更新資料結構（通常是並查集）；把每步的答案存進陣列，最後反轉輸出。

## 不變量或正確性證明

不變量：倒序處理到第 `i` 個操作時，資料結構的狀態恰好等於「正序執行完前 `i-1` 個操作後」的狀態。

正確性來自刪除與加入的對稱性：設操作序列為 $o_1, \ldots, o_m$，正序在執行完 $o_1 \ldots o_i$ 後的存活集合為 $S_i$。倒序從 $S_m$ 出發，第 `k` 步加回 $o_{m-k+1}$ 所刪除的元素，得到的集合恰為 $S_{m-k}$。因此倒序第 `k` 步結束時的狀態，正是正序第 `m-k` 步的狀態，兩者一一對應。

之所以值得這樣做，是因為許多資料結構對「加入」是均攤高效的，對「刪除」卻沒有對應操作。並查集是最典型的例子：`merge` 近似 $O(\alpha(n))$，但無法拆分已合併的集合。倒序把不可行的刪除轉成可行的加入，複雜度從「無法維護」變成線性對數級。

要注意的前提是**操作序列必須事先全部已知**（離線）。若是強制在線的題目（下一個詢問依賴前一個答案），無法先讀完所有操作，本法不適用。

## 逐步演算法

讀入全部操作；建構最終狀態的資料結構；由後往前逐一「還原」被刪除的元素並更新答案；把答案陣列反轉後輸出。

## C++17 模板

```cpp
// 依序刪除格子，問每次刪除後何時不再連通（倒序：加回格子並合併）。
vector<int> solveOffline(int n, const vector<int>& removals) {
    UnionFind uf(n);
    vector<bool> active(n, false);

    // 先建立「全部刪完」之後的狀態
    for (int x : removals) {
        active[x] = false;
    }

    vector<int> answers;
    for (int i = removals.size() - 1; i >= 0; --i) {
        const int x = removals[i];
        active[x] = true;  // 加回
        for (int y : neighbors(x)) {
            if (active[y]) {
                uf.merge(x, y);
            }  // 只與已存在的鄰居合併
        }
        answers.push_back(uf.cc);  // 記下此刻的答案
    }
    reverse(answers.begin(), answers.end());  // 倒回正序
    return answers;
}
```

## 常見錯誤與邊界條件

- 忘記把答案陣列反轉。
- 初始狀態沒有正確設成「全部刪完」之後。
- 加回時與尚未加回的鄰居合併。
- 題目是強制在線卻用了離線做法。
- 答案應記錄在加回之前還是之後，需依題意對齊一格。

## 與相似技巧的比較

倒序處理適用於「只刪不加」的離線題；若刪除與加入交錯出現，需要可撤銷並查集（按秩合併不做路徑壓縮，用堆疊記錄操作）或線段樹分治，成本升為 $O(n \log^2 n)$。若強制在線則只能用支援刪除的結構。

## 本節重點速查

- 刪除倒過來就是加入
- 必須離線
- 初始態是全刪完之後
- 答案記得反轉。

## 時間與空間複雜度

倒序掃描一遍，配合並查集為 $O(n \alpha(n))$；空間 $O(n)$ 存放操作序列與答案。
