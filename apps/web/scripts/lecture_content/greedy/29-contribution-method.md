## 這個技術解決什麼問題

要把「所有子陣列、所有子序列、所有配對」的某個量加總。直接列舉有 $O(n^2)$ 或 $2^n$ 個對象，逐一計算不可行。貢獻法反過來問：**每個元素被計入了幾次**，再把「值 × 次數」相加。

## 狀態／資料結構定義

通常只需一次排序或一次掃描，加上組合數或前綴統計。關鍵是為每個元素算出它的「權重」——它在多少個對象中出現，或在多少個對象中扮演特定角色（最大值、最小值）。

## 不變量或正確性證明

貢獻法的依據是求和的交換律：

$$\sum_{\text{對象}} f(\text{對象}) = \sum_{\text{元素}} (\text{該元素的貢獻總和})$$

只要每個「元素在某對象中的貢獻」被恰好計算一次，兩種求和順序必然相等。因此正確性完全取決於**分類是否互斥且窮盡**。

以「所有子陣列的和」為例：元素 `a[i]` 出現在多少個子陣列中？子陣列由左右端點決定，左端點有 `i + 1` 種選擇（`0` 到 `i`），右端點有 `n - i` 種（`i` 到 `n-1`），故出現次數為 $(i+1)(n-i)$。總和即 $\sum_i a_i (i+1)(n-i)$，$O(n)$ 完成。

以「所有子序列的最大值之和」為例：先排序，則元素 `a[i]`（升序第 `i` 個）作為最大值的子序列，其餘元素只能從比它小的 `i` 個中任選，共 $2^i$ 個。故答案為 $\sum_i a_i \cdot 2^i$。這裡排序是關鍵——它讓「誰比誰小」變成單純的下標比較，分類才互斥。

若元素有重複值，「誰當最大值」會產生歧義，必須用「相同值時取下標較小者」之類的規則打破平手，否則會重複計數。

## 逐步演算法

確定每個元素的角色（單純成員、最大值、最小值）；算出它扮演該角色的對象個數；把值乘上個數累加；必要時先排序或用單調堆疊求出左右邊界。

## C++17 模板

```cpp
// 所有子陣列的元素和之總和。
long long sumOfAllSubarrays(const vector<int>& a) {
    const long long n = a.size();
    long long total = 0;
    for (long long i = 0; i < n; ++i) {
        total +=
            1LL * a[i] * (i + 1) * (n - i);  // 左端點 i+1 種、右端點 n-i 種
    }
    return total;
}
```

若要算「所有子陣列的最小值之和」，用單調堆疊求出每個元素作為最小值的左右邊界 `[l, r]`，貢獻為 $a_i \cdot (i - l) \cdot (r - i)$。

## 常見錯誤與邊界條件

- 計數重複或遺漏（相同值未打破平手是最常見的原因）。
- 左右端點個數算錯（應為 `i + 1` 與 `n - i`）。
- 乘積溢位需 `long long` 並注意連乘順序。
- 子序列題忘記先排序。
- 取模時中間結果未及時取模。

## 與相似技巧的比較

貢獻法把「枚舉對象」換成「枚舉元素」，與前綴和的差異在於它處理的是計數而非區間查詢；當每個元素的貢獻需要知道左右邊界時，配合單調堆疊；當貢獻依賴排名時，配合樹狀陣列。

## 本節重點速查

- 改問每個元素被算幾次
- 分類要互斥且窮盡
- 重複值必須打破平手
- 子陣列端點數是 `(i+1)(n-i)`。

## 時間與空間複雜度

單次掃描為 $O(n)$；若需先排序或配合單調堆疊求邊界，則為 $O(n \log n)$ 與 $O(n)$。空間 $O(n)$。
