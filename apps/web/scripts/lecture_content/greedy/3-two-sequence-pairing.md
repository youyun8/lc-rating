## 這個技術解決什麼問題

有兩個序列，要用一邊的元素去匹配另一邊，使成功配對數最多或總收益最好。代表題是「分發餅乾」「田忌賽馬」「用最小的牌壓過對方」。

## 狀態／資料結構定義

兩邊各自排序後，用兩個同向指標 `i`、`j` 依序推進。滿足條件就同時前進並計入答案，否則只推進「無法滿足」的那一側。

## 不變量或正確性證明

不變量：處理到 `(i, j)` 時，已配成的對數等於「只用兩邊各自前綴」所能達到的最大配對數。

貪心規則是「用剛好夠用的資源去滿足最容易滿足的需求」。以分發餅乾為例（餅乾尺寸 `s`、孩子胃口 `g`，`s[j] >= g[i]` 才能滿足）：把兩邊都排序，對當前胃口最小的孩子，用**能滿足他的最小餅乾**。

交換論證：設某最優解中，胃口最小的孩子 `i` 被分到餅乾 `b`，而貪心選的是最小可用餅乾 `a`（`a <= b`）。若 `b` 在最優解中被用於 `i`，把它換成 `a`：`a >= g[i]` 故仍可行；而 `b` 被釋放出來，它比 `a` 大，能滿足的孩子集合是 `a` 的超集，所以原本使用 `a` 的那個孩子（若有）改用 `b` 依然可行。替換後配對數不減，故存在與貪心一致的最優解。

若當前餅乾連最小胃口都滿足不了，它對任何孩子都無用，可直接丟棄——這說明只推進 `j` 是安全的。

## 逐步演算法

兩個序列各自排序；雙指標從頭開始；若當前資源能滿足當前需求則配成一對、兩指標同時前進；否則只前進資源指標；任一側走完即結束。

## C++17 模板

```cpp
// 分發餅乾：g 為孩子胃口，s 為餅乾尺寸，求最多滿足幾個孩子。
int findContentChildren(vector<int>& g, vector<int>& s) {
    sort(g.begin(), g.end());
    sort(s.begin(), s.end());
    size_t i = 0;  // 孩子指標

    for (size_t j = 0; j < s.size() && i < g.size(); ++j) {
        if (s[j] >= g[i]) {
            ++i;
        }  // 滿足了就換下一個孩子
    }
    return static_cast<int>(i);
}
```

田忌賽馬的變形：若當前最小者贏不了對方最小者，就用它去消耗對方最大者（棄子），同樣是相向雙指標。

## 時間與空間複雜度

兩次排序 $O(n \log n + m \log m)$ 主導，掃描 $O(n + m)$，空間 $O(1)$。

## 常見錯誤與邊界條件

- 只推進一側或兩側都推進而漏配。
- 排序方向不一致。
- 某一側為空時未處理。
- 把「最多配對數」與「最大總收益」混淆——後者可能需要不同的配對規則（見排序不等式）。
- 重複元素造成重複計數。

## 與相似技巧的比較

單序列配對用相向雙指標，雙序列配對用同向雙指標，方向不同但都靠排序建立可交換性；若配對關係不是由大小決定而是任意的相容圖，就必須用二分圖匹配。

## 本節重點速查

- 兩邊都排序
- 用剛好夠用的去滿足最容易的
- 滿足不了的資源可直接丟棄
- 同向雙指標各推進一次。
