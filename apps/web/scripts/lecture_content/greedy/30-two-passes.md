## 這個技術解決什麼問題

每個位置的答案同時受左右鄰居牽制，一次掃描顧得了一邊就顧不了另一邊。解法是掃兩遍：先由左往右滿足左側約束，再由右往左滿足右側約束，最後合併。代表題是「分發糖果」「接雨水」。

## 狀態／資料結構定義

兩個輔助陣列 `left[i]`、`right[i]`，分別記錄只考慮單側約束時的最小可行值（或最大高度）。最終答案由兩者取 `max`（或相減）。

## 不變量或正確性證明

不變量：第一遍結束後，`left[i]` 是「僅滿足左側約束」的最小可行值；第二遍結束後，`right[i]` 是「僅滿足右側約束」的最小可行值。

合併取 `max` 的正確性（以分發糖果為例：每人至少 1 顆，評分較高者要比相鄰者多）：

**可行性**：取 $c_i = \max(left_i, right_i)$。對任一相鄰對，若 `i` 的評分高於 `i-1`，則由第一遍知 $left_i \ge left_{i-1} + 1$，故 $c_i \ge left_i \ge left_{i-1} + 1$；同時 $c_{i-1}$ 可能來自 `right`，但那一側的約束由第二遍保證。逐一檢查兩個方向的約束，都能由對應那一遍的建構滿足，故 `c` 可行。

**最優性**：任何可行解 `d` 必須同時滿足左右兩側約束。只考慮左側約束時，`left` 是逐項最小的可行解（歸納可證：$left_0 = 1$ 是下界，且每步只加最小的必要增量），故 $d_i \ge left_i$；同理 $d_i \ge right_i$。於是 $d_i \ge \max(left_i, right_i) = c_i$，總和也不小於 `c` 的總和。可行且逐項最小，故最優。

關鍵在於「兩側約束互相獨立，可以分別求下界再取最大」——若兩個約束會互相牽動（滿足一邊會破壞另一邊），本法失效。

## 逐步演算法

第一遍由左往右，只看左鄰居，滿足約束的最小值寫入 `left`；第二遍由右往左，只看右鄰居寫入 `right`；逐位取 `max`（或依題意相減）得到答案。

## C++17 模板

```cpp
// 分發糖果：每人至少 1 顆，評分高者比相鄰者多。
int candy(vector<int>& ratings) {
    const int n = ratings.size();
    vector<int> left(n, 1), right(n, 1);

    for (int i = 1; i < n; ++i) {  // 只顧左側
        if (ratings[i] > ratings[i - 1]) {
            left[i] = left[i - 1] + 1;
        }
    }
    for (int i = n - 2; i >= 0; --i) {  // 只顧右側
        if (ratings[i] > ratings[i + 1]) {
            right[i] = right[i + 1] + 1;
        }
    }

    int total = 0;
    for (int i = 0; i < n; ++i) {
        total += max(left[i], right[i]);
    }
    return total;
}
```

接雨水同理：`leftMax` 與 `rightMax` 各掃一遍，每格積水為 `min(leftMax[i], rightMax[i]) - height[i]`。

## 時間與空間複雜度

兩次掃描加一次合併，時間 $O(n)$、空間 $O(n)$。接雨水可用相向雙指標把空間降到 $O(1)$。

## 常見錯誤與邊界條件

- 第二遍的迴圈方向或起始下標寫錯。
- 合併時用相加而非取 `max`（會超發）。
- 初始值未設為 1（或 0）。
- 接雨水時忘記減去自身高度或未擋住負值。
- 單元素陣列應直接回傳。

## 與相似技巧的比較

兩次掃描適用於「左右約束獨立」的題目；若約束互相牽動則需 DP 或迭代到收斂；若只需要左右極值而非逐位答案，單調堆疊往往能一次掃完並降到 $O(1)$ 空間。

## 本節重點速查

- 左右各掃一遍再取 `max`
- 每遍只顧單側
- 兩側約束必須獨立
- 接雨水可用雙指標省空間。
