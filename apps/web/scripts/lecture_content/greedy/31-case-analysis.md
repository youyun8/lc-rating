## 這個技術解決什麼問題

沒有單一公式能涵蓋所有輸入時，把輸入切成幾類互斥的情形，每類各自給出處理方式。硬套單一模板必錯，正確策略是把分類窮盡並逐一處理。

## 狀態／資料結構定義

通常只需先算出幾個判別量（長度、正負個數、零的個數、首尾關係），再依它們分支。實作上建議把每個分支寫成獨立區塊，避免條件層層巢狀。

## 不變量或正確性證明

分類討論的正確性只有兩個要求，但兩者都必須嚴格成立：

**互斥**：任何輸入至多落入一類，否則不同分支可能給出矛盾的答案。
**窮盡**：任何輸入至少落入一類，否則會有輸入無人處理，導致回傳未初始化的值或走到預期外的路徑。

驗證方式是把判別量的所有取值列成表格，逐格確認恰有一個分支涵蓋它。例如以「正數個數的奇偶」與「是否含零」分類，就要確認四種組合都有對應處理。

每個分支內部仍需各自證明。分類只是把問題拆小，不會自動帶來正確性——常見的錯誤是分類做得很仔細，某個分支內的貪心卻沒有驗證。

實務上的檢驗手段是對拍：隨機生成能觸及所有分支的資料（刻意構造零、負數、全相等、長度為 1 的輸入），與暴力比對。若某個分支從未被觸發，代表分類可能有冗餘或測資不足。

## 逐步演算法

列出所有判別量；畫出取值組合表；確認互斥且窮盡；為每格寫出處理方式並各自論證；用涵蓋所有分支的測資對拍。

## C++17 模板

```cpp
// 依判別量分支，每個分支獨立處理，最後必有 return。
long long solve(const vector<int>& a) {
    const int negatives =
        count_if(a.begin(), a.end(), [](int x) { return x < 0; });
    const bool hasZero = find(a.begin(), a.end(), 0) != a.end();

    if (negatives % 2 == 0) {
        return handleEvenNegatives(a);  // 負數成對，可全部轉正
    }
    if (hasZero) {
        return handleOddWithZero(a);  // 有零可吸收掉一個負號
    }
    return handleOddNoZero(a);  // 必須犧牲絕對值最小的負數
}
```

## 常見錯誤與邊界條件

- 分類有遺漏（最常見，且往往出現在極端輸入上）。
- 分支重疊而順序決定結果，卻未意識到這個隱含優先權。
- 某個分支內的邏輯未經驗證。
- `if-else` 鏈最後沒有 `else` 導致無回傳值。
- 測資未涵蓋所有分支。

## 與相似技巧的比較

若分類數量爆炸（超過五六類且互相糾纏），通常代表建模角度不對，應考慮換一個等價轉換讓情形合併；若分類依賴的是「前面做了什麼決定」，那是狀態而非分類，應改用 DP。

## 本節重點速查

- 分類必須互斥且窮盡
- 列表格逐格確認
- 每個分支仍要各自證明
- 測資要能打到每一支。

## 時間與空間複雜度

判別量通常 $O(n)$ 算出，各分支多為 $O(n)$ 或 $O(n \log n)$，總成本取決於最貴的那一支。
