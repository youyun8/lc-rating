## 這個技術解決什麼問題

貪心章節的雜項綜合。這些題用得到貪心精神，但不剛好落入區間排程、反悔、字典序等標準小節。共同點是先觀察出一條可證明安全的局部規則，再照著走到底。

## 狀態／資料結構定義

依題而定，多半是一次排序加線性掃描，或一個堆。若需要複雜結構，通常代表這題其實不是貪心。

## 不變量或正確性證明

面對不熟悉的貪心題，按固定順序檢查以下四點，能涵蓋本章絕大多數題型：

**其一，順序有沒有意義。** 若元素可任意重排，就往「排序後掃描」想，並用交換論證推出比較器；若順序固定不可打亂，就往「單向掃描累積」想。

**其二，決策會不會後悔。** 若早期的選擇可能被後來更好的取代，加一個堆做反悔貪心；若不會，單純貪心即可。

**其三，有沒有守恆量或不變量。** 操作類與構造類題目，先問「一次操作改變了什麼、保住了什麼」，用它給出下界，再構造達到下界的方案。

**其四，是不是其實該用 DP。** 若資源有兩個以上維度、或當前決策會影響後續可用的選項集合，貪心選擇性質多半不成立。這時貪心會在某些測資上錯得很隱蔽——正是必須對拍的理由。

無論走哪條路，交出去之前都要用暴力對拍。貪心是本章最容易「看起來對但其實錯」的一類解法，測資通過不等於證明成立。

## 逐步演算法

判斷順序是否可變；推出候選的局部規則；用交換論證或不變量論證檢驗；寫暴力對拍；通過後才實作正式版本。

## C++17 模板

```cpp
// 貪心題的通用骨架與檢驗流程。
sort(items.begin(), items.end(), rule);  // rule 必須由交換論證推出
long long answer = 0;
for (const auto& item : items) {
    if (canTake(item)) {
        take(item);
        answer += gain(item);
    } else if (betterThanWorstTaken(item)) {
        swapOutWorst(item);
    }  // 需要反悔時
}
```

| 題目特徵         | 對應手法       | 證明工具           |
| ---------------- | -------------- | ------------------ |
| 可任意重排       | 排序後掃描     | 交換論證           |
| 順序固定         | 單向掃描累積   | 迴圈不變量         |
| 早期選擇可能吃虧 | 堆 + 反悔      | 費用流的增廣論證   |
| 區間輸入         | 依題型選排序鍵 | 交換或下界夾擊     |
| 操作類、構造類   | 找守恆量       | 下界加構造         |
| 資源有多維度     | 改用 DP        | 貪心選擇性質不成立 |

## 時間與空間複雜度

多數為排序主導的 $O(n \log n)$；帶堆的反悔貪心同樣是 $O(n \log n)$；單向掃描為 $O(n)$。空間 $O(1)$ 到 $O(n)$。

## 常見錯誤與邊界條件

- 未經證明就套用貪心。
- 比較器不可傳遞。
- 累加溢位。
- 極端輸入（空、全相等、單元素、含零與負數）未測。
- 把「多數測資通過」當成正確。

## 與相似技巧的比較

貪心與 DP 的分水嶺是貪心選擇性質。實務建議：不確定時先寫 DP 確保正確，再觀察它的決策是否呈現單調規律；若是，往往能簡化成貪心，且此時你已經有一份現成的對拍程式。

## 本節重點速查

- 先問順序可否改變、決策會否後悔
- 有守恆量就用下界加構造
- 多維資源就改 DP
- 一律對拍。
