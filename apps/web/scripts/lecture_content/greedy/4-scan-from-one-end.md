## 這個技術解決什麼問題

資料順序本身有意義、不能排序打亂時，從一端逐格掃到另一端，每格立刻做決定且不反悔。代表題是「跳躍遊戲」「加油站」「買賣股票」。

## 狀態／資料結構定義

一個掃描指標加上少量累積量：目前可達的最遠位置、累積油量、歷史最低價。所有狀態都只依賴「已掃過的前綴」。

## 不變量或正確性證明

不變量：掃描到位置 `i` 時，累積量恰好是「只看前綴 `[0, i]`」所能達到的最優值。

以跳躍遊戲的可達性為例，維護 `reach` 為目前能到達的最遠下標。不變量是：`reach` 等於「從起點出發、只用前 `i` 個位置起跳」所能觸及的最遠位置。

證明可達區間是連續的：若位置 `j` 可達，則所有 `k < j` 也可達——因為抵達 `j` 的最後一跳來自某個 `p`，而從 `p` 可以跳到 `[p, p + nums[p]]` 中的任一格，其中包含 `k`。因此「可達集合」永遠是一個前綴區間，只需記錄它的右端點。於是掃描時只要 `i <= reach` 就表示 `i` 可達，可以用它更新 `reach = max(reach, i + nums[i])`；一旦 `i > reach` 就永遠無法前進，可立即回報失敗。

加油站題的不變量則是：若從起點 `s` 出發在 `i` 處耗盡油量，則 `[s, i]` 之間任一點都不可能作為可行起點——因為從中途出發的累積油量恆不大於從 `s` 出發的累積量（少了前段的正結餘）。故可直接把候選起點跳到 `i + 1`，使整體只需一次掃描。

## 逐步演算法

初始化累積量；由一端逐格掃描；每格先判斷是否仍可行（或更新答案），再用當前元素更新累積量；掃完回傳。

## C++17 模板

```cpp
// 跳躍遊戲：能否從第 0 格到達最後一格。
bool canJump(vector<int>& nums) {
    int reach = 0;
    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        if (i > reach) {
            return false;
        }  // 這一格根本到不了
        reach = max(reach, i + nums[i]);
    }
    return true;
}
```

## 時間與空間複雜度

單次掃描，時間 $O(n)$、空間 $O(1)$。

## 常見錯誤與邊界條件

- 先更新 `reach` 再判斷可達性，使不可達的位置也參與更新。
- 掃到最後一格才判斷而漏掉中途中斷。
- 累積量初始值設錯。
- 加油站題忘記先檢查總油量是否足夠（不足時無解）。
- 單元素陣列應直接回傳可行。

## 與相似技巧的比較

排序後貪心適用於順序無關的題目；本節適用於順序有意義者，兩者的可交換性來源完全不同。

和 DP 的分界在於「前綴能否被一個支配性的摘要完整代表」。跳躍遊戲只需 `reach`：到得較近且不比 `reach` 遠的歷史狀態都被支配，留下它們不會改變未來答案，因此是 $O(1)$ 狀態的貪心。若同一位置仍有多個互不支配的可能（例如不同成本、剩餘資源或選取次數會導致不同未來），就要明確定義 `dp[i][state]`，不能只保留單一前綴最值。可用 [55 跳躍遊戲](https://leetcode.cn/problems/jump-game) 的 `reach` 與帶交易次數限制的股票 DP 對照。

若需要回頭修正先前決定，見「反悔貪心」；若每格轉移代價不同且要求最小值，通常改用 DP 或最短路。

## 本節重點速查

- 順序有意義就不能排序
- 先判斷可行再更新
- 可達集合是連續前綴
- 耗盡處之前的點都不能當起點。
