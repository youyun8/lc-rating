## 這個技術解決什麼問題

答案同時受兩個變數牽動，直接一起最佳化很難。先枚舉其中一個並固定，另一個往往就退化成一個容易求的最值，掃過所有枚舉值取最好即可。

## 狀態／資料結構定義

外層枚舉變數（分割點、選取個數、某個閾值、答案的某一位），內層用貪心或前綴統計 $O(1)$ 到 $O(n)$ 求出對應的最優值。常需預處理前綴與後綴陣列讓內層降到 $O(1)$。

## 不變量或正確性證明

不變量：掃過前 `k` 個枚舉值後，答案是「限制在這些枚舉值下」的最優解。

正確性來自**枚舉的完備性**：所有可能的解都可以依被枚舉的那個變數分類，且分類互斥且窮盡。若對每個類別都求出了該類的最優解，則所有類別最優值中的最大者就是全域最優。

因此本法的成敗只取決於兩件事：其一，枚舉的變數是否真的窮盡了所有情形（漏掉一個取值就可能漏掉最優解）；其二，固定該變數後，內層求解是否真的最優。內層若是貪心，仍需各自證明；若是前綴極值，則由定義直接成立。

例如「分成兩段使兩段和之差最小」，枚舉分割點 `i` 後，兩段和由前綴和 $O(1)$ 得出；每個分割點恰對應一種分法，分類完備，故取最小差即為答案。

## 逐步演算法

決定要枚舉哪個變數（通常選取值範圍小的那個）；預處理內層所需的前綴／後綴資訊；外層逐一枚舉並 $O(1)$ 或 $O(n)$ 求出對應最優；更新全域答案。

## C++17 模板

```cpp
// 枚舉分割點：把陣列切成兩段，最大化「左段最大值 - 右段最小值」之類的量。
int bestSplit(const vector<int>& a) {
    const int n = a.size();
    vector<int> suffixMin(n + 1, INT_MAX);
    for (int i = n - 1; i >= 0; --i) {
        suffixMin[i] = min(suffixMin[i + 1], a[i]);
    }

    int best = INT_MIN, prefixMax = INT_MIN;
    for (int i = 0; i + 1 < n; ++i) {  // i 為左段最後一格
        prefixMax = max(prefixMax, a[i]);
        best = max(best, prefixMax - suffixMin[i + 1]);
    }
    return best;
}
```

## 時間與空間複雜度

枚舉 $O(n)$ 乘上內層成本。內層用前綴預處理時總計 $O(n)$；內層需排序或掃描時為 $O(n^2)$ 或 $O(n^2 \log n)$。空間為前綴陣列的 $O(n)$。

## 常見錯誤與邊界條件

- 枚舉範圍漏掉端點（例如分割點允許空段與否）。
- 前綴與後綴的下標錯開一格。
- 內層貪心未經證明就套用。
- 枚舉變數選錯導致內層仍然困難。
- 空段時的極值初始化未處理。

## 與相似技巧的比較

若兩個變數都連續且範圍大，改用二分或三分搜尋；若固定一個後另一個仍需複雜決策，往往是 DP 而非貪心。枚舉的成本是多一層迴圈，換來的是把耦合拆開，這個取捨在資料範圍不大時非常划算。

## 本節重點速查

- 固定一個、最佳化另一個
- 枚舉必須完備且互斥
- 內層貪心仍要各自證明
- 用前綴後綴把內層壓到 $O(1)$。
