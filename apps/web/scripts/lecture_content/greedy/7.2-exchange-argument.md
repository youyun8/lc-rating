## 這個技術解決什麼問題

決定一批任務的處理順序時，如何證明某條排序規則是最優的。交換論證是貪心類題目最核心的證明手法，也是「該按什麼排序」這個問題的通用推導工具。

## 狀態／資料結構定義

通常只需一個自訂比較器加上一次排序，之後線性掃描累積答案。真正的工作在於推導出比較器。

## 不變量或正確性證明

交換論證的標準框架：假設存在一個最優解，其順序與貪心排序不同。既然不同，必存在**相鄰**兩個元素 `a`、`b`，在最優解中 `a` 排在 `b` 前，而貪心規則要求 `b` 在 `a` 前。證明交換這兩者後總代價不會變差，即可把最優解一步步調整成貪心解，故貪心最優。

只需考慮相鄰交換是關鍵簡化：任何排列都能透過一系列相鄰交換變成另一個排列（冒泡排序即是），而每次交換只影響這兩個元素的貢獻，其餘元素的相對位置與代價都不變。

推導比較器的方法就是寫下「`a` 在前」與「`b` 在前」的代價差並比較。例如任務排程中，任務 `i` 需時 `t_i`、逾期罰款率 `p_i`，兩者相鄰時：

- `a` 在前的額外代價為 $t_a \cdot p_b$
- `b` 在前的額外代價為 $t_b \cdot p_a$

故 `a` 應排在前面的條件是 $t_a p_b \le t_b p_a$，整理成 $\frac{t_a}{p_a} \le \frac{t_b}{p_b}$——這就是比較器。實作時應寫成乘法形式避免除法誤差。

要注意比較器必須構成**嚴格弱序**（可傳遞），否則 `std::sort` 行為未定義。推導出的規則若不可傳遞，通常代表題目其實不能用單純排序解決。

## 逐步演算法

寫出兩個元素相鄰時的兩種代價；令其中一種不劣，整理成不等式；把不等式改寫成比較器；排序後線性掃描求答案。

## C++17 模板

```cpp
// 依交換論證推出的規則排序：t_a * p_b <= t_b * p_a 時 a 在前。
sort(tasks.begin(), tasks.end(), [](const Task& a, const Task& b) {
    return 1LL * a.time * b.penalty <
           1LL * b.time * a.penalty;  // 用乘法避免除法
});

long long total = 0, elapsed = 0;
for (const auto& task : tasks) {
    elapsed += task.time;
    total += elapsed * task.penalty;
}
```

「連接數字使結果最大」也是同一套：比較器為 `a + b > b + a`（字串相接後比大小）。

## 時間與空間複雜度

排序 $O(n \log n)$ 主導，掃描 $O(n)$，空間 $O(1)$。

## 常見錯誤與邊界條件

- 比較器用除法造成精度誤差或除以零。
- 比較器不可傳遞導致排序未定義。
- 乘積溢位需 `1LL *`。
- 相等時回傳 `true` 破壞嚴格弱序（必須用 `<` 而非 `<=`）。
- 只驗證了相鄰交換卻誤以為需要驗證任意交換（相鄰即足夠）。

## 與相似技巧的比較

交換論證證明「排序後貪心」正確；歸納法證明「逐步擴張」正確；反證法用於「不存在更優解」。若相鄰交換的代價差無法化簡成兩元素的獨立比較（例如受第三者影響），排序貪心失效，需改用 DP。

## 本節重點速查

- 只需檢查相鄰交換
- 寫下兩種順序的代價差
- 整理成比較器並用乘法
- 比較器必須可傳遞。
