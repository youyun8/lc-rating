## 這個技術解決什麼問題

一般貪心選了就不回頭，但有些題目前面看似最好的選擇，到後面才發現吃虧。反悔貪心先大膽全拿，事後發現違規或有更好選擇時，用一個堆撤銷先前最差的決定。

## 辨識題型的訊號

依序處理事件、資源有限、且「早期的選擇可能被後來更好的選項取代」。代表題是「課程表 III」「最多能完成幾個任務」「買賣股票可反悔」。

## 狀態／資料結構定義

一個優先佇列存放已做出的選擇，堆頂是「最容易被撤銷的那一個」（通常是耗時最長或收益最低者）。另有累積量記錄已用資源與當前答案。

## 不變量或正確性證明

不變量：處理完前 `i` 個項目後，堆中保存的是「只考慮前 `i` 個項目時，某個最優解所選中的集合」，且該集合在同樣的選中個數下所耗資源最小。

歸納證明（以「課程表 III」為例，每門課有時長 `t` 與截止日 `d`，先按截止日排序）：處理第 `i` 門課時，若加入後總時長仍不超過截止日，直接加入，選中個數加一，顯然不劣。

若超出，則比較新課與堆頂（時長最長的已選課）。若新課更短，就把堆頂換成它——選中個數不變，而總時長嚴格減少，故不變量的「資源最小」性質得以維持，且為後續留下更多空間。若新課不更短，則捨棄它；此時任何包含它的解都可以把它換成堆中更短者而不變差，故捨棄安全。

按截止日排序是前提：它保證處理到第 `i` 門課時，所有先前課程的截止日都不晚於它，因此「總時長不超過當前截止日」是這個前綴的正確可行性判據。

## 逐步演算法

依關鍵欄位排序；逐一處理，先無條件納入並更新資源；若違反限制，就從堆中彈出最差的一個撤銷；記錄答案。

## C++17 模板

```cpp
// 課程表 III：每門課 (時長, 截止日)，求最多能修幾門。
int scheduleCourse(vector<vector<int>>& courses) {
    sort(courses.begin(), courses.end(),
         [](const auto& a, const auto& b) { return a[1] < b[1]; });  // 按截止日

    priority_queue<int> heap;  // 大根堆：堆頂是最長的已選課
    long long elapsed = 0;

    for (const auto& course : courses) {
        const int duration = course[0], deadline = course[1];
        heap.push(duration);
        elapsed += duration;
        if (elapsed > deadline) {  // 違規，撤銷最長的一門
            elapsed -= heap.top();
            heap.pop();
        }
    }
    return heap.size();
}
```

## 時間與空間複雜度

排序 $O(n \log n)$；每個項目至多入堆一次、出堆一次，各 $O(\log n)$，總計 $O(n \log n)$ 時間、$O(n)$ 空間。

## 常見錯誤與邊界條件

- 排序關鍵欄位選錯（本題必須按截止日而非時長）。
- 用小根堆而撤銷了最好的選擇。
- 撤銷後忘記同步扣除累積資源。
- 先判斷再加入而非「先加入再撤銷」（後者程式更短且不會漏解）。
- 累積量溢位。

## 常見變形

[LCP 30 魔塔遊戲](https://leetcode.cn/problems/p0NxJO) 是「前綴一旦違規，就延後目前遇過最傷的一項」的代表。先檢查所有房間總和；若總和為負，即使重排也不可能走完。掃描時把負數房間放進小根堆並累加生命值；只要生命值降到 0 以下，就彈出堆頂（數值最小、傷害最大的房間）並把它移到序列尾端：

```cpp
int magicTower(vector<int>& nums) {
    if (accumulate(nums.begin(), nums.end(), 0LL) < 0) {
        return -1;
    }
    priority_queue<int, vector<int>, greater<int>> negative;
    long long hp = 1;
    int moved = 0;
    for (int x : nums) {
        hp += x;
        if (x < 0) {
            negative.push(x);
        }
        if (hp <= 0) {
            hp -= negative.top();  // 撤銷目前最傷的房間，延後到最後
            negative.pop();
            ++moved;
        }
    }
    return moved;
}
```

不變量是：處理完目前前綴後，已延後 `moved` 間房的方案保持生命值為正，且在延後相同房間數的方案中，保留的前綴生命值最大。違規時延後最負的房間，回補生命最多，因此最不會傷害後續；總和非負則保證延後房間最後仍能走完。

## 與相似技巧的比較

一般貪心不保留撤銷機會，只在無後效性極強時才正確；DP 一定正確但狀態可能爆炸。反悔貪心本質是模擬最小費用流的增廣過程——堆中的每一項就是一條反向邊，詳見圖論題單的「模擬費用流」。

## 本節重點速查

- 先全拿再撤銷
- 堆頂放最容易撤銷者
- 排序欄位決定可行性判據
- 撤銷時記得同步扣資源。
