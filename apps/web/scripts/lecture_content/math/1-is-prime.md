## 這個技術解決什麼問題

判斷單一整數 `n` 是否為質數。試除到 `n - 1` 是 $O(n)$，對 $10^9$ 等級的輸入不可行；根號試除把成本壓到 $O(\sqrt{n})$，是單次查詢的標準做法。

## 狀態／資料結構定義

先單獨檢查 2 與 3，再只枚舉 $6k-1$、$6k+1$ 兩類候選。所有大於 3 的質數都落在這兩類，因為其餘餘數可被 2 或 3 整除。這只減少常數，不改變最壞時間 $O(\sqrt n)$。迴圈用 `i <= n / i`，避免 `i * i` 在接近 `long long` 上限時溢位。

## 不變量或正確性證明

不變量：迴圈進行到 `i` 時，`n` 沒有任何落在 `[2, i)` 的因數。

只試到根號就足夠的理由：若 `n` 是合數，可寫成 `n = a * b` 且 `a, b > 1`。兩者不可能同時大於 $\sqrt{n}$，否則乘積超過 `n`；故必有一個因數不超過 $\sqrt{n}$，會在迴圈內被找到。反之迴圈跑完仍無因數，表示不存在不超過 $\sqrt{n}$ 的因數，由上述論證也就不存在任何真因數，`n` 為質數。

## C++17 模板

```cpp
bool isPrime(long long n) {
    if (n < 2) {
        return false;
    }
    if (n % 2 == 0) {
        return n == 2;
    }
    if (n % 3 == 0) {
        return n == 3;
    }
    for (long long i = 5; i <= n / i; i += 6) {
        if (n % i == 0 || n % (i + 2) == 0) {
            return false;
        }  // 6k-1、6k+1
    }
    return true;
}
```

這個版本比逐一測試 `2, 3, 4, ...` 少做約三分之二的取餘，但上界仍是 $O(\sqrt n)$，不能宣稱為對數時間。

## 程式碼拆解

- `n < 2` 先排除負數、0、1。
- 2 與 3 必須在排除其倍數前單獨放行。
- 大於 3 的質數只可能是 `6k - 1` 或 `6k + 1`，每輪測試 `i` 與 `i + 2`。
- `i <= n / i` 等價於 `i * i <= n`，但不會讓乘法先溢位。

## 時間與空間複雜度

候選數量仍與 $\sqrt n$ 成正比，時間 $O(\sqrt{n})$、空間 $O(1)$。若要判斷 $[1, n]$ 中每個數，逐個試除是 $O(n\sqrt{n})$，此時應改用篩法。

## 常見錯誤與邊界條件

- 漏掉 `n < 2` 的判斷（0、1 與負數都不是質數）。
- 排除 2、3 的倍數時忘記單獨放行 2 與 3。
- 把 `6k ± 1` 誤當成充分條件（25 仍是合數，候選仍要試除）。
- 用 `i * i <= n` 處理極大 `long long` 而溢位。
- 把常數優化誤稱為低於 $O(\sqrt n)$。

## 與相似技巧的比較

單次查詢用根號試除；要反覆查詢一個範圍內的數就預處理埃氏篩或線性篩，把單次查詢降到 $O(1)$。若 `n` 大到 $10^{18}$，根號試除也不夠，需改用 Miller-Rabin 機率性判定。

## 本節重點速查

- 只試到根號就夠
- 用 `i * i <= n` 不用 `sqrt`
- 先擋掉小於 2
- 大範圍多次查詢改用篩法。
