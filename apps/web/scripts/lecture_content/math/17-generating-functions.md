## 這個技術解決什麼問題

把計數問題轉成多項式乘法。當「總量由若干部分相加」而要問「湊出某個總量有幾種方式」時，生成函式讓我們用多項式的次數記錄總量、係數記錄方案數，把組合推理變成機械的乘法。

## 狀態／資料結構定義

用 `vector<long long> f`，其中 `f[i]` 是「湊出總量 `i` 的方案數」。每加入一種可選部件，就把當前多項式與該部件的生成函式相乘。

## 不變量或正確性證明

不變量：處理完前 `k` 種部件後，`f[i]` 等於「只用前 `k` 種部件湊出總量 `i` 的方案數」。

乘法對應計數的理由：多項式乘積的係數定義為

$$(A \cdot B)[n] = \sum_{i+j=n} A[i] \cdot B[j]$$

右式恰好是「第一部分貢獻 `i`、第二部分貢獻 `j`，且 `i + j = n`」的所有組合數，由乘法原理各項相乘、再依加法原理對所有拆法求和。這與我們想計數的東西定義一致，故係數即方案數。

因為每種拆法 `(i, j)` 只被算一次，計數不重不漏。多個部件則由結合律逐一相乘，歸納可得不變量。

例如一顆骰子的生成函式為 $x^1 + \cdots + x^6$；擲 `n` 顆的點數和分布，就是它的 `n` 次方的各項係數。

## 時間與空間複雜度

單次多項式乘法（樸素）為 $O(nm)$；若目標總量上界為 `M`、部件有 `k` 種，總成本 $O(kM)$，與背包 DP 相同。需要極高次數時改用 NTT，把單次乘法降到 $O(M \log M)$。

## C++17 模板

```cpp
constexpr long long kMod = 1'000'000'007;

// 多項式乘法，只保留次數不超過 limit 的項。
vector<long long> multiply(const vector<long long>& a,
                           const vector<long long>& b, int limit) {
    vector<long long> c(limit + 1, 0);
    for (int i = 0; i < static_cast<int>(a.size()) && i <= limit; ++i) {
        if (a[i] == 0) {
            continue;
        }
        for (int j = 0; j + i <= limit && j < static_cast<int>(b.size()); ++j) {
            c[i + j] = (c[i + j] + a[i] * b[j]) % kMod;
        }
    }
    return c;
}
```

實務上多半不顯式建多項式，而是直接寫成背包遞推——兩者是同一件事的不同寫法。

## 常見錯誤與邊界條件

- 忘記截斷高於上界的項而讓長度爆炸。
- 常數項 `f[0] = 1` 未初始化（代表「什麼都不選」這一種方案）。
- 係數未取模而溢位。
- 把「有序」與「無序」搞混——生成函式相乘天然是有序的部件組合，若部件可互換需另行處理。

## 與相似技巧的比較

生成函式與背包 DP 等價，前者提供代數視角（可用封閉形式化簡，例如等比級數求和），後者實作直觀。當需要快速冪次方（擲 `n` 顆骰子）時，生成函式配合多項式快速冪明顯占優。

## 本節重點速查

- 次數記總量、係數記方案數
- 乘法對應「拆成兩部分」的求和
- `f[0] = 1`
- 記得截斷與取模。
