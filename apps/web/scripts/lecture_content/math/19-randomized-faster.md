## 這個技術解決什麼問題

有些演算法最壞情況很慢，但只要輸入隨機（或我們主動隨機化），期望成本就明顯下降。這一節用期望時間而非最壞時間來衡量，並接受極小機率的退化。

## 狀態／資料結構定義

以隨機快速選擇為例：維護待搜尋區間 `[l, r]` 與目標名次 `k`。每輪隨機挑一個基準值，分割後只遞迴進入包含目標名次的那一側。

## 不變量或正確性證明

不變量：目標元素恆落在當前區間 `[l, r]` 內，且 `k` 是它在該區間中的名次。

分割後只保留一側是安全的：分割使基準左側元素皆不大於它、右側皆不小於它，故基準的最終位置就是它的真實名次。比較 `k` 與該名次即可確定目標落在哪一側，另一側可整個丟棄。

期望複雜度 $O(n)$ 的論證：隨機基準落在中間一半（名次在 `[n/4, 3n/4]`）的機率為 $1/2$，此時區間長度至少縮成原來的 $3/4$。期望上每兩輪就發生一次這樣的「好分割」，故期望總比較次數滿足 $T(n) \le T(3n/4) + O(n)$，展開為等比級數，總和為 $O(n)$。

關鍵前提是基準真的隨機：若對已排序輸入固定取首元素，每次只縮短 1，退化成 $O(n^2)$。隨機化的作用正是讓對手無法構造最壞輸入——期望不依賴輸入分布，只依賴我們自己的隨機源。

## 時間與空間複雜度

隨機快速選擇期望 $O(n)$、最壞 $O(n^2)$（機率極低），空間 $O(1)$（迭代版）。隨機快排期望 $O(n \log n)$。若必須保證最壞線性，改用中位數的中位數，但常數大得多。

## C++17 模板

```cpp
// 回傳第 k 小（k 由 0 起算）。期望 O(n)。
int quickSelect(vector<int>& a, int k) {
    static mt19937 rng(chrono::steady_clock::now().time_since_epoch().count());
    int l = 0, r = a.size() - 1;
    while (l < r) {
        const int pivot = a[uniform_int_distribution<int>(l, r)(rng)];
        int i = l, j = r, p = l;
        while (p <= j) {  // 三向分割，處理大量重複值
            if (a[p] < pivot) {
                swap(a[i++], a[p++]);
            } else if (a[p] > pivot) {
                swap(a[p], a[j--]);
            } else {
                ++p;
            }
        }
        if (k < i) {
            r = i - 1;
        } else if (k > j) {
            l = j + 1;
        } else {
            return pivot;
        }  // 落在等於 pivot 的區段
    }
    return a[l];
}
```

## 常見錯誤與邊界條件

- 用 `rand()` 且未設種子，或種子固定而被卡。
- 分割寫成兩向而在大量重複值時退化。
- 遞迴兩側而非只走一側（那就變成排序，$O(n \log n)$）。
- `k` 的起算基準（0 或 1）與呼叫端不一致。
- 空陣列未處理。

## 與相似技巧的比較

完整排序後取第 `k` 個是 $O(n \log n)$，程式最短；堆做法為 $O(n \log k)$，適合 `k` 很小或資料流場景；隨機快速選擇期望 $O(n)$ 最快但最壞較差。需要確定性最壞線性時才動用中位數的中位數。

## 本節重點速查

- 只遞迴一側才是線性
- 隨機基準是複雜度保證的來源
- 三向分割應付重複值
- 期望不依賴輸入分布。
