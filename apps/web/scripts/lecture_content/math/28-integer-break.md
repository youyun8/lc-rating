## 這個技術解決什麼問題

把正整數 `n` 拆成若干正整數之和，使乘積最大。DP 能穩妥求解，但這題有一個可證明的貪心結論，能把成本降到 $O(\log n)$。

## 狀態／資料結構定義

DP 版本用 `f[i]` 表示「把 `i` 拆成至少兩個正整數後的最大乘積」，轉移枚舉第一段 `j`。貪心版本只需計數 3 的個數與餘數，配合快速冪求值。

## 不變量或正確性證明

結論：最優拆法只會用到 2 與 3，且 3 越多越好；當餘數為 1 時，把一個 3 與該 1 併成兩個 2。

分三步證明。

其一，**每段都不超過 4**。若某段 $a \ge 5$，把它換成 $2 + (a-2)$，乘積由 $a$ 變為 $2(a-2) = 2a-4$，而 $2a - 4 > a \iff a > 4$，故拆開更優。

其二，**不使用 1**。任何 1 與相鄰段 `a` 合併成 `a+1`，乘積由 $1 \cdot a$ 變為 $a+1$，嚴格更大。

其三，**4 可換成 2+2**（乘積同為 4，不影響），因此只需考慮 2 與 3。設用了 `x` 個 3 與 `y` 個 2，滿足 $3x + 2y = n$。比較同樣總和下的效率：$3^2 = 9 > 2^3 = 8$，即每 6 個單位用兩個 3 優於三個 2，故應盡量多用 3。

餘數討論：`n mod 3 == 0` 時全用 3；餘 2 時補一個 2；餘 1 時不可留下 1（由其二），改成退掉一個 3 與這個 1 合成兩個 2（$2 \times 2 = 4 > 3 \times 1 = 3$）。

## 時間與空間複雜度

貪心加快速冪為 $O(\log n)$ 時間、$O(1)$ 空間。DP 版本為 $O(n^2)$ 時間、$O(n)$ 空間，在 `n` 很小或需要對答案取模的變形題中仍實用。

## C++17 模板

```cpp
int integerBreak(int n) {
    if (n <= 3) {
        return n - 1;
    }  // 2->1, 3->2（必須拆成至少兩段）
    const int quotient = n / 3, remainder = n % 3;
    if (remainder == 0) {
        return pow3(quotient);
    }
    if (remainder == 1) {
        return pow3(quotient - 1) * 4;
    }  // 退一個 3 換兩個 2
    return pow3(quotient) * 2;
}
```

需要對大數取模時（例如 1808 題），把 `pow3` 換成快速冪並全程取模；注意餘 1 的情形要用模逆元或直接調整指數，不能在模意義下做除法。

## 常見錯誤與邊界條件

- `n <= 3` 未特判（題目要求至少拆成兩段，故 `n = 2` 答案為 1、`n = 3` 為 2）。
- 餘數為 1 時仍乘上一個 1。
- 取模題中先取模再比較大小而失效。
- 快速冪指數為 `quotient - 1` 時可能為負，需先確保 `quotient >= 1`。

## 與相似技巧的比較

DP 是通用保底方案，且容易推廣到「段數有限制」等變形；貪心快但依賴上面那條特定結論，換個目標函式就不成立。遇到類似「拆分求極值」的題目，建議先用小資料的 DP 打表觀察規律，再嘗試證明貪心。

## 本節重點速查

- 只用 2 和 3，盡量用 3
- 餘 1 要退一個 3 換成兩個 2
- `n <= 3` 特判
- $3^2 > 2^3$ 是關鍵不等式。
