## 這個技術解決什麼問題

把多層迴圈的計數式整理成「逐項可算」的形式。典型手法是固定其中一個變數（常是中間那個），把左右兩側的貢獻各自預先累積起來相乘，將 $O(n^3)$ 或 $O(n^2)$ 壓成 $O(n)$。

## 狀態／資料結構定義

維護前綴統計與後綴統計：`left[j]` 是「在 `j` 左側且滿足條件的元素個數（或權重和）」，`right[j]` 同理。實作上常用兩次掃描，或一次掃描搭配即時維護的計數表。

## 不變量或正確性證明

不變量：掃描到位置 `j` 時，`left` 恰好統計了下標嚴格小於 `j` 的所有合法元素，`right` 恰好統計了下標嚴格大於 `j` 的所有合法元素。

計數不重不漏的關鍵是**以中間元素分類**：每個要統計的三元組 `(i, j, k)` 且 `i < j < k`，其中間元素 `j` 是唯一確定的。因此把所有三元組按 `j` 分組後，各組互不相交且並集為全體。每組的個數由乘法原理得 `left[j] * right[j]`——左邊選一個、右邊選一個，兩個選擇互相獨立。對所有 `j` 求和即為答案。

這一步之所以能省掉一層迴圈，是因為我們不再枚舉 `i` 與 `k` 的具體組合，只需要它們的**數量**；而數量可以在掃描過程中 $O(1)$ 增量維護。

## 時間與空間複雜度

兩次掃描為 $O(n)$ 時間；若需前綴陣列則空間 $O(n)$，用即時維護的計數器可降到 $O(1)$ 或 $O(\Sigma)$。相較樸素三重迴圈的 $O(n^3)$，這是決定性的改善。

## C++17 模板

```cpp
// 統計滿足 i < j < k 且 (i,j)、(j,k) 各自滿足某條件的三元組個數。
long long countTriples(const vector<int>& a) {
    const int n = a.size();
    vector<long long> right(n, 0);
    // 先算每個 j 右側的合法數量
    for (int j = n - 2; j >= 0; --j) {
        right[j] = right[j + 1] + (okRight(a[j + 1]) ? 1 : 0);
    }

    long long total = 0, left = 0;
    for (int j = 0; j < n; ++j) {
        total += left * right[j];  // 以 j 為中間元素的三元組數
        if (okLeft(a[j])) {
            ++left;
        }  // j 處理完才併入左側統計
    }
    return total;
}
```

## 常見錯誤與邊界條件

- 把當前元素併入左側統計的時機寫在累加之前，導致 `i == j` 被算進去。
- 後綴陣列的邊界（`j = n-1` 時右側為空）未初始化。
- 乘積溢位需 `long long`。
- 條件對左右兩側其實不同卻共用同一個統計。
- `n < 3` 時答案為 0，迴圈應自然得出。

## 與相似技巧的比較

前綴和適用於「區間和」這類可加可減的量；本節的左右分解適用於「配對計數」；若條件涉及大小關係且需動態查詢排名，改用樹狀陣列或有序集合，成本升為 $O(n \log n)$。核心判準是「能不能只靠數量而不需具體組合」。

## 本節重點速查

- 固定中間元素分類
- 左右各自統計數量再相乘
- 當前元素併入的時機要在累加之後
- 只需數量就能省一層迴圈。
