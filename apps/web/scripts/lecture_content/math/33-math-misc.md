## 這個技術解決什麼問題

數學分類的雜項題。它們的共通心法是：先把題意翻成一條可證明的數學式或構造規則，再依式子直接算出答案，而不是用搜尋或模擬硬湊。

## 狀態／資料結構定義

沒有固定結構。多數題目只需幾個整數變數；少數需要預處理表（階乘與逆階乘、質數表、前綴和）。選擇的依據是「答案是否有封閉形式」。

## 不變量或正確性證明

本節不引入單一新定理，而是收束前面各節都用到的推導習慣。動手前先確認以下前提，選錯工具的原因幾乎都出在這裡：

- **等差／等比求和**：用封閉式 $\frac{n(n+1)}{2}$ 或 $\frac{a(r^n-1)}{r-1}$ 前，先確認項數與首末項；模意義下的除法要改乘逆元。
- **鴿籠原理**：要斷言「必有重複」，須先確認物件數嚴格大於容器數。
- **奇偶性與不變量**：許多構造題的關鍵是找出一個操作前後不改變的量（總和的奇偶、座標和模某數），用它證明目標狀態不可達。
- **對稱性**：若問題在某種變換下不變，答案往往可以只算一半再乘二，但要小心自對稱的情形被重複計數。
- **上下界夾擊**：先證答案不可能優於某個界，再構造一個達到該界的方案，兩邊夾出最優解。

每條都要先驗證前提再套用；把「觀察到的規律」當成已證結論是本類題目最常見的失分點。

## 時間與空間複雜度

有封閉式時多為 $O(1)$ 或 $O(\log n)$（含快速冪）；需預處理時為 $O(n)$ 建表後 $O(1)$ 查詢。若只能想到枚舉，先用資料範圍反推可接受的複雜度：`n` 到 $10^{18}$ 通常意味著答案有公式或需要數論分塊。

## C++17 模板

沒有單一模板；下面是本節最常用的兩個零件。

```cpp
// 等差數列求和：首項 a、公差 d、共 n 項。
long long arithmeticSum(long long a, long long d, long long n) {
    return n * (2 * a + (n - 1) * d) /
           2;  // 先乘後除，n 與 (2a+(n-1)d) 必有一偶
}

// 模意義下的等比求和：a * (r^n - 1) / (r - 1)，用逆元取代除法。
long long geometricSum(long long a, long long r, long long n, long long mod) {
    if (r % mod == 1) {
        return a % mod * (n % mod) % mod;
    }  // 公比為 1 要特判
    const long long numerator = (power(r, n, mod) - 1 + mod) % mod;
    return a % mod * numerator % mod * power(r - 1, mod - 2, mod) % mod;
}
```

## 常見錯誤與邊界條件

- 把觀察到的規律當成證明。
- 等比求和忘記公比為 1 的特判。
- 模意義下直接除法。
- 求和公式先除後乘造成整除誤差（或先乘後除造成溢位，需視情況權衡）。
- 鴿籠原理的容器數算錯。
- 對稱性計數時漏掉自對稱項。

## 與相似技巧的比較

有封閉式就用公式；沒有但狀態可枚舉就用 DP；狀態爆炸但答案單調就用二分；以上都不行才考慮搜尋加剪枝。判斷順序建議固定成這條路徑，避免一上來就寫暴力。

## 本節重點速查

- 先翻成式子再計算
- 規律要證明不能只靠觀察
- 模意義下除法一律換逆元
- 用資料範圍反推該用什麼工具。
