## 這個技術解決什麼問題

分析 `n!` 的質因數結構而不真的算出它的值（`21!` 已超過 64 位元）。最常見的問法是「`n!` 末尾有幾個零」，等價於問質因數 2 與 5 中較少的那個出現幾次。

## 狀態／資料結構定義

只需要一個累加器 `count` 與一個不斷放大的除數。用 `n / p`、`n / p²`、`n / p³`、…逐項相加；實作上以 `n /= p` 迭代即可，避免 `p^k` 溢位。

## 不變量或正確性證明

勒壤得公式：質數 `p` 在 `n!` 中的指數為 $\sum_{k \ge 1} \lfloor n/p^k \rfloor$。

證明用「分層計數」：`n!` 是 `1` 到 `n` 的乘積。其中 `p` 的倍數有 $\lfloor n/p \rfloor$ 個，每個至少貢獻一次 `p`；`p²` 的倍數有 $\lfloor n/p^2 \rfloor$ 個，它們各再多貢獻一次；依此類推。每個數 `m` 若含 `p` 的指數為 `e`，它恰好會在前 `e` 層各被數到一次，總計 `e` 次，正好等於它真正的貢獻。故總和無重複也無遺漏。

級數是有限的：當 $p^k > n$ 時該項為 0，所以最多 $\log_p n$ 項。

末尾零的個數等於 $\min(e_2, e_5)$；因為 `2` 的倍數比 `5` 密集，$e_2 > e_5$ 恆成立，直接算 `5` 的指數即可。

## 時間與空間複雜度

每次迴圈把 `n` 除以 `p`，迭代 $O(\log_p n)$ 次，時間 $O(\log n)$，空間 $O(1)$。

## C++17 模板

```cpp
// 質數 p 在 n! 中的指數（勒壤得公式）。
long long legendre(long long n, long long p) {
    long long count = 0;
    while (n > 0) {
        n /= p;  // 逐層：n/p, n/p^2, ...
        count += n;
    }
    return count;
}

int trailingZeroes(int n) {
    return static_cast<int>(legendre(n, 5));
}
```

## 常見錯誤與邊界條件

- 直接計算 `p^k` 而溢位（改用 `n /= p` 迭代）。
- 末尾零去數 2 的指數而非 5。
- 把公式誤記成 $\lfloor n/p \rfloor$ 單一項，漏掉高次冪的貢獻（`n = 25` 時會少算）。
- `n = 0` 時 `0! = 1`，答案為 0，迴圈自然處理。

## 與相似技巧的比較

一般整數的質因數分解要試除到根號；階乘則因為結構規律而有封閉公式，成本降到對數。若要算組合數 `C(n, k)` 對非質數取模，也常用勒壤得公式逐質數統計指數再組合回去。

## 本節重點速查

- 逐層累加 $\lfloor n/p^k \rfloor$
- 用 `n /= p` 迭代防溢位
- 末尾零看 5 不看 2
- 每個數在前 `e` 層各被數一次。
