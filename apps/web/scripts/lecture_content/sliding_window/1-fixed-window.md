## 這個技術解決什麼問題

在陣列或字串上，對每個長度恰為 `k` 的連續區間計算某個量（總和、母音個數、不同元素數），並取最值或收集答案。樸素做法對每個起點重算一次是 $O(nk)$，定長滑窗把它降到 $O(n)$。

## 辨識題型的訊號

題目明確給出一個固定長度 `k`，並問「所有長度為 `k` 的子陣列中……最大／最小／有幾個滿足條件」。長度不固定時屬於不定長滑窗，是另一套寫法。

## 核心想法與直覺

相鄰兩個視窗只差一進一出：右端進來一個新元素，左端出去一個舊元素。既然差異只有兩個元素，就不必重算整段，只要對維護的量做增量更新。

穩健的寫法把每次迭代拆成三步——**入、更新、出**：先讓 `right` 元素進入視窗，若視窗尚未滿 `k` 就繼續；滿了才更新答案；然後讓最左元素離開。這個節奏對所有定長滑窗題都適用，不必為每題重新設計邊界。

## 狀態／資料結構定義

視窗固定為 `[right - k + 1, right]`。維護的量依題而定：`sum` 為區間和、`count` 為某類字元個數、`unordered_map` 為元素出現次數。

## 不變量或正確性證明

不變量：每次執行到「更新答案」那一步時，維護的量恰好對應區間 `[right - k + 1, right]`，且該區間長度恰為 `k`。

證明：初始視窗為空，量為零。每輪先加入 `right` 使區間變成 `[left, right]`，當 `right < k - 1` 時長度不足而跳過更新；當 `right >= k - 1` 時長度恰為 `k`，此時更新答案是合法的；隨後移除下標 `right - k + 1`，使區間變成 `[right - k + 2, right]`，正是下一輪加入新元素後長度回到 `k` 所需的狀態。因此不變量在每輪之間保持。

## 逐步演算法

從左到右枚舉右端點；把新元素併入維護量；若視窗長度不足 `k` 就跳過；否則用當前量更新答案；最後把左端元素移出維護量。

## C++17 模板

```cpp
class Solution {
public:
    int maxSum(vector<int>& nums, int k) {
        long long sum = 0;
        long long answer = LLONG_MIN;

        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            sum += nums[right];  // 一、入
            if (right < k - 1) {
                continue;
            }  // 視窗還沒滿
            answer = max(answer, sum);   // 二、更新
            sum -= nums[right - k + 1];  // 三、出
        }
        return static_cast<int>(answer);
    }
};
```

維護量是次數表時，移除後記得清掉歸零的鍵，否則「不同元素個數」會算錯：

```cpp
if (--count[nums[right - k + 1]] == 0) {
    count.erase(nums[right - k + 1]);
}
```

## 時間與空間複雜度

每個元素恰好進入與離開視窗各一次，時間 $O(n)$。空間視維護量而定：純數值為 $O(1)$，次數表為 $O(\min(n, k))$ 或字元集大小。

## 常見錯誤與邊界條件

- 「出」的下標寫成 `right - k` 而不是 `right - k + 1`。
- 在視窗未滿時就更新答案。
- 用次數表時忘記刪除計數歸零的鍵。
- `k > n` 時應直接回傳無解。
- 答案初始值用 0 但陣列可能全負。
- 總和溢位需用 `long long`。

## 與相似技巧的比較

前綴和同樣能 $O(1)$ 取得任意區間和，且支援任意長度查詢，但無法維護「不同元素個數」這類不可減的量；不定長滑窗的視窗長度由條件決定，需要內層 `while` 收縮；單調佇列則是在定長滑窗上再維護區間最值。

## 本節重點速查

- 固定節奏是入、更新、出；
- `right < k - 1` 先跳過；
- 移出的下標是 `right - k + 1`；
- 次數歸零要刪鍵。
