## 這個技術解決什麼問題

不定長滑窗的變形題集。這裡的條件不再是簡單的和或計數，而是位元遮罩的互斥、「替換 `k` 次後可否全同」這類帶預算的判定，或是要與二分搜尋組合才能處理的「第 `k` 小」。

## 辨識題型的訊號

視窗合法性依賴一個需要特別維護的量：位元 AND 為 0（元素兩兩無共同位元）、視窗內「非眾數的個數」不超過 `k`、或題目問「第 `k` 小的子陣列和」而非某個極值。

## 核心想法與直覺

三種常見變形，各自的關鍵在於找出可 $O(1)$ 維護的等價判據。

**位元遮罩型**：維護視窗內所有元素的 OR 值 `mask`。加入 `x` 時若 `mask & x` 非零就必須收縮；因為元素離開視窗時要從 `mask` 中移除該位，用 `mask ^= nums[left]` 即可（前提是視窗內無共同位元，故 XOR 等同於清除）。

**帶預算型**：以「替換後的最長重複字元」為例，視窗合法的條件是 `視窗長度 - 視窗內出現最多的字元次數 <= k`。這裡有個常被誤解的細節——`maxCount` 不需要在收縮時回退。因為答案只在視窗變長時才可能更新，而視窗要變長就必須有更大的 `maxCount`，即使 `maxCount` 暫時偏大，也只會讓視窗維持原長而不會產生錯誤的更長答案。

**二分加滑窗型**：「第 `k` 小的子陣列和」對答案二分，再用滑窗統計「和不超過 `mid` 的子陣列個數」，把最優化問題轉成判定問題。

## 狀態／資料結構定義

依變形而定：`mask` 為視窗內元素的按位或；`count` 加 `maxCount` 為字元次數表與其歷史最大值；二分型則是外層的 `lo`、`hi` 加上內層滑窗的計數。

## 不變量或正確性證明

位元遮罩型的不變量：`mask` 恆等於視窗內所有元素的按位或，且視窗內任兩元素無共同位元。

在後者成立時，每個位元至多由一個元素貢獻，因此移除 `nums[left]` 時 `mask ^= nums[left]` 恰好清掉它貢獻的那些位，等價於重新計算按位或。收縮條件 `mask & nums[right]` 非零保證了不變量的後半部持續成立。

帶預算型的不變量：`maxCount` 不小於視窗內任一字元的真實出現次數，且等於歷史上某個視窗中的真實最大值。

因此判定式 `right - left + 1 - maxCount <= k` 若成立，真實所需的替換次數只會更少，視窗確實合法；若 `maxCount` 偏大而讓判定式誤判為合法，該視窗長度必定不超過 `maxCount` 當初被記錄時的視窗長度，故答案不會被高估。

## 逐步演算法

先辨識出可 $O(1)$ 維護的判據；沿用不定長滑窗骨架（求最長則不合法時收縮，求最短則合法時收縮）；在進出視窗時同步更新該判據；需要時在外層套一層對答案的二分。

## C++17 模板

最長優雅子陣列（視窗內元素兩兩按位與為 0）：

```cpp
class Solution {
public:
    int longestNiceSubarray(vector<int>& nums) {
        int answer = 0, left = 0, mask = 0;

        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            while ((mask & nums[right]) != 0) {  // 有共同位元就收縮
                mask ^= nums[left];  // 無共同位元時 XOR 等同於清除
                ++left;
            }
            mask |= nums[right];
            answer = max(answer, right - left + 1);
        }
        return answer;
    }
};
```

替換後的最長重複字元：

```cpp
int characterReplacement(string s, int k) {
    array<int, 26> count{};
    int answer = 0, left = 0, maxCount = 0;
    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        maxCount = max(maxCount, ++count[s[right] - 'A']);
        while (right - left + 1 - maxCount > k) {
            --count[s[left] - 'A'];  // 注意 maxCount 不必回退
            ++left;
        }
        answer = max(answer, right - left + 1);
    }
    return answer;
}
```

## 時間與空間複雜度

滑窗本身為 $O(n)$；位元遮罩型因為每個數的位元數有限，收縮總次數仍是 $O(n)$。二分加滑窗為 $O(n \log V)$，其中 `V` 為答案值域。空間 $O(1)$ 或 $O(\Sigma)$。

## 常見錯誤與邊界條件

- 位元型在移除時用 `mask &= ~nums[left]`（正確但較慢）或忘記移除。
- 誤以為 `maxCount` 必須在收縮時重算，導致複雜度升高（重算雖然不會錯，但沒有必要）。
- 二分型的判定函式與二分邊界不匹配。
- 把「兩兩按位與為 0」誤解為「整體按位與為 0」。

## 與相似技巧的比較

這些題的共同解法都是先把「難以維護的條件」化簡成「可增量維護的判據」，再套用前面幾節的標準骨架。若找不到這樣的判據，通常要改用前綴和加有序集合、單調佇列，或直接放棄滑窗改用分治。

## 本節重點速查

- 先找可 $O(1)$ 維護的判據；
- 無共同位元時 XOR 可當清除用；
- `maxCount` 不必回退；
- 最優化轉判定就套二分。
