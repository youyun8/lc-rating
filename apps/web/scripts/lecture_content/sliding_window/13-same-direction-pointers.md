## 這個技術解決什麼問題

兩個指標朝同一方向移動（通常都向右），一個負責「讀」、一個負責「寫」或「跟隨」。它是滑動視窗的骨架，也是原地修改陣列、合併有序序列、判斷子序列的共同框架。

## 辨識題型的訊號

需要在一次遍歷中維持「已處理區段」與「待處理區段」的分界；或兩個序列各有一個游標依序前進；或視窗的左右端點都只向右移動。

## 核心想法與直覺

把陣列切成三段：`[0, slow)` 是已經定稿的結果區，`[slow, fast)` 是被判定為丟棄的區域，`[fast, n)` 是尚未檢視的區域。快指標每輪前進一格檢視新元素，只有在該元素應被保留時，慢指標才前進並接收它。

這個「快讀慢寫」的分工之所以有效，是因為慢指標永遠不會超過快指標，寫入的位置一定是已經讀過的位置，因此可以安全地原地覆蓋而不破壞尚未讀取的資料。

## 狀態／資料結構定義

`fast` 為讀游標、`slow` 為寫游標，恆有 `slow <= fast`。結果長度為 `slow`。在滑動視窗的語境下則是 `left` 與 `right`，`left` 為視窗左界。

## 不變量或正確性證明

不變量：任一時刻，`[0, slow)` 恰好是「前 `fast` 個元素中所有應保留者」，且順序與原始順序一致。

歸納證明：初始 `slow = fast = 0`，區間為空，成立。每輪檢視 `nums[fast]`：若應丟棄，`slow` 不動，前 `fast + 1` 個元素中的保留集合未變，不變量保持；若應保留，執行 `nums[slow] = nums[fast]` 後 `slow` 加一，恰好把新的保留元素接在結果尾端，順序不變。

覆寫安全性：由 `slow <= fast` 知寫入位置 `slow` 不超過 `fast`，而 `[0, fast]` 的內容都已被讀取過，因此覆蓋不會影響後續讀取。

## 逐步演算法

`slow` 與 `fast` 皆從 0 出發；`fast` 逐一掃過每個元素；判斷該元素是否應保留；保留則寫入 `nums[slow]` 並推進 `slow`；掃描結束後 `slow` 即為結果長度。

## C++17 模板

原地移除所有等於 `val` 的元素：

```cpp
int removeElement(vector<int>& nums, int val) {
    int slow = 0;
    for (int fast = 0; fast < static_cast<int>(nums.size()); ++fast) {
        if (nums[fast] != val) {  // 應保留
            nums[slow] = nums[fast];
            ++slow;
        }
    }
    return slow;  // 前 slow 個即為結果
}
```

有序陣列去重只需把判斷改成「與已寫入的最後一個不同」：

```cpp
if (slow == 0 || nums[fast] != nums[slow - 1]) {
    nums[slow++] = nums[fast];
}
```

## 時間與空間複雜度

每個元素被讀一次、至多被寫一次，時間 $O(n)$，空間 $O(1)$。

## 常見錯誤與邊界條件

- 保留條件寫錯方向。
- 比較對象用 `nums[fast - 1]`（原始值）而非 `nums[slow - 1]`（已寫入值），在連續重複時會出錯。
- 忘記回傳長度而回傳陣列。
- 空陣列時 `slow` 為 0 是正確結果。
- 需要保留「至多兩個重複」時判斷應改為與 `nums[slow - 2]` 比較。

## 與相似技巧的比較

相向雙指標從兩端逼近，適合有序陣列上的配對搜尋；背向雙指標從中心往外擴散，適合迴文類問題；同向雙指標則是線性掃描的通用骨架，滑動視窗正是它的一個特例——差別只在慢指標的推進條件由視窗合法性決定。

## 本節重點速查

- 快讀慢寫；
- `slow <= fast` 保證覆寫安全；
- 比較對象是已寫入的 `nums[slow - 1]`；
- 結果長度就是 `slow`。
