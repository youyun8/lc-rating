## 這個技術解決什麼問題

判斷字串 `s` 是不是 `t` 的子序列——也就是能否從 `t` 中刪去若干字元（不改變剩餘字元的相對順序）得到 `s`。這是雙序列同向雙指標最乾淨的應用。

## 辨識題型的訊號

「刪除若干元素後能否得到」「保持相對順序」「是否為子序列」。注意與子**字串**（要求連續）區分——子序列不要求連續，因此不能用滑動視窗。

## 核心想法與直覺

兩個指標分別掃 `s` 與 `t`。`t` 的指標每輪必定前進一格；只有當兩個字元相等時，`s` 的指標才前進。若 `s` 的指標走到終點，代表每個字元都依序配對成功。

貪心的核心是：對 `s[i]`，在 `t` 中選擇**最早**能匹配的位置一定不劣。因為越早匹配，留給後續字元的可用範圍就越大。

## 狀態／資料結構定義

`i` 指向 `s` 中下一個待匹配的字元，`j` 指向 `t` 中下一個待檢視的字元。已配對的前綴是 `s[0..i)`。

## 不變量或正確性證明

不變量：任一時刻，`s[0..i)` 是 `t[0..j)` 的子序列，且 `i` 是在只掃過 `t[0..j)` 的前提下所能達到的最大匹配長度。

證明貪心最優（交換論證）：設存在一組合法配對，其中 `s[i]` 配到 `t` 的位置 `p`，而演算法選的最早位置為 `q <= p`。把該配對中 `s[i]` 的對應位置由 `p` 改成 `q` 後，因為 `q < p` 且後續字元原本配在 `p` 之後、必然也在 `q` 之後，整組配對依然合法。逐一替換即可把任意合法配對轉成演算法產生的配對，故演算法若失敗則不存在任何合法配對。

終止性：`j` 每輪嚴格加一，迴圈至多執行 `|t|` 次。

## 逐步演算法

兩個指標歸零；當兩者都未走完時，若字元相等就同時推進，否則只推進 `t` 的指標；迴圈結束後檢查 `s` 的指標是否走完。

## C++17 模板

```cpp
class Solution {
public:
    bool isSubsequence(string s, string t) {
        size_t i = 0;
        for (size_t j = 0; j < t.size() && i < s.size(); ++j) {
            if (s[i] == t[j]) {
                ++i;
            }  // 配對成功才推進 s
        }
        return i == s.size();
    }
};
```

若需要對同一個 `t` 反覆查詢大量不同的 `s`（進階版），先對 `t` 預處理一張「每個位置之後某字元最早出現在哪」的表，把單次查詢降到 $O(|s| \log |t|)$ 或 $O(|s|)$：

```cpp
// next[j][c]：從位置 j 起，字元 c 最早出現的下標；不存在為 |t|。
vector<array<int, 26>> next(t.size() + 1);
next[t.size()].fill(t.size());
for (int j = t.size() - 1; j >= 0; --j) {
    next[j] = next[j + 1];
    next[j][t[j] - 'a'] = j;
}
```

## 時間與空間複雜度

單次判斷時間 $O(|s| + |t|)$，空間 $O(1)$。預處理版本建表 $O(|t| \Sigma)$，之後每次查詢 $O(|s|)$。

## 常見錯誤與邊界條件

- 在字元不相等時也推進 `s` 的指標。
- 迴圈條件漏掉 `i < s.size()` 而越界。
- 空字串 `s` 應回傳 `true`。
- `|s| > |t|` 時必為 `false`（迴圈會自然得出，不需特判）。
- 把子序列誤當成子字串而要求連續。

## 與相似技巧的比較

子字串匹配要求連續，應用 KMP 或滑動視窗；最長公共子序列需要 $O(nm)$ 的 DP，因為兩邊都可以跳過字元，貪心不再成立——本題之所以能貪心，關鍵在於 `s` 必須整個被匹配，沒有選擇跳過的自由。

## 本節重點速查

- 相等才推進 `s`；
- `t` 每輪必推進；
- 最早匹配一定不劣；
- 多次查詢就預處理 next 表。
