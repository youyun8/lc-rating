## 這個技術解決什麼問題

定長滑窗的進階用法：視窗裡維護的不再是一個數字，而是一整組計數狀態，用來判斷「這段是否為某字串的排列」「是否涵蓋所有指定單字」；或是把答案拆成「固定不變的基準」加上「視窗帶來的增量」。

## 辨識題型的訊號

要在長字串中找出所有「字母異位詞」或「排列」的起始位置；視窗長度固定但判斷條件牽涉多個字元的出現次數；題目給了一個基準收益，再問「額外挑一段長度為 `k` 的區間能多賺多少」。

## 核心想法與直覺

兩個關鍵手法。

第一是**用差異計數取代整表比對**。每次移動視窗後若都把兩張次數表整個比一遍，成本是 $O(\Sigma)$。改為維護一個 `diff` 計數——記錄「目前有幾種字元的出現次數與目標不符」——則進出各一個字元時只需 $O(1)$ 更新，`diff` 歸零即表示完全匹配。

第二是**基準與增量分離**。像「愛生氣的書店老闆」這類題目，先算出不使用技能時的固定收益，再用定長滑窗求「這段區間能額外挽回多少」，兩者相加即為答案。把不變的部分抽離，滑窗只需處理真正變動的量。

## 狀態／資料結構定義

`need` 是目標次數表，`window` 是視窗次數表，`diff` 是兩者不一致的字元種類數。基準增量型則維護 `base`（固定收益）與 `gain`（視窗內的額外收益）。

## 不變量或正確性證明

不變量：`diff` 恆等於「使 `window[c] != need[c]` 的字元 `c` 的種類數」。

維護的正確性：加入字元 `c` 時，先看它在加入前是否相符。若原本 `window[c] == need[c]`，加入後必然不符，`diff` 加一；若原本 `window[c] + 1 == need[c]`，加入後恰好相符，`diff` 減一；其餘情況不符狀態不變。移除時對稱處理。由於每次只動一個字元的計數，只有該字元的相符狀態可能改變，因此 $O(1)$ 更新足以維持不變量。

於是「視窗內容是目標的一個排列」等價於 `diff == 0`，判斷成本從 $O(\Sigma)$ 降為 $O(1)$。

基準增量的正確性來自可加性：總收益 = 不受影響的固定部分 + 受區間選擇影響的部分，兩者互不重疊，故分別最大化後相加即為整體最優。

## 逐步演算法

建立目標次數表並初始化 `diff`；沿用定長滑窗的入、更新、出三步；每次進出時 $O(1)$ 維護 `diff`；視窗滿 `k` 且 `diff` 為 0 時記錄答案。

## C++17 模板

找出所有字母異位詞的起始下標：

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        if (s.size() < p.size()) {
            return {};
        }
        array<int, 26> need{}, window{};
        for (char c : p) {
            ++need[c - 'a'];
        }

        int diff = 0;
        for (int c = 0; c < 26; ++c) {
            if (need[c] != 0) {
                ++diff;
            }  // 一開始 window 全為 0
        }

        auto add = [&](int c, int delta) {
            if (window[c] == need[c]) {
                ++diff;
            }  // 本來相符，要變不符
            window[c] += delta;
            if (window[c] == need[c]) {
                --diff;
            }  // 變成相符
        };

        vector<int> answer;
        const int k = p.size();
        for (int right = 0; right < static_cast<int>(s.size()); ++right) {
            add(s[right] - 'a', 1);  // 入
            if (right < k - 1) {
                continue;
            }
            if (diff == 0) {
                answer.push_back(right - k + 1);
            }  // 更新
            add(s[right - k + 1] - 'a', -1);  // 出
        }
        return answer;
    }
};
```

## 時間與空間複雜度

每個字元進出各一次且更新為 $O(1)$，時間 $O(n)$，與字元集大小無關。空間 $O(\Sigma)$。若視窗單位是「單字」而非字元（串聯所有單字的子串），需對每個起始偏移各跑一次滑窗，時間 $O(n \cdot L)$，其中 `L` 為單字長度。

## 常見錯誤與邊界條件

- `diff` 的初始值算錯（視窗為空時，`diff` 應等於 `need` 中非零的種類數）。
- 更新 `diff` 時只在加入後檢查而忘了加入前的狀態。
- `s` 比 `p` 短時未特判。
- 串聯單字題把偏移量的迴圈寫成從 0 到 `n` 而非從 0 到 `L - 1`。
- 基準增量型忘記把基準加回答案。

## 與相似技巧的比較

直接比對兩張次數表也能得到正確答案，只是每步多了 $O(\Sigma)$ 的常數，在字元集小時實務上可接受；排序後比對則是 $O(k \log k)$ 每步，明顯更慢。`diff` 計數的價值在於把判斷降到 $O(1)$，也是「最小覆蓋子字串」中 `missing` 計數的同一套思路。

## 本節重點速查

- 用 `diff` 取代整表比對；
- 更新前後都要檢查相符狀態；
- 基準與增量分開算；
- 視窗骨架仍是入、更新、出。
