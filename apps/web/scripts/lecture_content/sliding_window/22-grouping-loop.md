## 這個技術解決什麼問題

當陣列會依題意被切成若干段、而每段的判斷邏輯完全相同時（連續遞增段、相同字元段、交替奇偶段），分組迴圈提供一個不需要特判最後一組的固定寫法。

## 辨識題型的訊號

題目描述「最長的連續遞增子陣列」「把相同字元壓縮」「最長交替子陣列」；直覺上想寫「遇到分界就結算」但總是在收尾時漏掉最後一組。

## 核心想法與直覺

問題出在「邊掃邊結算」把兩件事混在一起。分組迴圈把職責徹底分開：

外層迴圈負責**進入一組之前的準備**（記下這組的起點）與**離開一組之後的統計**（用起點與終點更新答案）；內層迴圈只負責**找出這組最遠延伸到哪裡**。

因為外層迴圈的條件就是「還有未處理的元素」，最後一組會自然地被同一段程式處理掉，不需要在迴圈外再補一次結算——這正是這個寫法最不容易出錯的原因。

## 狀態／資料結構定義

`i` 是目前掃描位置，同時也是外層迴圈的游標；`start` 記錄當前這一組的起始下標。組長度為 `i - start`。

## 不變量或正確性證明

不變量：每次外層迴圈開始時，`i` 指向一個尚未被歸入任何組的元素，且 `[0, i)` 已被完整劃分成若干組並全部結算過。

證明分組不重不漏：內層迴圈從 `start = i` 出發，只要下一個元素仍滿足同組條件就推進 `i`，停止時 `[start, i)` 恰為一個極大的同質段（再多一個元素就會違反條件）。外層隨即以此段更新答案，然後帶著新的 `i` 進入下一輪。由於每輪至少推進一格（內層第一次比較之前 `i` 已指向組內第一個元素），迴圈必然終止；又因為每個下標恰好屬於一個 `[start, i)` 區間，劃分是原始序列的一個分割，故不重不漏。最後一組由最後一次外層迭代處理，無需特判。

## 逐步演算法

外層 `while (i < n)`：記下 `start = i`；內層 `while` 依同組條件推進 `i`；退出內層後用 `[start, i)` 更新答案；回到外層繼續下一組。

## C++17 模板

以「最長連續遞增子陣列長度」為例：

```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        const int n = nums.size();
        int answer = 0, i = 0;

        while (i < n) {
            const int start = i;  // 一、準備
            ++i;
            while (i < n && nums[i] > nums[i - 1]) {  // 二、找出這組的終點
                ++i;
            }
            answer = max(answer, i - start);  // 三、統計，不必特判最後一組
        }
        return answer;
    }
};
```

若分組條件是「相同字元」，內層改成 `while (i < n && s[i] == s[start])`；若是「交替奇偶」，改成 `while (i < n && nums[i] % 2 != nums[i - 1] % 2)`。骨架完全不動。

## 時間與空間複雜度

每個下標恰好被內層推進一次，時間 $O(n)$，空間 $O(1)$。

## 常見錯誤與邊界條件

- 內層條件用到 `nums[i - 1]` 卻沒有先 `++i`，導致第一次比較越界或恆真。
- 忘記在外層先存下 `start`。
- 把 `i` 在外層額外再加一次造成跳格漏組。
- 空陣列時外層不執行、答案為 0 是正確行為。
- 組長度算成 `i - start + 1`（此處 `i` 已是組後一格，正確的是 `i - start`）。

## 與相似技巧的比較

「邊掃邊結算」的寫法需要在迴圈外補上最後一組，是常見的錯誤來源；滑動視窗處理的是可伸縮的視窗，而分組迴圈處理的是互不重疊的分割，兩者適用場景不同。當每組還需要內部統計（例如組內最大值）時，只要在內層迴圈裡順手維護即可，骨架不變。

## 本節重點速查

- 外層準備與統計、內層找終點；
- 不必特判最後一組；
- 組長度是 `i - start`；
- `start` 要先存。
