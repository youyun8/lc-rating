## 這個技術解決什麼問題

求滿足某個條件的最長連續子陣列。這裡的條件具有「越短越容易滿足」的單調性——例如「所有元素互不相同」「元素和不超過 `k`」「最多含 `k` 個奇數」。

## 辨識題型的訊號

問「最長」的子陣列或子字串，且條件在縮短視窗時只會更容易成立。若條件是「越長越容易滿足」（例如元素和至少為 `k`），那要求的會是最短，屬於另一節。

## 核心想法與直覺

右端點主動向右擴張，一旦條件被破壞，就讓左端點向右收縮直到條件恢復。因為條件越短越容易滿足，收縮一定能救回來，而且不需要回頭——左端點永遠不必左移。

為什麼左端點不必回頭：若某個左端點在 `right` 時已經不合法，那麼 `right` 再變大只會讓情況更糟，這個左端點永遠不會再合法，因此可以安全地永久拋棄。這正是雙指標總複雜度為線性的原因。

## 狀態／資料結構定義

視窗為 `[left, right]`，另外維護足以判斷條件的量：`unordered_map` 記元素出現次數、`sum` 記區間和、`count` 記違規元素個數。

## 不變量或正確性證明

不變量：每輪內層 `while` 結束後，視窗 `[left, right]` 是滿足條件的，且對這個 `right` 而言 `left` 是最小的合法左端點。

證明最優性：任何以 `right` 為右端點的合法子陣列，其左端點必然不小於當前的 `left`——因為若存在更小的合法左端點 `l < left`，則區間 `[l, right]` 合法，而收縮過程中 `left` 之所以推進到現在的位置，是因為每一個被拋棄的左端點在當時都使視窗不合法；由條件的單調性（更短更容易滿足，等價地更長更難滿足），`[l, right]` 包含那個不合法的更短區間，故也不合法，矛盾。因此 `right - left + 1` 就是以 `right` 結尾的最長合法長度，對所有 `right` 取最大即為答案。

## 逐步演算法

右端點逐一右移並把新元素併入維護量；用內層 `while` 在條件被破壞時移出左端元素，直到條件恢復；此時用 `right - left + 1` 更新答案。

## C++17 模板

以「最長無重複字元子字串」為例：

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        unordered_map<char, int> count;
        int answer = 0, left = 0;

        for (int right = 0; right < static_cast<int>(s.size()); ++right) {
            ++count[s[right]];             // 入
            while (count[s[right]] > 1) {  // 條件被破壞就收縮
                --count[s[left]];
                ++left;
            }
            answer = max(answer, right - left + 1);  // 此時視窗合法
        }
        return answer;
    }
};
```

收縮條件的寫法是關鍵：內層 `while` 的判斷應該是「目前不合法」，而不是「合法」。以元素和不超過 `k` 為例，寫成 `while (sum > k) { sum -= nums[left++]; }`。

## 時間與空間複雜度

`left` 與 `right` 各自單調右移且不回頭，總移動次數為 $O(n)$，時間 $O(n)$。空間為維護量的大小，通常 $O(1)$ 到 $O(n)$。

## 常見錯誤與邊界條件

- 把更新答案寫在收縮之前，導致統計到不合法的視窗。
- 內層寫成 `if` 而非 `while`，一次收縮救不回來。
- 收縮時忘了同步更新維護量。
- 用 `unordered_map` 判斷存在性時因 `operator[]` 而意外插入鍵。
- 空陣列應回傳 0。

## 與相似技巧的比較

「求最短」的版本節奏相反：在視窗合法時收縮並更新答案。「求個數」的版本在合法時累加 `right - left + 1`。三者共用同一個雙指標骨架，差別只在更新答案的時機與收縮條件的方向，值得放在一起記。

## 本節重點速查

- 條件越短越易滿足才適用；
- 不合法就收縮；
- `left` 永不回頭；
- 答案在收縮之後才更新。
