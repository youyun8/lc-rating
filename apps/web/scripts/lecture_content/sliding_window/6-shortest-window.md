## 這個技術解決什麼問題

求滿足某個條件的最短連續子陣列。這裡的條件具有「越長越容易滿足」的單調性——例如「元素和至少為 `k`」「包含目標字串的所有字元」「不同元素數不少於 `m`」。

## 辨識題型的訊號

問「最短」「最小長度」的子陣列或子字串，且把視窗加長只會讓條件更容易成立。經典題型是「和至少為 `target` 的最短子陣列」與「最小覆蓋子字串」。

## 核心想法與直覺

節奏與求最長恰好相反。右端點擴張直到條件被滿足，然後在**仍然合法**的前提下盡量收縮左端點，每收縮一步就更新一次答案。也就是說：求最長是「不合法才收縮，收縮完更新」；求最短是「合法就收縮，收縮時更新」。

## 狀態／資料結構定義

視窗為 `[left, right]`，維護量需要能判斷「是否已滿足條件」：`sum` 為區間和；覆蓋類問題用 `need` 記錄還缺多少種字元，配合次數表。

## 不變量或正確性證明

不變量：每輪內層 `while` 結束後，視窗 `[left, right]` 不再滿足條件，而 `[left - 1, right]` 是滿足條件的最短的、以 `right` 為右端點的合法區間。

證明最優性：任何合法的最短子陣列 `[l, r]` 都會被檢查到。當右端點掃到 `r` 時，因為 `[l, r]` 合法且條件具「越長越易滿足」的單調性，此刻視窗 `[left, r]` 只要 `left <= l` 就合法，內層迴圈會持續收縮；它停止的位置 `left` 必然滿足 `left > l` 或恰好在 `l` 之後一格，於是在收縮過程中 `[l, r]` 這個長度一定被 `right - left + 1` 取到過。因此對所有 `right` 取最小值即為全域最短。

## 逐步演算法

右端點右移並併入新元素；用內層 `while` 在條件已滿足時更新答案，然後移出左端元素繼續嘗試更短；右端點掃完即得答案。

## C++17 模板

以「和至少為 `target` 的最短子陣列」為例：

```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        const int n = nums.size();
        long long sum = 0;
        int answer = n + 1, left = 0;

        for (int right = 0; right < n; ++right) {
            sum += nums[right];                          // 入
            while (sum >= target) {                      // 合法就收縮
                answer = min(answer, right - left + 1);  // 收縮時更新
                sum -= nums[left];
                ++left;
            }
        }
        return answer <= n ? answer : 0;  // 沒有解回傳 0
    }
};
```

最小覆蓋子字串的差別只在「是否合法」的判斷方式——用一個 `need` 計數表示還缺幾種字元，減到 0 表示已覆蓋：

```cpp
if (--need[c] == 0) {
    --missing;
}  // 加入時
while (missing == 0) { /* 更新答案並移出左端 */
}
```

## 時間與空間複雜度

兩個指標各自單調右移，時間 $O(n)$（覆蓋類問題含字元集常數）。空間 $O(1)$ 或 $O(\Sigma)$。

## 常見錯誤與邊界條件

- 把更新答案寫在收縮之後，漏掉最短的那一格。
- 答案初始值設成 0 而無法取 `min`。
- 無解時未回傳題目要求的 0 或 -1。
- 元素可能為負時「和至少為 `target`」不再具單調性，滑窗失效，必須改用前綴和加單調佇列。
- 覆蓋類問題把「次數過多」誤判成不合法。

## 與相似技巧的比較

求最長的版本收縮條件相反，兩者常被記混，判準是「條件在加長時變易還是變難」。若元素含負數而破壞單調性，改用前綴和搭配單調佇列（求最短）或有序集合。若問的是個數而非長度，見「求子陣列個數」各節。

## 本節重點速查

- 條件越長越易滿足才適用；
- 合法就收縮；
- 收縮時就要更新答案；
- 無解記得回傳 0。
