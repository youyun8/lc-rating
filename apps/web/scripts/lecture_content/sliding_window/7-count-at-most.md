## 這個技術解決什麼問題

統計滿足某條件的子陣列**個數**，其中條件「越短越容易滿足」——例如「元素和不超過 `k`」「最多含 `m` 種不同元素」「不含重複元素」。

## 辨識題型的訊號

問「有多少個子陣列／子字串滿足……」，且把視窗縮短後條件依然成立。這類條件通常寫成「至多」「不超過」「最多 `k` 個」。

## 核心想法與直覺

沿用求最長的骨架：右端點擴張，不合法就收縮，收縮完視窗 `[left, right]` 合法。此時關鍵的一步是累加 `right - left + 1`。

理由是：固定右端點為 `right`，以它結尾的合法子陣列恰好是 `[left, right]`、`[left+1, right]`、……、`[right, right]`，共 `right - left + 1` 個。因為條件越短越容易滿足，這些更短的區間全都合法；而左端點小於 `left` 的都不合法。於是每個 `right` 貢獻的數量可以 $O(1)$ 算出。

## 狀態／資料結構定義

視窗 `[left, right]` 加上判斷條件所需的維護量。答案用 `long long` 累加——子陣列總數可達 $n(n+1)/2$，在 $n = 10^5$ 時已超過 32 位元。

## 不變量或正確性證明

不變量：每輪內層 `while` 結束後，`left` 是使 `[left, right]` 合法的最小左端點。

由此可證計數不重不漏：每個合法子陣列由其右端點唯一決定歸屬——我們把它算在自己的右端點那一輪。對固定的 `right`，合法左端點的集合恰為 `{left, left+1, ..., right}`，這是一個連續區間（因為條件的單調性保證：若 `[l, right]` 合法，則任何 `l' > l` 的 `[l', right]` 更短、也合法）。因此該輪貢獻恰為 `right - left + 1`，各輪之間互不重疊，總和即為答案。

## 逐步演算法

右端點右移並併入新元素；內層 `while` 在不合法時移出左端元素；收縮結束後累加 `right - left + 1`；掃完回傳總和。

## C++17 模板

以「元素和嚴格小於 `k` 的子陣列個數」為例（元素皆為正）：

```cpp
class Solution {
public:
    long long countSubarrays(vector<int>& nums, long long k) {
        long long answer = 0, sum = 0;
        int left = 0;

        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            sum += nums[right];                  // 入
            while (left <= right && sum >= k) {  // 不合法就收縮
                sum -= nums[left];
                ++left;
            }
            answer += right - left + 1;  // 以 right 結尾的合法子陣列個數
        }
        return answer;
    }
};
```

「最多 `m` 種不同元素」只需把收縮條件換成 `while (count.size() > m)`，並在移出時清掉歸零的鍵，累加那行完全不變。

## 時間與空間複雜度

雙指標各自單調右移，時間 $O(n)$；空間 $O(1)$ 或 $O(\min(n, \Sigma))$。

## 常見錯誤與邊界條件

- 累加寫成 `right - left`（少算了單元素子陣列）。
- 答案未用 `long long` 而溢位。
- 元素含 0 或負數時單調性被破壞（例如「和不超過 `k`」在有負數時失效），需改用前綴和加有序集合。
- 收縮迴圈缺少 `left <= right` 保護導致越界。

## 與相似技巧的比較

「越長越合法」的計數版本累加的是 `left` 而不是 `right - left + 1`；「恰好型」則用兩次「至多」相減。三者的骨架相同，差別只在累加式與收縮條件，建議對照著記。

## 本節重點速查

- 收縮完累加 `right - left + 1`；
- 合法左端點是連續區間；
- 答案用 `long long`；
- 有負數就不能用。
