## 這個技術解決什麼問題

統計滿足某條件的子陣列**個數**，其中條件「越長越容易滿足」——例如「元素和至少為 `k`」「至少包含 `m` 種不同元素」「涵蓋目標集合」。

## 辨識題型的訊號

問「有多少個子陣列滿足……」，且條件寫成「至少」「不少於」「包含全部」。把視窗加長條件依然成立，這正是與上一節相反的單調方向。

## 核心想法與直覺

骨架仍是雙指標，但累加的東西不同。右端點擴張，只要視窗合法就收縮左端點；收縮結束時 `[left, right]` 已經**不**合法，而 `[0, right]` 到 `[left-1, right]` 這些更長的區間全都合法。

於是以 `right` 結尾的合法子陣列個數恰為 `left`——左端點可以取 `0, 1, ..., left-1`，共 `left` 個。記法很簡單：至多型累加 `right - left + 1`，至少型累加 `left`。

## 狀態／資料結構定義

視窗 `[left, right]` 加上判斷條件的維護量。答案用 `long long`。注意這裡 `left` 停在「第一個使視窗不合法」的位置，與至多型的語意不同。

## 不變量或正確性證明

不變量：每輪內層 `while` 結束後，`left` 是使 `[left, right]` 不合法的最小左端點；等價地，`[left - 1, right]` 合法（當 `left > 0` 時）。

計數的正確性：對固定的 `right`，合法左端點的集合是 `{0, 1, ..., left-1}`。這是一個連續區間，因為條件「越長越容易滿足」意味著若 `[l, right]` 合法，則任何 `l' < l` 的 `[l', right]` 更長、也合法。收縮迴圈停在第一個不合法處，所以恰好有 `left` 個合法左端點。每個合法子陣列只在其右端點那一輪被計入一次，故不重不漏。

## 逐步演算法

右端點右移並併入新元素；內層 `while` 在**合法**時移出左端元素並推進 `left`；收縮結束後累加 `left`；掃完回傳總和。

## C++17 模板

以「元素和至少為 `k` 的子陣列個數」為例（元素皆為正）：

```cpp
class Solution {
public:
    long long countSubarrays(vector<int>& nums, long long k) {
        long long answer = 0, sum = 0;
        int left = 0;

        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            sum += nums[right];  // 入
            while (sum >= k) {   // 合法就收縮
                sum -= nums[left];
                ++left;
            }
            answer += left;  // 左端點取 0..left-1 都合法
        }
        return answer;
    }
};
```

「至少包含 `m` 種不同元素」把收縮條件換成 `while (count.size() >= m)`，移出時記得清掉歸零的鍵，累加那行同樣不變。

## 時間與空間複雜度

雙指標各自單調右移，時間 $O(n)$；空間 $O(1)$ 或 $O(\min(n, \Sigma))$。

## 常見錯誤與邊界條件

- 把累加式與至多型互換（這是本節最常見的錯誤）。
- 誤以為收縮後的視窗是合法的——恰恰相反，它是第一個不合法的。
- `left` 可能推進到 `right + 1`，此時 `sum` 為 0，屬正常狀態。
- 答案未用 `long long`。
- 元素含負數時單調性失效。

## 與相似技巧的比較

至多型累加 `right - left + 1` 且收縮後視窗合法；至少型累加 `left` 且收縮後視窗不合法。兩者是同一骨架的鏡像。恰好型則用兩次至少（或兩次至多）相減，見下一節。

## 本節重點速查

- 合法就收縮；
- 收縮後累加 `left`；
- 收縮完的視窗是不合法的；
- 與至多型互為鏡像。
