## 這個技術解決什麼問題

統計「恰好」滿足某個數量條件的子陣列個數——恰好含 `k` 個奇數、恰好有 `k` 種不同元素、元素和恰好等於 `k`。「恰好」本身不具單調性，無法直接用一次滑窗解決。

## 辨識題型的訊號

題目出現「恰好」「正好」「剛好等於 `k`」，而對應的「至多 `k`」或「至少 `k`」版本是標準滑窗題。

## 核心想法與直覺

把「恰好」拆成兩個具單調性的問題相減：

$$\text{恰好}(k) = \text{至多}(k) - \text{至多}(k-1)$$

或等價地 $\text{恰好}(k) = \text{至少}(k) - \text{至少}(k+1)$。

這樣就能把滑窗邏輯封裝成一個函式 `solve`，呼叫兩次即可，不必寫兩份不同的滑窗程式。

## 狀態／資料結構定義

一個接受參數 `k` 的輔助函式，內部是標準的至多型（或至少型）滑窗；外部用兩次呼叫的差值當答案。

## 不變量或正確性證明

輔助函式內部沿用至多型滑窗的不變量：收縮結束後 `left` 是使 `[left, right]` 合法的最小左端點，該輪貢獻 `right - left + 1`。

相減的正確性：令 $A_{\le j}$ 為「數量不超過 `j`」的子陣列集合。因為「數量不超過 `k-1`」蘊含「數量不超過 `k`」，有包含關係 $A_{\le k-1} \subseteq A_{\le k}$，且差集 $A_{\le k} \setminus A_{\le k-1}$ 恰為數量嚴格大於 `k-1` 且不超過 `k` 的子陣列，也就是數量恰好等於 `k` 者。取基數即得 $|\text{恰好}(k)| = |A_{\le k}| - |A_{\le k-1}|$。這裡唯一的要求是「數量」必須是整數值的量，否則 `k-1` 這個切點沒有意義。

## 逐步演算法

寫一個至多型滑窗函式 `atMost(k)`，回傳數量不超過 `k` 的子陣列個數；答案為 `atMost(k) - atMost(k - 1)`；注意 `k` 為 0 時 `atMost(-1)` 應回傳 0。

## C++17 模板

以「恰好含 `k` 個奇數的子陣列個數」為例：

```cpp
class Solution {
public:
    int numberOfSubarrays(vector<int>& nums, int k) {
        return atMost(nums, k) - atMost(nums, k - 1);
    }

private:
    // 奇數個數不超過 k 的子陣列個數。
    long long atMost(const vector<int>& nums, int k) {
        if (k < 0) {
            return 0;
        }  // 邊界：k 為 0 時會呼叫到 -1
        long long answer = 0;
        int left = 0, odd = 0;

        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            odd += nums[right] & 1;
            while (odd > k) {
                odd -= nums[left] & 1;
                ++left;
            }
            answer += right - left + 1;
        }
        return answer;
    }
};
```

另一種寫法是把兩個滑窗合併：維護同一個右端點與兩個左端點 `left1`、`left2`，答案累加 `left2 - left1`。這稱為**三指標滑動視窗**，只掃一遍，見「三指標」一節。

## 時間與空間複雜度

兩次滑窗各為 $O(n)$，總時間 $O(n)$；空間 $O(1)$ 或 $O(\min(n, \Sigma))$。三指標合併版本同為 $O(n)$ 但只掃一遍。

## 常見錯誤與邊界條件

- `k` 為 0 時忘記處理 `atMost(-1)`，導致收縮迴圈永遠成立而越界。
- 用「至少」版本相減時方向寫反（應為 `atLeast(k) - atLeast(k + 1)`）。
- 兩次呼叫共用了未重置的狀態。
- 答案未用 `long long`。
- 把「和恰好等於 `k`」在含負數時硬套此法——此時應改用前綴和加雜湊表。

## 與相似技巧的比較

前綴和加雜湊表能直接處理「和恰好等於 `k`」且允許負數，是更通用的工具；本法的優勢在於處理「不同元素種類數」這類無法用前綴和相減表示的量。三指標合併版本省一次掃描，但程式較易寫錯。

## 本節重點速查

- 恰好 = 至多 `k` 減至多 `k-1`；
- 封裝成函式呼叫兩次；
- `k` 為 0 要擋住 `-1`；
- 含負數的和要改用前綴和。
