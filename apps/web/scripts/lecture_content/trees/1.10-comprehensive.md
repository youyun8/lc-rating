## 這個技術解決什麼問題

LRU（146）、LFU（460）、快取與迭代器設計題要求**每個操作都是 $O(1)$**。單用雜湊表能 $O(1)$ 查值，但找不到「最久沒用的是誰」；單用鏈能 $O(1)$ 移動節點，但找不到指定 key 在哪。

槓桿在於**組合**：雜湊表存 `key -> 節點指標`，雙向鏈維護使用次序。查詢用雜湊表定位，重排用鏈的改邊；兩者各自補上對方的短板，於是插入、查詢、淘汰全部 $O(1)$。這是「用空間換操作時間、用兩種結構換單一結構做不到的組合能力」的典型例子。

## 狀態／資料結構定義

- `unordered_map<int, Node*> mp`：key 到節點的直接指標。存指標而非索引，才能 $O(1)$ 拿到節點。
- 雙向鏈 `Node { key, val, prev, next }`：**必須雙向**。單向鏈刪除節點需要前驅，而從雜湊表拿到的是節點本身，找前驅要 $O(n)$，$O(1)$ 就破功了。
- 節點必須存 `key`：淘汰尾節點時要用它從雜湊表中 `erase`，否則有節點沒 key 可刪，雜湊表會殘留失效指標。
- 兩個哨兵 `head`、`tail` 首尾相連：讓所有插入刪除都在「有前驅也有後繼」的情形下進行，完全免去空鏈與頭尾特例。約定 `head->next` 是最近使用、`tail->prev` 是最久未用。

LFU 再加一層：`freq -> 該頻次的雙向鏈`，以及 `minFreq`。

## 不變量或正確性證明

LRU 的資料結構不變量有三條，每個操作前後都必須成立：

1. `mp` 的鍵集合恰等於鏈中節點的 key 集合，且 `mp[k]` 指向鏈中那個節點（無失效指標、無遺漏）。
2. 鏈從 `head->next` 到 `tail->prev` 依「最近使用時間」由新到舊排列。
3. 鏈長（不含哨兵）不超過 `capacity`。

驗證 `get(k)`：若 `k` 不在 `mp` 回傳 $-1$，三條不變量未被觸碰。若在，取出節點、從原位置摘除、插到 `head` 之後。摘除與插入都不改變節點集合，故條件 1、3 維持；條件 2 成立是因為該節點剛被使用，理應排最前，其餘節點相對次序不變。

驗證 `put(k, v)`：若 `k` 已存在，更新值並移到最前，同上。若不存在，先建節點插到最前並登記到 `mp`（條件 1、2 維持，鏈長加一）；若此時超過容量，摘除 `tail->prev` 並用**該節點存的 key** 從 `mp` 中 erase，鏈長回到容量內，條件 1、3 恢復。

**淘汰的正確性**：由條件 2，`tail->prev` 是所有節點中最久未被使用者，正是 LRU 定義要淘汰的對象。這個推論完全依賴條件 2，而條件 2 又依賴「每次存取都把節點移到最前」——這就是為什麼 `get` 命中時也必須移動，只讀不移是最常見的錯誤。

順序也有講究：**必須先插入再檢查淘汰**。若先淘汰再插入，當容量為 1 且插入的是新 key 時仍正確，但若寫成「先淘汰」且新 key 恰是被淘汰者，就會出現先刪後加的多餘工作；更嚴重的是若容量檢查用 `>=` 而非 `>`，容量未滿時也會誤淘汰。

LFU 的額外不變量是 `minFreq` 等於所有節點頻次的最小值。它只在兩處可能改變：插入新節點時必然重置為 1；某節點頻次從 `minFreq` 升上去且該頻次鏈變空時，`minFreq` 加一即可——**不需要重新掃描**，因為頻次每次只加 1，最小值最多也只上升 1。這個攤還論證是 LFU 能做到 $O(1)$ 的關鍵。

## C++17 模板

```cpp
// LRU 快取（LeetCode 146）：雜湊表 + 雙向鏈，get/put 皆 O(1)。
class LRUCache {
    struct Node {
        int key, val;
        Node *prev = nullptr, *next = nullptr;
        Node(int k, int v) : key(k), val(v) {}
    };

    int cap_;
    Node* head_;  // 哨兵：head_->next 是最近使用
    Node* tail_;  // 哨兵：tail_->prev 是最久未用
    std::unordered_map<int, Node*> mp_;

    void remove(Node* n) {  // 從鏈上摘除；雙向鏈才能 O(1)
        n->prev->next = n->next;
        n->next->prev = n->prev;
    }
    void pushFront(Node* n) {  // 插到最前，代表剛被使用
        n->next = head_->next;
        n->prev = head_;
        head_->next->prev = n;
        head_->next = n;
    }

public:
    explicit LRUCache(int capacity) : cap_(capacity) {
        head_ = new Node(0, 0);
        tail_ = new Node(0, 0);
        head_->next = tail_;  // 兩個哨兵首尾相連，免去所有邊界特例
        tail_->prev = head_;
    }

    int get(int key) {
        auto it = mp_.find(key);
        if (it == mp_.end()) {
            return -1;
        }
        remove(it->second);
        pushFront(it->second);  // 命中也要移到最前，否則不變量 2 崩壞
        return it->second->val;
    }

    void put(int key, int value) {
        if (auto it = mp_.find(key); it != mp_.end()) {
            it->second->val = value;
            remove(it->second);
            pushFront(it->second);
            return;
        }
        Node* n = new Node(key, value);
        mp_[key] = n;
        pushFront(n);
        if (static_cast<int>(mp_.size()) > cap_) {  // 先插入再淘汰
            Node* victim = tail_->prev;
            remove(victim);
            mp_.erase(victim->key);  // 節點必須存 key，才刪得掉雜湊表項
            delete victim;
        }
    }
};
```

C++ 也可直接用 `std::list` 加 `unordered_map<int, list<...>::iterator>`，`splice` 能 $O(1)$ 移動節點且不使迭代器失效。

## 時間與空間複雜度

`get` 與 `put` 都是 $O(1)$ **均攤**：雜湊表查找均攤 $O(1)$（最壞 $O(n)$，發生在大量雜湊碰撞時），鏈上的摘除與插入是最壞 $O(1)$。空間 $O(\text{capacity})$，雜湊表與鏈各存一份指標。

LFU 同樣是均攤 $O(1)$，關鍵在 `minFreq` 的維護只需常數次更新，如前述攤還論證。

## 常見錯誤與邊界條件

- `get` 命中時忘記把節點移到最前（測資稍長就會露餡）。
- 用單向鏈導致刪除需找前驅而退化成 $O(n)$。
- 節點不存 `key`，淘汰時無法從雜湊表刪除，留下失效指標。
- 容量檢查用 `>=` 而在未滿時誤淘汰。
- `capacity` 為 0 的情形。
- `put` 已存在的 key 時又插入一個新節點造成重複。
- 忘記 `delete` 被淘汰節點（記憶體洩漏）。
- LFU 忘記在插入新節點時把 `minFreq` 重設為 1。

## 與相似技巧的比較

- 只需要「先進先出」淘汰用單純佇列即可，不必雙向鏈；LRU 之所以要雙向鏈，是因為需要把**中間**的節點移到最前。
- 若允許 $O(\log n)$，用平衡樹依時間戳排序也能實作，程式碼較短但更慢；面試明確要求 $O(1)$ 時只能用本節的組合。
- 設計題（707 設計鏈、432 全 $O(1)$ 資料結構、1019 鏈中下一個更大元素）的共同套路都是「先問清楚每個操作的目標複雜度，再反推需要哪幾種結構組合」。1019 則是把鏈倒成陣列後用單調堆疊，屬於換結構而非組合結構。

## 本節重點速查

- 雜湊表管定位、雙向鏈管次序，兩者組合達成 $O(1)$。
- 必用雙向鏈與雙哨兵；
- 節點要存 key 以便反向刪雜湊表項；
- `get` 命中也要移到最前；
- 先插入再淘汰。
- 核心不變量是「鏈序即最近使用序」。
