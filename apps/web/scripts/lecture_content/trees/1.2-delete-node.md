## 這個技術解決什麼問題

從陣列刪一個元素要把後面全部往前搬，$O(n)$；刪 $k$ 個就是 $O(nk)$。連結串列的節點只靠 `next` 相連，**刪除等於改一條邊**：讓前一個節點跳過被刪者，$O(1)$ 完成，走一趟就能刪掉所有符合條件的節點，總計 $O(n)$。

真正的麻煩不是刪除本身，而是「頭節點也可能被刪」——頭沒有前一個節點，於是程式碼被迫分裂成兩套邏輯。dummy head 就是為了消掉這個特例。

**延伸講解**：[刪除鏈表重複節點【基礎演算法精講 08】](https://www.bilibili.com/video/BV1VP4y1Q71e/)

## 狀態／資料結構定義

- `ListNode dummy; dummy.next = head;`：哨兵節點，語意是「一個保證不會被刪、且排在真正頭節點之前的位置」。
- `prev`：指向**已確定保留**的最後一個節點，初始為 `&dummy`。
- `prev->next`：待判定的節點。
- 回傳值一律是 `dummy.next`，而不是原本的 `head`——`head` 可能已被刪掉。

不變量所依賴的語意：`dummy -> ... -> prev` 這段是最終答案的前綴，且已經定案。

## 不變量或正確性證明

迴圈不變量：**每次檢查迴圈條件時，從 `dummy` 到 `prev` 的這條鏈，恰好是「原串列前綴中所有應保留節點」依原順序串成的鏈，且 `prev->next` 指向原串列中下一個待判定的節點。**

- 初始化：`prev = &dummy`，保留鏈為空，`prev->next = head` 是第一個待判定者，成立。
- 保持：設 `cur = prev->next`。若 `cur` 該刪，執行 `prev->next = cur->next`；保留鏈不變（仍以 `prev` 結尾），而待判定者變成原串列中 `cur` 的後繼，兩個條件都維持。若 `cur` 該留，執行 `prev = cur`；保留鏈末端接上 `cur`（它確實該留），待判定者變成 `cur->next`，同樣維持。
- 終止：`prev->next == nullptr` 時待判定集合為空，保留鏈就是所有應保留節點，故 `dummy.next` 是答案。

這裡有兩個容易被略過的前提。其一，刪除判定只能看 `cur` 本身（或已走過的資訊）；像 82 題「重複的全刪」需要看後繼，就得把判定條件改成對 `prev->next` 這一整段等值區塊做，不能逐點判。其二，`prev` 永不為 `nullptr`——這正是 dummy 保證的，也是不必為頭節點寫特例的原因。

至於 237 題那種「只給你要刪的節點、拿不到 `prev`」的變形，做法是把後繼的值複製到自己身上再刪後繼；它的正確性依賴「被刪者不是尾節點」，因為尾節點沒有後繼可以借。

## C++17 模板

```cpp
// 刪除所有值等於 val 的節點。
ListNode* removeElements(ListNode* head, int val) {
    ListNode dummy;  // 哨兵：保證每個節點都有「前一個」
    dummy.next = head;

    ListNode* prev = &dummy;  // 已確定保留的最後一個節點
    while (prev->next) {
        if (prev->next->val == val) {
            prev->next = prev->next->next;  // 跳過：改一條邊即完成刪除
        } else {
            prev = prev->next;  // 保留：前緣往前推
        }
    }
    return dummy.next;  // 不能回傳 head，它可能已被刪掉
}
```

刪除後若需自行管理記憶體，先用暫存指標抓住被刪節點再改邊，否則改完就找不到它了。

## 時間與空間複雜度

`prev` 單向前進、從不回頭，每個節點最多被判定一次，故時間 $O(n)$。空間 $O(1)$：只有一個哨兵與一個指標，與刪除幾個節點無關。相對地，用陣列做同樣的事需要 $O(n)$ 搬移或額外 $O(n)$ 空間。

## 常見錯誤與邊界條件

- 回傳 `head` 而非 `dummy.next`（頭被刪時就錯）。
- 刪除後仍執行 `prev = prev->next`，導致連續的目標節點被跳過只刪掉一個。
- 忘記 `prev->next` 可能為 `nullptr` 就存取 `prev->next->val`。
- 82 題把「刪重複」寫成逐點比對，只刪掉重複區塊的一部分。
- `dummy` 宣告成區域變數卻回傳指向它的指標（回傳 `dummy.next` 沒問題，回傳 `&dummy` 就是懸空）。
- 空串列輸入。

## 與相似技巧的比較

- 插入（1.3）與刪除是同一套「改箭頭」手法的正反面，都靠 dummy 消除頭部特例。
- 需要刪的是「倒數第 $k$ 個」時，配合前後指標（1.5）一趟定位再刪。
- 若要刪除的是子串列或需重排順序，改用雙指標拆鏈（1.7）比逐點刪乾淨。
- 陣列的對應技巧是原地雙指標覆寫；差別在陣列搬資料、連結串列搬指標。

## 本節重點速查

- 一律先架 dummy；
- `prev` 只在「保留」時前進，「刪除」時原地不動；
- 回傳 `dummy.next`。
- 不變量是「`dummy` 到 `prev` 已是定案的答案前綴」。
