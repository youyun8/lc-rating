## 這個技術解決什麼問題

陣列插入要把後面全部往後推，$O(n)$。連結串列插入只要改兩條邊：新節點指向後繼、前驅指向新節點，$O(1)$。這讓「維護一條有序鏈並不斷插入」變成可行——插入排序（147）用陣列是 $O(n^2)$ 次搬移，用連結串列則是 $O(n^2)$ 次比較但每次只改常數條邊。

槓桿在於：**只要能拿到「插入位置的前驅」，插入本身就是常數時間**。因此所有插入題的難點都被壓縮成同一件事——把前驅找出來。

## 狀態／資料結構定義

- `dummy`：哨兵，讓「插在最前面」與「插在中間」共用同一段程式碼。
- `prev`：插入點的前驅，語意是「新節點應該接在它後面」。
- 插入的兩行是有順序的：`node->next = prev->next;` 必須先於 `prev->next = node;`。
- 有序插入時，`prev` 的判定條件是「`prev->next` 為空，或 `prev->next->val` 已不小於待插值」——找的是**第一個不小於待插值的位置之前驅**。

環狀串列（708）多一個語意：沒有 `nullptr` 當終點，得靠「走回起點」判定走完一圈。

## 不變量或正確性證明

先證單次插入的正確性。設插入前鏈為 $\dots \to prev \to succ \to \dots$，記 `succ = prev->next`。執行 `node->next = succ` 後 `node` 指向 `succ`，且此時 `prev->next` 仍是 `succ`，鏈未斷；再執行 `prev->next = node`，鏈變成 $\dots \to prev \to node \to succ \to \dots$。**兩行的順序不能交換**：若先寫 `prev->next = node`，`succ` 的唯一入邊就被覆蓋，之後 `node->next = prev->next` 只會讓 `node` 指向自己，整條後綴洩漏。這不是風格問題，是唯一入邊被覆寫後資訊不可復原。

再證有序插入（147）的迴圈不變量：**每輪開始時，`dummy` 之後的鏈是「已處理過的節點」的有序排列，且原鏈剩餘部分完好。**

- 初始化：已處理集合為空，有序成立。
- 保持：取出剩餘鏈的第一個節點 `cur`（先存好 `cur->next` 再改動 `cur`，否則會弄丟剩餘鏈）。從 `dummy` 往後找到第一個滿足 `prev->next == nullptr || prev->next->val >= cur->val` 的 `prev`，把 `cur` 插在其後。由於掃描在「第一個不小於」處停下，`prev->val <= cur->val <= prev->next->val`，插入後整段仍有序；已處理集合多了 `cur`。
- 終止：剩餘鏈為空時，已處理集合是全部節點且有序，故 `dummy.next` 是答案。

穩定性也由此得到：掃描停在第一個**嚴格大於**還是**不小於**決定相等元素的相對次序；用 `>` 停會把新元素排在相等者之後，即穩定。

環狀串列插入的正確性另有前提：當所有值相等或待插值落在最大與最小之間（跨越接縫）時，找不到「前小後大」的位置，必須額外用「走滿一圈就插在任意接縫」收尾，否則會無限迴圈。

## C++17 模板

```cpp
// 對連結串列做插入排序（LeetCode 147）。
ListNode* insertionSortList(ListNode* head) {
    ListNode dummy;
    dummy.next = nullptr;

    ListNode* cur = head;
    while (cur) {
        ListNode* nxt = cur->next;  // 先抓住剩餘鏈，等下要改 cur->next

        ListNode* prev = &dummy;  // 找第一個「下一個 >= cur」的位置之前驅
        while (prev->next && prev->next->val < cur->val) {
            prev = prev->next;
        }

        cur->next = prev->next;  // 順序不可交換：先接後繼
        prev->next = cur;        // 再改前驅

        cur = nxt;
    }
    return dummy.next;
}
```

單純「在 `prev` 後插入一個新值」則是三行：`ListNode* node = new ListNode(v); node->next = prev->next; prev->next = node;`。

## 時間與空間複雜度

單次插入 $O(1)$，但**找前驅是 $O(n)$**——連結串列不能二分，即使鏈已有序也得線性掃。插入排序總計最壞 $O(n^2)$ 時間、$O(1)$ 額外空間；已接近有序時每次掃描很短，實務上遠快於最壞值。這也說明為何連結串列排序不用插入排序而用歸併（1.9）：後者靠分治把找位置的成本攤成 $O(n \log n)$。

## 常見錯誤與邊界條件

- 先改 `prev->next` 再改 `node->next`，導致自環並洩漏後綴。
- 忘記先存 `cur->next` 就改動 `cur`，弄丟剩餘鏈。
- 插入排序結束時忘記把最後一個節點的 `next` 設為 `nullptr`（若沿用原鏈的 `next` 會殘留舊指向而成環）。
- 環狀串列（708）漏掉「全部相等」與「跨越最大最小接縫」兩種情形而死迴圈。
- 空串列或插在頭部時未用 dummy 而寫特例。

## 與相似技巧的比較

- 刪除（1.2）是同一套改箭頭手法的反面，同樣靠 dummy 消特例；插入要小心兩行順序，刪除則要小心先抓住被刪節點。
- 需要 $O(\log n)$ 定位就不能用連結串列，得換成平衡樹或跳表——這正是 1.10 那些設計題選擇雜湊表加雙向鏈的原因。
- 陣列的有序插入可用二分找位置但搬移 $O(n)$；連結串列剛好相反，找位置 $O(n)$ 但接上去 $O(1)$。

## 本節重點速查

- 插入只有兩行，順序固定：先 `node->next = prev->next`，再 `prev->next = node`。
- 難點永遠在找前驅；
- 改動節點前先存好剩餘鏈；
- 用 dummy 消掉插在頭部的特例。
