## 這個技術解決什麼問題

「這條串列有沒有環」「環的入口在哪」「中點是哪個節點」——用雜湊表記錄走過的節點當然可以，但要 $O(n)$ 空間。快慢指標把這些問題全部壓到 $O(1)$ 空間：**兩個速度不同的指標在有環結構裡必定相遇，而相遇的位置藏著環長與入口的資訊。**

它的適用範圍其實比連結串列大得多：任何「狀態轉移是確定性函數」的系統（快樂數、287 題把陣列視為函數圖）都能套用。

## 狀態／資料結構定義

- `slow`：每次走一步。
- `fast`：每次走兩步。
- 兩者同時從 `head` 出發（判環、找中點）。
- 判環的退出條件是 `fast == nullptr || fast->next == nullptr`（無環）或 `slow == fast`（有環）。**必須同時檢查 `fast` 與 `fast->next`**，因為一次走兩步會跨過兩個可能為空的位置。

找中點時的語意選擇：以 `while (fast && fast->next)` 退出，偶數長度會停在**後中點**；以 `while (fast->next && fast->next->next)` 則停在**前中點**。反轉後半段（234）需要前中點，這個差別會直接決定程式對錯。

## 不變量或正確性證明

**相遇性。** 設串列從 `head` 走 $\mu$ 步進入環，環長 $\lambda$。當 `slow` 首次進入環時（走了 $\mu$ 步），`fast` 已走 $2\mu$ 步、也在環內。此後兩者都在環中，考慮 `fast` 相對 `slow` 的位置差（模 $\lambda$）：每輪 `fast` 多走一步，差值每輪恰減一（或加一，視方向定義）。差值在 $\{0,1,\dots,\lambda-1\}$ 中每輪變動 1，故至多 $\lambda$ 輪後必為 0，即相遇。**這裡的關鍵是速度差恰為 1**：若改成一次走三步、一次走一步，速度差為 2，當 $\lambda$ 為偶數且初始差為奇數時差值永遠是奇數，可能**永不相遇**。所以「兩倍速」不是隨手挑的常數。

無環時 `fast` 每輪前進兩步，至多 $\lceil n/2 \rceil$ 輪就會走到 `nullptr`，終止。

**入口定位（Floyd 判圈）。** 設相遇時 `slow` 走了 $s$ 步、`fast` 走了 $2s$ 步。兩者都在環上，故步數差是環長的整數倍：$2s - s = s = k\lambda$。又 `slow` 走了 $s = \mu + t$ 步（$t$ 是它在環內走的距離）。從相遇點再走 $\mu$ 步，總距離為 $s + \mu = k\lambda + \mu$；由於在環內繞 $k\lambda$ 步等於原地不動，這等價於從 `head` 走 $\mu$ 步——正是環的入口。因此把一個指標重置到 `head`，兩者**各走一步**同步前進，相遇處即入口。注意這一步的速度必須改成相同，沿用兩倍速就不成立，因為上述推導要求兩者走過的距離相等。

**中點。** 無環時，`fast` 走的步數恆為 `slow` 的兩倍，故 `fast` 到終點時 `slow` 恰在中間。這是「距離比」而非「距離差」，與前後指標（1.5）的機制不同。

## C++17 模板

```cpp
// 判環並回傳入口，無環回傳 nullptr（LeetCode 141 / 142）。
ListNode* detectCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast && fast->next) {  // 兩個都要檢查：一次跨兩步
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {  // 相遇，確定有環
            ListNode* p = head;
            while (p != slow) {  // 改成同速各走一步
                p = p->next;
                slow = slow->next;
            }
            return p;  // 相遇處即環的入口
        }
    }
    return nullptr;  // fast 走到底，無環
}
```

找中點只保留 `while` 那三行，退出後 `slow` 即中點（偶數長度取後中點）。

## 時間與空間複雜度

判環：`slow` 進環需 $\mu$ 步，進環後至多 $\lambda$ 輪相遇，故 $O(\mu + \lambda) = O(n)$。找入口再走 $\mu$ 步，仍是 $O(n)$。空間 $O(1)$——這正是它勝過雜湊表法的地方，後者同為 $O(n)$ 時間但需 $O(n)$ 空間。

找中點 $O(n)$ 時間、$O(1)$ 空間。回文判定（234）是找中點 $O(n)$ 加反轉 $O(n)$ 加對比 $O(n)$，仍為 $O(n)$ 時間、$O(1)$ 空間。

## 常見錯誤與邊界條件

- `while` 條件只檢查 `fast` 而漏掉 `fast->next`，偶數長度時解參考空指標。
- 找入口時沿用兩倍速（必須改同速）。
- 前中點與後中點搞混，導致 234 題反轉後多一個或少一個節點。
- `fast` 與 `slow` 起點不一致（判環兩者都從 `head`，某些寫法讓 `fast` 從 `head->next` 起跑，則需在最後對相遇點做偏移修正）。
- 空串列或單節點。
- 287 題忘記「把陣列視為 `i -> a[i]` 的函數圖」需要保證入口存在（值域在 $[1,n]$ 而長度 $n+1$）。

## 與相似技巧的比較

- 前後指標（1.5）維持**固定差**，用來定位倒數第 $k$；本節維持**固定比**，用來找中點與判環。看到「倒數」想差，看到「中點／環」想比。
- 雜湊表判環更直白也更容易推廣到「記錄第一次出現」，但空間 $O(n)$；面試要求 $O(1)$ 空間時只能用 Floyd。
- Brent 判圈演算法同樣 $O(1)$ 空間，比較次數更少，但實作較繁；競賽外少用。
- 找中點若之後還要反轉後半，記得 234 題結束前應把串列復原，否則呼叫端看到的資料已被破壞。

## 本節重點速查

- 一步配兩步；
- `while (fast && fast->next)` 兩個都要檢查。
- 相遇證明依賴速度差恰為 1。
- 找入口：相遇後把一個指標放回 `head`，**改成同速**同步走，再相遇即入口。
- 找中點注意前中點與後中點的差別。
