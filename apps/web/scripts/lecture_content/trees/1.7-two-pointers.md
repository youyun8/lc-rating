## 這個技術解決什麼問題

有些題目要把一條串列**按規則重新分配**：小於 $x$ 的排前面、大於等於的排後面（86），或奇數位一組、偶數位一組（328）。若在原鏈上邊走邊搬節點，前驅與後繼會互相牽動，很容易寫成一團漿糊。

這裡的槓桿是**拆成多條鏈再接起來**：準備若干條獨立的尾指標，掃描原鏈時把每個節點「摘下來」丟進對應的鏈，最後首尾相接。每條鏈各自維護，互不干擾，程式碼從糾纏的指標操作變成幾條平行的追加動作。

相交串列（160）則是另一種雙指標：兩條鏈長度不同，用「走完自己換走對方」補齊長度差。

## 狀態／資料結構定義

- 每條目標鏈一組 `dummy` 與 `tail`：`dummy` 是該鏈的哨兵頭，`tail` 是目前的尾。追加動作固定是 `tail->next = node; tail = node;`。
- `cur`：掃描原鏈的游標。摘下節點前必須先存好 `cur->next`（或改為在追加後才前進）。
- 收尾：最後一條鏈的 `tail->next` **必須顯式設為 `nullptr`**，否則會殘留原鏈的舊指向，形成環。

相交串列的狀態則是 `pA`、`pB` 兩個游標，各自走到底後跳到對方的頭。

## 不變量或正確性證明

**分鏈的正確性。** 不變量：每輪開始時，原鏈已掃描的節點恰好被分配到各條目標鏈中的一條且僅一條，各鏈內部維持這些節點在原鏈中的相對次序，`cur` 指向下一個待分配節點。

- 初始化：各鏈為空，`cur = head`，成立。
- 保持：判定 `cur` 屬於哪條鏈，用 `tail->next = cur; tail = cur;` 追加。因為只追加到尾端且掃描順序即原鏈順序，該鏈內部次序與原鏈一致；每個節點只被判定一次，故不重不漏。
- 終止：`cur == nullptr` 時全部節點分配完畢，依序接上各鏈即得答案。

**穩定性**由「只追加到尾端 + 依原序掃描」共同保證，86 題明確要求保留相對次序，靠的就是這一點。若改成插入到頭端，相對次序會反轉。

必須把最後一條鏈的 `tail->next` 清成 `nullptr`：被摘下的節點仍保有原本的 `next`，若不清除，接起來後最後一段會指回原鏈中間，形成環。這是本節最常見的無窮迴圈來源。

**相交串列（160）的正確性。** 設兩鏈獨有部分長度為 $a$、$b$，共同尾段長 $c$。`pA` 走完 A（$a+c$ 步）後跳到 B 頭，再走 $b$ 步；`pB` 走完 B（$b+c$ 步）後跳到 A 頭，再走 $a$ 步。兩者在各走了 $a+b+c$ 步時同時抵達交點。若不相交（$c=0$），兩者在各走 $a+b$ 步後同時變成 `nullptr`，迴圈以相等結束並回傳 `nullptr`——**這正是要用 `nullptr` 而非 `head` 作為換軌時機的原因**：若在到達尾節點時就換軌，不相交的情形下兩指標永遠差 $a-b$ 步，會無限繞行。

## C++17 模板

```cpp
// 分隔串列：小於 x 的在前，其餘在後，各自保持相對次序（LeetCode 86）。
ListNode* partition(ListNode* head, int x) {
    ListNode lo, hi;     // 兩條鏈的哨兵頭
    ListNode* lt = &lo;  // 小於 x 的鏈尾
    ListNode* ge = &hi;  // 大於等於 x 的鏈尾

    for (ListNode* cur = head; cur; cur = cur->next) {
        if (cur->val < x) {
            lt->next = cur;
            lt = cur;
        } else {
            ge->next = cur;
            ge = cur;
        }
    }

    ge->next = nullptr;  // 必須清乾淨，否則殘留舊指向而成環
    lt->next = hi.next;  // 兩鏈相接
    return lo.next;
}
```

奇偶鏈（328）結構相同，判定條件換成位置的奇偶。

## 時間與空間複雜度

每個節點恰被掃描並追加一次，時間 $O(n)$；只用常數個 dummy 與 tail，空間 $O(1)$（節點是搬移不是複製）。相交串列同樣 $O(a+b+c)$ 時間、$O(1)$ 空間，優於用雜湊表記錄 A 的所有節點那種 $O(n)$ 空間解法。

## 常見錯誤與邊界條件

- 忘記把最後一條鏈的 `tail->next` 設為 `nullptr`，造成環與無窮迴圈。
- 在 `for` 的更新式已寫 `cur = cur->next` 的情況下又在本體改動 `cur->next`，導致游標跳錯（追加時 `cur->next` 會被下一次追加覆寫，此處因先取 `cur->next` 再改而安全，改寫成 `while` 版時要特別小心）。
- 相交串列在尾節點換軌而非 `nullptr` 換軌，不相交時死迴圈。
- 某一條鏈為空時直接存取 `dummy.next->val`。
- 空串列輸入。

## 與相似技巧的比較

- 與 1.2 刪除、1.3 插入相比，本節不改動節點內容也不新增節點，只是**重新分組**；當要保持相對次序時，分鏈比原地交換好寫得多。
- 與陣列的雙指標（快慢覆寫）相比，陣列是搬值、連結串列是搬邊；陣列的原地分割可以不穩定（如快排 partition），連結串列分鏈天生穩定。
- 需要三組以上（如荷蘭國旗）就開三條鏈，模式完全一樣，這是分鏈法比原地交換更容易推廣的地方。

## 本節重點速查

- 每組一個 `dummy` 加一個 `tail`，追加固定兩行；
- 掃描順序即原序，故天生穩定；
- **收尾一定要把最後一條鏈的 `next` 清成 `nullptr`**。
- 相交串列用「走完自己換走對方」補長度差，換軌時機是 `nullptr` 不是尾節點。
