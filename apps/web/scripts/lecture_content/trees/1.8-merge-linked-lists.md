## 這個技術解決什麼問題

把兩條有序串列併成一條有序串列。用陣列做要先倒出來、合併、再建鏈，$O(n)$ 額外空間；直接在鏈上合併則只是**反覆從兩個頭中挑較小者接到結果尾端**，$O(1)$ 額外空間，且節點是搬移不是複製。

同一套「同步推進兩個游標」的骨架也支撐鏈上加法（2、445）：兩條數字鏈逐位相加並維護進位。差別只在「挑一個」變成「合兩個再進位」。

## 狀態／資料結構定義

- `dummy` 與 `tail`：結果鏈的哨兵頭與尾。dummy 讓「第一個節點來自哪條鏈」不必寫特例。
- `p1`、`p2`：兩條輸入鏈當前未處理的頭。
- 迴圈條件 `while (p1 && p2)`，退出後把非空的那條**整段接上**（不必逐點搬，因為剩下的本來就有序且都不小於已接入的元素）。

鏈上加法多一個狀態 `carry`，且迴圈條件放寬成 `while (p1 || p2 || carry)`——**進位必須算進終止條件**，否則最高位的進位會被丟掉（如 `5 + 5` 應為 `01`）。

445 題數字最高位在鏈頭，需先反轉（1.4）或改用堆疊，因為加法必須從低位開始。

## 不變量或正確性證明

迴圈不變量：**每輪開始時，結果鏈是「兩條輸入鏈已消耗部分」的有序合併，且結果鏈中每個值都不大於 `p1->val` 與 `p2->val`。**

- 初始化：結果鏈為空，兩個條件空虛成立。
- 保持：不失一般性設 `p1->val <= p2->val`，把 `p1` 接到 `tail` 後並前進 `p1`。需要驗證兩件事。其一，接上後仍有序：由不變量，`tail` 的值不大於 `p1->val`，故追加後非遞減。其二，新的結果鏈中每個值仍不大於兩個新頭——新加入的 `p1->val` 不大於 `p2->val`（分支條件），也不大於新的 `p1->next->val`（輸入鏈有序）。故不變量維持。
- 終止：某條鏈耗盡時，結果鏈是另一條鏈已消耗部分與整條耗盡鏈的合併。由不變量，結果鏈所有值都不大於剩餘鏈的頭，且剩餘鏈本身有序，故**直接整段接上**即得完整有序鏈。

這裡有兩個前提值得點名。第一，**輸入必須各自有序**；否則「挑較小者」無法保證後面不會冒出更小的值，不變量的第二個條件立刻崩潰。第二，分支用 `<=` 而非 `<` 才穩定——相等時優先取 `p1`，保證來自第一條鏈的元素排在前面；歸併排序（1.9）依賴這個穩定性。

鏈上加法的不變量則是：處理完第 $i$ 位後，結果鏈的低 $i$ 位等於兩數低 $i$ 位之和的低 $i$ 位，且 `carry` 等於其進位。歸納步驟就是 `sum = v1 + v2 + carry; carry = sum / 10; 接上 sum % 10;`。終止條件必須包含 `carry`，理由如上。

## C++17 模板

```cpp
// 合併兩條有序串列（LeetCode 21）。
ListNode* mergeTwoLists(ListNode* a, ListNode* b) {
    ListNode dummy;
    ListNode* tail = &dummy;

    while (a && b) {
        if (a->val <= b->val) {
            tail->next = a;
            a = a->next;
        }  // <= 保證穩定
        else {
            tail->next = b;
            b = b->next;
        }
        tail = tail->next;
    }
    tail->next = a ? a : b;  // 剩下那段整條接上，不必逐點搬
    return dummy.next;
}
```

鏈上加法（LeetCode 2）：

```cpp
ListNode* addTwoNumbers(ListNode* a, ListNode* b) {
    ListNode dummy;
    ListNode* tail = &dummy;
    int carry = 0;

    while (a || b || carry) {  // carry 必須進終止條件
        int sum = carry;
        if (a) {
            sum += a->val;
            a = a->next;
        }
        if (b) {
            sum += b->val;
            b = b->next;
        }
        carry = sum / 10;
        tail->next = new ListNode(sum % 10);
        tail = tail->next;
    }
    return dummy.next;
}
```

## 時間與空間複雜度

合併：每輪至少消耗一個節點，故至多 $n_1 + n_2$ 輪，時間 $O(n_1 + n_2)$；只用常數指標，額外空間 $O(1)$（結果重用原節點）。收尾的「整段接上」是 $O(1)$，不是 $O(n)$——這一點常被誤算。

鏈上加法時間 $O(\max(n_1, n_2))$，空間 $O(\max(n_1,n_2))$ 用於新節點（結果無法重用輸入節點的值）。445 用堆疊則額外 $O(n_1+n_2)$。

## 常見錯誤與邊界條件

- 收尾忘記接上剩餘鏈，答案被截斷。
- 用 `<` 而非 `<=` 導致不穩定（單獨看答案仍有序，但當作歸併排序的零件時就錯了）。
- 鏈上加法漏掉最後的 `carry`。
- 445 忘記數字方向相反、直接從頭相加。
- 某條輸入鏈為空。
- 合併後回傳 `a` 或 `b` 而非 `dummy.next`。
- `new` 出來的節點在多次呼叫下未釋放（面試環境通常不追究，但要能說明）。

## 與相似技巧的比較

- 合併 $k$ 條鏈（23）不要兩兩串接（$O(kn)$），改用分治兩兩配對或小根堆，見 1.9。
- 陣列的雙序列合併邏輯完全相同，差別在陣列需要 $O(n)$ 目標空間而鏈可原地重接。
- 與 1.7 的分鏈相比，本節是「多合一」、分鏈是「一分多」，兩者共用 `dummy` 加 `tail` 的追加骨架。

## 本節重點速查

- `dummy` 加 `tail`，每輪挑較小者接上；
- 用 `<=` 保持穩定；
- 退出後把剩餘鏈**整段**接上。
- 前提是兩條輸入各自有序。
- 鏈上加法把終止條件寫成 `p1 || p2 || carry`。
