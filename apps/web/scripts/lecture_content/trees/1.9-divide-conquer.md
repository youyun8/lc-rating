## 這個技術解決什麼問題

合併 $k$ 條有序鏈（23），若用「結果鏈依序與第 $i$ 條合併」，第 $i$ 次合併的結果鏈長度已達 $O(in/k)$，總成本 $\sum_i O(in/k) = O(kn)$。分治兩兩配對把它降到 $O(n \log k)$。

連結串列排序（148）也一樣：快排需要隨機存取取中位數，鏈上做不到；歸併排序卻天然適合鏈——**合併是 $O(1)$ 額外空間（1.8），分割靠快慢指標（1.6）**，於是能達成 $O(n \log n)$ 時間、$O(\log n)$ 空間（僅遞迴堆疊），這是陣列歸併排序做不到的（陣列版需 $O(n)$ 輔助空間）。

## 狀態／資料結構定義

- 子問題以「一段鏈」表示。由於鏈無法用下標界定範圍，分割時必須**真的把鏈斷開**：找到前中點後執行 `mid = slow->next; slow->next = nullptr;`，否則兩半仍相連，遞迴會無限展開。
- 合併 $k$ 條：子問題是區間 $[l, r]$ 上的鏈陣列，遞迴分成 $[l, m]$ 與 $[m+1, r]$。
- 遞迴出口：`head == nullptr || head->next == nullptr`（0 或 1 個節點必定有序）。

找中點必須取**前中點**（`while (fast->next && fast->next->next)`），理由見下。

## 不變量或正確性證明

**歸併排序的正確性**用強歸納法。命題：`sortList(h)` 回傳的鏈由 `h` 起始的所有節點組成，且非遞減排列。

- 基底：長度 0 或 1 時直接回傳，平凡成立。
- 歸納：長度 $n \ge 2$ 時分成兩段，長度分別為 $\lceil n/2 \rceil$ 與 $\lfloor n/2 \rfloor$，都嚴格小於 $n$，故由歸納假設兩段各自被正確排序。再由 1.8 的合併不變量，合併兩條有序鏈得到的鏈有序且含全部節點。故命題成立。

**終止性**是這裡真正容易出錯的地方，而且它依賴兩件事。其一，分割必須真的斷開；不斷開的話「兩段」其實都是整條鏈，遞迴深度無限。其二，**必須取前中點**：長度為 2 時，後中點會切成「0 個 + 2 個」，子問題與原問題同大，遞迴不下降；前中點切成「1 個 + 1 個」，嚴格下降。所以 `while (fast->next && fast->next->next)` 這個寫法不是風格偏好，是終止性的必要條件。

**穩定性**：分割時前半在原鏈中確實排在後半之前，而 1.8 的合併在相等時優先取第一條鏈，故歸併排序穩定。

**合併 $k$ 條的複雜度論證**：遞迴樹共 $\log k$ 層，每層所有合併加起來恰好掃過全部 $n$ 個節點一次（各子問題的節點集合互斥），故每層 $O(n)$，總計 $O(n \log k)$。相對地，順序串接法的每一層都要重掃已合併的長鏈，這正是它退化成 $O(kn)$ 的原因。

## C++17 模板

```cpp
// 連結串列歸併排序（LeetCode 148）：O(n log n) 時間、O(log n) 堆疊。
ListNode* sortList(ListNode* head) {
    if (!head || !head->next) {
        return head;
    }  // 出口：0 或 1 個節點

    ListNode* slow = head;  // 取「前中點」，長度為 2 時才會 1+1
    ListNode* fast = head;
    while (fast->next && fast->next->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    ListNode* mid = slow->next;
    slow->next = nullptr;  // 必須真的斷開，否則無限遞迴

    return mergeTwoLists(sortList(head), sortList(mid));  // 合併見 1.8
}
```

合併 $k$ 條鏈同樣分治：`merge(l, r)` 回傳 `mergeTwoLists(merge(l, m), merge(m + 1, r))`，出口是 `l == r` 時回傳該條鏈、`l > r` 時回傳 `nullptr`。

## 時間與空間複雜度

歸併排序：遞迴式 $T(n) = 2T(n/2) + O(n)$，其中 $O(n)$ 來自找中點與合併，解得 $O(n \log n)$。空間只有遞迴堆疊 $O(\log n)$——合併本身是原地重接指標，不需輔助陣列。自底向上寫法可把堆疊也消掉，達成真正的 $O(1)$ 空間，但程式碼繁瑣許多。

合併 $k$ 條：$O(n \log k)$ 時間（$n$ 為總節點數），$O(\log k)$ 堆疊。用小根堆的替代解法同為 $O(n \log k)$ 時間但需 $O(k)$ 空間，寫起來較短，兩者都可接受。

## 常見錯誤與邊界條件

- 分割後忘記 `slow->next = nullptr`，導致堆疊溢位。
- 取後中點導致長度為 2 時無限遞迴（最典型的當機原因）。
- 遞迴出口漏掉 `!head->next`。
- 合併 $k$ 條時 `l > r`（$k=0$）未處理。
- 順序串接 $k$ 條而超時。
- 誤以為鏈上可以寫快排（能寫，但取樞紐只能取頭或隨機走 $O(n)$ 步，最壞 $O(n^2)$ 且不穩定）。

## 與相似技巧的比較

- 對照陣列歸併排序：邏輯相同，但陣列版需 $O(n)$ 輔助空間、鏈版只需 $O(\log n)$；反過來陣列可用快排達成 $O(1)$ 空間而鏈不行。
- 合併 $k$ 條的小根堆解法（見 data_structure 的堆一節）在 $k$ 遠小於 $n$ 時常數更小、程式碼更短；分治版不需額外資料結構。
- 兩兩配對的迭代寫法（每輪把相鄰兩條合併，輪數 $\lceil \log k \rceil$）與遞迴版複雜度相同，可避免遞迴。

## 本節重點速查

- 鏈上排序用歸併不用快排。
- 三步：快慢指標取**前中點**、`slow->next = nullptr` **真的斷開**、遞迴後用 1.8 合併。
- 合併 $k$ 條用分治或小根堆得 $O(n \log k)$，不要順序串接。
