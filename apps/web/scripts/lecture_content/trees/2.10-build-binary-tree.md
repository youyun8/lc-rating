## 這個技術解決什麼問題

給定遍歷序列還原樹（105 前序＋中序、106 後序＋中序）、由有序陣列建平衡 BST（108）、由陣列建最大二元樹（654）。這些題的共同結構是**分治**：想辦法在序列中找出「根」與「左右兩段」，然後遞迴。

難點有二。其一，單一種遍歷序列**無法唯一確定一棵樹**——前序 `[1,2]` 既可能是 1 的左子為 2，也可能是右子。必須有第二種序列提供切分資訊。其二，若每層都用線性搜尋找根在中序中的位置，總成本 $O(n^2)$；用雜湊表把位置預先建好，降到 $O(n)$。

## 狀態／資料結構定義

以 105（前序＋中序）為例，子問題用**四個下標**界定，這是本節最容易寫錯的地方：

- `build(preL, preR, inL, inR)`：前序區間 $[preL, preR]$ 與中序區間 $[inL, inR]$ 描述**同一棵子樹**，兩段長度必然相等。
- `pos`：`unordered_map<int, int>`，中序中每個值的下標，用來 $O(1)$ 定位根。**前提是節點值互不相同**，題目若允許重複就不能這樣做（事實上有重複值時樹本身就無法唯一還原）。
- 切分：根是 `preorder[preL]`；設 `k = pos[根]`，則左子樹在中序中佔 $[inL, k-1]$，長度 `sz = k - inL`；左子樹在前序中佔 $[preL+1, preL+sz]$，右子樹佔 $[preL+sz+1, preR]$。

108 的狀態只需 $[l, r]$；654 需要在區間內找最大值的位置（可用單調堆疊優化成 $O(n)$）。

## 不變量或正確性證明

**唯一性：前序＋中序可唯一確定二元樹（值互異時）。** 用對節點數的強歸納。

- 基底：空序列對應空樹，唯一。
- 歸納：前序的第一個元素必為根（前序定義為「根、左、右」）。設它在中序中的位置為 $k$（值互異保證位置唯一）。由中序定義（「左、根、右」），中序中位於 $k$ 左邊的元素恰為左子樹的所有節點，右邊恰為右子樹的所有節點。於是左子樹的節點集合被唯一確定，其大小 `sz` 也隨之確定。再由前序定義，前序中緊接根之後的 `sz` 個元素恰為左子樹的前序、其餘為右子樹的前序。因此兩棵子樹各自的（前序，中序）配對被唯一確定，由歸納假設各自唯一，故整棵樹唯一。

**這個論證明確依賴「值互異」**。若有重複值，$k$ 的選擇不唯一，不同選擇會給出不同的樹——不是演算法沒寫好，是問題本身無解。

同理，後序＋中序可唯一確定（後序的**最後**一個元素是根）。但**前序＋後序無法唯一確定**：對只有一個子節點的節點，前序與後序都無法區分它是左子還是右子。這是為什麼 889 題只要求「回傳任意一棵符合的樹」。

**下標推導的驗證。** 兩段長度必須始終相等：初始 $preR - preL = inR - inL$。左子呼叫用 $[preL+1, preL+sz]$ 與 $[inL, k-1]$，長度分別為 $sz - 1$ 與 $k - 1 - inL = sz - 1$，相等。右子呼叫用 $[preL+sz+1, preR]$ 與 $[k+1, inR]$，長度分別為 $preR - preL - sz - 1$ 與 $inR - k - 1$；代入 $k = inL + sz$ 與初始等式即得兩者相等。這個檢查是除錯下標最快的方法：**任何一步若兩段長度不等，該步的推導就錯了**。

**108 建平衡 BST 的正確性與平衡性。** 取區間中點作根，左半遞迴為左子樹、右半為右子樹。BST 性質成立：左半全部小於中點、右半全部大於中點（輸入有序），且遞迴保證子樹內部也滿足。平衡性：每次把長度 $m$ 切成 $\lfloor (m-1)/2 \rfloor$ 與 $\lceil (m-1)/2 \rceil$，兩者相差至多 1，故深度 $T(m) = 1 + T(m/2) = O(\log m)$，高度差至多 1。中點取 `l + (r-l)/2` 或 `l + (r-l+1)/2` 都可以（產生不同但都合法的樹），題目通常接受任一。

**654 最大二元樹**：區間內最大值為根，左右兩段遞迴。樸素找最大值是 $O(n)$ 每層，最壞 $O(n^2)$（輸入遞增時退化成鏈）；用單調遞減堆疊可 $O(n)$ 建成，原理是「每個元素的父親是它左右兩側第一個比它大的元素中較小的那個」。

## C++17 模板

```cpp
// 由前序與中序還原二元樹（LeetCode 105）。前提：節點值互不相同。
class Solution {
    std::vector<int> pre_, in_;
    std::unordered_map<int, int> pos_;  // 中序值 -> 下標，O(1) 定位根

    TreeNode* build(int preL, int preR, int inL, int inR) {
        if (preL > preR) {
            return nullptr;
        }  // 空區間

        int rootVal = pre_[preL];  // 前序首元素是根
        int k = pos_[rootVal];     // 它在中序中的位置
        int sz = k - inL;          // 左子樹的節點數

        TreeNode* root = new TreeNode(rootVal);
        root->left = build(preL + 1, preL + sz, inL, k - 1);
        root->right = build(preL + sz + 1, preR, k + 1, inR);
        return root;
    }

public:
    TreeNode* buildTree(std::vector<int>& preorder, std::vector<int>& inorder) {
        pre_ = preorder;
        in_ = inorder;
        for (int i = 0; i < static_cast<int>(in_.size()); ++i) {
            pos_[in_[i]] = i;
        }
        return build(0, pre_.size() - 1, 0, in_.size() - 1);
    }
};
```

有序陣列建平衡 BST（LeetCode 108）：

```cpp
TreeNode* build(std::vector<int>& a, int l, int r) {
    if (l > r) {
        return nullptr;
    }
    int m = l + (r - l) / 2;  // 取中點保證高度差不超過 1
    TreeNode* root = new TreeNode(a[m]);
    root->left = build(a, l, m - 1);
    root->right = build(a, m + 1, r);
    return root;
}
```

## 時間與空間複雜度

105／106：每個節點建立一次、雜湊表查一次，$O(n)$ 時間；雜湊表 $O(n)$ 空間加遞迴堆疊 $O(h)$。若改用線性搜尋找根，退化成 $O(n^2)$（斜樹時每層都掃全長）。

108：$T(n) = 2T(n/2) + O(1) = O(n)$ 時間，$O(\log n)$ 堆疊。

654：樸素 $O(n^2)$ 最壞、$O(n \log n)$ 平均；單調堆疊版 $O(n)$。

536（由字串還原）需解析括號，$O(n)$ 時間。

## 常見錯誤與邊界條件

- 四個下標推導錯誤（用「兩段長度必須相等」自檢）。
- 忘記空區間出口 `preL > preR`。
- 有重複值時仍用雜湊表定位（此時題目本身無唯一解）。
- 106 誤以為後序的第一個是根（是最後一個）。
- 把左右子樹的前序區間切反。
- 108 對空陣列呼叫 `build(a, 0, -1)` 未處理。
- 654 用樸素找最大值而在遞增輸入下超時。
- 雜湊表在每層遞迴重建而非預先建好。
- 未釋放建樹失敗時的部分節點。

## 與相似技巧的比較

- 297（序列化與反序列化）走的是另一條路：在序列中**顯式標記空節點**，於是單一種遍歷就足以還原，不需要第二種序列。這說明「需要兩種序列」的根本原因是空節點資訊遺失，補上它就不必了。
- 889（前序＋後序）只能回傳任意合法解，理由如上——單子節點的左右歸屬無法區分。
- 108 與 109（有序鏈建 BST）思路相同，但鏈無法 $O(1)$ 取中點；可用快慢指標每層找中點（$O(n \log n)$），或用「中序模擬」的巧解達成 $O(n)$，見 2.14。
- 分治的骨架與 1.9 的歸併排序同構：都是切分、遞迴、合併，差別在這裡的「合併」是建立父子關係而非合併有序鏈。

## 本節重點速查

- 分治三步：定根、切分、遞迴。
- 前序＋中序（或後序＋中序）在**值互異**時唯一確定樹；
- 前序＋後序不行。
- 用雜湊表 $O(1)$ 定位根，否則退化 $O(n^2)$。
- 四個下標用「兩段長度必相等」自檢。
- 108 取中點建樹自然平衡。
