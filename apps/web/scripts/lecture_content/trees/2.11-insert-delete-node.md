## 這個技術解決什麼問題

在 BST 上插入（701）、刪除（450）、修剪到指定值域（669）。這些操作都必須在改動結構之後**仍然是一棵 BST**——這才是難點所在。插入相對容易（總能掛在某個空位），刪除則棘手：拿掉一個有兩個子節點的內部節點後，會留下一個必須被「合法填補」的洞。

槓桿在於 BST 的中序即有序序列（2.9）：**刪除一個節點後，只要用它在中序序列中的鄰居（前驅或後繼）補位，序列的有序性就自動維持**，因此 BST 性質也維持。這把一個看似要重建的問題化簡成一次替換。

## 狀態／資料結構定義

一律採用「**遞迴回傳新的子樹根**」的介面（與 2.4 剪枝相同）：

- `insert(node, key)` / `remove(node, key)` 回傳操作後該子樹的根，呼叫端用 `node->left = remove(node->left, key);` 接回去。這個介面讓「根本身被刪除」不必寫特例。
- 刪除時的三種情形：無子（直接回傳 `nullptr`）、單子（回傳那個子節點）、雙子（找替身）。
- 替身的定義：**後繼**是右子樹中的最小節點（一路往左走到底），**前驅**是左子樹中的最大節點（一路往右走到底）。
- 669 修剪的狀態只有 `[low, high]` 兩個界。

## 不變量或正確性證明

**插入的正確性。** 沿著 BST 的比較路徑下降，最終抵達一個空位並在該處建立新節點。要證明「掛在這個空位上仍是 BST」：下降過程中每一步都由比較決定方向，因此對路徑上每個祖先 $u$，新值與 $u$ 的大小關係恰好與「新節點最終落在 $u$ 的哪一側」一致。而非祖先的節點與新節點不存在祖先—後代關係，BST 性質對它們無約束。故整棵樹仍是 BST。注意新節點必定成為**葉節點**，這是這個做法最簡單的地方。

**刪除的正確性（雙子情形）。** 設要刪的節點為 $v$，取其後繼 $s$（右子樹最小者）。宣稱把 $v$ 的值換成 $s$ 的值、再從右子樹中刪除 $s$，結果仍是 BST。

論證分兩步。第一步，$s$ 是中序序列中緊接 $v$ 之後的節點，故 $s$ 的值大於 $v$ 的左子樹全部（它們在中序中都排在 $v$ 之前），也小於 $v$ 的右子樹中除 $s$ 外的全部（它們在中序中都排在 $s$ 之後）。因此把 $v$ 的值替換成 $s$ 的值，對 $v$ 位置上的 BST 約束仍然成立。第二步，$s$ 是右子樹的最小節點，故**它必定沒有左子**（若有，那個左子更小，與最小性矛盾）。於是遞迴刪除 $s$ 時落入「無子」或「單子（只有右子）」的簡單情形，不會無限遞迴。

這第二點是整個做法能終止的關鍵：**雙子情形被化簡成至多單子的情形，遞迴深度嚴格下降**。若隨便選一個右子樹的節點當替身，這個保證就沒了。

**669 修剪的正確性。** 對節點 $v$：若 `v->val < low`，則 $v$ 及其**整棵左子樹**都小於 `low`（BST 性質），全部該刪，故直接回傳 `trim(v->right)`；若 `v->val > high`，對稱地回傳 `trim(v->left)`；否則保留 $v$，並遞迴修剪左右。

這裡最值得點名的是「可以整棵子樹一起丟」——它直接來自 BST 性質，是 $O(h)$ 級別剪枝而非逐點判斷。同時要注意**不能在丟掉左子樹後就停止**：`v->val < low` 時右子樹中仍可能有合格節點，必須繼續遞迴，不能直接回傳 `nullptr`。這是 669 最常見的錯誤。

修剪後結果仍是 BST：保留的節點集合是原集合對值域的一個「區間篩選」，而中序序列的子序列仍然遞增，故仍是 BST（由 2.9 的等價性）。

## C++17 模板

```cpp
// BST 刪除節點（LeetCode 450）：回傳新的子樹根。
TreeNode* deleteNode(TreeNode* root, int key) {
    if (!root) {
        return nullptr;
    }

    if (key < root->val) {
        root->left = deleteNode(root->left, key);
    } else if (key > root->val) {
        root->right = deleteNode(root->right, key);
    } else {
        if (!root->left) {
            TreeNode* r = root->right;
            delete root;
            return r;
        }
        if (!root->right) {
            TreeNode* l = root->left;
            delete root;
            return l;
        }

        TreeNode* s = root->right;  // 後繼：右子樹最小者
        while (s->left) {
            s = s->left;
        }  // 它必定沒有左子
        root->val = s->val;  // 用後繼補位，中序序列仍遞增
        root->right =
            deleteNode(root->right, s->val);  // 遞迴刪除，至多單子情形
    }
    return root;
}
```

修剪到值域（LeetCode 669）：

```cpp
TreeNode* trimBST(TreeNode* root, int low, int high) {
    if (!root) {
        return nullptr;
    }
    if (root->val < low) {
        return trimBST(root->right, low, high);
    }  // 左子樹整棵丟
    if (root->val > high) {
        return trimBST(root->left, low, high);
    }
    root->left = trimBST(root->left, low, high);
    root->right = trimBST(root->right, low, high);
    return root;
}
```

插入（LeetCode 701）：沿比較路徑下降，`if (!root) return new TreeNode(key);`，其餘接回 `root->left`／`root->right`。

## 時間與空間複雜度

插入、刪除、修剪都是 $O(h)$：插入下降一條路徑；刪除下降一條路徑後再往下找後繼（後繼在右子樹中，兩段合計仍是 $O(h)$）；修剪最壞訪問每個節點 $O(n)$，但實際只會走到值域邊界附近的路徑，若大量節點被整段丟棄則遠快於 $O(n)$。

空間 $O(h)$ 遞迴堆疊，迭代版插入可做到 $O(1)$。

平衡時 $h = O(\log n)$，退化成鏈時 $O(n)$。純 BST **不保證平衡**：依序插入有序資料會建出一條鏈。要保證 $O(\log n)$ 必須用 AVL、紅黑樹或 Treap，那需要額外的旋轉操作，超出本節範圍。

## 常見錯誤與邊界條件

- 遞迴後忘記把回傳值接回 `root->left`／`root->right`，樹沒有變化。
- 669 在 `val < low` 時直接回傳 `nullptr` 而丟掉右子樹中的合格節點。
- 刪除雙子節點時選了非最小／最大的替身，導致遞迴不終止或破壞 BST。
- 替換值後忘記從子樹中刪除替身（該值出現兩次）。
- 刪除根節點後回傳 `root` 而非新根。
- `delete` 節點後仍存取其欄位（要先取出 `root->right` 再 delete）。
- 樹中不存在 `key` 時應原樣回傳。
- 空樹。

## 與相似技巧的比較

- 與 2.4 的批次剪枝相同的是「回傳新根」介面與後序接回；不同的是本節要維持 BST 性質，因此刪除需要替身而非單純移除。
- `std::set` / `std::map` 提供的就是平衡版本的這些操作，競賽中除非題目要求手寫，一律直接用標準庫。
- 776（拆分 BST）是修剪的變體：不是丟掉界外節點而是分成兩棵樹，同樣利用「整棵子樹可一起歸類」的性質。
- 1666（改變二元樹的根）不涉及 BST 性質，是純結構重連，要注意父子關係反轉時原本的父節點要先斷開。

## 本節重點速查

- 一律用「遞迴回傳新根 + 呼叫端接回賦值」的介面。
- 刪除雙子節點時用**後繼（右子樹最小者）**補位——它必定無左子，故遞迴化簡成至多單子情形而終止。
- 669 修剪時可整棵子樹丟棄，但界外節點的**另一側仍要遞迴**。
- 所有 $O(h)$ 都不保證平衡。
