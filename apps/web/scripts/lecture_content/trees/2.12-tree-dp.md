## 這個技術解決什麼問題

2.3 的自底向上處理的是「單一彙總量可由子樹彙總量算出」的情形。但很多題目不滿足這個條件：打家劫舍 III（337）中，一棵子樹能貢獻的最大金額**取決於它的根有沒有被選**——只回傳一個「最大值」不足以支撐父節點的決策，因為父節點需要知道「不選根時的最大值」才能在選自己時使用。

樹形 DP 的槓桿就是**擴充狀態**：讓每個節點回傳一組值（通常是「選自己」與「不選自己」兩種情形下的最優解），使得歸納步驟能夠完成。這是 2.3 末尾「組合不出來就擴充狀態」那句話的正式展開。

## 狀態／資料結構定義

以 337 為例：

- `dfs(v)` 回傳 `pair<long long, long long>`，記為 $(\text{rob}_v, \text{skip}_v)$。
  - $\text{rob}_v$：**選了 $v$** 的前提下，$v$ 子樹能取得的最大金額。
  - $\text{skip}_v$：**不選 $v$** 的前提下，$v$ 子樹能取得的最大金額。
- 空節點回傳 $(0, 0)$。
- 轉移：
  $$\text{rob}_v = val_v + \text{skip}_L + \text{skip}_R, \qquad \text{skip}_v = \max(\text{rob}_L, \text{skip}_L) + \max(\text{rob}_R, \text{skip}_R)$$
- 答案是 $\max(\text{rob}_{root}, \text{skip}_{root})$。

968（監控二元樹）需要三個狀態（未被覆蓋／已被覆蓋但無攝影機／有攝影機），2313（翻轉使根為目標值的最少翻轉次數）需要「結果為 true」與「結果為 false」兩個狀態。狀態的維度由「父節點需要知道什麼」決定。

## 不變量或正確性證明

**狀態定義的完備性。** 命題：對每個節點 $v$，`dfs(v)` 回傳的兩個值分別正確。

用結構歸納。基底：空子樹兩種情形都取 0，成立（沒有節點可選）。

歸納步驟需要驗證兩條轉移。

$\text{rob}_v$：既然選了 $v$，題目約束「不能選相鄰節點」意味著 $L$ 與 $R$ 都不能選。在此前提下，左子樹能貢獻的最大值恰為 $\text{skip}_L$（由歸納假設，這正是它的定義），右子樹同理。且**左右子樹的選擇互不影響**——它們的節點集合不相交，約束也不跨子樹。故三者可獨立相加。

$\text{skip}_v$：不選 $v$ 時，$L$ 與 $R$ 各自選或不選都合法，故各取自己的兩種情形之最大值。同樣由子樹不相交得到可加性。

由歸納，對根成立。

**這個證明實際依賴三個前提，每個都值得檢查：**

1. **無後效性**：$v$ 的決策只透過「$v$ 選或不選」這一位資訊影響子樹，不會有更遠的耦合。若題目改成「不能選距離 $\le 2$ 的節點」，狀態就要擴充成「子樹根的最近被選深度」，兩個狀態不夠。
2. **子樹獨立性**：左右子樹的節點集合不相交，故最優解可分別取。若題目有「全樹最多選 $k$ 個」這種全域約束，子樹就不獨立了，必須把「用了幾個」也放進狀態（變成樹上背包，複雜度上升）。
3. **狀態涵蓋所有情形**：$\{選, 不選\}$ 對每個節點是完備且互斥的劃分，故取兩者最大值不會漏解也不會重複計數。

**為什麼不能只回傳一個最大值。** 假設 `dfs(v)` 只回傳 $\max(\text{rob}_v, \text{skip}_v)$。父節點在選自己時需要「$v$ 不被選」的最大值，但單一回傳值可能來自「選了 $v$」的方案，直接使用會產生非法解（父子同選）。資訊已在回傳時遺失，無法補救——這就是狀態不完備的具體後果。

**968 的三狀態為何必要。** 一個節點對父節點的影響有三種質性不同的情況：它需要父節點裝攝影機來覆蓋（狀態 0）、它已被覆蓋但沒有攝影機因此無法覆蓋父節點（狀態 1）、它有攝影機因此能順帶覆蓋父節點（狀態 2）。這三種對父節點的決策後果各不相同，任兩者合併都會遺失資訊。**狀態維度的正確判斷法就是問：有哪些情形，父節點必須區別對待？**

## C++17 模板

```cpp
// 打家劫舍 III（LeetCode 337）：每個節點回傳「選」與「不選」兩個最優值。
class Solution {
    // first = 選了 node，second = 沒選 node
    std::pair<long long, long long> dfs(TreeNode* node) {
        if (!node) {
            return {0, 0};
        }

        auto [robL, skipL] = dfs(node->left);
        auto [robR, skipR] = dfs(node->right);

        long long rob = node->val + skipL + skipR;  // 選了自己，兩子必不選
        long long skip =
            std::max(robL, skipL) + std::max(robR, skipR);  // 沒選，兩子自由
        return {rob, skip};
    }

public:
    int rob(TreeNode* root) {
        auto [a, b] = dfs(root);
        return static_cast<int>(std::max(a, b));
    }
};
```

三狀態的骨架（968）同理，回傳 `array<int, 3>`，轉移時對每種情形分別寫出「兩子必須處於哪些狀態」的組合並取最小。

## 時間與空間複雜度

每個節點恰計算一次，每次做常數次（狀態數平方級，但狀態數是常數）的組合運算，故 $O(n \cdot S)$ 時間，$S$ 為狀態數（337 是 2，968 是 3），即 $O(n)$。

空間 $O(h)$ 遞迴堆疊，加上每層 $O(S)$ 的回傳值，仍是 $O(h)$。

若狀態中含有一個範圍為 $k$ 的維度（樹上背包，例如「子樹中選 $j$ 個」），複雜度會變成 $O(nk)$ 或 $O(n k^2)$；後者在「合併時枚舉左右各分配多少」的寫法下，透過經典的「按子樹大小上界枚舉」分析其實是 $O(n^2)$ 而非 $O(n k^2)$，這是樹上背包的著名結論。

## 常見錯誤與邊界條件

- 只回傳單一最大值導致狀態不完備，產生父子同選的非法解。
- 空節點的初始狀態設錯（968 中空節點應視為「已被覆蓋」而非「需要覆蓋」，否則會給葉節點的父親裝多餘的攝影機）。
- 用 `int` 累加而溢位。
- 把左右子樹的狀態組合寫漏一種。
- 誤以為可以貪心（樹形 DP 題常有看似合理的貪心，337 對某些測資會失敗）。
- 斜樹爆堆疊。
- 只有一個節點的樹。

## 與相似技巧的比較

- 與 2.3 的界線：能用單一彙總量寫出歸納步驟就用 2.3，寫不出來才擴充成樹形 DP。多開狀態沒有壞處以外的代價，但無謂的狀態會讓轉移變複雜、更容易寫錯。
- 與線性 DP（dynamic_programming 主題）的關係：樹形 DP 就是把「按下標順序」的轉移換成「按後序順序」，無後效性由樹的層次結構天然保證——**子樹的答案不依賴子樹外的資訊**，這正是遞迴能奏效的原因。
- 換根 DP（3.4）處理「以每個節點為根各求一次答案」，做法是第一趟後序算子樹資訊、第二趟前序把子樹外的資訊傳下去，$O(n)$ 完成 $n$ 次查詢。
- 樹上背包（子樹中選 $k$ 個）是狀態帶容量維度的版本，複雜度分析與本節不同，需另行討論。

## 本節重點速查

- 狀態擴充的判斷準則：**父節點需要區別對待哪些情形，就開幾個狀態**。
- 337 用「選／不選」兩個；
- 968 用三個。
- 轉移的正確性依賴無後效性、子樹獨立性、狀態劃分完備三個前提。
- 空節點的初始狀態要與轉移一致。
- 只回傳單一最大值會遺失資訊而產生非法解。
