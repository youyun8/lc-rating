## 這個技術解決什麼問題

有一類問題的答案是**按層組織**的：逐層輸出（102）、鋸齒形輸出（103）、每層最右邊的節點（199）、最底層最左邊的值（513）。DFS 能訪問所有節點，但訪問順序打散了層次，要靠額外記錄深度再重組。

BFS 直接按層推進，天然給出層次結構。更重要的是在**無權圖／樹**上，BFS 第一次到達某節點時經過的邊數就是最短距離——這條性質讓「最小深度」「最少步數」類問題有了 $O(n)$ 解，而且不必像 DFS 那樣搜完所有分支。

**延伸講解**：[二叉樹的層序遍歷【基礎演算法精講 13】](https://www.bilibili.com/video/BV1hG4y1277i/)

## 狀態／資料結構定義

- `queue<TreeNode*> q`：待處理節點，初始放入 `root`（**必須先判 `root` 非空**）。
- **分層的關鍵技巧**：進入每一輪迴圈時先記錄 `int sz = q.size();`，然後恰好處理 `sz` 個節點。這 `sz` 個就是當前層的全部。
- 若不記 `sz` 而直接 `while (!q.empty())` 逐個彈出，節點順序仍然正確，但**層與層之間的界線消失**，無法輸出巢狀結果。這是 102 與「單純 BFS」的唯一差別。
- 103 鋸齒形：不要反轉佇列（會破壞後續層的順序），而是照常 BFS，只在**輸出該層的結果陣列時**依層號決定是否反轉，或用 `deque` 從兩端插入。

## 不變量或正確性證明

**分層不變量：每輪迴圈開始時，佇列中恰好包含第 $d$ 層的所有節點，且順序為由左至右。**

- 初始化：$d = 0$，佇列只有根，成立。
- 保持：記下 `sz = q.size()`（第 $d$ 層的節點數）。依序彈出這 `sz` 個節點，對每個節點依「先左子後右子」的順序把非空子節點入隊。彈出時佇列前 `sz` 個是第 $d$ 層，後面新加入的都在其後（FIFO），故這一輪不會誤處理到第 $d+1$ 層的節點。處理完後，佇列中恰是第 $d$ 層所有節點的子節點——由於樹中每個第 $d+1$ 層節點的父節點唯一且必在第 $d$ 層，這正是第 $d+1$ 層的全部，不重不漏。左右順序也維持：父節點按左至右處理，每個父節點先加左子再加右子，故子節點整體仍是左至右。
- 終止：佇列為空時所有層都已處理完。

`sz` 必須在**彈出任何節點之前**取得。若在迴圈中途重新讀 `q.size()`，該值已被本輪新加入的子節點污染，分層就錯了。

**最短距離性質。** 由不變量，節點 $v$ 在第 $d$ 輪被彈出，當且僅當 $v$ 位於第 $d$ 層，即根到 $v$ 的邊數為 $d$。因此 BFS 依距離遞增的順序訪問節點，**第一次遇到某節點時的層號就是最短距離**。這條性質在樹上顯得平凡（樹中路徑唯一），但推廣到圖時就是 BFS 求無權最短路的基礎，前提是**每條邊的權重相同**——邊權不等時 BFS 不再給出最短路，必須改用 Dijkstra。

**513（最底層最左）的巧解**：把入隊順序改成「先右子後左子」，則最後一個被彈出的節點必是最底層最左者。理由：由不變量的對稱版本，每層的彈出順序變成由右至左，故每層最後彈出的是該層最左者；而最後一層最後彈出的節點就是全域最後一個。這省去了記錄層號與比較的步驟。

**199（右視圖）**：每層的最後一個彈出者即該層最右節點，用 `i == sz - 1` 判斷即可。

## C++17 模板

```cpp
// 逐層輸出（LeetCode 102）：用 sz 切出層界線。
std::vector<std::vector<int>> levelOrder(TreeNode* root) {
    std::vector<std::vector<int>> ans;
    if (!root) {
        return ans;
    }  // 空樹必須先擋掉

    std::queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        int sz = q.size();  // 必須在彈出前取得，否則被子節點污染
        std::vector<int> level;
        level.reserve(sz);
        for (int i = 0; i < sz; ++i) {  // 恰好處理當前層的 sz 個
            TreeNode* node = q.front();
            q.pop();
            level.push_back(node->val);
            if (node->left) {
                q.push(node->left);
            }
            if (node->right) {
                q.push(node->right);
            }
        }
        ans.push_back(std::move(level));
    }
    return ans;
}
```

鋸齒形（103）在 `ans.push_back` 前依 `ans.size() % 2` 決定是否 `std::reverse(level.begin(), level.end())`；右視圖（199）只取 `i == sz - 1` 的節點。

## 時間與空間複雜度

每個節點恰入隊一次、出隊一次，各做 $O(1)$ 工作，故 $O(n)$ 時間。

空間 $O(w)$，$w$ 是**最大層寬**。這與 DFS 的 $O(h)$ 是互補的：完全二元樹中 $w = O(n)$ 而 $h = O(\log n)$，此時 DFS 省空間；斜樹中 $w = 1$ 而 $h = n$，此時 BFS 省空間且不會爆堆疊。**選 DFS 還是 BFS，空間上要看樹的形狀。**

輸出所有層的結果本身需要 $O(n)$ 空間，不可省。

## 常見錯誤與邊界條件

- 忘記在入隊前判空樹，`q.push(nullptr)` 後解參考崩潰。
- 在迴圈中途重新讀 `q.size()` 導致分層錯亂。
- 把子節點入隊時沒判空，佇列混入 `nullptr`。
- 103 直接反轉佇列而破壞後續層次（應只反轉輸出）。
- 107（自底向上分層）忘記最後反轉整個結果，或用 `insert(begin())` 造成 $O(n^2)$。
- 只有根節點的樹。
- 深度很大但每層很窄時誤以為 BFS 省空間（此時反而是 DFS 省）。

## 與相似技巧的比較

- DFS（2.1、2.2）能拿到「路徑」，BFS 拿不到（要拿到得額外記父節點回溯）；反過來 BFS 天然給出層次與最短距離，DFS 要額外傳深度。**問「路徑」用 DFS，問「層」或「最少步數」用 BFS。**
- 空間上 $O(h)$ 對 $O(w)$，如上所述取決於形狀。
- 最小深度（111）用 BFS 遇到第一個葉節點即可回傳，比 DFS 需搜完所有分支更快；最大深度（104）則兩者都要走完全樹，用 DFS 較短。
- 圖上的 BFS（graph 主題）多了 `visited` 集合，因為圖可能有環且節點可從多條路徑到達；樹上不需要 `visited`，這是樹 BFS 較簡單的原因。
- 多源 BFS（同時把多個起點入隊）是常見變體，2385（感染時間）可用它，也可用 2.6 的直徑分解。

## 本節重點速查

- `while (!q.empty())` 外層加 `int sz = q.size()` 內層迴圈，這一行就是分層的全部；
- `sz` 必須在彈出前取得。
- 不變量是「每輪開始時佇列恰為第 $d$ 層、由左至右」。
- BFS 的層號即最短距離（前提：邊權相同）。
- 空間 $O(w)$ 對 DFS 的 $O(h)$，依樹形選擇。
