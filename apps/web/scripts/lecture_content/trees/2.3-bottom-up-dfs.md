## 這個技術解決什麼問題

另一類樹題，答案取決於**以當前節點為根的整棵子樹**：這棵子樹有多高（104）、有幾個節點（222）、是否平衡（110）、子樹和是多少。這些資訊在進入節點時還不存在，必須等兩棵子樹都算完才能合成。

若對每個節點各跑一次子樹掃描，成本是 $O(nh)$（斜樹達 $O(n^2)$）。自底向上 DFS 讓**每個節點只算一次、結果沿著遞迴回傳往上傳**，總計 $O(n)$。這是「一次遍歷解決全部節點的子樹查詢」的標準手法，也是樹形 DP（2.12）的雛形。

## 狀態／資料結構定義

- `dfs(node)` 的**回傳值**就是狀態：以 `node` 為根的子樹的彙總量。定義必須精確到能讓合併規則寫得出來。
- 空子樹的回傳值是**單位元**，且必須讓合併規則對它成立：高度取 0、節點數取 0、子樹和取 0、最小值取 `INT_MAX`。單位元選錯是本節最常見的錯誤。
- 合併規則 `f(node) = combine(f(left), f(right), node)`，只用兩個子樹的彙總值與節點自身。
- 若彙總量不只一個（例如同時要高度與是否平衡），回傳 `pair`/`struct`，或用哨兵值編碼（110 題常用 $-1$ 表示「已失衡」）。

## 不變量或正確性證明

命題（結構歸納）：**對每個節點 $v$，`dfs(v)` 回傳的值等於以 $v$ 為根之子樹的目標彙總量。**

- 基底：$v$ 為空，回傳單位元。這要求單位元的定義與「空子樹的彙總量」一致——高度 0、節點數 0 都對；但若求「子樹最小值」而回傳 0，遇到全正數的樹就會錯，必須用 `INT_MAX`。基底不是形式步驟，它是實際的正確性條件。
- 歸納：假設 `dfs(left)`、`dfs(right)` 各自正確。由於左子樹、右子樹、$v$ 三者的節點集合構成整棵子樹的一個劃分，只要 `combine` 忠實反映「彙總量如何由這個劃分組合而成」，`dfs(v)` 即正確。例如高度 $= 1 + \max(h_L, h_R)$，因為最長的根到葉路徑必經左或右其中一棵；節點數 $= 1 + n_L + n_R$，因為劃分不重不漏。
- 結論：對根成立，得證。

這條論證要求彙總量**可由子樹的彙總量組合而成**（即具有最優子結構／可分解性）。若某個量不具此性質——例如「子樹中距離為 3 的節點對數」無法只由兩個子樹的同類數字算出——就得擴充狀態（多回傳幾個量），這正是樹形 DP 的思路。判斷「狀態夠不夠」的標準就是：**歸納步驟能不能只用子樹的回傳值寫出來。**

**110 平衡二元樹的提前退出。** 定義 `dfs` 回傳高度，但一旦發現失衡就回傳 $-1$ 並讓 $-1$ 向上傳播。正確性在於 $-1$ 不可能是合法高度（高度非負），故它是無歧義的哨兵；且任何節點只要有一棵子樹回傳 $-1$ 就立刻回傳 $-1$，不再計算，於是「失衡」這個事實一路傳到根。這使複雜度從樸素的「對每個節點各算一次高度」$O(n^2)$ 降到 $O(n)$——**關鍵是把「高度」與「是否平衡」合併進同一次遍歷，而不是分兩次算。**

**100 相同樹、101 對稱樹**同屬此類：狀態是「這兩棵子樹是否相同」，合併規則是「根值相等且對應的兩對子樹都相同」。對稱樹要注意配對方式是 $(L.left, R.right)$ 與 $(L.right, R.left)$，寫成同側配對就變成判斷相同而非對稱。

## C++17 模板

```cpp
// 判斷平衡二元樹（LeetCode 110）：回傳高度，失衡則回傳 -1 並向上傳播。
int height(TreeNode* node) {
    if (!node) {
        return 0;
    }  // 單位元：空子樹高度為 0

    int l = height(node->left);
    if (l == -1) {
        return -1;
    }  // 已失衡，提前退出
    int r = height(node->right);
    if (r == -1) {
        return -1;
    }

    if (std::abs(l - r) > 1) {
        return -1;
    }
    return 1 + std::max(l, r);  // 合併：由兩棵子樹的高度組合
}

bool isBalanced(TreeNode* root) {
    return height(root) != -1;
}
```

需要回傳多個量時改用 `struct`：

```cpp
struct Info {
    int size;
    long long sum;
    int mx;
};

Info dfs(TreeNode* node) {
    if (!node) {
        return {0, 0, INT_MIN};
    }  // 單位元要讓 combine 成立
    Info l = dfs(node->left), r = dfs(node->right);
    return {1 + l.size + r.size, node->val + l.sum + r.sum,
            std::max({node->val, l.mx, r.mx})};
}
```

## 時間與空間複雜度

每個節點恰呼叫一次 `dfs`，每次做 $O(1)$ 的合併，故 $O(n)$ 時間。這正是「一次遍歷取代 $n$ 次子樹掃描」的收穫：樸素做法 $O(nh)$，最壞 $O(n^2)$。

空間 $O(h)$ 遞迴堆疊。回傳 `struct` 不改變漸近空間（每層一份，仍是 $O(h)$）。斜樹時 $h = n$，深度上萬的測資需改迭代版（後序迭代較繁瑣，通常用顯式堆疊記錄「是否已處理過右子」）。

## 常見錯誤與邊界條件

- 空子樹回傳的單位元選錯（求最小值回傳 0、求最大值回傳 0 而樹中有負數）。
- 110 題對每個節點各算一次高度而超時。
- 101 對稱樹配對方向寫成同側。
- 把需要路徑資訊的題目硬用後序寫（資訊在後序時已遺失）。
- `sum` 用 `int` 溢位。
- 斜樹爆堆疊。
- 忘記 `dfs(node->right)` 而只算左邊。

## 與相似技巧的比較

- 自頂向下（2.2）傳路徑資訊、自底向上傳子樹資訊。**問「我以下如何」用後序，問「從根到我如何」用前序**，這是選擇的唯一依據。
- 兩者結合就是 2.5「有遞有歸」，以及 2.6 直徑那類「在每個節點處用左右子樹資訊更新全域答案」的模式。
- 樹形 DP（2.12）是本節的推廣：當單一彙總量不足以支撐歸納步驟時，把狀態擴充成多維（例如「選這個節點」與「不選」兩種情形各一個值）。
- 一般樹的自底向上（3.3）完全同構，只是把「左右兩個子樹」換成「對所有子節點迴圈累積」。

## 本節重點速查

- 用**回傳值**把子樹彙總往上傳；
- 空子樹回傳單位元，且單位元必須讓合併規則成立。
- 正確性是結構歸納，關鍵條件是「彙總量可由子樹彙總量組合而成」；
- 組合不出來就擴充狀態。
- 時間 $O(n)$、空間 $O(h)$。
