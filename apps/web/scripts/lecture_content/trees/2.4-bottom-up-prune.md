## 這個技術解決什麼問題

「刪掉所有不含 1 的子樹」（814）、「刪掉所有不含指定目標的分支」（1325 反覆刪葉），這類題目要**修改樹的結構**而非只計算數值。

難點在於刪除的判定有連鎖效應：刪掉一片葉子後，它的父節點可能變成新的葉子而也該被刪。若自頂向下判斷，你在看父節點時還不知道子樹會不會被清空，於是只能反覆掃描直到不再變化，成本 $O(nh)$。

自底向上剪枝的槓桿是：**先遞迴處理子樹，回來時子樹已經是最終形態**，此時判斷自己去留所依據的資訊就是完整且最終的，一趟 $O(n)$ 解決連鎖。

## 狀態／資料結構定義

- `dfs(node)` **回傳修剪後的子樹根**，可能是 `nullptr`（整棵被刪）也可能是 `node` 自己。這個「回傳新根」的介面是關鍵：它讓父節點用 `node->left = dfs(node->left);` 一行就完成「接上修剪結果」，不必區分「有刪」與「沒刪」兩種情況。
- 判定順序固定：先遞迴左右並**把回傳值接回去**，再判斷自己。
- 「是否為葉」在判定時必須用**修剪後**的狀態：`!node->left && !node->right`，此時兩者已是遞迴回傳的結果。

1325 題（刪除值為 target 的葉節點）的判定條件是「修剪後成為葉節點且值等於 target」；814 題是「修剪後兩子皆空且自身值為 0」。

## 不變量或正確性證明

命題（結構歸納）：**`dfs(v)` 回傳的子樹，等於對以 $v$ 為根的原子樹反覆套用刪除規則直到穩定所得的結果。**

- 基底：$v$ 為空，回傳空，平凡成立。
- 歸納：假設 `dfs(v->left)`、`dfs(v->right)` 回傳的分別是左右子樹的**穩定形態**。把它們接回 $v$ 後，以 $v$ 為根的樹中除了 $v$ 自己，其餘部分都已穩定（不存在任何還該被刪的節點）。因此只需再判斷 $v$ 一次：若 $v$ 滿足刪除條件則回傳 `nullptr`，否則回傳 $v$。無論哪種情形，結果都已穩定。

論證的核心是這一句：**修剪只會讓節點消失，不會產生新節點；而某節點是否該刪只依賴其子樹的最終狀態。** 因此後序處理過的部分不會因為後續操作而重新變得「該刪」——單調性保證了一趟就到不動點，不需要迭代。

反過來看為什麼自頂向下不行：在 $v$ 處判斷時子樹尚未修剪，「$v$ 是否為葉」的答案可能與最終狀態不同。814 題若先判 $v$ 再遞迴，一棵值全為 0 的鏈只會刪掉最底層一個節點，需再掃一趟才刪下一層，共 $h$ 趟。

**這個論證依賴刪除規則的「向上單調」性質**：刪掉子節點只可能讓父節點更接近被刪的條件，不會讓已經確定保留的節點變回該刪。若題目的規則是「子樹被刪則父節點必須保留」這種非單調規則，一趟後序就不成立，得另尋方法。

另外注意 `node->left = dfs(node->left);` 這個寫法本身就是不變量的實作：它保證「父節點看到的永遠是修剪後的子樹」。寫成 `dfs(node->left);` 而不接回傳值，是本節最常見的錯誤——遞迴確實跑了，但結果沒有被接上，樹完全沒變。

## C++17 模板

```cpp
// 刪除所有不含 1 的子樹（LeetCode 814）。
TreeNode* pruneTree(TreeNode* root) {
    if (!root) {
        return nullptr;
    }

    root->left = pruneTree(root->left);  // 先修剪子樹，並把結果接回去
    root->right = pruneTree(root->right);  // 漏掉賦值 = 樹完全沒變

    if (!root->left && !root->right && root->val == 0) {
        return nullptr;  // 修剪後成為葉且值為 0，刪掉自己
    }
    return root;
}
```

1325 題（反覆刪除值為 target 的葉節點）只需把最後的判定換成 `!root->left && !root->right && root->val == target`；連鎖刪除由後序自動完成，不需外層迴圈。

## 時間與空間複雜度

每個節點恰被訪問一次、判定一次，$O(n)$ 時間。這是相對於「反覆掃描直到不變」$O(nh)$（最壞 $O(n^2)$）的主要收穫，而且省下的不只是常數——一趟到不動點是由上述單調性論證保證的，不是經驗。

空間 $O(h)$ 遞迴堆疊。若需要釋放被刪節點的記憶體，在回傳 `nullptr` 前 `delete` 即可，不改變複雜度。

## 常見錯誤與邊界條件

- 呼叫 `dfs(root->left)` 卻沒把回傳值賦回 `root->left`，樹完全沒被修剪。
- 判定「是否為葉」時用了修剪前的子樹（例如先判自己再遞迴）。
- 1325 題外面再包一層 `while (changed)` 迴圈，多餘且容易寫錯終止條件。
- 整棵樹被刪光時回傳 `nullptr`，呼叫端未處理。
- 只判 `root->val == 0` 而忘了同時要求兩子為空，把中間節點也刪掉。
- 被刪節點未釋放。

## 與相似技巧的比較

- 與 2.3 一般的自底向上相比，本節回傳的是**節點指標**而非數值，因此能直接改動結構；兩者的歸納骨架完全相同。
- 與 2.11 的 BST 刪除節點相比：本節是「依條件批次刪除」，2.11 是「刪除指定的單一節點並維持 BST 性質」，後者需要用前驅或後繼補位，複雜得多。
- 一般樹上的對應題型見 3.3；圖上「反覆刪度數為 1 的點」則是拓撲排序剝葉（3.6），那裡因為沒有天然的父子方向，必須用佇列顯式維護待刪集合。

## 本節重點速查

- 先遞迴、**把回傳值接回 `node->left` 與 `node->right`**、再判自己，這個順序保證判定時看到的是子樹的最終形態。
- 單調性（刪子只會讓父更該刪）保證一趟 $O(n)$ 到不動點，不需要外層迴圈。
