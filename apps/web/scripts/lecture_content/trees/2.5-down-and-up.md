## 這個技術解決什麼問題

有些題目同時需要兩個方向的資訊：處理某節點時，既要知道「從根到我累積了什麼」，也要知道「我的子樹回傳了什麼」。538／1038（把 BST 轉成累加樹）就是典型——每個節點要加上**所有比它大的節點之和**，而那些節點分佈在它的右子樹與若干祖先的右子樹裡。

一趟前序拿不到子樹資訊，一趟後序拿不到路徑資訊。「有遞有歸」的做法是在**同一次遍歷**中兩者兼顧：往下時傳遞參數，往上時回傳彙總，或者更巧妙地——**挑一個讓所需資訊恰好按順序出現的遍歷次序**。

## 狀態／資料結構定義

以 538 為例，關鍵洞察是：BST 的**反中序**（右 → 根 → 左）恰好給出由大到小的節點序列。於是狀態退化成一個變數：

- `sum`：目前為止（即所有比當前節點大的節點）的累加和，用引用或成員變數跨遞迴共享。
- 訪問順序：先遞迴右子樹，再處理自己（`sum += node->val; node->val = sum;`），最後遞迴左子樹。

一般形式則是：

- 往下傳的參數 `down`（路徑資訊）。
- 往上回的回傳值 `up`（子樹彙總）。
- 節點處理放在「兩者都齊備」的時機點。

865／1080 需要真正的雙向：1080 要先自頂向下算出根到當前節點的路徑和，才能判斷「經過此節點的最大路徑和是否不足 limit」；而刪除的效果又必須自底向上傳遞（子樹全刪則自己也要刪）。

## 不變量或正確性證明

**538 反中序累加的不變量：** 在對節點 $v$ 執行 `sum += v->val` 之前，`sum` 恰等於樹中所有**嚴格大於** $v->val$ 的節點值之和。

證明分兩部分，都依賴 BST 性質。

其一，反中序序列是節點值的遞減排列。由 BST 定義，左子樹全部小於根、右子樹全部大於根；反中序輸出「右子樹、根、左子樹」，由結構歸納，右子樹遞減、左子樹遞減，且右子樹的值全大於根、根大於左子樹全部，故串接後整體遞減。

其二，既然序列遞減，處理到 $v$ 時已處理過的節點恰是所有大於 $v$ 的節點；`sum` 是它們的和，正是不變量所述。因此 `sum += v->val` 後 `sum` 成為「大於等於 $v$」之和，賦給 `v->val` 即為所求。

**這裡點名關鍵前提：輸入必須是 BST，且值互不相同。** 若有重複值，「嚴格大於」與「大於等於」的界線落在重複區塊內部，反中序的相對次序決定結果，題目須另行約定。若不是 BST，反中序給不出遞減序列，整個論證崩潰，只能退回「先收集所有值排序」的 $O(n \log n)$ 做法。

**一般雙向模式的正確性**由兩條不變量疊加：往下的參數滿足 2.2 的路徑不變量（呼叫 `dfs(v, down)` 時 `down` 是根到 $v$ 之父的累積量），往上的回傳值滿足 2.3 的子樹不變量（`dfs(v, ·)` 的回傳值是 $v$ 子樹的彙總量）。兩者互不干擾——**前提是往下傳的參數不被子樹修改**。若 `down` 是傳參考的可變容器，遞迴回來後必須復原，否則兄弟子樹拿到的路徑資訊是錯的（見 2.7 回溯）。

1080 的刪除規則正確性：節點 $v$ 應被刪，若且唯若所有經過 $v$ 的根到葉路徑和都小於 limit。等價地，$v$ 的左右子樹在遞迴後都回傳 `nullptr`（各自沒有合格路徑），或 $v$ 是葉且路徑和不足。這個等價需要「合格路徑必然延伸到葉」這個前提，故葉節點的判定必須用原始的葉，而路徑和的累積必須自頂向下——兩個方向缺一不可。

## C++17 模板

```cpp
// BST 轉累加樹（LeetCode 538 / 1038）：反中序，一個共享變數即可。
class Solution {
    int sum_ = 0;

public:
    TreeNode* convertBST(TreeNode* root) {
        if (!root) {
            return nullptr;
        }
        convertBST(root->right);  // 先走大的一側
        sum_ += root->val;  // 此時 sum_ 是所有大於 root 的節點之和
        root->val = sum_;
        convertBST(root->left);  // 再走小的一側
        return root;
    }
};
```

真正雙向的骨架（以 1080 為例）：

```cpp
// 往下傳路徑和 down，往上回「修剪後的子樹根」。
TreeNode* sufficientSubset(TreeNode* root, int limit) {
    if (!root) {
        return nullptr;
    }
    int down = limit - root->val;       // 往下：扣掉自己
    if (!root->left && !root->right) {  // 葉：路徑和是否達標
        return down > 0 ? nullptr : root;
    }
    root->left = sufficientSubset(root->left, down);  // 往上：接回修剪結果
    root->right = sufficientSubset(root->right, down);
    return (root->left || root->right) ? root : nullptr;
}
```

## 時間與空間複雜度

兩者都是 $O(n)$ 時間——每個節點仍只訪問一次，「有遞有歸」指的是在同一次訪問中利用兩個時機點，不是走兩趟。空間 $O(h)$ 遞迴堆疊。

538 的替代解法「先中序收集再反向前綴和」同為 $O(n)$ 時間但需 $O(n)$ 額外空間；反中序版只用一個變數，這是選它的理由。

## 常見錯誤與邊界條件

- 538 寫成正中序（左 → 根 → 右），累加的變成比它小的節點。
- `sum` 宣告成區域變數而非跨遞迴共享，每層各算各的。
- 把往下傳的可變容器在遞迴後忘記復原，污染兄弟子樹。
- 1080 在非葉節點就用路徑和判定（必須延伸到葉才算數）。
- 1080 忘記把遞迴回傳值接回 `root->left`／`root->right`。
- 空樹。
- 整棵樹被刪光時回傳 `nullptr` 未被呼叫端處理。

## 與相似技巧的比較

- 純自頂向下（2.2）與純自底向上（2.3）各用一個方向；本節在需要兩者時才用，不要無腦套用——多傳一個沒用到的參數只會增加出錯面。
- 2.6 直徑那類「在每個節點用左右子樹回傳值更新全域答案」嚴格說只用了向上方向，但因為答案寫在全域變數，形式上很像雙向，要能區分。
- 一般樹的對應是 3.4；換根 DP（樹形 DP 的進階，見 2.12 與 3.4）是雙向的極致——第一趟後序算子樹資訊，第二趟前序把「子樹外」的資訊傳下去。

## 本節重點速查

- 往下傳路徑參數、往上回子樹彙總，兩個時機點在同一次遍歷中各取所需。
- BST 的反中序給出遞減序列，538 靠這條性質把雙向需求壓成一個共享變數。
- 往下傳可變容器時務必復原；
- 往上回節點指標時務必接回賦值。
