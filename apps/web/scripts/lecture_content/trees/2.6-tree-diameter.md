## 這個技術解決什麼問題

樹的直徑是「任意兩節點間最長路徑的長度」（543 數邊數，124 求最大路徑和）。樸素做法是對每個節點各跑一次 DFS 求最遠距離，$O(n^2)$。

槓桿在於一個結構性觀察：**每條路徑都有唯一的最高點**（離根最近的那個節點）。於是「枚舉所有路徑」可以轉成「枚舉最高點」——對每個節點 $v$，計算「以 $v$ 為最高點的最長路徑」，取全域最大值。而後者只需要 $v$ 的左右子樹各自的「向下最長鏈」，一次後序遍歷就能全部算完，$O(n)$。

這個「枚舉最高點」的分解方式是樹上路徑問題的通用武器，遠不只用在直徑。

## 狀態／資料結構定義

必須嚴格區分兩個量，混用是本節唯一的大坑：

- **回傳值** `down(v)`：從 $v$ 出發、**向下走到某個後代**的最長鏈。它必須是「單邊」的，因為父節點要拿它接上自己再往上延伸，路徑不能有分叉。空節點回傳 0（543 數邊）或 0（124 因為可捨棄負貢獻）。
- **全域答案** `ans`：在每個節點處用 `down(left) + down(right) + (自身貢獻)` 更新，這是「以 $v$ 為最高點」的最長路徑，允許左右分叉。

543 的兩者：`down(v) = 1 + max(down(L), down(R))`（邊數），`ans = max(ans, down(L) + down(R))`。

124 的兩者：`down(v) = v->val + max(0, max(down(L), down(R)))`，`ans = max(ans, v->val + max(0, down(L)) + max(0, down(R)))`。`max(0, ·)` 的意思是負貢獻的子樹乾脆不接。

## 不變量或正確性證明

**分解的完備性。** 命題：任一條路徑 $P$ 恰有一個節點是 $P$ 上深度最小的節點（即最高點）。存在性顯然（有限集合有最小值）。唯一性：假設有兩個節點 $a \ne b$ 深度同為最小，路徑 $P$ 上 $a$ 到 $b$ 這段必經過它們的 LCA，而 LCA 的深度嚴格小於兩者（$a$、$b$ 互不為祖先，否則深度不等），與最小性矛盾。故最高點唯一。

因此「所有路徑」被最高點劃分成 $n$ 個互斥類別，取各類別最大值的最大值即為全域最大——**沒有路徑被漏掉，也沒有被重複計算**。這就是為什麼在每個節點更新一次 `ans` 就足夠。

**每個類別內的最大值。** 以 $v$ 為最高點的路徑，形狀必定是「從左子樹某後代向上到 $v$，再向下到右子樹某後代」（其中一側可為空）。要最大化，兩側各自獨立取最長向下鏈即可——**兩側的選擇互不影響**，因為它們位於不相交的子樹中。這個獨立性正是能拆成 `down(L) + down(R)` 的依據；若路徑有「不能重複用某資源」之類的耦合約束，這一步就不成立。

**回傳值的正確性（結構歸納）。** `down(v)` 回傳從 $v$ 向下的最長鏈。基底：空節點回傳 0。歸納：從 $v$ 向下的鏈，若非空則必先走到左子或右子，之後就是從該子節點向下的鏈；由歸納假設兩者為 `down(L)`、`down(R)`，取較大者加上 $v$ 到子的那條邊即可。

**為什麼回傳值必須是單邊。** 若 `down(v)` 回傳了分叉後的值（即把 `ans` 那個公式當回傳值），父節點接上它會得到一條有分叉的「路徑」，不是合法路徑。這是本節最常見的錯誤，症狀是答案偏大。

**124 為何要 `max(0, ·)`。** 節點值可為負，接上一棵總和為負的子樹只會讓路徑和變小，故可以選擇不接。合法性在於「單一節點」本身就是合法路徑，所以捨棄某一側不會導致無路徑可選。若題目要求路徑必須含至少兩個節點，這個裁剪就要調整。相對地，543 數的是邊數且邊數非負，不需要裁剪。

## C++17 模板

```cpp
// 二元樹的直徑（LeetCode 543）：回傳向下最長鏈，全域答案允許分叉。
class Solution {
    int ans_ = 0;

    int down(TreeNode* node) {  // 從 node 向下的最長鏈（邊數）
        if (!node) {
            return 0;
        }
        int l = down(node->left);
        int r = down(node->right);
        ans_ = std::max(ans_, l + r);  // 以 node 為最高點：允許左右分叉
        return 1 + std::max(l, r);  // 回傳給父節點：必須單邊
    }

public:
    int diameterOfBinaryTree(TreeNode* root) {
        down(root);
        return ans_;
    }
};
```

最大路徑和（LeetCode 124）同一骨架，加上負貢獻裁剪：

```cpp
long long ans = LLONG_MIN;

long long down(TreeNode* node) {
    if (!node) {
        return 0;
    }
    long long l = std::max(0LL, down(node->left));  // 負的就不接
    long long r = std::max(0LL, down(node->right));
    ans = std::max(ans, node->val + l + r);  // 最高點在此
    return node->val + std::max(l, r);       // 單邊上傳
}
```

## 時間與空間複雜度

每個節點恰計算一次 `down` 並更新一次 `ans`，均為 $O(1)$ 工作，故 $O(n)$ 時間。相對於「對每個節點各跑一次 DFS」的 $O(n^2)$，收穫來自最高點分解讓每個節點只需負責自己那一類。

空間 $O(h)$ 遞迴堆疊，斜樹最壞 $O(n)$。

## 常見錯誤與邊界條件

- 把回傳值寫成 `l + r`（分叉值），父節點接上後路徑不合法，答案偏大。
- 124 忘記 `max(0, ·)`，被負值子樹拖累。
- 124 答案初始值設為 0 而全樹皆負時輸出 0（應設為 `LLONG_MIN` 或第一個節點值）。
- 543 混淆邊數與節點數（邊數 = 節點數 $-$ 1，題目要哪個要看清楚）。
- `ans` 用 `int` 在 124 溢位。
- 只有一個節點時直徑為 0（邊數）。
- 空樹。

## 與相似技巧的比較

- 一般樹的直徑（3.5）除了同樣的 DFS 解法，還有「兩次 BFS」的經典解法：從任意點出發找最遠點 $u$，再從 $u$ 出發找最遠點 $v$，$u$ 到 $v$ 即直徑。那個解法的正確性另需一套論證（且**只對無權或正權樹成立**），見 3.5。
- 687（最長同值路徑）、2385（感染時間）都是同一個最高點分解骨架，只是 `down` 的定義換成「向下最長同值鏈」或「向下最長距離」。
- 549（最長連續序列路徑）需要回傳兩個量（遞增鏈長與遞減鏈長），是狀態擴充的例子，思路同 2.3 末尾所述。
- 與樹形 DP（2.12）的界線：直徑類問題的狀態只有一維（向下最長鏈），樹形 DP 通常有多維狀態（選／不選）。

## 本節重點速查

- **枚舉最高點**：每條路徑有唯一最高點，故在每個節點更新一次全域答案就不重不漏。
- 回傳值是**單邊**向下最長鏈（給父節點延伸用），全域答案才允許**左右分叉**——兩者絕不可混用。
- 124 用 `max(0, ·)` 捨棄負貢獻，答案初值要能容納全負。
