## 這個技術解決什麼問題

當答案是「所有從根到葉、和為目標值的路徑」（113）或「所有根到葉路徑的字串」（257）時，你需要的不只是路徑的**摘要**（和、長度），而是路徑**本身**。

把路徑存成容器往下傳，若每層複製一份，$n$ 個節點各持有長度 $O(h)$ 的副本，光是複製就 $O(nh)$。回溯的槓桿是**全程共用同一個容器**：進入節點時 `push_back`，離開節點前 `pop_back`。每次進出各 $O(1)$，總計 $O(n)$ 的維護成本，只有在真正記錄答案時才付一次複製。

## 狀態／資料結構定義

- `path`：共享的可變容器（`vector<int>`），語意是「從根到當前節點的路徑」。**必須以引用傳遞或設為成員變數**，按值傳遞就退化成複製法。
- 三段式骨架，順序固定：
  1. `path.push_back(node->val);` — 進入，把自己加入路徑。
  2. 遞迴左右子樹（中間可能記錄答案）。
  3. `path.pop_back();` — 離開，撤銷。
- 記錄答案的時機在葉節點：`if (!node->left && !node->right && rest == 0) ans.push_back(path);` — 這裡的複製是必要的，因為 `path` 之後會被改動。
- 437（路徑和 III，路徑不必從根開始）改用另一種狀態：前綴和計數雜湊表 `cnt[prefix]`，同樣需要在離開時撤銷。

## 不變量或正確性證明

不變量：**每次呼叫 `dfs(node)` 進入函式時，`path` 恰等於根到 `node` 之父的路徑；每次 `dfs(node)` 返回時，`path` 已被還原成呼叫前的內容。**

- 初始化：`dfs(root)` 前 `path` 為空，而根之父不存在（空路徑），成立。
- 保持與還原：函式體 `push_back(node)` 使 `path` 成為根到 `node` 的路徑，故對子節點呼叫 `dfs(child)` 時，`path` 正是根到 child 之父（即 `node`）的路徑，不變量的前半對子呼叫成立。由歸納假設，每個子呼叫返回時 `path` 已還原（仍是根到 `node`）。最後 `pop_back()` 移除 `node`，`path` 回到進入前的狀態，後半成立。
- 結論：對任一葉節點 $\ell$，在其函式體內 `push_back` 之後，`path` 恰為根到 $\ell$ 的完整路徑。

**這個「返回時已還原」的性質是整套方法的核心，也是它為什麼叫「回溯」。** 它保證兄弟子樹之間完全隔離：右子樹開始時看到的 `path` 與左子樹開始時一模一樣。少寫一行 `pop_back()`，路徑就會不斷累積，右子樹看到的是「左子樹殘留 + 自己」，答案錯得離譜卻不會崩潰——這正是它難以除錯的原因。

**push 與 pop 必須嚴格配對**：函式的每一條返回路徑（包括提前 `return`）之前都要 pop。因此若在中途寫 `if (...) return;`，就漏了一次 pop。穩妥的寫法是把出口統一在函式末尾，或改用 RAII 守衛。

**437 前綴和法的正確性。** 定義 `pre(v)` 為根到 $v$ 的路徑和。以 $v$ 結尾的向下路徑中，和為 `target` 的條數，等於祖先鏈上（含根之前的虛擬起點）滿足 `pre(u) == pre(v) - target` 的 $u$ 的個數。用雜湊表 `cnt` 記錄**當前祖先鏈**上各前綴和出現的次數即可 $O(1)$ 查詢。

關鍵前提：`cnt` 必須恰好反映「當前祖先鏈」，不能包含已經離開的分支。因此進入時 `cnt[pre(v)]++`、離開前 `cnt[pre(v)]--`，與 `path` 的 push/pop 同構。少了這個撤銷，左子樹的前綴和會被誤算成右子樹的祖先，產生根本不存在的路徑。另需初始化 `cnt[0] = 1`，代表「空前綴」，否則從根開始的合格路徑會漏算。

## C++17 模板

```cpp
// 所有和為 target 的根到葉路徑（LeetCode 113）。
class Solution {
    std::vector<std::vector<int>> ans_;
    std::vector<int> path_;  // 全程共用一份

    void dfs(TreeNode* node, int rest) {
        if (!node) {
            return;
        }

        path_.push_back(node->val);  // 1. 進入
        rest -= node->val;

        if (!node->left && !node->right && rest == 0) {
            ans_.push_back(path_);  // 記錄時才複製一次
        }
        dfs(node->left, rest);  // 2. 遞迴
        dfs(node->right, rest);

        path_.pop_back();  // 3. 離開時撤銷，兄弟子樹才互不污染
    }

public:
    std::vector<std::vector<int>> pathSum(TreeNode* root, int target) {
        dfs(root, target);
        return ans_;
    }
};
```

437 的骨架相同，把 `path_` 換成 `unordered_map<long long, int> cnt_`，初始 `cnt_[0] = 1`，進入時 `++cnt_[pre]`、離開時 `--cnt_[pre]`。

## 時間與空間複雜度

113：遍歷 $O(n)$，但**記錄答案的複製不可省**。最壞情況（完全二元樹，全部路徑合格）有 $O(n)$ 條路徑、每條長 $O(h)$，故輸出規模 $O(nh)$，總時間 $O(nh)$。這是輸出下界決定的，不是演算法的浪費。空間除輸出外為 $O(h)$。

437：每個節點常數次雜湊操作，$O(n)$ 時間、$O(h)$ 空間。相對於「對每個節點各往下掃一次」的 $O(n^2)$（斜樹）或 $O(n \log n)$（平衡），前綴和法對任何形狀都是 $O(n)$。

## 常見錯誤與邊界條件

- 漏寫 `pop_back()`，或在提前 `return` 前漏 pop，導致路徑累積而答案錯亂。
- 把 `path` 按值傳遞（此時不必 pop，但複雜度退化成 $O(nh)$，且與教學骨架不一致）。
- 記錄答案時存的是引用而非副本，最後全部指向同一個已被清空的容器。
- 437 忘記 `cnt[0] = 1` 而漏掉從根開始的路徑。
- 437 用 `int` 存前綴和而溢位。
- 葉節點判定寫成 `!node`（會讓單邊節點被誤判為葉，且同一條路徑被記錄兩次）。
- 空樹。
- `rest == 0` 但節點不是葉時誤記錄。

## 與相似技巧的比較

- 與 2.2 自頂向下相比：純量摘要按值傳遞、天然隔離、不需撤銷；只有當狀態是**共享的可變結構**時才需要回溯。判斷標準就這一條。
- 與 4.x 的組合／排列回溯相比，樹上回溯的「選擇分支」由樹結構給定（就是左右子），而組合問題的分支要自己枚舉；撤銷的機制完全相同。
- 437 的前綴和加雜湊表撤銷，與陣列上「和為 K 的子陣列」（560）是同一招，差別只在陣列的前綴是線性的、樹的前綴是祖先鏈，因此需要 pop。
- 若只要「是否存在」一條合格路徑（112），不需要回溯，用 2.2 傳純量即可。

## 本節重點速查

- 三段式：進入 push、遞迴、離開 pop，每條返回路徑都要配對撤銷。
- 不變量是「函式返回時狀態已還原」，它保證兄弟子樹互不污染。
- 只有共享可變狀態才需要回溯，純量傳值不需要。
- 437 用前綴和計數表，撤銷機制相同，別忘 `cnt[0] = 1`。
