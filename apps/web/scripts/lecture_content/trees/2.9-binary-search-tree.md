## 這個技術解決什麼問題

二元搜尋樹（BST）用結構把「有序」編碼進樹裡：**左子樹全部小於根，右子樹全部大於根**（對整棵子樹成立，不只對直接子節點）。於是查找、插入、刪除都能沿著一條路徑完成，$O(h)$ 而非 $O(n)$。

本節處理的是「利用 BST 性質」的題型：驗證是否為 BST（98）、找第 $k$ 小（230）、修復被交換的兩個節點（99）、找最接近的值（270）。它們的共同槓桿是同一條性質的兩種等價表述——**遞迴的區間約束**，與**中序遍歷遞增**。選對表述，題目就化簡了。

## 狀態／資料結構定義

兩種表述各自對應一組狀態：

**區間約束法**（適合 98、255）：`dfs(node, lo, hi)`，語意是「以 `node` 為根的子樹，所有值必須嚴格落在開區間 $(lo, hi)$ 內」。往左走時上界收緊為 `node->val`，往右走時下界收緊為 `node->val`。根的初始區間是 $(-\infty, +\infty)$，用 `long long` 的極值或 `optional` 表示，**不能用 `INT_MIN`／`INT_MAX`**，因為節點值本身可能等於它們。

**中序遞增法**（適合 98、230、99）：只需一個變數 `prev`，記錄中序序列中前一個訪問到的節點（初始為空）。訪問到 `node` 時檢查 `prev->val < node->val`。230 則再加一個計數器。

## 不變量或正確性證明

**兩種表述的等價性。** BST 定義（每棵子樹的左邊全小於根、右邊全大於根）等價於「中序遍歷嚴格遞增」。

（⟹）由 2.1 已證：中序輸出「左子樹、根、右子樹」，由歸納左右各自遞增，又左子樹全小於根、根小於右子樹全部，故串接後嚴格遞增。

（⟸）反之，設中序嚴格遞增。對任一節點 $v$，其左子樹的節點在中序中全部排在 $v$ 之前，故全部小於 $v$；右子樹全部排在之後，故全部大於 $v$。這對每個 $v$ 成立，即 BST 定義。

這個等價性是本節的核心工具：**看到「BST」就可以自由切換成「一個遞增序列」來思考**。230（第 $k$ 小）在序列觀點下就是「取第 $k$ 個」，中序走到第 $k$ 個即可停止，根本不需要想樹。

**98 的常見錯誤與區間約束的必要性。** 只檢查 `node->left->val < node->val < node->right->val` 是不夠的——這只保證了直接子節點的關係。反例：根為 5，左子為 1，左子的右子為 6。每一對父子關係都成立，但 6 在根的左子樹中卻大於 5，不是 BST。區間約束法正是為了修這個漏洞：**約束必須從所有祖先繼承下來，而非只看父親**。不變量表述為：呼叫 `dfs(v, lo, hi)` 時，$(lo, hi)$ 恰是 $v$ 的所有祖先施加的約束之交集。歸納保持：往左遞迴時新上界是 `v->val`（因為左子樹必須小於 $v$），與繼承的 `lo` 合起來就是子節點的完整約束。

**99（修復兩個被交換的節點）的正確性。** 對正確的 BST 做中序遍歷得嚴格遞增序列；交換其中兩個元素後，序列中出現「逆序對」。關鍵論證是：

- 若被交換的兩個位置**不相鄰**，恰好產生兩處相鄰逆序（`prev > cur`）。第一處的 `prev` 是第一個錯位元素，第二處的 `cur` 是第二個錯位元素。
- 若**相鄰**，只產生一處逆序，此時第一個錯位是該處的 `prev`、第二個是該處的 `cur`。

因此演算法是：中序掃描，第一次遇到 `prev > cur` 時記下 `first = prev` 與 `second = cur`；之後每次再遇到就更新 `second = cur`。最後交換 `first` 與 `second` 的值。這個「第一次記兩個、之後只更新第二個」的寫法同時涵蓋了相鄰與不相鄰兩種情形——**這正是它為什麼長成那樣，不是隨手寫的**。

**230 的提前終止**：中序訪問到第 $k$ 個時即可回傳，不必走完，故實際成本是 $O(h + k)$。若題目允許預處理且會多次查詢，改在每個節點存「子樹大小」，查詢降到 $O(h)$。

## C++17 模板

```cpp
// 驗證 BST（LeetCode 98）：區間約束法，約束從所有祖先繼承。
bool isValidBST(TreeNode* node, long long lo = LLONG_MIN,
                long long hi = LLONG_MAX) {
    if (!node) {
        return true;
    }
    if (node->val <= lo || node->val >= hi) {
        return false;
    }  // 嚴格開區間
    return isValidBST(node->left, lo, node->val)       // 往左收緊上界
           && isValidBST(node->right, node->val, hi);  // 往右收緊下界
}
```

中序法（同時可用於 230、99）：

```cpp
// 第 k 小（LeetCode 230）：中序走到第 k 個就停。
class Solution {
    int cnt_ = 0, ans_ = 0;
    void dfs(TreeNode* node, int k) {
        if (!node || cnt_ >= k) {
            return;
        }
        dfs(node->left, k);
        if (++cnt_ == k) {
            ans_ = node->val;
            return;
        }
        dfs(node->right, k);
    }

public:
    int kthSmallest(TreeNode* root, int k) {
        dfs(root, k);
        return ans_;
    }
};
```

## 時間與空間複雜度

98、99：需檢查每個節點，$O(n)$ 時間、$O(h)$ 空間。

230：$O(h + k)$ 時間（走到第 $k$ 個即停），$O(h)$ 空間。若預先在節點存子樹大小，單次查詢 $O(h)$，但插入刪除時要維護大小。

270（最接近的值）：沿著比較結果單向下降，$O(h)$ 時間、$O(1)$ 空間（迭代版）。

所有 $O(h)$ 在平衡時是 $O(\log n)$、退化成鏈時是 $O(n)$——**BST 的所有優勢都建立在「樹是平衡的」這個前提上**，這也是實務上要用紅黑樹或 AVL 的原因。單純的 BST 若按有序資料依序插入會退化成鏈。

## 常見錯誤與邊界條件

- 98 只比較直接父子而漏掉跨層違規（上文反例）。
- 區間邊界用 `INT_MIN`／`INT_MAX` 而節點值恰好等於它們（用 `long long` 或 `optional`）。
- 比較用 `<=` 或 `>=` 與題目對重複值的約定不符（多數題目要求嚴格遞增，不允許重複）。
- 99 只記錄一處逆序而漏掉相鄰交換的情形。
- 230 忘記提前終止導致大樹超時。
- 中序法的 `prev` 宣告成區域變數而非跨遞迴共享。
- 空樹（通常視為合法 BST）。

## 與相似技巧的比較

- 區間約束法與中序法都能解 98；前者是自頂向下傳約束（2.2 的模式），後者是「有遞有歸」共享一個 `prev`（2.5 的模式）。中序法對 99、230 更自然，區間法對 255（驗證前序序列）更自然。
- BST 的 LCA（235，見 2.8）同樣靠值的大小關係下降，$O(h)$，比一般二元樹的 $O(n)$ 快。
- 需要動態插入刪除並保持平衡時，競賽用 `std::set`／`std::map`（紅黑樹）或平衡樹模板；LeetCode 的 BST 題通常不要求自己實作平衡。
- 「BST 中序即有序陣列」這條對應關係反過來也有用：108 題由有序陣列建平衡 BST（見 2.10），就是把中序序列切成「中點當根、左右遞迴」。

## 本節重點速查

- BST 的兩種等價表述：**遞迴區間約束**與**中序嚴格遞增**，選好用的那個。
- 98 必須用從祖先繼承的區間（只比父子會漏），邊界用 `long long`。
- 230 中序走 $k$ 步即停。
- 99 靠「第一次記兩個、之後只更新第二個」同時涵蓋相鄰與不相鄰交換。
- 所有 $O(h)$ 保證都依賴樹是平衡的。
