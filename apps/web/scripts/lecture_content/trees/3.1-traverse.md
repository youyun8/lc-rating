## 這個技術解決什麼問題

一般樹的輸入通常不是節點指標，而是**邊的集合**（`edges[i] = {u, v}`）或**父節點陣列**（`parent[i]`）。這帶來兩個二元樹沒有的問題：邊是無向的，所以從 $u$ 走到 $v$ 之後，$v$ 的鄰居裡還有 $u$；如果不擋住，DFS 會在兩個節點之間來回震盪，永不終止。

本節建立一般樹的基本工作方式：**建鄰接表 + DFS 時傳入父節點以避免回頭**。這是 3.x 所有內容的地基，也是與 2.x 的主要介面差異。

## 狀態／資料結構定義

- `vector<vector<int>> g(n)`：鄰接表。無向邊要**雙向加入**：`g[u].push_back(v); g[v].push_back(u);`
- `dfs(u, fa)`：`u` 是當前節點，`fa` 是它的父節點（根的父節點用 $-1$ 表示，因為節點編號從 0 起算）。迴圈中 `if (v == fa) continue;` 就是防止回頭的全部機制。
- 若題目未指定根，任選一個節點（通常是 0）當根即可——樹的許多性質（節點數、邊數、直徑）與選誰當根無關，但「子樹」「深度」「祖先」這些概念會隨根改變，所以題目要求這些量時必須用指定的根。
- 父節點陣列 `parent[i]` 的輸入（1466、2368）可直接建有向鄰接表，此時不需要 `fa` 參數。

## 不變量或正確性證明

**為何 `v == fa` 就足以防止重複訪問。** 在一般圖上，DFS 必須用 `visited` 陣列；但在**樹**上，只要擋住父節點就夠了。理由是樹的定義性質：任兩節點之間恰有一條簡單路徑，等價地，樹中無環。

嚴格論證：假設 DFS 從根出發，遞迴到 $u$ 且來自 $fa$。若某個鄰居 $v \ne fa$ 已經被訪問過，則存在一條從 $v$ 到 $u$ 的路徑（沿著 DFS 的呼叫鏈），再加上邊 $(u, v)$ 就構成一個環。這與樹無環矛盾。故 $u$ 的所有非父鄰居都尚未被訪問，`v == fa` 這一個判斷就涵蓋了全部重複情形。

**這條論證的前提是輸入真的是樹**——$n$ 個節點、$n-1$ 條邊、且連通。若題目給的其實是有環的圖，或給了重邊（同一對節點之間兩條邊），`v == fa` 就不夠了：重邊的情形下，第二條 $u$–$fa$ 邊會通過檢查，造成無限遞迴。此時必須改用 `visited` 陣列，或用邊的編號而非節點編號來判斷「來時路」。**看到「保證是樹」才能用 `fa` 判斷，這不是可以省略的細節。**

**每個節點恰訪問一次。** 由上，DFS 從根出發能訪問到所有節點（連通性保證），且每個節點只被其唯一的父節點訪問一次（樹中除根外每個節點恰有一個父節點）。故總訪問次數為 $n$。

**兩種時機**與 2.1 相同：進入 `u` 時手上有「根到 `u` 的路徑」資訊（前序，見 3.2），離開時手上有「`u` 的子樹」彙總（後序，見 3.3）。一般樹沒有中序的概念——子節點順序沒有「左右」的語意區分，就算有多個子節點也無法定義根該插在哪裡。

## C++17 模板

```cpp
// 一般樹的基本 DFS：建鄰接表，用 fa 擋住回頭路。
class Solution {
    std::vector<std::vector<int>> g_;

    void dfs(int u, int fa) {
        // 進入 u：此時「根到 u 的路徑」資訊已備妥（前序時機）
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }  // 唯一需要的防重複機制（前提：輸入是樹）
            dfs(v, u);
        }
        // 離開 u：此時所有子樹的彙總已備妥（後序時機）
    }

public:
    void solve(int n, const std::vector<std::vector<int>>& edges) {
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back(e[1]);  // 無向邊必須雙向加入
            g_[e[1]].push_back(e[0]);
        }
        dfs(0, -1);  // 任選 0 當根；根的父節點記為 -1
    }
};
```

節點數較大（$n$ 上看 $10^5$）時遞迴深度可能達 $n$，斜樹會爆堆疊。改成顯式堆疊的迭代版，或在支援的環境下加大堆疊。

## 時間與空間複雜度

建圖 $O(n)$（$n-1$ 條邊各加入兩次）。DFS 中，對 `g[u]` 的迴圈總共執行 $\sum_u \deg(u) = 2(n-1)$ 次，故遍歷是 $O(n)$ 時間——**不是 $O(n \cdot \text{maxdeg})$**，理由與 2.15 相同：所有度數之和等於邊數的兩倍。

空間：鄰接表 $O(n)$，遞迴堆疊 $O(h)$，最壞 $O(n)$（鏈狀樹）。

用 `unordered_map` 存鄰接表會慢很多且沒必要——節點編號通常是 $0$ 到 $n-1$ 的連續整數，直接用 `vector` 索引。

## 常見錯誤與邊界條件

- 無向邊只加一個方向，導致樹被切斷、DFS 只走到部分節點。
- 忘記傳 `fa` 或忘記 `v == fa` 的檢查，無限遞迴至爆堆疊。
- 根的 `fa` 用 0 而非 $-1$（若根恰為 0 號節點，會誤擋掉真正的鄰居 0）。
- 輸入其實是圖或含重邊時仍只用 `fa` 判斷。
- $n = 1$（沒有邊，鄰接表全空）。
- 節點編號從 1 起算而陣列開 $n$ 大小。
- 深度大時爆堆疊。

## 與相似技巧的比較

- 與 2.15 的 N 叉樹相比：N 叉樹的 `children` 已經是有向的父到子關係，不會走回頭，所以不需要 `fa`。**輸入形式決定要不要傳 `fa`**，這是兩者唯一的實質差異。
- 與圖的 DFS（graph 主題）相比：圖需要 `visited` 陣列，因為可能有環且節點可從多條路徑到達。樹省下這個是因為無環性質，如上所證。
- 父節點陣列輸入（1466）可直接建立有向邊，此時問題往往退化成「沿著父指標往上走」或「按拓撲序處理」，見 3.6。
- BFS 在一般樹上同樣可用，防重複機制相同（擋住父節點），適合求「層」與「距離」，見 3.5 的兩次 BFS 求直徑。

## 本節重點速查

- 一般樹的輸入是邊集合，先建**雙向**鄰接表。
- DFS 傳 `dfs(u, fa)`，用 `v == fa` 擋回頭——這在樹上（無環、無重邊）就足夠，在圖上不夠。
- 根的 `fa` 用 $-1$。
- 遍歷 $O(n)$，因為度數總和是 $2(n-1)$。
- 沒有中序的概念，只有進入與離開兩個時機。
