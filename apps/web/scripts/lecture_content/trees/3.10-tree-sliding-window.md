## 這個技術解決什麼問題

陣列上的滑動視窗解決「最長／最短的連續子陣列滿足某條件」。樹上的對應問題是「最長的**由上往下路徑**滿足某條件」——例如路徑上顏色不重複（3425）、最多允許一種顏色重複（3486）。

暴力枚舉每對祖先-後代再驗證是 $O(n^2)$ 或更差。樹上滑動視窗的槓桿是：**DFS 進行時，「根到當前節點」的那條鏈天然就是一個右端不斷擴張的視窗**，只要把陣列版的「左指標」改成「深度下界」，整套增量更新原封不動搬過來，一次 DFS $O(n)$。

## 狀態／資料結構定義

以 3425（最長特殊路徑：路徑上顏色互異）為例。

- `dis[d]`：根到深度 $d$ 的節點的路徑權重前綴和（用一個隨 DFS 增減的堆疊陣列維護）。有了它，視窗 $[\text{top}, \text{dep}(u)]$ 的長度就是 $\text{dis}[\text{dep}(u)] - \text{dis}[\text{top}]$。
- `lastDepth[c]`：**當前這條鏈上**顏色 $c$ 最近一次出現的深度；不存在記 $-1$。這是全域結構，回溯時必須還原。
- `top`：視窗的深度下界，意義是「合法路徑的最淺端點所在深度」。它**以參數形式往下傳**，不是全域變數。
- 進入 $u$ 時：`saved = lastDepth[color[u]]`，`top = max(parentTop, saved + 1)`，`lastDepth[color[u]] = dep[u]`。
- 離開 $u$ 前：`lastDepth[color[u]] = saved`。

`top` 傳參、`lastDepth` 全域加還原——這個分工是本節的實作核心，兩者混淆就會錯。

## 不變量或正確性證明

**不變量一（`lastDepth` 的意義）：在處理節點 $u$ 的期間，對每個顏色 $c$，`lastDepth[c]` 等於「根到 $u$ 這條鏈上顏色 $c$ 最深的出現位置」（不存在則為 $-1$）。**

由結構歸納。進入 $u$ 時把 `lastDepth[color[u]]` 更新為 $\mathrm{dep}(u)$，而 $u$ 是鏈上最深的節點，故成立；其他顏色不受影響。離開 $u$ 前還原成進入時的值，於是父節點的視角恢復原狀，兄弟子樹看到的是「不含 $u$ 的鏈」。**還原這一步不是清理習慣，是不變量的一部分**——少了它，兄弟子樹會誤以為 $u$ 的顏色在自己的鏈上出現過。

**不變量二（`top` 的意義）：`top` 是使區間 $[\text{top}, \mathrm{dep}(u)]$ 對應的鏈段顏色互異的最小深度。**

- 初始化：根節點，$\text{top} = 0$（單點必然互異）。
- 保持：設父節點 $p$ 的下界為 $\text{ptop}$，即 $[\text{ptop}, \mathrm{dep}(p)]$ 互異且 $\text{ptop}$ 最小。加入 $u$ 後，新的衝突**只可能來自 $u$ 自己的顏色**（其他顏色的互異性沒被改動）。設該顏色在鏈上前一次出現於深度 $s = \text{saved}$：
  - 若 $s < \text{ptop}$，那次出現已在視窗外，無新衝突，下界仍為 $\text{ptop}$。
  - 若 $s \ge \text{ptop}$，必須把下界推到 $s + 1$ 才能排除它。
  - 兩者合起來就是 $\text{top} = \max(\text{ptop}, s+1)$，且這是**最小**的可行值（再小一格就會含入某個衝突）。

這裡有一個容易被忽略的前提：**只需檢查「最近一次出現」就夠了**。因為若顏色 $c$ 在深度 $s' < s$ 也出現過，把下界推到 $s+1$ 之後 $s'$ 自動被排除；反之若只推到 $s'+1$，深度 $s$ 的那次仍在視窗內。故「最近」是唯一需要記錄的資訊，`lastDepth` 只存一個值就夠。

**不變量三（單調性，也是「滑動視窗」三個字的來源）：沿著任一條根到葉的鏈往下走，`top` 單調不減。**

由 $\text{top} = \max(\text{ptop}, s+1) \ge \text{ptop}$ 直接得到。這正是陣列版滑動視窗中「左指標只右移不左移」的樹上對應，也是總複雜度 $O(n)$ 的來源：下界在每條鏈上只往下移，不回頭。

**注意單調性只沿著「一條鏈」成立，不是全域成立。** 兄弟子樹的 `top` 各自從父節點的值出發，彼此獨立。這正是為什麼 `top` 必須用參數傳遞——若寫成全域變數並在回溯時忘記還原，第二棵子樹會繼承第一棵子樹壓下去的界線，答案偏小。

**答案的完整性。** 對每個節點 $u$，$[\text{top}, \mathrm{dep}(u)]$ 是以 $u$ 為下端點的最長合法路徑。每條合法向下路徑都有唯一的下端點，故枚舉所有 $u$ 不重不漏。

## C++17 模板

```cpp
// 最長特殊路徑（LeetCode 3425）：樹上滑動視窗，一次 DFS O(n)。
class Solution {
    std::vector<std::vector<std::pair<int, int>>> g_;  // {鄰居, 邊權}
    std::vector<int> color_, lastDepth_;  // lastDepth_: 顏色 -> 鏈上最深出現
    std::vector<long long> dis_;  // dis_[d]: 根到深度 d 的前綴和
    long long bestLen_ = 0;
    int bestNodes_ = 0;

    void dfs(int u, int fa, int d, int top) {  // top 以參數傳遞，不是全域
        int saved = lastDepth_[color_[u]];  // 記下進入前的值
        top = std::max(top, saved + 1);     // 只需管最近一次出現
        lastDepth_[color_[u]] = d;          // 更新為當前深度

        long long len = dis_[d] - dis_[top];  // 視窗 [top, d] 的長度
        int nodes = d - top + 1;
        if (len > bestLen_ || (len == bestLen_ && nodes < bestNodes_)) {
            bestLen_ = len;
            bestNodes_ = nodes;
        }

        for (auto [v, w] : g_[u]) {
            if (v == fa) {
                continue;
            }
            dis_[d + 1] = dis_[d] + w;  // 前綴和往下延伸
            dfs(v, u, d + 1, top);      // 兄弟各自從同一個 top 出發
        }

        lastDepth_[color_[u]] = saved;  // 回溯：還原，否則污染兄弟
    }

public:
    std::vector<int> longestSpecialPath(
        const std::vector<std::vector<int>>& edges,
        const std::vector<int>& nums) {
        int n = nums.size();
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back({e[1], e[2]});
            g_[e[1]].push_back({e[0], e[2]});
        }
        color_ = nums;
        lastDepth_.assign(*std::max_element(nums.begin(), nums.end()) + 1, -1);
        dis_.assign(n + 1, 0);
        bestNodes_ = 1;
        dfs(0, -1, 0, 0);
        return {static_cast<int>(bestLen_), bestNodes_};
    }
};
```

## 時間與空間複雜度

每個節點進入、離開各一次，每次做 $O(1)$ 的更新與還原（顏色用陣列索引；若值域大則離散化或用雜湊表，後者是 $O(1)$ 期望）。總計 $O(n)$ 時間。

空間：鄰接表 $O(n)$、`dis` $O(n)$、`lastDepth` $O(值域)$、遞迴堆疊 $O(h)$。

相對於「枚舉每對祖先-後代」的 $O(n^2)$，收穫全部來自不變量三的單調性——下界不回頭，所以不需要對每個上端點重算。

3486（最多允許一種顏色重複）把 `top` 換成「維護最近兩次出現」的版本，複雜度不變，仍是 $O(n)$。

## 常見錯誤與邊界條件

- 回溯時忘記還原 `lastDepth`（最常見，兄弟子樹被污染，答案偏小）。
- 把 `top` 寫成全域變數並在回溯時未還原（同樣污染，但更隱蔽，因為單條鏈上測試會過）。
- 還原時寫成 `lastDepth[color[u]] = -1` 而非進入前的 `saved`（祖先鏈上同色的資訊被抹掉）。
- `dis` 陣列用 `d` 索引但忘記在遞迴前寫入 `dis[d+1]`。
- 視窗長度算成 `dis[d] - dis[top-1]`（下界的定義是「合法端點所在深度」，前綴和要取 `dis[top]`）。
- 節點數與權重和混淆（3425 要求權重和最大、節點數最少，兩個都要更新）。
- 顏色值域大時未離散化導致 `lastDepth` 開不下。
- 單點路徑是否合法要看題目定義。

## 與相似技巧的比較

- 與陣列滑動視窗：條件判定、`left = max(left, last[c] + 1)` 的更新式完全一樣。唯一的差別是**視窗沿著 DFS 的鏈移動，因此需要回溯還原**——陣列版沒有分岔，不需要。
- 與 2.7 的回溯：還原的機制相同（進入時記錄、離開時復原），本節可視為回溯技巧與滑動視窗的合成。
- 與 3.2 的自頂向下 DFS：`top` 走的是自頂向下的傳遞路線（路徑資訊），`lastDepth` 則是需要撤銷的全域狀態。3.2 提到的「純量傳值不用撤銷、容器全域要撤銷」在這裡體現得最清楚。
- 與 3.11 的 DSU on tree：後者也維護一個全域計數器並要求清乾淨，但它處理的是**子樹**統計，本節處理的是**鏈**上的視窗，適用場景不重疊。
- 本節只能處理「由上往下」的路徑。若路徑可以在某節點分叉（經過 LCA 的一般路徑），視窗性質不成立，要改用 2.6／3.5 的枚舉最高點，或 3.12 的點分治。

## 本節重點速查

- 視窗 = 根到當前節點的鏈。
- `top = max(parentTop, lastDepth[color[u]] + 1)`，**只需看最近一次出現**。
- 三個不變量：`lastDepth` 描述當前鏈、`top` 是最小合法下界、`top` 沿鏈單調不減（$O(n)$ 的來源）。
- **`top` 傳參、`lastDepth` 全域且回溯必須還原**。
- 只適用「由上往下」的路徑，會分叉的路徑要改用枚舉最高點或點分治。
