## 這個技術解決什麼問題

一類題目要對**每一棵子樹**各給一個答案，而答案由子樹內元素的統計量決定（有幾種顏色？眾數是誰？缺失的最小值是多少？）。對每個節點各掃一次它的子樹是 $O(n^2)$。

樹上啟發式合併（DSU on tree，small-to-large）的槓桿是：**保留最大子樹的統計結果，只把較小的子樹搬進來。** 搬動總量從 $O(n^2)$ 降到 $O(n \log n)$，而且不需要任何高深的資料結構——只要一個全域計數器與 add／remove 兩個函式。

## 狀態／資料結構定義

- `sz[u]`：$u$ 的子樹大小；`big[u]`：$u$ 的**重兒子**，即子樹最大的那個子節點（無子節點時記 $-1$）。由第一次 DFS 求出。
- 全域統計結構，例如 `cnt[value]` 加上若干輔助量（不同值的個數、當前眾數等）。它描述的是**「目前已加入集合」的元素多重集**，而不是任何特定子樹——這點要想清楚，否則會弄不懂何時該清空。
- `add(u)` / `remove(u)`：把單一節點的貢獻加入／移出全域統計。
- `addSubtree(v)` / `removeSubtree(v)`：對子樹 $v$ 的每個節點呼叫 `add` / `remove`。
- `query()`：從全域統計讀出答案。
- 主遞迴 `dfs(u, fa, keep)`：`keep` 表示「回傳時是否保留 $u$ 子樹的貢獻在全域統計中」。

**輕邊**指 $u \to v$ 且 $v \ne \text{big}[u]$；**重邊**指 $u \to \text{big}[u]$。

## 不變量或正確性證明

**不變量（呼叫契約）：`dfs(u, fa, keep)` 被呼叫時，全域統計為空（不含 $u$ 子樹外的任何節點，也不含 $u$ 子樹內的節點）；回傳時，若 `keep == true` 則統計恰為 $u$ 的整棵子樹，若 `keep == false` 則統計恢復為空。**

先確認遞迴體維持了這個契約：

1. 對每個輕兒子 $v$ 呼叫 `dfs(v, u, false)`。由歸納假設，每次呼叫前後統計都是空的。
2. 對重兒子呼叫 `dfs(big[u], u, true)`。回傳後統計恰為重兒子的整棵子樹。
3. `add(u)`，再對每個輕兒子 $v$ 執行 `addSubtree(v)`。此時統計 = 重兒子子樹 ∪ $\{u\}$ ∪ 所有輕兒子子樹 = **$u$ 的整棵子樹**，不多不少（子樹的劃分不重不漏）。
4. `ans[u] = query()`。契約中「統計恰為 $u$ 子樹」正是 `query()` 能給出正確答案的前提。
5. 若 `keep == false`，把整棵 $u$ 子樹移除，統計歸空。

歸納成立。**注意步驟 1 的「呼叫前統計為空」依賴步驟 2 尚未執行**——這就是為什麼**輕兒子必須先遞迴、重兒子必須最後遞迴**。若順序反過來，遞迴輕兒子時全域統計裡還留著重兒子的資料，`query()` 會讀到別人的東西。這不是效率問題，是正確性問題。

**複雜度的攤還論證。** 成本集中在 `addSubtree` / `removeSubtree`，也就是「節點 $x$ 被逐點搬動」的總次數。

節點 $x$ 在處理祖先 $u$ 時被搬動，當且僅當 $x$ 位於 $u$ 的某個**輕兒子**的子樹中。也就是說：

$$x \text{ 被搬動的次數} = \text{根到 } x \text{ 的路徑上輕邊的條數}.$$

現在證明這個數不超過 $\log_2 n$。設 $p \to v$ 是一條輕邊，$h = \text{big}[p]$ 是重兒子。由重兒子的定義 $\text{sz}[h] \ge \text{sz}[v]$，於是
$$\text{sz}[p] \ge 1 + \text{sz}[h] + \text{sz}[v] \ge 1 + 2\,\text{sz}[v] > 2\,\text{sz}[v].$$
即**每往上跨過一條輕邊，子樹大小至少翻倍**。從 $x$（大小 $\ge 1$）往上到根（大小 $n$），翻倍最多 $\log_2 n$ 次，故輕邊不超過 $\log_2 n$ 條。

因此總搬動次數 $\le n \log_2 n$，每次 $O(1)$（假設 add/remove 是 $O(1)$），總計 $O(n \log n)$。

**這個論證點名的前提有兩個，換題時要各自檢查：**

1. **`add` 與 `remove` 必須是 $O(1)$（或至少常數小）。** 若 `add` 內部帶了一個 $O(\log n)$ 的資料結構操作，總複雜度變成 $O(n \log^2 n)$——通常仍可接受，但要算清楚。
2. **統計量必須可逆（能 `remove`）。** 「有幾種不同顏色」可逆（計數歸零時遞減種類數）；「歷史上出現過的最大值」不可逆。不可逆的統計量無法用本節的框架，得改用別的方法（例如 2003 的「缺失最小基因值」就不走通用 DSU on tree，而是用「只有一條鏈上的節點答案非 1」這條性質特判）。

**為何 `keep` 這個參數不能省。** 它的作用是把「清空成本」推給呼叫者中真正需要清空的那一方。重兒子回傳時不清（省下的正是這 $O(n \log n)$ 與 $O(n^2)$ 的差距），輕兒子回傳時清（維持契約）。把 `keep` 恆設為 `true` 會導致統計被污染；恆設為 `false` 則退化成暴力 $O(n^2)$。

## C++17 模板

```cpp
// DSU on tree：對每棵子樹各求一個答案，O(n log n)。
class DsuOnTree {
    std::vector<std::vector<int>> g_;
    std::vector<int> sz_, big_, val_, ans_;
    std::vector<int> cnt_;  // 全域統計：目前已加入集合的元素分佈
    int distinct_ = 0;      // 輔助量：不同值的個數

    void dfsSize(int u, int fa) {
        sz_[u] = 1;
        big_[u] = -1;
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            dfsSize(v, u);
            sz_[u] += sz_[v];
            if (big_[u] == -1 || sz_[v] > sz_[big_[u]]) {
                big_[u] = v;
            }
        }
    }

    void add(int u) {
        if (cnt_[val_[u]]++ == 0) {
            ++distinct_;
        }
    }
    void remove(int u) {
        if (--cnt_[val_[u]] == 0) {
            --distinct_;
        }
    }

    void addSubtree(int u, int fa) {  // 輕兒子只能逐點搬，沒有快取待遇
        add(u);
        for (int v : g_[u]) {
            if (v != fa) {
                addSubtree(v, u);
            }
        }
    }

    void removeSubtree(int u, int fa) {
        remove(u);
        for (int v : g_[u]) {
            if (v != fa) {
                removeSubtree(v, u);
            }
        }
    }

    void dfs(int u, int fa, bool keep) {
        for (int v : g_[u]) {  // 1. 輕兒子先做，做完清空
            if (v != fa && v != big_[u]) {
                dfs(v, u, false);
            }
        }
        if (big_[u] != -1) {
            dfs(big_[u], u, true);
        }  // 2. 重兒子最後做，保留

        add(u);                // 3. 補上自己
        for (int v : g_[u]) {  //    與所有輕兒子子樹
            if (v != fa && v != big_[u]) {
                addSubtree(v, u);
            }
        }

        ans_[u] = distinct_;  // 4. 此刻統計恰為 u 的整棵子樹

        if (!keep) {
            removeSubtree(u, fa);
        }  // 5. 契約：不保留就清乾淨
    }

public:
    std::vector<int> solve(int n, const std::vector<std::vector<int>>& edges,
                           const std::vector<int>& val, int maxVal) {
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back(e[1]);
            g_[e[1]].push_back(e[0]);
        }
        val_ = val;
        sz_.assign(n, 0);
        big_.assign(n, -1);
        ans_.assign(n, 0);
        cnt_.assign(maxVal + 1, 0);
        dfsSize(0, -1);
        dfs(0, -1, true);
        return ans_;
    }
};
```

## 時間與空間複雜度

第一次 DFS：$O(n)$。

主遞迴：每個節點被 `add`/`remove` 的次數 = 其到根路徑上的輕邊數 $+\,O(1)$，總計 $O(n \log n)$ 次，每次 $O(1)$，故 $O(n \log n)$。

空間：鄰接表與各陣列 $O(n)$，全域計數器 $O(值域)$，遞迴堆疊 $O(h)$。

與其他做法比較：用 3.7 的 dfn 把子樹轉成區間、再離線用莫隊是 $O(n\sqrt n)$，通常更慢；用可合併的資料結構（線段樹合併）也是 $O(n \log n)$，但空間常數大、實作長。**DSU on tree 的優勢是實作短、常數小，代價是統計量必須可逆。**

## 常見錯誤與邊界條件

- 重兒子先遞迴、輕兒子後遞迴（違反契約，`query()` 讀到重兒子殘留的資料）。
- `keep == false` 時清空不徹底（只 `remove(u)` 而沒清子樹，或漏掉重兒子），導致兄弟之間互相污染。
- 把 `addSubtree` 用在重兒子上（複雜度退化成 $O(n^2)$，答案仍對，只是慢）。
- `big[u]` 在葉節點時未初始化為 $-1$，被當成節點 0。
- 統計量不可逆卻硬套（`remove` 寫不出正確的反向操作）。
- `cnt` 陣列開的大小小於值域。
- 根呼叫時 `keep` 給 `false`（會白白多清一次，不影響正確性但浪費）。
- 深度大時遞迴爆堆疊。
- $n = 1$。

## 與相似技巧的比較

- 與 3.3 的自底向上 DFS：3.3 要求合併是 $O(1)$ 的（回傳一個純量）。**當合併需要整個集合（而非摘要）時就落到本節**——3.3 那節提過的「合併不是 $O(1)$ 時複雜度必須重算」，答案就在這裡。
- 與線段樹合併：兩者都是 $O(n \log n)$ 解同一類問題。線段樹合併支援「查詢子樹內第 $k$ 大」這類需要有序結構的問題，且統計量不必可逆；DSU on tree 實作短得多。先試 DSU on tree。
- 與 3.9 的虛樹：虛樹適用「只有少數點被關心」，DSU on tree 適用「每個點都要答案」。判準是**答案的個數**。
- 與一般的 small-to-large（例如用 `set` 啟發式合併，每次 `swap` 大小容器）：那是同一條攤還論證的另一種實作，複雜度也是 $O(n \log n)$（或帶 `set` 的 $O(n \log^2 n)$）。DSU on tree 用「重兒子不搬」取代「容器 swap」，省下了容器本身的開銷。
- 3575、3590 這類題的難點通常不在框架，而在設計出一個**可逆且 $O(1)$** 的統計量。

## 本節重點速查

- **輕兒子先做並清空、重兒子最後做並保留**，然後 `add(u)` 加所有輕子樹，此刻全域統計恰為 $u$ 的子樹。
- 攤還的核心：節點被搬動的次數 = 到根路徑上的輕邊數，而**每跨一條輕邊子樹至少翻倍**，故不超過 $\log_2 n$，總計 $O(n \log n)$。
- 兩個前提：`add`/`remove` 要 $O(1)$，統計量必須**可逆**。
- `keep` 參數不能省。
