## 這個技術解決什麼問題

這一節收的是不屬於前面任何一個固定模板的樹題。它們沒有共同的名字，但有共同的**降本手法**：把「每次都要重算的東西」壓進「一次遍歷的回傳值」或「並查集合併的那一瞬間」。

兩種主要形態：

- **子樹摘要型**（2479）：定義一個可向上合併的回傳值，一次後序 DFS 就把所有子樹的資訊算完，避免對每個節點重掃子樹。
- **合併時計數型**（2421、2867）：把邊或節點**按某個順序**加入並查集，在兩團合併的那一刻，用兩團的大小相乘算出「這一步新增了多少條跨團路徑」。這樣把 $O(n^2)$ 條路徑的枚舉，攤成 $n-1$ 次合併。

## 狀態／資料結構定義

**合併時計數型**（以 2421 好路徑數目為例，`vals[u]` 是節點值）：

- 並查集 `fa[]`，附帶按大小合併與路徑壓縮。
- `cntMax[r]`：連通塊 $r$ 中，**值等於該塊最大值**的節點個數。這是本題唯一需要維護的額外量。
- 邊按 $\max(\text{vals}[a], \text{vals}[b])$ 遞增排序，逐條加入。

**子樹摘要型**：回傳值的型別就是狀態定義。可能是純量（最長鏈、子樹大小）、`pair`（最大與次大）、或整個容器（各顏色計數；此時要注意合併成本，見 3.11）。

## 不變量或正確性證明

**合併時計數型的不變量（2421）：處理完所有「$\max$ 值 $\le v$」的邊之後，並查集中每個連通塊恰好是「僅使用值 $\le v$ 的節點所能連通的極大集合」，且 `cntMax[r]` 是塊 $r$ 中值等於塊內最大值的節點數。**

- 初始化：每個節點自成一塊，`cntMax = 1`，塊內最大值就是自己的值。成立。
- 保持：加入一條 $\max = v$ 的邊 $(a,b)$ 時，$a$、$b$ 所在塊的最大值都 $\le v$。合併後新塊的最大值是 $v$。因此新的 `cntMax` 只該累計「原本最大值就等於 $v$」的那些塊的計數：若某塊最大值 $< v$，它的 `cntMax` 對新塊沒有貢獻（那些節點不是新塊的最大值）。

現在論證答案。**好路徑的定義是：兩端點值相等，且路徑上所有節點的值都不超過端點值。** 設端點值為 $v$。這等價於「兩端點都在『只用值 $\le v$ 的節點』所形成的同一個連通塊中，且兩端點的值都等於 $v$」——而由不變量，在處理完所有 $\max \le v$ 的邊之後，這樣的塊正是並查集中的塊，塊內值為 $v$ 的節點數就是 `cntMax`。

因此，在合併兩塊 $A$、$B$（兩者最大值皆為 $v$）時，新增的好路徑數恰為 $\text{cntMax}[A] \times \text{cntMax}[B]$：一端取自 $A$、一端取自 $B$，跨團配對。**同團內部的配對在更早的合併中已經算過，不會重複**——這是「按值排序後逐步合併」能不重不漏的關鍵。單點路徑（$a = b$）另計 $n$ 條。

**這條論證點名的前提：邊必須按 $\max(\text{vals}[a], \text{vals}[b])$ 排序。** 若按邊權或任意順序加入，塊就不再是「值 $\le v$ 的極大連通集合」，`cntMax` 的意義崩潰，乘法計數會把「路徑上有更大值」的非法路徑算進去。

**為何乘法計數對「跨團」成立而對「同團」不成立。** 兩團合併後，任取 $x \in A$、$y \in B$，$x$–$y$ 的路徑必定經過新加的邊，因此這些路徑在此之前**不存在於任何一個塊內**，都是新的。反之同團內的路徑早已存在。這個「新舊劃分」是不重不漏的，乘法原理才適用。

**子樹摘要型的不變量**就是 3.3 的後序歸納：`dfs(u)` 回傳的是「僅由 $u$ 子樹決定」的摘要。要檢查的兩點與 3.3 相同——摘要是否對父節點**足夠**（完整性），以及合併是否 $O(1)$（否則複雜度要重算，見 3.11）。

## C++17 模板

```cpp
// 好路徑的數目（LeetCode 2421）：按值排序 + 並查集合併時計數。
class Solution {
    std::vector<int> fa_, cntMax_;

    int find(int x) { return fa_[x] == x ? x : fa_[x] = find(fa_[x]); }

public:
    int numberOfGoodPaths(const std::vector<int>& vals,
                          const std::vector<std::vector<int>>& edges) {
        int n = vals.size();
        fa_.resize(n);
        std::iota(fa_.begin(), fa_.end(), 0);
        cntMax_.assign(n, 1);  // 每個點自成一塊，塊內最大值即自己

        std::vector<std::vector<int>> es(edges);
        std::sort(es.begin(), es.end(), [&](const auto& p, const auto& q) {
            return std::max(vals[p[0]], vals[p[1]]) <
                   std::max(vals[q[0]], vals[q[1]]);
        });  // 必須按 max(端點值) 遞增

        long long ans = n;  // 單點路徑
        for (const auto& e : es) {
            int x = find(e[0]), y = find(e[1]);
            // 路徑壓縮後代表元不一定是最大值節點，實作上通常把
            // 「塊內最大值」也存在代表元上；此處用 vals[代表元] 需保證
            int vx = vals[x], vy = vals[y];
            // 合併時把代表元設為最大值較大的那一方。
            if (vx == vy) {
                ans += 1LL * cntMax_[x] * cntMax_[y];  // 跨團配對
                fa_[y] = x;
                cntMax_[x] += cntMax_[y];
            } else if (vx > vy) {
                fa_[y] = x;  // 較小的塊最大值被吞併，cntMax_ 不變
            } else {
                fa_[x] = y;
            }
        }
        return static_cast<int>(ans);
    }
};
```

上面的寫法讓「代表元」始終是塊內值最大的節點之一，因此 `vals[find(u)]` 就是塊內最大值。這個約定必須貫徹：合併時一定把最大值較小的那一方掛到較大的那一方底下。

## 時間與空間複雜度

**2421 型**：排序 $O(n \log n)$ 主導；$n-1$ 次並查集操作在路徑壓縮下是 $O(n\,\alpha(n))$，可視為近線性。總計 $O(n \log n)$，空間 $O(n)$。

相對於「枚舉所有點對再驗證路徑」的 $O(n^3)$、或「對每個值各跑一次連通性」的 $O(n^2)$，收穫來自把「所有值的門檻」用一次排序串成單調過程，每條邊只被處理一次。

**子樹摘要型**：一次 DFS $O(n)$；若回傳值是容器且合併成本非 $O(1)$，必須把合併成本乘進去（例如逐一插入是 $O(n^2)$，改用 small-to-large 才是 $O(n \log n)$）。

遞迴深度：鏈狀樹上 $O(n)$，必要時改成顯式堆疊，或用 BFS 的反序當作後序。

## 常見錯誤與邊界條件

- 2421 型：邊沒有按 $\max(\text{端點值})$ 排序。
- `cntMax` 在最大值不等時被誤加（只有兩塊最大值相同才累加）。
- 忘記代表元必須是最大值較大的一方，導致 `vals[find(u)]` 取到錯誤的塊最大值。
- 答案用 `int` 溢位（$n = 3\times10^4$ 時 `cntMax` 相乘可達 $10^9$ 級）。
- 漏掉 $n$ 條單點路徑。
- 重複邊或自環未處理。

- 子樹摘要型：摘要不完整（父節點需要的資訊沒被回傳，見 2.12 的狀態完整性）。
- 合併成本被忽略導致複雜度誤判。
- 空子樹的單位元選錯（見 2.3）。
- 忘記 `v == fa`。
- 遞迴過深。

2867（合法路徑：路徑上恰有一個質數）則是另一種形態：把質數節點當作「分隔點」，先對非質數節點做並查集，再枚舉每個質數節點、用其各鄰接塊的大小做乘法計數——同樣是「合併時計數」的思路，只是分組的依據換成質數與否。

## 與相似技巧的比較

- 與 3.3：子樹摘要型就是 3.3，本節只是提醒「摘要要完整、合併成本要算」。
- 與 3.12 的點分治：兩者都在數路徑。點分治適用「路徑條件與距離／權重和有關」；並查集合併計數適用「路徑條件可以表達成**單調的門檻**」（值 $\le v$、只用某類節點），因為它依賴「按門檻遞增逐步加入」這個單調過程。**條件不單調就用不了並查集。**
- 與 graph 主題的 Kruskal 重構樹：2421 的做法本質上就是 Kruskal 重構樹的簡化版——按權排序合併、在合併時統計。若題目要支援查詢而非只求總數，就該真的建出重構樹。
- 與 3.11 的 DSU on tree：名字都有 DSU 但完全是兩回事。本節的並查集是真的並查集（維護連通性）；DSU on tree 只是借用了 small-to-large 的攤還思想，並不使用並查集結構。**不要混淆。**

## 本節重點速查

- 兩種降本手法：**子樹摘要**（一次後序把重算壓成回傳值）與**合併時計數**（把 $O(n^2)$ 條路徑攤成 $n-1$ 次合併，每次用兩團大小相乘）。
- 2421 的關鍵不變量是「處理完 $\max \le v$ 的邊後，塊 = 值 $\le v$ 的極大連通集合，`cntMax` = 塊內取到最大值的節點數」，而它**依賴邊按 $\max(\text{端點值})$ 排序**。
- 乘法只對「跨團」成立，同團的配對早已算過。
- 這裡的 DSU 與 3.11 的 DSU on tree 沒有關係。
