## 這個技術解決什麼問題

與 2.2 相同的需求，換到一般樹上：答案取決於**從根走到當前節點這條路徑**——深度、路徑上的權重和、路徑上的最大邊權、路徑上某種狀態的累積（1376 通知員工所需時間、1443 收集蘋果的最短時間中的一部分）。

單獨對每個節點沿父指標往上算一遍是 $O(nh)$；把路徑資訊當參數往下傳，每個節點只做常數工作，$O(n)$。

## 狀態／資料結構定義

- `dfs(u, fa, acc)`：`acc` 是根到 `u` 之父的累積量（或到 `u` 為止，兩種語意擇一並貫徹）。
- 常見的 `acc` 型別：深度 `int`、路徑和 `long long`（邊權相加容易溢位）、路徑上的最大值、位元遮罩（記錄路徑上出現過的字元集合）。
- 若邊帶權，鄰接表要存 `pair<int, int>`（鄰居, 邊權）或 `vector<array<int,2>>`。
- 答案通常存進全域陣列 `ans[u]`（每個節點各有一個答案）或單一全域變數（取全樹最值）。

## 不變量或正確性證明

不變量：**每次呼叫 `dfs(u, fa, acc)` 時，`acc` 恰等於根到 `u` 之父這條路徑所定義的累積量。**

- 初始化：`dfs(root, -1, e)`，$e$ 是空路徑的單位元。
- 保持：計算 `acc' = combine(acc, u)`（或含邊權 `combine(acc, w(fa,u))`），對每個非父鄰居 `v` 呼叫 `dfs(v, u, acc')`。對 `v` 而言根到其父（即 `u`）的累積量正是 `acc'`，不變量維持。
- 結論：每個節點拿到的參數都正確。

適用前提與 2.2 相同：**所需資訊必須是路徑的函數，不能依賴子樹**。此外一般樹多一層考量——由於子節點不只兩個，若 `acc` 是可變的共享容器，**每個子節點遞迴後都要撤銷**（回溯），不是只在最後撤銷一次。這比二元樹更容易寫錯，因為迴圈裡的 push/pop 配對不像兩行遞迴那樣顯眼。

**1376（通知所有員工所需時間）的正確性。** 每個員工 $u$ 收到通知的時刻等於根到 $u$ 路徑上所有上司的 `informTime` 之和。答案是所有葉節點時刻的最大值。這裡值得點名的是**為何只需看葉節點**：通知時間沿路徑單調不減（`informTime` 非負），故任一節點的時刻不超過其某個後代葉節點的時刻。因此取全體節點的最大值與只取葉節點的最大值相同，實作上兩種寫法都對。若 `informTime` 可為負，單調性失效，就必須取全體節點的最大值。

**路徑資訊為何不能事後補算。** 有人會想「先做一次 DFS 記下每個節點的父親，再對每個節點沿父指標往上累加」。這是對的但成本是 $O(nh)$，斜樹時 $O(n^2)$。參數傳遞把「重複走祖先鏈」的部分共享掉了——每條祖先鏈的公共前綴只算一次。這個共享正是自頂向下的價值。

## C++17 模板

```cpp
// 一般樹自頂向下：計算每個節點到根的距離（帶權）。
class Solution {
    std::vector<std::vector<std::pair<int, int>>> g_;  // {鄰居, 邊權}
    std::vector<long long> dist_;

    void dfs(int u, int fa, long long acc) {
        dist_[u] = acc;  // 進入時，acc 已是根到 u 的距離
        for (auto [v, w] : g_[u]) {
            if (v == fa) {
                continue;
            }
            dfs(v, u, acc + w);  // 純量按值傳遞，天然隔離，不需撤銷
        }
    }

public:
    std::vector<long long> solve(int n,
                                 const std::vector<std::vector<int>>& edges) {
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back({e[1], e[2]});
            g_[e[1]].push_back({e[0], e[2]});
        }
        dist_.assign(n, 0);
        dfs(0, -1, 0);
        return dist_;
    }
};
```

若 `acc` 是共享容器（例如記錄路徑上的節點），迴圈裡要配對撤銷：

```cpp
path.push_back(u);
for (int v : g_[u]) {
    if (v == fa) {
        continue;
    }
    dfs(v, u);  // 每個子節點都在同一份 path 上遞迴
}
path.pop_back();  // 離開 u 時撤銷一次即可（push 也只有一次）
```

## 時間與空間複雜度

每個節點訪問一次、每條邊掃描兩次，$O(n)$ 時間。純量 `acc` 不增加空間；共享容器 `acc` 佔 $O(h)$。遞迴堆疊 $O(h)$，最壞 $O(n)$。

相對於「對每個節點各自往上追溯」的 $O(nh)$，收穫來自祖先鏈公共前綴的共享。

## 常見錯誤與邊界條件

- `acc` 的語意（到 `u` 還是到 `u` 之父）中途改變。
- 共享容器忘記撤銷，或在迴圈內部誤加了多餘的 push/pop。
- 邊權和用 `int` 溢位。
- 忘記 `v == fa` 而無限遞迴。
- 根的初始 `acc` 沒設成單位元。
- 1376 中 `informTime` 為 0 的葉節點也要納入計算。
- $n = 1$ 時答案為 0。
- 深度大時爆堆疊。

## 與相似技巧的比較

- 自底向上（3.3）傳子樹彙總；本節傳路徑資訊。判斷依據仍是「所需資訊是路徑的函數還是子樹的函數」。
- 兩者結合是 3.4，換根 DP 更是把兩個方向的資訊都用滿。
- 與 2.2 的唯一差異是要傳 `fa` 且子節點用迴圈；不變量與適用條件完全相同。
- BFS 也能自頂向下傳遞資訊（按層推進），且不會爆堆疊，在深度很大時是實用的替代；但 BFS 拿不到「當前路徑」本身，需要路徑時仍得用 DFS。
- 3.7 的 DFS 時間戳是自頂向下的一個特化用途：進入與離開時各記一個時間，用來 $O(1)$ 判斷祖先關係。

## 本節重點速查

- 把根到當前節點的資訊當**參數往下傳**，不變量是「`acc` 等於根到父的累積量」。
- 純量按值傳遞天然隔離；
- 共享容器必須配對撤銷，一般樹的迴圈結構讓這件事比二元樹更容易寫錯。
- 適用前提：所需資訊是路徑的函數。
- $O(n)$ 時間，勝過逐點追溯祖先鏈的 $O(nh)$。
