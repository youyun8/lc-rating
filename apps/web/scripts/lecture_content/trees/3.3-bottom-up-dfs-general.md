## 這個技術解決什麼問題

與 2.3 相同的需求，換到一般樹上：答案取決於**以當前節點為根的整棵子樹**——子樹大小、子樹權重和、子樹中的最值、子樹是否滿足某條件（1519 統計子樹中相同標籤的節點數、3004 最大星形和）。

一次後序遍歷同時算出**所有節點**的子樹彙總，$O(n)$；相對於「對每個節點各跑一次子樹掃描」的 $O(n \cdot \text{subtree size})$ 總和（最壞 $O(n^2)$）。

## 狀態／資料結構定義

- `dfs(u, fa)` 的回傳值是 `u` 子樹的彙總量；或改用全域陣列 `size[u]`、`sum[u]` 在後序時機填寫，兩種寫法等價。
- **合併方式從「兩個運算元」變成「對子節點迴圈折疊」**：初始值必須是運算的單位元，然後 `for (v : children) acc = combine(acc, dfs(v, u));`，最後併入 `u` 自己。
- 單位元的選擇：求和用 0、求最大值用 $-\infty$（或第一個子的值）、計數用 0、子樹大小的初始值是 1（把自己算進去）。
- 若彙總量有多個分量，回傳 `struct`；若彙總量是集合（1519 的標籤計數），要注意合併的成本，見下面的複雜度討論。

## 不變量或正確性證明

命題（結構歸納）：**對每個節點 $u$，`dfs(u, fa)` 回傳以 $u$ 為根之子樹的目標彙總量。**

- 基底：葉節點（除父節點外無其他鄰居），迴圈不執行，回傳「只有 $u$ 自己」的彙總量。這要求初始值設定正確——子樹大小是 1、子樹和是 $val_u$。
- 歸納：假設各子節點的回傳值正確。由於 $u$ 的各棵子樹的節點集合**兩兩不交**，且與 $\{u\}$ 的並集恰為 $u$ 的子樹（樹無環的直接後果），只要 `combine` 忠實反映這個劃分，結果即正確。

**「兩兩不交」這條在一般樹上仍然成立，是因為樹中任兩節點間路徑唯一**——若某節點同時在 $u$ 的兩棵子樹中，就會有兩條到 $u$ 的路徑，構成環。這是所有樹上後序彙總的共同基礎，值得明確點出，因為在 DAG 上它就不成立（同一節點可被多個父節點的子樹包含），此時後序累加會重複計數，必須改用記憶化。

**合併運算需滿足結合律**（理由同 2.15）：子節點的迭代順序不應影響結果。

**1519（統計子樹中同標籤節點數）的複雜度陷阱。** 直觀寫法是每個節點回傳一個大小 26 的計數陣列，父節點把所有子節點的陣列加起來。這是 $O(26n)$，可以接受。但若標籤種類是 $O(n)$（例如用 `map` 存），樸素合併會退化成 $O(n^2)$——每個節點都要複製一份 $O(n)$ 大小的 map。

解法是**啟發式合併（小併大）**：把子節點的 map 併入時，總是把小的併進大的，並直接**移動**（`std::move` 或交換指標）而非複製最大的那個。這樣每個元素被移動的次數是 $O(\log n)$，總計 $O(n \log n)$。這個技巧的完整論證見 3.11。

**3004（最大星形和）**：對每個節點 $u$，取其所有鄰居中權值為正的前 $k$ 大相加，再加上 $u$ 自己。注意這裡「鄰居」包含父節點，所以不能只在後序時機用子節點的資訊——這是一個**看起來像後序、實則需要全部鄰居**的例子。做法是直接對每個節點掃描其鄰接表（總計 $O(n)$ 次掃描 $+$ 排序），不必用樹的遞迴結構。**辨認出這一點可以省下大量無謂的換根推導。**

## C++17 模板

```cpp
// 一般樹自底向上：一次算出所有節點的子樹大小與子樹權重和。
class Solution {
    std::vector<std::vector<int>> g_;
    std::vector<int> val_, size_;
    std::vector<long long> sum_;

    void dfs(int u, int fa) {
        size_[u] = 1;  // 單位元：先算自己
        sum_[u] = val_[u];
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            dfs(v, u);  // 先遞迴，回來時子樹資訊已備妥
            size_[u] += size_[v];  // 折疊：各子樹節點集合兩兩不交，可直接相加
            sum_[u] += sum_[v];
        }
    }
};
```

回傳 `struct` 的寫法（需要多個分量時）：

```cpp
struct Info {
    int size;
    long long sum;
    int mx;
};

Info dfs(int u, int fa) {
    Info cur{1, val[u], val[u]};  // 單位元 = 只有自己
    for (int v : g[u]) {
        if (v == fa) {
            continue;
        }
        Info sub = dfs(v, u);
        cur.size += sub.size;
        cur.sum += sub.sum;
        cur.mx = std::max(cur.mx, sub.mx);
    }
    return cur;
}
```

## 時間與空間複雜度

每個節點訪問一次、每條邊掃描兩次，若 `combine` 是 $O(1)$ 則總計 $O(n)$ 時間。這是相對於樸素「對每個節點各掃一次子樹」的主要收穫，後者總成本是 $\sum_u |\text{subtree}(u)|$，鏈狀樹時達 $O(n^2)$。

若 `combine` 的成本與彙總量大小成正比（合併集合、合併計數表），樸素做法是 $O(n \cdot m)$（$m$ 為值域）或最壞 $O(n^2)$；用小併大可降到 $O(n \log n)$（3.11）。**判斷關鍵是問「合併一次要多久」，不能一律套 $O(n)$。**

空間：鄰接表 $O(n)$，遞迴堆疊 $O(h)$，回傳 `struct` 每層一份仍是 $O(h)$。

## 常見錯誤與邊界條件

- 單位元設錯（子樹大小忘記從 1 開始、求最大值用 0 而樹中權值為負）。
- 忘記 `v == fa` 而無限遞迴。
- 把彙總量宣告成全域變數卻在遞迴中被子節點覆寫（應用陣列按節點索引，或用回傳值）。
- 集合型彙總量樸素合併而超時。
- `sum` 用 `int` 溢位。
- 3004 誤以為只能用子節點而漏掉父節點方向的鄰居。
- $n = 1$。
- 深度大時爆堆疊。

## 與相似技巧的比較

- 自頂向下（3.2）傳路徑資訊、自底向上傳子樹資訊。**問「我以下如何」用後序，問「從根到我如何」用前序。**
- 若題目要「以每個節點為根各求一次答案」（而不是以固定根求每棵子樹的答案），單靠後序不夠——子樹外的部分沒被算進去。這時要用換根 DP（3.4）。**這是本節與 3.4 的分界線，也是最容易誤判的地方。**
- 與 2.3 的差異只有介面（傳 `fa`、迴圈折疊）；歸納骨架、單位元的要求、狀態擴充的判準完全相同。
- 樹形 DP 在一般樹上的形式見 2.12 的討論，狀態擴充的判準（父節點需要區別對待哪些情形）不因分支數改變。

## 本節重點速查

- 先遞迴所有非父鄰居，回來後**對子節點迴圈折疊**，單位元要與「只有自己」的語意一致。
- 正確性依賴「各子樹節點集合兩兩不交」，這來自樹無環。
- 合併若非 $O(1)$，複雜度要重算——集合型彙總用小併大（3.11）。
- 要「以每個節點為根」時本節不夠，改用換根（3.4）。
