## 這個技術解決什麼問題

3.3 能一次算出「以固定根 $r$ 為根時，每棵子樹的彙總量」。但很多題目問的是另一件事：**以每個節點為根時，全樹的某個量各是多少**（例如「每個節點到所有其他節點的距離和」，834）。

對每個節點各跑一次 $O(n)$ 的 DFS 是 $O(n^2)$，$n$ 上看 $10^5$ 時不可行。換根 DP（也叫二次掃描法）用兩趟 DFS 做到 $O(n)$：**第一趟後序算出「子樹內」的資訊，第二趟前序把「子樹外」的資訊傳下去**，兩者一合就是以該節點為根的完整答案。

## 狀態／資料結構定義

以 834（樹中距離和）為例，$n$ 個節點，`ans[u]` 表示 $u$ 到所有節點的距離和。

- 第一趟（後序，以 0 為根）：
  - `size[u]`：$u$ 子樹的節點數。
  - `down[u]`：$u$ 到**其子樹內**所有節點的距離和。
  - 轉移：$\text{down}[u] = \sum_{v \in \text{child}(u)} (\text{down}[v] + \text{size}[v])$。加 `size[v]` 是因為子樹 $v$ 中每個節點到 $u$ 都比到 $v$ 多走一條邊。
- 第二趟（前序）：
  - `ans[root] = down[root]`（根的子樹就是全樹）。
  - 從 $u$ 換根到子節點 $v$ 時：$v$ 子樹內的 `size[v]` 個節點各**少走**一條邊，其餘 $n - \text{size}[v]$ 個節點各**多走**一條邊。故
    $$\text{ans}[v] = \text{ans}[u] - \text{size}[v] + (n - \text{size}[v])$$

一般形式的兩個狀態就是「子樹內」與「子樹外」，第二趟負責把後者從父節點推導給子節點。

## 不變量或正確性證明

**第一趟的不變量**就是 3.3 的後序歸納，此處不重複。

**第二趟的不變量：進入 `reroot(u, fa)` 時，`ans[u]` 已經是「以 $u$ 為根時的完整答案」。**

- 初始化：對根 $r$，全樹就是 $r$ 的子樹，故 `ans[r] = down[r]`，成立。
- 保持：假設 `ans[u]` 正確。要推導 `ans[v]`（$v$ 是 $u$ 的子節點）。關鍵在於**把全部節點按「在不在 $v$ 的子樹裡」分成兩類**，這個劃分是不重不漏的（樹的子樹劃分性質）：
  - $v$ 子樹內的 $\text{size}[v]$ 個節點：從 $u$ 出發要經過邊 $(u,v)$，從 $v$ 出發不用，故每個少 1。
  - 其餘 $n - \text{size}[v]$ 個節點：從 $v$ 出發必須先走到 $u$，故每個多 1。
  - 兩類節點到 $u$ 與到 $v$ 的距離差恰好各是 $\mp 1$，沒有第三類。因此 $\text{ans}[v] = \text{ans}[u] - \text{size}[v] + (n - \text{size}[v])$。
- 結論：遞迴地，每個節點的 `ans` 都正確。

**這個推導依賴兩個前提，換一題就要重新檢查：**

1. **從 $u$ 換到相鄰的 $v$ 時，答案的變化量必須能由 $O(1)$ 個已知量算出。** 距離和滿足（只需 `size[v]` 與 $n$）。若題目的量是「到所有節點距離的最大值」，換根時的變化就不是簡單的加減，必須改存「向下最長鏈」與「向上最長鏈」等更多資訊。
2. **換根操作必須可逆或可分解。** 上式其實是「把 $v$ 子樹的貢獻從 $u$ 的答案中扣掉、再把其餘部分加上」，這要求彙總運算有逆元（加法有減法）。若彙總是「取最大值」，就**沒有逆元**——你無法從最大值中「移除」某個貢獻。這時的標準做法是維護**前綴最大值與後綴最大值**（對每個節點的子節點列表），或維護「最大值與次大值」，換根時若要排除的恰是最大值就改用次大值。

第二點是換根 DP 最常見的難點，也是判斷題目難度的分水嶺：加法類（距離和、計數）直接套公式；最值類（3313、最遠距離）必須額外維護前二大或前後綴。

## C++17 模板

```cpp
// 樹中距離和（LeetCode 834）：兩趟 DFS，O(n)。
class Solution {
    std::vector<std::vector<int>> g_;
    std::vector<long long> ans_;
    std::vector<int> size_;
    int n_ = 0;

    void down(int u, int fa) {  // 第一趟：後序，算子樹內
        size_[u] = 1;
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            down(v, u);
            size_[u] += size_[v];
            ans_[u] += ans_[v] + size_[v];  // 子樹 v 每個節點多走一條邊
        }
    }

    void reroot(int u, int fa) {  // 第二趟：前序，把子樹外的資訊推下去
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            // size_[v] 個少 1，其餘多 1
            ans_[v] = ans_[u] - size_[v] + (n_ - size_[v]);
            reroot(v, u);  // 必須先算好 ans_[v] 再遞迴
        }
    }

public:
    std::vector<long long> sumOfDistancesInTree(
        int n, const std::vector<std::vector<int>>& edges) {
        n_ = n;
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back(e[1]);
            g_[e[1]].push_back(e[0]);
        }
        ans_.assign(n, 0);
        size_.assign(n, 0);
        down(0, -1);  // ans_[0] 此時已是以 0 為根的完整答案
        reroot(0, -1);
        return ans_;
    }
};
```

## 時間與空間複雜度

兩趟 DFS 各 $O(n)$，總計 $O(n)$ 時間——這是相對於「對每個節點各跑一次 DFS」的 $O(n^2)$ 的全部收穫。

空間：鄰接表 $O(n)$，各狀態陣列 $O(n)$，遞迴堆疊 $O(h)$。

若換根時需要維護前後綴最值（最值類問題），每個節點要對其子節點列表做兩次掃描，總成本仍是 $\sum_u \deg(u) = O(n)$，複雜度不變，只是常數與程式碼量增加。

## 常見錯誤與邊界條件

- 第二趟中先遞迴再計算 `ans[v]`（順序反了，此時 `ans[u]` 可能已被後續操作改動，或 `ans[v]` 尚未算好就被使用）。
- 把 `ans[root] = down[root]` 這一步漏掉（第一趟結束時根的答案已經對，但若用了不同陣列存則要顯式複製）。
- 對最值類問題直接套加減公式（沒有逆元，答案錯）。
- `size` 與 `n - size` 寫反。
- 距離和用 `int` 溢位（$n = 10^5$ 時距離和可達 $10^{10}$）。
- $n = 1$ 時答案為 0。
- 忘記 `v == fa`。

## 與相似技巧的比較

- 與 3.3 的分界線：**「以固定根求每棵子樹的答案」用 3.3；「以每個節點為根求全樹的答案」用換根。** 誤判這一點會導致答案漏掉子樹外的貢獻。
- 與 2.5「有遞有歸」的關係：換根是它的系統化版本——第一趟純後序、第二趟純前序，兩趟分工明確，而非在同一次遍歷中兼顧。
- 3.5 的樹直徑若要「對每個節點求最遠距離」，就是最值類換根的典型，需維護向下最長與次長鏈；也可用「直徑的兩個端點」的性質繞開（見 3.5）。
- 換根的思路在圖上沒有直接對應——它本質上依賴「移除一條邊就把樹分成兩塊」這條樹特有的性質。

## 本節重點速查

- 兩趟：後序算「子樹內」，前序把「子樹外」推下去。
- 核心是**從 $u$ 換到 $v$ 時，全部節點按「在不在 $v$ 子樹裡」二分，兩類的變化量各自 $O(1)$ 可算**。
- 加法類直接加減；
- **最值類沒有逆元**，必須維護前二大或前後綴最值。
- 第二趟務必先算 `ans[v]` 再遞迴。
