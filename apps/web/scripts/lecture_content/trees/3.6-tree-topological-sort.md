## 這個技術解決什麼問題

有些樹題沒有指定根，而是要求「反覆剝掉葉節點」直到剩下核心——最小高度樹（310）就是要找出使樹高最小的根。若對每個節點各跑一次 BFS 求高度，$O(n^2)$；剝葉法一趟 $O(n)$。

剝葉法本質上是**樹上的拓撲排序**：把度數為 1 的節點視為「入度為 0」，用佇列逐層剝除。它同時也是處理「父子關係未給定、只能從邊界往內推」這類題目的通用手法（2603 收集硬幣、3812 類的變體）。

## 狀態／資料結構定義

- `deg[u]`：節點 $u$ 的度數（鄰居數）。初始由建圖時統計。
- `queue<int> q`：當前所有度數為 1 的節點（葉節點）。
- `remain`：尚未被剝除的節點數，初始為 $n$。
- 分層剝除：與 2.13 相同，用 `int sz = q.size()` 切出「這一輪剝掉的葉節點」。
- 310 的終止條件：`remain > 2` 時繼續剝；剩下 1 或 2 個節點時，它們就是答案（最小高度樹的根）。

注意「度數為 1」而非「度數為 0」——樹的葉節點有一條連向父親的邊。$n = 1$ 時唯一節點的度數是 0，必須特判。

## 不變量或正確性證明

**不變量：每輪剝除後，剩下的節點集合構成原樹的一棵子樹（連通），且它恰是「距離原樹葉節點超過 $k$ 層」的節點集合（$k$ 為已剝輪數）。**

- 初始化：$k = 0$，剩下全部節點，成立。
- 保持：剝掉當前所有度數為 1 的節點後，剩餘部分仍連通——移除葉節點不會斷開樹（葉節點不在任何兩個其他節點的路徑上）。且新的葉節點恰是「原本距離葉節點 $k+1$ 層」的那些。

**310 的正確性：最後剩下的 1 或 2 個節點就是最小高度樹的根。**

論證分兩步。

第一步，**最小高度樹的根必定是直徑的中點**。設直徑為 $a$–$b$，長度（邊數）為 $L$。對任意節點 $r$，以 $r$ 為根的樹高至少是 $\max(d(r,a), d(r,b)) \ge \lceil L/2 \rceil$——因為 $d(r,a) + d(r,b) \ge d(a,b) = L$（三角不等式），故兩者中較大者不小於 $\lceil L/2 \rceil$。取 $r$ 為 $a$–$b$ 路徑的中點時，$\max(d(r,a), d(r,b)) = \lceil L/2 \rceil$，且**不存在比 $\lceil L/2 \rceil$ 更遠的節點**（否則會有比直徑更長的路徑）。故中點達到下界，是最小高度樹的根。

第二步，**剝葉法最後剩下的正是直徑的中點**。每剝一輪，所有從葉節點出發的路徑都縮短 1，特別是直徑的兩端各縮進一格，直徑長度每輪減 2。因此經過 $\lfloor L/2 \rfloor$ 輪後：若 $L$ 為偶數，剩下 1 個節點（中點）；若 $L$ 為奇數，剩下 2 個相鄰節點（兩個中點）。這解釋了為何答案至多兩個——**這不是經驗規則，是直徑奇偶性的直接後果**。

**為何 `remain > 2` 是終止條件而非 `q` 為空**：若一直剝到佇列空，會把整棵樹剝光。必須在剩下 1 或 2 個節點時停手。

**與圖的拓撲排序的關係。** 這裡的「度數為 1 就入隊」對應拓撲排序的「入度為 0 就入隊」。剝除節點 $u$ 時，對每個尚未剝除的鄰居 $v$ 執行 `if (--deg[v] == 1) q.push(v);`——注意判斷的是**恰好等於 1**，不是「小於等於 1」。用 `<= 1` 會讓同一個節點被重複入隊。這與拓撲排序中 `if (--indeg[v] == 0)` 的寫法同構，原因也相同：每個節點只在度數「跨過」臨界值的那一刻入隊一次。

## C++17 模板

```cpp
// 最小高度樹（LeetCode 310）：剝葉法，O(n)。
std::vector<int> findMinHeightTrees(
    int n, const std::vector<std::vector<int>>& edges) {
    if (n == 1) {
        return {0};
    }  // 唯一節點度數為 0，必須特判

    std::vector<std::vector<int>> g(n);
    std::vector<int> deg(n, 0);
    for (const auto& e : edges) {
        g[e[0]].push_back(e[1]);
        g[e[1]].push_back(e[0]);
        ++deg[e[0]];
        ++deg[e[1]];
    }

    std::queue<int> q;
    for (int i = 0; i < n; ++i) {
        if (deg[i] == 1) {
            q.push(i);
        }  // 葉節點的度數是 1，不是 0
    }

    int remain = n;
    while (remain > 2) {    // 剩 1 或 2 個就停，不能剝光
        int sz = q.size();  // 分層：這一輪剝掉的葉節點
        remain -= sz;
        for (int i = 0; i < sz; ++i) {
            int u = q.front();
            q.pop();
            for (int v : g[u]) {
                if (--deg[v] == 1) {
                    q.push(v);
                }  // 恰好等於 1 才入隊，避免重複
            }
        }
    }

    std::vector<int> ans;
    while (!q.empty()) {
        ans.push_back(q.front());
        q.pop();
    }
    return ans;
}
```

## 時間與空間複雜度

每個節點入隊、出隊各一次；每條邊在其兩個端點被剝除時各被掃描一次，總計 $\sum \deg = 2(n-1)$。故 $O(n)$ 時間。

空間：鄰接表 $O(n)$、度數陣列 $O(n)$、佇列 $O(n)$。

相對於「對每個節點各跑一次 BFS 求高度」的 $O(n^2)$，收穫來自「答案只可能是直徑中點」這條結構性質——剝葉法等於用 $O(n)$ 直接定位它。

## 常見錯誤與邊界條件

- $n = 1$ 未特判（此時唯一節點度數為 0，不會入隊，迴圈直接結束但答案應為 `{0}`）。
- $n = 2$（兩個節點度數都是 1，`remain > 2` 立刻為假，直接回傳兩者，正確）。
- 把葉節點的判定寫成 `deg[i] == 0`。
- 更新時用 `if (deg[v] <= 1)` 導致重複入隊。
- 剝到佇列為空而把樹剝光。
- 忘記 `remain -= sz`。
- 忘記分層（不記 `sz` 的話 `remain` 的扣減與輪次對不上）。

## 與相似技巧的比較

- 與圖的拓撲排序（graph 主題）同構：入度為 0 換成度數為 1，`--indeg[v] == 0` 換成 `--deg[v] == 1`。差別在於樹是無向的，所以用度數而非入度，且必須避免剝光。
- 與 2.4 的自底向上剪枝相比：剪枝有天然的父子方向可依循，一次後序即可；剝葉法用在**沒有指定根**的場合，必須從外圍往內收，因此需要顯式的佇列。
- 求直徑（3.5）與本節密切相關——剝葉法的輪數就是 $\lfloor L/2 \rfloor$，因此也能用來求直徑長度，但通常直接用 3.5 的方法更直接。
- 2603（收集樹上硬幣）是剝葉法的進階應用：先剝掉沒有硬幣的葉子分支，再剝固定輪數，剩下的部分決定答案；它的關鍵同樣是「從邊界往內收」。

## 本節重點速查

- 樹上拓撲排序＝剝葉法：葉節點的判定是 **`deg == 1`**，更新時用 **`--deg[v] == 1`** 恰好觸發一次。
- 分層剝除用 `sz = q.size()`。
- 310 的答案至多兩個，因為它們是直徑中點，而直徑長度的奇偶決定 1 個還是 2 個。
- 終止條件是 `remain > 2`，不能剝光；
- $n = 1$ 要特判。
