## 這個技術解決什麼問題

很多樹上問題需要反覆回答「$u$ 是不是 $v$ 的祖先」，或者「把 $u$ 的整棵子樹加上某個值」。樸素做法是每次都往上走一遍（$O(h)$）或遞迴整棵子樹（$O(\text{size})$），查詢多時就爆了。

DFS 時間戳的槓桿是**把樹的子樹結構壓平成陣列上的連續區間**：對每個節點記錄進入時間 `tin[u]` 與離開時間 `tout[u]`，則「$u$ 的子樹」恰好對應區間 $[\text{tin}[u], \text{tout}[u]]$。於是祖先判定變成 $O(1)$ 的區間包含檢查，子樹修改變成**區間**修改——可以直接套線段樹或樹狀陣列。

## 狀態／資料結構定義

- 全域計數器 `timer`，DFS 進入節點時 `tin[u] = ++timer`，離開前 `tout[u] = timer`。
- 這個版本（不在離開時遞增）給出的是「**歐拉序中的節點區間**」：`tin[u]` 是 $u$ 自己的位置，`tout[u]` 是其子樹中最後一個被訪問節點的位置。子樹恰對應 $[\text{tin}[u], \text{tout}[u]]$，長度等於子樹大小。
- 另一種常見版本是進入與離開都遞增（`tin[u] = ++timer; ... tout[u] = ++timer;`），得到長度 $2n$ 的括號序列。兩種都能判祖先，但**只有第一種能讓子樹對應長度等於子樹大小的區間**，因此配合資料結構做子樹修改時要用第一種。
- 祖先判定：$u$ 是 $v$ 的祖先 $\iff \text{tin}[u] \le \text{tin}[v] \le \text{tout}[u]$。

## 不變量或正確性證明

**核心性質：$u$ 的子樹中的節點，其 `tin` 恰好構成連續區間 $[\text{tin}[u], \text{tout}[u]]$。**

證明用結構歸納。DFS 進入 $u$ 時把 `tin[u]` 設為當時的計數器值。接著依序遞迴各子節點；由歸納假設，第 $i$ 個子節點 $c_i$ 佔用連續區間 $[\text{tin}[c_i], \text{tout}[c_i]]$，且長度等於其子樹大小。由於 DFS 在完成 $c_i$ 的整棵子樹之前不會離開它，各子樹佔用的區間**依序首尾相接、互不重疊**。離開 $u$ 前把 `tout[u]` 設為當時的計數器，它等於最後一個子樹的 `tout`。故 $u$ 的子樹佔用 $[\text{tin}[u], \text{tout}[u]]$，長度為 $1 + \sum_i |\text{subtree}(c_i)| = |\text{subtree}(u)|$。

**這裡關鍵的一句是「DFS 在完成一棵子樹之前不會離開它」**——這正是深度優先的定義，也是為什麼廣度優先的訪問序**不具備**這個性質（BFS 中同一棵子樹的節點會被其他子樹的節點打散）。想用時間戳就必須用 DFS。

**祖先判定的正確性。** ($\Rightarrow$) 若 $u$ 是 $v$ 的祖先，則 $v$ 在 $u$ 的子樹中，由上述性質 $\text{tin}[v] \in [\text{tin}[u], \text{tout}[u]]$。($\Leftarrow$) 若 $\text{tin}[v]$ 落在該區間內，則 $v$ 屬於 $u$ 的子樹（區間與子樹一一對應），故 $u$ 是 $v$ 的祖先（或 $u = v$，視題目是否把自己算作祖先而定，需明確約定）。

另一個等價寫法是用**括號序列版本**：$u$ 是 $v$ 的祖先 $\iff$ $u$ 的括號對包含 $v$ 的括號對。兩種版本在祖先判定上等價。

**為何這使子樹修改變成區間修改。** 若把節點按 `tin` 排成陣列 `a`（即 `a[tin[u]] = val[u]`），則「對 $u$ 的子樹全體加 $x$」等價於「對 `a` 的區間 $[\text{tin}[u], \text{tout}[u]]$ 全體加 $x$」。這一步把樹上問題**完全轉成序列問題**，之後線段樹、樹狀陣列、差分陣列全部可用。這是時間戳最有價值的用途，也是樹鏈剖分等進階技巧的第一步。

**注意這只對「子樹」有效，對「路徑」無效**——樹上路徑在 `tin` 序中並不連續。路徑查詢要用 LCA（3.8）搭配前綴和，或用樹鏈剖分把路徑拆成 $O(\log n)$ 個連續區間。

## C++17 模板

```cpp
// DFS 時間戳：把子樹壓成連續區間。
class TreeTimer {
    std::vector<std::vector<int>> g_;
    std::vector<int> tin_, tout_;
    int timer_ = 0;

    void dfs(int u, int fa) {
        tin_[u] = ++timer_;  // 進入：佔一個位置
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            dfs(v, u);  // 子樹的區間首尾相接
        }
        tout_[u] = timer_;  // 離開：子樹最後一個節點的位置
    }

public:
    void build(int n, const std::vector<std::vector<int>>& edges) {
        g_.assign(n, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back(e[1]);
            g_[e[1]].push_back(e[0]);
        }
        tin_.assign(n, 0);
        tout_.assign(n, 0);
        dfs(0, -1);
    }

    // u 是 v 的祖先嗎（含 u == v）
    bool isAncestor(int u, int v) const {
        return tin_[u] <= tin_[v] && tin_[v] <= tout_[u];
    }

    // u 的子樹對應區間 [tin_[u], tout_[u]]，長度即子樹大小
    std::pair<int, int> subtreeRange(int u) const {
        return {tin_[u], tout_[u]};
    }
};
```

## 時間與空間複雜度

預處理一次 DFS，$O(n)$ 時間、$O(n)$ 空間（兩個陣列）加 $O(h)$ 堆疊。

單次祖先判定 $O(1)$——這是相對於「沿父指標往上走」$O(h)$ 的收穫，在 $q$ 次查詢時把 $O(qh)$ 降到 $O(n + q)$。

子樹加值／子樹求和：配合樹狀陣列或線段樹，單次 $O(\log n)$。相對於樸素的 $O(\text{subtree size})$（最壞 $O(n)$），$q$ 次操作從 $O(qn)$ 降到 $O((n + q)\log n)$。

## 常見錯誤與邊界條件

- `tout[u]` 在離開時又遞增一次（變成括號序列版），卻仍用「區間長度等於子樹大小」的假設去做子樹修改。
- 祖先判定寫成 `tin[u] < tin[v]`（漏掉 $u = v$）或 `tin[v] < tout[u]`（漏掉子樹最後一個節點）。
- `timer` 從 0 起算但樹狀陣列要求下標從 1 起算（用 `++timer` 而非 `timer++` 可避免）。
- 用 BFS 產生時間戳（不具備連續區間性質）。
- 試圖用時間戳處理**路徑**查詢（不連續，必須用 LCA 或樹鏈剖分）。
- 忘記 `v == fa`。
- 深度大時爆堆疊。

## 與相似技巧的比較

- 與 LCA（3.8）互補：時間戳處理**子樹**（連續區間），LCA 處理**路徑**。事實上時間戳提供的祖先判定是倍增 LCA 中判斷「是否已跳過頭」的常用工具，兩者常一起出現。
- 歐拉序（每次進入與返回都記錄，長度 $2n-1$）搭配稀疏表可做到 $O(1)$ 查詢 LCA，那是時間戳的另一種用法。
- 與 3.11 的 DSU on tree 相關：後者也是利用「子樹在 DFS 序中連續」這個性質，只是換一種方式利用。
- 樹鏈剖分把「路徑」也拆成 $O(\log n)$ 段連續區間，是時間戳思路的完整推廣，超出本節範圍。
- 3515、3590 這類「查詢子樹內滿足某條件的節點」的題目，標準套路就是時間戳加離線排序或可持久化資料結構。

## 本節重點速查

- 進入記 `tin`、離開記 `tout`，則**子樹恰對應連續區間 $[\text{tin}[u], \text{tout}[u]]$**，長度等於子樹大小。
- 祖先判定 $O(1)$：`tin[u] <= tin[v] && tin[v] <= tout[u]`。
- 這把子樹修改轉成區間修改，線段樹樹狀陣列全部可用。
- **只對子樹有效，路徑不連續**。
- 必須用 DFS，BFS 沒有這個性質。
