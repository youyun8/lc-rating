## 這個技術解決什麼問題

2.8 的遞迴 LCA 每次查詢 $O(n)$，$q$ 次查詢就是 $O(qn)$。當 $n, q$ 都上看 $10^5$ 時不可行。

倍增（binary lifting）的槓桿是**預先算出每個節點往上跳 $2^k$ 步到達哪裡**，於是「往上跳任意 $d$ 步」可以按 $d$ 的二進位展開，用 $O(\log n)$ 次跳躍完成。預處理 $O(n \log n)$，之後每次查詢 $O(\log n)$。

同一套表格還能回答「$u$ 的第 $k$ 個祖先」（1483）、「$u$ 到 $v$ 路徑上的最大邊權」（把最值也一起倍增）等問題，用途遠不只 LCA。

## 狀態／資料結構定義

- `LOG`：滿足 $2^{LOG} \ge n$ 的最小整數，通常取 $\lceil \log_2 n \rceil + 1$。
- `up[k][u]`：從 $u$ 往上跳 $2^k$ 步到達的節點；跳出根則記為 $-1$（或記為根自己，兩種約定都可行但要貫徹）。
- `dep[u]`：$u$ 的深度，根為 0。
- 遞推式：$\text{up}[0][u] = \text{parent}(u)$，且
  $$\text{up}[k][u] = \text{up}[k-1][\,\text{up}[k-1][u]\,]$$
  意思是「跳 $2^k$ 步 = 先跳 $2^{k-1}$ 步，再跳 $2^{k-1}$ 步」。
- 預處理順序很重要：必須**先把所有節點的第 $k-1$ 層算完，才能算第 $k$ 層**，所以外層迴圈是 $k$、內層是 $u$。若寫成外層 $u$、內層 $k$，`up[k-1][up[k-1][u]]` 可能還沒算好。

## 不變量或正確性證明

**遞推式的正確性。** 從 $u$ 往上跳 $2^k$ 步，等於先跳 $2^{k-1}$ 步到達某節點 $w = \text{up}[k-1][u]$，再從 $w$ 跳 $2^{k-1}$ 步。因為 $2^{k-1} + 2^{k-1} = 2^k$，且**祖先鏈是一條唯一的路徑**（每個節點恰有一個父節點），所以「跳 $a$ 步再跳 $b$ 步」與「跳 $a+b$ 步」結果相同。這個結合性正是倍增能成立的根本——它在一般圖上不成立（往上的路徑不唯一），只在樹（或更廣義的函數圖）上成立。

**任意步數可分解。** 任何 $d \ge 0$ 都能唯一寫成 $\sum_{k \in S} 2^k$（二進位表示），故往上跳 $d$ 步可以拆成 $|S| \le \log_2 d + 1$ 次跳躍。實作上枚舉 $d$ 的每個為 1 的位元即可。

**LCA 演算法的正確性。** 分兩階段。

*階段一：把較深的節點提到與較淺者同深度。* 設 $\text{dep}[u] \ge \text{dep}[v]$，把 $u$ 往上跳 $\text{dep}[u] - \text{dep}[v]$ 步。跳完後 $u' $ 是 $u$ 的祖先且與 $v$ 同深度。此時若 $u' = v$，則 $v$ 本來就是 $u$ 的祖先，LCA 即 $v$，直接回傳。

*階段二：兩者同時往上跳，找到「最深的仍然不同」的位置。* 對 $k$ 從大到小枚舉，若 $\text{up}[k][u] \ne \text{up}[k][v]$ 就同時跳。

這一步的不變量是：**每次跳躍後，$u$ 與 $v$ 仍然不相等，且它們的 LCA 保持不變。**

- 「仍不相等」由跳躍條件直接保證。
- 「LCA 不變」需要論證：若 $\text{up}[k][u] \ne \text{up}[k][v]$，表示往上跳 $2^k$ 步還沒到達 LCA（因為一旦到達或超過 LCA，兩者會落在同一條祖先鏈上而可能相等——更精確地說，設 $L$ 是 LCA，若 $2^k \ge \text{dep}[u] - \text{dep}[L]$，則 $\text{up}[k][u]$ 是 $L$ 或 $L$ 的祖先，同理 $\text{up}[k][v]$ 也是，且兩者深度相同，故必相等）。既然沒到達 LCA，跳過去之後 $u$、$v$ 仍在 LCA 的兩棵不同子樹中，LCA 不變。
- 由 $k$ 從大到小枚舉，這是標準的貪心二進位逼近：結束時 $u$ 與 $v$ 恰好停在 LCA 的兩個不同子節點上（再往上一步就相同）。故 $\text{up}[0][u]$ 即為 LCA。

**為何 $k$ 必須從大到小。** 從小到大枚舉會失去「每一位獨立決策」的性質：跳了小步之後，剩餘距離的二進位表示會改變，無法保證用剩下的位元湊出正確結果。從大到小則等價於貪心地決定二進位表示的每一位——與二進位轉換的標準算法一致。**這個順序不是慣例，是正確性要求。**

## C++17 模板

```cpp
// 倍增 LCA：預處理 O(n log n)，查詢 O(log n)。
class LCA {
    int n_, LOG_;
    std::vector<std::vector<int>> g_, up_;  // up_[k][u] = u 往上跳 2^k 步
    std::vector<int> dep_;

    void dfs(int u, int fa) {
        up_[0][u] = fa;
        for (int v : g_[u]) {
            if (v == fa) {
                continue;
            }
            dep_[v] = dep_[u] + 1;
            dfs(v, u);
        }
    }

public:
    LCA(int n, const std::vector<std::vector<int>>& edges) : n_(n) {
        LOG_ = 1;
        while ((1 << LOG_) < n_) {
            ++LOG_;
        }
        ++LOG_;

        g_.assign(n_, {});
        for (const auto& e : edges) {
            g_[e[0]].push_back(e[1]);
            g_[e[1]].push_back(e[0]);
        }
        up_.assign(LOG_, std::vector<int>(n_, -1));
        dep_.assign(n_, 0);
        dfs(0, -1);

        for (int k = 1; k < LOG_; ++k) {  // 外層必須是 k：先算完第 k-1 層
            for (int u = 0; u < n_; ++u) {
                int mid = up_[k - 1][u];
                up_[k][u] = (mid == -1) ? -1 : up_[k - 1][mid];
            }
        }
    }

    int kthAncestor(int u, int k) const {  // 第 k 個祖先（LeetCode 1483）
        for (int i = 0; i < LOG_ && u != -1; ++i) {
            if (k >> i & 1) {
                u = up_[i][u];
            }
        }
        return u;
    }

    int lca(int u, int v) const {
        if (dep_[u] < dep_[v]) {
            std::swap(u, v);
        }
        u = kthAncestor(u, dep_[u] - dep_[v]);  // 階段一：提到同深度
        if (u == v) {
            return u;
        }  // v 本來就是 u 的祖先

        for (int k = LOG_ - 1; k >= 0; --k) {  // 階段二：k 從大到小
            if (up_[k][u] != up_[k][v]) {  // 還沒跳到 LCA，安全地跳
                u = up_[k][u];
                v = up_[k][v];
            }
        }
        return up_[0][u];  // 此刻兩者停在 LCA 的兩個子節點
    }

    int dist(int u, int v) const {  // 樹上距離
        return dep_[u] + dep_[v] - 2 * dep_[lca(u, v)];
    }
};
```

## 時間與空間複雜度

預處理：一次 DFS $O(n)$，填表雙重迴圈 $O(n \log n)$。

查詢：階段一至多 $\log n$ 次跳躍，階段二枚舉 $\log n$ 個位元，故 $O(\log n)$。

空間 $O(n \log n)$——這是倍增的主要代價。$n = 10^5$、$\text{LOG} = 18$ 時約 $1.8 \times 10^6$ 個 `int`，約 7 MB，通常可接受但要留意題目的記憶體限制。

替代方案的取捨：歐拉序加稀疏表是 $O(n \log n)$ 預處理、$O(1)$ 查詢，空間同樣 $O(n \log n)$，查詢更快但實作稍繁；Tarjan 離線 LCA 是近線性時間與 $O(n)$ 空間，但**必須離線**（所有查詢預先給定）。**單次查詢用 2.8 的遞迴版就好，不要為了一次查詢建表。**

## 常見錯誤與邊界條件

- 填表時外層迴圈寫成節點、內層寫成 $k$，導致依賴的值尚未算好。
- 階段二的 $k$ 從小到大枚舉。
- 階段一忘記先判 `u == v` 就進入階段二（此時 `up[k][u] != up[k][v]` 恆為假，會直接回傳 `up[0][u]`，即 $v$ 的父節點，答案偏高一層）。
- `LOG` 取太小（$2^{LOG} < n$ 時跳不夠遠）。
- 跳出根時的約定不一致（有時記 $-1$、有時記根，混用會解參考 $-1$）。
- `kthAncestor` 未處理 $k$ 大於深度的情形（應回傳 $-1$）。
- 森林（非連通）時要對每個連通分量各跑一次 DFS。
- 深度大時 DFS 爆堆疊（可改迭代或用 BFS 建 `dep` 與 `up[0]`）。

## 與相似技巧的比較

- 與 2.8 的遞迴 LCA：**單次查詢用遞迴（$O(n)$ 但零預處理），多次查詢用倍增。** 這是唯一的選擇依據。
- 與 3.7 的時間戳：時間戳處理子樹、LCA 處理路徑，兩者互補。時間戳的祖先判定常被用在 LCA 的實作或驗證中。
- 倍增不只能存「祖先是誰」——把 `up[k][u]` 擴充成同時存「這 $2^k$ 步中的最大邊權／和」，就能 $O(\log n)$ 回答路徑最值與路徑和查詢（合併時取 `max` 或相加）。這是倍增最有價值的推廣，前提是該運算**可結合**。
- 樹上距離 $d(u,v) = \text{dep}[u] + \text{dep}[v] - 2\,\text{dep}[\text{LCA}]$，這條公式讓 LCA 直接支撐所有樹上距離查詢（2277、2646 等）。

## 本節重點速查

- `up[k][u] = up[k-1][up[k-1][u]]`，**填表外層必須是 $k$**。
- 查詢兩階段：先把深的提到同深度（若相等則淺者即 LCA），再讓 $k$ **從大到小**同時跳（只在 `up[k][u] != up[k][v]` 時跳），最後回傳 `up[0][u]`。
- $k$ 從大到小是正確性要求，不是慣例。
- 預處理 $O(n \log n)$、查詢 $O(\log n)$、空間 $O(n \log n)$。
- 單次查詢別建表。
