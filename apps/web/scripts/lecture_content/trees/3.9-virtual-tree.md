## 這個技術解決什麼問題

樹有 $n$ 個節點，但每次詢問只關心其中 $k$ 個關鍵點，且 $\sum k$ 遠小於 $qn$。逐次掃全樹是 $O(qn)$，太慢。

虛樹的槓桿是**把「與答案無關的過路點」壓縮掉**：只保留關鍵點與它們之間的岔路口（LCA），重新連成一棵節點數 $O(k)$ 的小樹，在小樹上跑原本的樹形 DP。單次成本從 $O(n)$ 降到 $O(k \log k)$。

它的價值不在於某一題，而在於它把「大樹＋小關鍵點集」這個常見結構，化約成「小樹上的標準樹形 DP」——你原本會寫的 DP 一行都不用改。

## 狀態／資料結構定義

- 原樹預處理：`dfn[u]`（DFS 進入時間戳，見 3.7）、`dep[u]`、倍增表 `up[k][u]`（見 3.8）。這兩節是虛樹的前置。
- 關鍵點陣列 `key`，按 `dfn` 遞增排序。
- **虛樹點集** $V' = \text{key} \cup \{\,\mathrm{lca}(\text{key}_i, \text{key}_{i+1}) : 1 \le i < k\,\}$，排序去重後即為最終點集。
- 虛樹鄰接表 `vt`：只存 $V'$ 中的點，**每次用完只清 $V'$ 中的點**，不可 `memset` 整棵原樹。
- 建樹用的單調棧 `stk`：棧內由底到頂是一條深度嚴格遞增的祖先鏈。
- 虛樹的邊代表原樹上的一段路徑，若題目在意路徑長度，邊權取 $\text{dep}[v] - \text{dep}[u]$（或路徑權重和）。

## 不變量或正確性證明

**引理（為何只需相鄰兩點的 LCA）。** 設關鍵點按 `dfn` 排序為 $a_1, \dots, a_k$。則
$$\{\,\mathrm{lca}(a_i, a_j) : i < j\,\} = \{\,\mathrm{lca}(a_t, a_{t+1}) : 1 \le t < k\,\}.$$

證明。$\supseteq$ 顯然。證 $\subseteq$：固定 $i < j$，令 $L = \mathrm{lca}(a_i, a_j)$。由 3.7，$L$ 的子樹在 `dfn` 上是連續區間，而 $\mathrm{dfn}(a_i)$ 與 $\mathrm{dfn}(a_j)$ 都在其中，故 $a_i, a_{i+1}, \dots, a_j$ **全部**落在 $L$ 的子樹內。把這些點按「屬於 $L$ 的哪個子節點的子樹」分組——由於 `dfn` 連續區間性質，同組的點在排序後是連續的一段。$a_i$ 與 $a_j$ 不在同一組（否則它們的 LCA 會比 $L$ 更深）。因此存在某個 $t \in [i, j)$ 使 $a_t$ 與 $a_{t+1}$ 分屬不同組（或其中之一就是 $L$ 本身），此時 $\mathrm{lca}(a_t, a_{t+1}) = L$。故 $L$ 在右側集合中。$\square$

這條引理把要算的 LCA 從 $\binom{k}{2}$ 個降到 $k-1$ 個，是虛樹能做到 $O(k \log k)$ 的根本原因。**它整個建立在 3.7 的「子樹在 dfn 上連續」之上**——若不按 `dfn` 排序，引理不成立，必須真的兩兩求 LCA。

**點數上界：$|V'| \le 2k - 1$。** 虛樹中的每個非關鍵點都是某兩個關鍵點的 LCA，因此在虛樹中至少有兩個子節點（否則它就不是分岔點，可被壓縮掉）。一棵有根樹中「子節點數 $\ge 2$ 的節點數」嚴格小於「葉節點數」，而葉節點必為關鍵點（非關鍵點都是分岔點），故葉數 $\le k$，分岔點數 $\le k - 1$，總計 $\le 2k - 1$。**這個上界保證虛樹的規模與 $n$ 無關**，才有意義。

**單調棧的不變量：處理完前 $i$ 個點後，棧內由底到頂是一條深度嚴格遞增的鏈，且棧中每個點都是 $a_i$ 的祖先（或 $a_i$ 自己）。**

- 初始化：棧內只有 $a_1$，成立。
- 保持：處理 $a_{i+1}$ 時令 $l = \mathrm{lca}(\text{stk.top}, a_{i+1})$。由於 `dfn` 遞增，$a_{i+1}$ 不在棧頂的子樹內時，棧中所有深度大於 $\mathrm{dep}(l)$ 的點的子樹**已經完全處理完畢**（它們的 dfn 區間已被走過），可以安全彈出並連邊。彈到深度 $\le \mathrm{dep}(l)$ 後，若棧頂不是 $l$ 就把 $l$ 補進去（它是新的分岔點），再壓入 $a_{i+1}$。不變量恢復。
- 終止：最後把棧清空、逐一連邊，得到完整虛樹。

「已完全處理完畢」這一句依賴的前提是**輸入按 `dfn` 遞增**——這也是為什麼排序不能省，且不能改用別的順序。

## C++17 模板

```cpp
// 虛樹建構。前置：dfn / dep / 倍增 LCA（見 3.7、3.8）。
// key 為關鍵點，回傳虛樹的根；vt 為虛樹鄰接表。
std::vector<std::vector<int>> vt;  // 只在 V' 上有內容
std::vector<int> dfn, dep;

int buildVirtualTree(std::vector<int>& key) {
    // 必須按 dfn 排序
    std::sort(key.begin(), key.end(),
              [](int a, int b) { return dfn[a] < dfn[b]; });

    int k = key.size();
    for (int i = 0; i + 1 < k; ++i) {
        key.push_back(lca(key[i], key[i + 1]));  // 只需相鄰的 LCA
    }
    std::sort(key.begin(), key.end(),
              [](int a, int b) { return dfn[a] < dfn[b]; });
    key.erase(std::unique(key.begin(), key.end()), key.end());

    for (int u : key) {
        vt[u].clear();
    }  // 只清 V'，不清全樹

    std::vector<int> stk;
    stk.push_back(key[0]);
    for (size_t i = 1; i < key.size(); ++i) {
        int u = key[i];
        int l = lca(stk.back(), u);
        while (stk.size() >= 2 && dep[stk[stk.size() - 2]] >= dep[l]) {
            vt[stk[stk.size() - 2]].push_back(
                stk.back());  // 子樹已處理完，連邊
            stk.pop_back();
        }
        if (stk.back() != l) {  // l 是新的分岔點
            vt[l].push_back(stk.back());
            stk.back() = l;
        }
        stk.push_back(u);
    }
    while (stk.size() >= 2) {
        vt[stk[stk.size() - 2]].push_back(stk.back());
        stk.pop_back();
    }
    return stk[0];  // 虛樹的根
}
```

## 時間與空間複雜度

單次建虛樹：排序 $O(k \log k)$，$k-1$ 次 LCA 各 $O(\log n)$，單調棧 $O(k)$。合計 $O(k \log k + k \log n)$。

之後在虛樹上跑樹形 DP 是 $O(|V'|) = O(k)$。

全部 $q$ 次詢問：$O\!\left(n \log n + \sum_i k_i (\log k_i + \log n)\right)$，其中 $n \log n$ 是一次性的倍增預處理。相對於暴力的 $O(qn)$，當 $\sum k_i \ll qn$ 時收穫巨大。

空間：倍增表 $O(n \log n)$，虛樹鄰接表 $O(n)$（但每次只用到 $O(k)$ 個位置）。

**清空的成本必須算進去。** 若每次詢問都 `memset` 整個 `vt` 陣列，單次就是 $O(n)$，總計 $O(qn)$——虛樹的全部好處被抵銷。這不是常數層級的疏忽，是複雜度層級的錯誤。

## 常見錯誤與邊界條件

- 沒有按 `dfn` 排序就取相鄰 LCA（引理不成立，會漏掉分岔點）。
- 只排一次序、加入 LCA 後忘記重新排序去重。
- 用 `memset` 清空整棵原樹的鄰接表（複雜度退化）。
- 忘記去重導致同一點在虛樹中出現兩次。
- 單調棧彈出條件寫成 `>` 而非 `>=`（$l$ 恰好等於棧中某點時會漏連邊）。
- 虛樹的根不是原樹的根（是所有關鍵點的 LCA），DP 時不要誤用原根。
- 只有一個關鍵點時虛樹只有一個節點（迴圈都不執行，要確認 DP 能處理）。
- 虛樹邊權若要用原樹路徑長，記得用深度差而非 1。
- 虛樹上的「子節點」與原樹的子節點不同，別把原樹的鄰接表混進來。

## 與相似技巧的比較

- 與 3.7、3.8：虛樹是這兩節的**組合應用**，兩者都是硬前置。不熟 dfn 的連續區間性質就無法理解為何只取相鄰 LCA。
- 與 3.11 的 DSU on tree：兩者都在對付「每次都掃子樹太慢」。差別在於 DSU on tree 要求**每個節點都要答案**（無法壓縮），虛樹則是**只有少數點被關心**（可以壓縮）。關鍵點多到接近 $n$ 時虛樹沒有好處。
- 與 3.12 的點分治：點分治處理「任意點對的路徑統計」，虛樹處理「指定點集上的樹形 DP」。前者是分治，後者是壓縮，思路正交。
- 樹鏈剖分也能處理多次路徑查詢，但它的長處在「路徑修改／查詢」，不在「對點集跑 DP」。
- 3786 這類「把節點分組、對每組各算一次」的題目是虛樹的教科書場景：各組節點數總和有界，逐組建虛樹即可。

## 本節重點速查

- 虛樹點集 = 關鍵點 ∪ **按 `dfn` 排序後相鄰兩點的 LCA**，這條引理靠的是 3.7 的「子樹在 dfn 上連續」。
- 點數上界 $2k - 1$，與 $n$ 無關。
- 單調棧內始終是一條深度遞增的祖先鏈，`dfn` 遞增保證彈出的點其子樹已處理完。
- **清空只清虛樹用到的點**，`memset` 全樹會讓複雜度退回暴力。
