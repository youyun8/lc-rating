## 這個技術解決什麼問題

有一類題目要求的不是「一個最佳答案」，而是**把所有合法方案列出來**：所有字母組合（17）、所有子集、所有排列、所有分割方式。這些答案的個數本身就是指數級的，沒有多項式解法可言，問題變成「如何不重不漏地枚舉，且不要浪費時間在注定失敗的分支上」。

回溯的槓桿有兩個。第一，**把「所有方案」組織成一棵遞迴樹**，讓「根到葉的路徑」與「方案」一一對應——有了這個雙射，不重不漏就是結構性的，不需要額外去重。第二，**共用前綴**：長度為 $n$ 的方案有指數多個，但它們共用大量前綴，回溯只把每個前綴構造一次，並在原地修改同一個 `path` 陣列，避免每條路徑各複製一份。

## 狀態／資料結構定義

以 17（電話號碼的字母組合）為例：

- `path`：當前已做出的選擇序列，長度等於當前遞迴深度。它是**全域可變**的，靠進入時 push、離開時 pop 維持正確。
- `i`：當前要決定第幾個位置。這是**唯一的狀態變數**——因為「還沒決定的部分」完全由 $i$ 決定。
- `ans`：收集完整方案的容器。

回溯函式的簽名 `void dfs(int i)` 意思是：「`path[0..i-1]` 已經定好，請把所有以它為前綴的完整方案都加進 `ans`」。**把這句話寫下來，是設計回溯的第一步**，因為它同時決定了遞迴的參數、終止條件與迴圈範圍。

一般化的三要素：

1. **狀態**：描述「已做的決策」與「還要決策什麼」的最小資訊。
2. **選擇列表**：在當前狀態下，下一步有哪些合法選項。
3. **終止條件**：什麼時候 `path` 已是一個完整方案。

## 不變量或正確性證明

**不變量：進入 `dfs(i)` 時，`path` 恰好是長度為 $i$ 的一個合法前綴；離開 `dfs(i)` 時，`path` 與進入時完全相同。**

第二句是「回溯」二字的全部內容。它由「每個 `path.push_back` 都配對一個 `path.pop_back`，且中間沒有其他路徑能跳出函式」保證。有了它，**兄弟分支之間互不干擾**：`dfs(i)` 的第二個選項開始執行時，看到的 `path` 與第一個選項開始時一模一樣。若少了 pop，第二個分支會繼承第一個分支的殘留，答案全錯。

**不重不漏的證明（方案 ↔ 根到葉路徑的雙射）。**

- *不漏*：對任一合法方案 $c_0 c_1 \cdots c_{n-1}$，由不變量遞迴地看：`dfs(0)` 的迴圈會枚舉第 0 位的所有合法選項，其中包含 $c_0$；進入該分支後 `dfs(1)` 會枚舉包含 $c_1$ 的所有選項……如此下去必定到達 $i = n$，把該方案加入 `ans`。前提是**每層的選擇列表涵蓋了該位置所有可能的取值**——這是設計時要自己確認的，程式不會提醒你。
- *不重*：兩條不同的根到葉路徑，必在某一層 $i$ 選了不同的值 $c_i \ne c'_i$，因此對應的方案在第 $i$ 位不同，是兩個不同方案。反過來說，同一個方案只可能沿著唯一一條路徑被生成，因為每層的選項互不相同（同一層的 `for` 迴圈枚舉的是**互異**的選項）。

**這條「不重」的論證點名了一個容易被違反的前提：同一層的選項必須兩兩互異。** 若輸入含重複元素（例如 `[1,1,2]` 求子集），同一層會出現兩個相同的選項，雙射就破了，必須額外去重——那正是 4.6 要處理的事。

**終止條件與「答案在哪裡收集」。** 17 這種「方案長度固定」的題目在 $i = n$ 時收集，答案只在葉節點。但**這不是通則**：4.2 的子集型在每個節點都要收集，因為每個前綴本身就是一個合法方案。收集的位置由「什麼是完整方案」決定，不由習慣決定。

## C++17 模板

```cpp
// 電話號碼的字母組合（LeetCode 17）：固定長度的回溯枚舉。
class Solution {
    static constexpr const char* kMap[10] = {
        "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};

    std::string digits_, path_;
    std::vector<std::string> ans_;

    // 契約：path_ 已定好前 i 位，請把所有以它為前綴的完整方案加進 ans_。
    void dfs(int i) {
        if (i == static_cast<int>(digits_.size())) {  // 完整方案
            ans_.push_back(path_);
            return;
        }
        for (char c :
             std::string(kMap[digits_[i] - '0'])) {  // 這一位的所有選項
            path_.push_back(c);                      // 做選擇
            dfs(i + 1);                              // 遞迴解決剩下的
            path_.pop_back();  // 撤銷：與 push 嚴格配對
        }
    }

public:
    std::vector<std::string> letterCombinations(std::string digits) {
        if (digits.empty()) {
            return {};
        }  // 空輸入回傳空陣列，不是 {""}
        digits_ = std::move(digits);
        path_.reserve(digits_.size());
        dfs(0);
        return ans_;
    }
};
```

## 時間與空間複雜度

回溯的複雜度 = **遞迴樹的節點數 × 每個節點的工作量**，不是「深度乘以分支數」這種直覺式的估算。

17 的遞迴樹：深度 $n$（數字個數），每層分支數是該數字對應的字母數 $b_i \in \{3, 4\}$。葉節點數為 $\prod_i b_i \le 4^n$，內部節點數比葉節點少，同階。每個葉節點要複製一份長度 $n$ 的字串，故時間 $O(n \cdot 4^n)$。

空間：`path` 佔 $O(n)$，遞迴堆疊 $O(n)$，**不計輸出**。若計入輸出則是 $O(n \cdot 4^n)$。回答複雜度時說清楚是否含輸出，否則對不上。

一般規則：

- **方案數本身就是指數級時，複雜度的下界就是方案數**，任何演算法都逃不掉。回溯的優化空間全在「減少無效分支」（剪枝），不在改變數量級。
- 「每個節點的工作量」常被忽略。若在每個節點都做一次 $O(n)$ 的檢查（例如判回文），複雜度要多乘一個 $n$。

## 常見錯誤與邊界條件

- `push` 與 `pop` 沒有嚴格配對（尤其是在迴圈中間 `return` 或 `continue` 時漏掉 `pop`）。
- 把 `path` 宣告成區域變數並逐層複製（正確但退化成 $O(n)$ 額外開銷乘上節點數）。
- 在葉節點忘記複製 `path` 而是存了指標／參考（回溯後內容被改，全部答案變成同一個）。
- 空輸入未特判（17 要回傳 `{}` 而非 `{""}`）。
- 終止條件寫成 `i > n` 或 `i >= n` 而 `path` 已超長。
- 答案收集的位置放錯（該在每個節點收集卻只在葉節點收集，反之亦然）。
- 同一層的選項有重複卻沒去重。

## 與相似技巧的比較

- 與 2.7 的二元樹回溯：機制完全相同（進入時記錄、離開時還原），差別只在「樹」是顯式給定的還是由選擇列表隱式生成。**回溯就是在一棵不存在的樹上做 DFS。**
- 與 DFS 的關係：回溯 = DFS + 狀態還原。若狀態是傳值的參數（純量），不需要顯式還原；若是共用的容器或全域陣列，就必須還原。這與 3.2 提過的判準一致。
- 與動態規劃：兩者都在遞迴樹上工作。**DP 適用於「不同前綴會導向相同子問題」而只需要一個最佳值的場合**（可以記憶化）；回溯適用於「要列出所有方案」的場合——方案本身依賴完整路徑，無法合併，記憶化沒有意義。這是選擇兩者的唯一判準。
- 與 BFS：回溯用 DFS 是因為「共用前綴」在深度優先下天然成立（同一個 `path` 反覆改），BFS 則必須為佇列中每個狀態各存一份路徑，空間爆炸。

## 本節重點速查

- 先把契約寫成一句話：「`dfs(i)` 表示前 $i$ 位已定，請枚舉所有以它為前綴的完整方案」。
- 三要素是**狀態、選擇列表、終止條件**。
- 不變量是「離開時 `path` 與進入時相同」，靠 push/pop 嚴格配對，這才讓兄弟分支互不干擾。
- 不重不漏來自「方案 ↔ 根到葉路徑」的雙射，其前提是**同一層的選項兩兩互異**（違反時見 4.6）。
- 複雜度 = 遞迴樹節點數 × 每節點工作量。
