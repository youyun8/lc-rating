## 這個技術解決什麼問題

劃分型回溯處理的是：**把一個序列切成若干連續段，每段要滿足某條件，列出所有切法**。分割回文串（131）、復原 IP 位址（93）、單詞拆分 II（140）、拆分字串使唯一子字串最多（1593）都是這個形狀。

它看起來像子集型，其實不同：子集型選的是「哪些元素」，劃分型選的是「在哪裡下刀」。把問題轉譯成「選切點」之後，$n$ 個字元的序列有 $n-1$ 個可能的切點位置，每個切點獨立地切或不切——**劃分型本質上是切點集合的子集枚舉**，$2^{n-1}$ 種切法。

## 狀態／資料結構定義

- `dfs(i)`：`s[0..i-1]` 已經被完整切好且每段合法，`path` 存著這些段；請枚舉 `s[i..n-1]` 的所有合法切法。
- **唯一的狀態變數是 $i$**（下一段的起點）。這是劃分型與子集型的關鍵區別：子集型的 `start` 是「候選元素的下界」，劃分型的 $i$ 是「已消耗的前綴長度」，兩者含義不同但都恰好一維。
- 迴圈枚舉這一段的**結束位置** $j \in [i, n)$，即取子串 `s[i..j]`。
- 終止條件：$i = n$，表示整個字串剛好用完，`path` 是一個完整劃分。
- 93 這種段數固定的題目多一個維度：`dfs(i, seg)`，`seg` 是已切出的段數；終止條件是 $i = n$ **且** $\text{seg} = 4$。

## 不變量或正確性證明

**不變量：進入 `dfs(i)` 時，`path` 中各段依序連接恰好等於 `s[0..i-1]`，且每段都滿足題目條件。**

- 初始化：`dfs(0)`，`path` 為空，連接起來是空串 = `s[0..-1]`，成立。
- 保持：在 `dfs(i)` 中取子串 `s[i..j]`（先檢查它合法），push 進 `path` 後遞迴 `dfs(j + 1)`。此時 `path` 各段連接為 `s[0..i-1] + s[i..j] = s[0..j]`，正是 `dfs(j+1)` 所要求的。回溯時 pop，恢復原狀。
- 終止：$i = n$ 時各段連接恰為整個 `s`，故 `path` 是一個合法劃分。

**不重不漏（劃分 ↔ 切點集合的雙射）。** 一個劃分完全由它的切點集合決定：段的邊界是 $0 = b_0 < b_1 < \cdots < b_m = n$，中間的 $b_1, \dots, b_{m-1}$ 就是切點，取自 $\{1, \dots, n-1\}$。

- *不漏*：對任一合法劃分，其第一段是 `s[0..b_1-1]`，這個 $j = b_1 - 1$ 必定被 `dfs(0)` 的迴圈枚舉到（迴圈範圍 $j \in [0, n)$ 涵蓋所有可能的第一段結束位置）；遞迴地，每一段都被枚舉到。
- *不重*：兩條不同路徑必在某一層取了不同的 $j$，於是對應劃分的該段長度不同，是兩個不同的劃分。反之同一個劃分只對應唯一一條路徑，因為各段的結束位置是它的固有屬性。

因此路徑與劃分一一對應，至多 $2^{n-1}$ 條。

**「合法性檢查放在哪裡」是本節唯一真正的設計決策。** 兩種寫法：

1. **在 push 之前檢查**（提前剪枝）：`if (!ok(i, j)) continue;`。不合法的段直接跳過，整棵子樹不展開。
2. **走到底再檢查**：把所有切法列出來再過濾。

兩者答案相同，但第一種的剪枝是**指數級**的收穫，不是常數優化。以 131 為例，若 `s = "aaaa...a"` 之外的一般字串，非回文的段往往在很淺的層就出現，提前剪枝直接砍掉整棵子樹。**設計時應該永遠選第一種**，並確認 `ok(i, j)` 判斷的是「這一段本身合法」而不涉及後續——若條件跨段（例如 1593 要求所有段互異），就得把「已用過的段」放進一個集合並在回溯時移除。

**93 的長度剪枝的正確性。** 剩下 `n - i` 個字元、還要切 `4 - seg` 段，每段長度在 $[1, 3]$。若 $n - i > 3(4 - \text{seg})$ 或 $n - i < 4 - \text{seg}$，則無論怎麼切都湊不出來，可直接剪枝。**這是一個必要條件的檢查：不滿足它一定無解，滿足它未必有解**——剪枝只要求前者，這就夠了。這類「剩餘量 vs 剩餘容量」的剪枝在劃分型與組合型中反覆出現。

**回文預處理不改變雙射，只改變每個節點的工作量。** 131 若每次現算 `isPalindrome(i, j)` 是 $O(n)$，總複雜度多乘一個 $n$；先用 $O(n^2)$ 的 DP 預處理 `pal[i][j]` 後，每次判斷 $O(1)$。這是「每節點工作量」這一項的優化，與剪枝是兩件不同的事，別混為一談。

## C++17 模板

```cpp
// 分割回文串（LeetCode 131）：劃分型回溯 + O(1) 回文判定。
class Solution {
    std::string s_;
    std::vector<std::vector<bool>> pal_;  // pal_[i][j]: s[i..j] 是否回文
    std::vector<std::string> path_;
    std::vector<std::vector<std::string>> ans_;

    // 契約：s_[0..i-1] 已切好，請枚舉 s_[i..] 的所有合法切法。
    void dfs(int i) {
        int n = s_.size();
        if (i == n) {  // 整串用完，path_ 是一個完整劃分
            ans_.push_back(path_);
            return;
        }
        for (int j = i; j < n; ++j) {  // 枚舉這一段的結束位置
            if (!pal_[i][j]) {
                continue;
            }  // 提前剪枝：整棵子樹不展開
            path_.push_back(s_.substr(i, j - i + 1));
            dfs(j + 1);  // 下一段從 j + 1 開始
            path_.pop_back();
        }
    }

public:
    std::vector<std::vector<std::string>> partition(std::string s) {
        s_ = std::move(s);
        int n = s_.size();
        pal_.assign(n, std::vector<bool>(n, true));
        for (int i = n - 1; i >= 0; --i) {  // 由內往外遞推，O(n^2) 預處理
            for (int j = i + 1; j < n; ++j) {
                pal_[i][j] = (s_[i] == s_[j]) && pal_[i + 1][j - 1];
            }
        }
        dfs(0);
        return ans_;
    }
};
```

## 時間與空間複雜度

遞迴樹的葉節點與合法劃分一一對應，至多 $2^{n-1}$ 個；內部節點同階。

131：每個節點的迴圈是 $O(n)$，回文判定 $O(1)$（預處理後），葉節點複製 `path` 是 $O(n)$。總計 $O(n \cdot 2^n)$，預處理 $O(n^2)$ 被吸收。若不預處理，回文判定 $O(n)$ 使總時間變成 $O(n^2 \cdot 2^n)$。

93：段數固定為 4，切點只有 $\binom{n-1}{3}$ 種組合，且每段長度 $\le 3$，實際搜尋空間是 $O(3^4) = O(1)$ 級——**段數固定時複雜度與 $n$ 幾乎無關**，這與段數自由的 131 是完全不同的量級。看到「固定切成 $k$ 段」就該意識到指數退化成 $O(\binom{n}{k})$。

空間：`path` $O(n)$、`pal` $O(n^2)$、遞迴堆疊 $O(n)$，不計輸出。

## 常見錯誤與邊界條件

- 遞迴傳 `j` 而非 `j + 1`（段會重疊或無限遞迴）。
- 終止條件寫成 `i >= n` 卻在 `i > n` 時也收集（段數固定的題目會多收）。
- 93 只檢查 $i = n$ 而忘記檢查段數 = 4（或反之），兩個條件缺一不可。
- 93 的前導零未處理（`"01"` 非法，但 `"0"` 合法）。
- 93 未做長度剪枝導致大量無效展開。
- 131 每次現算回文而複雜度多一個 $n$。
- 跨段條件（1593 的段互異）用集合維護時忘記在回溯移除。
- `substr` 的長度參數寫成 `j - i`（少一個字元）。
- 空字串輸入。
- 1849 這類要比較數值大小的題目，段長超過 `long long` 範圍要提前剪枝。

## 與相似技巧的比較

- 與 4.2 的子集型：劃分型 = 切點集合的子集枚舉，所以複雜度是 $2^{n-1}$ 而非 $2^n$。骨架相同，但**狀態的含義不同**——子集型的 `start` 是候選下界，劃分型的 $i$ 是已消耗的前綴長度。
- 與 4.4 的組合型：93 這種「固定切成 $k$ 段」的劃分，就是「從 $n-1$ 個切點中選 $k-1$ 個」的組合型，兩者的長度剪枝形式一模一樣。
- 與 DP：140（單詞拆分 II）要列出所有拆法，只能回溯；139（單詞拆分，只問能不能）用 DP $O(n^2)$。**「要所有方案」與「要一個布林／最佳值」的分界線在這裡最清晰。** 若題目問「最少切幾段」，用 DP；問「有哪些切法」，用回溯。
- 140 可以用「記憶化 + 回溯」的混合：先用 DP 算出 `canBreak[i]`（後綴 $i$ 能否被拆分），在回溯時用它剪枝。這樣能避免在注定失敗的後綴上浪費指數時間，是劃分型最有效的剪枝形式之一。
- 與 string 主題的回文相關演算法（Manacher）：131 的 $O(n^2)$ 回文預處理已足夠（它被指數項吸收），不需要更快的演算法。

## 本節重點速查

- 劃分型 = **選切點**，故方案數是 $2^{n-1}$。
- 契約：「`dfs(i)` 表示 `s[0..i-1]` 已切好」，迴圈枚舉這一段的**結束位置** $j$，遞迴傳 **`j + 1`**。
- 不變量是「`path` 各段連接 = `s[0..i-1]`」。
- 合法性檢查必須放在 push **之前**（指數級剪枝），而非事後過濾。
- 段數固定時（93）要同時檢查「用完字串」與「段數正確」，並用「剩餘字元 vs 剩餘段數×段長上下界」剪枝。
- 要所有方案用回溯，要最佳值用 DP。
