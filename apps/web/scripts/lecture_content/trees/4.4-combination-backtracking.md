## 這個技術解決什麼問題

組合型回溯處理「**從 $n$ 個候選中選出恰好 $k$ 個**」以及它的近親「選出若干個使某個量恰好達標」：77（組合）、216（組合總和 III）、22（括號生成）、301（刪除無效的括號）、1286（字母組合迭代器）。

它與 4.2 子集型的骨架相同，多了一個**大小約束**。這個約束不只是終止條件，更是**剪枝的來源**：當「還需要選的個數」超過「還剩下的候選個數」時，整棵子樹必然無解，可以直接砍掉。$\binom{n}{k}$ 相對於 $2^n$ 可以小非常多（$n = 20, k = 3$ 時 1140 對上 $10^6$），這個剪枝把差距真的兌現出來。

**延伸講解**：[回溯算法套路②組合型回溯＋剪枝【基礎演算法精講 15】](https://www.bilibili.com/video/BV1xG4y1F7nC/)

## 狀態／資料結構定義

**77（從 $1..n$ 中選 $k$ 個）：**

- `dfs(start)`：`path` 已選好若干個且下標嚴格遞增，下一個只能從 `start` 開始挑。
- 終止條件：`path.size() == k` 時收集並**立即回傳**（不再往下）。
- 剪枝：剩餘候選數 `n - j + 1` 必須 $\ge$ 還需要的個數 `k - path.size()`。

**22（括號生成）：** 狀態不是「選哪些」而是兩個計數器。

- `dfs(open, close)`：已放 `open` 個左括號、`close` 個右括號。
- 選擇列表：放左括號（條件 `open < n`）、放右括號（條件 `close < open`）。
- 終止條件：`open == close == n`。

兩者看起來不同，其實都是「在約束下枚舉固定長度的序列」。**22 的狀態之所以是 `(open, close)` 而不是位置下標，是因為合法性只取決於這兩個計數，與具體排列無關**——認出這一點是解 22 的關鍵。

## 不變量或正確性證明

**77 的剪枝正確性。** 在 `dfs(start)` 中枚舉 $j$，若選了 $j$，則剩下的必須從 $\{j+1, \dots, n\}$ 中選出 $k - |\text{path}| - 1$ 個。可用候選數是 $n - j$。故有解的**必要條件**是
$$n - j \ge k - |\text{path}| - 1 \quad\Longleftrightarrow\quad j \le n - (k - |\text{path}|) + 1 .$$
超過這個上界的 $j$ 一定湊不滿 $k$ 個，可以整批跳過——直接把迴圈上界設成 $n - (k - |\text{path}|) + 1$。

注意這是必要條件而非充分條件：滿足它未必真的有解（例如 216 還有和的限制）。**剪枝只需要必要條件**，這一點在所有搜尋問題中通用：剪掉的必須確定無解，留下的不保證有解。

這個剪枝把複雜度從「遍歷子集型的部分遞迴樹」壓成「恰好 $\binom{n}{k}$ 個葉節點加上同階的內部節點」。沒有剪枝時，程式會展開大量最終長度不足 $k$ 的分支，白白浪費。

**216 的雙向剪枝。** 從 $1..9$ 中選 $k$ 個不同數字使和為 $n$。除了上面的個數剪枝，還有和的剪枝：

- 若當前和已 $>$ 目標，剪（依賴**所有候選為正**）。
- 若「當前和 + 剩下能取的最大值之和」$<$ 目標，剪。
- 若「當前和 + 剩下能取的最小值之和」$>$ 目標，剪。

三條都是必要條件的檢查，且第一條的正確性明確依賴正數前提，與 4.2 中 39 的情形相同。

**22 的不變量：任何時刻 `open >= close`，且最終序列的每個前綴都滿足「左括號數 $\ge$ 右括號數」。**

這正是括號序列合法的充要條件（配合總數相等）。證明合法性判定的充要性：

- ($\Rightarrow$) 合法序列中，任一前綴的每個右括號都必須有一個在它之前的左括號與之配對，且配對互不重複，故左括號數 $\ge$ 右括號數。
- ($\Leftarrow$) 若每個前綴都滿足此條件且總數相等，則用「棧」掃描時每遇到右括號棧必非空，掃完棧必空，故合法。

因此把「放右括號」的條件寫成 `close < open`，恰好維持了這個不變量。**不重不漏**：每個合法序列對應唯一一條路徑（第 $t$ 步放的是哪種括號是序列的固有屬性），每條路徑對應唯一一個合法序列。

這個做法的精髓是**「只生成合法的」而非「生成全部再過濾」**：後者要枚舉 $\binom{2n}{n}$ 個序列，前者只走 $C_n = \frac{1}{n+1}\binom{2n}{n}$ 個葉節點（卡塔蘭數）。兩者相差 $n+1$ 倍——不算驚人，但更重要的是它示範了「把可行性條件編進選擇列表」這個通用技巧，在別的題目上能省下指數級的工作。

**301（刪除無效的括號）的層級搜尋。** 要刪最少的字元使括號合法。做法是先掃一遍算出必須刪的左、右括號數 $(l, r)$，再回溯枚舉刪哪些，只在恰好刪掉 $l + r$ 個且結果合法時收集。這裡的剪枝關鍵是「剩餘字元數 $<$ 還要刪的字元數就返回」，以及對連續相同字元只在第一個位置嘗試刪除（否則會生成重複結果，理由與 4.6 的去重完全相同）。

## C++17 模板

```cpp
// 組合（LeetCode 77）：從 1..n 選 k 個，帶個數剪枝。
class Solution {
    int n_ = 0, k_ = 0;
    std::vector<int> path_;
    std::vector<std::vector<int>> ans_;

    void dfs(int start) {
        int need = k_ - static_cast<int>(path_.size());  // 還需要選幾個
        if (need == 0) {
            ans_.push_back(path_);
            return;  // 湊滿就停，不再往下
        }
        // 剪枝：j 太大時剩餘候選 n_ - j 不足以湊滿 need - 1 個
        for (int j = start; j <= n_ - need + 1; ++j) {
            path_.push_back(j);
            dfs(j + 1);  // 保證嚴格遞增
            path_.pop_back();
        }
    }

public:
    std::vector<std::vector<int>> combine(int n, int k) {
        n_ = n;
        k_ = k;
        path_.reserve(k);
        dfs(1);
        return ans_;
    }
};
```

```cpp
// 括號生成（LeetCode 22）：把合法性編進選擇列表，只生成合法序列。
class Solution {
    int n_ = 0;
    std::string path_;
    std::vector<std::string> ans_;

    void dfs(int open, int close) {
        if (close == n_) {  // 右括號放滿 → 左括號也必然放滿
            ans_.push_back(path_);
            return;
        }
        if (open < n_) {  // 還能放左括號
            path_.push_back('(');
            dfs(open + 1, close);
            path_.pop_back();
        }
        if (close < open) {  // 不變量：任何前綴 open >= close
            path_.push_back(')');
            dfs(open, close + 1);
            path_.pop_back();
        }
    }

public:
    std::vector<std::string> generateParenthesis(int n) {
        n_ = n;
        path_.reserve(2 * n);
        dfs(0, 0);
        return ans_;
    }
};
```

## 時間與空間複雜度

77：葉節點數 $\binom{n}{k}$，內部節點同階（有剪枝時，每個內部節點至少能長出一個葉節點）。每個葉節點複製長度 $k$ 的 `path`。時間 $O\!\left(k \binom{n}{k}\right)$，空間 $O(k)$ 不計輸出。

**沒有剪枝時**內部節點數退化到 $O(2^n)$ 級（會展開大量長度不足的分支），差距在 $k \ll n$ 時極大。這是本節剪枝的實際價值。

216：候選只有 $1..9$，搜尋空間上界 $\binom{9}{k} \le 126$，實際更小。

22：葉節點數為卡塔蘭數 $C_n = \frac{1}{n+1}\binom{2n}{n} = O(4^n / n^{1.5})$，每個葉節點複製長度 $2n$ 的字串，時間 $O\!\left(\frac{4^n}{\sqrt n}\right)$。

301：最壞 $O(2^n)$（每個字元刪或不刪），但「必須刪的字元數固定」與去重剪枝讓實際規模小很多。

## 常見錯誤與邊界條件

- 77 的迴圈上界寫成 `n`（沒剪枝，正確但慢）或寫錯成 `n - need`（少一個，漏解）。
- 湊滿 $k$ 個後忘記 `return`（會繼續往下，多做無用功甚至越界）。
- 遞迴傳 `start + 1` 而非 `j + 1`（重複）。
- 22 的右括號條件寫成 `close < n`（生成非法序列）。
- 22 的終止條件用 `path.size() == 2 * n` 也對，但用 `close == n` 更直接。
- 216 忘記「數字不重複」或「範圍 $1..9$」。
- 剪枝條件用了「和超過就剪」卻沒確認候選全為正。
- 301 對連續相同字元未去重（產生重複答案）。
- $k = 0$ 時應回傳一個空組合。
- $k > n$ 時應回傳空。

## 與相似技巧的比較

- 與 4.2 的子集型：組合型 = 子集型 + 大小約束。**約束帶來的剪枝是主要價值**，別只把它當成一個 `if`。
- 與 4.3 的劃分型：93（固定切成 4 段）就是組合型——從 $n-1$ 個切點中選 3 個，剪枝形式相同。
- 與 4.5 的排列型：組合不計順序（用 `start` 保證遞增），排列計順序。同樣是「`start` 在不在」的差別。
- 與 4.6：若候選中有重複元素（40 組合總和 II），要加上 4.6 的去重規則。
- 與數學公式：只問「有幾種組合」而不問是什麼，直接算 $\binom{n}{k}$，不要枚舉。**回溯只在需要列出方案時使用。**
- 1286（字母組合迭代器）要求「按字典序逐個吐出」，可以預先回溯生成全部再逐個回傳（簡單，空間 $O(\binom{n}{k})$），也可以維護當前組合並實作「下一個組合」的迭代（空間 $O(k)$）。後者本質上是把遞迴展開成迭代，值得練。

## 本節重點速查

- 組合型 = 子集型 + 大小約束，方案數 $\binom{n}{k}$。
- **核心剪枝：迴圈上界取 `n - need + 1`**，其中 `need = k - path.size()`——這是「剩餘候選不足以湊滿」的必要條件。
- 剪枝只需必要條件，剪掉的必須確定無解。
- 22 示範另一種形態：**把可行性條件編進選擇列表**（右括號的條件是 `close < open`），只生成合法方案，其依據是「合法括號序列 ⟺ 每個前綴左 $\ge$ 右且總數相等」。
- 湊滿之後記得 `return`。
