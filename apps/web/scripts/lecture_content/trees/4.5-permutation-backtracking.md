## 這個技術解決什麼問題

排列型回溯枚舉「**所有元素的所有排列順序**」：46（全排列）、51/52（N 皇后）、37（解數獨）、1718、1307。

與子集／組合的差別只有一句話：**順序有意義**。子集用 `start` 強制下標遞增，把 $k!$ 種順序壓成一種；排列不能用 `start`，每一層都必須從**所有還沒用過的元素**中挑，因此需要一個 `used` 標記。

排列型的方案數是 $n!$，比 $2^n$ 增長得快得多（$n = 10$ 時 $10! \approx 3.6\times10^6$，$n = 12$ 時已近 $5\times10^8$）。因此**排列型題目幾乎都以剪枝為主戰場**——N 皇后與數獨的全部難度都在「如何快速判斷衝突並提早放棄」。

## 狀態／資料結構定義

**46（全排列）：**

- `path`：當前已排好的前綴。
- `used[i]`：元素 $i$ 是否已在 `path` 中。這是取代 `start` 的東西。
- `dfs(i)`：已填好前 $i$ 個位置，請枚舉剩下的。終止條件 $i = n$。

**51（N 皇后）：** 一列一列地放，本質上是在枚舉「列 → 行」的排列。

- `col[r]`：第 $r$ 行是否已有皇后。
- `diag1[r + c]`：主對角線（左上到右下）佔用標記，長度 $2n - 1$。
- `diag2[r - c + n - 1]`：副對角線佔用標記，長度 $2n - 1$。
- `dfs(c)`：前 $c$ 列已放好，請放第 $c$ 列。

**37（解數獨）：** 三組標記 `row[9][9]`、`col[9][9]`、`box[9][9]`，配合「找下一個空格」的遞迴。它與 46/51 的差別是**只要找到一組解就回傳**，因此遞迴函式回傳 `bool`，一旦成功就沿途 `return true`，不再回溯。

## 不變量或正確性證明

**46 的不變量：進入 `dfs(i)` 時，`path` 的長度為 $i$，且 `used` 恰好標記 `path` 中出現的那些元素——不多不少。**

「不多不少」是雙向的：`used[j] == true` $\iff$ 元素 $j$ 在 `path` 中。這由 push 時設 `true`、pop 時設 `false` 的嚴格配對保證。少了任一半都會出錯：漏設 `true` 會產生重複使用同一元素的非法「排列」；漏設 `false` 會讓兄弟分支誤以為元素已用完，漏解。

**不重不漏（排列 ↔ 根到葉路徑的雙射）。** 一條根到葉的路徑記錄了「第 0 位填誰、第 1 位填誰、……」，這正是一個排列的定義。不同路徑在某一層填了不同元素，故是不同排列；同一個排列只對應唯一一條路徑。葉節點數為 $n \times (n-1) \times \cdots \times 1 = n!$。

**為什麼不能用 `start`。** 若用 `start` 限制「只能挑下標 $\ge \text{start}$ 的元素」，則 `[2,1]` 這個排列永遠生成不出來（選了下標 1 之後不能回頭選下標 0）。`start` 的作用正是「消除順序」，那與排列的目標相反。這也解釋了為什麼排列型的分支數是 $n, n-1, \dots$ 而不是遞減到某個下界——每層都要掃全部 $n$ 個元素（其中已用的被 `used` 跳過）。

**51 的對角線編號為何是 `r + c` 與 `r - c`。**

兩個格子 $(r_1, c_1)$、$(r_2, c_2)$ 在同一條主對角線（往右下走，行與列同增）$\iff r_1 - c_1 = r_2 - c_2$；在同一條副對角線（往右上走，行減列增）$\iff r_1 + c_1 = r_2 + c_2$。

證明：沿主對角線移動一步是 $(r, c) \to (r+1, c+1)$，$r - c$ 不變；反之若 $r_1 - c_1 = r_2 - c_2$，令 $d = r_2 - r_1 = c_2 - c_1$，則從 $(r_1,c_1)$ 走 $d$ 步斜線可達 $(r_2,c_2)$。副對角線同理。

$r + c$ 的範圍是 $[0, 2n-2]$，可直接當下標；$r - c$ 的範圍是 $[-(n-1), n-1]$，**必須加上偏移量 $n-1$** 才能當下標。這個偏移是實作上最常見的越界來源。

有了這三組標記，「這格能不能放」是 $O(1)$ 判斷，取代了 $O(n)$ 的掃描——這是把 $O(n! \cdot n)$ 降到 $O(n!)$ 的關鍵。

**逐列放置為何不漏解。** 每列恰有一個皇后（否則某兩個皇后同列，衝突），所以「逐列放置、每列選一行」涵蓋了所有合法佈局。這一步把搜尋空間從 $\binom{n^2}{n}$ 降到 $n^n$，再由 `col` 標記降到 $n!$。**這三個數字的落差全部來自把約束編進枚舉方式，而不是編進事後檢查**——與 4.4 的括號生成是同一個道理。

**37 的「回傳 bool」與純枚舉的差別。** 數獨只要一組解，遞迴應寫成 `bool dfs()`：找到解時 `return true`，呼叫端收到 `true` 就立刻 `return true`，**不執行撤銷**（因為棋盤上的解要保留）。若寫成 `void` 並繼續搜尋，會把已找到的解撤銷掉。這是排列型裡最容易寫錯的一處：**「找一組解」與「列出所有解」的回溯骨架不同，撤銷的時機也不同。**

## C++17 模板

```cpp
// 全排列（LeetCode 46）：用 used 取代 start。
class Solution {
    std::vector<int> nums_, path_;
    std::vector<bool> used_;
    std::vector<std::vector<int>> ans_;

    void dfs(int i) {
        int n = nums_.size();
        if (i == n) {
            ans_.push_back(path_);
            return;
        }
        for (int j = 0; j < n; ++j) {  // 每層都掃全部，不能用 start
            if (used_[j]) {
                continue;
            }
            used_[j] = true;
            path_.push_back(nums_[j]);
            dfs(i + 1);
            path_.pop_back();
            used_[j] = false;  // 與設 true 嚴格配對
        }
    }

public:
    std::vector<std::vector<int>> permute(std::vector<int>& nums) {
        nums_ = nums;
        used_.assign(nums_.size(), false);
        path_.reserve(nums_.size());
        dfs(0);
        return ans_;
    }
};
```

```cpp
// N 皇后（LeetCode 51）：逐列放置，三組 O(1) 衝突標記。
class Solution {
    int n_ = 0;
    std::vector<int> pos_;  // pos_[c] = 第 c 列的皇后在第幾行
    std::vector<bool> row_, diag1_, diag2_;  // r + c 與 r - c + n - 1
    std::vector<std::vector<std::string>> ans_;

    void dfs(int c) {
        if (c == n_) {
            std::vector<std::string> board(n_, std::string(n_, '.'));
            for (int i = 0; i < n_; ++i) {
                board[pos_[i]][i] = 'Q';
            }
            ans_.push_back(std::move(board));
            return;
        }
        for (int r = 0; r < n_; ++r) {
            if (row_[r] || diag1_[r + c] || diag2_[r - c + n_ - 1]) {
                continue;
            }
            row_[r] = diag1_[r + c] = diag2_[r - c + n_ - 1] = true;
            pos_[c] = r;
            dfs(c + 1);
            row_[r] = diag1_[r + c] = diag2_[r - c + n_ - 1] = false;
        }
    }

public:
    std::vector<std::vector<std::string>> solveNQueens(int n) {
        n_ = n;
        pos_.assign(n, 0);
        row_.assign(n, false);
        diag1_.assign(2 * n - 1, false);
        diag2_.assign(2 * n - 1, false);
        dfs(0);
        return ans_;
    }
};
```

## 時間與空間複雜度

46：葉節點 $n!$，每個葉節點複製長度 $n$ 的 `path`，內部節點的迴圈總量同階。時間 $O(n \cdot n!)$，空間 $O(n)$ 不計輸出。

51：搜尋樹的上界是 $n!$（每列選一行、行不重複），但對角線約束砍掉極多分支，實際節點數遠小於 $n!$（$n = 8$ 時只有約 2000 個節點，而 $8! = 40320$）。每個葉節點構造棋盤是 $O(n^2)$。**這是「剪枝改變的是常數與實際規模，不改變理論上界」的典型例子**——寫複雜度時應說「$O(n!)$ 上界，實際遠低」。

52 只數個數，省掉 $O(n^2)$ 的棋盤構造，快一個數量級。

37：理論上界是指數級（每格 9 種填法），實際靠三組標記與「優先填候選最少的格子」（最小剩餘值啟發式）在毫秒級完成。

$n$ 的規模：$n! $ 在 $n = 10$ 時 $3.6\times10^6$（可行），$n = 12$ 時 $4.8\times10^8$（勉強），$n = 13$ 起不可行。**看到 $n \le 10$ 左右且要求「所有順序」，就是排列型的訊號。**

## 常見錯誤與邊界條件

- `used[j] = false` 漏寫或位置錯（放在 `continue` 之後、`return` 之前的分支）。
- 用 `start` 寫排列（漏解）。
- 51 的副對角線下標忘記加偏移 $n-1$（越界或錯誤衝突）。
- 51 的對角線陣列開成長度 $n$ 而非 $2n-1$。
- 37 寫成 `void` 而在找到解後繼續搜尋並撤銷（棋盤被還原成空）。
- 37 的宮格編號寫成 `r / 3 + c / 3`（應為 `r / 3 * 3 + c / 3`）。
- 把 `path` 存成參考導致所有答案指向同一份。
- 輸入含重複元素時本節的雙射失效，須用 4.6 的規則。
- $n = 0$ 或 $n = 1$。
- 1307 這類把字母映射到數字的題目要處理前導零與「不同字母不同數字」兩個約束。

## 與相似技巧的比較

- 與 4.2／4.4：唯一差別是「有沒有 `start`」。有 `start` → 不計順序（子集／組合）；用 `used` → 計順序（排列）。
- 交換法（`swap(nums[i], nums[j])` 後遞迴再換回）是排列的另一種寫法，省掉 `used` 陣列與 `path`，常數更小。但它的**生成順序不是字典序**，且在有重複元素時去重規則完全不同（不能沿用 4.6 的寫法），初學建議用 `used` 版。
- 與 `std::next_permutation`：若只需按字典序逐個產生排列，標準庫的迭代版更短且空間 $O(1)$。**能用它就用它**，回溯的價值在於可以剪枝。
- 與狀壓 DP：$n!$ 個排列中，許多不同前綴會導向「已用集合相同」的等價狀態。若題目只問**最佳值或方案數**而非列出所有排列，就該把狀態壓成 `mask`（已用集合）並記憶化，$O(n! ) \to O(2^n \cdot n)$。2850（石頭分散）、1307 都可以這樣優化。**這是排列型最重要的一條升級路徑。**
- 與 3376、1718 這類「按某順序貪心 + 回溯驗證」的題目：搜尋順序（先試哪個分支）會大幅影響實際速度。優先嘗試「最可能成功」或「選項最少」的分支，是搜尋題的通用加速手段，見 4.7。

## 本節重點速查

- 排列 = 沒有 `start`、改用 **`used`**，不變量是「`used` 恰好標記 `path` 中的元素，不多不少」，靠 push/pop 與 true/false 嚴格配對。
- 方案數 $n!$，$n \le 10$ 左右才可行。
- N 皇后逐列放置，同一主對角線 $\iff r - c$ 相同、同一副對角線 $\iff r + c$ 相同，**`r - c` 當下標要加偏移 $n-1$**。
- 把約束編進枚舉方式（逐列、三組標記）而非事後檢查，是效率的來源。
- **「找一組解」要用 `bool` 回傳並在成功時不撤銷**，與「列出所有解」的骨架不同。
- 只問最佳值時改用狀壓 DP。
