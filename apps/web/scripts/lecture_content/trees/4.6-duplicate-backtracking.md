## 這個技術解決什麼問題

前面幾節的不重不漏，全部建立在「同一層的選項兩兩互異」這個前提上。一旦輸入含重複元素（`[1,1,2]`），前提破裂：同一層會出現兩個相同的選項，於是同一個答案被生成多次。40（組合總和 II）、47（全排列 II）、90（子集 II）、491（非遞減子序列）、1079（活字印刷）都是這個形狀。

最省事的做法是「全部生成後用 `set` 去重」，但那要付出「生成重複答案」的指數級浪費加上比較的開銷。本節要做的是**在搜尋時就不生成重複**——代價只是一次排序加一行 `if`。

思路統一成一句話：**為每個答案指定一個唯一的「標準生成方式」，只允許沿著標準方式走，其餘剪掉。**

## 狀態／資料結構定義

前提：**先排序**，讓相等元素在下標上相鄰。排序是所有去重規則的共同基礎。

**子集／組合型（90、40）：**

- 沿用 4.2 視角二的 `dfs(start)`。
- 去重規則：`if (j > start && a[j] == a[j - 1]) continue;`
- 條件是 `j > start`，**不是 `j > 0`**。這個差別是本節的核心。

**排列型（47）：**

- 沿用 4.5 的 `used[]`。
- 去重規則：`if (j > 0 && a[j] == a[j - 1] && !used[j - 1]) continue;`

**491（非遞減子序列，不可排序）：**

- 題目要求保持原順序，**不能排序**，所以上面的規則失效。
- 改用「同一層用過的值集合」：在每個 `dfs` 內開一個區域的 `unordered_set<int> seen`，同一層遇到用過的值就跳過。這是最通用但常數最大的做法。

## 不變量或正確性證明

**子集型規則的正確性。** 設排序後有一段相等元素 $a_p = a_{p+1} = \cdots = a_q$。從這段裡選 $t$ 個，不同的下標選法有 $\binom{q-p+1}{t}$ 種，但它們對應**同一個多重集**，因此只該保留一種。

規則 `j > start && a[j] == a[j-1] → skip` 的效果是：在同一層（同一個 `start`）中，這段相等元素只有**第一個**（$j = \text{start}$，或前一個元素與它不等的那個 $j$）會被選；後續的 $j$ 全部跳過。而遞迴進入 `dfs(j + 1)` 之後 `start` 變成 $j+1$，此時 $j+1$ 位置的元素若仍相等，它的 `j > start` 為假，**可以被選**。

因此被允許的選法恰是「**從這段中取最前面的 $t$ 個**」，這是每個多重集的唯一標準表示。故每個答案生成恰一次：

- *不重*：兩條不同路徑對應的下標序列不同；由於只允許取前綴式的下標，不同下標序列必對應不同多重集。
- *不漏*：任一多重集都有其標準表示（各段取最前面若干個），而該表示對應的路徑沒有被規則剪掉。

**為什麼是 `j > start` 而不是 `j > 0`。** 用 `j > 0` 會把「$j$ 恰為 `start` 且 $a_j = a_{j-1}$」的情形也剪掉——但那個 $a_{j-1}$ 是**上一層剛選走的元素**，不是同一層的兄弟。剪掉它就無法選出含兩個相同元素的答案，`[1,1]` 這種解會消失。**`j > start` 精確地表達「同一層的第二個及之後的相同選項」**，一個字元之差就是漏解與正確的差別。

**排列型規則的正確性。** 對相等元素，我們指定的標準生成方式是「**按下標由小到大依次使用**」：即 $a_{j-1}$ 必須在 $a_j$ 之前被放入 `path`。

- 條件 `a[j] == a[j-1] && !used[j-1]` 表示「要放 $a_j$，但與它相等的前一個 $a_{j-1}$ 還沒被用」——這違反標準順序，剪掉。
- 反之若 `used[j-1]` 為真，表示 $a_{j-1}$ 已在 `path` 中，現在放 $a_j$ 符合標準順序，允許。

*不重*：每個排列（作為值序列）在標準順序下只有唯一一種下標指派方式（相等元素按下標遞增依次填入各自出現的位置），故只被生成一次。
*不漏*：任一值序列的標準下標指派都不會被剪掉。

**`!used[j-1]` 與 `used[j-1]` 都能去重，但前者更快。** 若寫成 `used[j-1]` 為剪枝條件，等於規定「相等元素按下標由大到小使用」，同樣是一種標準順序，答案也對。差別在於剪枝發生的時機：`!used[j-1]` 在**這一段相等元素的第一個之後就立刻剪**，被剪的子樹更靠上、更大；`used[j-1]` 則要等到已經深入才剪。實測差距明顯。**兩者都對，但預設寫 `!used[j-1]`。**

**491 為何不能排序。** 題目要求子序列保持原陣列順序，排序會改變答案本身。此時「相等元素相鄰」的前提不成立，前述規則失效。改用「同一層 `seen` 集合」的規則，其正確性依據是：同一層中選了值相同的兩個不同下標，會生成完全相同的後續子樹（因為後續只依賴「已選序列的值」與「起始下標」——注意這裡起始下標其實不同，所以嚴格說是「後者的子樹是前者的子集」），故只保留第一個即可，不會漏解。**這條論證比排序版弱，成立的原因是「更靠後的起始下標所能生成的答案是更靠前者的子集」**，遇到不符合這個性質的題目就不能照搬。

## C++17 模板

```cpp
// 子集 II（LeetCode 90）：排序 + 同層跳過重複。
class Solution {
    std::vector<int> nums_, path_;
    std::vector<std::vector<int>> ans_;

    void dfs(int start) {
        ans_.push_back(path_);
        for (int j = start; j < static_cast<int>(nums_.size()); ++j) {
            // j > start：只跳過「同一層」的第二個及之後的相同選項
            if (j > start && nums_[j] == nums_[j - 1]) {
                continue;
            }
            path_.push_back(nums_[j]);
            dfs(j + 1);
            path_.pop_back();
        }
    }

public:
    std::vector<std::vector<int>> subsetsWithDup(std::vector<int>& nums) {
        nums_ = nums;
        std::sort(nums_.begin(), nums_.end());  // 去重的前提
        dfs(0);
        return ans_;
    }
};
```

```cpp
// 全排列 II（LeetCode 47）：排序 + 相等元素按下標遞增使用。
class Solution {
    std::vector<int> nums_, path_;
    std::vector<bool> used_;
    std::vector<std::vector<int>> ans_;

    void dfs() {
        if (path_.size() == nums_.size()) {
            ans_.push_back(path_);
            return;
        }
        for (int j = 0; j < static_cast<int>(nums_.size()); ++j) {
            if (used_[j]) {
                continue;
            }
            // 與前一個相等且前一個還沒用 → 違反「按下標遞增使用」的標準順序
            if (j > 0 && nums_[j] == nums_[j - 1] && !used_[j - 1]) {
                continue;
            }
            used_[j] = true;
            path_.push_back(nums_[j]);
            dfs();
            path_.pop_back();
            used_[j] = false;
        }
    }

public:
    std::vector<std::vector<int>> permuteUnique(std::vector<int>& nums) {
        nums_ = nums;
        std::sort(nums_.begin(), nums_.end());
        used_.assign(nums_.size(), false);
        dfs();
        return ans_;
    }
};
```

## 時間與空間複雜度

排序 $O(n \log n)$，被後面的指數項吸收。

90：不同子集的個數是 $\prod_i (c_i + 1)$，其中 $c_i$ 是第 $i$ 種值的出現次數。全部互異時退化為 $2^n$；全部相同時只有 $n+1$ 個。時間 $O(n \cdot \prod_i (c_i + 1))$。

47：不同排列的個數是多重集排列數 $\dfrac{n!}{\prod_i c_i!}$。時間 $O\!\left(n \cdot \dfrac{n!}{\prod_i c_i!}\right)$。

**去重規則的價值就是把複雜度從「所有下標選法」降到「所有不同答案」。** 以 `[1,1,1,1,1,1,1,1]`（8 個 1）為例，$8! = 40320$ 對上 1 個——這不是常數優化。

491 的 `seen` 版每層多一個雜湊表，常數較大；若值域小可改用固定大小的布林陣列或 `bitset`。

空間：$O(n)$ 不計輸出。

## 常見錯誤與邊界條件

- **忘記排序**（規則完全失效，仍會產生重複）。
- 子集型寫成 `j > 0`（漏掉含重複元素的答案，例如 `[1,1]`）。
- 排列型寫成 `!used[j]`（拼字錯，變成恆真）。
- 排列型漏掉 `j > 0` 的邊界檢查（`nums_[-1]` 越界）。
- 491 誤加排序（改變題意）。
- 491 的 `seen` 宣告成全域或成員（跨層污染，會漏解——它必須是**每層各一份**的區域變數）。
- 40 的「每個元素只能用一次」與 39 的「可重複使用」混淆（前者傳 `j + 1`，後者傳 `j`）。
- 1079 需要的是「不同排列的個數」而非列出，用計數版回溯或多重集排列公式更快。
- 輸入為空。

## 與相似技巧的比較

- 與 4.2／4.4／4.5：本節是它們三個的補丁，骨架完全不變，只多一行 `if` 與一次排序。**先把無重複版寫對，再套規則。**
- **「換一種枚舉方式」常常比去重規則更清爽**：把輸入整理成「值 → 出現次數」的計數表，然後對每個不同的值枚舉「用幾個」（$0$ 到 $c_i$）。這樣同一層的選項天然互異，完全不需要去重規則。1079（活字印刷）用計數版寫出來比用 47 的規則短且快。遇到重複元素多的題目，優先考慮這個角度。
- 與事後 `set` 去重：正確但慢。它的問題不只是比較開銷，而是**仍然生成了指數多的重複答案**——複雜度沒有降。只有在去重規則實在寫不出來時才用。
- 與 3646（下一個特殊迴文數）：這類「按位構造且各數字有使用次數上限」的題目，計數版枚舉幾乎是唯一合理的寫法。
- 與 2014（重複 K 次的最長子序列）：去重之外還要配合「候選子序列按長度與字典序降序枚舉，第一個可行的就是答案」的搜尋順序設計，屬於 4.7 的範疇。

## 本節重點速查

- 統一思路：**為每個答案指定唯一的標準生成方式，只走標準路徑**。
- 前提是**先排序**。
- 子集／組合：`if (j > start && a[j] == a[j-1]) continue;`——**是 `j > start` 不是 `j > 0`**，因為要剪的是同層兄弟，不是上一層剛選走的元素。
- 排列：`if (j > 0 && a[j] == a[j-1] && !used[j-1]) continue;`——規定相等元素按下標遞增使用；
- `used[j-1]` 版也對但剪得晚。
- 不能排序時（491）改用**每層一份**的 `seen` 集合。
- 重複元素多時，改用「值 → 用幾個」的計數式枚舉，天然無重複，通常更好寫。
