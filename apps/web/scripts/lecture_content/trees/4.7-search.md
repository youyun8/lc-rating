## 這個技術解決什麼問題

前面幾節的回溯有固定的形狀（子集、劃分、組合、排列）。本節收的是**沒有固定形狀的搜尋**：在網格上找單詞（79、212）、把火柴分成四堆（473）、給表達式加運算子（282）、24 點（679）、貼紙拼詞（691）。

它們的共同點是：狀態不是一個簡單的下標，而是「棋盤／剩餘資源／已用集合」；搜尋空間巨大到必須靠剪枝才能通過。因此本節的重點不在骨架（骨架就是 4.1 的回溯），而在**四件讓搜尋真的跑得完的事**：狀態設計、可行性剪枝、搜尋順序、記憶化。

## 狀態／資料結構定義

**79（單詞搜尋）：**
- `dfs(r, c, k)`：當前站在格子 $(r, c)$，要匹配 `word[k]`。
- `vis[r][c]`：**當前路徑**上已走過的格子。注意它的語意是「路徑」而不是「曾經訪問過」——這是搜尋與 BFS/連通性 DFS 的分水嶺。
- 也可以不開 `vis`，改成把 `board[r][c]` 暫時改成 `'#'`，回溯時改回來（省一個陣列）。

**473（火柴拼正方形）：**
- `side[4]`：四條邊當前的長度。
- `dfs(i)`：前 $i$ 根火柴已分配，請分配第 $i$ 根。
- 這是「把物品分到 $k$ 個箱子」的通用形狀，狀態是**箱子的當前狀態**而非「選了哪些物品」。

**691（貼紙拼詞）／1601（換樓請求）：**
- 狀態壓縮：`mask` 表示目標字串中哪些位置已被覆蓋。狀態數 $2^n$，適合記憶化。

**212（單詞搜尋 II）：**
- 把所有待搜單詞建成 Trie，搜尋時同步在 Trie 上走。**狀態多一維「當前 Trie 節點」**，讓「所有單詞一起搜」成為可能。

## 不變量或正確性證明

**79 的不變量：進入 `dfs(r, c, k)` 時，`vis` 恰好標記了從起點到 $(r,c)$ 的這條路徑上的所有格子（含 $(r,c)$），且這條路徑對應 `word[0..k]`。**

「恰好」再次是雙向的，靠設 `true` 與設 `false` 的嚴格配對維持。**與圖的連通性 DFS 的差別在這裡最關鍵**：連通性 DFS 的 `vis` 一旦設 `true` 就永不還原（每個節點只訪問一次，$O(V+E)$）；路徑搜尋的 `vis` 必須還原，因為**同一個格子可以出現在不同的路徑上**。把兩者搞混是這類題最常見的錯誤：不還原會漏解，而且錯得很隱蔽（部分測資會過）。

這也解釋了複雜度的落差：連通性 DFS 是多項式的，路徑搜尋是指數的。**`vis` 還不還原，決定了演算法是多項式還是指數。**

**剪枝的通用要求：被剪的分支必須確定無解。** 這是必要條件，不是充分條件。逐一檢查本節的常見剪枝：

- 79 的 `board[r][c] != word[k]` → 這條路徑已經不匹配，往下不可能匹配。**成立**。
- 473 的「單根火柴長度 > 邊長」→ 它無論放哪條邊都超長。**成立**。
- 473 的「總和不能被 4 整除」→ 顯然無解。**成立**。
- 473 的「當前邊加上這根會超長就跳過」→ 該分支無解。**成立**（依賴火柴長度為正）。
- 473 的「若把火柴放進一條空邊失敗，就不必再試其他空邊」→ **這條需要論證**：所有空邊是對稱的（狀態完全相同），放進任一條空邊得到的子問題同構，故一條失敗則全部失敗。這是**對稱性剪枝**，威力極大但必須確認對稱性真的成立。
- 473 的「若某條邊剛好填滿後續失敗，直接回傳」→ 這條**不成立**，不能亂加。

**搜尋順序不影響正確性，但影響數量級。** 473 先把火柴**由大到小排序**再搜：大火柴的可放位置少，衝突提早暴露，錯誤分支在很淺的層就被砍掉。這不改變答案，只改變遞迴樹的形狀。同理 79 可以先統計 `word` 的首尾字元在棋盤上的出現次數，**若尾字元更少就把 `word` 反轉再搜**——起點少一個數量級，總時間就少一個數量級。

一般原則：**優先展開「選項最少」或「最可能失敗」的分支**（最小剩餘值啟發式）。這在數獨、N 皇后、火柴、24 點上都適用。

**何時該加記憶化。** 回溯與記憶化搜尋的界線是：**不同的路徑是否會到達「後續行為完全相同」的狀態**。

- 79：不會。狀態含整條路徑（`vis`），兩條不同路徑即使走到同一格，可用的後續格子也不同。**不能記憶化**。
- 691：會。狀態只有 `mask`（已覆蓋哪些位置），到達同一個 `mask` 之後的最少貼紙數與怎麼到達無關。**應該記憶化**，$O(2^n \cdot m \cdot n)$。
- 1601：`dfs(i, mask...)`，同理。

判準寫成一句話：**若「未來」只依賴一個小的狀態摘要，而不依賴完整路徑，就記憶化；否則就是純回溯。** 這與 4.1 提到的「DP vs 回溯」是同一條線，只是這裡的狀態通常需要壓縮才夠小。

**212 用 Trie 的收穫。** 樸素做法對每個單詞各跑一次 79，是 $O(W \cdot mn \cdot 4^L)$。建 Trie 後只跑一次 DFS，在每個格子同時推進所有單詞的匹配：若當前 Trie 節點沒有對應子節點，**所有以此為前綴的單詞一起被剪掉**。這是把「$W$ 次獨立搜尋」合併成「一次搜尋，共享前綴」——與回溯本身「共享前綴」的精神一致，只是共享的對象從路徑換成了模式串。實作上還要記得**找到一個單詞後把它從 Trie 上摘掉**（或標記），避免重複輸出。

## C++17 模板

```cpp
// 單詞搜尋（LeetCode 79）：路徑搜尋，vis 必須還原。
class Solution {
    std::vector<std::vector<char>> board_;
    std::string word_;
    int m_ = 0, n_ = 0;

    bool dfs(int r, int c, int k) {
        if (r < 0 || r >= m_ || c < 0 || c >= n_) {
            return false;
        }
        if (board_[r][c] != word_[k]) {
            return false;
        }  // 剪枝：已不匹配
        if (k + 1 == static_cast<int>(word_.size())) {
            return true;
        }

        char saved = board_[r][c];
        board_[r][c] = '#';  // 標記在「當前路徑」上
        static constexpr int kDir[4][2] = {{0, 1}, {0, -1}, {1, 0}, {-1, 0}};
        for (auto [dr, dc] : kDir) {
            if (dfs(r + dr, c + dc, k + 1)) {
                return true;
            }  // 找到就一路回傳
        }
        board_[r][c] = saved;  // 還原：換一條路徑還能再走
        return false;
    }

public:
    bool exist(std::vector<std::vector<char>>& board, std::string word) {
        board_ = board;
        m_ = board_.size();
        n_ = board_[0].size();
        // 搜尋順序優化：若尾字元比首字元罕見，反轉 word 可大幅減少起點數
        long long headCnt = 0, tailCnt = 0;
        for (const auto& row : board_) {
            for (char ch : row) {
                headCnt += (ch == word.front());
                tailCnt += (ch == word.back());
            }
        }
        word_ = (tailCnt < headCnt) ? std::string(word.rbegin(), word.rend())
                                    : word;

        for (int r = 0; r < m_; ++r) {
            for (int c = 0; c < n_; ++c) {
                if (dfs(r, c, 0)) {
                    return true;
                }
            }
        }
        return false;
    }
};
```

```cpp
// 火柴拼正方形（LeetCode 473）：分箱搜尋 + 三種剪枝。
class Solution {
    std::vector<int> nums_;
    int side_ = 0;
    int bucket_[4] = {0, 0, 0, 0};

    bool dfs(int i) {
        if (i == static_cast<int>(nums_.size())) {
            return true;
        }  // 全部分配完
        for (int b = 0; b < 4; ++b) {
            if (bucket_[b] + nums_[i] > side_) {
                continue;
            }  // 超長，剪
            if (b > 0 && bucket_[b] == bucket_[b - 1]) {
                continue;
            }  // 對稱性：同狀態的箱子只試一次
            bucket_[b] += nums_[i];
            if (dfs(i + 1)) {
                return true;
            }
            bucket_[b] -= nums_[i];
        }
        return false;
    }

public:
    bool makesquare(std::vector<int>& matchsticks) {
        int total = std::accumulate(matchsticks.begin(), matchsticks.end(), 0);
        if (total % 4 != 0) {
            return false;
        }
        side_ = total / 4;
        nums_ = matchsticks;
        std::sort(nums_.rbegin(), nums_.rend());  // 大的先放，早暴露衝突
        if (nums_[0] > side_) {
            return false;
        }
        return dfs(0);
    }
};
```

## 時間與空間複雜度

79：從每個格子出發，每步至多 3 個新方向（不能走回頭路），路徑長 $L$。上界 $O(mn \cdot 3^L)$，空間 $O(L)$。**剪枝與搜尋順序不改變這個上界，但能把實際運行時間降幾個數量級**——回答複雜度時要把兩者分開講。

473：上界 $O(4^n)$；加上對稱性剪枝與由大到小排序後，實際規模遠低於此。$n \le 16$。

691／1601：記憶化後 $O(2^n \times \text{每個狀態的轉移數})$，是真正的多項式（相對於狀態數），與純回溯的指數不同。

212：Trie 建構 $O(\sum |w_i|)$；搜尋上界 $O(mn \cdot 4^{L})$，但 Trie 剪枝讓實際只走「棋盤上存在的前綴」，通常快幾個數量級。空間 $O(\sum |w_i|)$。

**這類題的複雜度分析必須誠實：上界通常是指數，能過是因為剪枝。** 不要把「加了剪枝」寫成「複雜度變成多項式」——除非真的做了記憶化。

## 常見錯誤與邊界條件

- `vis` 忘記還原（把路徑搜尋寫成連通性 DFS，漏解）。
- 還原的位置放在 `return true` 之前（找到解後把棋盤改回去通常無妨，但若題目要求保留解就錯了，例如 37 解數獨）。
- 邊界檢查放在遞迴之後而非函式開頭（越界）。
- 剪枝條件沒有驗證「被剪的必定無解」（例如 473 若允許長度為 0 的火柴，「超長就跳過」仍對，但「一根超過邊長就回傳 false」需要火柴為正）。
- 對稱性剪枝套在不對稱的狀態上（漏解）。
- 該記憶化卻沒記憶化（超時）。
- 不該記憶化卻記憶化（狀態不完整，答案錯——這是更危險的一種）。
- 212 找到單詞後未從 Trie 摘除（重複輸出）。
- 搜尋順序未優化導致 TLE。
- 遞迴過深。

## 與相似技巧的比較

- 與 4.1–4.6：骨架相同，差別在狀態的複雜度與剪枝的必要性。**前面幾節可以「照抄模板」，本節不行——每題的剪枝都要自己論證。**
- 與 BFS：若問「最少幾步」且每步代價相同（126 單詞接龍 II），BFS 分層後再回溯構造路徑，比純 DFS 好得多。**問最短用 BFS，問所有／存在性用 DFS。** 126 正是兩者的結合：BFS 建層次圖，再在層次圖上回溯列出所有最短路徑。
- 與記憶化搜尋／DP：判準是「未來是否只依賴一個小狀態摘要」。691、1601、638（大禮包）都該記憶化；79、212 不該。
- 與 grid 主題的連通性 DFS：唯一但關鍵的差別是 `vis` 還不還原。
- 與 4.8 的折半列舉：當搜尋空間是 $2^n$ 且 $n \approx 40$，且目標可分解成兩半，折半列舉把 $2^n$ 變成 $2^{n/2}$。2386（第 K 大和）就走這條路。
- 與 IDA*／A*：更進階的搜尋框架，用估價函數引導。LeetCode 上少見，但 1240（鋪瓷磚）這類題用「當前已用塊數 + 樂觀下界 $\ge$ 已知最優就剪」的思路，本質上就是分支限界。

## 本節重點速查

- 骨架是 4.1，難點是四件事：**狀態設計、可行性剪枝、搜尋順序、記憶化**。
- 路徑搜尋的 `vis` **必須還原**——不還原就變成連通性 DFS，會漏解；
- 還不還原決定了演算法是指數還是多項式。
- 每條剪枝都要證明「被剪的分支確定無解」；
- 對稱性剪枝（473 跳過狀態相同的空箱）威力最大，但要先確認對稱性成立。
- 搜尋順序（大的先放、罕見端點當起點、選項最少的先展開）不影響正確性，影響數量級。
- 記憶化的判準：**未來只依賴小的狀態摘要就記憶化**（691、1601），依賴完整路徑就不行（79、212）。
