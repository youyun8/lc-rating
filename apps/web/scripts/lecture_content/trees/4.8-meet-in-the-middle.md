## 這個技術解決什麼問題

$2^n$ 的枚舉在 $n \le 20$ 時可行，$n = 40$ 時（$10^{12}$）不可行。但 $2^{20} \approx 10^6$ 很輕鬆。折半列舉（meet in the middle）就是利用這個落差：**把 $n$ 個元素切成兩半各自枚舉，再把兩邊的結果配對**，總成本從 $O(2^n)$ 降到 $O(2^{n/2} \cdot \text{配對成本})$。

適用題目：1755（最接近目標值的子序列和）、2035（分成兩陣列最小化和差）、805（陣列均值分割）、3267、2386、494 的大範圍變體。**看到 $n \le 40$ 且題目要對「子集」做某種最佳化，就該想到折半。** 這個上限值本身就是出題者留下的訊號。

## 狀態／資料結構定義

- 把陣列切成左半 $L$（前 $\lceil n/2 \rceil$ 個）與右半 $R$（其餘）。
- `sumL`：$L$ 的所有 $2^{|L|}$ 個子集和；`sumR`：$R$ 的所有 $2^{|R|}$ 個子集和。用位元枚舉或回溯生成。
- 配對結構：把 `sumR` **排序**後用二分搜尋，或放進雜湊表（等值查詢），或用雙指標（單調配對）。
- 若目標函數需要更多維度（2035 要求「左右各取恰好 $n/2$ 個」），就按「取了幾個」分桶：`sumL[k]` 存「左半取 $k$ 個」的所有和，配對時只讓 `sumL[k]` 對上 `sumR[n/2 - k]`。

**維度的判準：配對時需要對齊什麼，就要按什麼分桶。** 只要求和最接近 → 不分桶；還要求個數 → 按個數分桶；還要求乘積或其他量 → 那一維也要進桶。

## 不變量或正確性證明

**核心引理（唯一分解）。** 對全集 $S = L \sqcup R$（不交併），映射
$$T \;\longmapsto\; (T \cap L,\; T \cap R)$$
是 $2^S$ 與 $2^L \times 2^R$ 之間的**雙射**。

證明。單射：若 $T_1 \cap L = T_2 \cap L$ 且 $T_1 \cap R = T_2 \cap R$，則 $T_1 = (T_1 \cap L) \cup (T_1 \cap R) = (T_2 \cap L) \cup (T_2 \cap R) = T_2$（用到 $L \cup R = S$）。滿射：給定 $(A, B) \in 2^L \times 2^R$，取 $T = A \cup B$ 即可，且 $T \cap L = A$（用到 $A \subseteq L$、$B \cap L = \varnothing$，即 $L$ 與 $R$ **不交**）。$\square$

因此「枚舉左半的所有子集 × 枚舉右半的所有子集」與「枚舉全集的所有子集」是同一件事，**不重不漏**。$|2^L| \cdot |2^R| = 2^{|L|+|R|} = 2^n$——注意這說明**組合的總數並沒有減少**，減少的是「生成」的成本（從 $2^n$ 降到 $2^{|L|} + 2^{|R|}$）。折半列舉能贏，靠的是**不逐一檢查所有 $2^n$ 對，而是用排序／雜湊在對數時間內批次回答「右半有沒有／有幾個滿足條件的」**。

**這條論證點名了折半列舉的核心前提：目標函數必須可分解。** 具體地，要能寫成
$$f(T) = g(T \cap L) \;\oplus\; h(T \cap R)$$
其中 $\oplus$ 是一個「可查詢」的運算——通常是加法（配對成「和為定值／最接近定值」）、異或（雜湊表等值查詢）、或乘法（取對數後變加法）。

- 和／異或／乘積：可分解。✔
- 「子集中相鄰兩元素之差不超過 $k$」：**不可分解**，因為它涉及跨越切點的相鄰關係。✘
- 「子集的最大值減最小值」：可分解（各半的 max、min 再合併）。✔

**判斷一題能不能折半，就是判斷目標能不能寫成這個形式。** 寫不出來就別硬套。

**1755（最接近 `goal` 的子集和）的配對正確性。** 對每個 $a \in \text{sumL}$，我們要找 $b \in \text{sumR}$ 使 $|a + b - \text{goal}|$ 最小，即 $b$ 最接近 $\text{goal} - a$。把 `sumR` 排序後用 `lower_bound` 找到第一個 $\ge \text{goal} - a$ 的元素，**答案必在它與它的前一個之中**——因為排序後的序列裡，離某個值最近的元素只可能是「第一個不小於它的」或「最後一個小於它的」。這一步用到的是有序性，不是別的性質；漏掉「前一個」是最常見的錯誤。

**2035（左右各取恰好 $n/2$ 個）為何必須按個數分桶。** 題目要求把 $2n$ 個數分成兩組各 $n$ 個。設左半取 $k$ 個進第一組，則右半必須取 $n - k$ 個。若不分桶而任意配對，會得到大小不等於 $n$ 的分組，答案非法。**分桶不是優化，是正確性要求。**

**805 的均值轉換。** 「兩組平均值相等」等價於「第一組的和 × 全部個數 = 全部的和 × 第一組個數」，即
$$\text{sum}_A \cdot n = \text{sum} \cdot |A| .$$
為了避免浮點與分數，通常把每個元素替換成 $n \cdot a_i - \text{sum}$，則條件變成「該組替換後的和為 0」。**這個變換把「平均值」這個不可分解的量，轉成了「和」這個可分解的量**——折半列舉常常需要先做這種代數整理，這一步往往比折半本身更難想。

## C++17 模板

```cpp
// 最接近目標值的子序列和（LeetCode 1755）：折半 + 排序 + 二分。
class Solution {
    static std::vector<long long> subsetSums(const std::vector<int>& a) {
        int m = a.size();
        std::vector<long long> sums(1 << m, 0);
        for (int mask = 1; mask < (1 << m); ++mask) {
            int low = mask & -mask;  // 最低位的 1
            int idx = __builtin_ctz(mask);
            sums[mask] =
                sums[mask ^ low] + a[idx];  // 由子問題遞推，總計 O(2^m)
        }
        return sums;
    }

public:
    int minAbsDifference(std::vector<int>& nums, int goal) {
        int n = nums.size(), half = n / 2;
        std::vector<int> left(nums.begin(), nums.begin() + half);
        std::vector<int> right(nums.begin() + half, nums.end());

        std::vector<long long> sl = subsetSums(left);
        std::vector<long long> sr = subsetSums(right);
        std::sort(sr.begin(), sr.end());

        long long best = std::abs(static_cast<long long>(goal));
        for (long long a : sl) {
            long long need = goal - a;
            auto it = std::lower_bound(sr.begin(), sr.end(), need);
            if (it != sr.end()) {  // 第一個 >= need
                best = std::min(best, std::abs(a + *it - goal));
            }
            if (it != sr.begin()) {  // 最後一個 < need，不能漏
                best = std::min(best, std::abs(a + *std::prev(it) - goal));
            }
        }
        return static_cast<int>(best);
    }
};
```

`subsetSums` 用 `sums[mask] = sums[mask ^ lowbit] + a[idx]` 遞推，每個 `mask` $O(1)$，總計 $O(2^m)$——比「對每個 `mask` 掃 $m$ 位」的 $O(m \cdot 2^m)$ 快一個 $m$ 倍，在 $m = 20$ 時是 20 倍的差距，值得養成習慣。

## 時間與空間複雜度

生成兩半的子集和：$O(2^{n/2})$（用 lowbit 遞推）或 $O(n \cdot 2^{n/2})$（逐位累加）。

配對：排序 $O(2^{n/2} \cdot \frac{n}{2})$，對每個左半元素二分 $O(\frac{n}{2})$，合計 $O(n \cdot 2^{n/2})$。

總計 $O(n \cdot 2^{n/2})$ 時間、$O(2^{n/2})$ 空間。$n = 40$ 時 $2^{20} \approx 10^6$，乘上 $n$ 約 $4\times10^7$，可過。

與 $O(2^n) \approx 10^{12}$ 相比是決定性的差距。

**空間是折半列舉的真正瓶頸。** $2^{20}$ 個 `long long` 是 8 MB，兩半就 16 MB，加上排序的臨時空間可能吃緊。$n = 44$ 時 $2^{22}$ 已是 32 MB 一半，通常超限。**所以 $n$ 的上限不只由時間決定，也由空間決定**，這與一般的指數演算法不同，要特別留意。

若兩邊不等長，讓**較小的那半用來排序／建表**能省空間；或改用雙指標（兩邊都排序後從兩端夾逼）避免二分的常數。

## 常見錯誤與邊界條件

- 二分後只檢查 `lower_bound` 的結果而漏掉前一個（1755 的經典錯誤）。
- `it == sr.end()` 或 `it == sr.begin()` 未檢查（解參考越界）。
- 需要按「取了幾個」分桶卻沒分（2035，答案非法）。
- 和用 `int` 溢位（$n = 40$、$|a_i| \le 10^7$ 時和可達 $4\times10^8$，配上 `goal` 相減後仍要 `long long`）。
- 忘記空子集（和為 0）也是合法選擇，導致漏解。
- 805 未做「$n \cdot a_i - \text{sum}$」的變換而直接比較平均值（浮點誤差）。
- 805 要排除「兩組其中一組為空」的情形。
- 切分點取 `n / 2` 但陣列長度為奇數時兩邊長度差 1（正確，但空間分配要按較長那半算）。
- 目標函數其實不可分解卻硬套。

## 與相似技巧的比較

- 與 4.2 的子集型回溯：折半是它在 $n$ 太大時的救援。$n \le 20$ 直接枚舉，$20 < n \le 40$ 折半，$n > 40$ 兩者都不行，得找多項式解法或 DP。
- 與 494（目標和）：$n \le 20$ 時可以直接 DP（背包，$O(n \cdot \text{sum})$）。**當和的範圍小時，背包 DP 比折半好**；當元素值很大（和的範圍達 $10^9$）而 $n$ 小時，折半才是唯一出路。**判準是「$n$ 小還是值域小」。**
- 與雙向 BFS：同一個「兩邊夾擊」的思想用在最短路徑上，把 $b^d$ 降到 $2 b^{d/2}$。原理相同（狀態空間的平方根縮減），場景不同。
- 與 2386（第 K 大和）：那題結合折半與堆，先取全部正數的和當上界，再用堆逐步生成第 $k$ 大——是折半思想的變形。
- 與 3267（統計近似相等數對 II）：把「至多兩次交換」的所有變體枚舉出來再配對，也是「枚舉一半的可能性 + 查表」的形態，只是切分的維度不是元素而是操作。

## 本節重點速查

- $n \le 40$ 且對子集做最佳化 → 折半列舉。
- 依據是**唯一分解引理**：$T \mapsto (T \cap L, T \cap R)$ 是雙射，故不重不漏。
- **核心前提：目標必須寫成 $f(T) = g(T\cap L) \oplus h(T \cap R)$ 且 $\oplus$ 可查詢**（和、異或、乘積可以；
- 跨切點的相鄰關係不行）。
- 配對時**需要對齊什麼就按什麼分桶**（2035 要按個數分桶，這是正確性而非優化）。
- 二分後**別漏掉前一個元素**。
- 子集和用 `sums[mask] = sums[mask ^ lowbit] + a[idx]` 遞推可省一個 $n$ 倍。
- 空間 $O(2^{n/2})$ 常是真正的瓶頸。
