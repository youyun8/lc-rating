## 這個技術解決什麼問題

本節收的是不屬於樹、也不屬於回溯枚舉的遞迴／分治應用。它們的共同槓桿是同一句話：**把大問題化約成同型的小問題，使總工作量從 $O(n^2)$ 掉到 $O(n \log n)$，或從「$O(\text{結構大小})$」掉到 $O(\log \text{結構大小})$。**

三種形態，收穫的來源各不相同：

- **分治**（912 排序陣列）：兩邊都要解，合併成本 $O(n)$，遞迴式 $T(n) = 2T(n/2) + O(n) \Rightarrow O(n \log n)$。收穫來自「合併兩段有序序列比從頭排序便宜」。
- **減治**（215 第 K 大）：只往一邊遞迴，$T(n) = T(n/2) + O(n) \Rightarrow O(n)$。收穫來自**丟掉另一半**。
- **公式遞迴**（1545、880、3537）：結構大到無法生成，但「第 $n$ 層由第 $n-1$ 層按固定規則產生」，於是把查詢位置往上一層折算。收穫是把 $O(2^n)$ 的結構壓成 $O(n)$ 次折算。

## 狀態／資料結構定義

**912（合併排序）：** 狀態是區間 $[l, r]$。輔助陣列 `tmp` 用來合併（就地合併很難寫對，用輔助陣列是標準做法）。

**215（快速選擇）：** 狀態是區間 $[l, r]$ 加上目標下標 $k$（**全域下標，不是區間內的相對下標**——這是最容易搞錯的地方）。分區後基準落在 $p$，比較 $k$ 與 $p$ 決定往哪一邊。

**1545（第 N 個二進位字串的第 K 位）：** 狀態是 $(n, k)$。關鍵量是第 $n$ 個字串的長度 $\ell_n = 2^n - 1$ 與正中位置 $m_n = 2^{n-1}$（1-indexed）。

**880（索引處的解碼字串）：** 狀態是「解碼後的長度」與目標下標 $k$。由後往前掃描，遇到數字就把長度除回去、$k$ 對長度取模。

## 不變量或正確性證明

**912 的正確性（強歸納）。** 命題：`mergeSort(l, r)` 使 `a[l..r]` 有序，且是原多重集的一個排列。

- 基底：$l \ge r$，長度 $\le 1$，本就有序。
- 歸納：設 `mergeSort(l, m)` 與 `mergeSort(m+1, r)` 都正確（子區間嚴格更短，因為 $l \le m < r$）。`merge` 每次從兩段的當前頭部取較小者，故輸出遞增；每個元素恰被取一次，故是排列。

**穩定性的來源**：合併時相等取左邊（`a[i] <= a[j]` 用左邊），保證原本在前的元素仍在前。寫成 `<` 就不穩定了——這個字元在單獨排序時看不出差別，但當合併排序被當成別的演算法的元件時（例如 1.9 的連結串列排序、或需要穩定性的多關鍵字排序）就是錯的。

**必須取前中點。** $m = \lfloor (l+r)/2 \rfloor$ 保證 $l \le m < r$，兩個子區間都嚴格短於原區間，遞迴收斂。若取 $m = \lceil (l+r)/2 \rceil$，長度為 2 時會得到 $m = r$，右半是空、左半是原區間，**無限遞迴**。這與 1.9 中連結串列取前中點的理由完全相同。

**215 快速選擇的正確性不變量：「答案位於當前區間 $[l, r]$ 內」始終成立。**

- 初始化：$k \in [0, n-1]$，區間是全陣列，成立。
- 保持：分區後基準歸位到下標 $p$，滿足 `a[l..p-1] <= a[p] <= a[p+1..r]`。於是排序後第 $p$ 小的元素就是 `a[p]`——**這一步是快速選擇的全部**：分區之後，基準的位置就是它在最終有序陣列中的位置，這個事實與其他元素的順序無關。因此：
  - $k = p$：答案就是 `a[p]`，回傳。
  - $k < p$：答案在左半，且左半是 $[l, p-1]$，不變量保持。
  - $k > p$：答案在右半，同理。
- 終止：區間長度每次至少減 1（基準被排除），必定終止。

**期望 $O(n)$ 的論證。** 若每次基準隨機選取，期望上分區點均勻分佈，遞迴子區間的期望長度是原長的 $3/4$（更精確：期望上有一半的機會落在中間一半內）。於是期望總工作量
$$T(n) \le n + T(3n/4) \Rightarrow T(n) \le n \left(1 + \tfrac34 + \tfrac9{16} + \cdots\right) = 4n = O(n).$$

**這裡「隨機」不是可有可無的裝飾。** 若固定取 `a[r]` 當基準，在已排序或逆序輸入上每次只能剝掉一個元素，退化成 $O(n^2)$——而 LeetCode 215 的測資裡就有這種輸入。必須隨機化（或用三數取中）。**這是「平均情形分析成立的前提是輸入分佈假設，而隨機化把假設從輸入身上轉移到演算法身上」的標準例子。**

陣列含大量重複元素時，兩路分區也會退化；改用三路分區（`< pivot` / `== pivot` / `> pivot`）可解決。

**1545 的折算不變量：`solve(n, k)` 回傳第 $n$ 個字串的第 $k$ 位（1-indexed），且始終有 $1 \le k \le 2^n - 1$。**

構造規則是 $S_n = S_{n-1} + \texttt{"1"} + \text{invert}(\text{reverse}(S_{n-1}))$，長度 $\ell_n = 2\ell_{n-1} + 1 = 2^n - 1$，正中位置 $m = 2^{n-1}$。

- 若 $k = m$：該位是 `'1'`，直接回傳。
- 若 $k < m$：落在前半 $S_{n-1}$ 中，答案是 `solve(n-1, k)`。
- 若 $k > m$：落在後半。後半是「$S_{n-1}$ 先反轉再取反」，其第 $j$ 位（$j = k - m$）等於 $S_{n-1}$ 第 $\ell_{n-1} - j + 1$ 位取反。故答案是 `invert(solve(n-1, ell_{n-1} - j + 1))`。

每次遞迴 $n$ 減 1，故 $O(n)$ 次折算、$O(1)$ 空間（改成迴圈時）。**這裡真正的收穫是：字串長度 $2^n - 1$ 在 $n = 20$ 時已達百萬，$n$ 再大就無法生成，但折算完全不受影響。**

「反轉再取反」這個對應關係必須寫對，$\ell_{n-1} - j + 1$ 的 $+1$ 來自 1-indexed。**下標基準（0 還是 1）在這類公式遞迴中是最大的錯誤來源**，動筆前先寫清楚採用哪一種並貫徹。

## C++17 模板

```cpp
// 快速選擇（LeetCode 215）：隨機化分區，期望 O(n)。
class Solution {
    std::mt19937 rng_{std::random_device{}()};

    // 回傳 a[l..r] 中第 k 小的元素（k 為全域下標）
    int quickSelect(std::vector<int>& a, int l, int r, int k) {
        if (l == r) {
            return a[l];
        }

        int pick =
            l + static_cast<int>(rng_() % (r - l + 1));  // 隨機基準，不可省
        std::swap(a[pick], a[r]);
        int pivot = a[r];

        int p = l;  // 分區：a[l..p-1] < pivot
        for (int i = l; i < r; ++i) {
            if (a[i] < pivot) {
                std::swap(a[i], a[p++]);
            }
        }
        std::swap(a[p], a[r]);  // 基準歸位到 p

        if (k == p) {
            return a[p];
        }  // 分區後 p 就是最終位置
        return (k < p) ? quickSelect(a, l, p - 1, k)
                       : quickSelect(a, p + 1, r, k);
    }

public:
    int findKthLargest(std::vector<int>& nums, int k) {
        int n = nums.size();
        // 第 k 大 = 第 n-k 小（0-indexed）
        return quickSelect(nums, 0, n - 1, n - k);
    }
};
```

```cpp
// 合併排序（LeetCode 912）：穩定，O(n log n)。
class Solution {
    std::vector<int> tmp_;

    void mergeSort(std::vector<int>& a, int l, int r) {
        if (l >= r) {
            return;
        }  // 基底：長度 <= 1
        int m = l + (r - l) / 2;  // 前中點，保證 l <= m < r
        mergeSort(a, l, m);
        mergeSort(a, m + 1, r);

        int i = l, j = m + 1, t = l;
        while (i <= m && j <= r) {
            tmp_[t++] = (a[i] <= a[j]) ? a[i++] : a[j++];  // <= 才穩定
        }
        while (i <= m) {
            tmp_[t++] = a[i++];
        }
        while (j <= r) {
            tmp_[t++] = a[j++];
        }
        std::copy(tmp_.begin() + l, tmp_.begin() + r + 1, a.begin() + l);
    }

public:
    std::vector<int> sortArray(std::vector<int>& nums) {
        tmp_.resize(nums.size());
        mergeSort(nums, 0, nums.size() - 1);
        return nums;
    }
};
```

## 時間與空間複雜度

**912**：$T(n) = 2T(n/2) + O(n)$，由主定理得 $O(n \log n)$，最壞情形也是（與快速排序不同，合併排序沒有壞輸入）。空間 $O(n)$ 輔助陣列加 $O(\log n)$ 堆疊。

**215**：期望 $O(n)$，最壞 $O(n^2)$（隨機化後機率極低）。空間 $O(1)$（改成迴圈）或 $O(\log n)$ 期望堆疊。
若改用大小為 $k$ 的堆，是 $O(n \log k)$——**當 $k$ 很小時堆更好，且能處理串流輸入**；$k$ 接近 $n$ 時快速選擇更好。若要求最壞 $O(n)$，用中位數的中位數（BFPRT），常數大，競賽中少用。

**1545／880**：$O(n)$ 次折算（$n$ 是層數），$O(1)$ 額外空間。相對於「真的把字串建出來」的 $O(2^n)$ 時間與空間，這是**在時間與空間上同時**降到對數級——公式遞迴的典型收穫。

**主定理速記**：$T(n) = aT(n/b) + O(n^d)$ 時，$d > \log_b a$ 給 $O(n^d)$；$d = \log_b a$ 給 $O(n^d \log n)$；$d < \log_b a$ 給 $O(n^{\log_b a})$。合併排序是 $a=2, b=2, d=1$，落在第二種。快速選擇是 $a=1, b=2, d=1$，落在第一種，得 $O(n)$。**「兩邊都遞迴」與「只遞迴一邊」的差別，在主定理裡就是 $a=2$ 與 $a=1$，結果差一個 $\log$。**

## 常見錯誤與邊界條件

- 中點取後中點導致無限遞迴。
- 合併時用 `<` 而非 `<=` 破壞穩定性。
- `tmp` 每次遞迴都重新配置（正確但慢，應在外層開好一份）。
- 合併後忘記把 `tmp` 複製回 `a`。
- 215 把 `k` 當成區間內的相對下標（應為全域下標）。
- 215 用固定基準在有序輸入上退化成 $O(n^2)$。
- 215 的「第 $k$ 大」與「第 $k$ 小」轉換寫錯（$n - k$ 對應 0-indexed）。
- 分區迴圈的邊界寫成 `i <= r`（把基準也比進去，基準歸位錯誤）。
- 重複元素多時兩路分區退化（改三路）。
- 公式遞迴的下標基準（0 或 1）混用。
- `1 << n` 在 $n \ge 31$ 時溢位（用 `1LL << n`）。
- 880 的長度累乘可能爆 `long long`（超過 $k$ 就可以停止累乘）。
- 遞迴過深。

## 與相似技巧的比較

- 與 1.9 的連結串列分治：完全同源。差別是連結串列沒有隨機存取，找中點要用快慢指標，且**必須真的切斷**（`slow->next = nullptr`）；陣列版靠下標天然分割。
- 與 sorting 主題：合併排序在「求逆序對」「歸併過程中統計」這類題目上是不可替代的——因為合併的那一刻，左右兩段各自有序，可以 $O(n)$ 完成跨段統計。
- 與 binary_search：二分搜尋是減治的極致（每次丟掉一半，且合併成本 $O(1)$，故 $O(\log n)$）。快速選擇則是「每次丟掉一半，但分區成本 $O(n)$」，故 $O(n)$。**兩者的差別就在合併／分割的成本。**
- 與 4.7 的搜尋：搜尋也是遞迴，但它的子問題**不會變小到可控**（指數級分支），靠剪枝而非分治結構取勝。分治的前提是「子問題規模按固定比例縮小」。
- 與 heap／priority_queue：215 的替代解法，取捨見上。
- 與 3537（填充特殊網格）：$4^n$ 大小的網格無法生成，但每個 $2^k \times 2^k$ 的區塊由四個 $2^{k-1} \times 2^{k-1}$ 區塊按固定順序拼成——這是二維版的公式遞迴，折算的是「座標落在哪個象限」以及「該象限的起始編號」。思路與 1545 同構。

## 本節重點速查

- 三種形態：**分治**（兩邊都遞迴，$T(n)=2T(n/2)+O(n) \Rightarrow O(n\log n)$）、**減治**（只遞迴一邊，$\Rightarrow O(n)$）、**公式遞迴**（結構太大不生成，把查詢位置往上一層折算，$O(\log \text{size})$）。
- 合併排序：**取前中點**（否則無限遞迴）、合併時**相等取左邊**（穩定性）。
- 快速選擇的不變量是「答案始終在當前區間內」，核心事實是**分區後基準的位置就是它的最終位置**；
- **基準必須隨機化**，否則有序輸入退化 $O(n^2)$。
- 公式遞迴最大的坑是下標基準（0 或 1）與「反轉後對應到哪一位」。
- 主定理裡「兩邊遞迴」與「一邊遞迴」就是 $a=2$ 與 $a=1$，差一個 $\log$。
